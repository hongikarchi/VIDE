# ADR-009 · 단일 활성 호스트 + 공유 기록

## 1. 배경

PLAN §7.1(구 PRD §14.2)·AC-25는 두 호스트의 동시 라이브 연결을 MVP 완료 조건으로 두지만 §2 문제표에 대응 문제가 없고 §12.2가 호스트 간 변환·동기화를 이미 제외했다. 남는 가치는 '대상 혼동 없음'이라는 격리 속성뿐인데, 그 하나를 위해 두 호스트 프로세스·두 문서 버전·교차 상태 기계를 첫 호스트 완성 전에 설계하게 된다(PRD R-57, Codex R-43).

## 2. 결정

- **WorkScope와 Run은 호스트 문서 하나를 대상으로 한다.** 프로젝트는 여러 호스트·문서를 등록하고, 설계 대상 중심의 공유 기록(§6.1)으로 잇는다. 격리는 시험이 아니라 구조로 보장한다.
- AC-25는 "등록됐지만 비활성인 호스트에 쓰기가 발생하지 않고, 요청 대상은 요청 시점의 문서·버전에 고정된다(순차 연결 포함)"로 축소한다. §8.1의 "프로그램을 전환해도 요청 대상이 바뀌지 않는다"는 이 고정으로 충족된다.
- 두 호스트 시험(구 PRD §14.2, 현재 PLAN §7.1)은 목적을 '어댑터 계약 차이 확인'으로 바꾼다. 동시 라이브 연결은 후속 확장이다.

> **[검토 · codex · R-01 · 높음]** **추가 지적.** **활성 전환과 진행 중 쓰기.** WorkScope/Run의 단일 문서 대상과 공유 기록 선택에는 동의한다. 다만 격리를 시험 대신 구조로 보장한다는 문장은 구조와 시험을 함께 사용하는 것으로 수정할 것을 권한다. A에서 시작한 중단 불가 쓰기가 B 활성화 후 완료되면 대상은 고정했어도 비활성 호스트 쓰기 금지와 충돌한다. 제안: 활성 대상의 적용 범위를 정하고, 쓰기 중 전환을 막거나 실제 정지/완료를 확인한 뒤 넘긴다. 결과 불명은 확인 전 새 쓰기를 허용하지 않는다. 요청에는 호스트·문서 인스턴스·기준 버전·연결 세대를 고정하고 화면의 현재 선택으로 재해석하지 않는다. A→B→A 전환·문서 재열기·늦은 응답·연결 끊김을 시험해야 하며 동시 라이브 연결 기능을 추가할 필요는 없다.

## 부록 · Codex 검토 요약 (2026-09-17)
