# ADR-009 · 여러 호스트를 하나의 설계 작업으로 연결한다

## 1. 결정

Rhino와 ZWCAD의 복수 연결을 지원하고, 하나의 작업 범위에서 여러 호스트의 정보와 변경을 연결한다. 선언한 객체·동작 범위에서 CAD 정보를 이용해 Rhino에 네이티브 결과를 생성하거나, 하나의 설계 변경을 도면과 모델의 지정 대상에 함께 반영할 수 있어야 한다.

독립 작업은 병렬로 진행할 수 있고, 앞선 결과에 의존하거나 충돌하는 작업은 필요한 순서를 관리한다. 모든 명령을 무조건 동시에 실행한다는 뜻이 아니다. 사용자는 전체 목적과 호스트별 진행·후보·적용 결과를 보고 개입한다.

WorkScope와 Run을 호스트 문서 하나로 제한하는 안과, 단일 활성 호스트만 제어하는 안은 채택하지 않는다. 화면에서 보고 있는 호스트와 실제 실행 대상을 구분한다. 실행마다 호스트·문서·대상이 명시되어야 한다.

## 2. 판단 근거

사용자가 'CAD 정보를 읽어 Rhino에 매스로 반영'하고 '설계 변경을 도면·모델 양쪽에 반영'하는 실제 여정을 제시했다. 따라서 두 도구를 지원 목록에 올리는 것을 넘어 하나의 요청에서 연결하는 능력이 MVP 가치에 해당한다.

복수 연결, 호스트 간 연계, 독립 작업의 병렬 실행은 다른 능력이다. 두 개의 독립 에이전트를 띄웠다는 것만으로 공동 변경의 일관성을 검증하지 않는다. 호스트별 전용 AI 모델이나 추가 감독 에이전트를 필수로 정하지 않는다.

## 3. 보장 범위와 한계

대상 대응·좌표·단위·입력 기준과 작업 의존성을 구분한다. 처음부터 모든 객체의 자동 대응을 보장하지 않고 사용자 지정 또는 확인된 대응에서 시작할 수 있다.

한쪽 적용 성공과 다른 쪽 실패·결과 불명을 전체 성공으로 표시하지 않는다. 이미 확인된 변경은 재시도 과정에서 중복 적용하지 않는다. 전체 요청 또는 하위 작업에 대한 개입과 관련 작업에 미치는 영향은 SPEC에서 정한다.

요청 없는 상시 양방향 동기화, 임의 객체의 무손실 변환, 모든 호스트의 원자적 성공·취소·복구는 첫 출시 보장이 아니다. 선택·카메라 동기화도 별도 능력이다.

프로젝트별 한 로컬 작업환경(ADR-002)은 이 결정과 양립한다. 여러 로컬 PC의 공동 제어를 포함한다는 뜻은 아니다.

## 4. 기준 문서와 구현 위임

PRD §12.2·§14.1·FR-02가 제품의 정본이며, AC-25·32·33에서 연결·연계·부분 결과를 확인한다. SPEC-00 및 연계 기능 SPEC은 논리적 실행 대상·선후관계·충돌·개입·재개를 정한다. PLAN은 큐·메시지·연결·호스트 스레드·저장 등의 기술 방법을 정한다.
