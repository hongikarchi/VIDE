# ADR-009 · 단일 활성 호스트 + 공유 기록

## 1. 배경

PRD §14.2·AC-25는 두 호스트의 동시 라이브 연결을 MVP 완료 조건으로 두지만 §2 문제표에 대응 문제가 없고 §12.2가 호스트 간 변환·동기화를 이미 제외했다. 남는 가치는 '대상 혼동 없음'이라는 격리 속성뿐인데, 그 하나를 위해 두 호스트 프로세스·두 문서 버전·교차 상태 기계를 첫 호스트 완성 전에 설계하게 된다(PRD R-57, Codex R-43).

## 2. 결정

- **WorkScope와 Run은 호스트 문서 하나를 대상으로 한다.** 프로젝트는 여러 호스트·문서를 등록하고, 설계 대상 중심의 공유 기록(§6.1)으로 잇는다. 격리는 시험이 아니라 구조로 보장한다.
- AC-25는 "등록됐지만 비활성인 호스트에 쓰기가 발생하지 않고, 요청 대상은 요청 시점의 문서·버전에 고정된다(순차 연결 포함)"로 축소한다. §8.1의 "프로그램을 전환해도 요청 대상이 바뀌지 않는다"는 이 고정으로 충족된다.
- §14.2의 두 호스트 시험은 목적을 '어댑터 계약 차이 확인'으로 바꾼다. 동시 라이브 연결은 후속 확장이다.

## 3. 결과 — 적용 시 바꿀 문장

PRD §14.1 다중 호스트 정의, §14.2 두 호스트 시험 문장, AC-25 통과 기준, FR-02 수용 기준(동시성 제외). SPEC-00-common: 프로젝트–호스트–WorkScope 관계와 활성 호스트 전환 상태.

## 4. 재검토 조건

Rhino→ZWCAD 인계 작업에서 한 작업 안에 두 호스트를 함께 써야 하는 여정이 실제로 나오면 동시 연결을 다시 검토한다.
