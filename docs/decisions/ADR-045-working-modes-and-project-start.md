# 진행 방식과 프로젝트 시작

## 맥락

- 세 도구(Claude Code·Cursor·Kiro)는 모두 **모드를 사람이 고르고, 판정기는 그 모드 안에서만** 움직인다. Kiro는 세션을 열 때 Vibe(대화하며 만들기)와 Spec(요구 → 설계 → 작업 목록을 승인하며 만들기)을 고르게 한다([RESEARCH-18](../research/RESEARCH-18-environment-not-model.md) §1·§5.3).
- VIDE는 판정기(규칙·Jev)가 jig·계획을 고른다. 경로 판정(SPEC-02.17)이 jig로 판정하면 [ADR-026](ADR-026-chat-stage-and-skill-jigs.md) 4에 따라 자동으로 열고 사람 확인 단계 전까지 계산한다. PLAN-51 라운드 1~7의 P0 다수는 이 판정이 사람의 뜻과 어긋난 **강제 진입**이었다(T-360: 모델링 문장 속 '구조 검토'로 jig 진입, RESEARCH-18 §5.3).
- [ADR-011](ADR-011-delegation-working-mode.md) §6(재검토 조건)과 ADR-026 4가 판정에 맡긴 범위를 다시 볼 때가 됐다. '계획부터'(SPEC-02.20, Plan/Auto 토글)는 이미 사람이 고르는 모드다.

## 선택지

| 선택지 | 내용 | 장점 | 단점 |
|---|---|---|---|
| ① 판정기가 고름(현행) | 규칙·Jev가 jig·계획을 골라 자동으로 연다 | 사람이 고를 필요가 없다 | 강제 진입이 P0로 반복됐다. 판정 실수의 비용이 크다 |
| ② 사람이 첫 화면에서 고름 | 대화/작업(jig)/계획 중 사람이 고르고 판정기는 그 안에서만 | 세 도구와 같은 축 | 비개발자에게 매번 한 단계를 더 묻는다 |
| ③ 기본은 대화 | 말로 한 요청은 대화 AI가 기본, jig는 제안 카드, '계획부터'는 토글 유지 | 강제 진입이 사라지고 묻는 단계가 늘지 않는다 | jig를 자주 쓰는 사람은 한 번 더 누른다 |

RESEARCH-18 §8 D2의 추천은 ③이었다.

## 결정

2026-10-19 사용자 결정(환경 방향 결정 브리프의 D2 답 ③; 브리프는 반영 뒤 삭제, Git 이력 `65d58b9a`).

1. **말로 한 요청의 기본은 대화 AI다.** 판정기가 jig로 볼 만한 요청이라고 판단해도 jig를 열지 않고 대화 AI가 받는다.
2. **jig는 제안 카드로만 보인다.** 판정이 jig를 가리키면 대화 안에 '이 jig로 할 수 있다'는 제안 카드를 보이고, 사용자가 누를 때만 연다.
3. **예외 — 지금대로 바로 가는 경우:**
   - 사용자가 jig를 **이름으로 부를 때**.
   - **[JIG] 버튼**으로 열 때.
   - 프로젝트에 **고정된 jig의 설정값 변경**.
   - 화면·설정값·앱 동작 같은 **비-AI 경로**(SPEC-02.17의 view·param·app).
4. **'계획부터' 토글은 유지한다.** Plan/Auto는 사람이 고르는 모드로 그대로 둔다.
5. ADR-026 4의 "요청이 jig로 판정되면 자동으로 열고 계산한다"는 3의 예외(이름으로 부름·[JIG] 버튼)에만 적용되도록 좁힌다. 프로젝트에 고정된 jig의 설정값 변경은 jig를 새로 여는 일이 아니라 비-AI 경로의 설정값 변경으로 따로 처리한다. 해석 확정과 Rhino에 만들기를 사람이 누르는 규칙은 바뀌지 않는다. 의미는 SPEC-18.6이 소유한다.

## 프로젝트 시작 두 길 — 채택(2026-10-19 P1 ①)

2026-10-19 사용자가 P1 ①로 채택했다. 동작은 SPEC-18.7, 구현은 PLAN-55 T-375.

**사용자 메모(2026-10-19, D2 보충):** "Kiro처럼 처음에 프로젝트 세팅(워크플로·설정)을 하게 하는 것도 괜찮고, Cursor처럼 바로 즉흥으로 하는 워크플로도 있으면 좋겠다. 프로젝트를 처음 열 때 둘 중 하나를 고르게 하면 어떨까."

**내용:**

- 프로젝트를 만들 때 **'차근차근(설정 안내)'**과 **'바로 시작'** 중 고른다.
- 차근차근은 체크리스트를 순서대로 묻는다: 작업 폴더 트리, 서버 폴더 연결과 구조 확정, 프로젝트 AI 지시, 역할 경로, 자료 정리 범위, 기본 대화 모델.
- 바로 시작은 같은 항목을 건너뛰었다가 **처음 필요할 때 질문 카드로** 묻는다.
- 어느 길이든 대시보드에 **'프로젝트 설정 n/m'**이 남아 이어 할 수 있다.

**Kiro와 다른 점:**

- Kiro의 Vibe/Spec은 세션의 진행 방식(요구·설계 승인 여부)을 가른다. 두 길은 **프로젝트 설정을 언제 채우는가**만 가른다. 시작 길이 그 뒤 AI 동작(요청 경로·권한)을 가르지 않으며, 진행 방식은 위 결정(기본은 대화, '계획부터' 토글)이 정한다.
- 고른 길에 묶이지 않는다. 바로 시작한 프로젝트도 '프로젝트 설정 n/m'에서 차근차근 이어 할 수 있다.

## 결과·후속

- **PRD:** FR-25의 "jig로 판정되면 열고 사람 확인 단계 전까지 계산" 문구를 결정 1~3에 맞게 고쳤다(2026-10-19 수락). 프로젝트 시작 두 길은 PRD §8.1·FR-01에 반영됨.
- **SPEC:** SPEC-18.6(진행 방식)이 기본 경로·제안 카드·예외·토글의 의미를 소유한다. SPEC-02.17(경로 판정)·SPEC-07.18(jig 호출)은 SPEC-18.6을 가리키게 정렬한다. 프로젝트 시작 두 길은 SPEC-18.7이 소유한다.
- **ADR-026 4:** 이 결정으로 좁혀진다. ADR-026의 역링크는 PLAN-55 T-374에서 단다.
- **PLAN:** PLAN-55 T-374(SPEC-02.17·SPEC-07.18·ADR-026 4 정렬과 제안 카드 구현), 프로젝트 시작 두 길은 T-375. 검증은 PLAN-51의 강제 진입 시나리오(T-360 등)를 다시 돌려 jig가 제안 카드로만 뜨는지 본다.
