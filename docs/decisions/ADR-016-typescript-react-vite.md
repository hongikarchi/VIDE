# 웹과 로컬 제어기의 TypeScript 전환

## 결정과 범위

사용자의 TypeScript·React·Vite·CSS·Node.js·C# 확정 지시에 따라 웹은 TypeScript/TSX + React + Vite + CSS, 로컬 제어 서버는 TypeScript + Node.js, 네이티브 호스트 실행기는 C# + 공식 SDK를 사용한다. Node.js는 실행 환경이며 서버 작성 언어도 TypeScript다. SQLite와 Cloudflare 공유 실험 결정은 유지한다.

이 결정은 언어·프레임워크 기준이다. 구체 버전과 설정은 전환 시 호환성을 검증하여 잠금 파일에 고정한다. 현재 JavaScript 구현을 이미 전환된 것으로 표시하지 않는다. 3D 엔진·뷰어 선정과 React Three Fiber 같은 결합 계층의 채택은 이 결정에 포함하지 않는다.

## 이유와 영향

늘어나는 패널·초안·실행 상태를 React 컴포넌트로 나누고, UI·서버 간 데이터 계약과 변경 영향을 TypeScript로 점검한다. Vite는 웹 개발·빌드를 담당한다. 언어 전환 자체가 렌더링 속도나 외부 입력의 안전성을 보장하지 않으므로 런타임 검증과 기존 보안 경계를 보존한다.

기존 ESM/CSS 유지 판단은 당시 구현 기록으로 보존하되 이후 개발 기준으로 사용하지 않는다. 기존 기능·저장 데이터·디자인을 보존하며 점진적으로 옮긴다. 스택을 바꾸기 위해 제품 전체를 초기화하지 않는다.

## 지속 적용

[PLAN §3.4](../plans/PLAN.md)의 상시 개발 기준이 코드 작성·경계·검증을 소유하고 §3.3이 일회성 전환 순서와 완료 조건을 소유한다. 새 개발 세션은 개발 가이드 §12에서 이 기준을 읽는다. 같은 규칙을 AI.md·SPEC·Design에 복제하지 않는다.

선택한 스택의 지원 종료·검증된 비호환·제품 요구를 충족할 수 없는 근거가 생기면 영향과 대안을 정리해 결정 변경을 검토한다. 단순 선호나 새 세션 시작을 이유로 확정 스택을 재선정하지 않는다.
