# ADR-002 · 배포 형태 — 개인 도구 → 사내

## 1. 배경

배포 형태(개인 도구 / 사내 / 상용)는 FR-17 설치 수용 환경, FR-18 기밀·권한 의무, FR-19 웹 검토 형태, OQ-07 확장 신뢰 범위, 호스트 SDK·애드인 배포 조건 조사(PRD R-20 / Codex R-40)의 공통 상류 결정인데 §18에 없었다(PRD R-55, 제안 OQ-09).

## 2. 선택지

| 안 | 내용 | 트레이드오프 |
|---|---|---|
| A | 개인 도구 → 사내 순서 | MVP 설치 조건이 최소. 서명·자동 업데이트·계약은 사내 시점으로 |
| B | 처음부터 사내 배포 | 피험자 확보가 쉽지만 설치 권한·애드인 로더·업데이트가 MVP에 들어옴 |
| C | 상용 배포 전제 | SDK 재배포 약관·서명·라이선스·지원 범위가 전부 MVP 전제 — 1인 규모에 가장 무거움 |

## 3. 결정

**A. 개인 도구로 시작하고 사내 배포로 확장한다.**

- MVP 설치 수용 환경(FR-17·AC-23) = 소유자 PC + 검증용 Windows 1대. 수동 애드인 등록을 포함한 설치·제거·작업 자료 보존까지가 수용 기준이다.
- 코드 서명·자동 업데이트·설치 권한 정책·사용 계약은 사내 배포 착수 시점의 결정으로 미룬다.
- 호스트 SDK·애드인 배포 조건 조사는 개인·사내 사용 범위만 확인한다. 상용 재배포 조건은 조사하지 않는다.

## 4. 근거

1인 팀에서 배포 형태가 곧 작업량이다. 개인 도구 단계에서 가설 검증(ADR-006)을 먼저 끝내고, 사내 배포는 검증 결과가 있을 때 결정한다.

## 5. 결과 — 적용 시 바꿀 문장

- PRD §1.3 주 작업자 문단에 배포 단계 한 줄, FR-17 수용 기준의 "실제 지원 환경" 정의, AC-23 시험 환경, §17 "설치 권한의 차이" 행.
- §18에 OQ-09 "사내 배포 착수 조건(서명·업데이트·권한 정책·SDK 조건 재확인)" 행을 추가하고 이 ADR을 링크한다.

## 6. 재검토 조건

동료 건축가 피험자(ADR-006)가 자기 PC에 설치해야 하는 시점이 오면 사내 배포 조건을 먼저 결정한다.
