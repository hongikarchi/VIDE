# SDK 코드와 도구를 사용하는 범용 AI 실행

## 결정과 근거

사용자가 지시한 공식 SDK API 조합·구독 에이전트·복수 호스트 제어 방향에 따라, 도구 없는 제한 JSON 제안과 고정 편집 템플릿을 최종 실행 방식으로 사용하지 않는다. AI가 코드를 구성하고 필요한 조회/실행/오류 수정을 반복하며 VIDE는 대상·권한·기준·결과 기록을 소유한다. [ADR-013](ADR-013-local-coordinator-cli.md)의 도구 없는 단발 응답 제한을 대체한다. 실제 연결 선택/실험은 [PLAN-02 §1~3·6](../plans/PLAN-02-agent-host-versioning.md), 동작 의미는 [SPEC-02.15](../specs/SPEC-02-execution-candidates.md)가 소유한다.

## 대안과 대가

제한 JSON을 계속 늘리는 방식은 예측 가능한 동작에 유리하지만 사용자의 범용 과업에 템플릿 구현이 계속 필요하다. CLI가 사용자 호스트에 직접 코드를 보내는 방식은 간단하지만 제품의 후보 보호·원본 적용·재개 기록을 그대로 제공하지 않는다. 범용 경로는 소유가 확인된 작업 실행본의 사본을 사용하고, 후보 확인 뒤 고정된 변경 이식 경로로 원본에 적용한다. 사본 생성·추가 프로세스·재조회/적용 시간이 늘어나는 대가를 측정한다. 같은 문서 후보를 허용한 ADR-003의 제품 범위를 폐기하지 않는다.

고정 동작 허용 목록이라는 통제를 포기하는 대신 소유 실행본/합성 문서 확인, 대상·기준·권한·중복 검사, 결과 재조회와 명시적 원본 적용을 둔다. 전용 프로세스는 OS 보안 샌드박스가 아니다. AI 생성 코드도 신뢰된 코드로 간주하지 않는다. 조회 권한에 임의 코드 도구를 주지 않으며 공개 업로드 코드 실행 서비스를 제공하지 않는다.

## 승인 범위와 남은 검증

범용 실행 방향은 사용자 지시이며 구체 실행기의 기술 검증은 남아 있다. 승인 범위는 범용 SDK 실행과 VIDE의 대상·권한·결과 기록 책임이라는 방향이다. 구체 실행기의 채택·성능·호스트별 보장은 PLAN-02의 비교와 실증을 따른다. 이 승인은 제품 구현 완료나 새 배포 권한이 아니다. 기존 TCP 경로의 소유 확인/실행 직전 검사, 라이선스·미저장 사본 보호, 공급자 개입/중단, 실제 후보·적용을 단계별 시험한다. 시험 실패 시 사용자 실행본으로 자동 대체하지 않는다. 제품 코드의 이행 상태는 PLAN §6.5가 정본이다.

## 후속 결정

- **2026-09-29 [ADR-020](ADR-020-jig-platform.md) 결정 4 — 적용 범위를 좁힘.** 위 결정의 "고정 편집 템플릿을 최종 실행 방식으로 사용하지 않는다"는 AI가 코드를 구성해 호스트를 고치는 AI 편집 경로에 적용한다. jig의 Rhino에 만들기(이후 공식 호스트 조작 틀 포함)는 VIDE가 소유한 고정 틀에 데이터 블록 하나만 넘겨 AI 없이 실행할 수 있다. 이 경로도 작업 실행본 → 후보 → 사용자의 원본 반영과 대상·기준·결과 기록을 그대로 거친다. AI 편집 경로의 결정·보호는 바뀌지 않는다. 근거: 2026-09-29 결정 목록 A7(에이전트 권고, 사용자 이의 없음).
- **2026-09-29 [ADR-021](ADR-021-conversation-sessions.md) — 실행 단위를 대화 세션의 턴으로 읽음.** 위 결정의 문구는 바꾸지 않는다. 대상·권한·기준·결과 기록을 VIDE가 소유하는 책임은 대화 세션의 턴마다 그대로 적용하고, 공급자 세션 이어 실행은 ADR-021의 SPIKE를 통과한 항목에만 켠다. 근거: 2026-09-29 사용자 결정(모든 대화를 세션으로).
