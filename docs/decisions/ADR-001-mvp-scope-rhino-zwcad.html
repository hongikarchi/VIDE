ADR-001 · MVP 범위 — Rhino·ZWCAD 두 호스트의 전체 흐름

초록 추가·교체 제안빨강 삭제·교체 대상CLAUDE: 파란 상자 · CODEX: 보라 상자

검토자 필터는 코멘트·부록만 바꿉니다. ‘인라인 제안 미리보기’는 코멘트의 대안까지 합친 최종본이 아닙니다. 보기 전환은 MD 수정·수락·승인을 하지 않습니다.

01 / 배경

PRD §4.1·§14.1은 Rhino·Revit·선정 CAD 전부의 네이티브 기본 제어와 확장·산출물·설치를 하나의 MVP 완료 조건으로 묶는다. 2차 검토(PRD R-56, Codex R-43, Claude R-47)는 이것이 1인+AI 에이전트·무마감 조건에서 검증 가능한 베팅 하나가 아니라 7개 하위 시스템의 포트폴리오이며, 첫 호스트 alpha가 무엇을 증명하면 다음으로 가는지 정의가 없다고 지적했다. 호스트 어댑터 3계열은 SDK·스레딩·문서 모델이 서로 달라 사실상 독립 서브프로젝트다.

02 / 선택지

안 내용 트레이드오프
A 현행 유지: 3계열 전부 + 확장 + 산출물 + 설치 플랫폼 정체성은 지키지만 1인 규모에서 완료 시점이 정의되지 않음
B 첫 호스트 수직 슬라이스 + 둘째 호스트 계약 증명(읽기 + 객체 1종 쓰기) 가장 작은 다중 호스트 베팅. 둘째 호스트의 실사용 가치는 늦어짐
C 두 호스트 모두 전체 흐름 평면 작성(ZWCAD)까지 MVP에서 쓸 수 있음. 작업량은 B의 약 두 배, ZWCAD .NET 호환성 위험이 MVP 안에 들어옴

03 / 결정

  • MVP 호스트는 Rhino와 ZWCAD 두 개다. Revit은 MVP에서 제외하고 후속 확장으로 둔다. AutoCAD는 ZWCAD 뒤의 후속이다(OQ-01은 "ZWCAD 먼저"로 닫힌다).
  • 두 호스트 모두 전체 흐름을 완료 조건으로 한다: 문서·객체 읽기 → 핀·스케치 입력 → 선언한 객체의 네이티브 생성·수정 → 호스트 기본 도구 재편집 → 저장·재열기 (PRD §14.2 흐름).
  • Rhino가 첫 호스트다. ZWCAD는 Rhino alpha 판정(ADR-006의 기준 과업 ① 통과) 뒤 착수한다.

04 / 근거

  • 소유자가 매일 쓰는 호스트(Rhino)와 평면 작성 대상(ZWCAD)이 첫 검증 사용자의 실제 작업 쌍이다.
  • Revit은 단일 UI 스레드·트랜잭션·워크셰어링(PRD R-16 / Codex R-36) 때문에 후보 격리·저장 의미가 가장 복잡하다. 이를 빼면 ADR-003의 후보 격리 원칙을 "호스트 안 격리 영역" 하나로 통일할 수 있다.
  • §2 가설 1·3·4·5·7은 첫 호스트 수직 슬라이스로 검증되고, 둘째 호스트는 어댑터 계약의 재사용을 증명한다.

05 / 결과 — 적용 시 바꿀 문장

  • PRD §0 요약표 "호스트" 행, §4.1, §14.1 호스트 범위표(Revit 행 → 후속, AutoCAD/ZWCAD 행 → ZWCAD 확정), §14.4, §16.1 "다중 호스트" 행, FR-02 수용 기준.
  • AI.md §3 호스트 파일 목록은 유지(rhino, revit, autocad, zwcad)하되 MVP 지원표는 hosts/rhino.md·hosts/zwcad.md만 먼저 쓴다.
  • 첫 SPEC 대상: SPEC-00-common 1차 + SPEC-01 핀(FR-05) + hosts/rhino.md 확인 사실 행.

06 / 축소·재검토 조건

  • Rhino alpha 판정(ADR-006)에서 기준 과업 ①이 수작업 대비 총시간·재작업 절감을 보이지 못하면 ZWCAD 착수 전에 이 결정을 재검토한다.
  • ZWCAD .NET SDK 호환성 스파이크가 "선언 객체 1종의 네이티브 쓰기·재편집·저장"을 통과하지 못하면 ZWCAD를 "계약 증명"(B안)으로 축소한다.

codexR-01높음 추가 지적. 실패 조건과 대안의 같은 전제. 두 호스트 전체 흐름과 Rhino 우선 선택은 존중한다. 다만 ZWCAD의 객체 1종 네이티브 쓰기·재편집·저장이 실패했을 때 B안으로 축소한다는 분기는 성립하지 않는다. B안도 같은 객체 쓰기를 요구하기 때문이다. 제안: 그 최소 쓰기 자체가 불가하면 해당 SDK/버전·연결 방식을 재검토하거나 ZWCAD 범위를 사용자와 다시 정하고, 최소 쓰기는 되지만 전체 과업만 어렵다면 B안을 검토한다. 스파이크 미완료·환경 부재는 실패와 구분한다. §2의 약 두 배 비용은 측정 전 가정으로 표시하고, Rhino alpha 뒤 ZWCAD 착수는 전체 구현과 사전 SDK·환경 확인 중 어디에 적용되는지 짧게 구분하면 된다.

07 / 출처

PRD R-56·R-57·R-47, Codex R-43, 가이드 Codex R-32. 2026-09-17 brainstorming Q&A.

07 / 부록 · Codex 검토 요약 (2026-09-17)

Rhino·ZWCAD 전체 흐름을 선택한 방향을 다시 축소할 것을 요구하지 않는다. 확정 전에 고칠 핵심은 실패 시 선택할 대안이 실패한 전제를 그대로 요구하는 모순이다.

이번 검토는 사용자 수락이나 본문 반영을 뜻하지 않는다. 기존 스레드는 같은 ID로 갱신하고, 새 지적은 별도 ID를 부여한다. 철회 기록은 상대 참조가 정리될 때까지 남긴다.
