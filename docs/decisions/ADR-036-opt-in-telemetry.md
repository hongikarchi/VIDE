# 오류·성능 정보 — 동의한 설치만 자동 요약 전송

## 결정

2026-10-06 사용자 결정: 다른 사용자의 설치본에서도 오류·성능 보고를 받되, **설치할 때(처음 실행할 때) 동의한 경우에만** 자동으로 보낸다("설치할 때 동의하면 가능하도록"). 아래 1~6은 이를 구현하기 위한 구체화이며 사용자 확인을 기다린다(`status: review`). 동작은 [SPEC-05](../specs/SPEC-05-extensions-install.md).9, 화면은 [Design](../../Design.md) SCR-22, 물리 계약은 [ARCH-01](../architecture/ARCH-01-system.md) §6 「오류·성능 보고」, 작업은 [PLAN-34](../plans/PLAN-34-telemetry.md)(T-155~T-159)다. 진단 기록 자체는 [ADR-031](ADR-031-stock-first.md) 9(T-126)를 그대로 쓴다.

1. **답하기 전에는 보내지 않는다.** 설치본(PC 프로그램)의 첫 실행 — 이번 갱신 뒤 기존 설치의 첫 실행 포함 — 에 창의 첫 대화상자로 "오류·성능 정보를 자동으로 보내 VIDE 개선에 도움 주기"를 묻는다. [동의]·[보내지 않음] 둘 중 하나로만 닫히고(Escape로 닫히지 않음), 답하기 전에는 아무것도 보내지 않는다. 선택과 무작위 설치 번호(UUID)는 데이터 폴더의 `telemetry.json`에 두고 VIDE 계정과 연결하지 않는다. 설정 › 상태 · 오류의 [진단 묶음 내보내기] 옆 스위치로 언제든 바꾼다. 다른 기기(원격 접속)·호스트 패널에서는 묻지도 바꾸지도 않는다.
2. **동의 뒤의 기록만, 요약만.** 보내는 것은 T-126 로그에서 만든 이름 없는 요약이다: VIDE·플러그인·호스트·Windows 버전, CPU 수·메모리 크기, 설치 번호, 부분별 이벤트 수, 실패 줄(같은 종류는 합침), PC 프로그램이 기록한 비정상 엔진 종료 코드, 시간·메모리 수치(p50·p90·최대). 동의한 시각 이전의 줄은 넣지 않는다.
3. **거부 목록이 아니라 허용 목록.** 이벤트 종류마다 가져갈 수 있는 필드와 그 형식(코드·단어·정수·버전·경로 패턴·문장·스택)을 정해 두고, 목록에 없거나 형식이 맞지 않는 필드는 버린다. 요청·프로젝트·연결·대화 ID는 가져가지 않는다. 문장(오류 메시지·스택·CLI 오류 끝부분)은 키·토큰을 지운 뒤 경로(드라이브·UNC·POSIX, 공백 포함)·주소·이메일·따옴표 안 글자·문서 파일 이름·ASCII 밖 글자(한글 이름·프로젝트·요청 글)·긴 ID·Windows 사용자 이름·PC 이름·프로젝트 이름을 자리표시로 바꾼다. 스택은 VIDE 소스 위치(`src/…`, `hosts/…`)만 남긴다. 사이트도 경로·사용자 폴더·이메일이 남은 보고는 저장하지 않는다(이중 방어).
4. **작게, 모아서, 다시.** 요약은 시작할 때(지난 묶음에서 1시간 이상 지났을 때)와 하루 한 번 만들어 32 KB 상한을 넘으면 스택 → 실패 → 수치 순으로 줄이고 `truncated`로 알린다. 보내기 전까지 `<데이터>\telemetry-outbox`에 두고(최근 14개) 연결이 안 되면 1시간마다 다시 보낸다. 사이트가 형식·크기·내용 때문에 거절(400·413·415·422)하면 버리고, 한도(429)·엔드포인트 없음(404, 사이트 배포 전)·서버 오류·연결 실패는 남긴다. [보내지 않음]으로 바꾸면 남은 묶음도 지운다.
5. **큰 자료는 자동으로 보내지 않는다.** 진단 묶음과 충돌 덤프는 자동 전송하지 않는다. PC 프로그램이 기록한, VIDE가 요청하지 않은 엔진 종료(0·콘솔 종료·강제 종료 코드 제외)가 있으면 다음 화면에서 한 번 "진단 묶음을 보낼까요?"를 묻고 들어가는 것을 보인다. [보내기]일 때만 최근 3일 묶음(8 MB 이하)을 올리고, 덤프는 사용자가 체크할 때만 넣는다(95 MB 이하). 사이트의 묶음 받기는 스위치(`TELEMETRY_BUNDLES_ENABLED`)가 켜질 때만 동작하며 R2 정리가 끝날 때까지 **꺼 둔다** — 그동안 [보내기]는 묶음 파일을 이 PC에 만들고 경로를 보인다.
6. **사이트와 읽기.** 요약은 D1 `telemetry_reports`(마이그레이션 0010)에만 둔다(180일 보관). 공개 `POST /api/telemetry/reports`는 계정·쿠키 없이 받되 크기(48 KB)·설치당 하루 24건·주소당 하루 300건으로 제한한다. 보고 화면(`/?admin=reports`)과 관리자 API·CSV는 사이트 관리자(`ADMIN_USERS`)만, 개발 도구 `tools/diagnostics/reports.mjs`는 비밀 `TELEMETRY_ADMIN_TOKEN`(환경 변수, 저장소에 넣지 않음)으로 읽는다.

## 맥락

- T-126(ADR-031 9)으로 각 PC에 진단 기록이 남지만, 다른 사용자의 설치에서 생긴 문제는 사용자가 [진단 묶음 내보내기] 파일을 직접 보내야만 볼 수 있었다. 2026-10-06의 `0xC0000409` 종료(libuv#5274)처럼 원인을 찾으려면 여러 설치의 종료 코드·버전이 필요했다.
- PRD FR-18(데이터 보호·전송 권한)은 전송 항목의 고지와 끄기를 요구한다. 이 결정은 그 요구 안에서 사전 동의(opt-in)를 택한다.
- 사용자가 R2를 정리하는 중이라 큰 파일 저장은 미룬다. 작은 요약은 D1 행으로 충분하다.
- 개인정보 처리 안내(동의 화면의 목록과 사이트 `/privacy`, 문구 원본 `src/contracts/telemetry-notice.ts`)는 **초안**이다. 많은 사용자에게 배포하기 전에 법률 검토(개인정보 보호법상 수집 항목·보관 기간·국외 이전 고지 등)를 받는 것을 권한다.

## 선택지

| 질문 | 안 | 판단 |
|---|---|---|
| 기본값 | 기본 전송(opt-out) / 묻기 전 미전송(opt-in) | opt-in(사용자 결정). 답하기 전·거부 뒤에는 아무것도 보내지 않는다 |
| 개인정보 제거 | 거부 목록(키·경로 패턴만 지움) / 필드 허용 목록 + 문장 정리 | 허용 목록. 새 로그 필드가 생겨도 자동으로 보내지지 않는다 |
| 식별 | 계정 ID / 무작위 설치 번호 | 무작위 설치 번호. 같은 설치의 반복 문제는 묶어 볼 수 있고 사람과는 연결되지 않는다 |
| 큰 자료 | 충돌 때 자동 업로드 / 매번 묻기 | 매번 묻기, 덤프는 체크할 때만. 사이트 쪽은 스위치로 꺼 둔다 |
| 저장소 | R2에 JSON 파일 / D1 행 | D1 행(작고 질의·CSV가 쉬움). 묶음만 R2 |
| 분석 | 외부 분석 서비스 / 자체 관리자 화면·도구 | 자체. 제3자에게 넘기지 않는다 |

## 결과

- 사용자는 설치본의 첫 실행에 한 번 답하고, 설정에서 바꾸며, [보낼 내용 보기]로 다음 요약을 미리 본다. 충돌 뒤에는 묶음 전송을 따로 묻는다.
- 개발자와 Claude는 `node tools/diagnostics/reports.mjs`로 버전별 설치 수·실패 종류·종료 코드·주요 시간을 읽고, 사이트 보고 화면에서 날짜·버전·종류로 거르고 CSV를 받는다.
- 남은 위험: (1) 문장 정리는 휴리스틱이다. 경로 밖에 맨 영어 이름이 그대로 나오는 오류 문장은 지우지 못할 수 있다(사용자 이름·PC 이름·프로젝트 이름은 따로 지운다). (2) 사이트 배포(마이그레이션 0010 원격 적용, 비밀 설정) 전에는 보고가 엔진의 보낼 상자(최근 14개)에 쌓여 기다린다 — 배포를 먼저 하고 설치본을 낸다. (3) 문구는 법률 검토 전이다.
