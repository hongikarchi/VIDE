# jig 관리자 제출

## 결정

2026-10-07 사용자 메모와 선택이다.

> 사용자가 채팅으로 수정하면 기본 틀 안에서 알잘딱하게 바뀌고, 본인이 수정한 프로그램을 쉽게쉽게 공유할 수 있으면 좋겠음 … 관리자한테 내가 이런거 만들었는데 전체 내용으로 업데이트해줄래? 하고 보내주면 적용해서 업데이트 사항으로 공식 배포하는 방식

선택지 가운데 **'제출 기능까지 구현'**을 골랐다.

1. **수명 단계의 '공유'를 '관리자 제출'로 좁힌다(SPEC-07.3).** 순서는 초안 → 프로젝트 → **관리자 제출** → 공식이다. 공식은 VIDE 설치본에 포함된 jig다.
2. **제출 경로**
   1. 사용자가 만들기 탭이나 설치된 jig에서 [관리자에게 제출]을 누른다.
   2. VIDE가 그 jig의 pack을 만든다.
   3. 사용자 확인(T2)을 받은 뒤 메모와 함께 계정 사이트로 올린다.
   - 원격 터널에서는 거절한다.
3. **관리자 제출함**
   - 계정 사이트의 관리자만(`ADMIN_USERS`) 제출 목록을 본다.
   - 관리자는 pack을 받고, 상태를 받음, 검토 중, 반영됨, 반려(사유)로 바꾼다.
   - 제출한 사람은 자기 제출의 상태만 본다.
4. **반영은 저장소를 거친다.**
   - 관리자는 `npm run jig:unpack`으로 pack을 저장소의 `extensions/jigs/<id>/`에 풀어 검토한다.
   - 반영한 jig는 다음 공식 배포에 포함된다.
   - 다른 사용자 PC에 직접 설치하는 경로는 만들지 않는다. 그래서 '다른 PC에서 만든 pack은 설치하지 않음'(SPEC-07.15)은 그대로다.
   - 무결성은 사이트에 기록된 digest로 확인한다.

## 맥락

- pack은 PC별 HMAC으로 서명된다. 그래서 다른 PC가 그대로 설치할 수 없다(ARCH-03).
- 계정 사이트에는 host key 인증, R2, D1이 있다. 관리자 확인(`isAdminName`)은 오류·성능 보고에만 쓰였다(ADR-036).
- ADR-037은 '사이트 jig 저장소'를 별도 결정으로 미뤄 두었다. 이 ADR은 그 가운데 관리자에게 보내는 경로만 정한다. 모든 사용자에게 바로 게시하는 저장소는 여전히 범위 밖이다.

## 결과

- PRD §14.2의 제외 문구에서 'jig의 게시·다른 PC 또는 사용자와의 공유'는 '관리자 제출을 뺀'으로 좁힌다.
- 다음 문서가 이 결정을 따른다.
  - SPEC-07.3과 §18
  - SPEC-04의 사이트 장치 API
  - ARCH-01 §6
  - Design의 만들기 탭과 관리자 제출함
  - [PLAN-43](../plans/PLAN-43-section-finish-xref-submit.md) T-201
- 사이트 배포(D1 migration, Worker 배포)는 사용자가 확인한 뒤에 한다.
