# 순정 우선

## 결정

2026-10-02 사용자 결정. 터미널에서 Claude Code·Codex를 Rhino MCP와 함께 쓸 때보다 VIDE 안에서 작업이 더 자주 막히고 오류가 난다는 판단("안 만들어도 될 제약을 만들고, 기본적으로 있는 도구를 새로 만들고")에서 나왔다. **승인 범위:** 1~4는 사용자가 받아들인 방향이고, 5·6은 같은 날 사용자가 고르게 한 구체화다. 작업은 [PLAN-28](../plans/PLAN-28-stock-first.md), 대조 목록은 [RESEARCH-14](../research/RESEARCH-14-stock-first-audit.md)이다.

1. **AI 경로는 순정 그대로.** AI는 열린 호스트 문서를 직접 조회·실행하고 CLI 기본 도구를 그대로 쓴다. VIDE의 저장본(Sync 기록)을 거쳐야만 일할 수 있게 만들지 않는다.
2. **VIDE는 터미널에 없는 것만 더한다.** 화면, 핀, 요청 단위 되돌리기, 이력이다. 이것들이 AI 작업을 막지 않게 한다.
3. **상한은 실제 물리적 한계에만 둔다.** 모델 문맥 크기, 호스트 응답 한 덩어리(프레임) 같은 것이다. 넘으면 실패시키지 않고 잘라서 알린다. 새 검사·상한을 넣을 때는 "순정 터미널에도 있는가"를 먼저 묻는다.
4. **있는 상한·자체 도구를 대조해 걷어낸다.** RESEARCH-14의 목록에서 하나씩 사용자가 판단한다.
5. **모델 전체를 JSON으로 주고받지 않는다.** 저장(객체 단위, 바뀐 것만)과 Live Sync는 이미 그렇다(PLAN-27 T-083·T-084). 남은 경로(⟳ 응답, 요청 목록의 객체 줄, AI 턴의 모델 재조립, AI 조회의 문서 전체 재읽기, Rhino→엔진 전체 읽기)를 바이너리·바뀐 것만으로 바꾼다.
6. **실행 이력은 새 도구 없이.** 적용된 실행의 본문을 자르지 않고 요청 결과에 남긴다(`executions[].body`). AI가 읽는 경로는 프로젝트별 DB 분리([ADR-032](ADR-032-per-project-database.md)) 뒤 그 프로젝트 폴더를 읽기 전용으로 여는 것이며, 전용 조회 도구는 만들지 않는다.

## 맥락

2026-10-02 실사용에서 다음이 이어졌다. 1만 개 가까운 객체의 건축 파일에서 Sync가 총량 상한(`HOST_RESULT_TOO_LARGE`)에 걸려 계속 실패했다. AI 조회도 같은 이유로 실패했는데, AI에게는 원인 대신 `AGENT_TOOL_FAILED`만 보였다. 엔진이 종료되면서 남은 '결과 미확인' 때문에 실행 전에 조회부터 하라는 거절을 받았지만, 조회가 실패하니 AI는 멈췄다. 07~15 대안을 다시 만들려 했지만 실행 코드는 활동 기록에 4,000자까지만 남아 있었다. 엔진 비정상 종료(`0xC0000409`)는 94MB ⟳ 응답, 26.8MB 요청 목록, 수십 MB 옛 행 이전과 시간이 겹쳤다. 터미널 순정 구성은 문서를 통째로 복사하지 않고 필요한 것만 묻기 때문에 이런 큰 데이터 이동이 없다. 순정에도 MCP 출력 상한(약 25k 토큰)은 있지만, 넘으면 잘라서 줄 뿐 실패시키지 않는다.

## 결과

- 엔진은 모르는 오류 코드를 AI에게 그대로 전한다. 코드 없는 예외의 문구는 경로·자격 노출을 막기 위해 계속 감춘다.
- Sync는 문서 총량 상한 없이 페이지로 읽는다. 객체 하나가 호스트 응답 한 덩어리(16MB)를 넘을 때만 실패한다.
- ⟳ 응답은 형상 없는 요청(객체 줄)만 보내고, 화면은 형상을 바이너리로 받는다.
- 화면·저장 경로를 바꾸는 항목은 PLAN-27(T-085·T-086)과 겹치므로 그 작업과 순서를 맞춘다.
