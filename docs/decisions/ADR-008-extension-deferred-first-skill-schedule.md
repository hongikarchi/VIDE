# ADR-008 · 최소 확장과 기본 데이터 능력

## 1. 확장에 대한 결정

첫 출시는 개발자가 제공하는 작은 확장을 등록·실행·비활성화할 수 있는 최소 확장 기능을 제공한다. 확장은 프로젝트 문맥·입력·허용 도구와 권한·진행·결과·실패를 공통 기반과 연결한다.

빈 슬롯이나 등록 화면만이 아니라 작은 확장 하나의 실제 실행까지 완료 범위다. 전문 자동화 스킬의 완성, 공개 마켓·결제와 임의 비신뢰 코드 실행은 포함하지 않는다. 실제 전문 스킬 요구에 따라 계약을 보완할 수 있으며 모든 미래 기능을 예측한 영구 SDK를 요구하지 않는다.

## 2. 기본 데이터에 대한 결정

지원 객체의 속성·수량 조회와 기본 필터·그룹·집계·표 갱신을 MVP에 포함한다. 대상·단위·출처·계산 기준·기준 버전을 결과와 연결하며, 관련 입력이 변경되면 유효성을 구분하고 갱신할 수 있어야 한다.

모든 실시간 자동 계산, 법규 해석을 포함한 전문 면적 산정, 분야별 일람표 자동 작성은 이 능력에 포함하지 않는다. 층 구분이 없는 매스에서 층별 면적을 임의로 정하지 않는다.

기본 집계를 코어 또는 신뢰된 기본 확장으로 제공하는 것은 SPEC·PLAN의 선택이다. 구현 위치가 달라도 FR-22의 제품 능력은 제공되어야 한다.

## 3. 선택하지 않은 안과 근거

확장 가능한 내부 구조만 만들고 실제 등록·실행을 후속으로 미루는 안은 채택하지 않았다. IDE를 만든 뒤 전문 기능을 하나씩 붙인다는 사용 방식을 작은 실제 확장으로 확인한다.

첫 시험 확장의 종류·실행 형태, 첫 전문 스킬을 일람표로 고정하는 순서는 확정하지 않았다. 선택 객체 속성 요약은 설명 예시이지 정해진 유일한 구현 과업이 아니다. 이를 OQ-07에서 관련 단계에 구체화한다.

## 4. 기준 문서

PRD §12.3·FR-13·AC-26이 최소 확장을, §6.6·FR-22·AC-34가 기본 집계를 소유한다. FR-21은 전문 스킬의 후속 범위로 유지한다. SPEC은 실제 입출력·권한·상태·계산을, PLAN은 기술·패키징·코어 경계·시험 구현을 정한다.

호스트 쓰기·외부 자료 반입·전송 보호는 공통 규칙이다. 신뢰된 확장이라는 이유로 해당 보호를 끄지 않는다.

## 5. 승인 근거
