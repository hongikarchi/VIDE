# ADR-010 · 같은 프로젝트를 웹에서 검토한다

## 1. 웹 작업 공간 공유

로컬 IDE와 공통 화면·표시 기능을 활용하여 같은 프로젝트의 허용된 상태를 웹에서 열람하게 한다. 공개 범위를 정하고 링크로 공유하며, 권한 있는 사용자는 모델·도면·표·후보·작업 상태를 탐색한다.

공유하는 프로젝트 상태와 개인의 카메라·선택·패널을 구분한다. HTML 화면을 호스팅하는 것만으로 상태 갱신이 구현된 것으로 보지 않는다. 발표자 따라보기나 선택·카메라 동기화는 이 결정에 포함하지 않는다.

## 2. 최신 상태·단절·수작업 변경

AI 작업과 호스트에서의 수작업 변경 모두 허용된 공유 대상의 갱신에 포함한다. 작업을 멈추거나 로컬 호스트와 연결이 종료되어도 마지막으로 공유 저장이 완료된 상태는 권한 있는 사용자가 계속 열람할 수 있어야 한다.

나중에 공유 갱신이 완료되면 같은 프로젝트 링크에서 새 상태를 제공한다. 마지막 갱신 시점과 갱신 중·단절·미전송 상태를 드러내고, 전송되지 않은 원본 변경을 최신 공유 상태로 표시하지 않는다.

원본 수정·원본 파일 저장·IDE 확인·웹 공유 반영은 같지 않다. 공유 갱신의 감지·전송 주기·서버 저장·연결 구조는 SPEC·PLAN에서 정한다. 작업 PC가 꺼져도 과거 공유본을 보는 것과 꺼진 호스트에서 새 계산·쓰기를 실행하는 것은 다르다.

## 3. 웹 의견과 실행 권한

권한 있는 웹 참여자는 객체·위치에 문장·핀·스케치로 의견을 남긴다. 작성 당시 기준 버전·대상·원본 입력을 보존한다. 현재 모델과 대응을 확인하지 못하면 끊김을 표시하고 임의의 가까운 객체에 재연결하지 않는다.

로컬 설계자는 같은 프로젝트에서 의견을 검토하고 작업에 연결할 수 있다. 의견 제출이나 채택 자체는 AI 실행·원본 반영 승인이 아니다.

첫 출시의 외부 웹은 열람·탐색·의견 작성으로 제한한다. AI 작업 시작·진행 중 개입·중단·원본 반영 승인은 로컬 IDE에서 수행한다. 설계자 본인이 다른 기기로 접속해도 같은 경계를 적용한다. 작업 PC에서 사용하는 브라우저 기반 로컬 화면을 원격 제어로 오해하지 않는다.

## 4. 과거 검토본

사용자가 주요 작업 상태를 검토본으로 남기고, 보존한 모델·도면 표현·관련 표·검토 상태를 다시 열람하거나 현재 상태와 기본 비교할 수 있어야 한다. 대상·기준 시점·원본/후보·호스트별 적용/저장 상태를 함께 보존한다.

외부 사용자는 허용된 검토본만 열람한다. 과거 검토본의 열람은 현재 원본 변경이나 자동 복원이 아니다. 모든 편집 순간의 영구 보관, 고급 대안 트리·자동 병합·네이티브 복원까지 요구하지 않는다.

## 5. 별도 파일 내보내기

기본 표 데이터는 외부 도구에서 재사용할 수 있는 파일로 내보내고, 선택한 검토본의 모델·도면 이미지·기본 표·설명·검토 상태를 요약한 파일을 보관·전달할 수 있어야 한다.

파일은 기준 시점·포함 범위·계산 근거·미확인 사항·포맷 제한을 표시하고 이후 원본 변경을 자동으로 따라가지 않는다. 실제 포맷은 OQ-08과 SPEC에서 정하며 CSV·XLSX·HTML·PDF 등의 설명 예시 전부를 지원 확정으로 삼지 않는다.

웹의 최신 상태를 보기 위해 매번 파일을 내보내는 절차를 요구하지 않는다. 원본 네이티브 저장·웹 공유·과거 버전 열람·파일 내보내기는 별개 능력이다. C-01 즉석 HTML 생성·부분 선택 편집은 여전히 미채택 후보다.

## 6. 기준 문서

PRD §12.4~§12.6·§14.2~§14.4 및 FR-12·14·19가 정본이다. 기기·브라우저·입력 환경은 ADR-002와 OQ-04, 파일 형식은 OQ-08에서 구체화한다. 웹은 후속이라는 옛 범위 태그와 AC-19·28의 일괄 해당 없음 처리는 적용하지 않는다.

이 결정은 공통 화면 재사용의 제품 방향이며 특정 프레임워크·호스팅·인증·네트워크·저장 구현을 승인한 것은 아니다. 실제 권한과 공개 범위는 구현 및 검수에서 지켜야 한다.
