# 첫 실행은 VIDE 계정 로그인부터

## 결정

2026-10-06 사용자 결정 세 가지.

1. **로그인 필수.** 사용자: "처음에 딱 깔면, 로그인 화면이 나와야 하는거 아닌가? 왜 바로 새 프로젝트가 만들어지고 시작하는거지?" 선택지(로그인 필수 / 권장하되 건너뛰기) 가운데 **로그인 필수**를 골랐다. 설치한 VIDE의 첫 화면은 VIDE 계정(사이트 아이디) 로그인이고, 로그인하지 않은 PC는 작업 화면에 들어가지 않는다. 로그인 뒤 프로젝트를 고르거나 이름을 넣어 만든다. 프로젝트를 묻지 않고 만들지 않는다.
2. **원격 접속 도구(cloudflared)는 켤 때 자동으로 받고, 처음 설치 때도 미리 받는다.** 사용자: "1번(켤 때 자동 다운로드, 로그인해도 원격 기본 끔)으로 하되, 처음에 설치할 때 자동으로 같이 설치되도록 할 수는 없나?" 설치본에 넣지 않고(크기 약 53 MB), 설치 직후 첫 실행 때 엔진이 공식 배포처에서 고정 판을 받아 확인값을 검사한 뒤 데이터 폴더에 둔다. 그때 받지 못했으면 원격 접속을 켤 때 다시 받는다.
3. **로그인해도 원격 접속은 기본 끔.** 로그인은 사이트의 프로젝트 목록·PC 상태만 연결하고, 다른 기기에서 열기(터널)는 사용자가 켤 때만 연다.

## 맥락

- 이전 정본(SPEC-04.11 1)은 사이트 로그인을 선택으로 두었고, 첫 실행은 프로젝트가 없으면 '새 프로젝트'를 묻지 않고 만들었다. ADR-037 1로 프로젝트 목록의 원본이 사이트가 된 뒤에는 빈 로컬 프로젝트가 먼저 생겨 사이트 목록에 올라가는 흐름이 어긋났다.
- 설치본에는 cloudflared가 없고 로그인만 해도 원격 접속이 켜져, 원격을 쓰지 않는 새 PC에서도 '원격 접속 도구(cloudflared)가 설치되지 않았습니다.'가 떴다.

## 결과

- PRD §8.1, SPEC-04.11 1, SPEC-05.6·05.7, Design SCR-26, ARCH-01 §6 「원격 접속 도구」, [PLAN-38](../plans/PLAN-38-onboarding.md)이 이 결정을 따른다.
- PRD §1.3의 Local-first(로컬 입력·기록·호스트 제어를 작업환경이 관리)는 그대로다. 로그인은 작업 화면에 들어가는 조건일 뿐 작업 자료를 사이트로 옮기지 않는다(ADR-037의 공유 범위 그대로). 한 번 로그인한 PC는 사이트에 닿지 않아도 기존처럼 열린다.
- cloudflared는 사용자 PC가 공식 GitHub 릴리스에서 직접 받는다(Apache-2.0). VIDE 설치본은 이를 재배포하지 않는다.
- 개발 서버(`npm run dev`)와 자동 시험의 서버는 이 게이트와 미리 받기를 켜지 않는다. 설치한 PC 프로그램이 띄우는 엔진만 켠다.
