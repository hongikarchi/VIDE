대화 열 + 무대, jig = skill 자동 시작, 고정 코랄 포인트 하나

00 / 결정

2026-10-01 사용자 결정. 조사·대안 비교는 RESEARCH-12이다. 승인 범위: 결정 1~4·6·7은 확정이다. 결정 5(화면 구조)는 방향만 승인했고, 배치·치수는 정적 목업 검수(VERIFY) 뒤에 Design §03에서 확정한다.

  1. 프로젝트별 색을 두지 않는다. 프로젝트마다 --accent를 바꾸는 방식(참고 앱 A식)도, 프로젝트 이름 옆의 프로젝트 점도 두지 않는다(RESEARCH-12 §3.3의 B안과 'A + 프로젝트 점' 안을 버림).
  2. 포인트 색은 고정 코랄 하나(--accent)다. 허용 위치 목록(AI 실행 중 점·체크 목록의 현재 단계 점, 무대 전환 순간의 외곽선 한 번, 작성기 대상 칩, 뷰포트 선택과 AI가 방금 만진 객체의 외곽선, 포커스 링·::selection, 보고서·KPI의 실현값)에만 쓰고, 선택 행·탭·주 버튼·판정·넓은 면에는 쓰지 않는다. 정본은 Design §02.
  3. CSS를 토큰층 + 리터럴 정리로 다시 세운다. RESEARCH-12 §3.2 토큰표(프로젝트 색 제외)를 쓴다: 무채 웜 그레이 바탕과 글자 4단계, 모든 선 0.5px, 본문 13px(10px 이하 폐지), 모서리 6/10/14, 그림자 한 종, 판정색 --ok·--warn·--ng와 정보색 --info를 포인트 --accent와 분리, 왼쪽 색 막대 금지, 주 버튼은 검정(--cta-bg). 기존 이름(--ink·--muted·--line·--soft·--coral·--paper)은 새 토큰의 별칭으로 남긴다. 어두운 값은 지금처럼 호스트 패널의 어두운 테마에만 쓴다(앱 전체 어두운 모드는 이 결정 밖).
  4. 요청이 jig로 판정되면 자동으로 열고 계산한다. 판정 → 작업본(마지막 것 재사용, 없으면 기본 출력 레이어 VIDE/{jig}/{n}으로 생성) → jig 화면 열기 → 대화 묶기 → 원장 기록 → 요청에서 읽은 설정값 적용 → 첫 사람 단계 앞까지 미리보기 계산 → 결과 요약까지 한 번에 한다. 모호한 것은 질문 카드로 묻는다. 질문은 공급자 자체 질문 기능(예: Claude의 AskUserQuestion)을 기본으로 쓰고, 지원하지 않는 공급자·경로는 VIDE 카드로 대신한다. 잘못 판정됐으면 경로 줄의 [일반 대화로] 한 번으로 되돌린다. 계획 모드는 jig를 열고 대화를 묶는 데까지만 하고, 계산·설정값 적용은 체크리스트와 [진행] 뒤에 한다. 해석 확정(M)과 Rhino에 만들기(T2)는 계속 사람만 누른다.
  5. 화면은 대화 열 + 무대로 바꾼다(방향 승인). 상시 면을 대화 열과 무대 둘로 줄이고, 무대 머리의 연결 점, 접히는 무대 왼쪽 슬롯, [원래대로], 턴 블록 문법, '대기' 묶음, 빈 무대의 프로젝트 보드를 접붙인다(RESEARCH-12 §6.1). 정적 HTML 목업(tools/mockups/chat-stage/)을 사용자가 검토한 뒤에 셸을 바꾼다. 2026-10-01 조정: 목업이 실제 코드와 달라 무엇이 구현됐는지 헷갈린다는 사용자 판단으로 목업은 폐기했다. 셸은 한 번에 바꾸지 않고, 사용자가 명시한 항목만 지금 배치 위에 하나씩 반영하며(레일 대시보드·프로젝트 자료·피드백·다크/라이트, 연결 파일 행, 글꼴·아이콘, 산출물 탭 — PLAN-26 T-079·T-081), 화면 검토는 실제 빌드를 찍은 미리보기(tools/mockups/ui-preview/)로 한다.
  6. 프로젝트 jig도 AI·Jev가 스스로 부를 수 있다. 공식 jig와 이 프로젝트에 고정된 jig는 기본으로 자동 호출 대상(invocation: auto)이고, 초안은 사용자만 연다. 같은 말에 여러 jig가 맞으면 프로젝트 jig를 레거시·공식 jig보다 먼저 고른다(예: S-06의 "구조 분석" → project/s06-frame).
  7. 순서: 목업 검토가 먼저이고 셸 교체는 그 뒤다. 단계 0(jig 자동 시작)과 토큰·CSS 정리는 지금 배치에서 먼저 한다.

skill 계약(결정 4·6의 물리 형태). jig = skill은 공급자 CLI의 skill 기능이 아니라 VIDE 내부 계약이다. 새 파일 없이 기존 skill.md 앞머리와 jig.json v3에 필드를 얹는다. skill.md: description(한국어, 무엇 + 언제), examples, invocation: auto | user-only(공식·프로젝트 jig 기본 auto), 기존 words·not_for. jig.json(모두 선택): open: { reuse: "last" | "new", layerRoot }, autorun: { until: <stepId> | "first-hard" }(기본 first-hard), from_request: [paramId…], summary: { kpi: […] }. 동작 정본은 SPEC-07.18, 필드·로더·AI 도구(jig_open·ui_go)는 ARCH-03 §5.3.

01 / 맥락

  • 작성기에 "구조 분석"을 보내면 "'구조 분석' jig를 열까요?" 카드에서 멈췄고, [열기]를 눌러도 작업본·문맥 탭·대화 연결·원장 기록이 일어나지 않았다. 이 카드는 결함이 아니라 문서 결정(SPEC-02.17의 2, SPEC-02.19의 7, RESEARCH-10 §16 B7)을 따른 결과였다(RESEARCH-12 §2.3).
  • 라우팅 후보는 하드코딩된 세 개였고 프로젝트 jig의 skill.md는 후보에 들어가지 않아, S-06에서 "구조 분석"이 레거시 구조 jig로 갔다. 대화에 jigInstanceId를 넘기는 곳이 없어 AI 도구 jig_set·jig_run이 실사용에서 닿지 않았다.
  • 러너에는 이미 until·preview·입력 지문 통과가 있어, 자동 시작의 추가 비용이 작다(RESEARCH-12 §2.3 「이미 있는 것」).
  • 시각 부채: 16진 리터럴 327회, 모서리 17종·그림자 16종, 포인트 코랄과 초과 --ng·뷰포트 선택색이 거의 같아 '선택'과 '초과'가 헷갈렸다. 왼쪽 색 막대 7곳이 사용자 규칙을 어겼다(RESEARCH-12 §2.2).
  • 외부 사례에서는 '단어 판정 → 제안 카드 → 사용자 대기'를 기본값으로 쓰는 제품을 찾지 못했다. 신뢰는 사전 확인이 아니라 즉시 실행 + 되돌리기로 얻는다(RESEARCH-12 §4 E2·E6·E7).

02 / 선택지

화면 구조는 RESEARCH-12 §5의 세 안을 비교했다(세 관점 채점 평균, 50점 만점).

안 내용 합계 판단
1 chat-first 상시 면은 대화 열과 무대 둘. AI가 무대를 모델·jig·문서로 바꾼다 33.0 채택(뼈대). 사용자 의도·단순함·skill 흐름 점수가 가장 높다. 셸 전면 교체(L)와 발견성 검증이 대가다
2 workspace-first 고정 작업면 4개 + 모든 작업면의 대화 도크 31.8 뼈대로는 버림. 면이 5~6개로 남고 고정 작업면이 미래 jig를 담지 못한다. 연결 점·접히는 왼쪽 슬롯·[원래대로]·ui_go만 접붙인다
3 task-first 모든 요청이 런 카드, 동적 무대 탭 최대 12개 27.0 버림. 서버 오케스트레이터·SSE 신설과 탭 난립이 대가다. 턴 블록 문법·'대기' 묶음·프로젝트 보드만 접붙인다

jig 판정 뒤 처리(RESEARCH-12 §8.2 Q1)는 (a) 제안 카드 유지, (b) [열기]가 실제로 끝까지 열기, (c) 자동으로 열고 계산 중 (c)를 골랐다. 포인트 방식(§3.3)은 A 고정 코랄, B 프로젝트별, C 화면별, A + 프로젝트 점 중 A를 골랐다(권고였던 'A + 프로젝트 점'에서 점도 뺐다). 자동 호출 범위(Q4)는 (c) 공식 + 검증 이상 + 프로젝트 jig를 골랐다. 1차에는 공유·검증 단계가 없으므로(SPEC-07.3) 실제 대상은 공식과 프로젝트 jig다.

03 / 결과

  • "말하면 화면도 작업도 움직인다." jig 요청은 카드 없이 미리보기 결과까지 간다. 오판정의 비용은 VIDE 내부 계산뿐이다. Rhino 쓰기는 사람이 누르는 Rhino에 만들기 전에는 없고, [일반 대화로] 한 번으로 복구한다.
  • 확인 경계가 바뀐다. 지금까지 'Jev 판정만으로 누르지 않고 실행하는 것은 설정값 변경뿐'이었다. 이제 jig 열기·무대 이동·작업본 재사용·생성·미리보기 계산(모두 VIDE 내부이고 되돌릴 수 있음)이 더해진다. 해석 확정(M)·Rhino에 만들기·로그인·계정(T2)은 그대로 사람 몫이다.
  • 계획 모드의 뜻이 조금 넓어진다. 계획 모드는 여전히 호스트·설정값을 쓰지 않지만, 화면 이동과 작업본 열기·대화 묶기(VIDE 내부)는 한다.
  • 포인트가 뜻을 갖는다. 코랄은 'AI가 지금 하는 일'과 '지금 겨냥한 대상'만 뜻한다. 초과는 진홍 --ng, 정보는 파랑 --info로 갈린다. dark에서는 --ng와 --accent가 가까우므로 위반은 채움 + ✕ + 문구, 선택은 외곽선만으로 모양도 구분한다.
  • 2026-09-29의 작업공간 탭 결정을 되돌린다. 목업 검수 전까지는 지금 배치(Design §03)가 유효하다.
  • 위험. 오판정으로 인한 자동 계산, 손 아래에서 움직이는 화면(방금 보낸 요청에만, 턴당 1회), 대화 묶기와 목적 세션(ADR-021)의 충돌, 공급자별 질문 기능 차이, 레일·탭 없는 화면의 발견성. 완화책은 RESEARCH-12 §7.3이고 검증은 PLAN-26이 소유한다.

05 / 아직 반영하지 못한 곳

  • PRD §11.4, FR-25, AC-48: 결정 4에 맞춰 2026-10-01 반영함(PRD 0.14). jig 열기와 사람 확인 단계 전까지의 계산을 판정만으로 자동 실행하는 동작에 넣고, 호스트 문서 쓰기·해석 확정은 사람 확인으로 남겼다.
  • SPEC-01.10: "실제 효과를 실행 전에 알 수 있어야"에 '되돌릴 수 있는 VIDE 내부 표시·계산은 실행 뒤 알림으로 충분하다'는 단서가 필요하다. 이 파일은 다른 세션이 편집 중이라 이번에 고치지 않았다.
  • ARCH-01 §3: 턴마다 주는 도구 목록과 계획 모드 도구 집합에 jig_open·ui_go를 더해야 한다. 다른 세션이 편집 중이라 ARCH-03 §5.3에만 적었다.
  • 기본 출력 레이어의 생성: VIDE/{jig}/{n}은 연결 문서에 아직 없는 여러 단계 레이어다. 지금 만들기 틀은 이미 있는 출력 레이어 아래 한 단계만 만든다(ARCH-03 §9.5). 그래서 기본 레이어로 만든 작업본은 계산·보기는 되지만 Rhino에 만들기는 레이어를 만들 수 있을 때까지 이유를 보이고 막는다(SPEC-07.4). 여러 단계 레이어 생성은 PLAN-26 T-076이 PLAN-22의 부모 탐색 수정과 함께 다룬다.
  • Design SCR-03·SCR-18·§12.9와 §03 본문: 셸 교체의 목업 VERIFY 뒤 다시 쓴다(PLAN-26 T-079).
