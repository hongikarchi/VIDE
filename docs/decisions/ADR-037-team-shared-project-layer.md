# 팀 공유 프로젝트 층

## 결정

2026-10-06 사용자 결정: "서버로 올리는거는 추천대로". 추천은 "가벼운 것(글·목록·설정)은 서버에서 공유하고, 무거운 것(모델 형상·첨부·원본 파일)은 PC에 둔다"였다. 사용자는 다음을 물었다. 프로젝트 목록·프로젝트 AI 지시·정리된 자료 DB는 공유돼야 하지 않는지, 요청·AI 답·대화 기록도 나만 보는지. **승인 범위:** 아래 1~5의 방향이다. 표 구조·동기 방식은 작업 계획(PLAN-35·PLAN-36)이 구체화한다.

1. **프로젝트 목록·멤버는 서버가 원본이다.** VIDE 앱의 프로젝트 목록은 '이 PC의 프로젝트'와 '공유받은 프로젝트(사이트)'를 합쳐 보인다. 공유받은 프로젝트는 그 프로젝트를 돌리는 PC가 꺼져 있어도 열린다(ADR-035의 PC 없이 보기와 같은 자료).
2. **프로젝트 AI 지시는 서버가 원본이다.** CLAUDE.md에 해당하는 프로젝트 지시는 멤버 누구나 고치고, 각 PC는 사본으로 AI 턴에 넣는다. PC별 선호(기본 모델, 노력 수준, 웹 검색, 응답 대기 시간)는 PC에 둔다.
3. **정리된 프로젝트 자료 DB는 서버가 원본이다.** 진술·이슈·출처 규칙(SPEC-08)은 서버에 둔다. 원본 문서·파일과 수집 작업은 PC에 둔다. ADR-018 §3 '팀 공용 저장 위치'는 이것으로 정한다.
4. **요청·AI 답·대화 기록 전문을 서버에 올린다.** 그 작업을 돌린 PC가 원본이고, 서버에는 글 사본을 올린다. 사본에는 요청 글, 답 전문, 활동 줄, 실행 코드, 파일 이름이 들어간다. 멤버는 사이트와 자기 VIDE에서 읽는다. 모델 형상·첨부·핀 좌표는 올리지 않는다. 프로젝트마다 '서버에 올리지 않기'를 고를 수 있다. ADR-035의 '사이트에 올리기' 스위치를 이것까지 넓힌다.
5. **무거운 것은 PC에 둔다.** 모델 형상(Sync), 첨부, 사용자 원본 파일, 로그·덤프, PC별 키·설정이다. 모델은 R2 스냅샷(ADR-035, 상한 5GB)으로만 보인다.

jig 패키지 배포(사이트 jig 저장소)는 성격이 달라 별도 결정·계획으로 다룬다(2026-09-25 결정 '공유=VIDE 사용자 전체, IDE가 직접 서빙').

## 맥락

VIDE는 '프로젝트는 그 프로젝트를 돌리는 PC 한 대의 것'이라는 구조로 자라 왔다. 다른 사람은 사이트로 들어와 게시본만 봤다. 프로젝트별 DB 분리(ADR-032) 뒤 서버와 PC의 저장 위치를 정리하면서, 사용자는 팀이 함께 보는 것은 서버에 있어야 한다고 판단했다. 글 위주 자료는 D1 무료 한도(5GB) 안에서 오래 간다(2026-10-06 사이트 D1 약 0.3MB).

## 결과

- 대화 전문이 서버에 올라가므로 개인정보 안내(ADR-036의 안내 문서)에 함께 적고, 프로젝트별 끄기를 둔다. 외부 AI 회사로 나가는 자료(요청·첨부, Jev 분류의 요청 글)도 같은 안내에 적는다.
- 서버 원본 자료(목록·지시·자료 DB·노트)는 PC가 꺼져도 고칠 수 있다. PC는 켜질 때 사본을 맞춘다.
- 저장 위치 전체 표는 ARCH-01 「데이터 위치」가 소유한다.
