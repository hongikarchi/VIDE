# ADR-011 · 위임형 작업 방식

## 1. 배경

VIDE는 사람이 매 도구 호출마다 승인하는 방식도, 장시간 무엇이 일어나는지 알 수 없는 무관찰 자율 실행도 목표로 하지 않는다. 사용자는 목표·대상·유지 조건을 정하고 AI에게 작업을 맡기되, 실제 중간 상태를 보면서 언제든 개입할 수 있어야 한다.

기존 0.2의 `원본 반영 시점에만 확인한다`는 표현은 위임의 취지를 설명하는 데는 유용했지만, 외부 공개·유지 조건 변경·작업 범위 확대·큰 추가 비용처럼 사용자가 다시 결정해야 하는 경계까지 생략하는 것으로 읽힐 수 있었다. 2026-09-19 사용자 결정으로 확인 경계를 정합화한다.

## 2. 선택지

| 안 | 내용 | 트레이드오프 |
|---|---|---|
| A | 단계별 확인 — 내부 명령·후보마다 승인 | 통제는 세밀하지만 사용자가 계속 CAD를 직접 조작하는 것과 비슷해지고 위임 효과가 낮음 |
| B | 위임형 기본 — 맡긴 범위 안에서는 진행하고, 권한·범위가 바뀌는 경계에서 확인 | 자율성과 개입 가능성을 함께 유지. 후보 보호·진행 표시·중단 계약이 필요 |
| C | 빠른 요청/위임 작업을 별도 모드로 제공 | 사용 방식이 두 벌이 되어 상태·화면·시험 복잡도가 증가 |

## 3. 결정

**B. 위임형을 기본으로 한다.**

- 사용자가 맡긴 **목표·대상·유지 조건·허용 범위** 안에서 AI는 자료 읽기, 후보 생성·수정, 계산을 여러 단계 이어서 수행한다.
- 내부 명령이나 중간 후보마다 반복 승인을 요구하지 않는다.
- 중간 결과와 실제 진행은 검토 가능한 형태로 계속 보여주며, 사용자는 언제든 추가 지시·중단 등으로 개입할 수 있다.
- 작은 요청도 같은 구조 안에서 빠르게 끝나며 별도의 빠른 모드를 필수로 두지 않는다.
- 후보 보호, 사람의 직접 수정 보호, 늦은 결과의 덮어쓰기 방지 등 플랫폼 공통 보호는 위임 범위 안에서도 유지한다.

### 3.1 사용자 확인이 필요한 경계

다음은 AI가 조용히 대신 결정하지 않는다.

1. **원본 반영** — 검토한 변경을 실제 호스트 원본에 적용하는 행동
2. **외부 공개 또는 공개 범위 확대** — 이미 허용된 공유 범위의 상태 갱신과 구분
3. **유지 조건의 변경** — 사용자가 지키라고 지정한 조건을 완화·삭제·대체
4. **작업 범위 확대** — 맡긴 대상·영역·결과를 넘어 새 설계 판단이나 변경을 추가
5. **큰 추가 비용** — 사용자가 맡긴 범위를 넘어서는 유의미한 시간·비용·외부 자원 증가

`큰 추가 비용`의 실제 판정 기준과 요청 형태는 SPEC·PLAN에서 구체화한다. 이 ADR은 모든 비용 증가에 팝업을 띄우라는 뜻이 아니다.

### 3.2 확인과 중복 승인을 구분한다

사용자가 특정 후보와 대상을 명시하여 `이 후보를 원본에 반영해`처럼 충분히 명확하게 요청했다면 그 행동 자체가 원본 반영 결정의 근거가 될 수 있다. 같은 내용을 채팅과 별도 팝업으로 무조건 두 번 승인하게 하는 것은 요구하지 않는다.

한 하위 작업에서 추가 결정이 필요하더라도, 독립적으로 안전하게 진행할 수 있는 다른 조회·후보 작업까지 모두 멈추게 할 필요는 없다. 대기 중 가능한 행동과 작업 간 의존성은 SPEC에서 정한다.

## 4. 근거

- 모든 단계의 승인은 직접 CAD를 조작하는 부담을 다시 만들고 총시간·개입 부담을 늘린다.
- 반대로 원본 반영·공개·조건/범위 변경까지 AI가 자동 결정하면 사람이 중요한 설계 판단에 개입할 수 없게 된다.
- 위임의 단위는 `AI가 몇 번 호출되는가`가 아니라 사용자가 맡긴 목표·대상·조건·권한의 범위다.
- 후보 격리(ADR-003)와 진행·개입 상태(FR-11)가 있어야 위임형 작업이 원본 보호와 양립한다.

## 5. 문서 적용

- PRD §2·§8·§9.5: 맡긴 범위 안의 진행과 확인 경계를 이 결정으로 유지한다.
- Design §06·§07: 모든 후보에 승인 버튼을 강제하지 않고, 확인이 필요한 경계에서는 사용자가 필요한 행동을 이해할 수 있게 한다.
- SPEC-00-common 및 실행·개입 SPEC: 확인 시점, 승인 성립 조건, 대기 중 가능한 행동, 작업 의존·중단 의미를 정의한다.
- PLAN: 실제 승인 인터페이스, AI 실행 방식, 비용 계측·중단 구현을 정한다.

## 6. 재검토 조건

- 대표 과업에서 잘못된 대상·조건 위반이 후보 단계에서 발견되지 않고 원본 반영 직전에 반복적으로 드러나면 중간 확인 지점을 추가할지 재검토한다.
- 실제 사용자 시험에서 별도 모드가 필요하다는 반복 요구가 나오면 빠른 요청/위임 작업 분리를 검토한다.
- 확인 경계가 지나치게 자주 발생해 위임 효과를 잃거나, 반대로 중요한 설계 판단을 AI가 조용히 넘어가는 사례가 확인되면 SPEC의 경계 기준을 조정한다.
