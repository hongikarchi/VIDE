# ADR-001 · MVP 호스트와 완료 수준

## 1. 결정

첫 출시의 지원 호스트는 **Rhino와 ZWCAD**다. 두 호스트 모두 SPEC에서 선언한 객체·동작 범위 안에서 문서·객체 읽기, 공간 입력, 네이티브 생성·수정, 결과 확인, 호스트 기본 도구의 재편집, 저장·재열기를 제공한다.

Revit과 AutoCAD는 후속 확장으로 둔다. 연결 표시나 읽기만 제공하는 것을 두 호스트의 네이티브 기본 제어 완료로 집계하지 않는다. 한 호스트만 완결한 단계는 내부 alpha이며 전체 MVP 완료를 대신하지 않는다.

이 결정은 지원 호스트와 완료 수준에 대한 승인이다. 모든 객체·명령·자동화 업무를 지원한다는 뜻이 아니다. 상세 버전·에디션·객체·속성·동작은 OQ-02·03과 호스트 지원표에서 정한다.

## 2. 판단 이유와 선택하지 않은 안

플랫폼을 특정 Rhino 업무 앱으로 축소하지 않으면서 실제 사용할 두 도구를 연결한다. 첫 호스트만 완결하고 둘째 호스트는 읽기나 단일 명령 시연에 한정하는 안 대신, 선언 범위의 전체 사용자 흐름을 양쪽에서 제공하는 안을 채택했다.

작업량을 정확히 두 배라고 추정하지 않는다. 호스트별 지원 비용과 기술 제약은 실제 환경·선택 객체·연결 방식에 따라 확인한다. Revit 제외만으로 후보 보호나 트랜잭션 문제가 자동 해결되었다고 주장하지 않는다.

## 3. 구현 순서와 범위 변경의 경계

구현 순서는 PLAN에서 정한다. Rhino부터 시작하는 것은 가능한 개발 순서이지, 이번 승인만으로 특정 단계의 착수 관문이나 실험 순서를 모두 확정한 것은 아니다.

최소 네이티브 쓰기 자체가 불가한 경우와, 최소 쓰기는 가능하지만 전체 과업의 품질·시간이 목표에 못 미치는 경우를 구분한다. 둘 다 사용자 재결정의 근거가 될 수 있으나, 최소 쓰기 실패를 같은 쓰기가 필요한 '계약 증명'으로 자동 축소하지 않는다. 환경 부재·미시험은 실패와 구분한다. 성과 미달에 따른 자동 범위 축소는 채택하지 않는다.

## 4. 기준 문서

제품의 정본은 `docs/PRD.md` §13·§14.1이다. 복수 연결·연계·병렬 실행은 ADR-009와 PRD §12.2가, 대표 검수 과업은 ADR-006과 PRD §16.4가 다룬다. OQ-01의 CAD 선택은 이 결정으로 해소한다.

SPEC은 호스트별 실제 지원 범위를 작성하고, PLAN은 API·연결·기술 실험·개발 순서를 정한다. 기술 선택은 이 ADR의 승인에 포함되지 않는다.
