# AI 대화를 목적별 세션으로 잇는다

## 맥락

**단발 실행이 생긴 이유.** [ADR-013](ADR-013-local-coordinator-cli.md)(2026-09-20, 지금은 superseded)은 매 호출 도구 없는 새 CLI 실행으로 구조화 제안을 받고, 이전 실행의 재개는 VIDE의 확인된 기록에서 새 호출로 시작하며, CLI 세션 ID를 제품 기록의 정본으로 쓰지 않기로 했다. 세션 재사용과 장기 프로세스(app-server)는 "현재 경로가 아니다"로 두고, 나중에 채택하려면 도구 차단, 문맥 격리, 취소와 늦은 결과, 재시작 복구, 전송 범위 검증과 ADR 변경이 필요하다고 적었다. 현행 [ADR-014](ADR-014-sdk-agent-execution.md)는 도구 없는 단발 응답 제한을 SDK 도구 실행으로 대체했지만, 실행 단위는 그대로 남았다. 지금 코드는 요청 하나에 CLI 프로세스 하나를 띄우고 공급자 기록을 남기지 않으며(`--no-session-persistence`), 대상 참조·기준 판·호출 상한·토큰을 요청 단위로 발급·회수하고, 다음 요청에는 이전 요청과 답의 잘린 글만 다시 보낸다(SPEC-02.17의 이전 판 (5)). 그 결과 AI가 쓴 코드·도구 호출·오류·질문은 다음 턴에 넘어가지 않고, 편집 한 건에 입력 약 159k 토큰을 쓴 기록이 있다(2026-09-29 로그, [RESEARCH-10 §1.1](../research/RESEARCH-10-vide-restructure.md)).

**세션을 쓰지 않은 근거의 재평가**([RESEARCH-10 §1.2~1.4](../research/RESEARCH-10-vide-restructure.md)). 제품 기록의 정본이 VIDE라는 점과 개인 설정·전역 MCP를 막아야 한다는 점은 지금도 맞다. 요청마다 Jev가 공급자를 바꾸는 것은 정책일 뿐이고, 요청 단위 안전장치는 턴마다 새 프로세스를 띄우면 그대로 다시 발급할 수 있다. 작업 폴더를 지우면 기록이 고아가 된다는 추론은 틀렸다(설치된 CLI는 세션 ID로 이 PC의 어느 폴더에서나 기록을 찾는다). 공급자 기록 폴더에 프로젝트 자료가 쌓이는 문제는 VIDE가 관리할 비용으로 남는다. 대화형 화면(TUI)을 쓰지 않는 이유는 기계가 읽을 이벤트 규약이 없다는 것 하나이며, 원하는 것은 TUI 화면이 아니라 이어지는 대화다.

**바뀐 요구.** 2026-09-29 사용자 결정: 모든 대화를 세션으로 잇는다. 대화를 시작할 때 Jev가 공급자·모델을 정해 그 대화가 끝날 때까지 고정하고, 모델 편집·CAD 편집·법규 질문처럼 목적이 다른 대화를 동시에 진행한다. 동시 진행을 실제로 막는 것은 세션 여부보다 대화 개념이 없는 저장 구조와 겹치는 요청을 거절하는 접수 규칙이었으므로, 접수 규칙도 같은 날 함께 정했다(SPEC-02.9).

## 선택지

| | A. 단발 + VIDE 대화 원장 | B. 대화별 공급자 세션, 턴마다 새 프로세스 | C. 장기 프로세스 |
|---|---|---|---|
| 방식 | 지금처럼 턴마다 새로 실행하고, 대화 원장(가정·질문·답·결정·결과 참조)을 요청 자료에 싣는다 | 첫 턴에 세션을 만들고 다음 턴부터 그 세션을 이어 실행한다. 턴마다 지금과 같은 격리 인자를 다시 넘기고 기록 끄기만 뺀다 | 대화마다 CLI 프로세스를 띄워 두고 입력을 흘려 넣는다 |
| AI 작업 기억 | 원장에 적힌 것만 | 쓴 코드·오류·질문까지 | B와 같고, 턴 중간 지시가 가능 |
| 요청 단위 안전장치 | 그대로 | 턴마다 다시 발급해 유지 | 프로세스를 띄울 때 권한이 고정되어 턴마다 다시 묶는 장치가 새로 필요 |
| 턴당 입력 | 매번 새로 만든 문맥 | 누적 이력(짧은 간격은 캐시 이득, 긴 대화는 손해) | B와 같음 |
| 재시작·중단 | 안전 | 기록이 남고, 호스트 쓰기 보호는 그대로 필요 | 엔진 재시작과 함께 끊김 |
| 이용 조건 | 현행과 같음 | 현행과 같음(수정하지 않은 공식 CLI를 사용자 구독으로 실행) | 원시 CLI 입력 흐름은 현행 범주이나, 공급자 SDK 패키지를 구독 로그인과 함께 쓰는 쪽은 위험 |

## 결정

1. **모든 대화에 B를 쓴다.** 턴 하나 = CLI 실행 하나, 대화 하나 = 공급자 세션 하나다. 매 턴의 인자는 현행 격리 인자(도구 없는 턴과 도구 있는 턴 각각)에서 기록 끄기만 뺀 것이며, 대상·기준 판·허용 도구·권한·상한·토큰은 턴마다 발급하고 턴이 끝나면 회수한다. 동작 의미는 [SPEC-02.19](../specs/SPEC-02-execution-candidates.md), CLI 인자와 공급자 기록 관리는 [ARCH-01](../architecture/ARCH-01-system.md) §2, 저장 구조는 [ARCH-03](../architecture/ARCH-03-jig-runtime.md) §10이 소유한다.
2. **공급자·모델·계정은 대화를 열 때 정해 고정한다.** 같은 공급자 안에서 effort만 턴마다 바꿀 수 있다. 계정 한도·공급자 바꾸기·세션 잃음은 원장 기반 인계로 새 세션을 연다(SPEC-02.19의 5).
3. **Codex 대화는 SPIKE ④가 통과할 때까지 원장 방식(A)으로 둔다.** 사용자에게는 같은 대화로 보인다.
4. **한 대화 안에서 도구 없는 턴과 도구 있는 턴을 섞는 방법:** 대화마다 도구 유무를 주장하지 않는 중립 시스템 프롬프트 하나를 쓰고, 턴마다 달라지는 범위·대상·권한·상한·금지는 그 턴의 요청 자료('이번 턴 규칙')로 보낸다. 기록된 시스템 프롬프트를 쓰지 않게 하는 옵션은 SPIKE ⑦에서 확인한다. 둘 다 통하지 않으면 한 대화 아래 도구 없는 세션과 도구 있는 세션을 따로 연다.
5. **정본은 VIDE다.** 대화 원장·jig 작업본·초안 파일이 정본이고 공급자 세션은 어느 정본도 대체하지 않는다(ADR-013의 원칙과 ARCH-01 §1.1 유지). 세션을 잃어도 작업을 잃지 않는다.
6. **C는 지금 채택하지 않는다.** 턴 중간 지시는 SPIKE 결과를 본 뒤 따로 판단한다.
7. **SPIKE에서 떨어진 항목은 그 항목만 되돌린다.** 격리·권한 항목(①②⑤⑥)이 떨어진 공급자는 원장 방식으로, ⑦이 떨어지면 형제 세션 방식으로 간다. 모델 편집 대화는 세션의 이득이 작으므로 하나라도 떨어지면 원장 방식으로 둔다.

**2026-10-01 결정(보완, 사용자):** 요청마다 Jev가 공급자·모델·effort를 바꾸면 세션·캐시·문맥을 매번 버리게 되므로, 기본 대화를 포함한 모든 대화가 **첫 턴에** 공급자·모델을 정해 고정한다. 작성기에서 사용자가 모델을 직접 골랐으면 그 모델, 아니면 Jev가 그 첫 요청으로 고른다. Jev의 모델 판정은 대화를 열 때(첫 턴)만 쓰고 열린 대화의 턴에서는 쓰지 않는다. effort는 같은 모델 안에서 턴마다 바꿀 수 있고 세션은 이어진다. 열린 대화에서 작성기로 다른 공급자·모델을 골라 보내면 그 대화를 바꾸지 않고 대화 탭을 새로 열어 지금 대화의 인계 자료(원장·최근 턴·파일)와 함께 그 요청을 보내며, 두 대화에 한 줄씩 남긴다('모델이 달라 새 대화로 이어서 보냈습니다 · 모델'). [다른 AI로 이어 가기]도 같은 방식이다. 기본 대화도 첫 턴에 고정되면 다른 대화처럼 공급자 세션 하나를 이어 간다. 탭 [+]로 새 대화를 직접 열 수 있다. 동작은 SPEC-02.19의 2·5, 작업은 PLAN-24 T-088이 소유한다.

## 구현 전 통과해야 할 SPIKE

결정은 승인되었고, **공급자별 세션 이어 실행은 아래 SPIKE가 통과한 뒤에만** 켠다. 대화·원장·접수 규칙과 원장 방식의 대화는 SPIKE를 기다리지 않는다. 작업 순서와 기록 위치는 [PLAN-24](../plans/PLAN-24-ai-conversations.md)가 소유하며, 기록은 `docs/tdd/SPIKE-YYYY-MM-DD-cli-session-resume.md`로 남긴다. 합격 기준은 실험 전에 적는다.

| # | 질문 | 합격 기준 | ADR-013의 조건 |
|---|---|---|---|
| 0 | CLI 판 확인 | 실행 전 설치된 CLI 판이 검증한 범위 안인지 확인하고 밖이면 실행을 거절한다. 인증 방식 전환(`--bare` 기본화) 때 나오는 실패 신호를 미리 채집해 분류한다. 가능하면 검증한 판의 실행 파일 경로를 고정한다 | —(세션 방식의 전제) |

| ② | 파일 도구를 준 턴에서 작업 폴더와 붙인 폴더 밖으로 나갈 수 없는가 | 밖 읽기·쓰기 시도가 거부됨 | 문맥 격리 |

## 영향

- **공급자 기록 보존은 VIDE가 관리한다.** 대화를 닫고 30일 뒤 세션 ID로 공급자 기록을 지우고, 버린 jig 초안의 기록은 바로 지우며, 백업 대상에서 뺀다(SPEC-02.19의 1). 기본 로그인 프로필의 설정 경로는 바꾸지 않는다(ARCH-01 「CLI 기본 로그인 실행 경계」 유지).
- **동시 진행은 접수 규칙이 받친다.** 호스트 없는 턴은 호스트 경합에서 빼고, 읽기는 문서 단위로 보고 상한에서 빼며, 같은 문서 쓰기는 문서별 대기열, 프로젝트 AI 턴은 N개(기본 3)로 둔다(SPEC-02.9).
- **CLI 판 확인이 세션 방식의 전제다(에이전트 권고, 사용자 이의 없음).** 판 범위 밖이면 경고만 하지 않고 실행을 거절한다. 사용자가 직접 쓰는 CLI가 같은 실행 파일을 갱신하므로 자식 프로세스의 자동 업데이트를 끄는 것만으로는 부족하다.
- **비용.** 이어 실행은 매 턴 누적 이력을 다시 보내므로 긴 대화일수록 턴당 입력이 커지고, 동시에 도는 대화 수만큼 같은 구독 사용량을 쓴다. 길어진 대화는 원장으로 새 세션을 연다(SPEC-02.19의 5). 기준값은 SPIKE ⑨ 측정 뒤 정한다.
- **한 세션을 두 실행이 쓰지 않는다.** 종료를 확인하지 못한 턴 뒤에는 그 세션을 이어 쓰지 않는다.
- **작업 폴더는 매 턴 저장소·데이터 폴더 밖의 빈 임시 폴더다.** 세션은 ID로 이어지므로 폴더를 고정하지 않는다. jig 만들기 대화의 초안 폴더만 따로 붙이며, 그 범위와 금지 파일 검사는 SPEC-07.16·ARCH-03이 소유한다.
- **저장 구조가 바뀐다.** 대화·공급자 세션·대화 원장을 저장하고 기존 요청은 프로젝트 기본 대화로 본다. 이 판 이후 설치본은 이전 판으로 되돌릴 수 없음을 배포 안내에 적는다(ARCH-03 §10).

## 이 결정이 고치는 기준

- **ADR-014:** 결정 문구는 세션을 금하지 않으므로 바꾸지 않는다. ADR-014의 책임(대상·권한·기준·결과 기록을 VIDE가 소유)은 턴 단위로 그대로 적용한다. ADR-014에서 이 ADR로 가는 역링크가 필요하다.
- **ADR-013(superseded):** 세션 채택에 요구한 조건(도구 차단, 문맥 격리, 취소·늦은 결과, 재시작 복구, 전송 범위 검증, ADR 변경)을 위 SPIKE 표와 이 ADR로 충족한다.
- **PLAN-02 §2와 그 기술 정본 ARCH-01 §3(메시지와 도구):** "새 에이전트 세션"의 단위를 턴으로 읽는다. 세션 이어 실행의 CLI 인자·공급자 기록 관리는 ARCH-01 §2에, 대화·세션·원장 저장은 ARCH-03 §10에 적는다. 구현·검증 작업은 PLAN-24가 소유한다. ARCH-01 §3 개입 표의 '세션 내 메시지 주입' 행은 C를 위한 예비 칸으로 남는다.
- **SPEC-02.17의 이전 판 (5):** "요청마다 새 CLI가 실행되므로 … 압축되지 않는다"는 약속을 거두고, 대화마다 시작 때 정한 공급자 세션 하나를 이어 가며 VIDE 원장이 정본이라는 규칙으로 바꿨다(SPEC-02.17의 6).
- **SPEC-02.18:** 계정을 요청 접수 때 고정하던 규칙을 대화를 열 때 고정하는 것으로 적용한다(SPEC-02.19의 2).

**2026-10-01 후속([ADR-025](ADR-025-accounts-in-accountswitch.md)):** 결정 2의 계정 부분(대화별 계정 고정, 계정 한도 때 다른 계정으로 인계)은 ADR-025로 대체됐다. 계정은 대화에 고정하지 않고 턴마다 CLI 기본 로그인을 쓰며, 한도에 걸린 턴은 다시 보내지 않고 알린다. 공급자·모델 고정과 원장 기반 인계(공급자 바꾸기·세션 잃음)는 그대로다.
