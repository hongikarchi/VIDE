# ADR-020 · jig 플랫폼: 설명서 한 장, 코드 출처별 실행, 고정 틀로 Rhino에 만들기

동작 의미는 [SPEC-07](../specs/SPEC-07-jig-platform.md), 물리 계약은 [ARCH-03](../architecture/ARCH-03-jig-runtime.md), 구현 순서·검증은 [PLAN-22](../plans/PLAN-22-jig-platform.md)(플랫폼 1차)·[PLAN-23](../plans/PLAN-23-s06-frame-jig.md)(S-06 골조 jig)이 소유한다. 조사와 대안 비교는 [RESEARCH-10](../research/RESEARCH-10-vide-restructure.md) §3~§5·§9.6·§14, 형식 선택지의 앞선 조사는 [RESEARCH-05](../research/RESEARCH-05-jig-format-options.md)에 있다.

## 결정

1. **단위와 정본.** jig는 한 가지 건축 작업을 위해 만들어 쓰는 작은 작업 도구다. 패키지의 `jig.json`(계약 버전 3) 한 장이 정본이며 입력(연결된 여러 파일에서 역할별로 조립하는 입력 포함)·설정값·단계·출력·화면·보고서·Rhino에 만들기·자체 시험·AI 설명서를 선언한다. 단계를 맡는 주체(계산 코드·라이브러리 jig·공식 틀·AI 1회 호출·사람 확정)는 설명서에 드러난다. 한 프로젝트에서 jig를 쓰는 기록(작업본: 입력 조립·설정값·수정 사항·결과·만들기 기록)은 VIDE가 jig 버전을 고정해 저장한다. 설정값이 바뀌면 AI를 부르지 않고 바뀐 단계와 그 뒤만 다시 계산한다.
2. **수명 다섯 단계 중 1차는 셋.** 초안 → 프로젝트 jig → 공유 → 검증(AI 도구로 등록) → 공식. 1차는 초안·프로젝트 jig·공식만 연다. 게시·설치한 버전은 바꾸지 않고, 고치면 사본이 새 초안이 된다. 다른 jig가 부를 수 있는 것은 공식 단계의 라이브러리 jig뿐이다. 공유·보관소·검증·AI 도구 등록과 다른 PC에서 만든 jig의 설치는 공유 범위 결정(RESEARCH-10 §16 C1) 전까지 하지 않는다. 1차 가져오기는 이 PC 설치본의 키로 서명한 묶음만 받는다.
3. **코드가 도는 곳은 코드의 출처로 정한다.**
   - 공식 jig·라이브러리(저장소 코드): 엔진. 수십 ms 이상 걸리는 계산은 작업 스레드에서 돈다.
   - 개발자가 저장소에서 작성하고 이 PC에서 서명한 묶음: 최소 환경의 Node 자식 프로세스.
   - AI가 쓴 코드(초안, 초안에서 고정한 프로젝트 jig): 파일·네트워크·프로세스·환경 변수 API가 없는 계산 상자(엔진 안 wasm JS 실행기).
   - 선언형 화면·보고서: 코드 없이 데이터만.
   - 남이 만든 jig의 실행 환경은 C1 뒤에 정한다.

   jig 코드는 스스로 파일·API를 열지 않고 엔진이 권한을 검사한 뒤 넘긴 입력만 받는다. 유효 권한은 선언한 능력(닫힌 어휘) ∩ 수명 단계·실행 위치가 허용하는 것 ∩ 사용자 승인 ∩ 프로젝트 권한이며, 화면이 아니라 서버 명령 경계에서 검사한다.
4. **Rhino에 만들기는 VIDE 소유 고정 틀과 데이터 블록 하나로 한다.** 공식이 아닌 jig는 호스트 C#을 담지 않는다. 호스트에 객체를 만드는 단계는 공식 만들기 틀을 이름으로 부르고, 값은 데이터 블록 하나로만 넘긴다(C# 문자열에 값을 끼워 넣지 않는다). 실행은 AI를 부르지 않고 기존 작업 사본 → 후보 → 사용자의 원본 반영을 거친다. jig는 원본에 직접 쓰지 않는다. 이 범위에서 [ADR-014](ADR-014-sdk-agent-execution.md)의 "고정 편집 템플릿을 최종 실행 방식으로 사용하지 않는다"를 좁히며, AI 편집 경로는 ADR-014 그대로다. 1차 틀은 곡선·H 단면 스윕·기둥 압출·부호 문자 네 가지다. 기존 객체를 고치는 공식 호스트 조작 틀은 RESEARCH-10 §16 B14 결정 뒤에 더하고, 그 전에는 기존 객체 수정을 AI 편집 경로로 한다.
5. **교체 대상은 만들기 기록으로 정한다.** 교체·삭제 대상은 태그가 아니라 만들기 기록에 적힌 객체 ID와 지문으로 정한다. 기록 지문(원본 반영 직후 읽은 값)과 만들기 직전 호스트 읽기(숨긴 객체 포함)의 지문이 같은 객체만 교체한다. 태그(UserString)는 표시·검색용이다. 틀은 VIDE가 넘긴 객체 ID 목록만 지운다.
6. **사람의 수정이 우선한다.** 지문이 달라진 객체(사람이 고친 것)는 교체하지 않고 따로 보여 사람이 고르게 한다. 기록에 없는 태그 객체(사람이 만든 복사본)와 태그 없는 객체는 건드리지 않는다. 사람이 지운 객체는 다시 만들지 않는다. 레이어를 끈 것은 삭제로 판정하지 않는다. 사람이 받아들인 수정은 수정 사항으로 저장해 다시 계산해도 유지한다.
7. **화면은 선언형 패널과 공식 부품으로 만든다.** 새 jig 화면은 `panel.json`으로 공식 부품 목록 안의 부품을 배치하고 단계 출력·설정값에만 연결한다. 식·코드·임의 색은 넣지 않는다. 표현이 모자라면 부품 목록에 먼저 더한다. 격리 커스텀 뷰는 RESEARCH-10 §16 B13 결정 뒤다. 기존 구조·Sync·자료 jig 화면은 그대로 둔다.
8. **구조 해석은 라이브러리 jig다.** 구조 분석 jig(J-09)의 계산을 공식 라이브러리 `vide/structure-analysis`로 두고 범용 구조 화면과 S-06 골조 jig가 함께 쓴다. 기하 도구 `vide/geometry-kit`과 프로젝트 자료 `vide/project-facts`도 공식 라이브러리다. [ADR-019](ADR-019-structure-jig-rust-core.md)의 Rust 해석 코어와 [ARCH-02](../architecture/ARCH-02-structure-model.md) 계약은 바뀌지 않는다.
9. **S-06 골조 jig의 자리와 소스.** S-06 구조 jig는 프로젝트 jig `project/s06-frame`이다. S-06 고유 규칙은 이 jig 안에만 두고 일반 기능은 라이브러리로 올린다. 소스는 저장소 `extensions/jigs/s06-frame/`에 두되 단계 코드·틀·합성 시험 자료만 넣는다(검증용 샘플 규칙). S-06의 실제 설정값·근거·입력 조립·구역·수정 사항은 사용자 데이터 폴더의 작업본에만 두고, 설치본 빌드에는 넣지 않는다. jig 만들기의 시작 본은 공식 일반 예제이며 S-06 jig를 다른 프로젝트의 본으로 싣지 않는다.
10. **jig 시스템은 S-06 jig로 시험한다.** S-06 본체는 에이전트가 저장소에서 jig 형식대로 작성하되, 채팅 제작 루프와 같은 점검(`jig:validate`·`jig:test`)을 통과해야 들어간다. 채팅으로 jig를 만드는 경로는 1차 끝에 S-06 보조 jig(신설 E.J.마다 양쪽 기둥과 공통 파일캡이 있는지 보는 도구)를 만드는 것으로 시험한다.

**용어.** 화면과 AI의 말은 실무어(Rhino에 만들기·수정 사항·이 프로젝트의 jig·AI 도구로 등록·버전·설정값)를 쓰고, 화면 문구의 정본은 Design이다. 문서에서 '작업본'은 한 프로젝트에서 jig 한 버전을 쓰는 기록(화면 이름 '이 프로젝트의 jig')을 뜻하며, 코드 식별자(`bake`, `override`, `instance`)는 ARCH-03을 따른다.

## 이유

- 사용자 요구는 S-06 구조 jig를 만들면서 jig 시스템을 시험하고, 구조 해석은 라이브러리처럼 미리 만들어 두며, 한 프로젝트의 흐름을 일반화하지 않는 것이다. 공식 라이브러리와 프로젝트 jig를 나누면 세 가지를 함께 지킨다.
- 설명서 한 장이 정본이면 화면·계산·점검·AI 설명이 같은 선언에서 나오고, 조건을 바꿀 때 AI 없이 다시 계산할 수 있다.
- 설치된 Node 24의 권한 모델은 네트워크를 막지 못한다. AI는 오염될 수 있는 자료(자료 DB 진술·CAD 문자)를 읽고 코드를 쓰므로, 그 코드는 밖으로 보낼 길이 없는 실행기에서 돌려야 한다. 엔진 프로세스는 CLI 로그인 폴더와 DB에 닿으므로 개발자 묶음도 엔진 안에서 돌리지 않는다.
- AI가 매번 호스트 C#을 쓰면 느리고 같은 결과를 보장하지 못한다. 틀이 고정되고 값이 데이터 블록으로만 들어가면 값에 `"`나 줄바꿈이 섞여도 코드가 되지 않고, 결과가 입력에 대해 결정적이다.
- Rhino의 복사·배열·대칭은 UserString을 그대로 복제하므로 태그로 찾아 교체하면 사람이 복사해 둔 객체까지 지운다. Live Sync는 꺼진 레이어의 객체를 사라진 것으로 보고하므로, 이를 삭제로 읽으면 레이어를 끄기만 해도 결과가 지워진다.
- AI가 만드는 화면을 공식 부품으로 제한하면 쓰는 코드 양과 디자인 흔들림이 줄고, 목록 밖 부품·색을 점검에서 막을 수 있다.

## 대안과 대가

| 대안 | 채택하지 않은 이유 |
|---|---|
| jig가 호스트 C#을 직접 담거나 AI가 매번 만들기 코드를 씀 | 결과가 매번 같다는 보장이 없고, 건축가가 검토할 수 없는 코드가 원본 쓰기 경로에 들어간다 |
| 태그(UserString)로 찾아 교체 | 사람이 복사한 객체와 꺼진 레이어에서 고친 객체가 지워진다 |
| jig 출력 레이어에는 원본에 직접 쓰고 되돌리기로 보호 | 작업 사본·저장 재열기 확인·후보 보호를 우회한다 |
| 모든 jig 코드를 엔진 프로세스나 Node 권한 플래그 아래에서 실행 | 엔진은 로그인 폴더·DB에 닿고, Node 권한 모델은 네트워크를 막지 않는다 |
| jig마다 자유 React 화면 | AI가 쓰는 코드와 디자인 편차가 커지고 점검할 수 없다 |
| S-06 규칙을 범용 구조 jig에 넣음 | 한 프로젝트의 흐름을 일반화한다 |

대가: 계산 상자는 V8보다 느리므로 무거운 기하는 공식 라이브러리 단계로 넘겨야 한다. 1차 만들기 틀은 C# 메서드 본문을 기존 `worker.execute`로 보내므로 본문 길이 한도 때문에 큰 만들기를 여러 번 나누어 실행하고, 실행마다 저장·재열기 시간이 든다. 틀 종류가 적어 기존 객체 일괄 수정은 1차에 AI 편집 경로로 한다. 플러그인 내장 틀, CAD에 그리기, 호스트 조작 틀은 2차 이후다.

## 영향

- **ADR-014:** 결정 4가 적용 범위를 좁힌다. ADR-014 끝의 '후속 결정'에 적었다.
- **ADR-008·SPEC-05:** ADR-008 §1의 최소 확장 실행은 jig 형식이 잇는다(SPEC-05.8의 JIG 탭이 확장 입구를 대신한다). 신뢰하지 않는 업로드 코드를 등록하지 않는다는 SPEC-05.4와 PRD §14.2의 공개 마켓·임의 비신뢰 코드 실행 제외는 그대로다. 1차에 실행되는 코드는 저장소 공식 코드, 이 PC에서 서명한 개발자 묶음, 사용자의 제작 대화에서 AI가 쓴 코드(계산 상자)뿐이다.
- **ADR-019·ARCH-02:** Rust 코어와 해석 계약을 유지한다. 부재 만들기 앞의 해석 확정 점검과 확정 전 미리보기 해석의 범위는 SPEC-06·ADR-019가 정한다.
- **[ADR-021](ADR-021-conversation-sessions.md):** 제작 대화(초안 폴더 한정 파일 도구)와 jig 안 대화의 세션 방식은 ADR-021이 정한다.
- **AI.md §2 `extensions/`:** `extensions/jigs/<name>/`는 검증용 샘플 자리로 쓰며 실무 자료를 넣지 않는다.
- 패키지 폴더·타입·실행기 규약·서버 경로·스키마 v5·데이터 블록 형식은 ARCH-03이 소유한다.

## 승인 범위와 남은 검증

- **사용자 결정(2026-09-29):** 구조 jig와 S-06 전용 구조 jig 구현(FR-23 확장, FR-24), jig 시스템 시험 방식(결정 10), 입력은 연결된 CAD·Rhino 전부에서 AI가 조립하고 사람이 확인(SPEC-07).
- **에이전트 권고에 사용자 이의가 없어 적용한 기본값:** 결정 4(ADR-014 범위 좁힘), 결정 9(S-06 소스 위치와 시작 본), 화면 용어.
- **이 ADR이 정하지 않는 것:** 공유 범위·비신뢰 코드 실행 폭(C1), 격리 커스텀 뷰(B13), 공식 호스트 조작 틀(B14), skill 용어(B11). 결정 전까지 1차 범위 밖이다.
- 이 ADR은 방향 결정이며 구현 완료가 아니다. 남은 기술 검증(계산 상자 실행기, 자식 프로세스 격리, 만들기 틀의 코드 검사 통과·웨브 연직 스윕·본문 크기 분할, 원본 반영 뒤 객체 ID 대응)은 PLAN-22가, S-06 수용 검증은 PLAN-23과 VERIFY가 소유한다. 검증이 실패하면 해당 실행 위치나 틀을 쓰지 않고 이 ADR을 다시 연다.

## 근거

## 후속 결정

- **2026-09-30 [ADR-022](ADR-022-direct-apply-plan-auto.md) — Rhino에 만들기도 바로 적용.** 위 결정의 문구는 바꾸지 않는다. 결정 4의 '작업 사본 → 후보 → 사용자의 원본 반영'과 'jig는 원본에 직접 쓰지 않는다', 결정 5의 '원본 반영 직후 읽은 값'은 대체된다. Rhino에 만들기는 사용자가 누를 때 연결된 열린 문서에 되돌리기 기록으로 바로 만들고, 만든 직후 읽은 지문을 기록한다. 고정 틀·데이터 블록 하나·AI 없는 실행과 '만들기 기록의 객체만 교체'(결정 4·5의 나머지)는 그대로다. 「대안과 대가」에서 물리쳤던 '원본에 직접 쓰고 되돌리기로 보호'가 채택된 셈이며, 그 표의 대가(사본 저장·재열기 확인을 거치지 않음)는 ADR-022의 결과로 받아들인다. Rhino 문서가 연결되지 않은 파일 연결에서는 내부 작업 사본에만 만든다. 동작 정본은 SPEC-07.12. 근거: 2026-09-30 사용자 결정 (3).
