AI 편집은 열린 문서에 바로 적용하고 되돌리기로 보호한다

00 / 결정

2026-09-30 사용자 결정. 이 ADR이 ADR-014의 작업 실행본 → 후보 → 원본 적용 경로와 ADR-011 §3.1의 '원본 반영' 확인을 대체한다(아래 「고치는 결정」).

  1. 바로 적용. AI 편집은 사용자가 연결해 둔 Rhino·ZWCAD의 열린 문서에서 바로 실행한다. 실행 한 번(AI의 execute 호출 하나)은 호스트의 되돌리기 기록 하나(Rhino BeginUndoRecord/EndUndoRecord, ZWCAD는 명령 하나의 Undo 묶음) 안에서 돈다. 안전망은 호스트의 Ctrl+Z와 VIDE의 [되돌리기] 버튼(그 실행의 호스트 Undo를 부른다)이다. 제품 흐름에서 작업 사본 → 후보 → 적용 단계와 사용자에게 보이는 '후보'를 없앤다. 작업 사본 코드는 jig 만들기나 가져오기가 내부적으로 필요로 하는 곳에만 남긴다.
  2. 두 모드. 요청과 대화는 '검토·후보·적용' 권한 대신 두 모드 중 하나로 실행한다.
    • 계획(Plan): AI는 읽고, 재고, 화면을 캡처하고, 계획을 세우고, 묻는다. 쓰지 않는다. 결과는 계획 카드(단계 목록, 단계별 대상·위험, 남은 질문)이며 카드의 **[진행]**은 같은 대화를 자동 모드로 이어 간다.
    • 자동(Auto, 기본값): 바로 적용하고 실행마다 되돌리기 기록을 남긴다. 턴 중간 질문을 허용한다. 실행마다 바뀐 객체 목록과 [되돌리기]를 보인다. 복잡하거나 여러 파일을 고치는 요청이면 Jev가 '계획부터'를 제안할 수 있다(자동으로 바꾸지 않는다).
  3. 되돌리기로 쉽게 고칠 수 없는 동작만 확인한다(보호 목록). 자동 모드에서도 다음은 확인 카드를 거친다: 기준 개수(기본 50개)를 넘는 일괄 삭제, 레이어 삭제, 정리(purge), 경로를 지정한 다른 이름 저장·내보내기, 외부 공개, 계정·로그인. 집행 방식: 호스트가 되돌리기 기록 안에서 실행한 뒤 삭제 수와 레이어 제거를 센다. 확인 없이 보호 동작이 일어났으면 호스트가 그 기록을 되돌리고 확인 카드를 돌려준다. 사용자가 확인하면 보호를 풀고(confirmed: true) 같은 코드를 다시 실행한다. 계정·로그인·외부 공개는 AI 코드가 아니라 VIDE 동작이므로 기존 확인 카드(SPEC-02.19의 T2)를 그대로 쓴다.
  4. jig의 Rhino에 만들기도 같은 경로를 쓴다. 되돌리기 기록 하나 안에서 그 jig가 기록한 객체만 교체하고, 사람이 고치거나 복사한 객체는 보존한다(ADR-020 결정 4의 AI 없는 고정 틀은 유지).
  5. 질문 카드는 현재 카드 화면을 유지한다. 공급자의 기본 질문 기능을 SPIKE로 확인해 가능하면 질문의 출처만 그것으로 바꾼다.

01 / 맥락

  • 시간. 2026-09-29 로그의 편집 요청 세 건이 61.6 s·160.2 s·188.5 s였다(RESEARCH-10 §1.1). 문서 캡처 → 작업 사본 열기 → AI 편집 → 사본 저장·재열기 검증 → 후보 표시 → 사람의 반영 → 변경분 이식 → 재조회가 편집 하나에 모두 붙는다.
  • 낡은 상태. 사본은 요청 시점의 캡처다. 사용자가 AI 작업 중에 Rhino를 계속 만지면 반영 때 SOURCE_CHANGED로 막히거나, 기준을 다시 잡는 후속 턴이 필요했다(SPEC-02.9의 5). AI가 보는 문서와 사용자가 보는 문서가 달라 질문·가리키기도 어긋났다.
  • 이식 손실. 사본의 변경을 원본에 옮기는 경로는 독립 형상과 검증된 속성만 옮긴다. 블록 인스턴스 쓰기·그룹 구성 변경·재질·문서 설정은 거절하거나 빠진다(ARCH-01 §4의 「Rhino 변경분 적용」). 사본은 미터로 고정되어 단위 변환도 끼어든다.
  • 터미널과의 차이. 같은 모델이 터미널 Claude Code에서는 열린 문서에 바로 쓰고 결과를 보며 고친다. VIDE 안의 AI가 모델링을 못한다는 지적(2026-09-30)의 원인 가운데 쓰기 대상의 차이(RESEARCH-11 §1의 9행)는 RESEARCH-11 §3에서 '의도한 차이'로 남겨 두었던 항목이다. 이 결정으로 그 차이를 없앤다.
  • 이미 있던 바로 쓰기. ZWCAD 열린 도면 수정(runCode{write:true}, appliedDirectly)과 SPEC-02.16의 '연결 Rhino 수정'이 사실상 바로 쓰기의 수요였다. 두 경로가 따로 자라는 대신 한 규칙으로 모은다.

02 / 선택지

A. 현행 유지(사본 → 후보 → 적용) B. 바로 적용 + 되돌리기 기록 + 보호 목록 C. 같은 문서의 후보 레이어에 쓰고 반영 때 옮김
한 편집의 시간 캡처·사본·검증·이식이 붙어 분 단위 호스트 실행과 결과 조회만 사본은 없지만 반영 이동이 남음
AI가 보는 상태 요청 시점 캡처 사용자가 보는 문서 그대로 그대로(후보 레이어 포함)
이식 손실 블록·그룹·재질 등 이식 불가 항목 없음(네이티브 편집) 레이어 이동·교체 규칙이 새로 필요
사람이 되돌리는 법 후보 폐기 Ctrl+Z 또는 [되돌리기] 후보 레이어 삭제
위험 느리고 자주 막힘 AI 코드가 사용자 문서를 직접 바꿈. 되돌리기로 못 고치는 동작이 남음 기존 객체 수정은 여전히 이식이 필요

B를 택했다. A의 보호는 되돌리기로 대부분 대신할 수 있고, 되돌리기로 쉽게 고칠 수 없는 동작만 따로 막으면 된다. C는 새 객체에는 맞지만 기존 객체의 수정이 대부분인 실제 요청에서 A의 이식 문제를 그대로 남긴다.

03 / 결과

  • 빨라지고 단순해진다. 편집 요청은 대상 문서의 되돌리기 기록 하나로 끝난다. 후보·반영·반영 영수증·후보 계보 경합이 제품 흐름에서 빠진다.
  • 보호의 정본이 바뀐다. 기존 대상의 보호는 '반영 전에는 바꾸지 않는다'에서 '실행 단위로 되돌릴 수 있고, 되돌리기로 쉽게 고칠 수 없는 동작은 먼저 확인한다'로 바뀐다(PRD §11.2).
  • 보호 목록의 집행은 종류마다 다르다. 결정 3의 '실행 뒤 세고 되돌린다'는 일괄 삭제·레이어 삭제(와 ZWCAD의 정의 정리)에 쓴다. Rhino의 정리(purge)는 되돌리기로 복원되지 않으므로 실행 전에 코드에서 찾아 막는다. AI 코드의 파일 쓰기는 금지 API 정책으로 이미 거절되므로 경로 지정 저장·내보내기는 외부 공개·계정과 같이 VIDE 동작으로만 일어나고 확인 카드를 거친다. 세부는 SPEC-02.13의 4와 ARCH-01 §4.
  • 되돌리기의 한계를 그대로 알린다. [되돌리기]는 그 기록이 문서의 마지막 되돌리기 기록일 때만 한다. 그 뒤에 사람이나 다른 실행이 문서를 바꿨으면 not-latest로 거절하고 호스트에서 직접(Rhino의 Ctrl+Z, ZWCAD의 U) 되돌리라고 안내한다. 사용자 설정의 Undo 메모리 한도·문서 닫기·저장 뒤 다시 열기로 기록이 사라질 수 있다. 파일 저장은 여전히 사용자가 한다. Undo는 보안 샌드박스가 아니다.
  • AI 코드가 사용자의 Rhino 프로세스에서 돈다. 컴파일 검사·금지 API 정책(명령·UI·파일·리플렉션)은 유지한다. 코드가 죽거나 멈추면 사용자 세션이 영향을 받을 수 있다. 호스트 실행 시간 상한과 협조적 취소를 유지한다.
  • 불명확 결과. 응답을 잃으면 다시 실행하지 않고 문서 지문(fingerprint)과 되돌리기 기록 존재로 확인한다. 같은 문서의 쓰기는 여전히 한 번에 하나다(SPEC-02.9). 호스트가 문서를 건드리기 전에 거절한 실행(읽기 전용 문서·명령 진행 중·연결 끊김 등)은 불명확이 아니라 실행하지 않음이며, 이유와 다음 행동을 결과에 보인다(2026-10-01 사용자 결정, SPEC-02.7).
  • 여러 호스트의 원자적 성공·복구는 약속하지 않는다. 호스트별 되돌리기 기록을 따로 남긴다.
  • 계획 모드가 '검토 전용'을 대신한다. 계획 모드 턴에는 쓰기 도구를 주지 않는다.

04 / 고치는 결정

결정 본문은 고치지 않고, 각 ADR에 이 결정을 가리키는 '후속 결정'을 단다.

  • ADR-014: 범용 SDK 코드 실행과 VIDE의 대상·권한·결과 기록 책임은 그대로다. 「대안과 대가」·「승인 범위」의 작업 실행본 사본 → 후보 확인 → 고정된 변경 이식 → 원본 적용 경로를 이 결정의 바로 적용으로 대체한다. '사용자 실행본으로 자동 대체하지 않는다'도 사용자의 열린 문서가 기본 실행 대상이 되는 것으로 대체한다.
  • ADR-011 §3.1: 1번 '원본 반영' 확인은 실행별 되돌리기로 대체한다. 2~5번(외부 공개, 유지 조건 변경, 범위 확대, 큰 비용)은 그대로이며 이 결정의 보호 목록이 더해진다. 위임형 기본(§3)은 자동 모드로 이어진다.
  • ADR-020 결정 4·5: Rhino에 만들기의 작업 사본 → 후보 → 원본 반영과 'jig는 원본에 직접 쓰지 않는다'를 결정 4의 바로 적용으로 대체한다. 고정 틀·데이터 블록·AI 없는 실행·기록된 객체만 교체는 그대로다.
  • ADR-003: '원본 반영 승인 전에는 후보 작업이 기존 대상을 변경하지 않는다'는 AI 편집에 더는 적용하지 않는다. 사람의 수정을 되돌리지 않는다는 원칙은 되돌리기에도 적용한다(마지막 기록만 되돌린다).

05 / 승인 범위와 남은 검증

사용자 결정으로 승인한다. 구현·검증은 PLAN-22·23·24의 해당 작업이 소유하고 진행 상황은 PLAN §6.5가 정본이다. 남은 검증: Rhino 되돌리기 기록의 실행 단위 보장과 not-latest 판정, ZWCAD 명령 Undo 묶음의 동등성, 보호 목록 판정(삭제 수·레이어 제거)의 정확도, 되돌리기 뒤 문서 지문 복원, 계획 → [진행] 인계. 동작 의미는 SPEC-02, 물리 계약은 ARCH-01 §4가 소유한다.

07 / 후속 결정

  • 2026-10-01 ADR-026 — 계획 모드의 화면 이동·jig 열기, 공급자 자체 질문 기본. 위 결정의 문구는 바꾸지 않는다. 결정 2의 계획 모드는 여전히 호스트·설정값을 쓰지 않지만, VIDE 화면 이동과 jig 열기(기존 작업본을 열고 대화를 묶기)는 한다. jig 단계 계산과 설정값 적용은 체크리스트의 [진행] 뒤다. 결정 5의 질문 카드는 공급자 자체 질문 기능을 기본으로 쓰고, 지원하지 않는 공급자·경로는 VIDE 카드로 대신한다. 동작 정본은 SPEC-02.19의 6·SPEC-02.20의 2.
  • 2026-10-01 ADR-027 — 한 요청이 열린 연결 파일들을 함께 고침, 작업 단위 되돌리기, 전부 또는 전무. 위 결정의 문구는 바꾸지 않는다. 실행 하나가 그 문서의 되돌리기 기록 하나인 것은 그대로이고, 자동 모드 턴은 대상 문서 밖에 그 프로젝트의 열린 연결 파일도 읽고 고친다. 두 파일 이상을 쓴 요청은 VIDE [되돌리기] 한 번이 요청의 실행을 모든 파일에서 되돌리고, 그 요청이 실패로 끝나면 적용분을 자동으로 되돌린다. 동작 정본은 SPEC-01.11의 5·SPEC-02.13.
