# ADR-006 · 기준 과업 3개와 검증 사용자

## 1. 배경

'지원 과업·기준 과업'이 PRD §2·§11·§16·§17·OQ-06 등 10곳에서 성공·비용·출시 기준으로 인용되지만 정의가 없고, §8.2·PLAN §7.1(구 PRD §14.2)의 과업은 전부 호스트 명령 1회짜리라 AI 위임의 가치를 잴 수 없다(PRD R-58·R-50). AC-22(비개발자 실제 사용)는 피험자·과업·판정자가 없어 통과할 수 없다(제안 OQ-13·14).

## 2. 결정

### 기준 과업 (모두 채택, 단계 배정)

| # | 과업 | 호스트 | 판정 단계 | 검증하는 §2 가설 |
|---|---|---|---|---|
| ① | 지정 매스를 핀·스케치로 이동·변형하되 유지 대상(인접 매스·대지 경계)을 보존하고, 층별 면적·일람표를 다시 계산해 보여 준다 | Rhino | Rhino alpha 판정 입력 · MVP 완료 조건 | 1·3·4·5·7 |
| ② | 기준선·치수·스케치로 벽·문 폴리라인을 생성하고 기존 요소를 유지한다 (평면 작성 최소형) | ZWCAD | ZWCAD 슬라이스 판정 입력 · MVP 완료 조건 | 1·3·4·5 |
| ③ | 외부 자료(지적·건물 정보)로 주변 사이트 매스를 생성한다 | Rhino | 사이트 스킬 착수 시 측정 (MVP 조건 아님) | 2·6 |

- 조건: 공통 기능만으로 가능(③은 외부 자료 접점이 필요하므로 후속 스킬 단계), 조회+판단+변경 결합 또는 호스트 명령 3회 이상, 유지 조건 1개 이상, 수작업 대조 측정 가능.
- **수작업 기준선은 세 과업 모두 Rhino alpha 착수 전에 측정한다**(총시간·대상 오인 횟수·재작업 횟수). OQ-06의 수치 목표는 그 뒤 확정한다.
- ①의 면적·일람표 갱신은 §4.2 '일람표 작성' 스킬의 최소형이며 첫 스킬 후보다(ADR-008).

### 검증 사용자

- 기준선 측정과 자가 시험: 소유자 본인.
- 가설 판정과 AC-22: 개발에 관여하지 않은 **동료 건축가 1~2명**. 판정자는 피험자와 분리한다.
- AC-22 통과 조건: 개발자 외 피험자가 기준 과업을 개발자 개입 없이 완료하고, 후보/원본·접수/반영 상태를 스스로 설명한다.

<!-- codex-review:start -->

> **[검토 · codex · R-01 · 높음]** **추가 지적.** **기준 과업의 판정 가능성.** 세 과업의 단계 배정은 유용하나 과업 ①의 매스만으로 층별 면적·일람표의 정답이 정해지지는 않는다. 제안: 작은 고정 시험 모델에 층 구분·높이/절단 기준·닫힌 형상·단위·면적 계산 규칙과 허용 오차를 선언한다. 유지 대상은 어떤 형상·속성·관계가 같아야 하는지 정하고, ②의 벽·문은 폴리라인 최소 표현임을 명시해 BIM 객체나 도면 완성까지 확대하지 않는다. 총시간은 입력 준비·대기·검토·수정·반영까지 같은 범위로 측정한다. 이 시험용 계산 가정은 법정 면적이나 모든 실제 프로젝트에 통용되는 건축 규칙의 확정을 뜻하지 않는다.

## 3. 결과 — 적용 시 바꿀 문장

- 기술 검수 과업(구 PRD §14.2, 현재 PLAN §7.1)과 '기준 과업'(위 표)을 분리해 기준 과업은 PRD §16.3에, §16.3에 기준 과업·측정 항목, OQ-06 결정 시점을 "alpha 착수 전 기준선 측정"으로 전진, AC-22 통과 기준 보강, §2 표에 우선순위·검증 시점 열, §17에 "가설 미검증" 위험 행. §18에 OQ-13·OQ-14 행(이 ADR 링크).
- Design §13 검수에 외부 검수자와 실패 신호(후보를 원본으로 오답) 명시.

<!-- codex-review:start -->

> **[검토 · codex · R-02 · 중간]** **추가 지적.** **기준선의 시점과 증거 해석.** ③을 MVP 조건이 아니라고 하면서 세 과업 모두의 수작업 기준선을 Rhino alpha 착수 전에 요구하면 후속 사이트 자료 준비가 첫 기능을 막는다. 제안: ①의 시험 자료·수작업 기준선은 그 alpha 가치 시험 전, ②는 ZWCAD 가치 시험 전, ③은 사이트 스킬 착수 시 측정한다. 작은 기술 실험과 읽기/입력 보존 구현은 이 전체 가치 시험과 구분한다. 1~2명 검수는 초기 사용성의 실패 신호를 찾는 데 유용하지만 일반적인 우위를 입증하는 표본으로 표현하지 않는다. 목표는 기준선 측정 뒤, AI 비교 결과를 보기 전에 정하고, 원래 오인·재작업이 0이면 감소 대신 비열화와 시간 지표 등 판정 방식을 선언한다.

## 4. 재검토 조건

과업 ①이 Rhino alpha에서 수작업 대비 절감을 보이지 못하면 ADR-001·ADR-004의 축소 조건이 발동한다.

## 부록 · Codex 검토 요약 (2026-09-17)

구체적인 과업과 개발자 외 검수자를 정한 것은 좋은 진전이다. 남은 것은 과업의 정답·허용 오차를 재현 가능하게 만들고, 후속 과업의 기준선이 현재 단계의 불필요한 선행 조건이 되지 않도록 하는 일이다.

이번 검토는 사용자 수락이나 본문 반영을 뜻하지 않는다. 기존 스레드는 같은 ID로 갱신하고, 새 지적은 별도 ID를 부여한다. 철회 기록은 상대 참조가 정리될 때까지 남긴다.
