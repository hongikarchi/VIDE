# ADR-006 · 대표 검수 과업과 평가 범위

## 1. 결정

다음 세 가지를 MVP의 대표 사용자 검수 과업으로 채택한다. 이는 플랫폼을 특정 전문 업무 도구로 축소하는 결정이 아니라, 이미 포함한 능력이 연결되어 작동하는지 확인하는 기준이다.

| 과업 | 완료할 사용자 행동 | 확인할 가치 |
|---|---|---|
| ① 각 호스트의 공간 입력과 수정 | Rhino·ZWCAD 각각에서 대상 지정, 문장·스케치 요청, 후보 검토와 지시 수정, 원본 반영, 네이티브 재편집·저장 | 양쪽 모두에서 입력·후보·개입·결과가 이어지는가 |
| ② 도면과 모델의 연계 | 지원 CAD 정보를 Rhino 후보에 활용하고 같은 설계 변경을 두 호스트의 지정 대상에 반영하는 흐름 확인 | 한 요청의 연계, 독립 작업 병렬·의존 작업 순서, 호스트별 실제 결과를 구분하는가 |
| ③ 웹 검토에서 수정·전달까지 | 모델·표 열람, 웹 핀·코멘트·스케치, 로컬 작업 연결, 전후 검토본 비교, 표·요약 내보내기 | 공유·의견·수정·기록·전달이 연결되는가 |

작은 확장의 실제 등록·실행·실패·비활성화, 설치·재개·자료 보존과 공통 권한 보호는 별도 필수 검수로 유지한다. 세 과업의 통과를 다른 수용 기준 전체의 통과로 대신하지 않는다.

## 2. PRD·SPEC·PLAN의 역할

PRD §16.4가 대표 과업과 성공의 의미를 소유한다. SPEC은 지원 객체·입력·동작·유지 조건·기본 계산·기대 결과를 구체화한다. PLAN은 시험 파일·장비·순서·반복·허용 오차·기록과 자동/사람 검수 방법을 정한다.

특정 벽을 몇 mm 옮기는지, 호스트 명령을 몇 번 호출하는지, 층별 면적을 어떤 절단 기준으로 산정하는지, 정확히 몇 명을 검수에 참여시키는지는 이번 승인으로 고정하지 않았다. 개발자가 모의 결과를 실제 네이티브 검수로 보고하지 않도록 실제 증거와 미시험을 구분한다.

## 3. 두 기준선과 진행 시점

PRD §16.1·ADR-012의 수작업 및 에이전트+MCP 대비 개선 목표를 유지한다. 총시간·대상 오인·재작업을 비교하되 같은 조건을 재현하지 못한 범위와 미측정을 드러낸다. 목표 미달에 따른 자동 범위 축소는 없다.

각 기능은 작은 단위로 먼저 구현할 수 있다. 세 과업과 모든 후속 스킬의 비교 측정을 끝내야 첫 기능을 시작하는 관문은 두지 않는다. 해당 단계의 가치 평가와 출시 판단 전에 필요한 자료·목표·기준선을 PLAN에서 준비한다.

이전 초안의 '외부 자료로 주변 사이트 모델링'은 전문 스킬의 후속 과업으로 남으며 MVP 검수의 필수 선행조건이 아니다. '층별 면적·일람표'도 계산 조건을 선언하지 않은 보편적인 정답으로 사용하지 않는다. 기본 집계는 FR-22의 실제 지원 범위 안에서 시험한다.

## 4. 사용자 평가

제한 배포의 검증 사용자가 역할에 맞는 행동을 수행하고 상태를 이해하는지 확인한다. 코드 설명을 읽었거나 개발자가 대신 조작한 것만으로 사용자 과업의 성공을 선언하지 않는다. 정확한 인원·모집·역할·판정 방법은 OQ-14와 PLAN에 남긴다.

소수 사용자 시험을 모든 사용자의 성능 우위 입증으로 확대하지 않는다. 전문 결과의 평가와 비전공자의 이해·의견 작성 평가는 구분한다.

## 5. 승인 근거

2026-09-18 순차 결정 14에서 사용자가 세 대표 시나리오와 세부 시험 조건의 SPEC·PLAN 위임을 수락했다. 기준 커밋은 `e6856742b899d857059fb3f5da6d36cdee210220`이다. 이 결정은 검수 계획의 입력이며 시험 실행·성능 측정 결과가 아니다.
