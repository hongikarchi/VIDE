# 연결 ID를 문서 안에 저장한다

## 결정

2026-10-02 사용자 결정: "sync 부분은 추천대로 갈게. 그리고 D5처럼 묶을 수 있게 연결 ID를 문서 안에 저장하는 거 좋은 것 같아." **승인 범위:** 결정 1~4는 사용자가 받아들인 추천과 문서 안 연결 ID이고, 5는 이를 구현하기 위한 구체화다. 동작 정본은 [SPEC-01](../specs/SPEC-01-project-input-sync.md).11의 1, 물리 계약은 [ARCH-01](../architecture/ARCH-01-system.md) §7 「프로젝트 연결 파일(Link)」, 화면은 [Design](../../Design.md) §03·SCR-12, 작업은 [PLAN-16](../plans/PLAN-16-document-links.md) T-107·T-108이다.

1. **연결 ID를 문서에 저장한다(D5, LiveSync 방식).** Link할 때 플러그인이 VIDE 연결 행의 ID를 그 문서 안에 적는다. Rhino는 문서 사용자 문자열(`doc.Strings`, 구역 `VIDE`, 항목 `link:<프로젝트 ID>`), ZWCAD는 명명 객체 사전의 `VIDE_LINKS` 사전(프로젝트 ID마다 Xrecord 하나)이다. 열린 문서와 연결 행을 맞출 때 같은 창의 행 다음으로 이 ID를 경로·이름 추측보다 먼저 쓴다. 그래서 다른 이름으로 저장, 파일 이동·이름 바꾸기, VIDE·호스트 재시작 뒤에도 같은 연결로 이어진다.
2. **원본 무수정 원칙의 한 값 예외.** SPEC-01.11의 "패널과 플러그인은 모델·원본 파일을 임의 수정/저장하지 않는다"는 이 값 하나에 대해 예외다. 플러그인은 객체·레이어·다른 설정을 건드리지 않고, 파일을 저장하지 않는다. 적는 순간 문서가 '수정됨'이 되므로 처음 적을 때 그 사실을 알린다("연결 ID를 문서에 저장했습니다. 저장하면 다음에도 이어집니다"). 사용자가 저장하지 않으면 다음 실행에서는 예전처럼 창·경로로 잇는다.
3. **모호할 때만 묻는다(추천 1).** Link 때 이 창의 행이 없고, 같은 호스트의 닫힌 행 가운데 이 문서일 수 있는 것(같은 경로, 같은 이름, 최근에 닫힘)이 있으면 "기존 'X' 대체(기록 이어짐) / 새 연결 파일로 추가"를 묻는다. 기본 선택은 자동 대조가 고를 행(같은 경로의 행, 없으면 새 항목)이다. 문서가 저장한 ID의 행이 있으면 묻지 않고 그 행으로 잇는다. 사본이 같은 ID를 갖고 다른 창에서 이미 그 행이 열려 있으면 두 번째 창의 Link에서 묻고 기본은 새 항목이다. 모호하지 않은 Link는 지금과 같다.
4. **따라감 알림과 정리(추천 2·3).** 자동 따라가기가 행의 경로를 바꾸거나(다른 이름으로 저장) 다시 연 창에 경로로 이으면 목록의 그 행에 "'A' → 'B'로 따라감 · [새 항목으로 분리]"를 한 번 보인다. 분리하면 그 창은 새 행이 되고 이전 행은 기록을 지닌 채 이전 파일로 돌아간다. 같은 창의 중복 행은 [합치기](기록을 열린 행으로 옮김), 기록 없는 닫힌 행은 [빼기]를 보인다.
5. **구현 구체화.** 엔진 `POST …/links`는 `storedId`(문서가 가진 ID)·`replace`(행 ID 또는 `'new'`)·`ask`(플러그인이 물을 수 있음)를 받고, 물어야 하면 409 `LINK_CHOICE`와 후보·기본값을 돌려준다. `ask`가 없는 이전 플러그인은 예전처럼 묻지 않고 잇는다. 플러그인 상태(`attachedStatus`)는 저장된 ID 목록 `linkIds`를 보고하고, [새 항목으로 분리]는 엔진이 플러그인의 `setLinkId`로 새 행의 ID를 문서에 다시 적는다. 알림은 엔진 메모리에 두며(재시작하면 사라짐) DB 스키마는 바꾸지 않는다. 합치기는 옮기는 쪽 요청의 `input.linkId`와 jig 읽기·만들기 기록의 `linkId`를 받는 쪽으로 바꾸고 행을 뺀다.

## 맥락

연결 행은 창(`instance`·`documentId`)과 경로로만 문서를 알아봤다(T-095). 창은 재시작하면 바뀌고 경로는 이동·이름 바꾸기·다른 이름 저장으로 바뀌어, 예전 기록을 이을지 새 연결로 둘지를 엔진이 추측해야 했다. 같은 이름의 다른 파일이나 사본을 같은 연결로 잇거나, 이어야 할 파일을 새 행으로 만드는 일이 생겼다. 문서 안의 ID는 파일이 어디로 가든 따라가므로 추측이 필요 없는 경우가 대부분이 되고, 남는 모호한 경우(ID가 없는 예전 문서, 사본)만 사용자에게 묻는다.

## 결과

- 연결 ID를 저장한 문서는 Link를 다시 눌러도 묻지 않고 같은 행으로 이어진다. 저장하지 않은 문서·이전 버전 플러그인으로 연결한 문서는 예전 규칙(창, 경로)과 모호할 때의 질문을 따른다.
- 파일 사본은 같은 ID를 갖는다. 두 창이 동시에 열리면 두 번째 창의 Link에서 묻고, 새 항목을 고르면 그 사본에 새 ID를 적는다. 동시에 열리지 않은 사본은 같은 연결로 이어진다(사용자가 [새 항목으로 분리]로 나눌 수 있다).
- 사용자 문서에 VIDE 값이 남는다. 프로젝트를 지우거나 연결을 빼도 문서의 값은 지우지 않으며(문서를 다시 수정하지 않음), 그 ID의 행이 없으면 엔진은 무시한다.
- 실제 Rhino·ZWCAD에서의 쓰기·저장 뒤 유지는 설치본 반영 뒤 합성 문서로 확인한다(PLAN-16 T-108).
