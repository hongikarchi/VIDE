# PC가 꺼져도 프로젝트 열기 — 할 일과 작업 이력 요약을 계정 사이트에 둔다

## 결정

2026-10-06 사용자 결정: "지금은 메인 컴퓨터가 꺼져있으면 해당 프로젝트가 아예 열리지 않는데, 모델은 안 보여도 그냥 접속이 가능하면 좋겠음." 같은 날 고른 범위: PC가 꺼져 있어도 프로젝트는 사이트에서 늘 열린다. 할 일과 노트는 사이트에서 읽고 쓸 수 있고(쓴 것은 PC가 켜질 때 PC에 반영), 작업 이력은 요약만 읽기 전용으로 보인다. 모델 저장본은 기존 스위치(`SNAPSHOTS_ENABLED`·용량 한도) 그대로 두고 R2 정리가 끝났다고 사용자가 말할 때 켠다. 동작은 [SPEC-04.10](../specs/SPEC-04-web-review.md), 물리 계약은 [ARCH-01 계정 웹사이트와 작업 PC](../architecture/ARCH-01-system.md), 작업은 [PLAN-33](../plans/PLAN-33-offline-project.md)이다.

1. **작업 이력 요약이 PC를 떠난다.** 이 결정 전 SPEC-04.9는 "대화·작업 이력은 올리지 않는다"였다. 이제 요청마다 **요청 글(600자까지), 답의 처음 세 줄(400자까지), 상태, 시각, 연결 파일 이름**만 올린다. 모델·형상, 첨부 파일(이름 포함), 핀·스케치, AI 공급자·모델 이름, 도구 기록, 원본 경로는 올리지 않는다. 연결 파일의 Sync, 여러 파일 요청의 파일별 하위 요청, 사용자가 이력에서 지운 요청은 빼고 최근 50개만 둔다. 사이트는 이 여섯 필드만 저장하고 PC가 더 보내도 버린다.
2. **할 일은 사본과 대기열로.** PC가 프로젝트의 할 일(열린 항목 전부와 최근 완료 100개, 500개까지)을 사이트에 통째로 올린다. 사이트에서의 추가·완료·내용·날짜·삭제는 사이트의 대기열에 남고, 화면은 PC 사본 위에 대기 중인 변경을 겹쳐 보인다(항목마다 "PC 반영 대기"). 대기 중인 변경은 항목마다 하나로 합친다. PC는 켜지면 heartbeat 응답으로 받아 적용하고, 적용한 목록을 먼저 다시 올린 뒤 처리 결과를 알린다.
3. **충돌은 나중 쓰기가 이긴다.** 사이트가 읽은 뒤 PC에서 그 항목이 바뀌지 않았으면(같은 revision) 그대로 적용한다. 바뀌었으면 사이트 변경 시각과 PC 항목의 마지막 변경 시각 중 나중 것이 남고, 항목 글 끝에 `[사이트 수정 충돌 <시각>: …]`로 무엇이 어떻게 겹쳤는지 적는다. PC에서 지운 항목에 대한 변경은 버린다. 같은 변경은 두 번 적용하지 않는다(PC가 변경 id·버전을 기억한다).
4. **보는 사람은 소유자만.** 할 일·작업 이력 요약·저장된 모델·요청 대기는 프로젝트 소유자만 읽고 쓴다. 공유 참여자(열람자·의견 작성자)는 지금처럼 게시본(SPEC-04.4)만 보고 이 화면의 API에 403을 받는다. 참여자 역할은 게시본 열람·의견을 위해 만든 것이라 소유자의 작업 이력·할 일 쓰기를 열어 줄 근거가 없다(사용자 확인 대기, 아래 「남은 확인」).
5. **기본 켜짐, 프로젝트별 끄기.** 계정에 로그인한 PC의 모든 프로젝트가 할 일·이력 요약을 올린다. VIDE의 연결 파일 목록 아래 기존 "PC가 꺼져도 사이트에서 보기" 옆의 "할 일·작업 이력 요약을 사이트에 올리기"를 끄면 그 프로젝트의 사본과 요약을 사이트에서 지우고 더 올리지 않는다. 모델 저장본 스위치와 따로 동작한다(저장본을 끈 채로도 요약은 올라간다).
6. **비용.** 할 일·요약은 D1 행이다(R2를 쓰지 않음). 바뀐 때만 올리고(값싼 지문 비교, heartbeat 15초마다), 이력은 1분에 한 번까지다. `UPLOADS_ENABLED=false`(R2 업로드 정지)는 이것을 막지 않는다.

## 맥락

- 사이트의 "열기"는 PC가 꺼져 있으면 `HOST_OFFLINE`·`HOST_NOT_FOUND`·`HOST_CHOICE_REQUIRED`로 끝났다. 저장본 화면(PLAN-20)은 소유자가 저장본을 켠 프로젝트에서만 쓸모가 있었고, 저장본은 R2 과금 결정 전까지 꺼져 있다(PLAN-20 「용량 판단」).
- 할 일은 프로젝트별 DB(ADR-032)의 `agenda_items`에 있고 revision으로 동시 편집을 막는다(SPEC-01.14). 사이트는 그 revision을 그대로 받아 충돌 판단에 쓴다.
- 노트(실시간 공유 노트)는 PLAN-32가 만든다. 이 결정은 노트의 저장 위치를 정하지 않고, 사이트 화면에 노트 자리만 둔다.

## 고려한 대안

- **이력 전체(답 전문·첨부 이름 포함)를 올리기:** 사이트에서 더 많이 보이지만 설계 내용과 고객 자료 이름이 PC 밖에 쌓인다. 요약으로도 "무엇을 했는지"는 알 수 있어 택하지 않았다.
- **할 일을 사이트가 정본으로:** PC와 사이트가 같은 목록을 실시간 공유하려면 PC 쪽 저장 구조와 대시보드(PLAN-30)를 함께 바꿔야 한다. 정본은 PC에 두고 사이트는 사본·대기열로 했다.
- **참여자에게도 열람 허용:** 팀 작업에는 유용하지만 지금 역할(열람자·의견 작성자)은 게시본 범위의 권한이다. 별도 역할이나 공유 범위가 정해질 때 다시 본다.

## 남은 확인
