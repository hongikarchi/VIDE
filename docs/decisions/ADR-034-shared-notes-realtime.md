# 공유 노트·일지 — 사이트 원본, 실시간 공동 편집

## 결정

2026-10-06 사용자 요청과 결정이다. "Notion처럼 여러 사람이 텍스트로 정리할 수 있으면 좋겠음. 해당 노트들은 자동으로 서버에 연결되도록. 이 부분은 협의 사항 이쪽이랑 연동되면 좋을 듯. 일기장처럼 매일매일 작업 상황 기록할 수 있도록." 이어서 **노트의 원본은 계정 사이트**(PC는 AI가 읽을 사본만), **초대된 구성원은 모두 편집**, **실시간 공동 편집으로 바로 간다**("실시간으로 바로 갑시다")를 정했다. 아래 1~3은 그 결정이고 4~9는 구현을 위한 구체화로 사용자 확인을 기다린다(`status: review`). 동작은 [SPEC-10](../specs/SPEC-10-shared-notes.md), 물리 계약은 [ARCH-01](../architecture/ARCH-01-system.md) §6 「공유 노트」, 작업은 [PLAN-32](../plans/PLAN-32-shared-notes.md)다. 제품 범위 반영은 PRD의 첨삭 제안(FR-26, R-77)으로 냈다.

1. **원본은 사이트.** 노트·협의 사항·일지는 계정 사이트(Cloudflare)의 프로젝트에 속한다. 사이트 D1의 `notes` 행이 목록·제목·종류·날짜와 Markdown 사본을 갖고, 본문의 실시간 원본은 그 노트의 Durable Object에 있는 Yjs 문서다. 작업 PC는 그 프로젝트의 구성원으로 접속해 사본을 받아 둔다. 이는 [ADR-018](ADR-018-project-knowledge-store.md)이 미룬 "팀 공동 저장" 가운데 **사람이 쓰는 노트**에 한해 사이트 저장을 연다는 뜻이며, 프로젝트 자료(C-02) DB나 대화·실행 기록을 사이트로 옮기는 결정이 아니다.
2. **구성원 모두 편집.** 프로젝트 구성원이면 역할(소유자·열람자·의견 작성자)과 관계없이 노트를 만들고 고친다. 지우기는 만든 사람이나 소유자만 한다. 이 편집 권한은 노트에만 있고 원본 CAD·AI 실행 권한을 만들지 않는다(SPEC-04.2·04.8의 경계 유지).
3. **실시간 공동 편집.** 여러 사람이 같은 노트를 동시에 고치고 서로의 글과 커서를 바로 본다. 합치기는 CRDT(Yjs)로 하며 잠금·마지막 저장 우선을 쓰지 않는다.
4. **노트마다 Durable Object 하나.** `NoteRoom`(SQLite 저장 DO, 무료 요금제에서 쓸 수 있는 유일한 DO 종류)이 노트 하나의 Yjs 문서를 들고, 브라우저와 PC가 각자 WebSocket 하나로 붙는다. Hibernation API로 붙어 있되 조용한 동안은 요금이 붙지 않는다. 들어온 갱신은 다른 소켓에 바로 보내고 메모리에 모았다가 약 1초마다 한 행으로 DO SQLite에 쓰며(행 100개가 넘으면 상태 하나로 압축), D1의 Markdown 사본은 최대 5초에 한 번과 마지막 사람이 나갈 때 쓴다. 커서·접속 표시(awareness)는 저장하지 않고 중계만 한다.
5. **소켓 인증은 1분 표.** 소켓을 열기 전에 사이트 API(브라우저는 로그인 쿠키, PC는 PC 키)가 구성원임을 확인하고 사이트 비밀값 HMAC으로 서명한 1분짜리 표(계정·프로젝트·노트)를 준다. 소켓 주소는 그 표만 받고, 열 때 구성원 여부와 노트 존재를 다시 확인한다. PC의 WebSocket은 머리글을 붙일 수 없으므로 이 방식을 브라우저와 PC가 함께 쓴다.
6. **PC는 사본과 오프라인 대기.** 엔진이 연 노트마다 Yjs 복제본을 `<데이터>/projects/<id>/notes/.yjs/`에 두고 사이트에 붙는다. 사이트에 닿지 않는 동안의 편집은 그 복제본에 남고(`.pending` 표시), 다시 연결되면 Yjs 동기화 단계가 빠진 갱신을 보낸다. 별도 대기열 형식을 만들지 않는다. VIDE 화면은 사이트가 아니라 엔진에 붙는다(SSE + POST): 로컬·터널·사이트 중계 어디서 열어도 같다.
7. **AI는 Markdown 사본을 읽는다.** 엔진은 노트마다 `notes/<id>.md`, 일지는 `notes/journal-YYYY-MM-DD.md`, 목록은 `notes/README.md`로 쓴다. 이 폴더는 프로젝트 기록 폴더 안이라 AI가 기본 Read·Glob·Grep으로 묻지 않고 읽고([ADR-031](ADR-031-stock-first.md) 6), 턴 지시가 위치를 알린다. 노트 전용 AI 도구는 만들지 않는다. AI가 사이트 노트에 쓰는 길은 이번에 두지 않는다.
8. **협의 사항 → 할 일, 퇴근하기 → 일지.** 종류가 '협의 사항'인 노트의 체크 목록(☐) 가운데 끝나지 않은 줄을 [할 일로 보내기] 한 번으로 그 프로젝트의 할 일(SPEC-01.14)에 넣는다(같은 글의 열린 할 일은 건너뜀). 대시보드의 [퇴근하기]가 남기는 하루 요약은 엔진 함수 `appendJournal`로 사이트의 그날 일지 끝에 붙인다(사이트에 닿지 않으면 PC에 두었다가 다음 연결 때 보냄).
9. **편집기.** TipTap 3(ProseMirror) + `@tiptap/extension-collaboration`(y-tiptap)로 블록 편집(제목·목록·번호 목록·체크 목록·인용·구분선, Markdown 단축 입력)을 하고, 같은 React 화면을 사이트와 VIDE가 함께 쓴다. 노트 본문은 Yjs XML 조각 `default`이며 서버와 PC는 ProseMirror 없이 이 조각을 Markdown으로 바꾼다.

## 맥락

- 사이트는 Cloudflare Workers + D1 + R2 구성이다([ADR-015](ADR-015-cloudflare-sharing-experiment.md), ARCH-01 §6). 사이트 Worker는 요청마다 상태가 없어 여러 연결을 한 문서로 묶을 자리가 없다. Durable Object는 이름 하나에 인스턴스 하나가 전 세계에서 하나로 보장되어 공동 편집 방(room)에 맞는다.
- 2026-10-06 Cloudflare 문서 확인(무료 요금제, [한도](https://developers.cloudflare.com/durable-objects/platform/limits/)·[요금](https://developers.cloudflare.com/durable-objects/platform/pricing/)): SQLite 저장 DO만 사용 가능(키-값 저장 DO는 유료), 계정 저장 5 GB, 객체당 10 GB, 객체 수 제한 없음, DO 클래스 100개, 요청 하루 100,000건, 실행 시간 하루 13,000 GB-s, SQLite 행 읽기 하루 500만·쓰기 10만, WebSocket 받는 메시지는 20개가 요청 1건으로 계산, 받는 메시지 하나 32 MiB, 요청당 CPU 30초, 객체 하나 초당 약 1,000요청(연성 한도). 잠들 수 있는 조용한 객체는 실행 시간 요금이 없다.
- 이 한도에서 비용을 가르는 것은 **행 쓰기**다. 키 하나마다 갱신 하나를 쓰면 몇 사람이 하루 타이핑해도 10만 행에 닿을 수 있어, 1초 묶음(결정 4)으로 쓴다. 타이핑 메시지는 20개당 요청 1건이라 사람 다섯이 하루 종일 써도 요청 한도에 여유가 있다. 사이트 전체 요청 수(Worker 무료 10만/일)는 PC 중계와 함께 쓰므로 PLAN §6.5의 사용량 확인 대상이다.
- PC가 꺼져 있어도 다른 구성원은 사이트에서 노트를 쓴다. 이것이 원본을 사이트에 둔 이유다(사용자 결정 1). 반대로 PC의 AI는 사이트를 직접 읽지 않고 PC의 사본만 읽는다(키·네트워크 권한을 AI에 주지 않음).

## 선택지

| 질문 | 안 | 판단 |
|---|---|---|
| 원본 | PC DB(ADR-032)에 두고 사이트로 복사 / 사이트에 두고 PC가 사본 | 사이트(사용자 결정). PC가 꺼져도 구성원이 쓴다 |
| 편집 방식 | 한 사람씩 잠금 / 마지막 저장 우선 / CRDT 실시간 | CRDT 실시간(사용자 결정 "실시간으로 바로") |
| CRDT | Yjs / Automerge / 직접 OT | Yjs. 편집기 결합(y-prosemirror 계열)·y-protocols 메시지·문서 크기가 검증됐다 |
| 서버 | Worker + D1 폴링 / DO 하나에 모든 노트 / 노트마다 DO | 노트마다 DO. 방이 작아 메모리·잠듦이 노트 단위로 된다 |
| DO 저장 | 키-값 / SQLite | SQLite(무료 요금제는 SQLite만) |
| 갱신 저장 | 메시지마다 한 행 / 1초 묶음 + 압축 | 1초 묶음. 하루 쓰기 10만 행 안에 둔다. 잃을 수 있는 1초는 접속한 쪽이 다시 붙을 때 동기화 단계로 다시 보낸다 |
| 소켓 인증 | 쿠키 / Authorization 머리글 / 1분 표 | 1분 표. PC의 WebSocket이 머리글을 못 붙이고, 쿠키가 없는 PC와 같은 길을 쓴다 |
| 편집기 | BlockNote / TipTap / 직접 | TipTap 3. BlockNote는 화면 꾸밈 묶음(Mantine 등)이 커서 두 화면(사이트·VIDE)의 디자인 기준과 따로 논다 |
| VIDE 화면의 연결 | 사이트 소켓 직접 / 엔진 경유 | 엔진 경유. 화면에는 사이트 쿠키가 없고, 엔진이 오프라인 편집을 들고 있어야 한다 |
| AI 읽기 | 노트 도구 / 파일 사본 | 파일 사본(ADR-031 6, 기본 도구 우선) |

## 결과

- 사이트 배포에 DO 바인딩(`NOTES` → `NoteRoom`)과 DO 이행 태그(`v1-notes`, `new_sqlite_classes`)가 붙고, D1 이행 `0008-notes.sql`이 생긴다. 배포는 사용자·리드가 한다(PLAN-32 「배포」).
- Worker 묶음이 Yjs만큼 커진다(시험 빌드 약 2.9 MB, gzip 약 0.5 MB, 무료 3 MB 압축 한도 안). 사이트 화면의 편집기는 노트를 열 때만 받는다(별도 청크).
- 노트 내용은 구성원 모두와 그들의 PC 사본에 간다. 공개하지 않을 자료를 노트에 적지 않도록 화면에 "구성원 모두가 본다"를 알린다(SPEC-10.2).
- 구성원에서 빠진 사람의 이미 열린 소켓은 그 연결이 끝날 때까지 남는다(다음 연결부터 막힘). 즉시 끊기는 후속(SPEC-10.8).

## 다시 검토할 때

- 노트 수·편집량이 무료 한도(행 쓰기 10만/일, 요청 10만/일)에 닿을 때.
- 표·이미지·파일 붙이기, 노트 안 객체 핀, AI가 노트에 쓰기, 노트별 권한을 요구할 때.
- 사이트를 Cloudflare 밖으로 옮길 때(ADR-015).
