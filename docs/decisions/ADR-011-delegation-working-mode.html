ADR-011 · 위임형 작업 방식

01 / 배경

PRD §8 여정(§8.2~§8.5)과 §9.5(확인이 필요한 순간)는 대상 지정 → 후보 → 개입 → 반영의 단계를 적지만, AI가 여러 단계를 스스로 진행하는지 단계마다 확인을 받는지가 문장마다 달랐다. §2 가설 5("매 단계 승인하면 직접 CAD를 쓰는 것만큼 번거롭다")는 위임을 전제하지만 본문이 그 전제를 선언하지 않았다(PRD R-58). 기준 과업(ADR-006)은 호스트 명령 3회 이상·유지 조건 1개 이상을 요구하므로, 작업 방식이 정해져야 측정이 뜻을 갖는다.

02 / 선택지

안 내용 트레이드오프
A 단계별 확인 — 도구 호출·후보마다 승인 통제가 세밀. 가설 5를 검증할 수 없고 직접 CAD보다 느림
B 위임형 기본 — 목표·조건을 주면 여러 단계 진행, 중간 결과는 후보로 계속 표시, 원본 반영 시점에만 확인 사용자는 언제든 끼어들거나 멈춘다. 후보 격리(ADR-003)와 개입 상태(FR-11)가 전제
C 두 모드(빠른 요청 / 위임 작업)를 따로 제공 작은 요청이 빠름. 모드 전환과 상태 기계가 두 벌

03 / 결정

B. 위임형이 기본이다.

  • 목표와 지켜야 할 조건(유지 대상 등)을 주면 AI가 여러 단계를 진행한다.
  • 중간 결과는 후보로 계속 보인다. 사용자는 언제든 끼어들거나 멈춘다(FR-11: 접수·반영·정지 구분).
  • 원본 반영 시점에만 확인한다.
  • 작은 요청도 같은 구조 안에서 빨리 끝난다. 별도 모드는 없다.
  • PRD §4.3의 보호 규칙(쓰기 승인, 사람 수정 보호, 늦은 결과가 새 상태를 덮어쓰지 않음)은 위임 범위 안에서도 그대로다.

04 / 근거

가설 5는 이 방식의 전제다. 위임 없이는 기준 과업의 총시간이 두 기준선(ADR-012)을 이길 수 없고, 별도 모드는 상태·화면·시험을 두 벌로 만든다. 후보 격리(ADR-003)와 개입 상태(FR-11)가 이미 원본을 보호하므로 확인 지점을 반영 시점으로 모을 수 있다.

05 / 결과 — 적용 시 바꿀 문장

  • PRD §2: 가설 5는 이 방식의 전제라고 한 문장.
  • PRD §8.2~§8.5 여정과 §9.5를 이 방식으로 맞춘다 — 목표·조건 전달 → 여러 단계 진행 → 후보 표시 → 끼어들기·멈춤 → 반영 시 확인.
  • SPEC-00-common: 실행·개입·확인 상태의 논리적 의미(위임 범위, 끼어들기·멈춤, 반영 확인)를 이 결정 기준으로 쓴다. 필드·전송 형식은 PLAN.
  • Design §06·§07: 이 전제와 어긋나는 문장이 있을 때만 고친다.

06 / 재검토 조건

  • 기준 과업 시험에서 잘못된 대상·조건 위반이 후보 단계에서 잡히지 않고 반영 직전에야 드러나는 사례가 반복되면 중간 확인 지점을 추가할지 재검토한다.
  • 별도 모드 요구가 실제 사용에서 나오면 그때 검토한다.

07 / 출처
