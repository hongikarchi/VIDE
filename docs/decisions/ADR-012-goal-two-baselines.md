# ADR-012 · 목표 — 두 기준선 대비 개선

## 1. 배경

VIDE가 실제 건축가의 부담을 줄이는지 판단하려면 단순 성공 시연만으로는 부족하다. 기존 작업 방식과 비교해야 하지만, 하나의 부분 지표가 나쁘다고 제품 범위를 자동으로 줄이는 관문으로 사용하면 시험 미완료·구현 보완 가능·다른 사용자 가치를 구분하기 어렵다.

이 결정은 수작업과 일반 에이전트+MCP 흐름을 비교 기준으로 두되, 측정 결과를 자동 축소 조건이 아닌 사용자 재결정 자료로 사용하는 원칙을 정한다.

## 2. 선택지

| 안 | 내용 | 트레이드오프 |
|---|---|---|
| A | 판정 관문 — 수치 미달 시 자동 범위 축소 | 빠르게 범위를 줄일 수 있으나 시험 미완료와 실패를 혼동하고 부분 지표가 다른 가치를 지울 수 있음 |
| B | 목표 — 두 기준선 대비 개선을 목표로 하고 미달은 사용자 재결정 시점 | 자동 축소 없음. 비교 절차·환경을 PLAN에서 별도로 관리해야 함 |
| C | 비교 목표 없이 기능 시험만 수행 | 동작 여부는 확인하지만 VIDE 고유의 가치가 실제로 개선됐는지 판단하기 어려움 |

## 3. 결정

**B. 두 기준선 대비 개선은 출시 범위를 자동으로 자르는 판정 관문이 아니라 제품 목표다.**

비교 기준은 다음 두 가지다.

1. **수작업** — 같은 과업을 사용자가 기존 호스트 도구로 직접 수행
2. **에이전트+MCP** — Claude·Codex 같은 일반 에이전트를 호스트 제어 경로에 연결해 VIDE의 별도 구조 없이 수행

VIDE는 같은 조건의 지원 과업에서 **총시간, 대상 오인, 재작업(헛수고)**을 줄이는 것을 목표로 한다. 이 세 항목 중 하나만 좋아졌다고 전체 성공으로 단정하지 않고, 모든 과업에서 세 항목을 똑같은 방식으로 측정해야 한다고 강제하지도 않는다.

대표 검수 과업의 정본은 PRD §16.4와 ADR-006이다. 과업 ①은 첫 호스트 alpha에서 두 기준선과 비교하기 좋은 초기 가치 시험으로 사용할 수 있지만, 그것이 과업 ②·③의 사용자 가치나 전체 MVP의 유일한 판정 과업을 뜻하지 않는다.

목표 미달은 자동 범위 축소가 아니라 **사용자의 재결정 시점**이다. 유지, 구현 보완, 순서 변경, 노력 상한 설정, 범위 변경 중 무엇을 할지는 측정 증거를 보고 사용자가 결정한다. 비교 절차·시점·측정 환경은 PLAN §6·§7·§9에서 정한다.

## 4. 근거

- 수작업만 비교하면 `AI를 붙인 효과`와 VIDE의 핀·스케치·후보·진행·개입 구조의 효과를 분리하기 어렵다.
- 일반 에이전트+MCP 기준선을 함께 두면 VIDE가 추가로 제공하는 구조가 실제로 시간·오인·재작업을 줄였는지 볼 수 있다.
- 자동 축소 조건은 시험 미완료나 개선 가능한 구현을 제품 가치 부재로 오해할 수 있다.
- 자체 뷰·웹 검토·호스트 연계처럼 여러 가치를 가진 기능을 단일 지표 하나로 자동 폐기하지 않는다.

## 5. 문서 적용

- PRD §16.1: 두 기준선과 개선 목표의 정본.
- PRD §16.4: 대표 검수 과업 세 가지와 성공의 의미.
- ADR-006: 실제 대표 과업의 역할과 검증 사용자 범위.
- PLAN §6·§7·§9: 동일 조건의 비교 절차, 시점, 기록 방법과 사용자 재결정 지점.
- ADR-004 등 개별 기능 문서는 자체 자동 축소 조건을 두지 않고, 측정 결과를 이 결정의 재결정 자료로 사용한다.

## 6. 재검토 조건

- 특정 과업에서 두 기준선 중 하나를 같은 조건으로 재현할 수 없으면 그 차이를 기록하고 대체 비교 방법을 사용자가 정한다.
- 기준선의 대상 오인·재작업이 이미 0인 과업처럼 개선 목표가 의미를 잃는 경우 해당 과업의 측정 항목을 조정한다.
- 대표 과업이나 제품 가치가 바뀌어 현재 두 기준선이 비교 대상으로 부적절해지면 기준선을 다시 검토한다.
