# 구조 분석 jig의 첫 출시 포함과 Rust 해석 코어

## 결정

1. **범위:** 전문 스킬 가운데 구조 분석 jig(J-09)를 첫 출시 범위에 넣는다. PRD는 이를 FR-23(MVP 지원 범위)과 AC-40으로 두고, 나머지 전문 스킬은 FR-21 후속 확장으로 유지한다. OQ-07의 "첫 전문 스킬" 항목이 이 결정으로 정해진다.
2. **해석 코어 언어:** 해석·부재 검정 코어는 **Rust**로 구현한다. Node 서버와의 구동 방식(네이티브 애드온·별도 실행 파일·wasm)은 PLAN-17의 첫 실험으로 정한다.
3. **입력:** 구조 입력은 프로젝트마다 CAD, Rhino 부재 솔리드(Brep), Rhino 중심선 곡선 등으로 다르게 온다. AI가 해석 모델 초안을 만들거나 조정하고, 코드 점검과 사용자 확정을 거친 모델만 해석한다.
4. **교환:** 일반적인 교환은 CAD·Rhino 파일이다. midas MGT 내보내기와 상용 SW의 직접 검토는 특정 프로젝트의 방식이라 일반 요구로 두지 않는다.

## 이유

- 사무소가 반복해 수행한 구조 자동화 자산(RESEARCH-08의 S-18·S-10·S-05)이 있고, KDS 강구조 부재 검정·검증 체계까지 갖춘 출처가 있다. 배치가 자주 바뀌는 계획 단계에서 구조 검토를 빠르게 되풀이하는 것이 사용자 목표다.
- 성능을 우선한 비교(RESEARCH-09 §5)에서 Rust가 속도, MIT 라이선스의 희소 행렬 해법(faer), 한 코드로 서버·Rhino·브라우저에 쓸 수 있는 점, AI 코딩 벤치마크 결과에서 가장 균형이 좋았다. 순수 TypeScript는 희소 해법·고유값 라이브러리가 없고, C#은 기존 자산이 있지만 새 해석 모델 계약에 맞춰 다시 짜야 하는 점은 같았다.
- 입력 형태가 일정하지 않아 결정적 변환기만으로는 모든 경우를 받을 수 없다. 모호한 부분은 AI가, 계산과 판정은 코어가 맡는다.

## 영향

- 해석 모델 계약은 언어와 무관한 JSON으로 ARCH-02가 소유한다. 코어를 바꿔도 계약과 검증 시험 자료는 유지된다.
- 개발 환경에 Rust 도구(rustup·cargo)와 MSVC 빌드 도구가 필요하다. 설치본에는 빌드된 코어 산출물만 들어가며 Python은 넣지 않는다. PyNite 등 Python 기준 해석기는 개발용 교차 검증에만 쓴다.
- 결과는 탐색용 예비값이며 구조계산서·구조기술사의 최종 검토를 대체하지 않는다.
