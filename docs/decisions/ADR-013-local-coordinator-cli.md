# 로컬 제어 계층과 구독 CLI 분리

## 결정과 근거

PLAN §2·3·5에서 Node 로컬 제어 계층이 프로젝트 기록·대상·권한·명령 수명을 소유하고, CLI는 허용 자료를 받은 뒤 구조화된 동작 제안을 반환하도록 한다. 사용자의 구독형 경로 우선 지시에 따라 설치된 Claude Code를 첫 어댑터 후보로 삼는다. [연결 실험](../tdd/SPIKE-2026-09-19-ai-execution-path.md)에서 구독 로그인·도구 없는 합성 응답을 확인했다. 채택은 개발 경로에 관한 것으로 배포 지원 선언이나 이용 조건 검토 완료를 뜻하지 않는다.

## 대안과 결과

CLI에 셸과 호스트 MCP를 바로 제공하면 도구 실행 순서와 원본 쓰기 통제가 공급자 설정에 종속되므로 첫 경로에서 사용하지 않는다. 직접 API 방식은 인증·한도·공급자 조건이 달라 후속 어댑터로 분리한다. 구독 토큰을 추출해 SDK나 자체 API 클라이언트에 주입하지 않는다.

CLI 세션을 제품 기록의 정본으로 삼지 않는다. 프로세스 종료와 호스트 중단을 구분하고, 재개 시 확인된 결과를 전달하는 새 세션을 허용한다. 공급자 교체 때 저장·호스트 프로토콜을 바꾸지 않는 이점이 있지만 문맥 구성과 다음 동작 검증은 VIDE가 구현해야 한다.

## ChatGPT 구독 경로 추가

사용자는 Claude Code뿐 아니라 GPT 구독도 사용할 수 있도록 요청했다. 공식 Codex CLI의 ChatGPT 로그인을 두 번째 공급자 경로로 추가했다. [공식 인증 문서](https://learn.chatgpt.com/docs/auth)는 구독 인증과 API 키 인증을 구분하고, [비대화형 실행 문서](https://learn.chatgpt.com/docs/non-interactive-mode)는 저장된 CLI 인증 재사용과 JSON 이벤트를 설명한다. VIDE는 공식 도구의 인증을 그대로 사용하고 토큰을 추출·복제하지 않는다. 공급자 선택은 명시적이며 자동 전환하지 않는다. PLAN §5에 구현과 한계를 반영했다.


## 실행 기준 확정 — 2026-09-20

첫 통합은 매 호출 도구 없는 새 CLI 실행으로 구조화 제안을 받고 VIDE가 검증·실행·결과 재조회·다음 문맥 구성을 반복한다. 이전 실행 재개는 VIDE의 확인된 기록에서 새 호출로 시작한다. 공급자 전환 시 새 실행으로 연결하며 세션 ID를 제품 기록의 정본으로 쓰지 않는다. 중단·출력 유실은 호스트 완료의 증거가 아니다.

세션 재사용/app-server는 현재 경로가 아니다. 향후 채택에는 도구 차단, 문맥 격리, 취소/늦은 결과, 재시작 복구, 전송 범위 검증과 이 ADR의 변경이 필요하다. PLAN-01의 유력 후보 표현이 본 결정을 대체하지 않는다. 공급자별 도구 차단을 설치 버전에서 증명하지 못하면 해당 연결은 차단하고 프런트 합성 모드와 구분한다.
