# ADR-005 · AI 실행 형태 — 미결 (스파이크 후 결정)

**대체(superseded) · 2026-09-17.** 제품 결정이 아니라 PLAN 결정이다. PLAN §9 결정 항목으로 이동했다.

## 1. 배경

FR-08 'MVP 한 실행 경로 이상'이 직접 API+자체 하네스인지, 에이전트 CLI/런타임 내장인지, 혼합인지에 따라 §9.3 중단·재개, §10.2 압축, §11.5(현 §11.4) 비용 관측, §1.3 전송 확인, FR-15·FR-18 수용 기준이 지켜지는 정도가 달라진다(PRD R-52, 가이드 Codex R-33·Claude R-39, 제안 OQ-12). 구독형 CLI를 제품 안에 내장하는 것은 이용 약관·데이터 보존·비용 모델이 걸린 제품 제약이다.

## 2. 선택지

| 안 | 내용 | 트레이드오프 |
|---|---|---|
| A | API 기반 자체 하네스(사용자 API 키, 종량제) | 도구 호출 승인/거부·비용 관측·전송 목록·세션 소유가 모두 제품 통제 아래. 하네스를 직접 만들어야 함 |
| B | 에이전트 CLI/런타임 내장 | 하네스 구축 없이 빠름. 비용·전송 관측이 제한되고 제품 내 재사용 허용 여부를 약관으로 확인해야 함 |
| C | 지금 정하지 않고 스파이크 뒤 결정 | 결정이 늦어지는 대신 실측 근거로 정함 |

## 3. 결정

**C. 지금 정하지 않는다.** 가이드 §06 스파이크 순서 ①(AI 실행 경로)의 결과로 결정한다.

- 스파이크가 후보 경로 계열(API+자체 하네스 / 에이전트 SDK / CLI 내장)별로 다음 7항목을 확인/불가/미확인+증거로 기록하면 이 ADR을 갱신해 확정한다: (1) 텍스트+핀 참조+스케치 좌표+이미지의 구조화 입력 (2) 호스트 쓰기 도구 호출을 제품이 승인/거부 (3) 도구 호출 단위 중단과 실제 정지 관측 (4) 앱 재시작 후 제품 소유 세션 ID로 재개 (5) 실행별 토큰·비용 값 취득 (6) 전송 전 자료 목록 표시·제외 (7) 제품 내 재사용의 이용 조건.
- 결정 전까지: 개발·실험 단계에서는 Claude Code·Codex CLI 사용을 허용하고, 출시 경로로는 인정하지 않는다(당시 PRD §11.5에 보강하려던 문장; 해당 내용의 절은 현재 PRD §11.4다). SPEC-00-common의 실행·개입·재개 상태 절은 초안까지만 쓰고 확정하지 않는다.
- 프로젝트 단위 전송 정책(허용/금지)과 로컬 추론 경로 요구 여부(PRD R-52 후반)는 같은 스파이크 결과와 함께 결정한다.

> **[검토 · codex · R-01 · 높음]** **추가 지적.** **일곱 확인 항목의 통과 의미.** 실제 경로를 조사한 뒤 선택하는 방향에 동의한다. 다만 확인 목록이 일곱 항목 모두 완전 지원해야 한다는 출시 조건으로 해석되면 기존 PRD보다 요구가 강해진다. §9.3은 중단 불가와 실제 정지 확인을 구분하고 §11.5는 관측 가능한 비용·추정·관측 불가를 구분한다. 제품 소유 세션/작업 기록 복원도 공급자 내부 세션을 그대로 복원하는 것과 다르다. 제안: 제품이 강제할 쓰기 승인·전송 범위 등 필수 통제와, 중단 단위·비용 정확도·재개 수단처럼 제약을 표시할 능력을 나눠 후보별 증거를 기록한다. API 직접 사용도 이미 실행 중인 호스트 쓰기를 자동 취소해 주지는 않는다. 공식 문서로 제외할 후보는 먼저 좁히고 유력 경로만 작은 실험을 하며, 공급자와 무관한 보호 의미까지 미결로 되돌리지 않는다.

## 부록 · Codex 검토 요약 (2026-09-17)

AI 실행 형태 미결을 정직하게 기록한 점은 적절하다. 다만 공급자 선택 조사와 새로운 제품 필수 요구의 추가가 섞이지 않도록 검증 기준을 구분해야 한다.

이번 검토는 사용자 수락이나 본문 반영을 뜻하지 않는다. 기존 스레드는 같은 ID로 갱신하고, 새 지적은 별도 ID를 부여한다. 철회 기록은 상대 참조가 정리될 때까지 남긴다.
