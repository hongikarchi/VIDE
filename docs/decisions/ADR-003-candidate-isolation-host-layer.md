# ADR-003 · 후보 격리 원칙 — 호스트 안 격리 영역

## 1. 배경

PRD §5·§11.2는 "원본과 분리된, 호스트에서 편집 가능한 실제 후보"를 약속하지만 실현 수단이 없었다. Codex R-42와 Claude R-46은 격리 수단이 호스트마다 다르면 '후보'의 공통 의미가 흔들린다고 지적했고, 호스트별 보장 수준(L1 IDE 측 변경 집합 / L2 호스트 안 격리 영역 / L3 별도 문서)을 선언하는 안을 제안했다(제안 OQ-10). ADR-001로 Revit이 빠지면서 트랜잭션 제약이 사라져 단일 원칙이 가능해졌다.

## 2. 선택지

| 안 | 내용 | 트레이드오프 |
|---|---|---|
| A | 호스트 안 격리 영역(전용 레이어·그룹)으로 통일 | 실제 형상·호스트 도구 재편집·뷰포트 표시가 모두 됨. 원본 객체 무변경을 호스트별로 검수해야 함 |
| B | 별도 호스트 문서(사본)에만 존재 | 원본 문서 절대 무변경. 반영이 문서 간 복사가 되어 참조·속성 유지가 어렵고 두 문서를 오가야 함 |
| C | 호스트별 수준 허용(L1~L3) | 유연하지만 SPEC-00과 UI가 복잡해짐. Revit 추가 시에만 필요할 가능성 |

## 3. 결정

**A. 후보는 원본 문서 안의 격리 영역(전용 레이어 또는 그룹)에 실제 형상으로 존재한다.** Rhino·ZWCAD 모두 같은 원칙이다.

- 수용 기준: **후보를 폐기하면 원본 객체·파일은 무변경**(AC-17·AC-24 보강). 원본 객체는 후보가 채택되어 원본 반영을 확인하기 전까지 수정되지 않는다.
- 후보는 호스트 기본 도구로 재편집할 수 있고, 반영은 격리 영역의 형상을 원본 레이어로 옮기거나 원본 객체를 교체하는 동작으로 정의한다(세부는 SPEC-00-common 2차와 hosts/ 지원표).
- Revit을 추가하는 시점에 C안(수준 선언)으로 확장할지 재검토한다.

## 4. 근거

두 호스트 모두 레이어 기반 격리가 가능하고, 후보가 호스트 안에 있으면 호스트 뷰포트에서 바로 보이며(ADR-004) 호스트 없이 후보를 보존할 필요가 줄어든다.

## 5. 결과 — 적용 시 바꿀 문장

- PRD §5 '후보' 행에 격리 원칙 한 문장, §11.2 탐색 행, AC-17·AC-24에 "후보 폐기 뒤 원본 무변경" 시험, §18에 OQ-10 행(이 ADR 링크).
- SPEC-00-common: 후보 상태(생성·수정·폐기·채택·반영)와 격리 영역 명명 규칙. hosts/rhino.md·hosts/zwcad.md: 격리 영역 구현 방식과 제한.
- Design §08: '기준이 바뀐 후보'(Codex R-34) 표현은 격리 영역 안 후보와 현재 원본의 차이로 정의.

## 6. 재검토 조건

첫 호스트 후보/원본 경계 스파이크(가이드 R-39 순서 ②)에서 "폐기 뒤 원본 무변경"을 보장할 수 없는 경우가 나오면 B안 또는 C안으로 돌아간다.
