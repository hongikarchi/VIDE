# ADR-003 · 후보와 원본의 보호 경계

## 1. 결정

후보는 현재 설계 결과와 명확히 구분하며 같은 호스트 문서 안에 존재할 수 있다. 원본 반영 승인 전에는 후보 작업이 기존 설계 대상의 형상·속성·관계를 변경해서는 안 된다.

후보 추가로 발생하는 문서 변경과 저장 시 포함 여부를 사용자에게 알린다. 후보 폐기는 해당 후보를 대상으로 하며, 그동안 사람이 직접 수정한 원본을 과거 상태로 되돌리지 않는다.

**기존 설계 대상을 보호하는 것과 문서·파일 전체가 무변경인 것은 다르다.** 같은 문서에 후보를 넣는다는 선택만으로 파일 바이트·자동 저장·공유 정의까지 무변경이라고 보장하지 않는다.

## 2. 허용과 구현 방법의 구분

선택한 것은 '같은 문서의 후보를 허용하면서 기존 대상을 보호한다'는 제품 원칙이다. 전용 레이어·그룹 하나를 모든 호스트와 객체의 필수 수단으로 확정하지 않았다.

호스트 내 네이티브 편집과 직접 개입을 우선하되, 분리 방식·문서 변경·저장·폐기·원본 반영의 구체 동작은 SPEC·PLAN에서 정한다. Revit을 제외한 것만으로 보호가 증명되었다고 쓰지 않는다.

## 3. 반영에서 구분할 의미

새 객체 추가, 기존 객체 수정, 기존 객체 교체는 같은 행동이 아니다. 후보와 원본 대응, 보호할 속성·관계, 변경의 유효 기준, 부분 성공·결과 불명·저장 실패의 의미를 SPEC에서 정한다. 레이어 이동을 모든 반영의 의미로 고정하지 않는다.

후보 자체의 변경과 보존 대상 원본의 관련 변경을 구분해야 한다. 문서 버전이 달라졌다는 사실만으로 자기 후보를 원본 충돌로 판정하여 작업을 막는 규칙을 만들지 않는다. 실제 확인 방법은 PLAN과 호스트 검수에서 다룬다.

확인된 원본 반영 이후 캡처·표·보고서·파일 저장이 실패해도 원본 변경을 중복 실행하지 않는다. 여러 호스트의 일괄 성공·원자적 복구는 ADR-009에서 보장 범위 밖으로 둔다.

## 4. 기준 문서

제품의 정본은 PRD §11.2, FR-12와 AC-38이다. 후보/원본·적용/저장 상태는 SPEC-00-common과 관련 기능 SPEC에서, 호스트별 방법·실험은 PLAN과 호스트 지원표에서 구체화한다. OQ-10은 보호 원칙의 재선택이 아니라 남은 상세 동작·검증을 추적한다.

## 5. 승인 근거

2026-09-18 순차 결정 3에서 사용자가 A안(기존 설계 대상 보호·같은 문서 후보 허용)을 수락했다. 기준 커밋은 `e6856742b899d857059fb3f5da6d36cdee210220`이다. 이전 초안의 '후보 폐기 뒤 원본 객체·파일 무변경'과 '전용 레이어/그룹으로 통일'은 이 결정의 정확한 보장과 구현 위임으로 대체한다. 실제 호스트에서 검증되었다는 뜻은 아니다.
