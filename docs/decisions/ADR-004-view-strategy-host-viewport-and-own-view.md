# ADR-004 · 모델 뷰 전략 — 호스트 뷰포트 + IDE 자체 뷰 (양방향 동기화)

## 1. 배경

Design §03의 중앙 '3D/평면/도면/비교'는 IDE 자체 뷰어를 전제하지만 어느 문서도 그 범위를 선언하지 않았다(Design R-39, PRD R-11/Codex R-31, 제안 OQ-11). 자체 뷰어는 호스트별 표시용 형상 추출·좌표 매핑·선택 동기화·렌더러·픽킹·대형 모델 처리를 뜻해 1인 개발에서 가장 큰 단일 비용 항목이다. 제품 형태(독립 IDE vs 호스트 내장 패널 등, PRD R-49)도 이 결정과 묶여 있다.

## 2. 선택지

| 안 | 내용 | 트레이드오프 |
|---|---|---|
| A | 호스트 뷰포트 + IDE 동반 패널(자체 뷰 없음) | 가장 싸다. 호스트 없이는 아무것도 볼 수 없고 웹 검토와 뷰어를 공유할 수 없음 |
| B | IDE 자체 뷰어만 | 호스트 부재 열람·웹 공유 가능. 사실상 뷰어 제품 하나를 더 만드는 일 |
| C | 둘 다 + 양방향 동기화 | 사용자는 어디서든 보고 가리킬 수 있음. A+B의 비용에 동기화 계약이 추가됨 |

## 3. 결정

**C. 호스트 뷰포트와 IDE 자체 뷰를 모두 제공하고, 선택·카메라를 양방향으로 동기화한다.** 소유자는 이 비용을 알고 선택했다.

- 어댑터 계약에 지금부터 포함: 객체 식별, 선택 이벤트(호스트→IDE, IDE→호스트), 카메라 상태, 표시용 형상 추출(Rhino 메시, ZWCAD 2D 엔티티), 좌표계·단위.
- 후보(ADR-003)는 호스트 안에 있으므로 호스트 뷰포트에서는 즉시 보이고, IDE 자체 뷰에는 격리 영역의 표시용 형상으로 그린다.
- 제품 형태는 **독립 Windows IDE**로 유지한다(PRD §1.1). 근거: 여러 호스트를 같은 프로젝트에서 다루고 호스트 없이도 후보·기록을 열람하려면 호스트 밖의 앱이 필요하다.

<!-- codex-review:start -->

> **[검토 · codex · R-01 · 높음]** **추가 지적.** **양방향 동기화의 최소 계약.** 자체 뷰와 호스트 뷰를 함께 제공한다는 사용자 선택을 기준으로 삼는다. 다만 선택·카메라라는 이름만으로 호스트별 동일 표현이나 완전한 동기화를 보장할 수는 없다. 제안: Rhino 3D와 ZWCAD 2D에서 지원할 투영·뷰·단위, 선택 대상 매핑, 대응할 수 없는 카메라/객체의 표시, 갱신 지연 허용 범위를 선언한다. 왕복 이벤트의 출처·순서와 되울림 방지, 문서 종료/재열기 뒤 오래된 이벤트 배제도 확인해야 한다. ADR-009의 단일 활성 대상과 동기화 대상을 일치시키고, 오프라인 표시용 기록은 현재 호스트 상태와 구분한다. 상세 프로토콜·렌더러 선정은 PLAN의 몫이다.

## 4. 근거

소유자의 사용 방식이 호스트 뷰포트와 IDE 창을 오가며 가리키는 것이며, 웹 검토(ADR-007)가 온라인 제출까지 MVP에 포함되어 IDE 자체 뷰어를 웹 뷰어와 공유할 여지가 생겼다.

## 5. 결과 — 적용 시 바꿀 문장

- PRD: '모델 표시'를 새 FR로 두거나 §14.1 '요구할 능력' 열에 호스트별 최소 능력(표시 형상 추출·선택 대응·좌표 변환·갱신 방식)을 명시. §18에 OQ-11 행(이 ADR 링크). §1.1에 제품 형태 근거 2~3문장.
- Design §03을 확정 전제로 고치고 §04·§05·§08의 "호스트 뷰포트에서 할 때 / IDE 뷰에서 할 때"를 구분.
- 가이드 §06 스파이크 순서 ③(표시 기준)이 스파이크 대상으로 확정: Rhino 메시 추출 + 선택 양방향 동기화 + ZWCAD 2D 렌더 최소 실험.

## 6. 축소 조건 (alpha 판정 관문, ADR-006)

- Rhino alpha에서 핀·스케치 대조 시험(가설 1)이 텍스트 대비 대상 오인 감소를 보이지 못하거나, 자체 뷰 구축이 첫 호스트 수직 슬라이스 전체보다 오래 걸리면 **자체 뷰를 후보 C-02로 내리고 A안으로 축소**한다.
- 축소 시 웹 검토(ADR-007)의 뷰어는 캡처·명명된 뷰 기반으로 재정의한다.

<!-- codex-review:start -->

> **[검토 · codex · R-02 · 높음]** **추가 지적.** **비교 시간의 범위와 축소 판단.** 자체 뷰 구축 시간이 그 뷰를 포함하는 첫 호스트 슬라이스 전체보다 오래 걸리는지 비교하면 부분과 전체의 기준이 겹친다. 의도한 기준이 뷰를 제외한 슬라이스 예상 시간이라면 이를 명시해야 한다. 제안: 뷰 실험의 별도 노력 상한·최소 표시/선택 성공 기준을 먼저 정하고 실제 결과로 계속/보완/범위 재결정을 한다. 텍스트 대비 대상 오인이 줄지 않았다는 사실 하나로 호스트 부재 열람·후보 비교·웹 표시 가치까지 부정할 수도 없다. 축소는 사용자가 그 조건까지 수락한 경우에 적용하며, 시험 미완료와 실패를 구분한다.

## 부록 · Codex 검토 요약 (2026-09-17)

양방향 뷰 선택은 존중한다. 확정 전 필요한 것은 지원 능력의 경계와 검증 가능한 축소 기준이며, 모든 대안을 처음부터 다시 비교하는 절차는 아니다.

이번 검토는 사용자 수락이나 본문 반영을 뜻하지 않는다. 기존 스레드는 같은 ID로 갱신하고, 새 지적은 별도 ID를 부여한다. 철회 기록은 상대 참조가 정리될 때까지 남긴다.
