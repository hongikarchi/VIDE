# CAD 도면 역반영과 도곽 미리보기

2026-10-07 사용자 결정("JIG 기능을 상세히 계획")의 도면 부분이다. 동작은 [SPEC-14](../specs/SPEC-14-drawing-generator.md), 실험 근거는 [SPIKE-2026-10-07-drawing-export](../tdd/SPIKE-2026-10-07-drawing-export.md), 선행 구현은 [PLAN-43](PLAN-43-section-finish-xref-submit.md) T-199(실험)·T-200(xref 그래프·표시)·H-ZWCAD-13(숨은 ZWCAD 충돌 안내 응답)이다.

## 2026-10-07 검토 의견과 바뀐 방향

사용자가 계획을 검토하고 이렇게 말했다.

> 도면의 경우 라이노 레이아웃은 필요없고, cad와의 호환성이 중요한 듯.

> 도면 출력의 경우, PDF로 바로 뽑기를 기대하기 보다는 위에서 말한 것처럼 기존에 있는 도면에 반영되는게 더 중요한 것 같아. cad를 플롯하는거는 기존에 있는 lisp들도 있어서 그거를 활용하면 되니까. 아니면 cad 파일에서 도곽을 추출해서 ctb 적용해서 preview 이런 식으로 구현해도 되는 것 같고

> Acro-full 코드의 경우 소유권과 라이선스 문제는 없어. 바탕화면에 있는 원본 소스코드를 참고해서 우리꺼에 맞춰서 작성하면 돼

그래서 이 계획은 다음과 같이 바뀌었다.

- **중심은 역반영(T-232·T-233):** 이미 있는 CAD 도면에 모델 변경을 형식 그대로 반영한다. 도면은 동료가 쓰는 보통의 CAD 파일로 남는다(레이어·블록·치수 스타일·xref·Handle·DWG 버전 유지).
- **폐기:** Rhino 레이아웃·디테일 → DWG 내보내기(T-228), 그 결과의 정리 패스(T-229), Make2D 실험(T-231). 행은 남기고 번호는 재사용하지 않는다(AI.md §7).
- **좁힘:** 템플릿 병합(T-230)은 '새 도면이 필요할 때 기존 도면·템플릿 사본에 Rhino 2D 곡선을 넣는' 보조 경로로 줄이고 역반영 적용 경로를 그대로 쓴다. 템플릿 등록부(T-227)는 레이어 대응과 도면 읽기로 줄인다.
- **플롯·PDF는 VIDE가 하지 않는다:** 사용자가 CAD에서 기존 LISP로 한다. 대신 선택 기능으로 도곽 추출 + CTB 미리보기(T-235, SPEC-14.15)를 더한다.

## 착수 조건과 범위

- **제품 결정:** 2026-10-07 사용자가 C-08을 채택했고 PRD §4.4·§14.2에 반영했다. 같은 날 계획 검토 의견(위)을 반영했다. 시작 시점은 PLAN-44의 「시작 시점」을 따르고, 아래 「결정이 필요한 질문」은 바꾸지 않으면 기본값으로 진행한다.
- **범위:** ZWCAD 2023 연결 도면(열림)과 숨은 실행(닫힌 도면 사본)의 역반영, 새 도면 시작(보조), 도곽·CTB 미리보기, mm 도면. Rhino 레이아웃의 DWG 변환, Make2D, 플롯·PDF, AutoCAD·Revit은 제외(SPEC-14.13).
- **원칙(AI.md §8):** 숨은 호스트는 VIDE가 띄우고 사본만 연다. 시험은 `.vide/` 아래의 합성 3DM·DWG·CTB만 쓴다. 사용자 원본과 사용자 호스트 창은 쓰지 않는다. 실호스트 시험은 호스트가 없으면 건너뜀으로 표시한다.
- **기술 계약:** ZWCAD worker 명령, 출처 표시(xdata)·반영 기준 저장 형식, 도곽 목록·CTB 읽기 결과는 [ARCH-01](../architecture/ARCH-01-system.md)에 「도면 역반영(PLAN-47)」 절로 추가한다(T-226에서 시작, 티켓마다 보완).

## T-225 SPIKE: ZWCAD 사이드 DB 쓰기·출처 표시·도곽 읽기

- **기준:** SPEC-14.4·14.7·14.8·14.15, SPIKE-2026-10-07-drawing-export의 「한계」, H-ZWCAD-12·13.
- **위치:** 코드 `tools/spikes/YYYY-MM-DD-dwg-backflow/`(실행하는 날), 기록 `docs/tdd/SPIKE-YYYY-MM-DD-dwg-backflow.md`(실행하는 날 만든다).
- **질문:**
  1. 사이드 DB(`ReadDwgFile` 쓰기 모드)에서 개체를 고치고 `SaveAs`할 때 원래 DWG 버전(2013·2018 등)을 그대로 지정할 수 있는가. 다시 열었을 때 고치지 않은 개체의 Handle·레이어·블록 정의·스타일·레이아웃·xref 부착이 그대로인가. 동료가 AutoCAD로 열어도 되는 보통 DWG인가(ZWCAD 화면 확인, AutoCAD가 이 PC에 있으면 함께).
  2. xref 자식 도면을 따로 열어 고치고 저장할 때 루트의 상대 경로 해석이 유지되는가.
  3. ZWCAD가 새로 만든 개체(SPEC-14.4)에 xdata로 출처 표시(원천 객체 ID)를 붙이고 다시 읽을 수 있는가. 사용자가 CAD에서 복사·이동·`WBLOCK`할 때 xdata가 어떻게 되는가.
  4. 사용자 도면을 읽을 때 죽는 속성 목록을 넓혀 확인한다(ZWCAD 2023의 `Dimension.TextStyleId` 접근 위반처럼; 치수·MText·해치·뷰포트·속성 블록 일괄 읽기).
  5. 도곽 읽기: 속성 블록 삽입의 이름·범위·ATTRIB 값, 레이아웃(배치)의 플롯 범위·용지·플롯 스타일 이름을 사이드 DB에서 읽을 수 있는가. S-19 ARCO-full의 LISP 도곽 참고 자료(06·13·15)를 참고한다.
  6. CTB 파일 형식: `.ctb`(압축된 텍스트 표)를 엔진에서 읽어 ACI별 펜 색·선가중치로 바꿀 수 있는가. ZWCAD 기본 CTB와 회사 CTB 합성 표본으로 확인한다.
- **방법:** SPIKE-2026-10-07의 `run.mjs`·probe를 재사용해 합성 DWG(2013·2018, 속성 도곽 블록·레이아웃 2개·xref 1개)를 만들고 probe를 쓰기 모드로 확장한다. 매 실행 뒤 띄운 호스트 종료와 충돌 덤프 0건을 확인한다.
- **완료:** 질문별 가능/불가/우회와 ZWCAD 결함 목록을 기록하고, T-232·T-233(출처 표시 방식, 버전 유지)과 T-235(도곽·CTB 읽기)의 방식을 확정한다.
- **실패 처리:** 1이 불가하면(버전 유지·Handle 보존이 안 됨) 닫힌 도면 반영을 지원 안 함으로 바꾸고 열린 도면만 반영하는 SPEC 수정안을 낸다. 3이 불가하면 SPEC-14.4로 넣은 개체도 Sync jig 일치 행으로 짝을 잇는 수정안을 낸다.

## T-226 선행: 숨은 호스트 견고성과 쓰기 경로 정책

- **기준:** SPEC-14.7, SPEC-14.13 실패 1·2, SPEC-14.14의 1, PRD §11.2, H-RHINO-08, H-ZWCAD-09·13.
- **변경:**
  - 숨은 실행 공통: 반영·새 도면·도곽 작업마다 숨은 ZWCAD를 `launchHiddenZwcad`(기존)로 띄우고, 시간 상한·중단·종료 확인·충돌 덤프 처리를 한 곳에서 한다. 비정상 종료 코드와 마지막 단계를 진단 로그에 남긴다.
  - ZWCAD worker에 T-225 4의 위험 속성 회피 목록을 넣는다(읽지 않거나 안전한 대체 API).
  - **쓰기 경로 정책:** 엔진이 발급한 출력 토큰(작업 폴더 또는 사용자가 확인한 경로 + 파일 이름 집합)을 가진 worker 명령만 `SaveAs`를 할 수 있게 한다. 경로가 토큰 밖이면 거절, 이미 있는 파일이면 거절(덮어쓰기 금지), 저장 버전은 원본 버전으로 고정(SPEC-14.7의 3).
  - AI 코드 정책은 바꾸지 않는다: `SdkCompiler`의 `Save`·`SaveAs`·`AttachXref` 등 금지, Rhino `CodePolicy`의 저장·내보내기 금지를 그대로 두고 시험으로 고정한다.
  - ARCH-01에 「도면 역반영(PLAN-47)」 절을 만들고 출력 토큰·worker 명령 목록을 적는다.
- **선행:** 없음(T-225와 병렬).
- **검증:**
  - 정상: 토큰 경로에 원본 버전으로 쓰기 성공, 다시 읽기.
  - 실패: 토큰 밖 경로·기존 파일·AI 코드의 `SaveAs`/`AttachXref`/`Export`가 모두 거절(`tests/core/` 정책 시험, 실호스트 시험은 없으면 건너뜀). 숨은 호스트 강제 종료 시 작업이 실패로 끝나고 원본 파일 해시가 그대로.
- **완료:** 시험 통과, 호스트 지원표에 역반영용 행(H-ZWCAD 새 번호) 추가.

## T-227 도면 읽기와 레이어 대응 (2026-10-07 좁힘)

- **변경:** 프로젝트 DB 표(도면별 레이어 대응 표, 도면 읽기 결과의 지문), 엔진 경로 `/api/v1/projects/:id/drawing/layers*`, ZWCAD worker 명령 `VIDEDRAWINGINSPECT`(사본 읽기: 레이어·선종류·문자/치수 스타일·블록·xref, 단위, DWG 버전). T-200의 사본 방식과 경로 해석(`src/core/xref-graph.ts`)을 재사용한다. 템플릿 등록부·레이아웃/뷰포트 목록은 만들지 않는다(Rhino 레이아웃을 옮기지 않으므로).

- **검증:** 합성 DWG로 목록과 레이어 자동 대응, 도면 사이 대응 표 복사. 실패: mm 아님·읽기 실패·파일 없음 → 대상 거절과 이유. 원본 해시 불변.

## T-228 Rhino → DWG 내보내기 경로 — 폐기(2026-10-07)

- 폐기 이유: 사용자 검토 "도면의 경우 라이노 레이아웃은 필요없고, cad와의 호환성이 중요한 듯." Rhino 레이아웃·디테일을 DWG 시트로 내보내지 않는다(SPEC-14.13). 새 도면에 넣는 2D 요소는 ZWCAD가 직접 만든다(T-230).
- 번호는 재사용하지 않는다.

## T-229 ZWCAD 정리 패스 — 폐기(2026-10-07)

- 폐기 이유: Rhino가 내보낸 DWG의 손실(치수 문자·글꼴·빈 레이아웃·뷰포트·링크 블록)을 고치는 단계였다. T-228 폐기로 Rhino 내보내기 결과를 도면에 넣지 않으므로 고칠 대상이 없다(SPEC-14.5 폐기).
- 번호는 재사용하지 않는다.

## T-230 새 도면 시작 — 보조 (2026-10-07 좁힘)

- **기준:** SPEC-14.4·14.7, 사용자 검토 "기존에 있는 도면에 반영되는게 더 중요".
- **변경:** 사용자가 고른 기존 도면·템플릿 DWG의 사본을 출력 토큰 경로에 새 파일로 쓰고(원본 버전 유지), 고른 Rhino 2D 곡선(선·폴리선·원·호)을 T-233의 적용 경로로 '추가' 행으로 넣는다. 개체마다 출처 표시(T-225 3의 방식)와 레이어 대응(T-227). 레이아웃·도곽 속성·뷰포트는 건드리지 않는다. 템플릿 병합·모델 기하 블록/xref 단위·시트 대응은 만들지 않는다.
- **선행:** T-227, T-233.
