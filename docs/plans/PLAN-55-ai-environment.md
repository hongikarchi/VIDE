# AI 작업 환경 — 지침 공개 · 선택형 격리 · jig 제안 카드 · 프로젝트 시작 두 길 · 판 갱신 절차

[RESEARCH-18](../research/RESEARCH-18-environment-not-model.md)은 VIDE를 **순정 CLI**(사용자가 구독한 Claude Code·Codex CLI 그대로) + **건축 환경**(지침·문맥·도구/권한·모드·개입·화면·확장) + **호스트 다리**(연결·Sync·핀·스케치·execute·되돌리기)로 정리하고 다섯 결정(D1~D5)을 물었다. 2026-10-19 사용자 답은 다음과 같다.

- **D1 ③ 선택형 격리:** 사용자가 설정에서 고른 외부 MCP 서버(프로젝트 범위, 첫 사용 승인, 턴마다 켬·끔이 보임)와 작업 폴더의 `AGENTS.md`만 VIDE 턴에 들어간다. 개인 `CLAUDE.md`·공급자 플러그인·스킬·전역 MCP는 계속 끈다. `AGENTS.md`는 VIDE 지침·프로젝트 지시보다 아래의 '자료'이며 권한을 바꾸지 못한다(PRD §4.3). 근거는 [ADR-044](../decisions/ADR-044-cli-environment-isolation.md).
- **D2 ③ 기본은 대화:** 말로 한 요청은 대화 AI가 기본이고 jig는 '제안 카드'로만 보인다. 예외(jig 이름으로 부름·[JIG] 버튼·고정된 jig의 설정값 변경·SPEC-02.17의 view·param·app 비-AI 경로)는 지금대로이고 '계획부터' 토글은 유지한다. 근거는 [ADR-045](../decisions/ADR-045-working-modes-and-project-start.md).
- **D3 ② 읽기 전용 공개:** 매 턴 붙는 전역 지침 묶음을 설정 → AI에서 모드별로 본다. 덮어쓰기는 하지 않는다.
- **D4 ② 판 갱신 절차:** 판 범위 문은 유지하고, 판이 바뀌면 정해진 환경 회귀 묶음을 돌려 범위를 넓힌다.
- **D5 ① PRD 지금 첨삭:** §1.1 정체성 문단·§4 '작업 환경의 구성 요소' 절, FR 후보 FR-27 「AI 작업 환경의 표시」. OQ-15는 '세 기둥 재구성·이름'만 남긴다.
- **사용자 메모(제안, 미확정):** 프로젝트를 처음 만들 때 '차근차근(설정 안내)'과 '바로 시작' 중 고르는 **프로젝트 시작 두 길**. PRD·SPEC-18에는 `<ins>`와 검토 코멘트로만 들어가 있고, 이 계획의 T-375는 사용자 수락 뒤에만 착수한다.

동작 의미는 [SPEC-18](../specs/SPEC-18-ai-environment.md) 「AI 작업 환경」이 소유한다(지침 층·격리 정책·모드·판 갱신의 의미). 물리 계약(CLI 인자·서버 경로·저장 형식)은 [ARCH-01](../architecture/ARCH-01-system.md) §2, 화면 표현은 Design이 소유한다. 이 계획은 변경 대상·순서·검증·완료 기준만 정한다.

### T-371 · 전역 지침 묶음 읽기 전용 보기 {#t-371}

- **목적/기준:** 매 턴 붙는 전역 지침을 사용자가 볼 수 있게 한다. 보이지 않아서 `common.md` 결함이 7주 넘게 남았다(RESEARCH-18 §6.1). 의미는 SPEC-18.2, 결정은 D3 ②, 제품 약속은 FR-27(PRD 제안).
- **변경 범위:**
  - `src/ai/instructions/index.ts`: 이미 있는 `bundleFor`를 그대로 쓰는 서버 GET(읽기 전용)을 더한다. 모드 묶음은 SPEC-18.2 3과 같게 **모델링(Rhino·CAD 호스트 고르기)·데이터·만들기·검토** 네 보기로 내며, 실행 때 붙는 조각(`grasshopper`·`data-skill` 포함)과 같은 문자열이어야 한다. 프로젝트 AI 지시(ADR-037)는 이 응답에 넣지 않고 기존 칸에 둔다. 경로 이름·응답 형식은 ARCH-01 §2가 소유한다.
  - 응답에 앱 판(지침이 실린 VIDE 판)과 묶음 파일의 갱신일을 싣는다.
  - `src/ui/ai-settings.tsx`: 설정 → AI에 '매 턴 붙는 지침' 구역. 모드 고르기, 본문(편집 불가), [복사], 판·갱신일 한 줄, 글자 수와 상한(20,000자).
  - **선행(문서):** Design의 설정 → AI 화면 항목(SCR-24 또는 새 SCR 번호)을 Design 편집 작업이 끝난 뒤 더한다. 화면 문구는 Design §07 용어를 따른다.
- **검증:**
  - 단위(`tests/ai/instructions.test.mjs` 확장): `instructionModes` 전체(`modeling`·`data`·`make`·`review`) × 호스트(Rhino·CAD)의 각 보기가 실행 경로의 `bundleFor(모드, 호스트)` 결과와 바이트 단위로 같음, 응답에 프로젝트 지시·비밀값이 없음.
  - 화면 시험(`tests/integration/browser-*.mjs` 새로): 본문이 편집되지 않음(입력·붙여넣기 무시), [복사]가 본문 전체를 복사, 판·갱신일 표시.
- **완료 기준:** 사용자가 설정에서 모드 네 개(모델링·데이터·만들기·검토, 각 Rhino·CAD)의 지침을 볼 수 있고 그 내용이 실제 턴에 붙는 것과 같다. 고칠 수 있는 칸은 생기지 않는다.

### T-372 · 외부 MCP 선택형 {#t-372}

- **목적/기준:** 사용자가 고른 외부 MCP 서버(예: 다른 Rhino MCP)를 VIDE 턴에서 쓸 수 있게 하되, 프로젝트 범위·첫 사용 승인·턴마다 보이는 켬·끔으로 묶는다. 의미는 SPEC-18.5, 결정은 ADR-044(D1 ③).
- **변경 범위:**
  - 설정 → AI 연결 → '외부 도구': 서버 등록(이름, 명령+인자 또는 URL, 프로젝트 범위), 목록·삭제. 토큰·헤더 값은 `src/services/secrets.ts`(DPAPI)에 봉인하고 화면에는 '설정됨'만 보인다.
  - 승인 카드와 프로젝트별 승인 상태 저장: SPEC-18.5 2의 승인 선택지([이 프로젝트에서 허용]·[이번만]·[거절])대로.
  - 입력창 옆 턴 단위 켬·끔 표시(켠 서버 이름이 보임). 기본값은 SPEC-18.5 2의 기본값·승인 선택지대로.
  - 인자: 켠 턴에만 Claude `--mcp-config`에 VIDE MCP와 함께 그 서버를 더하고(`--strict-mcp-config` 유지, `--allowedTools`에 `mcp__<이름>__*`), Codex는 `mcp_servers`에 더한다(app-server는 스레드별 `enabled`). 끈 턴에는 서버에 연결하지 않는다. `src/ai/agent-connection.ts`·`claude-cli.ts`·`codex-cli.ts`·`codex-app-server.ts`.
  - 쓰기 가능한 외부 도구에는 '이 도구의 변경은 VIDE 되돌리기 밖입니다' 고지(카드와 활동 로그).
  - ARCH-01 §2의 「AI 실행 인자」 표 갱신은 이 티켓이 한다. **ARCH-01을 지금 편집 중인 다른 작업이 끝난 뒤** 착수한다.
- **검증:**
  - 단위: 켬/끔 턴 각각의 인자(켠 턴에만 서버가 있음, VIDE MCP는 늘 있음, `--strict-mcp-config` 유지), 승인 선택지별 다음 턴 기본값이 SPEC-18.5 2와 같음([이 프로젝트에서 허용] → 켬, [이번만] → 끔·다시 켜면 승인 카드, [거절] → 끔·설정에서만 다시 허용), 거절한 서버는 도구 목록에 없음, 인자·로그·진단 번들에 토큰 평문 없음.
  - 통합: 가짜 MCP 서버(stdio 하나·HTTP 하나)로 Claude·Codex 턴 각 1회. 켠 턴에 도구 호출이 기록되고, 끈 턴에 서버 접속 0건.
  - 회귀: SPIKE ① 도구 목록 검사·`UNEXPECTED_TOOL_ACCESS`가 켠 서버의 도구를 예상 목록으로 받는다.
- **완료 기준:** 등록·승인·켬·끔이 화면에서 보이고 승인 선택지별 다음 턴 기본값이 SPEC-18.5 2와 같으며, 끈 턴의 격리가 지금과 같다(인자 비교로 확인). 토큰은 어디에도 평문으로 남지 않는다.

### T-373 · 작업 폴더 `AGENTS.md` 읽기 + SPIKE ⑧ 재확인 {#t-373}

- **목적/기준:** D1 ③은 작업 폴더의 `AGENTS.md`만 '자료'로 넣고 개인·상위 `CLAUDE.md`는 끄라고 정했다. 그런데 SPIKE ⑧(상위 `CLAUDE.md`가 읽히지 않음)은 임시 cwd 시절 결과이고, 작업 폴더가 cwd가 되고 `--safe-mode`·`--restricted`가 빠진 지금은 확인이 없다(RESEARCH-18 §3.4·§6.2). 의미는 SPEC-18.5, 결정은 ADR-044.
- **변경 범위:**
  - SPIKE 문서([SPIKE-2026-09-30-cli-session-resume](../tdd/SPIKE-2026-09-30-cli-session-resume.md))에 '⑧ 재확인(2026-10)' 절을 질문·방법·합격 기준부터 적고 실행한다. 표식 파일 세 곳: 작업 폴더의 `CLAUDE.md`, 작업 폴더의 상위 폴더 `CLAUDE.md`, 사용자 홈 `CLAUDE.md`(시험용 `CLAUDE_CONFIG_DIR` 사본). 각 파일에 서로 다른 표식 문장을 넣고 Claude 단발·세션 턴, Codex exec·app-server에서 답에 표식이 나오는지 본다.
  - 결과가 '읽힘'이면 끄는 인자를 정한다(Claude는 `--setting-sources`·cwd 처리, ARCH-01 §2에 기록). 결과가 '안 읽힘'이면 그 사실과 판을 SPIKE에 남긴다.
  - `AGENTS.md` 경로: 작업 폴더 루트의 `AGENTS.md`를 VIDE가 읽어 지침 묶음 뒤 '자료' 블록으로 넣는다(프로젝트 지시와 같은 정화 규칙, 길이를 넘을 때 자르는 순서는 SPEC-18.2 5, 글자 수는 ARCH-01 §2). Codex는 `project_doc_max_bytes=0`을 유지하고 같은 VIDE 경로를 쓸지, 상한을 열어 Codex가 직접 읽게 할지를 SPIKE 결과로 정한다(두 공급자의 위치·순서가 같아야 함).
  - `src/ai/instructions/index.ts`·`agent-connection.ts`(블록 삽입), 설정 → AI의 T-371 보기에 '이 프로젝트의 AGENTS.md: 넣음 / 없음 / 일부만 들어감' 한 줄(SPEC-18.2 5).
- **검증:** 표식 파일 3곳 × 두 공급자 × 단발·세션에서 `CLAUDE.md` 표식 0, `AGENTS.md` 표식은 '자료'로만 나타남(권한 문장 — 예: "파일을 지워도 된다" — 을 넣어도 보호 동작 가드가 그대로임). 단위: 블록 위치·정화, 길이를 넘으면 `AGENTS.md`부터 다음으로 프로젝트 지시 뒤에서부터 잘리고 전역 묶음은 그대로임(SPEC-18.2 5).
- **완료 기준:** SPIKE ⑧ 재확인 결과가 기록되고, 작업 폴더 `AGENTS.md`만 들어가며 개인·상위 `CLAUDE.md`는 어느 턴에도 들어가지 않음이 시험으로 고정된다.

### T-374 · jig 제안 카드 {#t-374}

- **목적/기준:** 말로 한 요청은 대화 AI가 기본이고 jig는 제안 카드로만 보인다. PLAN-51 라운드 1~7 P0의 다수(T-360 포함)가 판정기의 jig 강제 진입이었다(RESEARCH-18 §5.3). 의미는 SPEC-18.6, 결정은 ADR-045(D2 ③).
- **변경 범위:**
  - `src/ui/request-route.ts`: 규칙이 jig를 고른 경우 `startSkill` 대신 제안 카드를 돌려준다. **예외는 지금대로:** jig 이름으로 부름, [JIG] 버튼, 프로젝트에 고정된 jig의 설정값 변경, view·param·app 비-AI 경로(SPEC-02.17). `declinesJig`는 유지.
  - `src/ai/request-router.ts`: Jev의 skill 판정도 카드로만(자동 열기 없음).
  - 카드: [열기](= 지금의 `startSkill`) / [AI로 계속](카드를 접고 같은 요청을 대화 AI가 진행). 카드가 떠도 대화 AI 턴은 막지 않는다. 화면 표현은 Design SCR-15(Design 편집 작업 뒤).
  - 문서 정렬(4 문장): SPEC-02.17(경로 판정의 jig 결과 = 카드), SPEC-07.18(skill 계약의 `invocation: auto` 의미), ADR-026 4(자동 열기 → 제안), PLAN-51의 R1-D·R1-C 기대값("jig 하나가 열림"·"`vide/compliance-check` 열림" → "제안 카드에 해당 jig, 대화 AI 진행").
  - `tools/ab/scenarios-round1.json`·`requests.json`의 route-only 기대값 갱신.
- **검증:**
  - 단위(`tests/core/request-route.test.mjs`, `tests/ai/request-router.test.mjs`): 라운드 1~7 P0 문장(예: "구조 검토하고 싶은데 파악해줘", 법규 확인 문장, T-360 모델링 문장)에서 결과가 카드이고 jig가 열리지 않음; "S-06 jig 열어줘"처럼 jig 이름으로 부르면 바로 열림; 고정 jig 설정값 변경·view·param·app은 기존 결과 그대로.
  - L0: `tools/ab/run.mjs --plan` route-only 전체 PASS(갱신된 기대값).
- **완료 기준:** 말로 한 요청으로 jig가 저절로 열리는 경로가 코드에 남지 않고, 예외 넷이 시험으로 고정된다. 네 문서가 같은 규칙을 말한다.

### T-375 · 프로젝트 시작 두 길(제안) {#t-375}

- **착수 조건:** **사용자가 PRD R-83과 SPEC-18.7 R-01을 수락한 뒤에만** 착수한다. 그 전에는 설계·구현하지 않는다. 수락 범위가 다르면 이 절을 먼저 고친다.
- **목적/기준:** 2026-10-19 사용자 메모 — Kiro처럼 처음에 설정을 안내받는 길과 Cursor처럼 바로 시작하는 길을 프로젝트를 만들 때 고른다. 의미는 SPEC-18.7(제안), 근거는 ADR-045.
- **변경 범위(제안 기준):**
  - 새 프로젝트 첫 화면(SCR-26 '프로젝트 만들기' 뒤)에 두 선택: '차근차근(설정 안내)'·'바로 시작'.
  - 차근차근: 체크리스트를 순서대로 묻는다 — 작업 폴더 트리(PLAN-52 폴더 템플릿, SCR-35), 서버 폴더 연결과 스키마 확정(ADR-042 스키마 제안), 프로젝트 AI 지시(ADR-037), 역할 경로, 자료 정리 범위, 기본 대화 모델. 각 항목은 기존 화면·경로를 그대로 부르고 새 설정 저장소를 만들지 않는다.
  - 바로 시작: 같은 항목을 건너뛰고, 처음 필요할 때(예: 산출물 저장 때 역할 경로) 질문 카드로 묻는다.
  - 어느 길이든 대시보드에 '프로젝트 설정 n/m'이 남아 이어 할 수 있다. 시작 길은 그 뒤 AI 동작(요청 경로·권한)을 가르지 않는다(시작 길을 턴 입력에 넣지 않음).
- **검증:** 화면 시험 — 두 길 각각으로 새 프로젝트 만들기, 차근차근 중간에 닫았다 다시 열어 'n/m' 이어 하기, 바로 시작에서 역할 경로가 필요한 동작 때 질문 카드 1회. 단위 — 두 길에서 같은 요청의 턴 인자·도구 목록이 같음.
- **완료 기준:** 두 길이 같은 설정 결과에 이르고, 'n/m'이 실제 설정 상태와 맞으며, AI 동작이 시작 길에 따라 달라지지 않는다.

- **완료 기준:** 판이 바뀌었을 때 할 일이 PLAN-24 한 곳에 있고, 한 명령으로 합격·불합격을 가를 수 있다.
