# PLAN-08 — 프로젝트 지식 DB

2026-09-28~29 사용자 요청의 단계 계획이다. 요청 내용은 메일·첨부·회의록을 모아 누가 무엇을 말했는지, 주요 쟁점, 진행 경과를 DB로 정리하고, 질문 답변·도면/모델 크리틱에 쓰며, 여러 팀원이 함께 쌓는 것까지 목표로 한다. 원본은 회사 서버에 있을 가능성이 높다. 파악과 선택 근거는 [RESEARCH-06](../research/RESEARCH-06-project-knowledge.md), 저장·공유 구조의 결정 초안은 [ADR-018](../decisions/ADR-018-project-knowledge-store.md)이 소유한다.

## 착수 조건

- **제품 결정:** PRD §4.4 C-02 제안(첨삭 R-74)이 채택돼야 한다. 채택 전에는 구현하지 않는다.
- **구조 결정:** ADR-018의 공동 축적 예외(지식 기록만 여러 PC)와 팀 공용 원본 위치. K5 착수 전까지 정하면 되고, K0~K4는 로컬만으로 진행할 수 있다.
- **RESEARCH-06 §12 결정:** 회사 정책(외부 저장·외부 AI 처리), 역할과 공개 범위, 자료 폴더, 표본 자료.
- **동작 계약:** 채택되면 K0 결과로 새 SPEC(가칭 SPEC-06 프로젝트 지식)을 먼저 쓴다. 출처·역할·상태 규칙은 SPEC-03.4를 확장한다.
- **진행 중 작업과의 관계:** 현재 우선순위(Rhino·CAD 연결 왕복과 Sync 성능)를 막지 않는다. 아래 T-025~031은 제안 번호이며 채택 뒤 마스터 PLAN에 등록한다.

## 처음부터 지킬 기록 구조

K1부터 아래 규칙을 지키면 K5에서 데이터를 옮기지 않고 공동 축적으로 넓힐 수 있다. 물리 스키마는 ARCH-01에 정한다.

- 모든 기록(자료 등록, 근거 구간, 진술, 확정·기각, 대체, 별칭 합치기, 관측)은 **전역 고유 ID·작성자·기록 시각을 가진 사건**으로 쌓기만 한다. 수정·삭제 대신 새 사건을 남긴다.
- 진술은 유효 시작·끝과 기록 시각의 **두 시간축**을 가진다.
- 원본은 복사하지 않고 **위치 참조(UNC 또는 프로젝트 루트 상대 경로) + 내용 해시**로 등록한다.
- 자료마다 **공개 범위**(팀 / 특정 멤버 / 나만)와 **AI 전송 허용**을 가진다.
- 기하 관측은 모델 Sync/체크포인트 ID와 계산 방법을 함께 저장한다.

## 단계

각 단계는 앞 단계만으로도 쓸모가 있어야 하며, 다음 단계는 앞 단계의 실제 사용 결과를 보고 조정한다.

### K0 · 표본 자료 조사(SPIKE) — T-025 제안

- **목적:** 실제 프로젝트 자료 1세트(사본, `.vide/knowledge-sample/`)의 형식 분포와 추출 가능성을 잰다. 회사 서버 원본은 사용자가 고른 사본만 쓴다.
- **내용:**
  - 형식별 개수·크기, 스캔 PDF 비율, 메일 형식(.eml/.msg), HWP 비중
  - 도면·모델의 문자 정보량, 회사 서버 경로 구조
  - 소표본(메일 20통·PDF 5개·회의록 3건 내외)으로 AI 진술 추출을 시험하고, 인용 일치율과 사람 판단과의 차이를 기록한다.
- **산출:** `docs/tdd/SPIKE-YYYY-MM-DD-project-knowledge.md`, 형식별 파서 선택, SPEC-06 초안 입력.
- **완료 기준:** 형식별 “결정적 추출 가능 / AI 판독 필요 / 제외” 판정표와 추출 시험 결과가 기록된다.

### K1 · 자료함과 원문 검색 — T-026 제안

- **변경 범위:**
  - 위 기록 구조의 Source·Excerpt 저장(SQLite 마이그레이션)
  - 회사 서버 폴더 지정·감시(읽기 전용, 제외 규칙, 수집 전 확인)와 끌어 놓기
  - 형식별 텍스트 추출기(EML·PDF 텍스트·PPTX·DOCX·XLSX, K0 판정에 따라 HWP)
  - FTS5 trigram 검색, 자료함 UI(목록·검색·원문 구간 열람·원본 열기)
- **AI 사용:** 없음.
- **검증:**
  - 형식별 추출 단위 시험(쪽·슬라이드·메일 헤더 보존)
  - 같은 파일 재수집·이동·이름 변경 시 해시로 중복 없음
  - 다른 드라이브 문자로 같은 자료 인식, 한국어 부분 검색
  - 원문 구간 열람 브라우저 시험, 원본 폴더에 쓰기 없음, 백업/복구 포함, 비밀값 검사
- **완료 기준:** 표본 자료에서 “기둥 간격”, “회의실” 같은 검색으로 해당 메일·쪽·슬라이드를 찾아 원문을 연다.

### K2 · 진술·쟁점 정리와 검토 큐 — T-027 제안

- **변경 범위:**
  - Party·Subject·Statement·Issue·Milestone·Episode 저장
  - AI 추출 작업: 구독 CLI, 도구 없는 JSON, 근거 구간 ID·원문 인용 필수, 대조 실패 시 폐기
  - 자료별 AI 전송 확인(FR-18), 진행률·중단·재개
  - 검토 큐(확정·수정·기각·별칭 합치기)와 대체·모순 후보 표시
  - 프로젝트 정보 탭: 브리핑·쟁점 표·타임라인·주체 목록
- **검증:** 가짜 인용·다른 자료 인용 거절, 확정 전 진술이 사실로 표시되지 않음, 대체가 이전 진술을 지우지 않음, 전송 거부 자료가 AI 입력에 들어가지 않음, 중단 뒤 재개 시 중복 없음, “특정 날짜 기준” 조회가 당시 유효 진술만 반환.
- **완료 기준:** 표본 자료에서 주요 결정·요청·쟁점이 근거와 함께 목록화되고, 확정한 항목만 “확정”으로 보인다. 품질 기준은 K0 결과로 SPEC-06에서 정한다.

### K3 · 질의응답과 요청 문맥 제안 — T-028 제안

- **변경 범위:**
  - AI 읽기 전용 MCP 도구: 자료 검색, 진술·쟁점 조회, 대상별 근거, 타임라인, 기준 날짜 조회
  - 채팅 답변의 인용 표시와 원문 열람
  - 모델 수정 요청 시 관련 필수조건·결정 칩 제안(자동 첨부 아님)
  - Inspector에 객체의 연결 진술과 연결·끊김 표시
- **검증:** 근거 없는 질문에 “자료에 없음”, 대체된 결정보다 최신 결정을 날짜와 함께 답함, 다른 프로젝트·비공개 자료 접근 불가, 기존 AI 작업 권한이 넓어지지 않음.
- **완료 기준:** 사용자가 고른 질문 목록에 인용이 붙은 답을 받고, 근거를 원문에서 확인한다.

### K4 · 구조화된 조건과 크리틱 — T-029 제안

- **변경 범위:**
  - 요구 진술의 구조화된 조건(대상·항목·조건·단위)과 확정
  - 모델 시점별 기하 관측(기본 집계 FR-22 재사용)
  - 조건-관측 대조로 쟁점 생성(AI가 숫자를 추측하지 않음), 시각 판단은 뷰포트 캡처
  - 결과는 “AI 추정” 쟁점으로 객체에 연결하고 채택·기각. 법규 해석은 FR-21로 넘긴다.
- **검증:** 요구와 어긋나게 만든 합성 모델에서 해당 객체·근거를 짚는지, 맞는 모델에서의 거짓 지적 비율, 모델 변경 시 관측이 오래됨으로 바뀌는지, 크리틱이 원본을 수정하지 않는지.
- **완료 기준:** 대표 과업 수준의 모델 1건에서 채택할 만한 지적과 거짓 지적의 비율을 기록하고, 사용자가 계속 쓸지 판단한다.

### K5 · 팀 공동 축적 — T-030 제안

- **선행:** ADR-018 승인(공동 축적 예외, 팀 공용 원본 위치: 사내 팀 서버 / D1 / Supabase), 역할·공개 범위 결정.
- **변경 범위:**
  - 사건 동기화(모르는 사건 가져오기·내 사건 보내기, 재시도 멱등)
  - 팀 공용 원본 서비스(선택한 위치), 멤버십·역할(관리자·편집·열람·외부)과 확정 권한
  - 자료별 공개 범위 적용, 동기화 상태·충돌(나란한 판단) 표시
  - 원본 파일은 업로드하지 않고, 다른 팀원이 원문을 열 때는 회사 서버 경로 사용
- **검증:**
  - 두 PC가 오프라인에서 각자 기록한 뒤 동기화하면 양쪽 결과가 같음
  - 같은 자료를 두 사람이 넣어도 한 번만 저장, 비공개 자료의 진술이 다른 멤버에게 가지 않음
  - 권한 없는 확정 거절, 동기화 중단·재시작에도 중복 없음
  - 호스트 제어는 여전히 한 작업환경만 가능(AC-37)
- **완료 기준:** 2~3명이 같은 프로젝트에 자료를 넣고 확정한 결과를 서로의 VIDE에서 질문·조회한다.

### K6 · (선택) 관계 보기

K2~K5의 표·타임라인·인용으로 부족하다는 실제 근거가 생길 때만 Obsidian 폴더 한 방향 내보내기나 한 쟁점 중심의 국소 그래프를 추가한다. 전체 그래프는 만들지 않는다. — T-031 제안

## 기술 선택(초안)

- **로컬:** 기존 SQLite에 테이블 추가, FTS5 trigram, R*Tree 공간 색인, JSON. 벡터 검색은 부족함이 측정될 때 sqlite-vec(로컬 임베딩 모델 필요).
- **팀 공용 원본:** ADR-018. 동기화 방식은 저장소와 분리해 사내 팀 서버·D1·PostgreSQL 어느 쪽으로도 옮길 수 있게 한다.
- **추출기:** 표준 형식은 가벼운 파서 의존성을 추가한다. 스캔 PDF·이미지 판독은 AI 판독 선택 기능. 새 의존성은 PLAN-03의 추적·검사 규칙을 따른다.
- **AI:** 각자 PC의 구독 CLI. 정리는 도구 없는 JSON 추출, 질의·크리틱은 읽기 전용 MCP 도구. 서버 쪽 AI 실행은 하지 않는다.

## 비목표

문서 관리·결재·버전 관리 시스템, 메일 클라이언트, 녹음 전사(STT), 법규 자동 판정, 전체 관계 그래프, 사용자 확정 없는 결정 자동 확정, 원본 파일의 클라우드 업로드, 같은 프로젝트의 호스트 공동 제어.
