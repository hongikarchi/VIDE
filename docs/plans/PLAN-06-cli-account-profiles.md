# 구독 CLI 계정 프로필과 안전한 전환 계획

## 1. 범위와 연구 판단

[RESEARCH-03](../research/RESEARCH-03-multi-account-cli.md)에 기록된 사용자 선택을 기준으로 계정 추가/재로그인, 계정별 확인 가능한 사용량, 수동 전환을 우선한다. 자동 전환은 지원 근거가 확인된 경우의 후속 단계다. 공급자별 활성 계정 하나를 유지하며 에이전트별 서로 다른 계정 할당·계정 풀 프록시는 이번 범위가 아니다. 2026-09-25 사용자 구현 지시에 따라 A1부터 순서대로 구현한다. 실제 사용자 로그인은 공식 CLI를 통해 진행하며 인증 파일을 직접 조작하지 않는다.

공식 CLI 실행과 프로필별 설정 디렉터리 패턴을 채택 후보로 삼는다. 인증 파일 백업/덮어쓰기, OAuth 토큰 추출·재사용, 비공개 사용량 API를 기본 구조로 채택하지 않는다. 공식 CLI를 사용한다는 사실만으로 모든 다중 계정 운용의 이용 조건이 승인됐다고 단정하지 않는다. 스타 수·도구 수는 격리와 안정성의 증거가 아니다.

현재 `src/ai/claude-cli.ts`와 `codex-cli.ts`는 상속 인증 환경을 제거한 뒤 선택 프로필의 관리 디렉터리를 명시한다. Codex 관리 프로필은 공식 파일 자격증명 저장소를 사용한다. 기본 로그인은 변경하지 않는다. 실제 두 ChatGPT 프로필의 공식 인증·응답과 브라우저 선택·재시작 복원을 확인했다. 토큰 갱신 충돌과 장기간 병렬 사용의 검증까지 완료한 것은 아니다.

## 2. 기준 문서와 착수 순서

제품 기준은 PRD FR-08·FR-18, 기존 실행·공급자 전송은 SPEC-02, 자식 프로세스·설정 격리는 ARCH-01이다. 구현 전에 아래 동작을 SPEC-02, 프로필 식별자·저장·실행 lease·환경 구성은 ARCH-01, 설정 패널 표현은 Design에 반영한다. PLAN으로 제품 계약을 대신하지 않는다. PRD의 범위·과금 약속을 넓혀야 하는 경우 해당 결정부터 처리한다.

PLAN-02 L2의 병렬/개입 및 L6의 불명확 쓰기 보호를 유지한다. **활성 계정 하나와 프로세스 하나는 다르다.** 현재 같은 공급자에서 실행 가능한 독립 요청들을 임의로 하나로 직렬화하지 않는다. 전환은 이전 프로필의 모든 실행이 끝난 뒤 새 요청에 적용한다. 미완료 로컬 검증은 별도로 남긴다.

## 3. 단계별 변경과 완료 기준

| 단계 | 변경 범위 | 완료 기준 |
|---|---|---|
| A1 격리 실험 | 고정된 설치 CLI 버전의 공식 로그인/상태 명령과 별도 설정 디렉터리 지원 확인. 가짜 CLI 두 프로필로 환경 전달 검증 | 기본 사용자 설정 불변, 프로필 간 경로/로그/설정 누출 없음. 실제 Windows 자격증명 격리의 미확인을 기록 |
| A2 프로필 저장 | 기존 기본 로그인은 호환 프로필로 유지. 새 프로필은 로컬 앱 데이터 아래 관리 경로와 불투명 ID 사용 | 재시작 복원, 경로 이탈/동일 경로 별칭 거절, 토큰이 DB·로그·공유·백업에 들어가지 않음 |
| A3 계정 등록·수동 전환 | 공식 CLI 로그인 진입·상태 확인·재로그인, 사용자가 정한 표시 이름. 공급자별 선택 계정 | 로그인 취소/실패가 기존 계정을 바꾸지 않음. 실행 중 선택 변경은 대기 표시, 모든 기존 실행 종료 후 다음 작업부터 적용 |
| A4 사용량 표시 | 공식적으로 이용 가능한 출력만 공급자별 어댑터로 해석 | 출처·갱신 시각·사용 가능 여부 표시. 확인 불가는 미확인, 오래된 수치는 구분. 미확인을 0%/무제한으로 표시하지 않음 |
| A5 조건부 자동 전환 | 명확한 한도 소진 신호와 안전한 실행 경계가 확인된 공급자만, 기본 꺼짐 | 실행 중·불명확 쓰기 중 교체 없음. 다음 요청의 계정 변경을 표시하고 기존 요청을 자동 재전송하지 않음 |
| A6 제품 검수 | 실제 두 로그인 프로필, 제품 채팅, 재시작·병렬 요청·재로그인 회귀 | 계정별 대상·모델/effort 지원·로그인 상태 일치. 기본 계정 설정과 사용자 문서 불변 |

A1의 가짜 CLI 시험은 바로 준비할 수 있다. 실제 두 계정 시험은 사용자가 공식 로그인 UI에서 인증할 수 있을 때 수행한다. 비밀번호·토큰을 채팅으로 요청하지 않는다. 지원되지 않는 공급자에서 계정 격리를 가장하거나 기본 인증 파일을 교체하는 우회는 하지 않는다. 공급자 하나만 통과하면 능력을 구분해 제공한다.

## 4. SPEC·ARCH에 반영할 동작과 구현 항목

요청 접수 시 선택된 프로필과 모델/effort 능력을 고정한다. 큐 대기 중 선택이 바뀌어도 이미 접수된 요청의 계정을 조용히 바꾸지 않는다. 대기 전환은 해당 프로필의 큐·실행 lease가 모두 해소된 후 완료하며, 새 요청이 이전 계정 큐를 계속 늘리지 않도록 전환 중 전송을 대기 상태로 안내한다. 현재 실행의 개입은 원 계정을 유지한다. 재시작 후 불명확 실행은 기존 결과 확인 규칙을 먼저 따른다.

계정 제거/로그아웃은 사용 중이면 보류한다. 프로세스 종료·오류·재시작 시 lease를 조정하되 저장된 running 숫자만 믿지 않는다. 동일 프로필의 여러 프로세스에서 인증 갱신 충돌이 실제로 확인되면 공급자별 제약과 UX를 다시 설계하고 동시성을 조용히 낮추지 않는다.

상속 인증 환경을 정리한 뒤 선택 프로필의 관리 경로만 명시적으로 설정한다. 브라우저가 보낸 임의 파일 경로를 사용하지 않는다. 기존 MCP 도구 범위·호스트 실행 권한·셸 제한은 유지한다. 설정 디렉터리 변경으로 필수 CLI 설정/도구 등록이 빠지지 않는지도 검사한다. 자격증명은 CLI가 관리하며 VIDE는 인증 파일을 복사하거나 파싱하지 않는다.

UI는 설정의 공급자별 계정 목록·연결/재연결·선택/전환 대기와 입력창의 현재 계정을 연결한다. 사용량을 모르면 해당 사실만 보여주며 총 잔여 크레딧을 추정 합산하지 않는다. 모델 목록은 계정/공급자별로 재확인한다. 명칭/배치는 Design에서 확정하고 입력창에 상세 설정을 모두 상시 노출하지 않는다.

A3 로그아웃은 관리 프로필만 공식 CLI로 수행하고 현재 선택은 유지한다. 기존 로그인 작업 수명과 차단 검사를 재사용하며 UI에서 로그아웃 진행/실패/완료를 구분한다. 대역 프로세스로 명령·환경·실패·종료 지연·검증 timeout을 검사하고 실제 빈 시험 프로필에서는 기본 사용자 로그인 불변을 확인한다. 사용자 로그인 계정은 시험용으로 로그아웃하지 않는다. 목록 제거/로컬 이력 정리와 인증 해제는 분리한다.

A3 목록 제거는 로그아웃 상태·사용 중 보호·로컬 데이터 삭제 확인을 API와 UI에 연결한다. 기본/다른 공급자/경로 이탈·junction·사용 중 거절, 선택/대기 정리·재시작 복원, Chromium 확인 취소/수락을 합성 프로필로 검증한다. 실제 로그인된 사용자 프로필은 제거 시험에 사용하지 않는다.

A6 전환 완료·인증 작업 종료 시 모델 목록을 재확인한다. 입력창과 다른 공급자의 전환도 감시하고 설정 목록의 대기/완료를 갱신한다. 늦게 도착한 과거 목록은 최신 조회를 덮어쓰지 않고 명시 모델/effort가 없으면 재선택을 요구한다. 합성 두 계정의 다른 모델 캐시로 전환 대기→종료→목록 변경을 Chromium에서 검사하고 로그인 종료 후 재조회도 확인한다.

## 5. 검증·중단 기준

A3의 로그인 명령 안내를 보완해 VIDE가 공식 CLI 로그인 프로세스를 직접 소유한다. 공급자별 로그인 진행 중 새 요청·다른 로그인·계정 선택은 보류하고, 기존 작업/불명확 결과가 있으면 로그인을 시작하지 않는다. 성공 종료 뒤 공식 인증 상태를 다시 확인하며 자동 계정 선택은 하지 않는다. 사용자 취소·5분 시간 초과는 소유 프로세스만 종료하고 실제 종료 확인 전 잠금을 해제하지 않는다. 서버 종료도 소유 로그인 정리를 수행한다. 원시 출력·인증 URL·토큰은 API/로그에 내보내지 않는다. 대역 프로세스로 실패·취소·시간 초과·종료 지연·인증 확인 실패를 검사하고 Chromium에서 로그인 진행/취소 UI를 검수한다.

자동 시험은 두 가짜 홈의 환경 격리, 기본 프로필 호환, 로그인 실패/취소, 두 동시 요청의 전환 대기, 큐에 고정된 계정, 실행 중 재로그인/제거 거절, 프로세스 비정상 종료, 재시작 후 lease, 미확인/오래된 사용량, 지원하지 않는 모델, 전환 중 개입을 포함한다. 경로 대소문자·junction 별칭과 앱 데이터 외부 경로를 검사한다. 인증값은 성공/실패 로그와 테스트 스냅샷에 출력하지 않는다.

실제 검수는 공식 CLI 로그인→상태 확인→합성 읽기 요청→다른 프로필 선택→다음 읽기 요청→재시작 순서로 공급자별 수행한다. 격리 실패·잘못된 계정 실행·토큰 누출이 하나라도 발견되면 해당 기능 공개를 막는다. 쓰기 작업은 기존 PLAN-02 회귀가 통과한 뒤 소유 합성 사본에서만 검사한다. 사용량 접근이 미지원이면 수동 전환은 완료 가능하지만 사용량/자동 전환은 미지원으로 남긴다. 유료 API로 자동 우회하지 않는다.

## 6. 공식 근거와 결과 기록

2026-09-25 확인: [Codex 인증](https://developers.openai.com/codex/auth/)은 인증 캐시와 파일/OS 저장소 선택을 설명한다. [Claude Code 설정](https://code.claude.com/docs/en/settings)은 CLAUDE_CONFIG_DIR로 설정 위치 변경을 설명한다. 두 문서의 설정 위치 지원을 다중 계정 동시성·Windows 자격증명 격리 보장으로 확대 해석하지 않는다. 구현 직전 CLI 버전별 동작과 이용 조건을 다시 확인한다.

A1 결과는 SPIKE, 채택한 저장/전환 구조는 ADR 및 ARCH, 제품 회귀는 VERIFY에 기록한다. 연구 원문을 계획에 복제하거나 연구 저장소를 제품 의존성으로 추가하지 않는다. 현재 A1 빈 프로필 상태 시험, A2 메타데이터 저장, A3 계정 추가·선택·공식 로그인 명령 UI와 요청 계정 고정, A4 미확인 사용량 표시를 구현했다. 두 ChatGPT 프로필의 실제 인증·채팅 왕복과 선택 재시작 복원은 통과했다. ChatGPT 2의 짧은 실제 병렬 요청은 통과했고 공식 재로그인도 확인했다. 장기 토큰 갱신 충돌과 Claude 두 계정 시험은 미검증이며 관리 프로필 로그아웃 UI·종료/인증 해제 확인은 구현·검증했으며 로그아웃 후 목록 제거/관리 프로필 로컬 설정 정리도 API·경로 보호·Chromium 검증을 통과했다. A5는 공식 사용량/소진 신호가 확인되지 않아 비활성 상태다. [증거](../tdd/SPIKE-2026-09-25-cli-profiles.md)를 따른다.
