# JIG 시작 양식 — 카드는 입구, 만들기 창은 체계화된 양식 (T-185~T-186)

근거: 2026-10-06 사용자 요청 "Jig에서 새로 만들기는 지금처럼 UI가 보이는게 아니라, 그 카드를 누르면 바로 만들기 창으로 넘어가는게 좋을 듯. 그리고 그 만들기 창은 누구나 그럴듯한거를 만들 수 있도록 어느정도 input값이 체계화된 방식으로 구현되면 좋겠음." 동작은 [SPEC-07](../specs/SPEC-07-jig-platform.md).16의 0·3, 화면은 [Design](../../Design.md) SCR-18 '새로 만들기 카드'와 SCR-16 '시작 양식'. [PLAN-26](PLAN-26-chat-stage.md) T-099가 만든 카드(한 문장 입력·[만들기 시작]·[빈 초안에서])를 대신한다.

같은 요청에서 정한 것: 기본 시작점은 빈 초안(본보기 격자 예제는 고를 때만), 목적 한 문장만 필수, [계획 받기]가 양식을 첫 턴으로 **저절로 보낸다**(SPEC-07.16 0의 '저절로 보내지 않는다'를 이 경우만 바꿈). 양식은 진입 비용을 늘리지 않도록 목적 외 칸을 모두 비워 둘 수 있고, 비운 칸은 AI가 가정으로 채운다(RESEARCH-05 §4.2 ⑥의 경고). 화면에는 개발 용어를 쓰지 않는다(Design §07, RESEARCH-10 §8.6).

## T-185 카드 → 시작 양식 → 계획 → [만들기 시작]

| 대상 | 변경 |
|---|---|
| `src/ui/make-tab.tsx` `MakeCard` | 점선 카드 전체가 버튼 하나(‘+ 새로 만들기’). 입력 칸·설명·보조 링크 없음. 누르면 `openBrief` |
| `src/ui/make-tab.tsx` `openBrief` | 만들기 탭을 시작 양식으로 연다: 열 초안 없음, `rememberDraft(projectId, undefined)`로 마지막 초안이 다시 열리지 않음 |
| `src/ui/make-tab.tsx` `MakeBrief` | 초안이 없을 때의 만들기 화면: 목적(필수, 100자), 언제 쓰나/쓰지 않나(예문 칩), 입력 칩 6개(호스트 레이어 → 형상 칩, 그리는 구역 → 모양 칩), 설정값 표(이름·종류·단위·기본값·범위·근거, 행 추가·삭제), 계산 단계 행(이름·맡는 쪽·한 줄), 결과 체크(3D 미리보기선·표·보고서·다른 jig로 넘김, Rhino에 만들기: 곡선·보 스윕·기둥 돌출·문자점), 통과 조건 행(막음/주의), 시작점(빈 초안 기본 / 격자 예제). [계획 받기]는 목적이 비면 꺼짐 |
| `src/ui/make-brief.ts`(신설, 순수 + 브라우저 저장) | 양식 형식과 목록, `briefPrompt`(양식 → 첫 턴 문장, 비운 칸은 ‘가정으로 채워 주세요’, 계획만 요청), `briefPlan`(양식 기준 계획 카드), `untouched`·`phaseOf`·`planOf`(make-tab에서 옮김), 초안별 양식과 [만들기 시작] 여부(`vide:make-brief:<draftId>`, 이 브라우저의 편의 값) |
| `src/ui/make-tab.tsx` `sendMakeTurn` | [계획 받기] 뒤 초안의 만들기 대화가 고른 대화가 되면 입력 칸에 문장을 넣고 보낸다. 다른 대화로는 보내지 않고, 입력 칸에 적어 둔 말이 있으면 보내지 않으며, 보내기가 꺼져 있으면(모델 없음 등) 입력 칸에 남기고 한 줄 안내. 이 턴은 경로 판정(Jev·규칙)을 거치지 않는다 — 양식 문장이 ‘Sync 받기’ 같은 앱 동작으로 판정되는 것을 확인함 |
| `src/ui/make-tab.tsx` 진행·계획 카드 | 작성 시작 = [만들기 시작]을 보냄 또는 초안 생성 뒤 파일(`jig.json` 제외)이 바뀜. 그 전에는 진행 ‘계획’, 시작점 파일로 ✓를 찍지 않고, 양식으로 시작한 초안은 양식 항목(‘양식 n칸’)을 보인다 |
| `src/ui/make-tab.tsx` 오른쪽 계획 카드 | 아래에 주 버튼 [만들기 시작](SCR-16). 누르면 ‘만들기 시작’을 대화로 보내고 숨는다 |
| `src/ui/make.css` | 버튼 카드, 양식(칩·표·행·좁은 폭 1열) |
| `src/ai/instructions/make.md`, `src/ai/agent-connection.ts` `makeToolInstruction`·`codexMakeInstruction` | 계획 먼저: ‘만들기 시작’ 전의 턴은 코드·파일을 쓰지 않고(Codex는 `files: []`) 양식을 입력·설정값·단계·화면·결과 한 장으로 정리, 빈 칸은 가정으로 적음. 작성이 시작된 대화의 뒤 턴은 이어서 씀 |

서버(`src/jigs/runtime/drafts.ts`)는 그대로 둔다. 양식은 초안 파일로 남기지 않는다(`jig.json`에 선언하지 않은 파일은 점검에서 다뤄야 하므로). 계획의 정본은 만들기 대화다.

**선행·외부 조건:** 없음. 실제 Claude·Codex가 계획 턴에서 파일을 쓰지 않는지는 설치본에서 확인한다(지침만 바꿈).

## T-186 검증

- 단위 `tests/core/make-brief.test.mjs`: 목적만 필수·기본 시작점 빈 초안, 첫 턴 문장(계획만·빈 칸 7곳 가정·채운 칸의 문장, 빈 행 제외), 양식 기준 계획 카드, 시작점 파일은 작성 전 ‘계획’·✓ 없음, [만들기 시작] 뒤·파일이 바뀐 뒤 ‘작성’, 시각을 모르면 예전 판정.
- 브라우저 `tests/integration/browser-make.mjs`: 마지막 카드가 입력 없는 [새로 만들기] 버튼 → 누르면 만들기 화면의 시작 양식(초안 요청 없음) → 목적이 비면 [계획 받기] 꺼짐 → 칩·설정값·단계 추가/삭제·결과·통과 조건 → 요청 `{ name, from: 'blank' }` → 첫 턴이 `conv-make`로 저절로 감(목적·입력·설정값·단계·결과·통과 조건·‘코드와 파일을 쓰지 말고’) → 진행 ‘계획’, 계획 카드 ‘양식 6칸’ → [만들기 시작]이 ‘만들기 시작’을 보내고 숨음, 진행 ‘작성’ → 이후 기존 점검·시험·미리보기·고정·버리기(버린 뒤 시작 양식).
- 회귀: `browser-jigs.mjs`, `browser-workspace-tabs.mjs`, `npm test`, `npm run typecheck`, `npm run build:web`, prettier, `npm run docs:check`.

**완료 판단:** 위 자동 검증 통과(2026-10-06). 남은 조건: 설치본에서 실제 Claude·Codex 만들기 대화의 첫 턴이 계획만 내는지, [만들기 시작] 뒤 작성으로 넘어가는지 확인(사용자 실기). 말('jig로 만들어')로 시작하는 초안과 [수정하기] 사본은 양식 없이 그대로 열린다.
