개발 기반 구축과 저장소 보호

01 / 범위와 착수

2026-09-24 사용자의 개발 착수 지시에 따라 T-019부터 구현한다. Git 이력 재작성·강제 push는 포함하지 않는다. 목표는 개발 중 회귀와 저장소 노출을 발견하고 기존 자료를 보존하며 다음 제품 작업을 진행할 기반이다. 현재 상태는 마스터 §6.5가 소유한다.

제품 목표는 PRD를 유지한다. AI 실행기의 오류/위험 API 방어, Rhino/ZWCAD 기능 확장, 원격 게시·의견은 후속 PLAN-02 제품 작업이다. 개발 기반을 이유로 완전한 보안 보증이나 끝없는 리팩터링을 목표로 삼지 않는다. 이후 데이터 보존의 사용자 약속이 바뀌면 SPEC-05·관련 SPEC을 먼저 검토한다.

02 / 작업 순서와 완료 기준

T-019 → T-020 → T-021 → T-022 → T-023 → T-024 순서로 진행한다. 포맷과 동작 변경은 별도 커밋으로 나눈다. 새 라이브러리는 기존 도구·잠금 파일과 호환성을 확인해 최소한으로 채택한다.

T-019 · Git 추적과 ignore

  • 변경 대상: .gitignore, 추적 파일 정책, 패키지/시험 산출물 경로.
  • 조사: tracked/untracked/ignored를 구분하고 자격 증명·개인 DB·사용자 모델·로그·덤프·캐시·빌드·패키지 산출물을 목록화한다. 승인된 합성 fixture·잠금 파일·생성 문서 HTML은 보존한다.
  • 구현: 필요한 ignore 패턴을 좁게 추가한다. 이미 추적된 파일은 ignore로 숨겨지지 않으므로 개별 판단한다. 사용자 파일을 삭제하거나 일괄 git clean을 하지 않는다.
  • 완료: git check-ignore로 포함/제외 양쪽 예시를 확인하고 필요한 소스·시험 자료가 누락되지 않는다. ignore된 파일이 배포 패키지에 포함되는지도 별도 검사한다.

T-020 · 비밀정보와 Git 배포 보호

  • 변경 대상: 검사 도구 설정, 로컬 커밋/푸시 검사와 CI, 배포 대상 확인 절차.
  • 조사: 현재 추적 파일과 로컬 Git 이력·참조를 읽기 전용으로 점검한다. 원격 전체 이력을 확보하지 못한 범위는 미검사로 표시한다. 실제 키 값을 로그·채팅·검증 문서에 복사하지 않는다.
  • 구현: 기존 도구 유무를 확인한 뒤 비밀정보 스캐너를 선정한다. 예외는 정확한 합성 fixture와 이유에 한정한다. account_id는 인증 비밀과 구분하며 환경 변수화는 배포 대상 분리 목적일 때만 적용한다. 계정·D1·R2·환경명이 맞는지 배포 전에 확인한다.
  • 완료: 무효한 합성 키 패턴이 검사에서 차단되고 일반 코드·시험 fixture는 통과한다. 검사 실패나 도구 미설치가 성공으로 처리되지 않는다. 로컬 훅 우회만으로 원격 검증이 생략되지 않도록 CI 검사를 마련한다. 브랜치 보호 등 원격 설정은 현재 권한과 공개 저장소 조건을 확인해 별도 보고한다.
  • 발견 시: 파일 위치·유형·범위만 보고하고 실제 비밀정보는 폐기/교체를 우선한다. Git 이력 재작성·강제 push·키 변경은 구체 영향 범위에 대한 사용자 지시 없이 하지 않는다. 공개 이력에서 삭제만 하면 비밀이 복구됐다고 말하지 않는다.

T-021 · 자동 검증 경로

  • 변경 대상: 루트/공유 package scripts, .githooks, CI 구성.
  • 구현: UI·서버·공유 Workers의 타입 검사, 코어/AI/서버·공유 테스트, 빌드·문서 일치 검사를 통합 명령으로 연결한다. 현재 루트 npm test의 웹 사전 빌드와 공유 패키지의 별도 검증을 고려한다.
  • 커밋: 변경 범위에 맞는 빠른 검사와 기존 MD/HTML 일치 보호를 유지한다. 부분 스테이징 상태에서 작업 트리 검사만 통과하고 다른 코드가 커밋되는 문제를 방지한다. 자동 포맷으로 사용자의 미스테이징 변경을 함께 추가하지 않는다.
  • 통합: 전체 검사와 헤드리스 브라우저 회귀를 CI/명시적 통합 명령으로 실행한다. C# 빌드는 SDK 보유 환경에서, Rhino/ZWCAD 실호스트 검증은 합성 자료를 사용하는 별도 경로로 둔다. CLI 계정이나 CAD 라이선스가 필요한 시험을 일반 공개 CI에 강제하지 않는다.
  • 완료: 의도한 타입 오류·실패 테스트·오래된 HTML을 각각 검출하고 실패 시 커밋/검증이 중단된다. 실제 실행한 검사와 환경 미확보로 빠진 검사를 구분한다. CI에서 비밀값이나 사용자 프로젝트를 사용하지 않는다.

T-022 · 일관된 포맷

  • 변경 대상: TS/TSX/JS/CSS/JSON 등 제품·도구 소스의 포맷 설정. C#은 해당 생태계의 도구로 별도 검토한다.
  • 구현: Prettier/Biome 중 기존 문법·CSS·JSONC와 호환되는 도구 하나를 선정한다. 생성 HTML, 번들, 사용자 자료, SDK/vendor, 잠금 파일을 임의 재포맷하지 않는다. Markdown 재배치는 이 티켓에서 반복하지 않는다.
  • 완료: check/write가 재현 가능하고 두 번째 실행에서 차이가 없다. 포맷 전후 검증 결과가 같으며 기능 변경을 별도 커밋으로 분리한다. 긴 줄 개수 감소를 설계 품질의 완료 기준으로 삼지 않는다.

T-023 · 로컬 SQLite 마이그레이션

  • 변경 대상: src/core/store.ts와 생성자별 스키마 초기화, 업그레이드 시험 fixture, 백업 경로.
  • 구현: 기존 schema 1의 실제 테이블을 조사하고 현재 데이터를 보존하는 기준선을 만든다. 번호가 있는 순차 이행·지원 버전 검사·단일 제어자·백업·트랜잭션·무결성 확인을 일관되게 처리한다. D1의 번호 관리 원리는 참고하되 로컬 SQLite/WAL/자산 파일의 수명에 맞게 구현한다.
  • 완료: 빈 DB, 기존 설치본 DB, 재실행, 중간 실패, 지원보다 새로운 DB, 디스크/백업 실패를 시험한다. 기존 요청·후보·관계와 파일 참조가 보존되고 실패 후 확인 가능한 복구 경로가 있다. 시험은 복사본에서만 한다. 미래 전체 제품 테이블을 선구현하지 않는다.

T-024 · 호스트 의존 경계와 공통 함수

  • 변경 대상: hosts/zwcad/inspector.ts의 서버 내부 경로 의존, Rhino literal 변환의 중복, 실제 필요한 호스트 포트 타입.
  • 구현: 서버가 실행 환경/리소스 위치를 주입하고 호스트가 서버 구현을 import하지 않게 한다. 의미가 같은 C# 문자열 인코딩만 공통화하며 PowerShell/JSON 등 서로 다른 언어의 이스케이프를 합치지 않는다. 불필요한 범용 플러그인 프레임워크를 만들지 않는다.
  • 빈 catch: 종료/정리의 best-effort, 입력 파싱, 사용자 작업 실패를 구분한다. 실패를 숨기는 경로는 관련 시험과 진단을 보완하고 정상적인 정리 예외는 의도와 관측 방법을 남긴다. 제품 실행기의 상세 오류/unknown 정책은 후속 제품 티켓과 연결한다.
  • 완료: 호스트→서버 구현 import가 없고 따옴표·역슬래시·개행·유니코드 문자열 시험과 기존 호스트 회귀가 통과한다. 동작을 바꾸는 추상화를 포맷 변경에 섞지 않는다.

03 / 산출물과 다음 단계

확정된 구조는 ARCH-01, 실제 검사 명령과 실행 절차는 가이드의 해당 절, 결과는 범위를 가진 VERIFY에 기록한다. PLAN §6.5에는 현재 결과·남은 조건·증거 링크만 갱신하고 별도 일지를 쌓지 않는다. 티켓마다 필요한 경우에만 호스트 지원표를 갱신한다.

기반 검증 후 제품 단계는 오류·실행 방어 → ZWCAD 범용 AI/SDK → 기존 문서·복수 실행본 → 공유 왕복 → 대표 과업/출시 관문 순서다. 기존 Rhino SDK 연결을 새로 시작하지 않는다. 외부 권한·장비가 필요한 시험은 미시험으로 명시하고 사용자와 완료 범위를 확인한다. Jev는 마스터 §9.4의 후속 조사로 유지한다.
