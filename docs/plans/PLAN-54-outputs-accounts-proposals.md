# 산출물 등급 · 외부 계정 배포 · 갱신 제안 카드 · JIG README · 팀 기록 공유

2026-10-15 사용자 생각 정리([RESEARCH-17](../research/RESEARCH-17-workspace-and-records.md))에서 **작업 폴더(PLAN-52)와 기록 모델(PLAN-53)에 속하지 않는 다섯 가지**를 한 계획으로 묶었다. 같은 날 사용자 결정은 다음과 같다.

- 산출물은 **검토용과 보고용 두 등급**으로 나눈다. 공유는 먼저 VIDE 공유 사이트, 다음에 본인 Cloudflare.
- 외부 계정은 **GitHub·Cloudflare 둘 다 1차**다.
- 도구 사이 갱신은 **변경 감지 → "맞출까요?" 카드 → 적용은 사람**이다. PRD §4.4·§12.2의 비목표("요청 없는 호스트 간 원본 자동 동기화")는 그대로 둔다. 카드는 글이 아니라 **그림**이어야 한다(CAD의 rev cloud처럼 어디가 안 맞고 어떻게 바뀌는지).
- jig의 **자연어 명세(README)가 정본이고 코드는 생성물**이다.
- 일지·회의록·일정은 **팀원과 공유**하고 작업 폴더에도 사람이 읽는 사본을 남긴다.

후보 기능 번호(C-11 산출물·배포, C-12 갱신 제안)는 PRD §4.4가 확정한다. 이 계획은 **계획 단계**이며 구현 착수는 PLAN-51 졸업과 PLAN-52 1차 뒤다. 동작 의미는 각 SPEC 보완이 먼저이고(AI.md §8), 이 문서는 어느 절을 보완할지와 변경·검증 범위만 정한다.

## 착수 조건과 범위

- **제품 결정:** 위 사용자 결정. PRD 비목표는 바꾸지 않는다. 범위 태그(§14.2)에 C-11·C-12를 넣는 일은 PRD가 한다.
- **선행:** [PLAN-52](PLAN-52-workspace-folders.md)의 역할 경로(`project.config.json`의 `paths`)가 있어야 산출물·기록 사본을 폴더에 쓸 수 있다. 1부·5부는 PLAN-52 1차 뒤, 2부·3부·4부는 독립이다.
- **원칙(AI.md §8):** 실호스트 시험은 `.vide/` 아래 사본만. 토큰·키는 저장소·검수 증거·진단 번들에 넣지 않는다. 사용자 Rhino·ZWCAD 창은 쓰지 않는다.
- **기술 계약:** 서비스 설정 파일·비밀 저장 형식·배포 템플릿 위치·제안 카드의 표시 레이어 이름은 [ARCH-01](../architecture/ARCH-01-system.md)에 절을 더해 소유한다(이 계획은 가리키기만 한다).
- **범위 밖:** 플롯·PDF 생성(PLAN-47 결정 유지), 자동 적용(비목표), Notion·Slack 같은 외부 협업 도구 연동, jig 코드 편집기·흐름 다이어그램(SPEC-07.16 "1차에 넣지 않는 것" 유지).

## 1부. 산출물 두 등급 — 검토용과 보고용 (T-340~T-343)

### 목적과 기준

같은 jig 결과에서 **안에서 보는 것**과 **밖에 내는 것**을 다르게 뽑는다. 지금은 jig마다 HTML 보고서·CSV 하나뿐이라(SPEC-12.13 6, SPEC-15.12) 발주처에 줄 수 없는 가정·미검토 표시가 그대로 나가거나, 반대로 내부 검토에 필요한 출처가 빠진다. 기준은 SPEC-07.11(보고서 틀: 주장 템플릿, 첫 쪽의 가정·미검토, 설정으로 돌아가는 단추)과 FR-14(산출물 열람·파일 내보내기)다.

| 등급 | 들어가는 것 | 저장 위치(PLAN-52 역할 경로) | 쓰는 사람 |
|---|---|---|---|
| **검토용** | 모든 가정·출처·미검토 항목, 사실 문장 `[S#]` 인용(SPEC-08), 매개변수 이력, 실패·건너뜀 표시, 설정으로 돌아가는 단추 | `05_검토/<jig>/<회차>/` — 데이터 JSON과 함께 | 우리 팀, 다음 회차의 입력 |
| **보고용** | 사람이 고른 장면·표·범위만. 첫 쪽의 가정·미검토 **요약은 유지**(SPEC-07.11을 어기지 않음), 내부 ID·요청 번호·검토 단추 없음 | `06_산출물/<이름>/` — 자체 완결 HTML + CSV | 발주처·협력사, 게시 대상 |

검토용은 회차마다 자동으로 남고, 보고용은 사람이 [보고용 만들기]를 눌러 범위를 고를 때만 생긴다. 보고용을 만들 때 어느 검토용 회차에서 나왔는지(회차 ID·시각)를 HTML 머리에 적어 추적한다.

### 변경

- **SPEC 보완(먼저, 2026-10-15 완료 — T-340):** SPEC-07.11에 '두 등급'과 보고용의 범위 선택·추적 표기를 더했다. SPEC-12.13 6·SPEC-15.12는 "등급은 SPEC-07.11을 따른다"로 가리킨다. 저장 위치는 PLAN-52가 정하는 역할 경로(`review`·`output`)를 인용한다.
- `reports/*.json` 보고서 틀에 `tier`별 섹션 포함 규칙(검토용 전부, 보고용은 `public: true` 섹션과 사람이 고른 장면).
- `src/ui/report-tab.tsx`: 등급 전환, [보고용 만들기](장면·표 선택 → 미리보기 → 저장), 저장 위치 표시.
- `src/ui/compliance/model.ts`와 다른 jig의 HTML 생성기: 공통 생성기로 모아 등급 인자를 받게 한다(jig별 복제 금지).
- 엔진: 회차 완료 시 검토용을 `05_검토/<jig>/<회차>/`에 쓰고, 보고용 저장은 `06_산출물/`에만. 폴더가 없거나 서버 쓰기가 막힌 경우(ADR-042)는 PC 데이터에 두고 '폴더에 아직 안 씀'을 보인다.
- 공유: 보고용 HTML을 VIDE 공유 사이트의 보고용 게시(SPEC-04.14)로 올리는 [공유] 단추. 본인 Cloudflare 배포는 2부 T-347.

## 2부. 외부 계정 — GitHub·Cloudflare (T-344~T-347)

### 목적과 기준

작업 폴더의 **이력·재현(GitHub)**과 보고용 산출물의 **본인 계정 배포(Cloudflare)**를 VIDE 안에서 끝낸다. 기준은 SPEC-13.11의 외부 서비스 설정 틀(계정 사이트가 아닌 PC 설정, DPAPI 봉인), FR-18(전송·공개 권한 구분), ADR-040(도메인 서비스: 외부 서비스는 계약으로 연결하고 VIDE가 대신 소유하지 않음). ADR-040은 "사용자 자신의 계정으로 쓰는 서비스"를 다루지 않으므로 **확장 결정**이 필요하다(ADR-042가 작업 폴더·서버 규칙과 함께 소유하거나 별도 ADR).

### 변경

- **설정(의미는 SPEC-05.11, 결정은 ADR-043):** '외부 서비스' 탭에 두 항목. GitHub는 PAT 붙여넣기(1차) 또는 device flow(2차, OQ), Cloudflare는 API 토큰 + 계정 ID. 저장은 `src/services/secrets.ts`(DPAPI)·`src/services/settings.ts`. 화면은 '연결됨/안 됨'과 마지막 확인 시각만 보이고 값은 다시 보이지 않는다. 진단 번들·로그·공유 사이트 업로드에서 제외(기존 `public-data.env` 규칙과 같음).
- **용도 ① GitHub(PLAN-52 훅 지점):** 작업 폴더 git 초기화(`.gitignore`는 PLAN-52 템플릿: 텍스트·설정·분석 JSON·md·html만 추적, 3dm·dwg·pdf·이미지 제외), [저장점 만들기](커밋, 메시지는 사람이 고치는 한 줄 초안), 원격 저장소 만들기·푸시, 다른 PC에서 [가져오기]. 충돌은 VIDE가 풀지 않고 "로컬이 다릅니다 — 폴더를 git 도구로 여세요"로 멈춘다. 회사 서버 폴더(UNC)에는 git을 만들지 않는다(ADR-042).
- **용도 ② Cloudflare:** 보고용 산출물(`06_산출물/<이름>/`)을 본인 계정의 Worker(정적 자산 + 비밀번호 확인)로 배포. 논현동 164의 `cloudflare-deploy` 패턴을 VIDE 내장 템플릿(`src/sharing/deploy-templates/password-site/`)으로 옮기고, VIDE가 wrangler 없이 Cloudflare API로 올린다(가능 여부는 SPIKE). 배포마다 URL·비밀번호·시각을 `06_산출물/<이름>/publish.json`에 남긴다(비밀번호는 봉인 저장, 파일에는 '설정됨'만).
- **권한 경계(FR-18):** 배포·푸시는 항상 사람이 단추를 누른다. AI 요청이 대신 누르지 않는다.

## 3부. 갱신 제안 카드 — 호스트 안 rev cloud 표시 (T-348~T-351)

### 목적과 기준

사람이 **지정한 파일 쌍**(예: `03_모델/A.3dm` ↔ `04_도면/A-평면.dwg`)에서 한쪽이 바뀌면 VIDE가 "모델이 바뀌었어요. 도면도 맞출까요?" 카드를 띄운다. 쌍은 [PLAN-52](PLAN-52-workspace-folders.md) 파일 지도의 Sync 쌍 연결선에서 지정하며, 카드는 그 지도의 영향 미리보기(T-319)와 같은 면에 뜬다. 적용은 사람이 누르고, 누르면 Sync jig의 역반영 경로(SPEC-14.8, PLAN-47 T-233)가 돈다. PRD 비목표(요청 없는 자동 적용)는 유지한다. 사용자 요구는 카드가 **직관적**이어야 한다는 것이다: 어디가 안 맞는지, 어떻게 바뀌는지를 CAD의 rev cloud처럼 **그 도구 안에서** 보여준다.

| 곳 | 표시 | 지움 |
|---|---|---|
| CAD(ZWCAD) | VIDE 전용 레이어(`VIDE_제안`)에 어긋난 객체 둘레 **rev cloud** + 이전→이후 화살표·치수 문자(예: "기둥 C3 +500") | [적용]·[무시] 뒤 레이어째 삭제, 저장 전이면 문서에 남지 않음 |
| Rhino | 어긋난 객체 강조(기존 하이라이트 conduit) + 반투명 '이후' 형상(역반영 결과를 임시 표시) | 같은 때 conduit 해제 |
| VIDE 뷰포트·카드 | 같은 것을 겹쳐 보기, 어긋남 목록(SPEC-05.8 행), [적용]·[무시]·[나중에] | 카드 닫힘 |

### 변경

- 엔진: 쌍 등록(`project.config.json`의 `pairs`로 폴더에도 남김 — PLAN-52), 변경 감지(Rhino Live Sync 변경 이벤트·CAD 저장 감지), 어긋남 계산은 Sync jig 재사용.
- 호스트: ZWCAD worker에 rev cloud·문자 쓰기 명령(PLAN-47 T-233의 쓰기 경로 재사용, 전용 레이어·출처 xdata), Rhino 임시 표시.

## 4부. JIG README 표준 — 자연어 명세가 정본 (T-352~T-354)

### 목적과 기준

사용자의 디지털 지그 생각: jig는 **목적·입력·출력·구현 논리**를 자연어로 적은 규격화된 설명으로 정의되고, 그 설명이 있으면 누구나(사람도 AI도) 같은 특수해를 다시 쓸 수 있어야 한다. 지금은 만들기 양식(SPEC-07.16 0: 목적/입력/설정값/단계/결과/통과조건)이 대화 시작에만 쓰이고 저장되지 않으며, `skill.md`는 AI 호출 안내문이고 입력·출력은 `jig.json`에만 있다. 기준은 SPEC-07.2(jig 구성), SPEC-07.16(만들기), SPEC-07.19(관리자 제출), FR-24.

규칙: **jig 폴더의 `README.md`가 정본, 코드는 생성물.** README 없이 코드만 고친 jig는 '명세 없음'으로 표시되고, AI가 jig를 다시 만들거나 고칠 때 README를 기준으로 삼는다. README는 사람이 직접 고칠 수 있고, 고치면 jig.json·코드와 어긋나는지 점검(SPEC-07.14)에 걸린다.

README 고정 절: 목적(한 문단) · 언제 쓰나/언제 아니다(`words`·`not_for`와 같은 뜻) · 입력(역할·형태·출처) · 설정값(이름·단위·기본·근거) · 단계(사람이 끼어드는 곳 표시) · 결과(화면·Rhino·파일) · 통과 조건(점검 항목) · 한계·가정 · 이력(판·날짜·바꾼 이유 한 줄). 문장은 한국어, 식별자는 ASCII(AI.md §8).

### 변경

- **SPEC 보완(먼저):** SPEC-07.2에 README를 구성 요소로, SPEC-07.16에 "양식 → README 저장, 대화 중 갱신, 수정하기는 README부터", SPEC-07.14에 README↔jig.json 대조 항목, SPEC-07.19에 제출 묶음 포함을 더한다. `skill.md`와의 관계: `skill.md` frontmatter(`words`·`not_for`·`examples`)는 README의 해당 절에서 **생성**한다(두 곳에 손으로 쓰지 않음).
- `src/ui/make-brief.ts`·`make-tab.tsx`: 양식 → `README.md` 초안 저장, 대화가 입력·단계를 바꾸면 README도 갱신(AI가 쓰고 사람이 본다).
- 카탈로그(`src/jigs/catalog.ts`)·JIG 목록: README 첫 문단을 설명으로 표시, '명세 없음' 배지.
- 공식 jig 전부에 README를 소급 작성(규모검토 3종·법규 체크·구조·패널링·Sync·도면). 내장 jig(Sync·구조·지식)도 README는 둔다(복사 불가 규칙은 그대로).
- 관리자 제출(`src/server/jig-submit.ts`)에 README 포함, 받는 쪽 화면에 README 먼저.
- PRD 과제로만 표시: §4.2 '전문 스킬로 추가하는 업무' 문구에 '특수해의 재사용(한 프로젝트의 해법을 설명과 함께 다른 프로젝트가 다시 씀)'을 반영할지는 PRD가 정한다. 이 계획은 구현 항목으로 삼지 않는다.

## 5부. 팀 기록 공유 — 일지·회의록·일정 (T-355~T-357)

### 목적과 기준

프로젝트 구성원이 **날마다의 작업 일지, 회의·협의 기록, 일정**을 같은 곳에서 보고 적는다(FR-26, SPEC-10). 지금은 노트 공동 편집과 [퇴근하기] 일지, 할 일·일정 화면이 있고 사이트(D1)에 노트·할 일 사본이 가지만(ADR-037), 회의록은 종류가 없고 일정은 PC 화면뿐이며 사람이 읽는 파일이 폴더에 남지 않는다. PLAN-32/33/35/36의 원격 배포와 2대 검수가 "사용자 확인 대기"로 남아 있다.

### 변경

- **SPEC 보완(먼저):** SPEC-10에 노트 종류 `meeting`(회의록: 날짜·참석·결정·할 일 추출)과 `schedule`(일정: 기존 일정 화면과 같은 데이터)을 더하고, SPEC-10.5 일지에 "폴더 사본" 규칙을 더한다. 공유 범위는 ADR-037 3(사이트가 정본인 것)을 따른다: 노트·일지·회의록·일정은 사이트 정본 + 폴더 사본 + PC 사본.
- 폴더 사본(PLAN-52 역할 경로 `01_운영/`): `일지/YYYY-MM-DD.md`, `회의록/YYYY-MM-DD-<제목>.md`, `일정.md`(월 단위). 사이트에서 적은 것은 PC가 연결될 때 사본이 생기고, 사본을 사람이 고치면 사이트로 올라가지 않고 '폴더에서 바뀜' 표시만(정본은 사이트).
- 외부 미팅: 폰·노트북의 사이트에서 회의록을 적으면 돌아왔을 때 `01_운영/회의록/`에 사본. 회의록의 '할 일' 줄은 기존 [할 일로 보내기] 규칙(`agendaFromText`)을 쓴다.
- 기록 모델 입력(PLAN-53): 일지·회의록의 결정 줄은 R/I/K/E/D 기록 후보로 넘어간다(태깅은 PLAN-53).
- 미완 배포 마무리: PLAN-32/35/36의 D1 마이그레이션·Worker 배포·2대 검수를 이 계획의 T-357에서 함께 끝낸다(각 PLAN의 상태는 그 PLAN에 적음).

## 결정이 필요한 질문

- **GitHub 인증 방식:** PAT 붙여넣기(단순, 만료 관리 필요) vs device flow(편하나 OAuth 앱 등록 필요). 1차는 PAT로 두고 device flow는 OQ.
- **Cloudflare 배포 방식:** T-347 SPIKE(문서 + 가짜 API)로 REST API만으로 가능하다고 보고 wrangler를 동봉하지 않았다. 실제 계정 배포 1회로 확인한다.
- **보고용 게시 업로드 허용:** 스테이징 사이트의 `UPLOADS_ENABLED`(ADR-038)를 보고용 게시에만 따로 열지, R2 결정 때 함께 열지.
- **PRD §12.2 문구:** '제안은 허용, 적용은 사람'으로 좁힐지(C-12)는 PRD에서 결정한다.
- **보고용의 비밀번호 수명:** 링크당 고정 vs 만료. 1차는 고정 + 사람이 [다시 만들기]로 바꿈(구현됨, ARCH-01). 만료는 아직 없다.
