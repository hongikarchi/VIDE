# 작업 공간 UI 점검 반영

사용자가 선택한 A 전체, B06·10·11·12·14, C05만 반영한다. 제품 범위는 PRD FR-01·05·07·08·15·16, 동작은 SPEC-01.7과 SPEC-05.2 및 입력 보호/연결 표시 절, 표현은 Design 작업 공간 조작 절을 따른다.

## 변경 순서와 범위

1. A01: 다중 로컬 서버 쿠키 충돌 재현/격리, 인증 상실 표시·초안 보존. B12: 호스트별 준비와 공급자 상태 분리.
2. A03~08: 입력 버튼 조건, 연계 선행 조건/묶음 제거, 파일 형식·크기 안내 및 원자적 첨부, 초안 교체 확인.
3. A02·B06: 실제 카메라 상태 기반 강조와 투영 단일 토글.
4. B10·14: 좌우 폭 조절, 문서/이력/참고 탭. B11: 의미 있는 문맥 요약과 진단 펼침.
5. C05: 설치 공급자 자료와 공식 지원표로 모델별 effort를 확인하고 이산 슬라이더 적용.

## 선행 조건·검증·완료

기존 사용자 프로젝트/호스트 문서는 수정하지 않는다. 새 격리 프로젝트의 브라우저 테스트로 입력·취소·탭 보존·키보드·폭 제한·카메라 상태를 검증한다. 인증은 서로 다른 서버 두 개의 쿠키 공존 및 잘못된 인증 거절을 확인한다. 모델 목록과 실제 계정 실행 성공은 구분하며 유료 추론을 일괄 실행하지 않는다.
typecheck·단위/서버 회귀·브라우저 회귀를 수행하고 Aside에서 실제 렌더와 주요 동작을 확인한다. MD의 HTML을 재생성하고 VERIFY에 실제 결과/한계를 기록한다. 선택 항목의 동작과 기존 초안·요청 흐름이 검증되면 완료다. 다른 세션의 research 파일은 변경/커밋하지 않는다.

검증 결과: [UI 조작 VERIFY](../tdd/VERIFY-2026-09-24-workspace-controls.md). 현재 선택 범위는 구현·검증 완료이며 미선택 UI 항목과 실기기 검수는 별도다.

## 작성기·탐색·상태 정리 (2026-09-28)

T-010·T-004, PRD FR-05·08·15·16, SPEC-01 입력 보호 및 SPEC-05.2·5, Design 작성기·카메라·상태 조작 보완을 기준으로 한다. 기존 기능을 정리하며 호스트 데이터나 실행 권한은 변경하지 않는다.

1. Effort를 현재 단계 캡슐과 팝업 슬라이더로 정리한다. 모델 변경·비지원 단계·키보드를 검증한다.
2. 작성기 상단 경계에 포인터/키보드 resize를 제공하고 높이 제한·축소 화면·새로고침 보존을 검증한다.
3. 우클릭 회전·Shift 우클릭 평행 이동, 표준 직교/스케치 평면에서 이동을 검증한다. 왼쪽 선택/스케치 입력은 유지한다.
4. 연결·오류를 상태줄 및 상세 팝업으로 이동한다. 실제 공급자 상태와 설치 호스트를 구분하며 인증 상실·API 실패·실패 작업 기록을 확인한다.
5. 설정 진입점을 rail 하단에 둔다. 기존 AI 계정/경로 및 작업 상한 설정을 연결하고 닫은 뒤 초안 보존을 확인한다.

격리 브라우저에서 정상/오류/1440×900/좁은 화면을 확인하고 typecheck 및 기존 UI 회귀를 실행한다. 사용자 Rhino 모델에는 테스트 명령을 보내지 않는다.

검증: [작성기·카메라·상태줄 VERIFY](../tdd/VERIFY-2026-09-28-workspace-polish.md). 위 5항목은 구현 및 격리 브라우저 검증 완료다. 실제 사용자 모델 연결 검증은 PLAN-02의 별도 범위를 따른다.
