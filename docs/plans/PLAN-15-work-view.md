# 작업 이력과 우측 작업 보기(진행·개입)

2026-09-29 사용자 지적("오른쪽은 요청이 어떻게 진행되는지 보여 주고, 어느 지점에서 개입할지 고르게 해야 하는데 PRD의 생각이 반영되지 않았다")과 결정("요청 목록은 왼쪽 작업 이력으로 모으고, 오른쪽은 진행 화면으로")의 작업이다. 동작은 [SPEC-02.11](../specs/SPEC-02-execution-candidates.md)의 진행 단계, 화면 표현은 [Design §06 SCR-03](../../Design.md)이 소유한다.

## 이전 상태

오른쪽은 모든 요청 카드가 쌓이는 대화 목록과 그 아래의 진행 중 영역(단계 문구 한 줄·로그 8줄·추가 지시)이었고, 같은 요청이 왼쪽 작업 이력에도 있었다. 현재 대상·조건, 계획 대비 위치, 중간 결과, 미확인 사항, 단계별 개입이 한눈에 보이지 않았다.

## 변경

1. `src/ui/work-stages.ts`: 요청 상태·단계 표시(phase)·활동 기록에서 단계 목록과 상태·횟수를 계산하는 순수 함수(SPEC-02.11의 규칙).
2. `src/ui/work-view.tsx`: 선택한 작업 하나의 보기(머리·조건·단계·결과·확인할 것·작업 과정). 기존 카드의 결과 행동(후보 보기·적용·복구·복원·중단)은 그대로 옮긴다.
3. `app.ts`: 우측 대화 목록과 진행 중 영역을 작업 보기로 바꾸고, 작업 이력 행을 누르면 그 작업을 연다. 새 요청·추가 지시는 새 작업을 연다. 작업 이력은 기본으로 펼치고 진행 중 표시를 둔다.
4. 브라우저 시험의 카드 선택자를 작업 이력·작업 보기 기준으로 바꾼다.

## 검증

- 단위(`tests/core/work-stages.test.mjs`): 진행 중 최신 사건의 단계와 실제 횟수, 검증 뒤 재조회, 끝난 검토 작업의 생략 단계, 멈춘 단계의 실패, 대기·CAD 진행 수·질문·Sync. 통과.
- 브라우저: 기존 시험을 작업 이력·작업 보기 기준으로 바꿔 통과(작업 문맥·복원·불명확 결과·원본 적용·확장·검토본·비교, 개입(`browser-intervention`), 동시 작업의 단계 횟수(`browser-concurrent-work`), 복구 후보, 작업 공간 조작, Live Sync, JIG 등 17개). 하니스 인자가 필요한 시험(native-*, remote-loop, browser-workspace·extensions·linked-hosts)은 선택자만 바꾸고 이번에 실행하지 않았다.
- 화면: 진행 중·완료 작업을 1440px·390px에서 확인했다.
- 남음: 실제 설치본에서 Rhino 요청 하나의 진행 화면 확인.
