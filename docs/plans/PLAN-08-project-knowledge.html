PLAN-08 — 프로젝트 지식 DB

2026-09-28 사용자 요청(메일·첨부·회의록을 모아 누가 무엇을 말했는지, 주요 쟁점, 진행 경과를 DB로 정리하고, 질문 답변·도면/모델 크리틱에 쓴다)의 단계 계획이다. 파악 내용과 선택 근거는 RESEARCH-06이 소유한다.

00 / 착수 조건

  • 제품 결정: PRD §4.4의 C-02 제안(첨삭)이 사용자에게 채택돼야 한다. 채택 전에는 이 계획의 구현을 시작하지 않는다.
  • RESEARCH-06 §9 결정: 입력 경로, AI 전송 기본값, 확정 대상, 표본 자료 프로젝트.
  • 동작 계약: 채택되면 K0 결과로 새 SPEC(가칭 SPEC-06 프로젝트 지식)을 먼저 쓴다. 출처·역할·상태 규칙은 SPEC-03.4를 확장하며 새 원칙을 따로 만들지 않는다.
  • 진행 중 작업과의 관계: 현재 우선순위(Rhino·CAD 연결 왕복과 Sync 성능)를 막지 않는다. 채택 뒤 티켓 번호를 마스터 PLAN에 등록한다. 아래 T-025~029는 제안 번호다.

01 / 단계

각 단계는 앞 단계만으로도 쓸모가 있어야 하며, 다음 단계는 앞 단계의 실제 사용 결과를 보고 조정한다.

K0 · 표본 자료 조사(SPIKE) — T-025 제안

  • 목적: 실제 프로젝트 자료 1세트(사본, .vide/knowledge-sample/)에서 형식 분포와 추출 가능성을 잰다. 사용자 원본 폴더를 직접 읽지 않고, 사용자가 고른 사본만 쓴다.
  • 내용: 형식별 개수·크기, 텍스트 레이어 유무(스캔 PDF 비율), 메일 형식(.eml/.msg), HWP 비중, 도면·모델의 문자 정보량. 한 소표본(메일 20통·PDF 5개·회의록 3건 내외)으로 AI 진술 추출을 시험하고 근거 인용 일치율, 사람 판단과의 차이를 기록한다.
  • 산출: docs/tdd/SPIKE-YYYY-MM-DD-project-knowledge.md, 형식별 파서 선택, SPEC-06 초안 입력.
  • 완료 기준: 형식별 “결정적 추출 가능/AI 판독 필요/제외” 판정표와 추출 시험 결과가 기록된다. 수치 없이 “가능하다”로 끝내지 않는다.

K1 · 자료함과 원문 검색 — T-026 제안

  • 변경 범위: 프로젝트별 Source·Excerpt 저장(SQLite 마이그레이션), 원본 보관(프로젝트 데이터 폴더, 해시 중복 제거), 형식별 텍스트 추출기(EML·PDF 텍스트·PPTX·DOCX·XLSX, K0 판정에 따라 HWP), FTS5 trigram 검색, 자료함 UI(끌어 놓기·목록·검색·원문 구간 열람), 폴더 수집을 쓰는 경우 제외 규칙과 수집 전 확인.
  • AI 사용: 없음.
  • 검증: 형식별 추출 단위 시험(쪽·슬라이드·메일 헤더 보존), 같은 파일 재수집 시 중복 없음, 한국어 부분 검색, 원문 구간 열람 브라우저 시험, 백업/복구에 자료함 포함, 비밀값 검사.
  • 완료 기준: 표본 자료를 넣고 “기둥 간격”, “회의실” 같은 검색으로 해당 메일·쪽·슬라이드를 찾아 원문을 연다.

K2 · 진술·쟁점 정리와 검토 큐 — T-027 제안

  • 변경 범위: Party·Subject·Statement·Issue·Milestone 저장. AI 추출 작업(구독 CLI, 도구 없이 JSON 반환, 근거 구간 ID·원문 인용 필수, 원문 대조 실패 시 폐기), 자료별 AI 전송 확인(FR-18), 진행률·중단·재개. 검토 큐(확정·수정·기각·별칭 합치기), 대체·모순 후보 표시. 프로젝트 정보 탭: 브리핑·쟁점 표·타임라인·주체 목록.
  • 검증: 가짜 인용·다른 자료 인용 거절, 확정 전 진술이 사실로 표시되지 않음, 대체 관계가 이전 진술을 지우지 않음, 전송 거부 자료가 AI 입력에 들어가지 않음, 중단 뒤 재개 시 중복 진술 없음.
  • 완료 기준: 표본 자료에서 주요 결정·요청·쟁점이 근거와 함께 목록화되고, 사용자가 확정한 항목만 “확정”으로 보인다. 품질 기준은 K0 결과로 SPEC-06에서 정한다.

K3 · 질의응답과 요청 문맥 제안 — T-028 제안

  • 변경 범위: AI 읽기 전용 MCP 도구(자료 검색, 진술·쟁점 조회, 대상별 근거, 타임라인). 채팅 답변의 인용 표시와 원문 열람. 모델 수정 요청 작성 시 관련 필수조건·결정을 칩으로 제안(자동 첨부 아님). Inspector에 객체의 연결 진술 표시와 진술↔객체 연결·끊김 표시.
  • 검증: 근거 없는 질문에 “자료에 없음”, 대체된 결정보다 최신 결정을 답함(날짜 표시), 도구가 다른 프로젝트 자료에 접근 불가, 기존 AI 작업 권한이 넓어지지 않음.
  • 완료 기준: 표본 프로젝트에 대해 사용자가 고른 질문 목록(예: “발주처가 3층에 대해 요청한 것”, “주차 대수 결정 경과”)에 인용 포함 답을 받고, 사용자가 답의 근거를 원문에서 확인한다.

K4 · 도면·모델 크리틱 — T-029 제안

  • 변경 범위: 확정된 요구·결정과 현재 모델·도면을 대조하는 크리틱 작업. 치수·면적은 기본 집계(FR-22)로 계산하고 AI가 숫자를 추측하지 않는다. 시각 판단은 뷰포트 캡처를 쓴다. 결과는 “AI 추정” 쟁점으로 객체에 연결하고, 사용자가 채택·기각한다. 법규 해석은 FR-21 범위로 넘긴다.
  • 검증: 요구와 어긋나게 만든 합성 모델에서 해당 객체·근거를 짚는지, 맞는 모델에서 거짓 지적을 얼마나 하는지 기록. 크리틱이 원본을 수정하지 않음.
  • 완료 기준: 대표 과업 수준의 모델 1건에서 채택할 만한 지적과 거짓 지적의 비율을 기록하고, 사용자가 계속 쓸지 판단한다.

K5 · (선택) 관계 그래프

K2~K4의 표·타임라인·인용으로 부족하다는 실제 사용 근거가 생길 때만 한 쟁점·한 주체 중심의 국소 그래프를 추가한다. 전체 그래프는 만들지 않는다.

02 / 기술 선택(초안)

  • 저장: 기존 SQLite에 테이블 추가, FTS5 trigram(한국어 부분 검색, 추가 의존성 없음). 그래프 DB·벡터 DB는 K0~K3 결과로 필요성이 확인될 때 검토한다.
  • 추출기: 표준 형식은 가벼운 파서 의존성을 추가하고, 스캔 PDF·이미지 판독은 AI 판독을 선택 기능으로 둔다. 새 의존성은 PLAN-03의 추적·검사 규칙을 따른다.
  • AI: 기존 구독 CLI 실행 경로. 정리 작업은 도구 없는 JSON 추출, 질의·크리틱은 읽기 전용 MCP 도구.
  • 저장 위치: 로컬 프로젝트 데이터. 웹 공유(ADR-015 계열)에는 기본 포함하지 않는다.

03 / 비목표

문서 관리·결재·버전 관리 시스템, 메일 클라이언트, 녹음 전사(STT), 법규 자동 판정, 전체 관계 그래프, 사용자 확정 없는 결정 자동 확정.
