# 원격 기기에서 작업 PC 열기

2026-09-28 사용자 지시: 아이패드에서 웹으로 프로젝트를 열고, 스케치와 채팅으로 요청하면 Rhino·CAD가 켜져 있는 작업 PC가 처리해 모델을 고치고, 바뀐 모델을 아이패드에서 다시 보는 흐름을 오늘 실제로 쓸 수 있게 만든다. 호스트 PC가 꺼져 있으면 목록에서 꺼짐으로 보여 막는다. 접속 방식은 사용자가 고른 **Cloudflare 임시 터널 + staging 공유 사이트**다(도메인·유료 자원 없음).

제품 범위 측면에서 원격 요청의 실행(권한 모드는 로컬과 같음)은 PRD의 공유 절(FR-18·19)을 넘어서는 흐름이다. PRD 반영은 후속 제안으로 남긴다.

## 구조

1. 작업 PC의 VIDE가 공식 cloudflared로 임시 주소(`*.trycloudflare.com`)를 열고, 공유 Worker에 페어링된 기기 키로 15초마다 상태를 보낸다(주소, 연결된 Rhino/CAD 문서 이름·Live 여부).
2. 기기 페어링은 공유 사이트에서 로그인한 소유자가 만든 10분짜리 일회용 코드를 PC의 설정 → 원격 접속에 입력해 한다.
3. 아이패드는 공유 사이트에 로그인해 "작업 PC" 목록을 본다. 45초 안에 상태를 보낸 PC만 켜짐이다. 열기를 누르면 Worker가 그 PC의 키로 서명한 60초짜리 일회용 토큰을 주고 PC 주소로 이동한다.
4. PC 서버는 토큰을 한 번만 받아 원격 세션(Secure·HttpOnly 쿠키, 터널이 켜져 있는 동안 최대 12시간)을 연다. 원격 세션은 프로젝트 작업(모델 보기, 스케치, 요청, Live Sync, 원본 반영)을 하고 앱 종료·계정·설정·확장 등록·원격 제어·AI 도구 엔드포인트는 쓰지 못한다.
5. 모바일 전송: 원격 응답은 gzip으로 보낸다. 요청 목록은 표시 메시를 빼고 보내며 화면에 띄울 결과만 받아 온다(로컬도 같은 효과).

## 검증

- Worker: 페어링 1회성, 임시 터널 주소만 허용, 소유자만 목록·열기, 토큰의 PC 측 검증과 재사용 거절, 끄면 꺼짐(`tests/sharing/hosts.mjs`, 로컬 workerd).
- PC 서버: 로그인 전 거절, 만료·재사용 토큰 거절, 로컬 쿠키로 원격 접근 불가, 원격 차단 경로 403, gzip, 끄면 원격 세션 종료(`tests/server/remote-http.test.mjs`).
- 실제 터널과 배포된 staging에서 에뮬레이션 iPad로 로그인 → 목록 → 열기 → 실제 크기 모델 표시 → 터치 스케치 → 요청 전송 → PC 수신 → 끄기(`tests/integration/remote-loop.mjs`, `VIDE_SHARING_TEST_ORIGIN` 필요). 결과는 [원격 루프 검수](../tdd/VERIFY-2026-09-28-remote-loop.md).

## 남은 일

- 실제 iPad(Safari·펜) 사용성과 실제 Rhino 문서의 원격 AI 수정 왕복 확인. 원격 요청은 로컬과 같은 실행 경로를 쓰지만 이 경로로 실측하지는 않았다.
- CAD(ZWCAD) 연결 문서의 AI 수정은 연결 도면 쪽에서 아직 지원하지 않는다(PLAN-07). 원격에서도 CAD는 보기·Sync만 된다.
- 임시 터널 주소는 켤 때마다 바뀌고 서비스 보장이 없다. 상시 운영은 도메인·정식 터널·Access 로그인 결정 뒤에 옮긴다.
- 큰 모델 전송(실측 23.5 MB)과 모바일 GPU 부담은 표시 데이터 바이너리화·병합으로 더 줄일 수 있다.
