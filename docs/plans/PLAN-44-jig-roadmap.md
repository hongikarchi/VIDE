# JIG 로드맵

2026-10-07에 사용자가 다음 세 묶음을 먼저 다루고 모두 상세히 계획하라고 했다.

- 법규 Q&A(cLAWde 연동)
- 도면 생성기와 역반영(C-08)
- 규모검토

규모검토에 대해서는 이렇게 말했다.

> 규모 검토의 경우, site modeling / 법규 검토 사항을 바탕으로 모델링(건축 가능 영역) + 매스 검토 / 건축 개요 작성(문서작업) 이런 식으로 기능을 쪼개서 개발하는게 좋아보이는데

이 문서는 세 작업 계획의 순서와 서로의 의존만 정한다. 각 티켓의 변경 범위, 검증, 완료 기준은 해당 PLAN이 소유한다.

| 묶음 | 동작 | 계획 | 티켓 |
|---|---|---|---|
| 규모검토: 사이트 모델 → 가능 영역·매스 → 건축개요 | [SPEC-12](../specs/SPEC-12-site-and-massing.md) | [PLAN-45](PLAN-45-site-massing-jigs.md) | T-203~T-214 |
| 법규 Q&A(cLAWde) | [SPEC-13](../specs/SPEC-13-legal-qa.md) | [PLAN-46](PLAN-46-legal-qa.md) | T-215~T-224 |
| 도면 생성기·역반영 | [SPEC-14](../specs/SPEC-14-drawing-generator.md) | [PLAN-47](PLAN-47-drawing-generator.md) | T-225~T-234 |

## 의존 관계

- 규모검토의 가능 영역·매스(T-209~T-212)는 법규 결과의 '규제 조건'(SPEC-13.8, T-220)을 입력으로 받는다.
  - 법규 쪽이 늦으면 같은 형식을 사람이 입력하는 칸으로 먼저 진행한다(SPEC-12의 '사람 입력 필요').
- 법규 Q&A의 모델 연결(T-220)은 사이트 모델의 출력(SPEC-12.3~12.6, T-207)을 읽는다.
- 도면 생성기는 앞의 두 묶음과 독립이다. 다만 xref 그래프(T-200)와 숨은 ZWCAD 견고성(H-ZWCAD-13)을 전제로 한다.
- 세 묶음 모두 숨은 호스트 실행, Link ID(ADR-030), 질문 카드(ADR-026), jig 만들기 경로(SPEC-07)를 공유한다.

## 사용자 결정이 필요한 것

세 PLAN의 「결정이 필요한 질문」 가운데 시작을 막는 것만 모았다. 나머지는 각 PLAN의 권장값으로 진행하고, 진행 중에 바꿀 수 있다. 2026-10-07 사용자가 1·2를 정했고, 3·4는 권장값으로 둔다.

1. **범위 채택 — 결정됨(2026-10-07).** 사용자가 C-05(규모검토), C-06·C-04(법규 Q&A·서비스 연동), C-08(도면 생성·역반영)을 모두 채택하고 "기존에 만들어놓은 코드와 repo들을 잘 활용할 것"을 함께 지시했다. PRD §4.4·§14.2에 반영했고 SPEC-12·SPEC-14의 채택 제안(R-01)을 닫았다. 재사용 원칙은 각 작업 계획의 「재사용할 기존 코드·저장소」(PLAN-45·PLAN-47)와 PLAN-46 T-215가 구체화한다. 출처 설명은 [RESEARCH-04](../research/RESEARCH-04-jig-past-experience.md) §1.1이다.
2. **cLAWde의 자리 — 결정됨(2026-10-07).** "새 저장소로 시작하는데, 옛 비공개 CLAWDE랑 규모검토 때 했던 법규 검토(논현동 규모검토 때), ARCO-FULL에서 만들었던것 까지 3개를 모두 종합해서 하는게 좋을 듯." 새 저장소로 시작하고 S-01·S-04·S-19를 종합한다. 종합 방법은 T-215(세 출처 종합 조사 → 새 저장소 설계 메모와 재사용 지도)다. 실행 기반(Cloudflare Workers + D1, 계정 사이트와 같은 계정, VIDE 계정으로 받은 짧은 토큰)은 권장값이며 T-215 결과를 볼 때 바꿀 수 있다. 실제 저장소가 생기기 전에는 VIDE가 가짜 서버로 개발한다.
3. **공공 데이터 수집의 자리(OQ-16) — 권장값.** 지금은 VIDE 공식 라이브러리에 두고, 응답 형식을 외부 서비스 계약에 맞춰 나중에 Site Modeling 서비스로 바꿔 끼울 수 있게 한다(SPEC-12 R-02는 열려 있다).
4. **도면의 첫 대상 — 권장값.** Rhino 레이아웃과 2D 요소부터 시작한다. Make2D(평면·입면·단면 투영)는 T-231 실험 뒤에 정한다.

**시작 시점:** 사용자가 "계획 검토 먼저"라고 했다. 0단계를 포함한 모든 티켓은 사용자가 SPEC-12·13·14와 PLAN-45·46·47을 검토한 뒤 시작한다.
