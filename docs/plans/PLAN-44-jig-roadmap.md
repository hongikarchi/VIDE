# JIG 로드맵

2026-10-07에 사용자가 다음 세 묶음을 먼저 다루고 모두 상세히 계획하라고 했다.

- 법규 Q&A(cLAWde 연동)
- 도면 생성기와 역반영(C-08)
- 규모검토

규모검토에 대해서는 이렇게 말했다.

> 규모 검토의 경우, site modeling / 법규 검토 사항을 바탕으로 모델링(건축 가능 영역) + 매스 검토 / 건축 개요 작성(문서작업) 이런 식으로 기능을 쪼개서 개발하는게 좋아보이는데

이 문서는 세 작업 계획의 순서와 서로의 의존만 정한다. 각 티켓의 변경 범위, 검증, 완료 기준은 해당 PLAN이 소유한다.

| 묶음 | 동작 | 계획 | 티켓 |
|---|---|---|---|
| 규모검토: 사이트 모델 → 가능 영역·매스 → 건축개요 | [SPEC-12](../specs/SPEC-12-site-and-massing.md) | [PLAN-45](PLAN-45-site-massing-jigs.md) | T-203~T-214 |
| 법규 Q&A(cLAWde) | [SPEC-13](../specs/SPEC-13-legal-qa.md) | [PLAN-46](PLAN-46-legal-qa.md) | T-215~T-224 |
| 도면 생성기·역반영 | [SPEC-14](../specs/SPEC-14-drawing-generator.md) | [PLAN-47](PLAN-47-drawing-generator.md) | T-225~T-234 |

## 의존 관계

- 규모검토의 가능 영역·매스(T-209~T-212)는 법규 결과의 '규제 조건'(SPEC-13.8, T-220)을 입력으로 받는다.
  - 법규 쪽이 늦으면 같은 형식을 사람이 입력하는 칸으로 먼저 진행한다(SPEC-12의 '사람 입력 필요').
- 법규 Q&A의 모델 연결(T-220)은 사이트 모델의 출력(SPEC-12.3~12.6, T-207)을 읽는다.
- 도면 생성기는 앞의 두 묶음과 독립이다. 다만 xref 그래프(T-200)와 숨은 ZWCAD 견고성(H-ZWCAD-13)을 전제로 한다.
- 세 묶음 모두 숨은 호스트 실행, Link ID(ADR-030), 질문 카드(ADR-026), jig 만들기 경로(SPEC-07)를 공유한다.

같은 단계 안의 세 묶음은 서로 다른 파일을 다루므로 worktree 작업자가 병렬로 맡는다(PLAN-43의 방식).

## 사용자 결정이 필요한 것

세 PLAN의 「결정이 필요한 질문」 가운데 시작을 막는 것만 모았다. 나머지는 각 PLAN의 권장값으로 진행하고, 진행 중에 바꿀 수 있다.

1. **범위 채택.** PRD 후보 C-04(외부 서비스 연동), C-05(규모검토), C-06(법규 Q&A), C-08(도면 역반영)을 범위에 넣는가. 넣으면 1단계 이후가 열린다. 첨삭 제안은 SPEC-12, SPEC-13, SPEC-14의 R-01에 있다.
2. **cLAWde의 자리.** 별도 저장소를 둔다. 옛 비공개 CLAWDE를 이어 쓸지 새로 시작할지는 T-215 결과로 정한다. Cloudflare Workers와 D1을 쓰고, 계정 사이트와 같은 계정에 둔다. 인증은 VIDE 계정으로 받은 짧은 토큰이다. 실제 저장소가 생기기 전에는 VIDE가 가짜 서버로 개발한다.
3. **공공 데이터 수집의 자리(OQ-16).** 지금은 VIDE 공식 라이브러리에 두고, 응답 형식을 외부 서비스 계약에 맞춰 나중에 Site Modeling 서비스로 바꿔 끼울 수 있게 한다.
4. **도면의 첫 대상.** Rhino 레이아웃과 2D 요소부터 시작한다. Make2D(평면·입면·단면 투영)는 T-231 실험 뒤에 정한다.
