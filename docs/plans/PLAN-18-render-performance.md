# 큰 모델 표시·Sync 성능

2026-09-29 사용자 요청("렌더도 개선"). 무거운 모델을 돌려 볼 때와 Sync할 때의 속도를 올린다. 측정은 [SPIKE-2026-09-29-render-perf](../tdd/SPIKE-2026-09-29-render-perf.md).

## 1단계 — 그리기 묶음 (완료)

- `src/ui/viewport.ts`: 객체별 메시는 선택·숨김·색·객체 찾기(raycast)의 기준으로 두고, 일반 면·모서리·선은 공간 칸(250 m)별 최대 400개씩 합친 묶음으로 그린다(정점 색, 칸 원점 기준 좌표로 측량 좌표 정밀도 유지). 묶인 객체는 찾기 전용 레이어로 옮긴다. 선택이 바뀌면 관련 묶음만 다시 만들고, 표시 방식·숨김·Live 갱신 때는 전체를 다시 묶는다. 출력 미리보기·선택·숨김·해치·문자는 따로 그린다.
- 결과: 객체 18,000개에서 그리기 호출 27,001 → 74, 프레임 83 ms → 9.7 ms.
- 검증: `tests/integration/browser-batching.mjs`(1,800개가 8번 호출, 측량 좌표에서 클릭 선택, 선택 강조는 따로, 숨기면 삼각형 감소), 기존 화면 시험 16개 통과.

## 2단계 — 이진 전송·저장 (다음)

- Sync 결과의 좌표·인덱스를 JSON 숫자 대신 이진(Float32/Uint32)으로 저장·전송하고, 해석은 백그라운드 작업자에서 한다. 꺼진 PC용 보기 사본(사이트 업로드)도 같은 형식으로 압축한다.
- 완료 기준: 18,000개 모델의 전송 크기·열기 시간 절반 이하, 기존 결과 읽기 호환.

## 3단계 — 호스트 Sync 구간 측정

- 사용자 모델 사본으로 Rhino 메시 생성·페이지 읽기·저장 구간을 나눠 재고, 느린 구간만 고친다.

## 남은 것

- 매우 큰 블록의 인스턴싱(같은 정의 반복을 한 번에 그리기), 먼 객체 단순화(LOD), WebGPU 선택지.
