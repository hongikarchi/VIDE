# 판정 계층의 실효성 평가 계획

## 1. 목적과 현재 결정

기존 구독 AI 실행보다 사용자 체감 지연을 줄이면서 작업 품질을 유지할 수 있는지 확인한다. Jev 도입이나 한국어 인코더 학습을 확정한 계획이 아니다. 제품 기준은 PRD FR-08·FR-18, 실행·전송 범위는 SPEC-02, 현재 구조는 ARCH-01을 따른다. 2026-09-25 사용자 구현 지시에 따라 로컬 평가 도구부터 구현한다. 외부 호출과 제품 라우팅 채택은 아래 실험 조건을 따른다.

[RESEARCH-02](../research/RESEARCH-02-decision-layer.md)의 타입 있는 판정·대체 경로·한국어 검증 필요성은 채택한다. 서로 다른 과제의 인코더 F1과 Jev 점수를 직접 비교해 기본 모델을 고르는 결론은 채택하지 않는다. 커뮤니티 사례와 벤더 벤치마크는 후보 선정의 단서이며 VIDE 실측이 아니다. 실행 로그는 표본 자료이지 난이도나 올바른 행동의 정답이 아니다. 별도 학습·런타임·서버 추가는 이득을 확인한 뒤 결정한다.

## 2. 범위와 선행 조건

첫 실험은 요청의 effort **추천** 하나로 제한한다. 사용자 모델·effort 선택은 항상 우선하며, 실험 추천은 실제 요청에 적용하지 않는다. 권한·문서 선택·수치/단위 검증·원본 적용·재실행 안전성은 기존 코드가 계속 소유한다. 분류 결과로 필수 질문이나 안전 검사를 생략하지 않는다.

PLAN-02 L1~L6의 남은 제품 검증을 이 연구로 대체하지 않는다. 합성 평가셋·규칙 기준선 준비는 독립 가능하다. 실제 제품 경로 비교는 재현 가능한 성공/실패 기준선과 실행 로그가 확보된 범위에서만 한다. 외부 Jev 시험은 사용 가능한 접근 수단, 비용 상한, 합성 입력의 전송 범위, 보관/학습 정책을 확인한 뒤 시작한다. 실제 사용자 자료 전송은 별도 범위 확인 전 수행하지 않는다.

## 3. 후보와 실험 순서

| 단계 | 작업 | 산출물·종료 기준 |
|---|---|---|
| J1 | 기존 effort 경로의 품질·전체 지연 측정, 합성 한국어 CAD 요청 120건 작성 | 단순 수정·보존/부정·다중 문서·모호한 목표·긴 문맥·적대 문구를 각 20건. SPEC 근거와 기대 행동/허용 추천을 기록 |
| J2 | 60건 개발/60건 고정 평가로 분리, 중복·의미상 변형의 교차 유입 방지 | 판정 불가 항목은 보류 정답으로 남김. LLM 자동 생성 라벨을 그대로 정답으로 사용하지 않음 |
| J3 | 기존 경로와 결정적 코드 규칙 비교 | 핀/대상 수 등 이미 가진 정보 사용. 추천 실패·시간 초과는 기존 경로 유지 |
| J4 | Jev를 동일 입력의 비적용 비교로 실행 | 호출마다 모델 버전·지연·결과·오류·과금 단위 기록. 고정 평가 60건 1회와 20건 3회 반복: 최대 120호출, 자동 무한 재시도 금지 |
| J5 | 품질·지연·비용·운영 부담 비교 | 채택/미채택 ADR과 SPIKE 증거. 이득 없으면 기존 실행 유지 |

Jev와 별도 소형 구독 모델의 분류 호출은 모두 추가 왕복 비용을 포함한다. 소형 모델 후보는 현재 계정에서 지원되는 것이 확인될 때만 같은 상한으로 비교한다. 한국어 인코더는 규칙의 반복적인 오분류와 충분한 라벨 자료가 확인된 경우 후속 후보로 추가하며 이번에 학습부터 시작하지 않는다. 평가 품질이 불명확하면 데이터 보완을 먼저 하고 모델 수를 늘리지 않는다.

## 4. 측정과 선택 기준

추천 일치율뿐 아니라 위험한 낮은 effort 추천, 보류율, 반복 응답 변화, 실패/시간 초과율, 실제 과업 성공률, 전체 처리 시간 p50/p95와 추가 호출 지연을 기록한다. 구독 사용량을 확인할 수 없으면 비용 0으로 환산하지 않고 호출·시간·확인 가능한 사용량을 따로 기록한다. 신뢰도는 정확도와 같지 않으며 임계값은 개발셋에서 정한 뒤 평가셋에서 바꾸지 않는다.

진입 기준은 보존 조건·권한·대상 안전 실패 0건, 고정 평가의 과업 실패가 기준선보다 늘지 않음, 전체 p95 지연 10% 이상 감소를 목표로 한다. 표본이 작거나 측정 변동이 이득보다 크면 통과로 단정하지 않는다. 10%는 실험의 실용적 선택 기준이며 제품 성능 약속이 아니다. 외부 장애 시 기존 경로로 복귀하는 비용까지 포함한다. 호출을 추가하면서 기존 작업을 줄이지 못하면 빠른 단일 응답만으로 채택하지 않는다.

## 5. 채택될 때의 구현 순서

1. SPIKE에 실제 입력 범위·측정 조건·원시 결과 위치·한계를 남기고 ADR로 채택 여부를 결정한다.
2. 동작/실패/사용자 우선권은 SPEC-02, 최소 결과 타입과 설정·버전·타임아웃은 ARCH-01에 먼저 반영한다. Choice/Score/Noul 전체를 복제하는 프레임워크는 만들지 않는다.
3. 추천 하나의 어댑터와 기본 꺼짐 설정, 실패 시 기존 실행 유지, 공급자 전송 고지를 구현한다. Jev Score는 가중 점수로 소수가 가능하므로 정수라고 가정하지 않는다.
4. 외부 키를 제품에 번들하지 않는다. 서비스 중계가 필요하다고 결정된 경우 기존 Cloudflare 구성을 우선 검토하고 별도 플랫폼을 미리 추가하지 않는다.
5. 계약/타임아웃/429·인증 실패/잘못된 응답/비활성화 회귀와 제한된 실사용 비교 후 확대한다. 자동 모델 교체나 문맥 삭제는 이 첫 실험의 완료 범위가 아니다.
