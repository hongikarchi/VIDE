# 판정 계층의 실효성 평가 계획

## 1. 목적과 현재 결정

기존 구독 AI 실행보다 사용자 체감 지연을 줄이면서 작업 품질을 유지할 수 있는지 확인한다. Jev 도입이나 한국어 인코더 학습을 확정한 계획이 아니다. 제품 기준은 PRD FR-08·FR-18, 실행·전송 범위는 SPEC-02, 현재 구조는 ARCH-01을 따른다. 2026-09-25 사용자 구현 지시에 따라 로컬 평가 도구부터 구현한다. 외부 호출과 제품 라우팅 채택은 아래 실험 조건을 따른다.

[RESEARCH-02](../research/RESEARCH-02-decision-layer.md)의 타입 있는 판정·대체 경로·한국어 검증 필요성은 채택한다. 서로 다른 과제의 인코더 F1과 Jev 점수를 직접 비교해 기본 모델을 고르는 결론은 채택하지 않는다. 커뮤니티 사례와 벤더 벤치마크는 후보 선정의 단서이며 VIDE 실측이 아니다. 실행 로그는 표본 자료이지 난이도나 올바른 행동의 정답이 아니다. 별도 학습·런타임·서버 추가는 이득을 확인한 뒤 결정한다.

## 2. 범위와 선행 조건

첫 실험은 요청의 effort **추천** 하나로 제한한다. 사용자 모델·effort 선택은 항상 우선하며, 실험 추천은 실제 요청에 적용하지 않는다. 권한·문서 선택·수치/단위 검증·원본 적용·재실행 안전성은 기존 코드가 계속 소유한다. 분류 결과로 필수 질문이나 안전 검사를 생략하지 않는다.

PLAN-02 L1~L6의 남은 제품 검증을 이 연구로 대체하지 않는다. 합성 평가셋·규칙 기준선 준비는 독립 가능하다. 실제 제품 경로 비교는 재현 가능한 성공/실패 기준선과 실행 로그가 확보된 범위에서만 한다. 외부 Jev 시험은 사용 가능한 접근 수단, 비용 상한, 합성 입력의 전송 범위, 보관/학습 정책을 확인한 뒤 시작한다. 실제 사용자 자료 전송은 별도 범위 확인 전 수행하지 않는다.

## 3. 후보와 실험 순서

| 단계 | 작업 | 산출물·종료 기준 |
|---|---|---|
| J1 | 기존 effort 경로의 품질·전체 지연 측정, 합성 한국어 CAD 요청 120건 작성 | 단순 수정·보존/부정·다중 문서·모호한 목표·긴 문맥·적대 문구를 각 20건. SPEC 근거와 기대 행동/허용 추천을 기록 |
| J2 | 60건 개발/60건 고정 평가로 분리, 중복·의미상 변형의 교차 유입 방지 | 판정 불가 항목은 보류 정답으로 남김. LLM 자동 생성 라벨을 그대로 정답으로 사용하지 않음 |
| J3 | 기존 경로와 결정적 코드 규칙 비교 | 핀/대상 수 등 이미 가진 정보 사용. 추천 실패·시간 초과는 기존 경로 유지 |
| J4 | Jev를 동일 입력의 비적용 비교로 실행 | 호출마다 모델 버전·지연·결과·오류·과금 단위 기록. 고정 평가 60건 1회와 20건 3회 반복: 최대 120호출, 자동 무한 재시도 금지 |
| J5 | 품질·지연·비용·운영 부담 비교 | 채택/미채택 ADR과 SPIKE 증거. 이득 없으면 기존 실행 유지 |

Jev와 별도 소형 구독 모델의 분류 호출은 모두 추가 왕복 비용을 포함한다. 소형 모델 후보는 현재 계정에서 지원되는 것이 확인될 때만 같은 상한으로 비교한다. 한국어 인코더는 규칙의 반복적인 오분류와 충분한 라벨 자료가 확인된 경우 후속 후보로 추가하며 이번에 학습부터 시작하지 않는다. 평가 품질이 불명확하면 데이터 보완을 먼저 하고 모델 수를 늘리지 않는다.

## 4. 측정과 선택 기준

추천 일치율뿐 아니라 위험한 낮은 effort 추천, 보류율, 반복 응답 변화, 실패/시간 초과율, 실제 과업 성공률, 전체 처리 시간 p50/p95와 추가 호출 지연을 기록한다. 구독 사용량을 확인할 수 없으면 비용 0으로 환산하지 않고 호출·시간·확인 가능한 사용량을 따로 기록한다. 신뢰도는 정확도와 같지 않으며 임계값은 개발셋에서 정한 뒤 평가셋에서 바꾸지 않는다.

진입 기준은 보존 조건·권한·대상 안전 실패 0건, 고정 평가의 과업 실패가 기준선보다 늘지 않음, 전체 p95 지연 10% 이상 감소를 목표로 한다. 표본이 작거나 측정 변동이 이득보다 크면 통과로 단정하지 않는다. 10%는 실험의 실용적 선택 기준이며 제품 성능 약속이 아니다. 외부 장애 시 기존 경로로 복귀하는 비용까지 포함한다. 호출을 추가하면서 기존 작업을 줄이지 못하면 빠른 단일 응답만으로 채택하지 않는다.

## 5. 채택될 때의 구현 순서

1. SPIKE에 실제 입력 범위·측정 조건·원시 결과 위치·한계를 남기고 ADR로 채택 여부를 결정한다.
2. 동작/실패/사용자 우선권은 SPEC-02, 최소 결과 타입과 설정·버전·타임아웃은 ARCH-01에 먼저 반영한다. Choice/Score/Noul 전체를 복제하는 프레임워크는 만들지 않는다.
3. 추천 하나의 어댑터와 기본 꺼짐 설정, 실패 시 기존 실행 유지, 공급자 전송 고지를 구현한다. Jev Score는 가중 점수로 소수가 가능하므로 정수라고 가정하지 않는다.
4. 외부 키를 제품에 번들하지 않는다. 서비스 중계가 필요하다고 결정된 경우 기존 Cloudflare 구성을 우선 검토하고 별도 플랫폼을 미리 추가하지 않는다.
5. 계약/타임아웃/429·인증 실패/잘못된 응답/비활성화 회귀와 제한된 실사용 비교 후 확대한다. 자동 모델 교체나 문맥 삭제는 이 첫 실험의 완료 범위가 아니다.

## 6. 공식 근거와 미확인 항목

2026-09-25 확인: [TypeSafe 소개](https://docs.typesafe.ai/introduction), [API](https://docs.typesafe.ai/api), [Jev 모델 한계](https://docs.typesafe.ai/model-jaggedness/jev-1.13). 타입 있는 결과·응답 모델 버전은 활용 후보지만 한국어 CAD 정확도나 보안 승인을 보장하지 않는다. 실제 접근 가능 모델·가격·데이터 보관/학습 조건은 호출 직전 다시 확인한다. 이번 계획에서 연구의 법률 단정이나 벤더 간 수치 우열을 검증된 사실로 확정하지 않는다.

## 현재 구현과 다음 실험

오프라인 추천·입력 분리 검사·실측 결과 비교 집계기를 구현했다([SPIKE](../tdd/SPIKE-2026-09-25-decision-layer.md)). 120개 서로 다른 요청 문장을 준비했지만 독립 라벨 검수·실제 긴 문맥·과업 기준선이 부족해 최종 평가셋 품질 기준은 아직 미충족이다. 집계기 합성 시험을 Jev 성능으로 보고하지 않는다. 다음은 독립 과업과 검수된 라벨로 평가셋을 보완하고, 실제 과업 기준선·접근/예산이 확보된 외부 후보를 비교하는 것이다. 제품 자동 라우팅 채택은 하지 않았다.

외부 접근 조건: 2026-09-25 공식 사이트의 신규 가입 중단 공지를 확인했고, 사용자가 기존 계정이 없으므로 가입 재개까지 보류한다고 결정했다. 접근 설정·Jev 외부 호출(J4)은 재개 전 수행하지 않는다. 대기 명단 신청·결제·자동 재시도도 하지 않는다. 가입이 재개되면 공식 콘솔에서 가입·API 접근·데이터 취급 조건·시험 예산을 확인한 후 J4를 진행한다. 로컬 평가셋·기준선 준비와 PLAN-06은 독립적으로 진행할 수 있다.

## 7. 2026-09-29 제품 이식 계획(계획만)

2026-09-29 사용자가 Jev API 키를 발급받아 외부 접근 보류(§현재 구현과 다음 실험의 외부 접근 조건)가 해소됐다. 사용자 지시에 따라 **개발 도구(T-032)를 먼저 쓰고, 제품 쪽은 계획만 세운 뒤 더 조사한 다음 이식**한다. 공식 문서 대조와 용도별 판단은 [RESEARCH-02 2026-09-29 보강](../research/RESEARCH-02-decision-layer.md)이 소유한다. 아래는 §5 구현 순서를 두 용도에 적용한 계획이며 구현 착수가 아니다.

### 7.1 대상 용도

| 용도 | 입력(state) | 질문 | 결과 사용 | 쓰지 않는 곳 |
|---|---|---|---|---|
| 모델·effort 추천 | 요청 문장, 첨부 종류·수, 대상 호스트, 모드 | Choice: 작업 유형(조회·단순 수정·복합 생성·해석/최적화), Score: 복잡도 | 계정의 모델·effort 선택 추천. 신뢰도가 낮으면 사용자 기본값 | 계정·사용량 한도 기반 전환(수치 판단, 코드가 담당) |
| 수정 대상 찾기(sync jig 포함) | 요청 문장 + 레이어·블록·그룹 이름, 객체 이름·속성 텍스트 요약(결정적 공간 필터 뒤 후보만) | Choice: 레이어/그룹 → 객체 후보, 후보별 Noul 검증 | [RESEARCH-07](../research/RESEARCH-07-request-processing.md) 의도 카드의 “대상” 제안. 사용자·결정적 조회가 확정 | 대상 확정, 쓰기 권한, 기하·치수 판정 |

### 7.2 순서

1. **T-032 실측에서 배우기:** 개발 도구의 한국어·혼합 텍스트 신뢰도 분포, 지연, 토큰, 실패 유형을 기록해 제품 임계값의 출발점으로 쓴다. 첫 실측([SPIKE](../tdd/SPIKE-2026-09-29-jev-locate.md))에서 한국어 요청도 영어 대상 이름에 잘 매칭됐고(정답 5위 안 100%, 단어 일치 기준선 14%), **입력 요약의 품질이 정확도를 가장 크게 좌우**했다. 제품 대상 찾기에서도 레이어·객체 이름·속성 요약 설계를 먼저 한다.
2. **평가셋:** §3·§4의 기준(검수된 라벨, 과업 기준선)에 두 용도의 사례를 추가한다. 모델 추천은 실제 요청과 사후 결과(성공·실패·재시도·소요 시간), 대상 찾기는 합성 도면·모델 사본의 요청 ↔ 정답 객체를 쓴다. 사용자 원본은 쓰지 않는다.
3. **섀도 모드:** 실제 선택·대상은 기존 경로대로 두고 Jev 추천만 기록한다. 추천과 실제의 차이, 추천대로였다면의 예상 결과를 비교한다(§4 측정 기준).
4. **제안 모드:** 기준을 넘으면 기본 꺼짐 설정으로 “추천 + 사용자 확인”을 연다. 모델 추천은 선택 칸의 추천 표시, 대상 찾기는 의도 카드의 대상 후보다. 실패·시간 초과·저신뢰는 기존 경로로 넘긴다.
5. **기본값 검토:** 실사용 비교 뒤에만 기본값 적용을 사용자와 정한다.

### 7.3 이식 전에 정할 것

- **키 중계:** 배포물에 키를 넣지 않는다(§5-4). 기존 Cloudflare 구성의 중계와 호출량 상한을 설계한다.
- **전송 고지·동의·끄기:** 요청 문장과 객체 이름이 TypeSafe로 전송된다(FR-18). 국외 이전 동의, 끄기 옵션, 끈 상태의 동작을 SPEC-02에 쓴다.
- **자식 프로세스 환경:** 제품이 키를 서버 환경에 둘 경우 CLI·호스트 자식 프로세스에서 `TYPESAFE_*`를 지운다(RESEARCH-02 보안 항목).
- **버전 고정:** `jev-1.13.0` 고정, `jev-latest` 변경 추적.
- **벤더 중립:** 추천 결과 타입은 Choice/Score/Noul 최소 형태로 두어 코드 규칙·다른 모델로 바꿀 수 있게 한다(§5-2).
