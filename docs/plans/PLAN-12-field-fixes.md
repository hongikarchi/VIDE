# 실사용 오류 수정·외부 접속 안정화·스케치·설정 정리

2026-09-29 사용자 지시(설치된 PC 프로그램과 아이패드에서 쓴 결과)의 작업 묶음이다. 동작 의미는 [SPEC-01](../specs/SPEC-01-project-input-sync.md) §5, 기술 계약은 [ARCH-01](../architecture/ARCH-01-system.md) §4 "사본 결과를 원본에 적용"과 §6 "계정 웹사이트와 작업 PC"가 소유한다.

## 1. 요청 오류 (최우선)

설치본 DB의 실패 4건은 모두 수정 전 문서 사본을 만드는 단계의 과한 검사에서 났다: `IMPORT_LIMIT`, `Readback count mismatch`, `Readback geometry mismatch`, `CAPTURE_FAILED`. 사용자 문서의 사본(`.vide/probe`, 517개 객체)으로 같은 요청을 재현해 아래 원인을 차례로 확인했다.

- Sync 뒤 Rhino의 revision이 재질·속성 이벤트로도 올라가 `SOURCE_CHANGED`로 막혔다 → 요청 시점 문서를 새로 캡처해 편집한다.
- 캡처 사본의 전체 readback 동일성 검사(개수·형상) → 사본이 열리는지만 본다.
- 원본 적용이 문서 전체를 비교해 재질·블록·주석·그룹이 있는 실제 문서를 거부했다 → 작업 사본이 기록한 변경 목록(추가·수정·삭제)만 적용하고, 대상 객체만 캡처 시 지문과 비교한다.
- 바뀐 것이 없는 응답(질문)이 적용 단계에서 실패로 끝났다 → 적용 없이 성공.
- 생성 코드 검사가 `GetType().Name`을 막아 재시도가 늘었다 → 형식 이름 읽기만 허용.
- 치수가 부족하면 AI가 멈추고 되물었다 → 규격·관례값이 있으면 쓰고 가정을 밝힌다.

완료 기준: 사용자 문서 사본에서 "고정한 객체와 같은 레이어의 중심선마다 H형강 Brep"(34개 생성·적용)과 "curve는 다 hide"(326개)가 실제 구독 AI·Rhino로 성공한다.

## 2. 외부(아이패드) 접속

- 원격 열기는 계정 사이트의 고정 주소 `/pc/<hostId>/`로 하고 Worker가 그 PC의 현재 터널로 중계한다(ARCH-01 §6). 터널이 다시 시작돼도 같은 주소가 이어진다.
- 작업 화면은 상대 주소만 쓴다. 원격에서 세션이 끝나면 목록에서 다시 여는 링크를 보인다.
- 사이트는 PWA로 아이패드 홈 화면에 추가할 수 있다. 네이티브 iPad 앱(App Store/TestFlight)은 macOS·Xcode·Apple 개발자 등록이 필요해 이 Windows PC에서 빌드할 수 없다. 필요해지면 같은 화면을 WKWebView로 감싸는 방식으로 별도 작업한다.

완료 기준: `tests/integration/remote-loop.mjs`(실제 staging·실제 터널·에뮬레이트 iPad)에서 `/pc/` 주소로 모델 표시·스케치·요청 왕복·터널 재시작 뒤 다시 열기가 통과한다.

## 3. 스케치 (SPEC-01 §5.2~5.4)

색상 견본 표시(CSP로 인라인 스타일이 막혀 모두 흰색이던 문제), Grease Pencil식 자동 배치와 "표면에 붙이기" 전환(S), 펜은 그리고 손가락은 화면 조작, 선 역할·좌표 입력 제거, 선택 도구로 바꾸면 그린 선을 자동 첨부.

## 4. 화면 정리

- 홈(모든 프로젝트) 버튼을 왼쪽 레일 맨 위로 옮긴다.
- 고정 토큰은 입력창과 같은 글자 배치의 배경층이 글자를 그려 칩이 글자와 어긋나지 않게 한다. 빈 입력창에서는 고정 칩을 오른쪽 위에 둔다.
- 모델 목록은 "기본 모델" 항목을 없애고 Claude(Opus 5.5·Fable 5.1·Sonnet 5·Haiku 4.5)와 Codex CLI 목록을 서비스별로 묶는다. 이전 요청의 CLI 기본값은 "(CLI 기본)"으로 표시한다.
- 설정은 계정·원격 접속 / AI / 연결 프로그램 / PC 프로그램 / 상태·오류 탭으로 나눈다.
- Rhino 패널(좁은 폭): 빈 머리 띠 제거, 알림을 위로, 모드·모델 줄 바꿈.

## 5. 내일 실무 준비 — CAD 반영과 Rhino↔CAD

사용자의 다음 날 작업(철골보 중심선·전체 구조 곡선·단면 형식 라벨과 Brep·CAD 도면 반영·Rhino와 CAD 불일치 확인과 동기화)에 필요한 부족분을 먼저 채운다.

- 열린 ZWCAD 도면의 AI 조회·직접 수정(`VIDEAIRUN` 명령 단위), 연결 프로그램의 ZWCAD 설치와 시작 시 자동 로드·패널.
- Rhino+CAD 연계 요청에서 두 파일이 같은 원점을 쓴다고 가정하던 지시를 없앴다. 연계 대상 창은 "원점·축이 다르거나 모름(AI가 대응 요소로 맞춤, 기본)"과 "같음" 중 고르며, 앞의 경우 AI가 이동·회전·축척·잔차를 먼저 밝힌다. 열린 문서의 Sync도 연계 대상이 된다(Rhino는 실행 때 사본, CAD는 직접).
- Rhino 조회 행에 레이어와 곡선의 시작·끝점·길이·직선 여부를 더했다. 합성 시험(원점 차 125,000·48,000·3,200mm, 0.8mm 오차, Rhino에만 있는 보)에서 연계 Plan mode 요청이 이동량·0.8mm 차이·누락 보를 찾았다(`tests/integration/linked-open-compare.mjs`, 약 1분).
- 남은 것: 실제 ZWCAD 창에서 UNDO 한 번 되돌리기 확인, 정렬·차이·동기화를 반복 작업으로 만드는 sync jig(다음 작업).

완료 기준: `tests/integration/zwcad-open-ai.mjs`(합성 도면, 실제 구독 AI)와 연결 프로그램 단위 시험 통과, 자동 로드 실험.

## 6. 마무리

`npm run verify` 해당 부분·표준 브라우저 시험·Rhino 정책 시험, staging 배포, 커밋·push, `npm run desktop:release -- 0.2.2`와 GitHub Releases 게시, 설치본 업데이트와 Rhino 플러그인 갱신 안내.
