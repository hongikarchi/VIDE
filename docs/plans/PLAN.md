# VIDE · PLAN (구현계획)

**이 파일의 현재 상태.** PRD 0.3 재구성(2026-09-17)에서 PRD §14에 섞여 있던 구현 순서와 기술 검수 과업을 옮겨 담은 초안이다. 가이드 §05 목차 가운데 §6·§7만 내용이 있고, 구조·Stack·데이터 계약·호스트 연결·설치·위험(§1~§5·§8·§9)은 SPEC-00-common과 첫 SPEC이 정해진 뒤에 쓴다. 이 문서가 `draft`인 동안 AI.md §8의 구현 착수 조건은 충족되지 않는다. 앱 기술·설치 도구 선택(구 PRD §0 요약표)은 §3 Stack에서 정한다.

## 6. 마일스톤·선행 조건·하위 task

### 6.1 순서 원칙 (구 PRD 0.2 §14.4에서 이관)

구현 순서는 한 호스트의 내부 alpha부터 시작할 수 있다. 구현 순서가 PRD §14의 첫 출시 범위를 조용히 축소하거나 전문 스킬을 첫 출시로 앞당기는 이유가 되어서는 안 된다.

확인 가능한 부분의 명세·목업·기술 실험은 먼저 진행할 수 있으나, 관련 지원 선언 전에 결정을 완료해야 한다(구 PRD §18에서 이관). 미결 항목과 결정 시점은 PRD §18 표가 소유한다.

### 6.2 정할 것

- 첫 호스트와 그 alpha의 판정 입력·관문·축소 조건: PRD §14.3의 이견 스레드(R-59)와 [ADR-001](../decisions/ADR-001-mvp-scope-rhino-zwcad.md)·[ADR-004](../decisions/ADR-004-view-strategy-host-viewport-and-own-view.md)·[ADR-006](../decisions/ADR-006-benchmark-tasks-and-test-users.md)·[ADR-007](../decisions/ADR-007-web-review-online-submission-in-mvp.md)의 축소 조건이 확정되면 그 결정을 인용해 실행 순서와 판정 시점에 반영한다. 판정 기준 자체는 PRD §14.3·§16.3이 소유한다.
- 하위 task(T-NNN)는 첫 SPEC 뒤에 가이드 §05 양식으로 쓴다.

## 7. 테스트 계획·실호스트 검수

### 7.1 기술 검수 과업 (구 PRD 0.2 §14.2에서 이관)

각 호스트에서 대상 읽기 → 제한된 네이티브 생성 또는 수정 → 실제 후보·상태 표시 → 사용자 조정 → 원본 반영 → 호스트 기본 도구로 재편집 → 저장·재열기의 흐름을 검수한다. 기하 생성과 사용자의 조건 판단을 별개로 확인한다.

검증 사례의 후보는 Rhino의 지원 곡선·솔리드, Revit의 지정 벽 유형, CAD의 선·폴리라인 등이다. 이는 **SPEC을 정하기 위한 시험 후보**이며 모두 지원 확정된 목록은 아니다. 전문 법규·구조·평면 자동화까지 구현해야 이 시험을 수행할 수 있는 구조는 피한다.

최소 두 호스트가 같은 프로젝트에 연결된 상황에서 대상 혼동이 없고, 한쪽의 끊김이나 변경이 다른 문서의 잘못된 쓰기로 이어지지 않는지 확인한다. 같은 호스트의 복수 문서·인스턴스 구분도 해당 지원 환경에서 확인한다. 이 두 호스트 시험의 목적을 ‘어댑터 계약 차이 확인’과 순차 연결·활성 전환 시험으로 재정의할지는 [ADR-009](../decisions/ADR-009-single-active-host-shared-record.md) 초안(PRD §14.1 스레드 R-57·R-69)에서 결정한다.

### 7.2 정할 것

- 위 과업은 API·계약 수준의 기술 검수다. 시간·대상 오인·재작업을 재는 기준 과업(가치 시험)은 [ADR-006](../decisions/ADR-006-benchmark-tasks-and-test-users.md) 확정 뒤 PRD §16.3(무엇을 재는가)과 이 절(측정 절차)로 나눠 적는다.
- 단위·계약·UI·설치 시험과 TDD 대상은 첫 SPEC과 §2~§5가 정해진 뒤 쓴다. `docs/tdd/TEST_PLAN.md`는 이 절이 커졌을 때만 분리한다(AI.md §2).
- 수치 목표(PRD OQ-06)의 측정은 실제 장비·데이터의 기준 작업으로 한다(구 PRD §16.3에서 이관). 확정 시점은 OQ-06 행이, 측정 절차는 이 절이 소유한다.

### 7.3 확장 검증 과업 (구 PRD §14.2·§8.6에서 이관)

작은 검증용 확장 하나로 등록, 필요한 입력·권한 전달, 실행, 진행·개입, 결과 보존, 실패, 비활성화를 확인한다. 예시는 선택 객체 속성 요약이나 허용된 기본 객체 생성이다.

시험용 확장은 플랫폼의 확장 접점을 확인하는 용도이며 완성된 법규·구조 스킬을 요구하지 않는다.

범위 결정 자체는 PRD §13의 FR-13 범위 태그와 AC-26이 소유한다. 이 과업을 후속으로 내릴지는 [ADR-008](../decisions/ADR-008-extension-deferred-first-skill-schedule.md) 초안에서 결정한다.

### 7.4 검수 기록 규칙 (구 PRD §15에서 이관)

실행 시에는 적용 AC의 통과·실패·미시험·해당 없음과 증거를 기록한다. 시험 결과는 장비·호스트·작업 유형·모델 규모·데이터 상태와 함께 기록한다. 모의 결과·정적 UI 시연·실제 호스트 시험을 구분한다.

AC별 시험 조작·증거 인정 규칙(구 PRD §15 AC 셀에서 이관):

- AC-29: 호스트에서 단위를 바꾸는 조작은 지원 범위 확인 뒤 사용한다.
- AC-30: 목업에서 버튼이 보이지 않는 것만으로 권한 검사를 통과 처리하지 않는다.

기록 양식은 `docs/tdd/VERIFY-YYYY-MM-DD-<scope>.md`(AI.md §2)를 따르고, 관련 AC와 호스트 검수일 때 H-*를 인용한다.
