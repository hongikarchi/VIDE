# VIDE · PLAN (구현계획)

**이 파일의 현재 상태.** PRD 0.3 재구성(2026-09-17)에서 PRD §14에 섞여 있던 구현 순서와 기술 검수 과업을 옮겨 담은 초안이며, PRD 0.6(2026-09-18)의 확정 범위에 맞추어 절 참조를 갱신했다. 가이드 §05 목차 가운데 §6·§7·§9(일부)만 내용이 있고, 구조·Stack·데이터 계약·호스트 연결·설치(§1~§5·§8)는 SPEC-00-common과 첫 SPEC이 정해진 뒤에 쓴다. 이 문서가 `draft`인 동안 AI.md §8의 구현 착수 조건은 충족되지 않는다. 앱 기술·설치 도구 선택(구 PRD §0 요약표)은 §3 Stack에서 정한다.

## 6. 마일스톤·선행 조건·하위 task

### 6.1 순서 원칙 (구 PRD 0.2 §14.4에서 이관)

구현 순서는 한 호스트의 내부 alpha부터 시작할 수 있다. 구현 순서가 PRD §14의 첫 출시 범위를 조용히 축소하거나 전문 스킬을 첫 출시로 앞당기는 이유가 되어서는 안 된다.

확인 가능한 부분의 명세·목업·기술 실험은 먼저 진행할 수 있으나, 관련 지원 선언 전에 결정을 완료해야 한다(구 PRD §18에서 이관). 미결 항목과 결정 시점은 PRD §18 표가 소유한다.

### 6.2 정할 것

- 첫 호스트와 그 alpha의 목표는 PRD §16.1·[ADR-012](../decisions/ADR-012-goal-two-baselines.md)(두 기준선 대비 개선)이며 판정 관문이 아니다. 미달은 자동 축소가 아니라 사용자의 재결정 시점이다. 판정 입력은 PRD §16.4의 대표 과업 ①([ADR-006](../decisions/ADR-006-benchmark-tasks-and-test-users.md)), 판정 절차와 시점은 이 절과 §9.2가 정한다. 판정 기준 자체(무엇이 참이어야 하는지)는 PRD §14.3·§16.1이 소유한다.
- 하위 task(T-NNN)는 첫 SPEC 뒤에 가이드 §05 양식으로 쓴다.

## 7. 테스트 계획·실호스트 검수

### 7.1 기술 검수 과업 (구 PRD 0.2 §14.2에서 이관)

각 호스트에서 대상 읽기 → 제한된 네이티브 생성 또는 수정 → 실제 후보·상태 표시 → 사용자 조정 → 원본 반영 → 호스트 기본 도구로 재편집 → 저장·재열기의 흐름을 검수한다. 기하 생성과 사용자의 조건 판단을 별개로 확인한다.

검증 사례의 후보는 Rhino의 지원 곡선·솔리드, ZWCAD의 선·폴리라인 등이다. 이는 **SPEC을 정하기 위한 시험 후보**이며 모두 지원 확정된 목록은 아니다. 전문 법규·구조·평면 자동화까지 구현해야 이 시험을 수행할 수 있는 구조는 피한다.

최소 두 호스트가 같은 프로젝트에 연결된 상황에서 대상 혼동이 없고, 한쪽의 끊김이나 변경이 다른 문서의 잘못된 쓰기로 이어지지 않는지 확인한다. 같은 호스트의 복수 문서·인스턴스 구분도 해당 지원 환경에서 확인한다. [ADR-009](../decisions/ADR-009-single-active-host-shared-record.md)가 복수 연결·호스트 간 연계·독립 작업의 병렬 실행을 확정했으므로(PRD §12.2·§14.1), 이 시험에는 한 작업 범위의 연계 요청과 독립 작업의 병렬 진행, 호스트별 부분 성공·실패의 구분이 포함된다(AC-25·32·33). 화면의 활성 호스트가 실행 대상을 대신하지 않는지도 확인한다.

### 7.2 정할 것

- 위 과업은 API·계약 수준의 기술 검수다. 시간·대상 오인·재작업을 재는 가치 시험의 과업은 PRD §16.4의 대표 검수 과업 세 가지([ADR-006](../decisions/ADR-006-benchmark-tasks-and-test-users.md))이며, 무엇을 재는가는 PRD §16.1·§16.3이, 측정 절차는 이 절이 소유한다. 세부 자료·판정·검증 인원·허용 오차는 OQ-14를 따른다.
- 단위·계약·UI·설치 시험과 TDD 대상은 첫 SPEC과 §2~§5가 정해진 뒤 쓴다. `docs/tdd/TEST_PLAN.md`는 이 절이 커졌을 때만 분리한다(AI.md §2).
- 웹 작업 공간 공유·의견(AC-19·28·35), 검토본 열람·비교(AC-36), 기본 조회·집계와 파일 내보내기(AC-34·20)의 검수 절차는 관련 SPEC이 정해진 뒤 이 절에 쓴다. §7.1·§7.3의 과업만으로 PRD §14.2의 첫 출시 범위를 검수했다고 보지 않는다.
- 수치 목표(PRD OQ-06)의 측정은 실제 장비·데이터의 기준 작업으로 한다(구 PRD §16.3에서 이관). 확정 시점은 OQ-06 행이, 측정 절차는 이 절이 소유한다.

### 7.3 확장 검증 과업 (구 PRD §14.2·§8.6에서 이관)

작은 검증용 확장 하나로 등록, 필요한 입력·권한 전달, 실행, 진행·개입, 결과 보존, 실패, 비활성화를 확인한다. 예시는 선택 객체 속성 요약이나 허용된 기본 객체 생성이다.

시험용 확장은 플랫폼의 확장 접점을 확인하는 용도이며 완성된 법규·구조 스킬을 요구하지 않는다.

범위 결정 자체는 PRD §13의 FR-13 범위 태그와 AC-26이 소유한다. [ADR-008](../decisions/ADR-008-extension-deferred-first-skill-schedule.md)이 작은 확장의 실제 등록·실행·비활성화를 첫 출시 범위로 확정했으므로 이 과업은 별도 필수 검수로 유지한다(PRD §14.2·§16.4). 시험 확장의 종류·실행 형태·입출력·권한은 OQ-07에 따라 SPEC·PLAN에서 정한다.

### 7.4 검수 기록 규칙 (구 PRD §15에서 이관)

실행 시에는 적용 AC의 통과·실패·미시험·해당 없음과 증거를 기록한다. 시험 결과는 장비·호스트·작업 유형·모델 규모·데이터 상태와 함께 기록한다. 모의 결과·정적 UI 시연·실제 호스트 시험을 구분한다.

AC별 시험 조작·증거 인정 규칙(구 PRD §15 AC 셀에서 이관):

- AC-29: 호스트에서 단위를 바꾸는 조작은 지원 범위 확인 뒤 사용한다.
- AC-30: 목업에서 버튼이 보이지 않는 것만으로 권한 검사를 통과 처리하지 않는다.

기록 양식은 `docs/tdd/VERIFY-YYYY-MM-DD-<scope>.md`(AI.md §2)를 따르고, 관련 AC와 호스트 검수일 때 H-*를 인용한다.

## 9. 미확인 위험·작은 실험·결정이 필요한 사항

이 절은 PRD가 소유하지 않는 기술 결정과 그 확인 실험을 모은다. 결정이 나면 ADR로 기록하고 해당 장(§2~§6)에 반영한다.

### 9.1 AI 실행 형태 (구 ADR-005 · OQ-12에서 이관)

제품 결정이 아니라 기술 결정이다(2026-09-17). PRD가 약속하는 것은 이미 FR과 §4.3에 있다 — 쓰기 승인, 전송 자료 목록, 중단·재개(FR-08·FR-11·FR-15·FR-18). [ADR-005](../decisions/ADR-005-ai-execution-path-pending-spike.md)는 superseded이며 그 후보와 확인 항목은 여기서 잇는다.

- 후보: 에이전트 SDK/CLI 내장 vs API 직접(자체 하네스).
- 확인할 필수 통제 3가지 — 후보별로 확인/불가/미확인과 증거를 기록한다:
  1. 쓰기 승인/거부 — 호스트 쓰기 도구 호출을 제품이 승인하거나 거부할 수 있는가.
  2. 전송 자료 목록 표시·제외 — 전송 전에 자료 목록을 보여 주고 뺄 수 있는가.
  3. 중단·재개 — 도구 호출 단위 중단과 실제 정지 관측, 앱 재시작 뒤 재개.
- 사용자가 언급한 'aside' 방식은 PLAN 작성 시 확인한다(무엇을 뜻하는지, 위 후보 중 어디에 속하는지).
- 실험 기록: `docs/tdd/SPIKE-<date>-ai-execution-path.md`, 코드 `tools/spikes/<date>-ai-execution-path/`(AI.md §2). 결정은 ADR로 남기고 §3 Stack과 §5에 반영한다.

### 9.2 alpha 판정 절차·시점

목표는 PRD §16.1·[ADR-012](../decisions/ADR-012-goal-two-baselines.md)(두 기준선 대비 개선)이며 판정 관문이 아니다. 미달은 자동 축소가 아니라 사용자의 재결정 시점이다. 이 절이 정할 것:

- 판정 시점: PRD §16.4의 대표 과업 ①([ADR-006](../decisions/ADR-006-benchmark-tasks-and-test-users.md))에서 두 기준선(수작업, 에이전트+MCP) 측정과 VIDE 측정을 언제 하는가.
- 판정 절차: 같은 조건(모델·장비·과업 정의)으로 총시간·대상 오인·재작업을 재고, 시험 미완료·실패·보완 가능을 구분해 기록한다(§7.2·§7.4). 측정 절차는 §7.2가 소유한다.
- 재결정 지점: 목표 미달 시 사용자가 범위·순서·노력 상한을 다시 정한다. 자동 축소 조건은 두지 않는다.
