# 결정 브리프 (`docs/briefs/`)

사용자가 그때그때 **보고 판단할 내용**(분석 결과, 보고, 결정할 항목)을 한 장짜리 HTML로 둔다. 아티팩트는 열기 번거로우므로 파일을 더블클릭해서 본다(2026-10-19 사용자 지시). 이 폴더는 AI.md §4 "저장소에는 MD만 둔다"의 **유일한 예외**이며, 여기 HTML은 생성물이 아니라 원본이다. 렌더러(`tools/docs`)는 이 폴더의 HTML을 건드리지 않는다.

결정의 **정본은 PRD·ADR·SPEC·PLAN**이다. 브리프는 결정을 받기 위한 안내문이고, 답이 나오면 정본에 반영한다.

## 양식 원칙 — 쉽고, 짧고, 보자마자 결정

1. **한 문서 = 한 번에 결정할 묶음.** 결정 항목은 최대 6개. 넘으면 문서를 나눈다.
2. **맨 위 세 줄.** 제목 · 날짜와 상태와 근거 문서 · "왜 지금 정해야 하나" 한 문장.
3. **결정 항목 하나의 구성.** 질문 한 문장 → 선택지 2~4개(추천을 맨 앞에 두고 '추천' 표시) → 추천 이유 한 줄 → 틀렸을 때의 비용 한 줄. 그 밖의 근거는 '더 보기'에 접고 정본 문서로 링크한다.
4. **글자 수.** 질문 40자, 선택지 이름 12자 + 설명 40자, 이유 60자 안. 표는 3열 이하. 코드·식별자·숫자는 꼭 필요한 것만.
5. **조작.** 선택지를 누르면 표시되고 [추천 전부]로 한 번에 고를 수 있다. [답장 복사]가 "D1 ③ / D2 ① · 메모: …" 문장을 만든다. 사용자는 그 문장을 채팅에 붙이기만 하면 된다.
6. **파일.** `_template.html`을 복사해 만든다. CSS·JS는 안에 넣고 외부 의존(CDN·웹폰트)을 두지 않는다. 밝은/어두운 화면 자동. 이름은 `YYYY-MM-DD-<slug>.html`(ASCII kebab). 만들면 `index.html` 목록 맨 위에 한 줄 추가한다.
7. **보고용도 같은 꼴.** 결정 항목 대신 '결과 카드'(한 줄 결론 + 상태 색 통과·주의·실패 + 더 보기)를 쓴다. 긴 분석은 RESEARCH/VERIFY에 쓰고 브리프에는 결론만 옮긴다.
8. **수명.** 답이 오면 상단 상태를 '결정됨'으로 바꾸고 답을 한 줄 적는다. 문서는 지우지 않는다. `index.html`의 상태도 맞춘다.
9. **넣지 않는 것.** 비밀값, 사람 이름, 사용자 원본 파일명, 보고서 전문, 아티팩트를 대신하는 긴 서술.

## 구성

- `index.html` — 브리프 목록(최신이 위). 상태: 결정 대기 · 결정됨 · 보고.
- `_template.html` — 복사해 쓰는 틀. 결정 항목(`<li class="d">`)과 결과 카드(`<li class="r">`) 예가 하나씩 있다.
- `YYYY-MM-DD-<slug>.html` — 브리프 본문.

## 에이전트가 만들 때

사용자가 "브리프로", "보고 판단하게", "결정할 것 정리해 줘"라고 하면 이 양식으로 만든다. 만든 뒤 채팅에는 파일 경로와 결정 항목 ID 목록만 적는다. 답을 받으면 정본 문서에 반영하고 브리프 상태를 갱신한다.
