# RESEARCH-15 — S-18 기능 수확 조사

## 1. 목적과 범위

- **목적:** 실무 프로젝트 S-18의 공유 폴더에 쌓인 코드·도구(규모검토, 실 배치, 설비, CAD, 구조, 뷰포트, 대안 비교 등)에서 VIDE의 jig·코어 기능으로 가져올 만한 것을 고르고, 이미 VIDE에 있는 것과 겹치는 부분을 가린다.
- **범위:** 기능의 존재·형태·가치·작업량·일반성 판단까지만 다룬다. 채택한 기능의 동작은 해당 SPEC, 구현은 PLAN이 정한다. 나머지 후보는 사용자 선택을 기다린다(§5).
- **출처 표기:** 출처 프로젝트는 `S-18` 코드로만 쓰고, 경로는 S-18 폴더 루트 기준 상대 경로만 적는다.

## 2. 방법

1. S-18 폴더를 11개 영역(사무 문서, 설비 배치, 지식·에이전트 운영, 실 배치 도구, Revit·Rhino 연동, 규모검토, 최근 매스 검토, 공유·발표, CAD 파이프라인, 배치 최적화, 대안 크리틱)으로 나눠 코드를 판독했다. 구조 해석은 [RESEARCH-08](RESEARCH-08-structure-analysis-jig.md) 이후(2026-09-29 이후) 바뀐 부분만 따로 봤다.
2. 기능 단위로 217개 후보를 뽑고, 후보마다 VIDE 현재 상태(이미 있음 30 / 일부 있음 105 / 없음 82), 형태(jig·코어·geometry-kit·공용 스키마 등), 일반성, 작업량, 가치를 매겼다.
3. 가치가 높거나 중간이면서 VIDE에 없거나 일부만 있는 것 가운데 다른 프로젝트에도 쓰이는 것을 묶어 34개로 줄였다(§3).

## 4. 뺀 것

217개 중 183개는 다음 이유로 후보에서 뺐다.

- **이미 VIDE에 있음(30):** 사무 문서 텍스트 추출 레시피, 서버 앱 단일 HTML 스냅샷과 PC 없이 보기, 정본 보호·초안·낙관적 동시성 등 공유·저장 계층과 겹치는 것.
- **가치가 낮음(89):** 한 번 쓰고 버린 스크립트, 컨택트시트 이미지, 시트 접근 경로 조사처럼 기능이라기보다 작업 산출물인 것.
- **프로젝트 전용:** S-18의 특정 공정·장비·건물 유형에만 맞춘 규칙과 데이터(예: 특정 장비 접근 규칙, 품셈 기반 공사비 표).
- **기존 조사에 포함:** 구조 해석 코어·설계 검정·축선 규칙 등은 [RESEARCH-08](RESEARCH-08-structure-analysis-jig.md)·[RESEARCH-09](RESEARCH-09-structure-analysis-methods.md)가 다룬다. 여기서는 그 뒤 바뀐 부분만 D에 남겼다.
- **커뮤니케이션 아카이브·실시간 공동편집:** 검토 결과 VIDE의 최근 기능이 대부분을 대신한다(§5).

**공동편집 대조 요약:** S-18 표 공동편집은 표 하나를 행 위치(인덱스)로 찾고 칸 단위 마지막 저장이 이기며, 인증·이력이 없고 초기화·가져오기가 전원의 편집을 되돌릴 수 없게 덮는다. 가져올 때는 행을 고정 id로 찾고 칸을 글자 단위로 병합하며, 일괄 작업은 확인·되돌리기를 거쳐야 한다. 상태 배지·필터(해당·확인필요 등), 행 단위 할 일 보내기, 결과·의견·교차검토 열은 함께 가져올 만하다. 교차검토 열은 "AI가 노트에 쓰기"(SPEC-10.8 후속)를 AI 칸에만 쓰는 좁은 권한으로 시작하는 자리가 될 수 있다.

나머지 후보(M-01~M-23, M-24의 걷기 외 항목, M-25~M-33)는 사용자 선택을 기다린다.

## 6. 확인 한계

- S-18 문서가 다른 PC의 경로로만 가리키는 도구는 코드를 보지 못했다: RhinoBIM(Rhino 커브 → 벽·슬래브·기둥), 입면 패턴 분할·전개 GH 컴포넌트, 회의록 작성 스크립트, pyRevit 가져오기 스크립트. 문서 설명만으로는 후보에 넣지 않았다.
- 큰 HTML 단일 파일(실 배치 도구, 3D 안내 화면 등)과 대량 결과 폴더는 함수 이름과 일부만 읽었다. 성능·정확도는 실행해 보지 않았다.
- 가치·작업량 판단은 코드 판독과 VIDE 대조에 근거한 추정이다. 작업량은 VIDE 구조로 옮기는 비용 기준이다.
