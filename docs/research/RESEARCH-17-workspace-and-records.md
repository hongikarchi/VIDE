## 2. 세 아티팩트 분석

사용자가 "VIDE에 있었으면 하는 느낌"으로 준 세 페이지는 한 데이터 모델의 세 가지 보기다.

| 페이지 | 무엇을 보여주나 | 데이터 |
|---|---|---|
| ① [IRREG04 관계 표시](https://claude.ai/artifact/CHoyPsfVirAbg532hvVDkf) | 카톡·메일 한 줄씩을 **O(정하거나 확인하거나 고쳐 쓰는 기록) / X(이미 정해진 것을 만들고 마감하는 기록)**로 거르는 태깅 도구. 장(章)은 Bypassing·Reinforcing·Replacing·Contrasting, 성격은 판단·검토 / 사양·마감 / 행정·문서 / 시공·공정 / 기타. J/K 이동, O/X 표시, 문자열 내보내기 | 날짜·시각·출처(채팅/메일)·발화자·성격·주제어·본문 |
| ② [Threads Through the Building](https://claude.ai/artifact/UNed9NoLHp48HdBPu19sHf) | 프로젝트 모델(three.js)을 15개 부위로 나누고, 아래 타임라인과 **커서 하나**로 묶음. 날짜를 끌거나 에피소드를 고르면 기록이 있는 부위가 켜지고, 선이 "그 뒤 어느 부위에서 무엇이 이어졌는지"를 보여줌. 신설/기존 분리 보기 | 부위(id·이름·new/existing), 기록(날짜·부위·유형·한 줄·에피소드), 기록 사이 연결, 마일스톤, 부위별 형상(mm) |
| ③ [Interconnected Judgements](https://claude.ai/artifact/NfaoNe3FvzsoyRmnpNXDWr) | 기록을 **유형 R 요구(법·관청·건축주·이웃) / I 의도(건축가가 원한 것) / K 앎(부위를 얼마나 알았나) / E 근거(실측·개구·구조 검토) / D 결정(역할·사양 변경)**으로 나눠 **부위 × 시간** 차트에 놓고, 연결선(chain)과 마일스톤, 장별 대화 밀도 띠를 겹침. 행 기준을 부위/다섯 요소/장으로 바꿀 수 있고, 기존 부위는 '열어 본 날'부터 실선 | ②와 같은 기록·연결에 부위의 역할 변화(시작 → 끝)와 장 표시, 밀도(날짜별 메시지 수) |

**공통 데이터 모델.** 기록 = {날짜, 출처(채팅·메일·회의·요청·현장), 유형 R/I/K/E/D, 부위(레이어·객체군), 본문 한 줄, 이어진 기록}. 부위는 모델의 레이어·객체군에 대응하고, 연결은 "이 기록이 저 기록을 불렀다"는 방향이 있는 관계다. ①은 입력 단계(거르기·분류), ③은 분석 단계(부위×시간), ②는 모델 위의 열람 단계다. VIDE에는 요청 → 객체의 앞방향 기록과 사실/추정/결정 문장이 이미 있으므로, 이 모델은 그 둘을 한 기록 유형 체계 아래 합치고 **부위와 연결**을 더하는 일이다. 자세한 단계는 PLAN-53이 정한다.

### 2.4 파일 지도 — 탐색기를 관계 지도로

같은 날 사용자가 덧붙인 생각: 파일 탐색기도 "파일들이 서로 연결되고 영향을 받는" 것을 아티팩트 ②③처럼 **그림으로** 보여 주면, 요청을 할 때 무엇이 바뀌고 무엇이 따라 움직이는지 직관적으로 알 수 있다. 폴더 목록은 파일이 어디 있는지만 말하고, 어느 파일이 어느 파일을 끌고 가는지는 말하지 않는다.

| 요소 | 내용 |
|---|---|
| 노드 | 파일(서버·로컬 모두), 로컬 체크아웃은 서버 원본과 짝 |
| 관계(선) | xref(도면 → 참조 도면), Rhino ↔ CAD Sync 쌍, jig 입력 → 결과(`05_검토/<jig>/<회차>`), 데이터 → 보고서(검토용·보고용 HTML), 로컬 체크아웃 ↔ 서버 원본, 참조 이미지 → 그것을 쓴 요청, 노트·회의록이 언급한 파일 |
| 시간축 사건 | Sync, 체크아웃, [서버에 반영], jig 실행, 요청으로 바뀐 객체, 게시 |
| 보기 | ③처럼 행=파일(또는 폴더 역할) × 시간에 사건을 놓고 관계선을 잇는 차트, ②처럼 커서 하나로 "이 시점에 무엇이 어디서 이어졌나"를 켜는 보기 |
| 요청과 연결 | 파일을 고르거나 요청 카드에 대상이 잡히면 **영향받는 파일이 켜진다**(예: 이 3dm을 고치면 Sync 쌍 dwg, 그 dwg를 xref한 도면, 그 모델로 만든 보고서가 켜짐). 제안 카드(C-12)의 "맞출까요?"도 같은 지도 위에 선다 |

데이터 모양은 §2의 기록 모델과 같다 — 노드·연결·시간. 기록 모델은 노드가 부위이고 파일 지도는 노드가 파일일 뿐이므로 **차트 부품을 공유**한다(PLAN-52의 파일 지도 티켓 T-318·T-319 ↔ PLAN-53 웨이브 2의 차트). 나중에 기록(결정·근거)이 파일 노드에도 붙는다. 사용자 결정(§6): 1차 범위는 **관계 + 요청 중 영향 미리보기 + 시간축**까지다.

## 3. 논현동 164·7-3 폴더 규약

사용자는 규모검토를 VIDE 밖의 Claude 세션으로 하고 있다(`논현동 164 규모검토` → 2026-10-15 `논현동 7-3 규모검토`로 템플릿 복사). 그 폴더가 사용자 자신이 만든 작업 폴더 표준이다.

```text
<프로젝트>/
├─ project.config.json      schema architecture-workspace/1 · 역할별 paths · 정본 위치 authority · git project-local
├─ Architecture.md          작업 구조와 정본(사람·AI 공용)
├─ AGENTS.md · CLAUDE.md     "Architecture.md를 보고 정본 위치를 확인하라"
├─ 00_도구/검토엔진/         분석 엔진 코드(node) — 프로젝트 안에 들어 있음
├─ 00_운영/templates/        위 네 파일의 템플릿 · 정리 기록
├─ 10_원본자료/              법규원본 · 수치지도 · 대장 · 일정표 (Git 제외)
├─ 20_라이노/                3dm · dwg · ctb · Rhino_Context_Pipeline (Git 제외)
├─ 30_분석/_데이터/          site.json · sources.json · *.auto.json (정본과 생성물)
├─ 30_분석/법규검토·사이트모델링/  _정의 · _기록 · _산출 · 분석 HTML
├─ 40_레퍼런스/
├─ 50_보고서작업/산출물/     model.html · alts.html · PDF · 캐드 도면 (Git 제외)
├─ 50_보고서작업/cloudflare-deploy/  Worker + 비밀번호 게시
├─ 90_아카이브/              구판·백업
└─ tmp/
```

`.gitignore`는 바이너리(3dm·dwg·pdf·이미지·zip)와 원본자료·산출물을 빼고 설정·정의·md·html만 추적한다. `authority`는 형상(`20_라이노/모델구성.json`)·사실(`site.json`)·출처·발표 정의·브리지 계약·환경 기록의 정본 위치를 적는다.

**그대로 복사하지 않는 이유 세 가지.**

1. `00_도구/검토엔진`처럼 **엔진 코드가 프로젝트 안**에 있다. VIDE에서는 그 역할을 VIDE와 jig가 맡으므로 프로젝트 폴더에는 프로젝트 전용 jig의 README·정의만 남아야 한다.
2. `20_라이노`에 3dm과 dwg가 섞여 있는데 둘은 **서버/로컬 규칙이 다르다**(§4: Rhino는 로컬, CAD는 서버의 xref).
3. `50_보고서작업`에 **산출물과 배포 설정**이 섞여 있다. 배포 계정·설정은 VIDE의 외부 서비스 설정이 맡는다.

반대로 가져올 것은 ① 역할 경로와 정본 위치를 적은 매니페스트, ② 사람·AI가 같은 진입문(README·AGENTS)을 읽는 것, ③ 텍스트만 추적하는 프로젝트 로컬 git, ④ `_데이터`의 정본(`site.json`)과 생성물(`*.auto.json`)을 이름으로 구분하는 습관이다.

## 4. 파일 위치 모델

### 4.1 세 곳, 세 역할

| 곳 | 역할 | 들어가는 것 | 누가 보나 |

| **작업 폴더**(로컬) | **정본**. 사람이 탐색기로 보는 곳. VIDE가 설계하고 만든다 | 매니페스트, 로컬 체크아웃한 모델, jig 결과(검토용 HTML·데이터), 보고용 산출물, 일지·회의록 사본, 프로젝트 jig README | 나. git으로 다른 PC와 맞춤 |
| **회사 서버 폴더**(NAS·UNC) | **회사의 정본**. 구조는 회사 것이고 VIDE는 만들지도 이름 붙이지도 않는다(예: `\\Lifethings\Lifethings_02\PROJECTS\2026 Project\2601-나진상가 공공기여`). 어디에 무엇을 둘지는 VIDE 안에서 대화로 정하고 프로젝트가 기억한다(§4.2) | 원본 자료, 공유 도면(xref 포함), 반영된 모델, 공유할 산출물 | 회사 전체 |
| **VIDE PC 데이터**(`%LOCALAPPDATA%\VIDE`) | **캐시·개인 것** | 검색 인덱스, 대화 원문, 키·토큰, 스냅샷 | 그 PC의 나 |
| **공유 사이트**(VIDE 사이트 또는 본인 Cloudflare) | **게시본**. PC 없이·회사 밖에서 볼 것 | 보고용 HTML(비밀번호), 모델 스냅샷, 할 일·노트·일지 복사본 | 초대한 사람, 폰·노트북 |

한 줄 규칙: **파일은 폴더, 게시는 사이트, VIDE DB는 캐시. GitHub은 네 번째 장소가 아니라 작업 폴더의 이력.** 게시본은 정본이 아니므로 폴더에서 다시 게시하면 덮인다.

### 4.2 서버와 로컬: 읽기는 서버, 쓰기는 로컬, 서버 반영은 사람

사용자의 세 사실 — NAS는 느려서 Rhino는 로컬에서 작업한다, CAD는 X-PLAN처럼 xref로 묶여 있어 결국 서버 파일이 고쳐지는 것이 맞다, AI가 서버 파일을 바로 고치는 것은 아직 못 믿겠다 — 는 "정본이 어디 있나"와 "AI가 어디에 쓰나"를 떼면 충돌하지 않는다.

서버에는 **규약이 없고 기억만 있다.** 어느 폴더를 연결할지는 지금처럼 설정에서 미리 정하고(SPEC-01.13 프로젝트 폴더), 거기서 무엇을 어떻게 할지는 VIDE 안에서 대화로 정한다. 폴더를 연결하면 AI가 안에 이미 있는 구조를 읽고 "도면은 `03_도면`, 보고서는 `05_보고서`로 보이는데 맞나요?"처럼 스키마를 **제안**하고, 사람이 확인·수정하면 프로젝트가 **기억**한다(`project.config.json`의 서버 블록). 이후 VIDE는 목적지를 모를 때만 묻고("이 보고서는 어디에 둘까요?"), 답은 다시 기억한다. "앞으로 보고서는 여기에"라고 말하면 기억이 바뀐다. 회사마다 다른 구조는 AI가 읽어서 맞추므로 VIDE가 바뀌지 않는다. VIDE는 서버 구조를 만들거나 이름을 바꾸지 않는다.

| 단계 | 규칙 | AI 신뢰 문제 |
|---|---|---|
| 서버 폴더 연결 | 회사 폴더를 설정에서 그대로 연결한다. 연결 때 AI가 구조를 읽어 역할(원본/모델/도면/산출물…)을 **제안**하고, 사람이 대화로 확정하면 프로젝트가 기억한다. 고정 템플릿·매핑 규약은 없다 | — |
| 로컬 체크아웃 | 작업할 3dm을 로컬 작업 폴더로 가져오고 서버에는 '작업 중(누가·언제)' 표시를 남긴다(사이트로 팀원도 봄) | AI는 로컬 사본에만 쓴다 |
| [서버에 반영] | 사람이 누를 때만 로컬 → 서버. 서버의 이전 판은 `아카이브/<날짜>/`에 자동 보관 | 반영 전 바뀐 객체 목록과 Sync 어긋남을 보고 누른다 |
| CAD(dwg) | 서버에서 직접 연다. xref는 서버 경로를 읽는다(2026-10-15 사용자: "cad는 서버에서 작업하는 것도 오케이") | AI 수정은 요청 단위 되돌리기 + 그날 첫 수정 전 로컬 자동 사본 + rev cloud 표시로 보호 |
| 원본 자료·레퍼런스 | 서버에서 바로 읽고 인덱스만 로컬 캐시 | 쓰기 없음 |
| 게시 | 보고용은 로컬 `06_산출물`에 쓴 뒤 사이트/Cloudflare로, 서버에는 [서버에 반영]으로. 서버의 목적지는 기억한 위치, 없으면 그때 묻는다 | — |

**상황표**

| 상황 | 어디에 무엇 |
|---|---|
| 회사 안 협업 | 서버 폴더가 회사 정본이고 구조는 회사 것. VIDE는 연결 때 읽어 둔 기억으로 어디서 읽고 어디에 반영할지만 안다. 모델 편집은 한 번에 한 사람(로컬 체크아웃 + '작업 중'), 도면은 서버에서, 일지·할 일·노트·회의록은 사이트에서 동시에 |
| 외부 미팅 | 노트북에 작업 폴더(git)가 있으면 전부. 없으면 사이트 게시본(보고용 HTML·스냅샷·할 일)만. 미팅 메모는 사이트 노트에 적으면 돌아와서 폴더 `01_운영/회의록`에 사본이 생긴다 |
| 재현 | 작업 폴더(+git)만 있으면 VIDE가 `project.config.json`을 읽어 프로젝트를 다시 만들고 DB를 다시 짓는다 |

**두 안과 남은 고민(OQ-18).** dwg를 (가) 서버에서 직접 고치되 위 보호를 두는 안과 (나) dwg도 로컬 체크아웃하고 xref만 서버를 읽는 안이 있다. 사용자는 (가)에 기울었으나 "AI를 아직 못 믿겠다"는 고민을 남겼다. 1차는 (가)를 기본으로 두고 설정으로 (나)로 바꿀 수 있게 하며, 결정은 작업 폴더를 실제로 써 본 뒤 OQ-18에서 내린다. 파일 종류별 '바로 서버 쓰기' 허용(예: 운영·검토·산출물)도 같은 시점에 정한다.

## 5. 로컬 폴더 트리

트리는 규모검토 폴더가 아니라 **VIDE 기능에서 거꾸로** 뽑았다. 번호는 01~09이고 10이 아카이브다(사용자 질문 "왜 00, 10인가"에 대한 답: 10 단위 번호는 사이에 끼워 넣을 자리를 두는 습관인데, 역할이 매니페스트로 고정되므로 빈 자리가 필요 없다). 새 역할은 11부터 뒤에 붙인다.

이 트리는 **설정 파일에 든 기본 템플릿이지 하드코딩이 아니다.** 사용자의 말대로 회사마다·사람마다 다르므로, 폴더 이름과 번호는 회사·개인 설정에서 바꿀 수 있고 **정본은 폴더 이름이 아니라 `project.config.json`의 역할 경로**다. 우리가 규칙을 정하는 곳은 로컬뿐이다 — 로컬은 AI가 만들고 사람이 보는 폴더이므로 우리 규칙이고, 서버는 각 회사의 것이라 규칙 대신 §4.2의 기억을 쓴다. 아래 '서버/로컬' 열의 "서버(기억)"는 그 뜻이다.

| 폴더 | 어느 기능이 쓰나 | 서버/로컬 |
|---|---|---|
| `project.config.json` · `README.md` · `AGENTS.md` | 역할 경로·정본 위치(VIDE가 읽고 씀), 사람·AI 진입문(Claude Code를 이 폴더에서 열어도 바로 읽음) | 로컬(git 추적) |
| `01_운영/` | 일지·회의록·할 일 내보내기·일정(SPEC-10, 팀 기록의 파일 사본) | 로컬, 서버 직접 쓰기 허용 후보 |
| `02_자료/` | 원본 자료 — 법규·대장·수치지도·의뢰 문서. 읽기 전용. 지식 수집(SPEC-08.9)과 수동 자료 카드가 여기로 받음 | 서버(기억), 로컬은 사본 |
| `03_모델/` | Rhino 3dm, 모델 구성 | 서버 정본, 작업 중은 로컬 체크아웃 |
| `04_도면/` | DWG·xref·CTB(참조 원도면 포함) | 서버, 직접 작업 |
| `05_검토/<jig>/<회차>/` | 모든 jig 결과 — 규모검토·법규 체크·구조·패널링의 데이터 JSON과 검토용 HTML | 로컬, VIDE가 씀 |
| `06_산출물/` | 보고용 HTML·CSV·PDF·내보낸 모델 = 게시 대상 | 로컬, VIDE가 씀, 반영은 사람 |
| `07_검토본/` | 검토본 스냅샷(시점 비교, SPEC-05) | 로컬 |
| `08_레퍼런스/` | 이미지·사례(느낌 요청 이미지 포함) | 서버(기억) |
| `09_도구/` | 프로젝트 jig(README·jig.json)·프로젝트 전용 스크립트. 엔진 코드는 두지 않음 | 로컬(git 추적) |
| `10_아카이브/` | 이전 판 보관([서버에 반영]의 자동 보관 포함) | 로컬·서버 각각 |

## 7. 보류 — 규모검토 UX (잊지 않기 위한 기록)

7-3 작업이 끝나면 아래를 그때의 SPEC-12·jig 상태와 대조해 다시 계획한다. 지금은 구현하지 않는다.

1. **규모검토 진행판.** "규모검토 시작" 한 입구 → 주소 → 대지 확인(지도) → 사이트 모델 → 가능 영역 → 건축개요 → 법규 체크 → 보고서. 각 칸은 기존 jig이고, 칸마다 '끝남 / 지금 할 것 / 사람 입력 필요 / 다시 계산 필요'만 보인다. SPEC-12.1의 흐름과 SPEC-07.18의 자동 진행 위에 얹는다.
2. **지도 카드.** 주소·후보 필지·대지 경계를 실제 지도 위에. 1안은 이미 키가 있는 VWorld 2D 타일(계정 추가 없음), Kakao·Naver는 계정이 더 필요하다.
3. **수동 자료 단계 카드.** "토지이음에서 토지이용계획확인원을 내려받아 `02_자료/법규원본`에 넣으세요" → 폴더 감시 → 들어오면 다음 단계. 세움터(대장)·구청 고시도 같은 틀. 브라우저 자동화는 나중.
4. 7-3 엔진(`00_도구/검토엔진`)의 분석 코드 가운데 VIDE jig로 가져올 것은 그때 RESEARCH-04의 출처 표 방식으로 목록화한다.
