# RESEARCH-16 — 도메인 서비스와 설계 워크플로 메모

2026-10-07 사용자가 앞으로의 방향을 메모로 줬다. 이 문서는 그 메모를 주제별로 나눠 정리하고, 지금 VIDE에 있는 것과 대조한다. 제품 결정이 아니라 조사와 분석이다. 채택한 것은 PRD 후보(C-04~C-08), ADR-040·041, PLAN-43이 소유한다.

## 1. 메모의 구성

| 주제 | 메모 요지 | 이번 처리 |
|---|---|---|
| 단면 | clipping plane | PLAN-43 T-197 구현 |
| 도면 생성기 | CAD로 내보내기. 시트, 주석, 치수, xref 설정이 그대로 넘어가는지 | T-199 실험 |
| 마감 | 마감 일람표, 실 마감표. 사용자가 만든 '마감코드 체계' 앱을 바탕으로 | T-198 구현 |
| 도면-모델 Sync | ① 서버의 파일 전부를 링크로 ② CAD 파일의 xref 관계를 파악해 모델에 반영 ③ 모델을 고치면 CAD에 형식을 지켜 역반영 | ①②는 T-200(읽기 전용), ③은 C-08 |

## 2. 규모검토 흐름 (메모의 0~6단계)

0. **지역지구.** 지역지구를 설명한다.
1. **대지 안 건축 가능 영역(2D).** 건축선 후퇴선, 민법상 이격거리, 일조 사선 제한선, 기타 이격거리를 확인한다.
2. **건축 가능 매스(3D).**
   - 평면 커브(후퇴선, 이격거리) 기준으로 돌출한다.
   - 일조 사선 제한을 닫힌 폴리서피스로 만든다.
   - 최대 건축 가능 영역을 닫힌 폴리서피스로 만든다.
3. **인센티브 검토(3D) — 대안을 여러 개 만든다.**
   - 층별로 잘라 모양을 정리한다.
   - 친환경 인센티브로 용적률을 더 확보하는 방법을 설명한다.
   - 기본 용적률 배치의 대안 여러 개와 인센티브 반영안을 만든다.
   - 공개공지 설치안과 표를 만든다.
4. **용도 배분(3D).** 용도 법규 조건을 설명하고, 매스를 용도별로 나눈다.
5. **주차와 대지 안의 공지.**
   - 주차 대수와 공지 면적을 산정한다.
   - 주차 진입 가능 구역의 대안을 2D로 확인한다.
   - 공지가 들어갈 부분을 3D로 확인한다(건물은 투명하게).
   - 주차 방식별 대안을 평면과 3D로 만든다.
6. **건축개요.** 건축개요와 층별 면적표를 만든다.

데이터원: 법제처, vworld, 토지이음.

**지금 VIDE와의 관계**
- J-01(사이트 모델링), J-02(사이트 분석), J-03·J-04(법규)가 `src/jigs/catalog.ts`의 계획 항목으로 있다.
- 구조 jig(FR-23)가 '대안 계산 → 사람 확인 → 호스트 만들기'의 기존 틀이다.
- 1·2단계는 형상 계산이 정해져 있어 jig에 맞는다. 3·4단계의 설명과 대안 생성은 AI와 jig를 함께 쓰는 영역이다.

## 3. 법규검토

**Front**
1. 전체 구조를 보여 준다: 무엇을 어떤 방식으로 검토해야 하는지.
   - 결론("어떻게 해야 한다")을 먼저 보여 준다.
   - 이유(왜)는 뒤에서 근거 자료와 함께 자세히 설명한다.
2. 보여 주는 방식: 그림으로 보는 건축법처럼 시각적으로 보여 준다.
   - 근거 조항은 하이퍼링크로 건다.
   - 법령 원문 발췌와 해석을 함께 둔다.

**Backend**
- 대충 물어도 그 안에서 찾아 답한다. 예: "우리 건물은 일조 사선 봐야 해?" → "이런 근거로 적용받지 않는다".
- 단계별(규모검토, 계획설계, 기본설계, 실시설계)로 봐야 할 법령을 나눈다. 예: BF 인증은 면적과 관련된 부분이 아니면 규모검토 단계에서는 볼 필요가 없다.

**모델과 연결**
- 법규검토는 Rhino와 CAD(가능하면 Revit)에 연결되어야 의미가 있다.
- 땅을 검색하면 다음이 이어지는 흐름을 목표로 한다.
  1. 법규검토 보고 페이지가 하이퍼링크와 함께 나온다.
  2. Rhino에서 대지가 모델링된다.
  3. 법규 질의응답을 할 수 있다(방위와 주변 환경, SHP 메타데이터를 인지한 상태로).
  4. 애매한 사항은 AI가 되묻는다(예: 용도).
  5. 여기까지 되면 모델링까지 이어진다.

**데이터 구조 질문**
- 법규는 글 정보라서 DB로 만들어야 한다. 어떤 구조가 좋은지가 질문이다(OQ-16).
- 지적도, 연속수치지형도, 건물 데이터는 SHP·JSON·XLSX 형태의 형상과 데이터다.
- Rhino와 CAD는 형상이다.
- 이들을 연결하고 형상에 메타데이터를 최대한 넣어서, LLM이 형상을 읽고 법규를 해석할 여지를 만든다.
- VIDE에서는 Link ID(ADR-030)와 객체 속성이 메타데이터의 자리다.

## 4. 패널링

- 패널링 작업 흐름을 이해하는 것이 중요하다. 다만 프로젝트마다, 사람마다 다르다.
- 입력: 기준 면, 패턴, 패널 크기, 줄눈 논리. 필요한 정보는 사람에게 되물어 가며 구성한다.
- 단계마다 입력과 출력이 다르다.

| 단계 | 내용 | 형상 |
|---|---|---|
| 1. 미리보기 | 패턴을 3D로 빠르게 본다 | mesh, surface |
| 2. 부재 | 실제 부재 크기, 두께, 줄눈을 고려한다 | mesh, polysurface |
| 3. 최적화 | 부재 최적화, 평면화, 타입화, 결합부 타입화 | 타입별 부재와 결합부 |

J-07(패널링)이 계획 항목으로 있다. 질문 카드(ADR-026)가 '되물어 가며 구성'의 틀이다.

## 5. 도면-모델 Sync의 단계

| 단계 | 지금 | 다음 |

| 링크 | 파일을 하나씩 업로드하거나 열린 문서로 링크한다 | 경로 기반 링크(T-200) |
| xref 관계 | 지식 수집이 xref 이름과 경로만 남긴다 | 관계 그래프와 삽입 변환으로 함께 표시(T-200) |
