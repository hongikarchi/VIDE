# 대화가 화면과 작업을 이끄는 구조

이 문서는 조사 사실과 대안 비교만 담는다. 여기서 결정하지 않으며, 채택할 내용은 뒤에 ADR(가칭 ADR-026)과 SPEC·Design 첨삭으로 옮긴다. 코드 위치는 2026-09-30 `main`(d597436) 기준이다.

## 1. 질문과 범위

사용자 메모(2026-09-30)에서 나온 질문 네 가지를 다룬다.

| # | 질문 | 이 문서에서 다루는 곳 |
|---|---|---|
| Q1 | 참고 앱 A처럼 **심플한 느낌에 포인트 컬러 하나**로 UI를 깔끔하게 할 수 있는가 | §2.2, §3 |
| Q2 | 화면 레이아웃을 정리하고 **전체 구조를 다시 짜야** 하는가 | §2.1, §5, §6.1 |
| Q3 | jig를 **skill처럼**: 채팅에서 요청하면 해당 화면으로 바로 이동하고, 필요한 기능이 좌르륵 수행되게 할 수 있는가 | §2.3, §6.3 |
| Q4 | 전체적으로 **말하면 화면도 알아서, 작업도 알아서** 움직이게 할 수 있는가 | §4, §6.2, §6.4 |

**계기:** 작성기에 "구조 분석"을 보내면 "'구조 분석' jig를 열까요? [열기] [AI 작업으로 보내기] [닫기]" 카드에서 멈춘다. [열기]를 눌러도 jig는 열리지 않는다. 원인은 §2.3에 정리했다.

**범위 밖:** 제품 범위(PRD §13·§14) 변경, 새 jig 기능, 호스트 애드인 변경은 다루지 않는다. 구현은 하지 않았고, 사용자 메모("일단 바로 수행하지는 말고")에 따라 탐구만 했다.

**조사 방법:** VIDE UI 코드 감사, 채팅→jig 흐름 추적, 참고 앱 A의 스타일 코드 판독, 외부 제품 13종 조사를 했다. 그다음 구조안 세 가지를 쓰고 세 관점(사용자 의도, 구현 비용, 실무자 사용성)에서 채점했다. 채점 과정에서 각 안의 코드 관련 주장을 다시 확인했고, 틀린 주장은 §5.4에 적었다.

## 2. 현재 상태 진단

### 2.1 화면 구조

지금 화면은 다섯 면이 동시에 있고, 우측 AI 열 안에는 약 10층이 쌓여 있다.

```text
┌──┬──────────┬──────────────────────────────────┬───────────────┐
│레│ 좌측 266 │ 작업공간 탭 32 (모델·자료·JIG·    │ 'AI WORK'     │
│일│ 프로젝트 │  만들기·보고서 + 문맥 탭)          │ 대화 칩       │
│48│ 연결 파일│──────────────────────────────────│ 작업 보기     │
│  │ details×4│ 뷰포트 (공간 도구·카메라 8·       │ 대기          │
│6 │ 상태 3줄 │  스케치 툴바·선택 바)              │ 질문 카드     │
│개│          │──────────────────────────────────│ route-card    │
│  │          │ 검사기 (탭 4)                     │ 작성기·모드줄 │
├──┴──────────┴──────────────────────────────────┴───────────────┤
│ 상태줄: 문장 3 · 버튼 5 · 사용량                                │
└────────────────────────────────────────────────────────────────┘
```

| 문제 | 근거 |
|---|---|
| 같은 곳으로 가는 입구가 여럿이다. JIG로 가는 길은 레일 버튼과 JIG 탭 두 개, 문서로 가는 길은 레일·좌측 details·모바일 탭 두 종이다 | `src/ui/index.html`, `workspaces.ts:24-30` |
| 모델 탭이 아니면 좌측 패널이 통째로 사라져 레이아웃이 흔들린다 | `style.css:3116-3129` |
| 결과가 다섯 곳으로 흩어진다: 우측 작업 보기, 작성기 위 카드, 9초 뒤 사라지는 토스트, 뷰포트, 좌측 작업 이력 | `app.ts:1913-1927`, `work-view.tsx:23-25` |
| 우측은 대화 기록이 아니라 **선택한 요청 하나**를 보여 준다. 요청 목록은 좌측에 있어서 말하고 결과를 보는 흐름이 좌우로 찢어진다 | `work-view.tsx:23-25` |
| 연결 상태가 세 곳(좌측 문장, 상태줄 버튼, 연결 카드)에 표시된다. 모드도 토글과 상태줄 문장 두 곳에 있다 | `workspace-status.ts:117-125` |
| jig 관련 탭이 JIG·만들기·보고서·자료 네 개로 나뉘어 있다 | `workspaces.ts:24-30` |
| 배선이 한 파일에 몰려 있다 | `app.ts` 3013줄 |

### 2.3 채팅 → jig 흐름: "구조 분석"이 카드에서 멈추는 이유

```text
작성기 "구조 분석"
  → decisiveRoute (request-route.ts:490-540)
      OFFICIAL_JIG_ROUTING.structure.words(:123-128)에 '구조 분석' 포함
      → Jev를 부르지 않고 규칙으로 확정 (서버 judgeRoute도 by:'rules', confidence 1 — request-router.ts:266-290)
  → target=jig, jig='structure'(레거시 StructureJig)
  → runAppRoute (app.ts:2036-2055) → routeCard(T1) "…jig를 열까요?"
      [열기]            = clearComposer() + setWorkspace('jig') + 토스트 "JIG 목록에서 '…'을(를) 여세요"
      [AI 작업으로 보내기] = revert 기록 후 일반 AI 턴 (이 AI는 jig를 열 수 없음)
```

| 사실 | 근거 |
|---|---|
| [열기]는 작업본을 만들지도, 문맥 탭을 열지도, jig 대화를 연결하지도, 원장에 기록하지도 않는다. 요청 글은 **지워진다** | `app.ts:2039-2050` |
| 사용자는 목록에서 jig를 찾고, 작업본을 고르거나 만들고(새로 만들 땐 출력 레이어 필수 폼), 문맥 탭까지 가야 한다. 최소 3~4번 클릭이다 | `jigs.tsx:919-1005` |
| 이 카드는 버그가 아니라 문서 결정이다. SPEC-02.17의 2(`:219`), SPEC-02.19의 T1 제안 카드(`:277`, `:288`), RESEARCH-10 §16 B7(`:2593` "jig는 제안형")을 따른 결과다 | 해당 줄 |
| 그런데 SPEC-02.19 예시(`:288`)의 "열면 그 jig의 대화가 열린다"는 **구현되지 않았다** | `app.ts:2044-2050` |
| 라우팅 id `structure`는 인스턴스·설정값이 없는 레거시 jig다. 선언형 `project/s06-frame`의 `skill.md`(intent_en·words)는 라우팅 후보에 들어가지 않는다. 후보는 3개가 하드코딩돼 있다 | `request-route.ts:120-128`, `request-router.ts:381-387`, `extensions/jigs/s06-frame/skill.md:1-8` |
| AI 도구 `jig_set`·`jig_run`은 대화에 `jigInstanceId`가 있을 때만 등록된다. 그런데 `src/ui` 어디에서도 그 값을 넘기지 않아 실사용에서는 닿지 않는다(PLAN.md:101 '대화 도구 연결' 남음) | `agent-tools.ts:916-983`, `server/conversations.ts:219,1229` |

**이미 있는 것(비용이 작다는 근거)**

- 러너는 `until`에서 멈추고, 입력 지문이 지난 확인과 같으면 사람 단계를 통과한다(`runner.ts:364`, `:371`). `mode: 'preview'`는 사람 단계를 확인됨으로 본다(`:361`).
- s06-frame의 `confirmInputs`는 `blocks: []`다(`jig.json:1070`). 그래서 입력을 확인하지 않아도 해석 미리보기까지 계산이 이어진다. 실제로 멈추는 곳은 `confirmAnalysis` → `analysisConfirmed`다.
- `sizing`은 `analysis`만 needs로 받는다(`jig.json:1507`). 단면 선정은 해석 확정 **전에** 이미 계산된다. 확정이 막는 것은 `analysisConfirmed`와 bake뿐이다.
- 선언형 작업본은 열면 자동으로 run된다(`jig-panel/instance.ts:236-251`).
- 서버 `jig_set`은 이미 여러 값을 한 묶음으로 받는다(`agent-tools.ts:916-940`). 1개 제한은 UI 빠른 경로 `paramFor`(`request-route.ts:460-487`)에만 있다.
- 러너는 `speed` 필드를 보지 않는다. 진행 이벤트(onStep)도 없어서 끝날 때 보고서를 한 번에 돌려준다(`runner.ts:280`). `src`에는 SSE가 없고 폴링만 있다(`app.ts:729`, `:747`).

- **이행:** 기존 이름 `--line/--muted/--soft/--coral/--ink/--paper`를 새 토큰의 별칭으로 연결하면 이미 있는 `var()` 362곳이 한 번에 새 톤을 따른다. 약 0.5일 분량이고, 인상 변화의 약 60%가 여기서 나온다.
- **dark 주의:** dark에서는 `--ng #f07a6e`와 `--accent #e48a6c`가 가깝다. 위반은 채움 + ✕ + 문구로, 선택은 외곽선만으로 표시해 **모양으로도** 구분한다.

### 3.3 포인트 컬러 사용 규칙

| 허용(여기에만) | 금지 |
|---|---|
| ① AI 실행 중 점, 체크 목록의 현재 단계 점(정지한 점, 무한 반복 애니메이션 없음) | 목록·카드 선택 → `--bg-selected` + 600 |
| ② 화면(무대)이 바뀌는 순간의 600ms 외곽선 한 번 | 왼쪽 색 막대(전면 금지) |
| ③ 작성기 대상 칩(`--accent-subtle` 바탕 + 0.5px `--accent-muted` 테두리) | 탭·레일·보기 전환의 활성 표시 → 1.5px 검정 밑줄 |
| ④ 뷰포트 선택, AI가 방금 만진 객체의 외곽선 | 판정색(ok/warn/ng) 대체 |
| ⑤ 포커스 링, `::selection` | 넓은 면 채움(패널·헤더 배경) |
| ⑥ 보고서·KPI의 실현값 | 주 버튼(검정 CTA가 기본안) |

**동시 노출 목표:** 한 화면에 포인트 요소는 대략 3개 이하로 둔다(대상 칩, 선택, AI 활동 점).

**포인트 방식 비교**

| 안 | 내용 | 판단 |
|---|---|---|
| A 고정 코랄 | `--accent` 하나 | 권장. 뜻이 흔들리지 않는다 |
| B 프로젝트별(참고 앱 A식) | 프로젝트마다 20색 중 하나 | 판정색과 충돌하고, 포인트의 뜻이 프로젝트마다 바뀐다 |
| C 화면·모드별 | 모델=코랄, 구조=파랑 … | 채팅이 화면을 옮길 때마다 색이 바뀌어 산만하다 |
| A + 프로젝트 점 | A에 더해 `--project-dot`을 프로젝트 이름 옆 6~8px 점에만 쓴다 | 절충 권장. 정체성 효과만 가져온다 |

### 6.3 "jig = skill" 계약

**정의:** jig = skill = **설명(언제 쓰나) + 절차(steps) + 전용 무대(`panel.json`)**. 공급자 CLI의 skill로 싣지 않는 **VIDE 내부 계약**이므로 SPEC-07.2(`:42`)와 ARCH-03 §5.3의 '공급자 skill 금지'는 유지할 수 있다. 새 파일 없이 `skill.md` 앞머리와 `jig.json` v3에 필드를 얹는다.

| 계약 항목 | 위치 | 필드(초안) | 지금 있는 것 |
|---|---|---|---|
| 트리거 | `skill.md` 앞머리 | `description`(한국어, 무엇 + 언제, 500자 이내), `examples`, `invocation: auto \| user-only`, `scope` | `name`·`intent_en`·`words`·`not_for`·`limits` (`s06-frame/skill.md:1-8`) |
| 입력 | `jig.json` | `inputs.roles`(그대로), `from_request: [spanMax, beamSpacing_m, layoutSource]` | `inputs.roles`, `params[].words` |
| 열 때 결정 | `jig.json` | `open: { reuse: last\|new, layerRoot: 'VIDE/{jig}/{n}' }`, `stage: { preset, view: 3d\|plan\|report }` | 없음(새로 만들 때 레이어 폼 필수, `jigs.tsx:919-1005`) |
| 자동 실행 | `jig.json` | `autorun: { until: <stepId> \| first-hard }`. 입력 확인은 `preview` 모드로 '입력 미확인' 표시를 단다 | `runner.ts`의 `until`·`preview`·지문 통과 |
| 확인 지점 | 기존 선언 재사용 | human step의 `slot`, `gates`, `bake.requires`. 체크포인트마다 '스레드에서 답함 / 무대로 가야 함'을 표시 | 있음 |
| 결과 | `jig.json` | `summary: { kpi: [...], report, oneLine }` | `panel.json` kpi, reports |

**로더:** 공식·설치·프로젝트 jig의 `skill.md` 앞머리를 읽어 Jev 후보로 공급한다(`drafts.ts:309`의 파서를 일반화). 하드코딩 `OFFICIAL_JIG_ROUTING`(`request-route.ts:120-128`)과 `officialJigs`(`request-router.ts:381-387`)는 폴백으로 내린다. 같은 단어에서는 프로젝트 skill을 우선한다(RESEARCH-10 §8.8).

**단일 진입점:** 라우터 빠른 경로, AI 도구 `jig_open`, 사람의 버튼이 모두 **같은 함수**를 부른다. 1차는 서버 신설 없이 클라이언트 함수 `startSkill()`로 두고, 기존 run과 폴링을 재사용한다.

```text
startSkill(jigId, request, mode)
  1 작업본: open.reuse=last → 마지막 작업본, 없으면 layerRoot 기본값으로 생성
  2 무대: setWorkspace/openContextTab(instanceId) (셸 교체 후엔 stage.open)
  3 대화: 목적 없는 일반·새 대화면 jigInstanceId로 묶고, 아니면 새 jig 대화 + 서로 가리키는 줄
  4 원장 기록
  5 from_request 값 적용 (한 번의 되돌리기 묶음, 서버 jig_set 재사용)
  6 autorun: until까지 (preview로 입력 미확인 표시)
  7 summary 결과 카드 + 판정색 보기
```

**AI 도구(프런트 동작 노출)**

| 도구 | 등급 | 계획 모드 |
|---|---|---|
| `ui_go(stage, view, focus)` | R (화면만) | 허용 |
| `jig_open(jigId, reuse)` = startSkill 1~4 | T1 (비파괴) | 허용 |
| `jig_set(values{…})` | T1 (되돌리기 묶음) | 제외 |
| `jig_run(until)` | T1 (VIDE 내부 계산) | 제외 |
| `view_set(level, projection, isolate)` | R | 허용 |

**모드별 동작 (ADR-022의 두 모드)**

| 단계 | 자동 | 계획 |
|---|---|---|
| 판정, 무대 열기, 작업본 재사용·생성, 대화 바인딩 | 실행 | 실행(비파괴). 단, 새 작업본 생성은 §8 Q5 |
| `from_request` 적용 | 실행 | '제안된 설정값 변경'으로 표시만 |
| autorun | until까지 | 체크리스트 + [진행] 하나 |
| 해석 확정(M), Rhino에 만들기(T2, SPEC-07.7), user-only jig 열기 | **사람만** | **사람만** |

## 8. 권장안과 결정이 필요한 질문

2026-10-01 사용자가 아래 질문을 결정했다. 결정과 반영 위치는 [ADR-026](../decisions/ADR-026-chat-stage-and-skill-jigs.md)이며, 이 절은 결정 전의 권장안 기록으로 둔다.

### 8.1 권장안 (결정 아님)

1. **목표 구조:** 안 1(대화 열 + 무대 하나)을 뼈대로 하고, 안 2의 상시 연결 점·접히는 왼쪽 슬롯·[원래대로]·`ui_go`, 안 3의 턴 블록 문법·'대기' 묶음·프로젝트 보드를 접붙인다(§6.1).
2. **jig = skill:** VIDE 내부 계약으로 정의하고, 기존 `skill.md`·`jig.json` v3에 필드를 얹는다. 러너는 거의 그대로 쓴다(§6.3).
3. **시각:** 참고 앱 A식 무채 웜 그레이 틀 + 고정 코랄 포인트를 허용 목록 6곳에만 쓴다. 토큰층과 별칭부터 시작한다(§3).
4. **순서:** 단계 0(멈춤 해소)과 단계 1(토큰 별칭)을 지금 레이아웃에서 먼저 한다. 목업으로 구조를 확인한 뒤 셸을 교체한다(§7.2).
