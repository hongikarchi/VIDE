# 마감 일람표 jig

근거: 2026-10-07 사용자 메모 "마감 일람표 / 내부 실 마감표 같은 기능 있으면 좋겠음"과 사용자가 만든 HTML 앱(`마감코드 체계.zip`). 구현 범위는 [PLAN-43](../plans/PLAN-43-section-finish-xref-submit.md) T-198과 그 「같은 날 정한 기본값」 2다. 연결되는 제품 약속은 FR-24(jig로 작업하고 결과를 표로 본다)와 FR-14(재사용 가능한 데이터 파일로 내보낸다)다. FR-21(전문 일람표)은 PRD §14에서 후속 확장으로 남아 있다. 이 jig는 사용자가 2026-10-07에 고른 한정된 범위이며, FR-21의 범위 판단은 PRD가 소유한다.

이 jig는 SPEC-07.10의 예외인 **내장 화면 jig**다. 구조 분석·Sync·자료 jig처럼 정해진 화면을 JIG 목록에서 연다. 화면은 Design SCR-28이 정한다.

## 사용자가 하는 일 — SPEC-11.1

1. 설계자는 JIG 목록에서 **마감 일람표**를 연다. 탭이 네 개 있다: **라이브러리 · 마감 선정**, **실별 배정**, **납품 출력**, **체계 · 기준**.
2. 라이브러리에서 부위(바닥·벽·천장 등)·카테고리(바탕군)·마감재·속성·총두께로 마감 코드를 거르고 검색한다. 카드를 누르면 이 프로젝트에 **채택**된다. [상세]에서 층 구성표와 단면 그림을 보고, 층별 두께를 이 프로젝트에 맞게 조절한다.
3. 실별 배정에서 실(층별·실번호·실명)을 추가하고 각 실의 바닥·벽·천장 칸에 코드를 넣는다. 엑셀에서 복사한 표를 붙여넣어 실을 한꺼번에 추가할 수도 있다.
4. 납품 출력에서 **실 마감표**(실마다 바탕·마감·두께·코드)와 **마감 일람표**(쓴 코드마다 구성·마감·두께·적용 실)를 본다. 표제(공사명·도면번호·작성·검토·승인·날짜)와 프로젝트 일반사항을 적고 [인쇄]로 A3 가로 출력하거나 CSV로 내보낸다.
5. 체계 · 기준에서 코드 구조, 카테고리 대역, 재료 해치 범례, 기준표(법정 단열 두께·내화 인정 등), 표준 일반사항을 읽는다.

AI는 이 jig의 계산과 저장에 끼지 않는다. 화면의 조작이 모든 결과를 만든다.

## 1. 코드 체계와 라이브러리 — SPEC-11.2

- 코드는 다섯 자리다: **부위 1글자 + 카테고리(바탕군) 1자리 + 마감재 1자리 + 순번 2자리**(예: `W3101`). 부위는 F 바닥·W 벽·C 천장(내부)과 E 외벽·R 지붕·G 외부바닥(외부)이다.
- 코드 하나는 구성 이름, 구조체, 층 목록(바탕 → 마감 순서), 최종 마감, 속성(방수·단열·내화 등), 설계 주의, 같은 구성의 다른 마감 코드를 가진다. 층마다 재료 종류(해치), 기본 두께, 권장 범위, 실무 상한, 상한을 넘을 때의 대안, 두께 근거를 가진다.
- 라이브러리(코드 477개, 재료 145종, 기준표 8개, 표준 일반사항)는 공식 라이브러리 `vide/finish-codes`로 VIDE와 함께 배포된다. VIDE 안에서는 읽기 전용이다. 라이브러리를 바꾸는 일은 다음 공식 배포로 한다.
- 다른 jig의 계산 단계도 이 라이브러리의 코드 조회·검색 함수를 쓸 수 있다(SPEC-07.2의 공식 라이브러리).

## 2. 마감 선정과 두께 조절 — SPEC-11.3

1. **채택**은 이 프로젝트에서 쓸 코드 목록이다. 카드를 누르면 채택·해제가 바뀌고, 카테고리·마감재 묶음 단위로 [모두 채택]·[해제]한다. 실에 배정한 코드는 자동으로 채택된다.
2. **필터:** 부위는 하나를 고른다. 카테고리와 마감재는 여러 개를 고르면 그중 하나에 맞는 코드, 속성은 고른 것을 모두 가진 코드, 총두께는 그 값 이하, 검색어는 공백으로 나눈 낱말이 코드·구성·마감·속성·층 이름에 모두 들어 있는 코드를 남긴다. 표시를 '전체·채택·미채택'으로 바꿀 수 있다. 각 선택지 옆에 그 선택을 더했을 때의 건수를 보인다.
3. **두께 조절:** 상세에서 층마다 두께를 입력하거나 슬라이더로 바꾼다. 권장 범위의 최소와 최대가 같은 층은 고정이며 바꿀 수 없다. 음수는 0으로 둔다. 조절값은 이 프로젝트에만 저장되고 라이브러리는 바뀌지 않는다. 기본값과 같게 돌리면 조절이 없어진다. [기본 두께로 복원]은 그 코드의 조절을 모두 지운다.
4. **상한 경고:** 조절한 두께가 그 층의 실무 상한을 넘으면 그 층과 카드에 경고를 보이고 라이브러리의 대안(예: "무근콘크리트 + 와이어메쉬 전환")을 함께 보인다. 경고는 저장·출력을 막지 않는다.
5. **총두께**는 층 두께(조절값 반영)의 합이다. 표면 처리처럼 두께가 0인 층만 있는 코드는 "구조체면 · 별도 두께 없음"으로 보이고 단면 그림을 그리지 않는다.
6. **단면 그림:** 층을 재료별 해치로 그리고 층별 치수와 전체 치수를 두 줄로 단다. 벽은 가로, 바닥은 아래에서 위로, 천장은 위에서 아래로 쌓는다. 상세에서는 층 이름을 지시선으로 인출한다. 두께를 바꾸면 그림이 바로 바뀐다.

## 3. 실별 배정 — SPEC-11.4

1. 실 행은 층별·실번호·실명과 바닥(F)·벽(W)·천장(C) 코드 목록을 가진다. 한 칸에 코드를 여러 개 넣을 수 있고 순서가 출력 순서다. 층별이 바뀌는 행에서 표에 구분선을 보인다.
2. **검증:** 칸에 넣는 코드는 라이브러리에 있어야 하고 부위가 칸과 같아야 한다(바닥 칸에는 F 코드). 같은 칸에 같은 코드를 두 번 넣지 않는다. 외부 부위(E·R·G) 코드는 실에 배정하지 않는다. 맞지 않는 코드는 칸에 들어가지 않고 이유를 보인다.
3. **코드 고르기:** 칸의 [+ 코드]는 그 부위로 거른 선택 창을 연다. 처음에는 채택한 코드만 보이고 [전체 라이브러리]로 넓힐 수 있다. 전체에서 고른 코드는 자동으로 채택된다.
4. **붙여넣기:** [붙여넣기로 추가]에 엑셀·CSV·탭 구분 표를 붙여 넣으면 행마다 실 하나를 끝에 추가한다. 열 순서는 층별, 실번호, 실명, 바닥, 벽, 천장이다. 첫 행이 머리글('층', '실명', '바닥' 같은 글자)이면 건너뛴다. 코드 칸 안의 여러 코드는 공백·쉼표·가운뎃점·세미콜론·줄바꿈으로 나눈다. 대소문자는 가리지 않는다. 2번의 검증에 맞지 않는 코드는 넣지 않고, 추가 전에 행과 코드별로 무엇을 뺐는지 보인다. 사용자가 [추가]를 눌러야 들어간다.
5. 실 추가·이름 고치기·코드 넣기·빼기·실 삭제는 바로 저장된다. 상한: 실 2,000개, 한 칸 코드 20개, 글자 칸 100자. 넘으면 그 변경을 거절한다.

## 4. 납품 출력 — SPEC-11.5

1. **실 마감표:** 실마다 묶고, 그 실의 F·W·C 칸 가운데 가장 많은 코드 수만큼 줄을 쓴다. 줄마다 부위별로 바탕(마감 층을 뺀 층 목록, 두께가 있는 층은 `T두께 이름`), 마감, 총두께, 코드를 쓴다. 코드가 없는 칸은 비운다.
2. **마감 일람표:** 채택했거나 배정한 코드마다 한 줄: 코드, 부위, 카테고리, 구성(바탕 → 마감), 마감, 총두께, 속성, 적용 실(실명 넷까지, 나머지는 '외 n'). 부위마다 묶음 머리 줄을 둔다. 채택했으나 배정하지 않은 코드는 [제외]하거나 [흐리게 표시]한다(기본 제외).
3. **표제:** 공사명·도면번호·날짜·작성·검토·승인은 사용자가 이 화면에서 적는 값이며 이 프로젝트에 저장된다. VIDE는 계정 이름이나 다른 자료로 채우지 않는다. 도면명은 표 이름과 쪽 번호로 정해진다.
4. **일반사항:** 라이브러리의 표준 일반사항 뒤에 사용자가 적은 프로젝트 일반사항을 번호를 이어 붙인다.
5. **인쇄:** [인쇄]는 브라우저 인쇄 창을 연다. 인쇄에는 표·일반사항·표제만 나오고 탭·버튼은 나오지 않는다. 판형은 A3 가로다. 쪽 나눔은 브라우저가 정하며 표 머리를 쪽마다 다시 쓴다.
6. **CSV:** 실 마감표와 마감 일람표를 각각 CSV(UTF-8 BOM, CRLF, 모든 칸을 큰따옴표로 감쌈)로 내려받는다. 엑셀에서 바로 열린다. 라이브러리 탭의 [CSV]는 지금 걸러진 코드 목록을 내려받는다. 두께는 조절값을 반영한다.
7. XLSX 파일 쓰기는 이번 범위 밖이다. 새 라이브러리가 필요하므로 따로 정한다.

## 5. 저장과 실패 — SPEC-11.6

- 실 목록과 선정 상태(채택, 두께 조절, 표제, 프로젝트 일반사항)는 프로젝트마다 그 프로젝트의 DB에 저장된다. 다른 프로젝트와 섞이지 않고, 프로젝트를 지우면 함께 지워진다.
- 저장 요청은 전체 목록을 보낸다. 검증(SPEC-11.4의 2·5)에 맞지 않으면 전체를 거절하고 아무것도 바꾸지 않는다. 화면은 마지막으로 저장된 상태로 돌아가 거절 이유를 한 줄로 보인다.
- 두 화면에서 같은 프로젝트를 동시에 고치면 나중 저장이 남는다. 화면은 저장할 때 돌아온 상태를 그대로 보인다.
- 저장에 실패하면(연결 끊김 등) "저장하지 못했습니다"를 보이고 화면의 편집은 남긴다. 다음 변경 때 다시 저장한다.
- 라이브러리를 읽지 못하면 탭을 그리지 않고 이유를 보인다. 저장된 코드가 새 라이브러리에 없으면 그 코드는 표에 경고색으로 남고 출력에서는 빈 칸이 된다(지우지 않는다).
- 원격 화면(SPEC-04.11)에서도 읽고 고칠 수 있다. 호스트 문서는 읽거나 바꾸지 않는다.

## 6. 자료 경계 — SPEC-11.7

- 사용자 HTML 앱에 들어 있던 실제 프로젝트의 실 목록, 작성자·검토자·승인자 이름, 프로젝트 일반사항은 VIDE·저장소·시험 자료에 넣지 않는다(AI.md §8). VIDE의 라이브러리에는 코드 체계·재료·기준표·표준 일반사항만 있다. 시험은 합성 실 목록을 쓴다.
- 표제의 사람 이름은 사용자가 그 프로젝트에 직접 적은 값만 쓴다.

## 7. 이 명세 범위 밖

- 실 목록을 모델(Rhino 방·CAD 실명)에서 자동으로 읽어 오기, 면적·수량 산출, 마감 코드를 모델 객체에 붙이기.
- CAD 도면(DWG) 표 출력, XLSX 출력.
- 라이브러리 편집(코드 추가·수정)과 회사별 라이브러리.
