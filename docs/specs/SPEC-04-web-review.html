외부 웹 공유·의견·검토본

00 / 웹 의견을 실제 설계 수정으로 이어간다 — SPEC-04.7

근거: PRD §8.7·§12.5·§16.4 과업 ③, FR-06·07·16·18·19. 외부 검토자는 공유된 설계를 보고 공간에 의견을 남기고, 설계자는 그 의견을 실제 수정 작업에 연결한다. 로컬 IDE의 편집 화면을 원격 제어하는 기능은 아니다.

  1. 설계자는 로컬 프로젝트에서 공개할 모델/도면 표현, 표, 후보·작업 상태와 허용 검토본을 선택한다. 공개 범위를 미리 본 뒤 게시하고 프로젝트 검토 링크를 전달한다.
  2. 검토자는 링크에서 마지막 게시 상태를 연다. 모델/도면을 탐색하고 객체·표·공개된 후보를 확인한다. 설계자의 현재 카메라나 선택과 같을 필요는 없다. PC가 꺼져 있어도 마지막 게시본을 열 수 있다.
  3. 검토자는 객체 또는 위치에 핀을 붙이고 “이쪽을 더 줄여 주세요”라는 문장과 선을 남긴다. 공간 평면에 등록된 선과 화면 주석은 구분한다. 제출하면 서버가 실제 접수한 시각과 기준을 확인한다.
  4. 설계자는 IDE의 새 의견 목록에서 그 의견을 연다. 작성 당시 게시본과 대상·원본 선을 보고 현재 상태와 비교한다. 이미 바뀐 대상에 대한 의견이면 그 차이를 확인한다.
  5. 설계자는 의견 전체나 필요한 내용을 기존 작업 또는 새 작업의 입력으로 연결한다. 원 의견은 보존하고, 채택한 목표·대상·보존 조건으로 실행 요청을 구성한다. 이때부터 SPEC-02의 후보 생성·조정·적용 흐름이 이어진다.
  6. 수정 후 표를 갱신하고 전후 검토본을 남긴다. 허용 범위의 새 상태를 게시하면 같은 프로젝트 링크에서 새 게시본을 확인한다. 이전 기준의 의견은 새 객체로 조용히 이동하지 않는다. 파일 전달은 SPEC-03.8로 이어진다.

첫 동작 검토안은 로컬 작업자가 ‘공유 갱신’을 명시적으로 요청하는 방식이다. 공개 범위 확대와 이미 허용된 범위의 갱신을 구분한다. 이 방식은 수동 Sync와 별개이며, 향후 허용 범위 내 갱신 자동화 여부는 OQ-04에서 판단한다. 게시본/의견의 접수·권한·보존 계약은 §1·2·4·5를 따른다.

완료 기준: 모델·표를 보는 데서 끝나지 않고, 실제 제출된 의견을 로컬 설계자가 찾아 같은 대상을 수정하고, 수정 결과·검토본·전달 자료까지 연결할 수 있어야 한다. 검토자가 IDE 미설치 상태에서 이 과정을 이해하는지 확인한다(AC-19·22·28·30·35~37). 합성 의견 카드와 로컬 임시 웹 화면은 실제 접수·PC 종료 후 지속성 검수의 대체물이 아니다.

01 / 게시 경계 — SPEC-04.1

근거: FR-18·19. 선택한 공개 자료를 별도 게시본으로 만들어 외부 서비스에 보관한다. 마지막 서버 확인 게시본은 로컬 PC가 꺼져도 열람 가능해야 한다. 업로드 실패는 이전 성공 게시본을 유지하고 로컬 최신 상태와 구분한다. 게시본의 범위를 늘리는 일은 자동 동기화의 부수 효과로 수행하지 않는다. 보존·만료·인증 범위는 OQ-04를 따른다.

02 / 의견과 권한 — SPEC-04.2

근거: FR-06·07·16·18·19. 외부 의견은 게시본 버전과 핀·스케치 기준에 연결한다. 로컬 초안, 서버 접수, IDE 수신, 작업 조건으로 채택, 원본 적용은 서로 다르다. 재전송은 동일 의견을 중복 생성하지 않는다. 원본이 바뀌어도 의견의 대상 버전을 바꾸지 않는다.

외부 열람·의견 권한으로 AI 실행, 호스트 명령, 원본 적용, 로컬 설정 변경을 요청하면 서버에서 거절한다. 같은 사용자의 다른 기기라도 이 권한 경계는 유지한다. 검토 링크 폐기 후 새 접근을 차단하고 이미 내려받은 복사본을 원격 삭제했다고 주장하지 않는다.

03 / 검수 경계

외부 서비스에서 마지막 게시본 읽기와 의견 저장을 검증한 뒤 로컬 제어 프로세스를 종료해 다시 확인한다. 같은 PC의 임시 서버나 정적 화면 시연은 PC 종료 후 지속성 검수의 대체물이 아니다. 지원 브라우저·iPad 입력 검수는 PLAN §7과 OQ-04에 연결한다.

04 / 게시 버전과 접근 — SPEC-04.4

근거: FR-16·18·19. 게시 요청은 공개 목록과 선택 기준을 고정한다. 업로드 도중 로컬 결과가 바뀌면 현재 요청에 몰래 포함하지 않는다. 자산·메타데이터 전체를 서버에서 확인한 뒤 해당 게시본을 열람 대상으로 전환한다. 일부 업로드만으로 이전 게시본을 대체하지 않는다. 재접속 시 요청 ID로 서버 결과를 확인하고 이미 성공한 게시를 중복 생성하지 않는다.

공개 범위에서 제외한 입력·숨긴 속성·로컬 경로는 서버 응답/자산에도 포함하지 않는다. 현재 게시본과 과거 검토본마다 접근 범위를 확인하며 현재 링크가 과거 전체 이력 접근권을 자동으로 부여하지 않는다. 권한 만료/폐기 때 새 자료 조회와 의견 제출을 차단한다. 인증 방식·보존 기간·삭제 정책의 구체 값은 OQ-04 결정 전까지 설정 미완료로 취급한다.

05 / 의견 제출과 로컬 채택 — SPEC-04.5

근거: FR-06·07·16·18·19. 의견에는 작성한 게시본·문서/객체 또는 표현 기준, 본문, 원본 선, 작성자 표시와 제출 식별자를 둔다. 서버 접수 후에는 작성 당시 원본을 보존한다. 새 게시본이 나와도 작성 중 의견의 대상을 옮기지 않는다. 제출 전에 이전 기준에 대한 의견임을 알린다.

상태 가능한 행동 금지할 오해
작성 중·미전송 편집·로컬 초안 보관 다른 기기나 IDE에 접수되었다고 표시
전송 중·접수 불명 동일 제출 ID로 확인/재전송 실패 확정·다른 ID의 자동 중복 제출
서버 접수 접수 시각·기준 확인 로컬 실행 조건으로 자동 채택
IDE 수신 로컬 작업자가 검토·작업에 연결 원본 적용 완료
작업 조건에 채택 원 의견 버전을 참조한 새 조건 생성 원 의견/작성자의 문구를 수정

웹 초안 저장이 불가하면 화면에 남은 입력과 저장 불가를 알린다. 재접속 시 동일 게시본·초안·제출 상태를 복구하며 서버가 없을 때 접수 성공을 만들지 않는다. 취소와 화면 이동은 실제 접수된 의견의 원격 삭제를 뜻하지 않는다.

06 / 기기별 입력과 수용 사례

근거: FR-06·19. 모델 선택·회전/이동/확대와 스케치 모드를 분리한다. 스케치 중 탐색 제스처가 원본 점열을 바꾸지 않는다. 포인터 취소 때 미완성 선을 확정하지 않고 유지/취소를 선택할 수 있게 한다. 기기별 제스처 표현은 Design §12 상세를 따른다. 지원 iPad·펜·브라우저 조합과 실제 동작의 확정은 OQ-04와 실기기 검수에 남긴다.

AC-19·28: 전송 직후 응답 유실·재접속에서 의견 하나만 접수되고 원 게시 기준이 유지된다. AC-35·36: 게시 중 실패는 이전본을 유지하고 PC 종료 후 외부 서버에서 마지막 게시본·허용 검토본을 열람한다. AC-30·37: 권한 밖 자산 조회·로컬 실행 요청을 서버에서 거절한다. 표시용 시나리오만으로 이 AC들을 통과 처리하지 않는다.
