jig 플랫폼

이 명세는 모든 jig에 공통인 동작을 정한다. 구조 분석 jig와 S-06 골조 jig의 분야 동작은 SPEC-06, JIG 탭과 Sync jig는 SPEC-05.8, 대화 세션·경로 판정·질문 카드·확인 규칙은 SPEC-02가 소유한다. 설명서 스키마·폴더·실행기·데이터 형식·서명 방식 같은 물리 계약은 ARCH-03, 선택 근거는 ADR-020, 구현 순서와 시험은 PLAN-22·PLAN-23이 소유한다.

00 / 작은 작업 도구로 조건을 바꿔 보며 계산하고 모델에 만든다 — SPEC-07.1

근거: PRD §12.3·FR-24, AC-41~45, ADR-020. 설계자는 한 가지 건축 작업(예: 골조 배치 점검, 도면↔모델 대조)을 위한 jig를 프로젝트에 열고, 연결된 도면·모델에서 입력을 모아 확인한 뒤 설정값을 바꿔 가며 결과를 3D·표·보고서로 본다. 설정값을 바꾸면 AI 없이 바뀐 부분만 다시 계산된다. 필요한 결과는 Rhino의 열린 문서에 바로 만들고 되돌릴 수 있다. 맞는 jig가 없으면 VIDE 안의 대화로 만들어 이 프로젝트의 jig로 고정한다.

  1. 열기: JIG 목록에서 jig를 골라 이 프로젝트의 작업본을 만든다. 이때 Rhino에 만들 출력 레이어를 정한다(SPEC-07.4).
  2. 입력: 연결 파일 전부에서 역할별 입력 후보가 제안되고 사람이 항목마다 확인한다(SPEC-07.5).
  3. 계산·보기: 단계가 순서대로 계산되어 3D 겹침·표·핵심 수치로 보인다(SPEC-07.7·07.10).
  4. 고치기: 설정값을 바꾸거나 결과 요소를 직접 고친다(SPEC-07.6·07.8). 사람이 맡은 단계(입력 확인·해석 확정 등)는 사람이 누른다.
  5. Rhino에 만들기: 사용자가 누르면 연결된 열린 문서에 되돌리기 기록으로 만들고, [되돌리기]로 되돌린다(SPEC-07.12).
  6. 보고: 보고서와 표를 보고 내보낸다(SPEC-07.11).
  7. 다시: 입력 문서가 바뀌면 '다시 계산 필요'가 되고, Rhino에서 사람이 고친 것은 받을지 묻는다(SPEC-07.13).

완료 기준(1차): 공식 jig와 이 PC에서 묶어 가져온 프로젝트 jig 하나(S-06 골조 jig, PLAN-23)가 형식 점검·자체 시험을 통과하고, Rhino 사본 문서에서 작업본 생성 → 입력 확인 → 설정값 변경 시 AI 없이 바뀐 단계만 다시 계산 → Rhino에 만들기(바로 적용) → 되돌리기 → 사람이 고친 뒤 다시 만들기에서 고친 객체·복사한 객체·꺼진 레이어의 객체가 보존되어야 한다. 채팅 제작은 SPEC-07.16의 수용 시험을 통과해야 완료다. 합성 예제만 되거나, 화면만 있거나, 되돌리기 기록 없이 원본에 쓰는 경로로는 완료하지 않는다. 시험 항목은 PLAN-22.

01 / jig와 구성 — SPEC-07.2

근거: FR-24·13. jig는 한 가지 건축 작업을 위해 그때그때 만들어 쓰는 작은 작업 도구다. 무엇을 받아, 어떤 설정값으로, 어떤 순서로 계산·판단하고, 결과를 어떻게 보이고, 무엇을 모델에 만드는지를 한 묶음으로 정한다. 설명서 한 장이 jig의 정본이고 VIDE가 그것을 읽어 화면을 그리고 단계를 돌린다.

구성 뜻
입력 연결 파일의 레이어, 프로젝트 자료의 진술, 사람이 그린 구역, 다른 jig의 출력. 여러 파일에서 역할별로 모으는 입력 포함(SPEC-07.5)
설정값 이름·건축 단위·범위·기본값·근거가 있는 값(SPEC-07.6)
단계 누가 맡는지(계산·라이브러리·호스트·AI·사람)가 드러나는 계산 순서(SPEC-07.7)
화면 공식 부품만으로 짜는 선언형 패널(SPEC-07.10)
보고서 결과를 주장 문장·표·원장으로 묶는 틀(SPEC-07.11)
만들기 공식 틀에 넘길 결과 항목·레이어·교체 방식(SPEC-07.12)
자체 시험·점검 합성 입력과 기대 결과, 코어가 정한 점검 가운데 고른 것(SPEC-07.14·07.15)
AI 설명서 언제 쓰고 언제 쓰지 않는지, 예문, 한계. VIDE가 jig를 찾고 권할 때 쓴다. 공급자 CLI의 skill 기능으로 싣지 않는다
  • 종류: 화면이 있는 작업 jig와 다른 jig가 부르는 라이브러리 jig(구조 해석, 기하 도구, 프로젝트 자료 등)가 있다. 라이브러리 jig는 공식으로만 만들고, 다른 jig가 코드로 부를 수 있는 것은 라이브러리 jig뿐이다. 작업 jig끼리는 출력을 입력으로 받을 뿐 코드를 부르지 않는다.
  • 호스트에 하는 일: jig는 공식 틀로 자기 결과 객체를 새로 만들거나 전에 자기가 만든 것을 교체할 수만 있다. 기존 객체의 레이어·속성 변경, 이동·복사, 문자·치수 일괄 수정은 jig가 할 수 있는 일에 없으며 AI 편집 경로(SPEC-02)로 한다.
  • 프로젝트 고유 규칙은 그 프로젝트의 jig 안에만 둔다. 공식으로 올리는 것은 여러 프로젝트에 쓰이는 일반 기능뿐이다. 예: S-06의 축선·회피 규칙은 S-06 골조 jig 안에, 삼각형 연결·간섭 거리 계산은 공식 라이브러리에 둔다.

용어의 뜻. 화면 문구는 Design이 정한다.

말 뜻
작업본 한 프로젝트에서 jig 한 버전을 쓰는 기록(입력 조립·설정값·구역·수정 사항·결과·만들기 기록). 화면 이름은 '이 프로젝트의 jig'
설정값 슬라이더·숫자·선택·말로 바꾸는 설계 조건
수정 사항 다시 계산해도 유지되는 사람의 수정(기둥 하나 옮김, 높이 고침)
Rhino에 만들기 jig 결과를 Rhino 객체로 만드는 것. 연결된 열린 문서에 바로 만들고 되돌리기 기록을 남긴다
점검 계산을 믿을 만한지 보는 검사. 막음 수준이면 다음 단계로 가지 않는다
판정 설계가 조건을 만족하는지(여유·주의·초과·미검토). 결과 표에 오르며 흐름을 막지 않는다
버전 jig의 고정된 판(v0.3). 설치·고정한 버전은 바뀌지 않는다

02 / 수명 단계와 출처 — SPEC-07.3

근거: FR-24·13·18, ADR-020. jig는 초안 → 프로젝트 → 공유 → 검증 → 공식의 다섯 단계를 가진다. 1차는 초안·프로젝트·공식만 지원한다. 공유·검증은 이름과 순서만 정하며 그 범위와 남이 만든 코드의 실행 방식은 이 명세 범위 밖이다.

단계 누가 만들고 쓰나 1차
초안 제작 대화로 만든 본인. 이 PC에만 있고 AI가 권하지 않는다 지원(SPEC-07.16)
프로젝트 초안에서 고정했거나 이 PC에서 묶어 가져온 jig. 고정한 프로젝트의 목록에만 보인다 지원
공유 다른 VIDE 사용자에게 게시한 jig 범위 밖
검증 시험 재실행·표준 점검·사람 확인을 통과해 AI가 권하고 부를 수 있게 한 jig('AI 도구로 등록') 범위 밖
공식 VIDE 설치본에 들어 있는 jig·라이브러리 지원
  • 출처를 기록한다: 공식(설치본), 개발자가 이 PC에서 묶음, AI가 쓴 초안에서 고정 중 하나다. 출처가 실행 위치를 정한다(SPEC-07.9). 다른 PC에서 만든 묶음은 1차에 설치하지 않는다(SPEC-07.15).
  • 신뢰 표시는 jig가 스스로 주장할 수 없다. 설명서에 적힌 등급·요약은 표시 근거가 아니며 VIDE가 출처와 점검 결과로 정한다.
  • 버전은 바꾸지 않는다. 설치·고정한 버전을 고치면 사본이 새 초안이 되고, 사본도 SPEC-07.15의 패키지 규칙을 다시 거친다.
  • 쓰고 버린다: 30일 동안 열지 않은 초안은 보관함으로 옮긴다(삭제 아님). 사용자가 보관함을 비울 수 있다.
  • 제작의 본보기는 공식 일반 예제(구조 해석 라이브러리 사용 예, 합성 입력의 격자 골조 배치 예)다. 프로젝트 jig는 그 프로젝트의 목록에서만 참고 jig로 보이고 다른 프로젝트의 본보기가 되지 않는다.

03 / 작업본 — SPEC-07.4

근거: FR-24·16, SPEC-00.7·00.8. 작업본은 프로젝트에 속하고 jig 한 버전에 묶인다. 한 프로젝트에 같은 jig의 작업본을 여러 개(대안) 둘 수 있다.

  • 담는 것: 입력 조립 결과(SPEC-07.5), 설정값과 변경 이력(SPEC-07.6), 구역, 수정 사항(SPEC-07.8), 단계 결과와 점검 결과, 만들기 기록(SPEC-07.12), 이 jig의 대화 연결.
  • 만들 때 정하는 것: 이름과 출력 레이어. 출력 레이어는 연결 모델에 이미 있는 레이어에서 고르고, jig는 그 바로 아래 한 단계 레이어만 만든다. 출력 레이어는 이후 슬라이더·말·AI로 바꿀 수 없다. 바꾸려면 새 작업본을 만든다.
  • 버전 고정: jig의 새 버전이 설치돼도 작업본은 자동으로 올라가지 않는다. 올리기는 사용자의 명시 행동이며, 올리면 모든 단계가 '다시 계산 필요'가 된다.
  • 상태: 계산 전 → 계산됨 / 점검 실패 / 다시 계산 필요(입력 문서 판·설정값·수정 사항이 바뀜). 사람이 맡은 단계는 따로 확정됨 / 다시 확인 필요를 가진다. 만든 뒤 계산 결과가 바뀌면 '만든 결과가 오래됨'을 표시한다.
  • 실제 프로젝트 값은 작업본에만 둔다. 저장소에서 작성하는 프로젝트 jig의 소스에는 단계 코드·화면·보고서 틀·합성 시험 자료만 두고, 실제 설정값·근거·입력 조립·구역·좌표 변환·수정 사항은 사용자 데이터 폴더의 작업본에 둔다(소스 위치는 PLAN-23).
  • 재시작 뒤 작업본·설정값 이력·만들기 기록을 복원한다. 진행 중이던 만들기는 결과를 확인하기 전 다시 보내지 않는다(SPEC-05.3).

04 / 입력 조립 — SPEC-07.5

근거: FR-24·02·03, SPEC-01.11, SPEC-02.9. 2026-09-29 사용자 결정: 입력은 연결된 CAD·Rhino 파일 전부에서 AI가 조립하고 사용자가 확인한다. 사용자에게 입력 폼을 채우게 하지 않는다.

  1. 역할별 후보: jig는 필요한 역할(예: 슬래브 경계, 기존 기초, 레벨)과 모양(다각형·선·점·레벨·문자 등)을 선언한다. 먼저 레이어 이름 규칙으로 후보를 내고, 남은 역할은 단발 AI 단계가 연결 파일의 레이어 표·형상 요약·자료 검색 결과를 보고 "어느 파일의 어느 레이어가 이 역할인가"와 이유 한 줄을 제안한다.
  2. 형상은 코드가 뽑는다. AI는 좌표를 만들지 않는다. 역할의 형상은 선언된 공식 추출기가 연결 파일에서 뽑는다.
  3. 사람이 역할마다 확인한다: 확인 · 바꾸기 · 직접 그리기. 확인하지 않은 역할로도 계산은 돌지만 결과에 '입력 미확인'이 붙고 Rhino에 만들기는 막힌다(inputs-confirmed).
  4. 좌표가 다른 파일: CAD 도면은 Sync jig(SPEC-05.8)의 정렬로 모델 좌표에 옮기고, 변환·대응 수·잔차를 작업본에 두며 사람이 확인한다. 확인하지 않은 변환을 거친 입력은 참고로만 쓰고 만들기에 쓰지 않는다(SPEC-02.9).
  5. jig 입력 읽기는 표시용 Sync와 따로다. 필요한 레이어만 읽으며 뷰포트·Live Sync 기준·작업 이력을 바꾸지 않는다(Sync 동작은 SPEC-01.11).
  6. 확인한 입력의 사본: 확인한 역할은 추출한 형상 사본과 읽은 문서 판을 작업본에 둔다. '고정'이면 그 사본으로 계산하고 '따라가기'면 문서 판이 바뀔 때 다시 읽는다. 어느 쪽이든 읽은 판이 지금 판과 다르면 '다시 계산 필요'를 표시한다(stale-input).

05 / 설정값과 근거 — SPEC-07.6

근거: FR-24·16·18. 설정값은 이름·건축 단위·범위·기본값·근거·영향 단계를 선언한다. 저장은 SI 단위, 표시는 건축 관행(경간 m, 부재 치수 mm, 하중 kN/㎡, 레벨 EL)이다.

  • 출처와 근거: 값마다 누가 정했는지(기본값·사용자·사용자 결정·프로젝트 자료·AI·Rhino·스케치)와 근거(자료 진술 ID, 사용자 결정, 모델 객체)를 기록한다. 근거 상태는 확정 · 가정 · 선택 · 물어볼 것이다. 보고서는 "설정값 n개 중 근거 있음 n · 가정 n · 물어볼 것 n"을 보인다.
  • 근거의 변화: 근거 진술이 확정되면 확정으로 바뀌고, 오염·기각되면 '근거 무효'가 되어 fact-valid가 계산을 막거나 경고한다. 같은 주제의 새 진술이 다른 값을 말하면 알림만 하고 값을 자동으로 바꾸지 않는다. 사용자 결정으로 정한 값은 새 진술이 와도 알림만 한다.
  • 바꾸는 길: 슬라이더·숫자·선택, 전체 설정값 목록('자세히'), 말. 말을 설정값 변경으로 판정하는 경로는 SPEC-02.17이 정한다. 모든 변경은 이전 값·새 값·누가·이유를 이력에 남기고 되돌릴 수 있다. 말로 한 설정값 변경은 되돌리기가 있는 자동 적용이다.
  • 상대 표현: "조금 더 촘촘히" 같은 말의 방향은 설정값 선언에서만 읽는다(간격형은 줄이고 개수형은 늘린다). 선언에 방향이 없으면 적용하지 않고 질문으로 돌린다.
  • 작업본을 만들 때 고정한 값(출력 레이어 같은 쓰기 범위)은 슬라이더·말·AI로 바꾸지 않는다. 그런 요청은 거절하고 이유를 보인다.
  • 이미 결정한 것은 다시 묻지 않는다. 사용자 결정으로 정한 값은 질문에 올리지 않고 '자세히'에서만 바꿀 수 있다.

06 / 단계와 다시 계산 — SPEC-07.7

근거: FR-24·10·16. 단계는 다섯 종류이며 jig 안에서 순환 없는 순서를 이룬다. 단계마다 읽는 입력·설정값·앞 단계와 내는 결과를 선언하고, 이 선언이 의존 관계가 된다.

종류 하는 일 같은 입력이면 같은 결과인가
계산 jig의 순수 계산 코드 예
라이브러리 공식 라이브러리 jig 호출(구조 해석 등) 예
호스트 공식 틀로 Rhino에 만들기(SPEC-07.12) 예(틀 고정)
AI 단발 AI 호출. 결과는 '초안'이며 뒤에 점검이 하나 이상 있어야 한다 아니오
사람 입력 확인·해석 확정·구역 그리기 등을 기다린다 —
  • 설정값을 바꾸면 AI 없이 다시 계산한다. 바뀐 값을 읽는 단계와 그 뒤만 다시 돌고, 입력·설정값·수정 사항이 같으면 이전 결과를 다시 쓴다. 계산 중에 값이 또 바뀌면 이전 계산을 버리고 최신만 보인다.
  • 계산 시점: 단계마다 끄는 동안 갱신 · 손을 뗄 때 갱신 · 누를 때까지 '다시 계산 필요'만 표시 · 사람 확정 중 하나를 선언한다. 무거운 계산 중에도 연결 확인·Sync·다른 대화 응답은 멈추지 않는다.
  • AI 단계는 초안만 낸다. 설정값·수정 사항을 바꾸거나, 사람 단계를 확정하거나, 호스트에 쓰지 못한다. AI가 성공이라고 말해도 점검 통과만 상태를 만든다. 1차에 AI 단계를 쓰는 곳은 입력 역할 제안이며, 그 밖의 AI 단계는 꺼진 상태로 시작한다.
  • 사람 단계: 확정한 뒤 그 단계가 읽는 입력의 지문이 바뀌면 '다시 확인 필요'로 돌아간다. 해석 확정의 의미와 확정 전 미리보기 해석은 SPEC-06.3을 따른다.
  • Rhino에 만들기는 자동으로 하지 않는다. 결과가 바뀌면 '만든 결과가 오래됨'만 표시한다.
  • 입력 개수만큼 단계가 늘어나는 구성은 두지 않는다. 목록은 한 단계 안에서 처리한다. 사람이 단계를 선으로 잇는 편집기는 두지 않는다.

07 / 수정 사항 — SPEC-07.8

근거: FR-24·16. 사람이 결과의 한 요소를 직접 고친 것(옮김 · 추가 · 빼기 · 값 지정 · 고정)은 수정 사항으로 남아 다시 계산해도 유지된다. 평면에서 끌기, 표에서 고치기, 말, 펜, Rhino에서 고친 것 받기(SPEC-07.13)로 생긴다. AI가 제안한 수정 사항은 사용자가 받아야 기록된다.

  • 같은 요소를 다시 찾는 기준(안정 키): 기둥은 축선 교점 이름, 보는 양 끝 기둥과 역할, 부호가 붙은 뒤에는 부호다. 다시 계산해 초안이 새로 만들어져도 같은 대상을 찾는다. 같은 입력이 ±1 mm 움직여도 키가 바뀌지 않아야 한다(ids-stable).
  • 대상을 잃으면: 축선 이름이 바뀌면 가장 가까운 새 요소로 옮기고 "위치가 바뀐 수정 사항 n개"를 알린다. 옮길 곳이 없으면 '떠 있는 수정 사항'으로 남기고 지우지 않는다.

08 / 실행 위치와 권한 — SPEC-07.9

근거: FR-24·18, SPEC-00.9, ADR-020. 코드가 어디서 도는지는 코드의 출처로 정한다. 물리 방식은 ARCH-03.

출처 실행 위치 규칙
공식 jig·라이브러리 VIDE 엔진 저장소에서 검토한 제품 코드. 무거운 계산은 엔진의 다른 일을 멈추지 않게 따로 돈다
개발자가 저장소에서 작성해 이 PC에서 묶은 jig 엔진 밖의 별도 프로세스 자기 패키지 폴더만 읽고 로그인 정보·키·환경 변수를 받지 않는다. 이 실행 위치는 네트워크를 막지 못하므로 사람이 검토하고 이 PC에서 서명한 코드만 올린다
AI가 쓴 코드(초안, 초안에서 고정한 프로젝트 jig) 입출력이 없는 계산 상자 파일·네트워크·프로세스·환경 변수에 닿을 방법이 없고 메모리·시간 상한이 있다. 무거운 기하는 공식 라이브러리 단계에 맡긴다
다른 PC에서 만든 jig 설치하지 않음 범위 밖
  • 입력은 엔진이 권한 검사 뒤 넘긴다. jig 코드는 스스로 파일·연결·API를 열지 않는다. 넘기는 것은 조립된 역할 형상이지 원본 Sync 전체가 아니다.
  • 출력은 엔진이 형식을 검사한 뒤에만 다음 단계·화면으로 간다. 시간 상한을 넘으면 끊고 이유를 보인다.
  • 할 수 있는 일은 닫힌 목록에서 선언한다: 연결 파일·레이어 목록 보기, 지정 레이어 형상 읽기, 프로젝트 자료의 조건·근거 읽기, 다른 jig 결과 받기, 공식 라이브러리 계산 쓰기, 공식 틀로 Rhino에 만들기(작업본 출력 레이어와 자기 만들기 기록 안에서만), AI 단발 호출·조회 도구, 보고서·표 파일 만들기. 선언은 가져오기·실행 화면에 건축 문장으로 보인다. 목록 밖 능력을 선언한 jig는 등록하지 않는다. 임의 호스트 코드, 외부 프로그램 실행, 네트워크 접근은 공식만 할 수 있다.
  • 유효 권한 = 선언 ∩ 수명 단계·출처가 허용하는 것 ∩ 사용자 승인 ∩ 프로젝트 권한. 초안은 Rhino에 만들기를 미리보기 선이나 합성 문서에서만 한다. 검사는 화면이 아니라 서버 명령 경계에서 하며, 화면에서 숨긴 행동을 직접 요청해도 같은 거절을 받는다(SPEC-00.9).
  • 실행 위치의 격리는 정확성을 보증하지 않는다. 점검·자체 시험·사람 확인이 따로 필요하다. 공식 틀을 포함한 호스트 코드의 종료도 보증하지 않는다(SPEC-02.4).

09 / 선언형 화면 — SPEC-07.10

근거: FR-24·10·14. 새로 만드는 jig 화면은 선언형이다. 어느 공식 부품을 어느 자리에 두고 어느 단계 결과·설정값에 묶는지만 적는다.

  • 부품은 공식 부품 목록에 있는 것만 쓴다. 목록 밖 부품·속성·토큰을 쓰면 등록을 거절한다. 색은 토큰 이름만 쓰고 16진 색은 거절한다. 부품 목록과 모양은 Design이 소유한다.
  • 묶을 수 있는 것은 단계 결과와 설정값뿐이다. 식·코드는 넣지 않는다.
  • 결과는 VIDE 뷰포트 위의 겹침 층(판정색·라벨)과 표로 보이며 호스트 문서를 바꾸지 않는다. 표 행을 누르면 3D에서 찾아가고, 설정값을 움직이면 겹침이 갱신된다. 판정색은 끌 수 있다.
  • 화면에 내부 확인 등급이나 개발 용어를 보이지 않는다.
  • 부품으로 표현할 수 없는 사용자 정의 화면은 이 명세 범위 밖이다. 구조·Sync·자료 jig의 기존 화면은 그대로 쓰고 jig 작업 영역에서 연다.

10 / 보고서 틀 — SPEC-07.11

근거: FR-24·14·22, SPEC-03.6. 보고서는 결과를 주장 문장·핵심 수치·절·원장으로 묶는다.

  • 주장 문장은 결과에 따라 고른 틀 문장에 숫자를 채워 만든다(결정적). 틀마다 참이어야 할 조건을 두며, 조건은 단계 결과·설정값과 숫자의 비교와 '그리고'만 쓰는 닫힌 형식이다. claim-consistent가 쓰인 틀의 조건이 지금 결과에서 참인지 확인한다. 숫자가 모두 맞아도 주장이 거짓일 수 있기 때문이다.
  • AI 다듬기는 선택이고 한 번뿐이다. 다듬은 문장은 원래 틀의 조건을 물려받고 문장 속 숫자가 모두 결과에 있어야 한다(numbers-in-source). 통과하지 못하면 틀 문장으로 되돌리고 '확인 필요'를 붙인다.
  • 첫 쪽에 가정 목록과 검토하지 않은 항목을 싣는다(unchecked-listed). 구조 jig는 하중 조합도 싣는다(SPEC-06.7).
  • 출처 줄에 입력을 읽은 시각, 자료 진술 수(확정 수), 설정값 근거 현황을 둔다.
  • 앱 안의 보고서에는 그 작업본의 설정값으로 돌아가는 버튼을 둔다. 내보낸 파일에는 그 버튼 대신 "VIDE에서 열기: 프로젝트 · 작업본 · 버전" 한 줄만 둔다.
  • 보고서는 자체 포함 HTML로, 표·일람표는 CSV로 내보낸다. 그 밖의 형식은 OQ-08을 따른다. 내보낸 HTML은 외부 요청 없이 열리고 스크립트를 실행하지 않는다.
  • 미확정 미리보기 결과는 보고서에 확정 결과로 쓰지 않는다(SPEC-06.3).

11 / Rhino에 만들기 — SPEC-07.12

근거: FR-24·12·16·18, SPEC-02.2·02.3·02.13, ADR-014, ADR-020, ADR-022. jig는 사용자가 누를 때만, 연결된 열린 문서에 되돌리기 기록으로 쓴다. Rhino에 만들기는 AI를 부르지 않는 결정적 쓰기이며, AI 편집과 같은 바로 적용 경로(SPEC-02.13)로 실행해 작업 이력에 남는다. 이전 판의 작업 사본 → 후보 → 원본 반영은 2026-09-30 사용자 결정으로 대체되었다.

  1. 공식 틀과 데이터: jig는 VIDE가 소유한 공식 틀을 이름으로 부르고 값은 데이터 한 덩어리로만 넘긴다. 값이 호스트 코드 문장이 되지 않는다. 공식이 아닌 jig는 호스트 코드를 담을 수 없다. 1차 공식 틀은 곡선, H형 단면 부재(상단 기준 레일 아래, 웨브 연직), 기둥, 부호 문자다. 키·부호 문자는 정한 문자 규칙을 통과해야 한다(bake-args-safe). 틀과 데이터 형식은 ARCH-03.

  2. 출력 레이어: 작업본에 정한 출력 레이어 바로 아래 한 단계 레이어에만 만든다. 새로 만드는 레이어는 켜짐·잠금 해제 상태다.

  3. 사용자가 누를 때만 시작한다. 누르면 VIDE가 그 문서의 출력 레이어와 이전 만들기 객체를 꺼진 레이어까지 포함해 다시 읽고 그 읽기로 교체 대상을 정한다. 마지막 Live Sync로 정하지 않는다. 실행 직전 문서 판이 그 읽기와 다르면 쓰지 않고 다시 읽게 한다.

  4. 교체는 이전 만들기가 기록한 객체만 한다. 만들기 기록은 결과 키마다 객체 ID·만든 직후의 지문·레이어를 가진다. 객체에 붙이는 태그(Rhino 속성 문자열)는 표시·검색용이고 교체 판단에 쓰지 않는다. 사람이 복사한 객체도 같은 태그를 갖기 때문이다.

    지금 문서의 상태 처리
    기록된 객체이고 지문이 같다 교체한다
    기록된 객체인데 지문이 다르다 사람이 고친 것. 교체하지 않고 따로 보인다(SPEC-07.13)
    기록된 객체가 없다 사람이 지운 것. 다시 만들지 않고 되살리기를 둔다
    태그는 있는데 기록에 없다 사람이 복사한 것. 건드리지 않고 "복사된 객체 n개(그대로 둠)"로 보인다
    태그가 없다 건드리지 않는다

  5. 지우거나 교체할 객체가 꺼진·잠긴 레이어에 있으면 만들기 전에 막는다(hidden-target). VIDE가 레이어를 켜지 않고 "Rhino에서 레이어를 켠 뒤 다시 누르세요"를 안내한다.

  6. 열린 문서에 바로 만들고 결과를 보인다. 만들기 한 번은 되돌리기 기록 하나로 남긴다(PRD FR-24). 공식 틀은 VIDE가 넘긴 객체 ID 목록만 지우며, 기록에 없는 객체를 지우는 실행은 문서에 남기지 않고 실패로 알린다. 결과 카드에 추가 N · 교체 M · 사람이 고친 것 보존 K · 복사본 그대로 C · 사람이 지운 것 D와 [되돌리기]를 보인다. Rhino 문서가 연결되어 있지 않으면(파일 연결만 있음) VIDE 내부 작업 사본에만 만들어 결과를 보이고 원본 파일은 바꾸지 않으며, 파일을 Rhino에서 열어 연결하라고 안내한다.

  7. 만든 뒤 VIDE가 그 문서를 다시 읽어 만들기 기록의 기준 지문을 남긴다. [되돌리기]는 그 만들기의 기록이 문서의 마지막 되돌리기 기록일 때만 하며 규칙은 SPEC-02.13의 3과 같다. 되돌리면 만들기 기록을 '되돌림'으로 두고 다음 만들기의 교체 대상에서 뺀다.

  8. 부재를 만드는 만들기는 같은 입력 지문의 확정 해석이 있어야 한다(analysis-confirmed). 미확정 미리보기 결과로 부재를 만들지 않는다.

  9. 같은 연결 문서에 대한 만들기와 AI 편집은 그 문서의 대기열에 한 줄로 선다(SPEC-02.9).

  10. 이전 도구가 만든 객체(기록에 없거나 이 작업본의 태그가 아닌 것)는 지우지 않는다. CAD에 만들기는 이 명세 범위 밖이다.

12 / Rhino에서 사람이 고친 것 — SPEC-07.13

근거: FR-24·03·16, SPEC-00.3. 기본은 사람 수정 우선이다. 평소에는 Live Sync로 알림만 띄우고, 교체 여부는 만들기 직전 읽기(SPEC-07.12 3)로 확정한다. 알림은 작업 영역 위에 한 번에 모아 보이고(예: "Rhino에서 5건이 바뀌었습니다: 기둥 높이 3 · 거더 모양 2 · 꺼진 레이어 1(비교 안 함)"), 사람이 받을 때만 작업본에 기록한다.

만든 것 / 바뀐 것 처리
jig와 사람이 함께 쓰는 선(축선·상단선 등)의 위치만 또는 끝점 높이만 바뀜 수정 사항(옮김·높이 지정)으로 받을지 제안한다. 받으면 다시 계산한다
jig가 소유한 결과(부재 솔리드)가 바뀜 "사람이 고친 부재 n개"로 보이고, 다음 만들기에서 유지(교체 제외) · jig 값으로 덮기 · 수정 사항으로 받기(단면만 읽음) 중에서 고르게 한다
모양이 바뀜(제어점 편집 등) 만들기 기록에서 빼고 이후 교체하지 않는 쪽을 제안한다
레이어가 꺼짐 판정하지 않는다. "꺼진 레이어 'jig 부재'(n개)는 비교하지 않았습니다"만 보인다. Sync에서 보이지 않게 된 것을 삭제로 기록하지 않는다
레이어는 켜져 있는데 지워짐 사람이 받으면 입력은 빼기 수정 사항, 결과는 '다시 만들지 않음'으로 기록하고 되살리기를 둔다
복사된 객체 건드리지 않는다. jig 결과로 쓸지 제안만 한다
jig 레이어·입력 레이어에 생긴 태그 없는 새 선 입력(예: 축선)으로 쓸지 제안만 한다
  • '위치만 바뀜' · '높이만 바뀜' · '모양 바뀜'은 같은 방식으로 읽은 지문끼리 비교해 가린다(방식은 ARCH-03).
  • 사람이 받지 않은 변화는 작업본을 바꾸지 않는다. 받은 값(예: Rhino에서 고친 기둥 높이)은 다음 계산부터 지켜진다.
  • 수정 사항으로 받기의 뜻: 받으면 그 객체의 받을 때 지문이 작업본의 수정 사항으로 남고, 이후 만들기는 그 객체를 jig 결과를 대신하는 것으로 보아 지우지도 다시 만들지도 않는다("수정 사항으로 받은 것 n개"). 단계가 그 수정 사항의 값(예: 단면)을 읽어 결과에 반영하는 것은 단계의 몫이며, 반영하지 않아도 사람의 객체는 교체되지 않는다. 받은 뒤 Rhino에서 다시 고치면 다시 '사람이 고친 것'이 되고, '덮기'를 고르면 jig 값으로 교체하며, 그 수정 사항을 지우면 기록된 지문 기준의 보통 교체로 돌아간다.

13 / 점검 — SPEC-07.14

근거: FR-24·10·16·18, RESEARCH-05. 점검의 목록과 구현은 VIDE 코어가 소유하고 jig는 이름으로 고른다. 수준은 막음(다음 단계로 가지 않음) · 경고(목록에만 올림) · 분리(통과분만 넘기고 실패분을 이름 붙여 보고)다. 실패 이유는 단계 레일에 건축 문장으로 보인다(예: "거더 3개가 슬래브 경계 밖으로 나갑니다 — Rhino에 만들기를 멈췄습니다").

시점 점검 무엇을 보나
계산 전 inputs-present, inputs-confirmed, units-si, stale-input, fact-valid 필요한 역할이 있음, 사람이 확인함(없으면 만들기 막음), 단위가 SI로 환산됨, 읽은 문서 판이 지금 판과 같음, 근거 진술이 오염·기각이 아님(미확정이면 경고)
계산 뒤 non-empty, no-nan, ids-stable, ring-orientation, polygon-valid 빈 결과·수치 오류 없음, 같은 입력이면 같은 키, 다각형 방향·자기교차
계산 뒤(분야) inside-boundary, span-max, cantilever-max, no-overlap, planar-curve, mark-unique, schedule-complete, combo-echo, unchecked-listed 경계 안, 경간·내민 길이 상한, 최소 거리, 한 연직면 안의 곡선, 부호 중복 없음, 모든 부재가 일람표에 있음, 입력 하중조합과 결과의 조합이 같음, 검토하지 않은 항목이 결과에 있음
AI 뒤 ref-whitelist, numbers-in-source, quote-exists, no-formula-invented, no-plan-dependent-conclusion 없는 부재·진술을 인용하지 않음, 숫자가 결과·자료에 있음, 인용문이 원문에 있음, 자료에 없는 산식을 쓰지 않음, 계획에 따라 달라지는 항목에 결론을 싣지 않음
보고서 전 claim-consistent 주장 틀의 조건이 지금 결과에서 참
만들기 전 solid-closed, tag-scope, count-match, layer-scope, hidden-target, bake-args-safe, analysis-confirmed 닫힌 솔리드, 지울 객체가 모두 만들기 기록에 있음, 만든 수 = 계획 수, 출력 레이어 아래만, 지울 객체가 꺼진·잠긴 레이어에 없음, 키·부호 문자 규칙, 부재는 확정 해석이 있음
  • 점검과 판정을 구분한다. 같은 분야 계산을 두 용도로 쓸 수 있다. 경계 밖 거더는 만들기를 막는 점검이고, 경간 초과는 결과 표의 '초과' 판정이다. 판정은 흐름을 막지 않는다.
  • AI 단계는 표준 점검이 하나 이상 있어야 등록된다.
  • 점검 통과는 설계가 맞다는 뜻이 아니다. 구조 결과의 '탐색용 예비값' 표시는 SPEC-06.7을 따른다.

14 / 자체 시험·가져오기·고정 — SPEC-07.15

근거: FR-24·13·17·18, SPEC-05.1·05.4.

  • 자체 시험: 모든 jig는 합성 입력·설정값·기대 결과로 된 시험 자료를 담는다. 허용오차는 길이 1 mm, 비율 0.001이다. 비공개 원본은 넣지 않는다. 형식 점검(설명서 형식·부품·능력 어휘·단위·점검·금지 파일)과 자체 시험을 통과해야 등록한다. 저장소에서 작성한 jig도 제작 대화와 같은 점검·시험 코드를 통과해야 한다(2026-09-29 사용자 결정, S-06 골조 jig 포함).
  • 패키지 규칙: 선언한 파일만 읽는다. 패키지 밖을 가리키는 경로, 설치·실행 훅, 에이전트 지시 파일(CLAUDE.md, AGENTS.md, GEMINI.md, .claude/, .codex/, .mcp.json)이 있으면 거절한다. 설명서에서 파생되는 값(AI 필요 여부, 실행 위치)은 VIDE가 다시 계산하고 선언과 다르면 등록을 거절한다.
  • 가져오기는 이 PC에서 묶은 것만 받는다. 개발자가 이 PC에서 jig를 묶으면 이 PC 설치본의 비밀 키로 서명된다. 가져오기는 내용 지문을 다시 계산하고 서명을 확인하며, 서명이 없거나 다른 PC의 묶음은 "다른 PC에서 만든 jig는 아직 설치할 수 없습니다"로 거절한다. 같은 id·버전을 다른 내용으로 가져오면 거절한다.
  • 가져오기와 프로젝트에 고정은 사용자가 확인하는 행동이다(SPEC-02.19의 T2). 무엇을 · 어느 프로젝트에 · 할 수 있는 일을 한 장으로 보이고 사용자가 누를 때만 한다. 원격 작업 화면에서는 둘 다 거절한다.
  • 확장 등록·실행의 기존 계약(SPEC-05.1·05.4)과 신뢰하지 않는 업로드 코드를 등록하지 않는다는 원칙은 그대로다. AI가 쓴 초안은 사용자가 올린 코드가 아니며 계산 상자에서만 돈다(SPEC-07.9).

15 / 채팅으로 jig 만들기(1차 최소판) — SPEC-07.16

근거: FR-24·15·18. 2026-09-29 사용자 결정: jig 시스템은 S-06 골조 jig를 만들며 시험하고, 채팅 제작은 M5에서 S-06 보조 jig로 시험한다. 대화 세션·질문 카드·확인 등급은 SPEC-02.19가 정한다.

  1. 시작: 사용자가 JIG 목록의 '말로 만들기' 또는 'jig로 만들어' 같은 말(SPEC-02.17)로 초안을 만든다. 초안은 빈 틀 또는 공식 일반 예제(시작 본)에서 출발하고, 그 초안에 붙은 만들기 대화가 열린다. 초안 하나는 만들기 대화 하나가 쓰고, 고정하거나 버린 초안에는 턴을 보낼 수 없다.
  2. 계획: 무엇을 받아 무엇을 내놓는지(입력·설정값·단계·화면·결과)를 한 장으로 보인다. 이 단계에서는 코드를 쓰지 않는다. 기존 jig·라이브러리의 설정값만으로 되면 그것을 먼저 권한다.
  3. 질문: 모호한 것만 질문 카드(SPEC-02.19)로 묻는다. 기본값이 있으면 쓰고 가정으로 원장에 적는다. 답은 다음 턴으로 이어진다.
  4. 만들기 시작: 사용자가 누르거나 시작하라고 말한다.
  5. 작성: 초안 폴더에만 설명서·단계 코드·화면·시험 자료·AI 설명서를 쓴다. 부품은 공식 목록에서만 고른다. 만들기 턴은 호스트 문서를 읽거나 쓰지 않는다.
  6. 시험: 형식 점검 → 자체 시험(시험 자료가 없으면 합성 자료부터) → 미리보기 계산 → 실패를 읽고 고친다. 파일을 바꿀 때마다 이 순서로 다시 돌린다. 시험은 VIDE가 계산 상자에서 돌리고 결과만 대화에 준다. 마지막 점검·시험 결과는 만들기 화면에도 보인다.
  7. 미리보기: 실제 실행 화면이 시험 자료나 최신 입력 사본으로 돌고 사람이 설정값을 만져 본다. Rhino에 만들기는 미리보기 선으로만 보인다.
  8. 고정 또는 버리기: 사용자가 '이 프로젝트의 jig로 고정'을 확인하면(T2) 점검·자체 시험 통과를 다시 확인한 뒤 이 프로젝트의 jig(출처: AI가 쓴 초안, 계산 상자에서 실행)가 되어 실행 화면에서 열린다. 금지 파일이 있거나 시험이 실패하면 고정하지 않는다. AI는 고정하지 않는다. 버리면 초안 폴더와 그 만들기 대화의 공급자 기록을 함께 지우고 대화를 닫는다.
  9. 작업본으로 돌리기: 고정한 jig는 다른 jig와 같이 작업본을 만들어 프로젝트 입력(예: S-06 작업본의 기둥·E.J.)으로 돌린다.
  • 제작 대화의 경계: 초안 폴더 밖의 파일, 셸, 네트워크에 닿지 않고 VIDE가 주는 jig 도구만 쓴다. 에이전트 지시 파일·설정 파일·패키지 목록·모듈 폴더·연결(링크) 파일은 금지 파일이다. 쓰기 시도는 쓰기 전에 거절하고, 점검이 금지 파일을 찾으면 실패로 돌려준다. 실행 방식은 ADR-021·ARCH-03.
  • 공급자: 만들기 대화는 Claude·Codex 어느 쪽으로도 열며 흐름·경계·상한·멈춤은 같다. Claude는 초안 폴더에 한정한 파일 도구로 직접 쓴다. Codex에는 폴더에 한정한 쓰기 도구가 없으므로 원장으로 작성한다(잠정): 턴 결과로 쓸 파일(초안 안 경로와 전체 내용)을 내고, VIDE가 같은 금지 파일·경로 검사를 거쳐 초안 폴더에 쓴 뒤 원장에 코드 항목으로 남기고 점검·시험을 돌려 결과를 다음 턴에 준다. 검사에 걸린 파일은 하나도 쓰지 않고 이유를 돌려준다. 구현 계약은 ARCH-01 §2(공급자 인자·files 출력)·ARCH-03, 작업은 PLAN-22 T-063이다.
  • 상한과 멈춤: 한 턴(질문 카드의 답 턴 포함) 600초·도구 호출 100회. 상한에 닿으면 그 턴을 멈추고 초안 파일·점검 결과는 그대로 둔다. 20턴을 넘으면 "여기까지 저장하고 새로 시작할까요?"를 묻는다. 같은 시험이 같은 이유로 세 번 잇달아 실패하면 자동으로 다시 고치지 않고 멈춰 마지막 실패와 남은 문제를 보이고 사람에게 묻는다. 권한 밖 도구·금지 파일 쓰기를 요청하면 그 턴을 바로 멈춘다. 멈춘 뒤 이어 가는 것은 사람의 새 말이다.
  • 정본은 초안 폴더의 파일과 대화 원장이다. 대화 세션을 잃거나 다른 AI로 넘겨도 파일·원장으로 새 세션을 열어 이어 간다.
  • 1차에 넣지 않는 것: 코드 읽기 화면, 단계 흐름 그림, 초안 보관함 화면, 버전 비교, 공유 게시. 화면 배치는 Design.
  • 수용(M5): 제작 대화로 S-06 보조 jig 하나("신설 E.J. 선마다 양쪽 기둥과 공통 파일캡이 있는지, 쌍기둥 간격은 얼마인지 보는 도구")를 만들어 프로젝트 jig로 고정하고, S-06 작업본의 기둥·E.J. 입력으로 돌린다. 합격은 10턴 안에 점검·시험 통과, 쌍기둥 판정이 S-06 골조 jig의 결과와 같음, 사람이 코드를 고치지 않음이다. 기록은 PLAN-22가 정한 VERIFY에 남긴다. 반복 실패·턴 초과의 멈춤은 수용과 별도로 확인해 같은 기록에 적는다.

16 / 실패와 복구 — SPEC-07.17

근거: FR-24·16, SPEC-00.6·00.10, SPEC-02.7.

  • 단계 실패(시간 초과·예외·출력 형식 불일치): 그 단계와 뒤 단계를 멈추고 이유를 단계 레일에 보인다. 입력·설정값·수정 사항과 마지막으로 통과한 결과는 보존하되 '다시 계산 필요'로 표시한다. 실행 프로세스가 죽으면 새로 띄워 다시 계산하며 작업본은 영향을 받지 않는다.
  • 입력 문제: 필요한 역할이 없거나 연결 파일이 닫혔으면 해당 단계만 막고, 저장된 입력 사본으로 가능한 열람은 유지한다. 입력 문서 판이 바뀌면 결과를 지우지 않고 '다시 계산 필요'로 둔다.
  • AI 단계 실패: 이전 결과와 사람 확인을 유지하고 제안이 없다고 알린다. 사람은 역할을 직접 지정할 수 있다.
  • 만들기 실패: 실행이 실패하거나 보호에 걸리면 그 만들기의 되돌리기 기록을 되돌려 문서에 아무것도 남기지 않고 이유를 보인다. 만들기 전 점검에 걸리면 이유와 해결 행동을 보인다. 결과가 불명확하면 다시 실행하지 않고 실행 기록으로 해소한다(SPEC-02.7). 만들기는 됐는데 만든 직후 읽기가 실패하면 읽기만 다시 시도하고, 기준 지문을 남기기 전에는 그 기록의 객체를 교체하지 않고 사람이 고친 것처럼 보존한다.
  • 가져오기·고정 실패: 아무것도 설치·고정하지 않고 이유를 보인다. 기존 설치 버전과 작업본은 그대로다.
  • 근거 무효: 근거 진술이 오염·기각되면 해당 설정값에 '근거 무효'를 보이고 fact-valid가 막거나 경고한다. 값을 자동으로 바꾸지 않는다.
  • 제작 대화 실패: 초안 폴더의 마지막 파일과 점검 결과를 유지한다. 공급자 한도·인증 실패는 그 대화의 중지 사유로 남긴다(SPEC-05.5).
  • 한 작업본·한 문서의 실패가 다른 작업본·다른 문서의 계산과 열람을 막지 않는다.

17 / 이 명세 범위 밖

공유·검증 단계와 게시·보관소·AI 도구로 등록, 다른 PC·다른 사용자가 만든 jig의 실행, 부품으로 표현할 수 없는 사용자 정의 화면, CAD에 만들기, 기존 객체를 고치는 jig 조작, 이전 도구 결과의 정리, 위쪽 작업본이 바뀔 때 아래 작업본을 이어서 다시 계산하는 설계 단계 그래프, 제작 화면 전체(코드 보기·흐름 그림·버전 비교). 설계 근거는 RESEARCH-10 §3~§5·§8.7·§9.6·§9.7에 있다.
