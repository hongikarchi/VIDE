# Rhino 호스트 계약과 검증 범위

사용자 지정 시험 버전은 현재 설치본 8.34.26223.11001이다. 이 문서는 §1의 현재 지원표가 정본이며, §2 이후는 날짜순 검증 이력이다. 이력의 "미시험·추가 검증"은 그 날짜 기준이고 현재 상태는 §1로 읽는다.

SDK의 AI query는 기본 50개·최대 100개/64 KiB 페이지와 ID 필터를 지원한다. 다음 페이지는 같은 revision을 요구한다. 소유 합성 문서 120개 실제 조회와 전체 후보 보존을 확인했다([검수](../../tdd/VERIFY-2026-09-24-local-product-completion.md)). 네이티브 가져오기 규모의 확대 검증과 구분한다.

## 1. 현재 지원 상태 — 2026-10-01 기준

2026-09-30 [ADR-022](../../decisions/ADR-022-direct-apply-plan-auto.md) 이후 AI 편집의 제품 경로는 사용자가 연결한 열린 Rhino 문서에서 바로 실행하는 `direct-execute`이다(H-RHINO-06, `hosts/rhino/worker/DirectExecution.cs`). 실행 한 번은 `BeginUndoRecord`/`EndUndoRecord` 기록 하나이고 VIDE의 [되돌리기]는 `direct-undo`로 그 기록만 되돌린다. 계획 모드는 쓰기 도구 없이 조회·캡처·측정만 한다. VIDE가 기동·소유한 별도 Rhino 실행본(같은 `hosts/rhino/worker/` 플러그인)의 작업 사본 실행과 편집 창의 후보 적용 고정 메서드는 jig·가져오기 같은 내부 사본과 이전 결과 호환용으로 남아 있으며 아래 H-RHINO-01~05의 이력 대부분이 그 경로의 실증이다. 현재 문서의 VIDEConnect/VIDEDisconnect 및 VIDESync/VIDELiveSync 연결도 자체 채널을 사용한다. 기존 RhinoMCP 호환 어댑터(TCP 1999)는 호환 경로다. 새 연결은 포트 하나를 공유하지 않고 실행본·문서·세션을 구분한다.

현재 문서 연결의 합성 실증: mm 원본 무변경 연결, 24→48 m³ 네이티브 수정과 Undo, 요청별 수정 위임 후 자동 읽기, 직접 Move 뒤 Live Sync, 토큰/문서 불일치·생성 코드 거절, 재연결 후 이전 대상 거절. [검증 기록](../../tdd/VERIFY-2026-09-28-rhino-attached-sync.md). 실제 사용자 문서 연결은 확인했지만 10,713개 조회 모델의 전체 Sync는 IMPORT_LIMIT으로 거절됐다. 화면 검수는 미완료이며 합성 통과로 일반 BIM 정보·대형 파일 지원을 선언하지 않는다.

그룹 보존 적용: 그룹 표(ID·이름·인덱스·사용자 문자열)와 각 객체의 그룹 소속을 유지하면 그룹 안 기존 객체의 형상·일반 속성 수정도 허용한다. 그룹 생성/이름 변경/해제/구성원 추가·삭제는 적용 전에 거절한다. 잠김·참조·이력·재질 등 다른 적용 제한은 유지한다. 실제 검증 상태는 [로컬 검수](../../tdd/VERIFY-2026-09-24-local-product-completion.md)를 따른다.

3개 층 독립 Brep의 관통 개구부 4×4→6×4m 확대에서 솔리드·체적·GUID·층/역할 속성 보존과 고정 적용/재열기를 실증했다([검수](../../tdd/VERIFY-2026-09-24-local-product-completion.md)). 결정적 SDK 시험이며 임의 Boolean/곡면의 성공 보장이나 기본 UI 편집 검수는 아니다.

편집 창 적용의 지원 범위: 독립 Brep/Extrusion/Curve/Mesh/Point의 형상·사용자 문자열 수정, 추가·삭제와 기존 층. 그룹 소속 변경·구성원 추가/삭제·이력·참조·잠김·재질·층/문서 자원 변경과 미확인 관계는 거절한다. 객체가 없는 층도 전체 활성 층 목록·표시/참조 속성·사용자 문자열 비교에 포함하며 변경을 무시한 성공을 허용하지 않는다. 빈 층 변경 거절과 객체만 이동한 적용/재열기를 검증했다. 적용과 파일 저장은 구분하며, 적용 후 원본 지문이 달라지므로 취득 전 후보를 다시 적용하지 않는다.

새 개발 빌드의 자체 SDK·편집 창 객체 상한은 20,000개다. 10,713개 합성 혼합 문서의 전체 네이티브 재검증과 1,000개 이하 표시 페이지 합산을 확인했다. 블록 인스턴스 13개는 목록·네이티브 파일에 보존되지만 상세 화면 표현은 미지원으로 표시한다. 합산 표시 JSON은 32MiB이며 브라우저 스트리밍/LOD는 미구현이다. 실제 사용자 모델은 플러그인 재연결 후 별도 검증해야 한다. 이전 10,000개 빌드에서의 증거: 합성 1천 박스·1만 점의 네이티브 저장/재열기·ID·수량 캐시와 실제 브라우저 가져오기/선택을 확인했고, 1만 점 중 한 객체 후보를 편집 창에 적용한 뒤 전체 ID 보존을 확인했다([검수](../../tdd/VERIFY-2026-09-24-local-product-completion.md)). 131,072 삼각형 합성 메시의 저장/재열기·브라우저 선택·고정 이동 적용도 확인했다. 819,200 삼각형의 응답 상한 초과에서는 저장 영수증/파일 해시 보존과 재실행 없는 복구 거절을 확인했다. 요청 4 MiB·응답 16 MiB 제한을 유지하므로 개수 이내인 임의 복잡 메시까지 지원을 보장하지 않는다. 레거시 JSON/외부 MCP 경로의 500개 제한과 원격 공유 규모는 별도다.

독립 Rhino·ZWCAD 요청의 실제 동시 실행과 분리 결과 저장을 합성 문서로 확인했다([검수](../../tdd/VERIFY-2026-09-24-local-product-completion.md)). 같은 문서의 동시 쓰기 허용을 뜻하지 않는다.

수동 Sync는 같은 프로젝트·호스트 문서의 이전 취득 결과와 객체 ID·기하 해시·측정 버전이 일치하면 수량을 재사용한다. 실제 변경 형상 재계산과 재시작 후 무변경 재사용을 확인했다. 실행본 내 수정 후 반복 조회의 수량 계산 0건과 tolerance 변경 무효화도 확인했다([검수](../../tdd/VERIFY-2026-09-24-local-product-completion.md)). 단순 박스의 m/mm 환산 및 단위 해석 변경에 따른 수량 무효화도 실증했다. 기본 Undo/Redo의 크기·속성 복원과 삭제 취소에서 ID·수량·캐시 무효화를 확인했으며 일반 복합 Undo 이력과 대형 모델 비용 검증은 남아 있다.

공통 규칙: 제품 어댑터는 프로세스 인스턴스와 문서 런타임 식별자를 연결에 고정한다. 재열기·재연결 시 저장된 경로나 GUID 하나만으로 이전 명령을 재전송하지 않는다. 문서 간 원점/축/단위 변환은 사용자가 확인한 값으로 적용한다. 바로 실행은 바뀐 객체(추가·수정·삭제)와 되돌리기 기록을 남기고 결과를 재조회한다. 사본 경로의 후보는 생성 시 원본 대응과 소유 정보를 기록한다. 보존을 확인할 수 없는 경우 임의 삭제/재생성으로 성공을 위장하지 않는다. 위 표는 첫 완결 과업의 실증 범위이며 전체 MVP 지원 상한의 확정이 아니다. 화면 선택·작업 평면·수동 Sync·사용자 편집 중 충돌은 T-003·005에서 판정한다.

## 2. 검증 이력

### 2.0 headless 실험 — 2026-09-19

[호스트 실험](../../tdd/SPIKE-2026-09-19-host-native.md)에서 RhinoCommon으로 H-RHINO-01~03을 확인했다. 네이티브 객체를 생성·변환·삭제하고 길이·위치를 비교했고, 후보 분리·이동·3DM 재열기 후 사용자 문자열 유지, 저장 후 새 headless 문서에서 GUID 조회와 좌표·단위를 확인했다. headless 실험은 화면 선택·작업 평면·수동 Sync·사용자 편집 중 충돌을 대체하지 않는다.

### 2.1 실제 제품 연결 — 2026-09-20

[작업 공간 검증](../../tdd/VERIFY-2026-09-20-native-workspace.md)에 브라우저 채팅·핀·스케치에서 실제 구독 CLI와 Rhino까지 연결한 결과가 있다. 3dm 파일은 별도 작업 사본으로 가져오며 네이티브 형상·속성을 유지한 이동을 수행한다. 생성된 박스 후보를 식별된 열린 Rhino 문서에 반영하고 후속 후보로 높이를 수정하면서 GUID와 무관한 객체를 보존했다. 독립 Extrusion을 네이티브 형상과 사용자 문자열을 유지해 복사하고 작업 사본에서 이동·삭제·후속 복사를 수행했으며 그룹을 포함한 복사는 거절했다. 당시 경로는 설치된 RhinoMCP 플러그인의 TCP 수신부였다.

### 2.2 열린 문서 취득·이동 적용·사용자 문자열 — 2026-09-20~21

명시한 문서 인스턴스에서 원본 상태를 유지한 작업 사본 취득을 연결했다. 취득 시각·원본 단위·문서 대응을 기록하며 현재 상태는 미확인으로 표시한다. 합성 솔리드·점 2개를 취득하고 원본 형상/속성·이름·경로·저장 상태·선택 보존을 확인했다. 같은 취득 기준에서 만든 이동 후보를 원본에 반영하고 GUID·공개 스칼라 속성·사용자 문자열·무관한 형상 보존을 확인했다. 저장된 작업 사본의 ObjectAttributes 사용자 문자열을 읽어 Inspector에 출처와 함께 표시하고 요청에 첨부할 수 있으며, 읽기 한도로 누락된 값은 일부 취득으로 표시한다. 증거는 [작업 공간 검증](../../tdd/VERIFY-2026-09-20-native-workspace.md)의 열린 문서 취득·취득 원본 이동 적용·Rhino 사용자 속성 확인 절이다.

### 2.3 자체 SDK 실행기와 편집 창 적용 — 2026-09-22

제품 경로를 VIDE 소유 실행본의 자체 .NET 8 플러그인으로 전환했다. 소유 프로세스 확인·토큰 인증·헤드리스 재읽기 검증을 갖추고, 구독 AI가 작성한 SDK 코드를 작업 사본에서 실행한다. VIDE에서 복사해 연 Rhino 편집 문서에 SDK 후보의 형상·사용자 문자열 수정, 추가·삭제를 반영하고 기존 GUID·무변경 객체를 보존했다. 실제 브라우저에서 영향 검토→적용→재취득과 체적 24→48을 확인했다. Brep·Point 복합 적용 뒤 독립 Curve·Extrusion·Mesh·Point의 이동/속성 후보 적용·재취득·독립 재열기도 확인했다([검수](../../tdd/VERIFY-2026-09-24-local-product-completion.md)). 그룹·재질·관계 일반화나 각 유형의 기본 호스트 수동 편집 검수는 별도다. 제어기 재시작 후 편집 창 pairing 복원과 응답 유실 영수증도 확인했다. 상세 증거는 [자체 연결 적용 검증](../../tdd/VERIFY-2026-09-22-typescript-foundation.md)의 해당 절이다.
