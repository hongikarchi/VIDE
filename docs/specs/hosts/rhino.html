Rhino 호스트 계약과 검증 범위

사용자 지정 시험 버전은 현재 설치본 8.34.26223.11001이다. 이 문서는 §1의 현재 지원표가 정본이며, §2 이후는 날짜순 검증 이력이다. 이력의 "미시험·추가 검증"은 그 날짜 기준이고 현재 상태는 §1로 읽는다.

01 / 현재 지원 상태 — 2026-09-23 기준

제품 경로는 VIDE가 기동·소유한 별도 Rhino 실행본의 자체 .NET 8 플러그인(hosts/rhino/worker/)이다. AI 코드는 작업 사본에서 실행하고, 편집 창(VIDE가 복사해 연 문서)에는 검토한 후보를 적용하는 고정 메서드만 제공한다. 사용자가 직접 연 외부 실행본에는 기존 RhinoMCP 호환 어댑터(TCP 1999)가 남아 있으며 제품 지원 경로로 확대하지 않는다.

편집 창 적용의 지원 범위: 독립 Brep/Extrusion/Curve/Mesh/Point의 형상·사용자 문자열 수정, 추가·삭제와 기존 층. 그룹·이력·참조·잠김·재질·층/문서 자원 변경과 미확인 관계는 거절한다. 적용과 파일 저장은 구분하며, 적용 후 원본 지문이 달라지므로 취득 전 후보를 다시 적용하지 않는다.

공통 규칙: 제품 어댑터는 프로세스 인스턴스와 문서 런타임 식별자를 연결에 고정한다. 재열기·재연결 시 저장된 경로나 GUID 하나만으로 이전 명령을 재전송하지 않는다. 문서 간 원점/축/단위 변환은 사용자가 확인한 값으로 적용한다. 후보는 생성 시 원본 대응과 소유 정보를 기록하고 결과를 재조회한다. 보존을 확인할 수 없는 경우 임의 삭제/재생성으로 성공을 위장하지 않는다. 위 표는 첫 완결 과업의 실증 범위이며 전체 MVP 지원 상한의 확정이 아니다. 화면 선택·작업 평면·수동 Sync·사용자 편집 중 충돌은 T-003·005에서 판정한다.

02 / 검증 이력

2.0 headless 실험 — 2026-09-19

호스트 실험에서 RhinoCommon으로 H-RHINO-01~03을 확인했다. 네이티브 객체를 생성·변환·삭제하고 길이·위치를 비교했고, 후보 분리·이동·3DM 재열기 후 사용자 문자열 유지, 저장 후 새 headless 문서에서 GUID 조회와 좌표·단위를 확인했다. headless 실험은 화면 선택·작업 평면·수동 Sync·사용자 편집 중 충돌을 대체하지 않는다.

2.1 실제 제품 연결 — 2026-09-20

작업 공간 검증에 브라우저 채팅·핀·스케치에서 실제 구독 CLI와 Rhino까지 연결한 결과가 있다. 3dm 파일은 별도 작업 사본으로 가져오며 네이티브 형상·속성을 유지한 이동을 수행한다. 생성된 박스 후보를 식별된 열린 Rhino 문서에 반영하고 후속 후보로 높이를 수정하면서 GUID와 무관한 객체를 보존했다. 독립 Extrusion을 네이티브 형상과 사용자 문자열을 유지해 복사하고 작업 사본에서 이동·삭제·후속 복사를 수행했으며 그룹을 포함한 복사는 거절했다. 당시 경로는 설치된 RhinoMCP 플러그인의 TCP 수신부였다.

2.2 열린 문서 취득·이동 적용·사용자 문자열 — 2026-09-20~21

명시한 문서 인스턴스에서 원본 상태를 유지한 작업 사본 취득을 연결했다. 취득 시각·원본 단위·문서 대응을 기록하며 현재 상태는 미확인으로 표시한다. 합성 솔리드·점 2개를 취득하고 원본 형상/속성·이름·경로·저장 상태·선택 보존을 확인했다. 같은 취득 기준에서 만든 이동 후보를 원본에 반영하고 GUID·공개 스칼라 속성·사용자 문자열·무관한 형상 보존을 확인했다. 저장된 작업 사본의 ObjectAttributes 사용자 문자열을 읽어 Inspector에 출처와 함께 표시하고 요청에 첨부할 수 있으며, 읽기 한도로 누락된 값은 일부 취득으로 표시한다. 증거는 작업 공간 검증의 열린 문서 취득·취득 원본 이동 적용·Rhino 사용자 속성 확인 절이다.

2.3 자체 SDK 실행기와 편집 창 적용 — 2026-09-22

제품 경로를 VIDE 소유 실행본의 자체 .NET 8 플러그인으로 전환했다. 소유 프로세스 확인·토큰 인증·헤드리스 재읽기 검증을 갖추고, 구독 AI가 작성한 SDK 코드를 작업 사본에서 실행한다. VIDE에서 복사해 연 Rhino 편집 문서에 SDK 후보의 형상·사용자 문자열 수정, 추가·삭제를 반영하고 기존 GUID·무변경 객체를 보존했다. 실제 브라우저에서 영향 검토→적용→재취득과 체적 24→48을 확인했다. 실제 복합 적용 시험은 Brep와 Point다. 제어기 재시작 후 편집 창 pairing 복원과 응답 유실 영수증도 확인했다. 상세 증거는 자체 연결 적용 검증의 해당 절이다.
