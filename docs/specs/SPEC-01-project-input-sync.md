# 프로젝트·공간 입력·수동 동기화


## 모델·도면을 가져와 작업 대상을 찾는다 — SPEC-01.9

근거: PRD §8.1~2·§12.2, FR-01·02·03·05·09. **설계자는 이 기능으로 Rhino의 모델과 ZWCAD의 도면을 프로젝트 안에서 확인하고, 다음 요청이 다룰 대상을 고른다.** 로컬 작업자가 지원 호스트에 문서를 연 상태에서 시작한다.

1. 프로젝트를 만들거나 다시 연다. 프로젝트는 연결 문서, 자료, 작업과 결정을 함께 보여 준다. 기존 작업을 열면 그 목표·입력·마지막 결과로 돌아간다.
2. 호스트 플러그인의 Link로 열린 문서를 프로젝트에 연결한다(§ '프로젝트 연결 파일'). 연결 등록만으로 원본을 변경하지 않는다.
3. 연결하면 바로 Sync되어 지원 형상과 객체 속성·문서 단위를 취득하고 자체 뷰와 객체 목록에 표시한다. 한 프로젝트에 여러 파일을 연결할 수 있고 보이기로 둔 파일은 한 공간에 함께 표시된다. 읽지 못한 종류와 범위도 확인할 수 있다.
4. 자체 뷰에서 확대·이동·회전, 평면 보기 또는 **걷기**로 대상을 찾고 객체를 선택한다. 걷기는 카메라 방식이다: 눈높이로 서서 이동·둘러보고, 바닥을 따라 계단을 오르며, 벽은 통과하지 않는다(끌 수 있다). 층은 그 자리에서 위·아래로 옮긴다. 걷는 동안에도 클릭·창 선택과 고정은 그대로 쓰고, 스케치 도구·다른 보기·맞춤은 걷기를 끝낸다. 나가면 걷던 자리에서 보던 곳을 중심으로 돌아온다(2026-10-06 사용자 결정, PLAN-37). 객체 목록의 유형·레이어·이름으로도 찾을 수 있다. 선택한 객체의 이름·유형·호스트·문서·지원 속성과 마지막 취득 기준을 확인한다.
5. 선택한 객체를 요청의 변경 대상·유지 대상·참고 대상으로 넣거나, 연결된 코멘트·조건·표의 근거를 연다. 보는 대상을 바꿔도 이미 작성한 요청은 유지한다.

연결된 Rhino 문서의 선택은 VIDE가 문서별로 따라 보이고, Rhino와 고정 묶음을 함께 쓴다(SPEC-01.11의 4). ZWCAD 등 다른 호스트에서 고른 객체는 ‘호스트 선택 가져오기’(패널의 선택 첨부)로 지정 문서의 현재 선택을 명시적으로 읽는다. 그 객체의 대응 자료가 없으면 필요한 Sync를 안내한다. VIDE의 선택은 호스트로 보내지 않고, 카메라는 어느 쪽으로도 동기화하지 않는다.

**결과:** 설계자는 코드나 객체 ID를 직접 입력하지 않고 실제 형상/목록을 통해 요청 대상을 지정할 수 있다. 미분류 형상도 지원 유형이면 선택·참조할 수 있으며 건축 속성 DB를 먼저 완성하도록 요구하지 않는다. 형상 표현·레이어/속성의 호스트별 읽기 범위는 지원표의 검토안과 실증 범위를 구분한다(OQ-03).

**예외:** 연결 실패·불완전 취득은 §2·6, 참조 끊김은 §1·5를 따른다. 연결이 없어도 저장된 자료·의견은 열 수 있지만 현재 호스트 상태라고 표시하지 않는다.

## 문장·핀·스케치로 한 요청을 만든다 — SPEC-01.10

근거: PRD §8.2·§9.2·§10.3, FR-05·06·07·08·16. **같은 입력기에 설계 의도와 공간 참조를 함께 작성한다.** 코멘트에서 시작하거나 작업 대화에서 시작해도 같은 핀·선·자료를 사용한다.

예를 들어 설계자는 “이 [경계 A]의 북쪽을 [그린 선]까지 늘려 줘. [유지 대상 B]는 그대로 두고 폭은 유지해”라고 입력한다. 대괄호는 이름을 추측하는 일반 텍스트가 아니라 선택한 실제 대상/스케치 참조다. ‘북쪽’이 문서 기준으로 정의되지 않았으면 선택한 변·방향 화살표 등으로 확인한다.

| 사용자 입력 | 프로그램의 동작 | 사용자가 확인할 결과 |
|---|---|---|
| 선택 객체를 문장에 삽입 | 작성 시점의 객체 참조를 핀으로 고정 | 핀을 열어 문서·형상·역할 확인 |
| 평면에 선을 그리거나 좌표·치수 입력 | 평면·단위와 원본 점열 보존 | 원래 선·선 역할·기하 입력으로 사용할 기준 |
| “유지”, “여기까지”, “이 방향” 지정 | 변경/보존 대상과 목표를 요청 맥락에 연결 | 빠뜨린 대상·모호한 해석을 실행 전에 교정 |
| 코멘트·결정·지원 자료 참조 추가 | 특정 자료 버전과 출처 연결 | 어떤 자료가 필수조건/참고이며 AI에 전달되는지 확인 |
| 코멘트 저장 | 입력을 프로젝트에 보존 | AI 없이도 다시 열고 편집 가능한 의견 |
| 이 입력으로 작업 요청 | 저장된 입력을 실행 문맥에 연결 | SPEC-02.11의 작업 구성과 실행으로 진행 |

현재 선택·작업·기존 확정 조건으로 채울 수 있는 문맥은 자동 구성한다. 사용자가 매번 WorkScope·Task·Run을 만들거나 모든 문서를 다시 선택하지 않는다. 다른 목적의 새 작업과 기존 작업의 후속 지시는 구분해서 연결한다. 모든 문장을 명령으로 실행하지 않으며, 의견 저장·설명 질문·설계 변경 요청의 실제 효과를 실행 전에 알 수 있어야 한다.

스케치 해석이 필요하면 원본 선과 해석 경계를 함께 표시한다. 닫힘/평면/단위/어느 변을 바꿀지 등의 중요한 모호함만 묻는다. 사용자가 수정한 원본 선으로 다시 해석하고, AI가 정리한 선을 사용자의 입력으로 덮어쓰지 않는다. 읽기 가능한 자료 형식과 이미지의 공간 정합은 지원 범위를 표시하며 임의 파일 전부를 이해한다고 약속하지 않는다.

**수용 결과:** 선택을 바꿔도 핀은 유지되고, 카메라를 바꿔도 같은 평면의 선이 남으며, 입력만 저장한 경우 원본은 바뀌지 않는다. 이후 “이 요청으로 작업”을 하면 같은 대상·선·치수·유지 조건을 다시 입력할 필요가 없다(AC-01~04·13·14·31).

## 파일·이미지 첨부와 첨부 메뉴 — SPEC-01.12

근거: FR-05·07, SPEC-01.10(지원 자료 참조 추가). 2026-10-01 사용자 결정: 첨부는 파일을 보관한 위치를 알려 주고 AI가 그 파일을 읽으러 가는 방식이므로 형식을 제한하지 않는다. 첨부 버튼은 파일 첨부만 하고, 객체 고정·그리기(모드)는 각자의 자리에서 한다. 요청의 대상 파일은 사용자가 고르지 않는다(SPEC-01.11의 5, 2026-10-02).

1. **첨부하는 방법.** 작성기의 첨부(클립) 버튼은 메뉴 없이 바로 파일 선택 창을 열고 여러 파일을 한 번에 고른다. 형식은 제한하지 않는다. 작성기에 이미지·파일을 붙여넣거나 끌어 놓아도 같은 첨부가 된다. 파일 크기·개수 상한은 없다(ADR-031 7). 고른 묶음 가운데 하나라도 상한을 넘으면 그 묶음 전체를 첨부하지 않고 이유를 보인다.
2. **보관.** 엔진이 파일을 프로젝트별 첨부 폴더(VIDE 데이터 폴더 안)에 내용으로 정한 이름으로 복사해 둔다. 사용자의 원본 파일은 열어 두거나 바꾸지 않는다. 요청에는 첨부 ID·이름·크기·형식·위치와 복사본인지 여부만 담고 파일 내용은 담지 않는다. 첨부는 늘 복사한다. 원본 위치의 파일은 첨부하지 않고 프로젝트 폴더의 읽기 전용 접근(SPEC-01.13)으로 AI가 직접 읽는다. 같은 내용을 다시 첨부하면 같은 보관본을 쓴다. 프로젝트를 지우면 그 첨부 폴더도 지운다(SPEC-01.1).
3. **AI가 읽는 범위.** 첨부가 있는 턴의 AI는 그 요청과 같은 대화의 앞선 요청에 붙은 첨부를 보관 경로로 읽는다. 패킷의 'file' 항목에 보관본의 경로가 있고, AI CLI의 기본 읽기 도구(SPEC-01.13의 2)가 그 경로를 묻지 않고 읽는다(2026-10-02 [ADR-031](../decisions/ADR-031-stock-first.md) 8, 전용 첨부 도구 없음). 다른 대화·다른 프로젝트의 첨부는 VIDE 데이터 폴더 안이라 늘 거절된다(SPEC-01.13의 4). 계획 모드에서도 읽을 수 있다. 형식별로 무엇을 읽을 수 있는지는 공급자 도구가 정한다(예: 텍스트·이미지·PDF는 Claude의 Read가 읽는다). Rhino 3DM·DWG는 파일에서 열거나 Link로 열어 모델 도구로 읽는다. AI는 읽지 못한 내용을 읽은 것처럼 답하지 않고, 필요한 형태(쪽 이미지·텍스트·연결)를 사용자에게 요청한다.
4. **화면.** 첨부한 파일은 작성기의 문맥 줄에 칩으로 보이며 이미지는 작은 미리보기를 함께 보인다. 칩의 ×로 뺀다. 보낸 요청의 첨부는 그 요청의 작업 보기 '조건'의 첨부에 보인다: 보관한 이미지는 이름을 눌러 엔진의 첨부 이미지 보기로 새 탭에서 열고, 그 밖의 보관 파일은 이름·크기만 보인다(엔진은 첨부 가운데 이미지만 화면에 내보내고 다른 파일은 AI가 보관 경로로 읽는다). 왼쪽에 첨부를 따로 모은 목록은 두지 않는다(2026-10-02 사용자 결정, PLAN-26 T-109).
5. **첨부 버튼에 두지 않는 것.** 객체 고정은 뷰포트 선택 막대의 [요청에 고정]과 문장 커서의 현재 선택 넣기(SPEC-01.10), 연결된 Rhino의 선택 따라 보기와 패널의 선택 첨부(SPEC-01.9·11)로 한다. 스케치는 뷰포트 도구 막대의 연필로 그린 뒤 첨부한다(§5.4). 요청이 다룰 파일은 고르는 자리가 없다: 열린 연결 파일 가운데 어느 것을 고칠지는 AI가 정한다(SPEC-01.11의 5, 2026-10-02 T-103). 예전의 연계 대상 창(SPEC-02.14)과 작성기의 대상 파일 칩은 없앴다.
6. **붙여넣은 경로는 칩(2026-10-06 사용자 결정 "파일 경로 복붙하면 pin처럼 block으로").** 작성기에 이 PC의 절대 경로(드라이브 `C:\…`, 공유 `\서버\…`, 따옴표로 감싼 경로, 공백이 든 경로, 여러 줄에 걸친 여러 경로)를 붙여넣으면, 엔진이 이 PC에 있는지 확인한 경로마다 문장 안의 토큰으로 바꾼다: 파일은 `[파일 · 도면.dwg]`, 폴더는 `[폴더 · 2601 자료]`. 직접 쳐서 적은 경로는 끝난 뒤에(닫는 따옴표나 줄바꿈) 같은 확인을 한다. 토큰은 고정 토큰(SPEC-01.10)처럼 칩으로 그리고 한 덩어리로 지우며(Backspace·Delete), 칩 위에 마우스를 올리면 전체 경로가 보인다. 이름이 같은 다른 경로는 `(2)`처럼 번호를 붙여 구분한다. 없는 경로, 드라이브·공유 맨 위, SPEC-01.13의 4의 위치와 비밀 파일은 글자 그대로 둔다.
   - **보낼 때.** 파일 칩은 2의 복사 첨부가 된다(형식·크기 제한 없음, 첨부 버튼으로 고른 것과 같다). 문맥 줄에도 첨부 칩으로 보이고 AI는 3대로 읽는다. 폴더 칩은 복사하지 않고 그 요청(턴)의 읽기 허락이 된다: 사용자가 그 경로를 붙여넣은 것이 허락이므로 그 턴의 AI는 그 폴더 안을 묻지 않고 읽는다(SPEC-01.13의 3의 [이번만] 읽기와 같은 범위, 쓰기·실행은 그대로 묻는다). AI는 요청의 '폴더' 항목으로 경로를 받는다. 칩을 지운 경로는 보내지 않는다.
   - **이미지.** 이미지 파일 칩도 보낼 때 첨부가 되므로 참고 의도 말이 있으면 SPEC-09.11의 1 카드가 그대로 묻는다. 칩으로 바뀐 경로는 SPEC-09.11의 2 경로 카드가 다시 묻지 않는다(칩이 되지 않은 경로만 묻는다).
   - **원격 세션.** 이 PC가 아닌 기기(사이트·iPad)에서는 경로를 확인하지 않고 글자 그대로 두며 '원격 세션에서는 이 PC의 경로를 칩으로 바꾸지 않습니다' 한 줄을 보인다. 엔진도 원격 세션의 경로 확인·복사·폴더 허락을 거절한다(SPEC-09.11의 3과 같다).
7. **이전 요청.** 이 결정 전 요청에 담긴 본문 첨부(TXT·MD·CSV·JSON, 파일당 50,000바이트 이하)는 그대로 읽고 다시 실행할 수 있다. 검토 의견·외부 의견·객체 속성처럼 VIDE가 만든 작은 본문 자료는 지금도 요청에 본문을 담는다.

**수용 결과:** 클립 버튼으로 PDF·PNG·3DM 같은 TXT 아닌 파일이 첨부되고, 붙여넣은 이미지가 미리보기 칩으로 보이며, AI가 첨부 이미지를 보고 답한다. 다른 대화의 첨부 ID로 읽으면 거절된다. 붙여넣은 파일 경로와 폴더 경로가 각각 `[파일 · …]`·`[폴더 · …]` 칩이 되고 Backspace 한 번에 칩 전체가 지워지며, 보내면 파일은 첨부로, 폴더는 그 턴의 읽기 허락과 경로로 간다.

## 프로젝트 폴더와 AI의 파일 도구 — SPEC-01.13

근거: FR-01·05·07, SPEC-01.12(2의 '프로젝트 폴더의 읽기 전용 접근'), SPEC-02.19의 7(확인 등급). 2026-10-01 사용자 결정: 대시보드에서 프로젝트에 해당하는 폴더를 정하고, AI는 그 안의 파일을 직접 읽으며, 밖의 파일은 읽으려 할 때 사용자에게 권한을 묻는다. 경로 없이 붙여넣거나 끌어 놓은 내용은 SPEC-01.12의 복사 첨부 그대로다. 2026-10-02 사용자 결정([ADR-031](../decisions/ADR-031-stock-first.md) 8): "가능한 순정의 기능을 쓰고 vide의 기능은 도와주는 역할", "프로젝트 작업 폴더 안으로 묶어서 켜고, 만약 외부 폴더를 할 경우에는 사용자 승인을 받는 방식" — VIDE의 읽기 전용 파일 도구 대신 AI CLI의 기본 읽기·검색·쓰기·셸 도구를 프로젝트 폴더(작업 폴더) 안에서 쓴다.

1. **프로젝트 폴더.** 한 프로젝트에 폴더를 여러 개 정할 수 있다(예: `…\Desktop\로컬 2601-나진상가 공공기여`). 대시보드의 '프로젝트 폴더' 구역에서 목록을 보고 [폴더 추가]로 더하고 행의 [빼기]로 뺀다. PC 프로그램 창에서는 [폴더 추가]가 Windows 탐색기와 같은 폴더 선택 창(즐겨찾기·주소 표시줄·검색이 있고 크기를 조절·기억)을 VIDE 창 앞에 열고, 고른 폴더를 그대로 더한다. 취소하면 아무것도 바뀌지 않는다. 선택 창을 열지 못하면 경로 입력칸이 이유와 함께 열린다. 브라우저에서는 경로를 붙여넣어 더한다. 엔진은 경로가 이 PC에 있는 폴더인지 확인하고, 드라이브 맨 위(`C:\` 등), VIDE 데이터 폴더와 그 안, 4의 금지 위치와 그 안은 거절하고 이유를 보인다. 다른 드라이브·연결된 네트워크 드라이브·공유(UNC)의 폴더도 같은 드라이브의 폴더와 똑같이 쓴다(2026-10-08 사용자 보고). 연결·subst 드라이브로 적은 폴더는 실제 경로(예: `Z:\…` → `\\서버\공유\…`)로 저장하고, 도면·외부 참조·AI 도구가 같은 파일을 드라이브 문자로 적어도 그 폴더 안의 파일로 보며, 4의 금지 위치는 적힌 경로와 실제 경로 모두로 검사한다. 폴더를 빼도 그 안의 파일은 그대로다. 프로젝트를 지우면 목록도 지운다(SPEC-01.1). 폴더 목록을 바꾸는 일은 이 PC에서만 한다(원격 세션은 보기만).
2. **AI가 쓰는 도구.** AI는 공급자의 기본 도구를 쓴다: Claude는 읽기·찾기(Read·Glob·Grep), 고치기·쓰기(Edit·Write), 셸(Bash). Codex는 셸·파일 변경(apply_patch)·이미지 보기. 작업 디렉터리는 첫 프로젝트 폴더이고, 다른 프로젝트 폴더와 읽기 허용 폴더(3)는 묻지 않고 닿는다(읽기 허용 폴더는 읽기만). 프로젝트 폴더가 없으면 빈 임시 폴더에서 돌며 그 밖은 모두 3을 따른다. 계획 모드에서는 읽고 찾기만 하고 파일을 쓰지 않는다. Rhino·CAD 문서는 이 도구나 그 파일로 열거나 고치지 않고 실행 도구(`execute`, 되돌리기 기록)로만 고친다. 묻거나 거절한 경로는 그 요청의 진행 기록에 경로만 남는다(내용은 남기지 않음). 셸 명령은 인자에 적힌 경로로 판정하며 프로그램이 스스로 여는 경로까지 막지는 못한다(방어선이지 OS 경계가 아니다). Codex의 작업 중 묻기를 끈 경로(`codex exec`)는 승인을 받을 통로가 없어 이 도구를 주지 않는다.
3. **폴더 밖은 그때마다 사용자 승인.** 프로젝트 폴더와 읽기 허용 폴더 밖을 읽거나, 프로젝트 폴더 밖에 쓰거나 그곳의 경로로 명령을 실행하려 하면 엔진이 그 호출을 멈추고 질문 카드(SPEC-02.19의 6 모양)로 묻는다.
   - 읽기: 'AI가 프로젝트 작업 폴더 밖의 파일을 읽으려 합니다 · (경로)' — [이번만] [이 폴더는 항상] [거절](권장). 쓰기·실행: '…밖에 파일을 쓰려 합니다'·'…밖에서 명령을 실행하려 합니다 · (경로)' — [이번만] [거절](권장).
   - [이번만]은 그 요청(턴)이 끝날 때까지 그 폴더(파일이면 그 파일이 든 폴더)에 같은 동작을 허락한다(쓰기 허락은 읽기도 포함). 다음 턴에는 다시 묻는다.
   - [이 폴더는 항상](읽기만)은 그 폴더를 이 프로젝트의 '읽기 허용 폴더'에 더한다. 읽기 허용 폴더는 대시보드의 같은 구역에 프로젝트 폴더와 구분해 보이며 [빼기]로 뺀다. 원격 세션에서 고르면 [이번만]으로 처리한다(1).
   - [거절]이나 답 없이 닫힘·시간 초과(5분)면 그 호출 하나만 거절하고 AI에 거절로 알린다. 턴은 계속된다. AI는 같은 곳을 같은 턴에 다시 시도하지 않고, 필요한 파일을 첨부하거나 폴더를 정해 달라고 말로 요청한다.
   - 묻는 동안 그 호출은 기다리고, 기다리는 시간은 턴의 시간 제한에 들지 않는다(SPEC-02.6). 질문 카드를 보일 대화가 없는 단일 요청에서는 묻지 않고 거절한다.
4. **늘 거절하는 위치.** 프로젝트 폴더·허용 폴더 안이거나 사용자가 허락해도 다음은 읽거나 쓰지 않는다: VIDE 데이터 폴더(첨부 보관본은 그 턴의 첨부 경로만, SPEC-01.12의 3), 사용자 폴더의 `.ssh`·`.aws`·`.gnupg`·`.azure`·`.kube`·`.docker`·`.claude`·`.codex`, Windows 자격 증명 폴더, 브라우저 사용자 정보 폴더, 그리고 이름으로 알아보는 비밀 파일(`.env`류, `.git-credentials`, `.netrc`, `.npmrc`, `.pypirc`, `id_rsa`·`id_ed25519` 같은 SSH 키, `*.pem`·`*.key`·`*.pfx`·`*.p12`·`*.kdbx`, `credentials`류). 목록 결과에서도 이 항목은 뺀다. 거절은 권한 질문 없이 바로 한다. 정확한 목록은 ARCH-01 §3이 소유한다.
5. **붙여넣은 폴더.** 작성기의 폴더 칩(SPEC-01.12의 6)으로 보낸 폴더는 그 요청(턴) 동안 읽기 허용 폴더처럼 묻지 않고 읽는다. 보낼 때 엔진이 1의 폴더 검사(있는 폴더, 드라이브 맨 위·VIDE 데이터 폴더·4의 위치 아님)를 다시 하며, 원격 세션에서 보낸 폴더는 거절한다. 다음 턴에는 다시 묻는다. 4의 위치는 그 안이어도 거절한다.
6. **경로의 해석.** 상대 경로는 작업 디렉터리(첫 프로젝트 폴더) 기준이다. 바로 가기 연결(심볼릭 링크·정션)은 실제 위치로 풀어 판정한다: 프로젝트 폴더 안의 연결이 폴더 밖을 가리키면 폴더 밖으로 보고 3처럼 묻는다. 아직 없는 파일(새로 쓸 파일)은 가장 가까운 상위 폴더의 실제 위치로 판정한다.

**수용 결과:** 대시보드에서 폴더를 더하고 빼면 목록이 바뀐다. 프로젝트 폴더 안의 파일을 AI가 묻지 않고 읽고 쓰며 그 안에서 명령을 실행한다. 폴더 밖 읽기는 질문 카드가 뜨고 세 답이 각각 이번 턴 허용·허용 폴더 추가·거절로, 폴더 밖 쓰기·실행은 두 답이 이번 턴 허용·거절로 처리되며, 거절해도 턴은 이어진다. `.ssh` 안 파일은 허락과 관계없이 거절된다.

## 대시보드의 할 일과 일정 — SPEC-01.14

근거: FR-01(프로젝트 작업 문맥), SPEC-02.19의 7(확인 등급). 2026-10-01 사용자 요청('Dashboard에 오늘의 할일 / 일정 이런거 적혀있으면 좋을 듯. 편집도 가능하도록.')과 같은 날 추천안 수락으로 PLAN-26 T-079의 '대시보드 내용 결정'을 정했다. 달력 보기와 종류는 2026-10-02 사용자 결정('대시보드 켈린더 좋아요~ 구글 캘린더 연동은 아직. 여러 프로젝트 합친 달력도 아직.')과 추천안 수락이다(PLAN-26 T-110). 할 일·일정 구역의 분리(3), 글·파일에서 할 일 만들기(9), 퇴근하기(10)는 2026-10-06 사용자 요청('달력이랑 to-do list는 분리될 것', '내용(협의 내용, 회의록, 이메일 등)을 적거나 파일을 한번에 넣으면 to-do list 만들어주는 기능', '오늘의 할 일 느낌으로 다 끝내면 퇴근하기같은 느낌')이며 세부 기본값은 같은 날 작업 지시가 정했다(PLAN-30). 기간·하루 종일·여러 날 일정, 종류 넷, 위치·참석자, 날짜를 눌러 여는 일정 폼은 2026-10-06 사용자 요청('일정에 시간을 범위로 넣을 수 있어야 할 듯(캘린더처럼. 혹은 하루 종일 체크. 여러 날짜에 겹쳐서 일정을 넣을 수도 있도록)', '일정 종류에 할일/협의/접수/마감 이렇게 있어야 할 듯', '위치/참석자 이렇게도 정보 기입 가능하도록', '달력이 좀 더 크게 … 위쪽 일정 아래 날짜 표기칸 필요 없어보임 … 아래쪽 날짜 없음도 무슨 기능인지 모르겠음')과 같은 날 배치 선택 '안 A: 할 일 | 큰 달력, AI 접기'다(PLAN-39). 달력 왼쪽·할 일 오른쪽 배치와 그 아래 연결 파일·프로젝트 폴더, 폭 조절, 15분 단위 시각, 'AI' 표기 없음은 2026-10-07 사용자 요청('캘린더가 왼쪽으로 오고, 할일이 오른쪽으로', '할일 아래에 연결 파일/프로젝트 폴더 설정 가능하도록', '일정에 시간 입력할 때 15분 단위로 선택하도록', '할일에 AI 표기 필요없음', '섹션 넓이 조절 가능하도록')이다(PLAN-42 T-192). '할 일'은 사람이 챙길 일이며 PRD의 Task(작업 단위)와 다르다.

1. **의미.** 프로젝트마다 할 일 목록 하나를 둔다. 항목은 내용, 시작 날짜(선택)와 끝 날짜(선택), 시작 시각(선택)과 끝 시각(선택), 종류, 위치(선택, 200자까지), 참석자(선택, 300자까지의 자유 글, 예: '김 대리, 설비 업체'), 완료 여부, 순서, 더한 쪽(사용자·AI), 만든·바꾼 시각을 가진다. 더한 쪽은 기록에만 두고 행에 'AI' 같은 표시로 보이지 않는다. 시작 시각이 없는 날짜 있는 항목은 **하루 종일**이다. 끝 날짜는 시작 날짜가 있을 때만 두며 시작 날짜보다 뒤다(같은 날이면 두지 않는다): 끝 날짜가 있으면 **여러 날 일정**이다. 끝 시각은 시작 시각이 있을 때만 두며 같은 날이면 시작 시각보다 뒤다. 종류는 '할 일'·'협의'·'접수'·'마감' 넷 중 하나이며 정하지 않으면 '할 일'이다(종류가 생기기 전의 항목도 '할 일', 전의 '회의'는 '협의'로 보인다). '협의'는 회의·미팅처럼 정해진 때에 열리는 **일정**이라 완료 확인이 없고 때가 지나면 그냥 지나간다('지남'이 아니며 오늘 진행·퇴근하기를 막지 않는다). '할 일'·'접수'(허가·도서 제출과 접수)·'마감'은 확인란으로 완료하는 **체크 항목**이다. 날짜·시각은 이 PC의 현지 달력 기준이다. 개인 목록과 여러 프로젝트를 합친 목록·달력은 두지 않는다.
2. **더하기.** 할 일·일정 구역의 입력칸에 적고 Enter로 더한다(여러 항목을 한 번에 넣는 길은 9). 날짜·시각은 이 PC가 문장에서 읽는다(AI를 부르지 않음): 오늘·내일·모레·글피, 요일(오늘이거나 다음 그 요일, '이번 주'·'다음 주'는 월요일에 시작하는 주), `10/7`·`10월 7일`·`2026-10-07`, `3시`·`3시 반`·`3시 10분`·`오후 2시`·`14:00`. 오전·오후 없는 1~7시는 오후로 읽는다. 범위도 읽는다: 시각 둘을 `~`·`-`로 잇거나 '부터 … 까지'로 이으면 시작~끝 시각(`2시~4시`, `14:00-16:00`, `2시부터 4시까지`; 끝이 시작보다 이르면 12시간 뒤로 읽는다), 날짜 둘을 그렇게 이으면 시작~끝 날짜(`10/7~10/9`, `10월 7일~9일`, `10/7부터 10/9까지`). 끝이 시작보다 앞서면 범위로 읽지 않는다. 날짜 뒤의 '하루 종일'·'종일'은 내용에서 뺀다. 읽은 말(뒤의 '까지'·'부터'·'에' 포함)은 내용에서 빼고, 아무것도 읽지 못하면 적은 그대로 둔다. 시각만 있으면 오늘 날짜다. 종류도 문장에서 읽는다(앞의 것이 먼저): 따로 선 낱말 '마감'('마감일' 포함. '마감재'·'마감 상세'·'마감 공사'처럼 건물의 마감을 뜻하는 말은 아님)이면 '마감', 낱말 '접수'·'제출'이면 '접수', 날짜·시각 뒤의 '까지'이면 '마감'(범위를 닫는 '까지'는 아님), '협의'·'회의'·'미팅'이면 '협의'('회의록'·'회의실'·'협의서'는 아님), 그 밖은 '할 일'. 적는 동안 읽은 날짜·시각(범위면 시작~끝)과 종류('할 일'이 아닐 때)를 한 줄로 미리 보인다. 위치·참석자는 문장에서 읽지 않고 일정 폼(3)에서 적는다.
3. **할 일과 일정 구역.** 대시보드는 왼쪽 나머지 전체에 '일정'(큰 달력) 구역, 오른쪽 열에 위에서부터 '할 일' 구역, 연결 파일(SPEC-01.11의 3), 프로젝트 폴더(SPEC-01.13) 구역을 따로 둔다(좁으면 일정이 위·오른쪽 열이 아래). 오른쪽 열의 폭은 사용자가 두 열 사이 손잡이로 바꾸며(달력이 너무 좁아지지 않는 범위) 이 브라우저에 기억한다. 할 일과 일정 두 구역은 1의 같은 목록을 다르게 보인다.
   - **할 일.** 머리의 '오늘'은 오늘 날짜와 진행 'n/m'을 보인다: m은 체크 항목 가운데 날짜가 오늘이거나 지났거나 기간에 오늘이 드는 것 중 완료하지 않은 것과 오늘(이 PC의 현지 날짜) 완료한 것의 수, n은 그 가운데 완료한 수다. 날짜 없는 항목과 '협의'는 세지 않으며 m이 0이면 진행을 보이지 않는다. 그 아래 입력칸과 [글·파일에서 할 일 만들기](9). 목록은 완료하지 않은 항목 가운데 날짜가 지났거나('지남'; 여러 날 일정은 끝 날짜가 지났을 때), 오늘이거나(여러 날 일정은 기간에 오늘이 들 때), 날짜가 없는 것을 사용자 순서대로 보인다. '협의'는 오늘 것과 날짜 없는 것만 확인란 없이 보이고 지난 것은 목록에서 빠진다(달력에는 남는다). 날짜가 뒤인 항목은 '예정 n'에 접혀 있고 펼치면 날짜·시각 순이다. 완료한 항목은 '완료 n'에 접혀 남고 사용자가 [완료 비우기]로 지우거나 퇴근하기(10)로 뺄 때까지 남는다. 완료를 풀면 다시 목록에 나온다. 행은 종류가 '할 일'이 아니면 작은 종류 표시를 달고, 시각(범위면 시작~끝), 위치가 있으면 위치를 단다.
   - **일정.** 이 프로젝트의 날짜 있는 항목을 한 달로 보인다(일요일에 시작하는 주, 이전·다음 달과 [이번 달]). 날마다 그날 항목을 종류 점과 짧은 내용으로 다섯 개까지 보이고 나머지는 '+n'이다. 여러 날 일정은 그 주의 줄을 가로지르는 막대 하나로 먼저 놓고(주를 넘으면 다음 주 줄에서 이어진다), 그 아래 하루 항목을 하루 종일·시각 순으로 놓는다. 완료한 항목은 줄 그어 보인다. 일정 구역에는 입력칸, '날짜 없음' 상자, 달 아래의 그날 목록을 두지 않는다. 날을 누르거나 칸의 [+]를 누르면 그 날짜로 시작하는 **일정 폼**이 그 자리에 뜬다: 제목, 종류, 하루 종일, 시작 날짜·시각 ~ 끝 날짜·시각, 위치, 참석자, [추가]·[취소]. 시각은 15분 단위(00:00~23:45) 목록에서 고른다. 문장에서 읽었거나 전에 넣은 15분 단위가 아닌 시각은 그 값 그대로 목록에 함께 보여 바뀌지 않는다. 하루 종일을 켜면 시각 칸이 사라지고 시각을 비운다. 달력의 항목을 누르면 같은 폼이 그 항목의 내용으로 떠 [저장]·[삭제]·[취소]로 고치거나 지운다. 폼에서 시작 날짜를 비우면(또는 [날짜 빼기]) 날짜가 빠져 할 일 목록의 날짜 없는 항목이 된다. 항목을 다른 날로 끌어 놓으면 기간을 그대로 둔 채 옮긴다: 시작 날짜가 놓은 날이 되고 끝 날짜도 같은 날수만큼 옮긴다. 시각·종류·내용·위치·참석자는 그대로다. 할 일 구역의 행을 달력의 날로 끌어 놓아도 같다. 끌어 놓기도 고치기처럼 읽은 판으로 저장하며 5의 거절 규칙을 따른다.
4. **고치기.** 체크 항목은 확인란으로 완료한다. 할 일 구역에서 내용을 누르면 그 자리에서 3의 일정 폼과 같은 칸(내용·종류·하루 종일·시작~끝 날짜·시각·위치·참석자)으로 고친다(Enter 저장, Esc 취소). 날짜를 비우면 시각·끝 날짜·끝 시각도 비우고, 시작 시각을 비우면 끝 시각도 비운다. 시작 날짜만 바꾸면 끝 날짜는 같은 날수만큼 따라 옮기고, 시작 시각만 바꾸면 끝 시각은 길이를 지켜 따라 옮긴다(그날을 넘으면 끝 시각을 비운다). 끝이 시작보다 앞서는 값은 받지 않는다. [빼기]로 지운다. 끌어 놓기나 ↑↓로 할 일 목록의 순서를 바꾼다. 순서 바꾸기는 보이는 항목끼리의 자리만 바꾸며 다른 항목의 자리는 그대로다.
5. **여러 화면.** 원격 세션(iPad)도 요청처럼 보고 고친다. 다른 화면이 먼저 고친 항목을 오래된 내용으로 고치면 덮어쓰지 않고 거절하며 최신 목록을 다시 읽어 보인다. 고치는 칸을 연 뒤 다른 화면이 고쳤으면 그 저장도 거절하고, 칸에는 최신 내용에 이 화면에서 바꾼 칸만 얹어 보인다(다시 Enter로 저장). 대시보드는 열 때, 창으로 돌아올 때, AI가 고친 뒤에 목록을 다시 읽는다. PC가 꺼져 있으면 원격에서 볼 수 없다(오프라인 보기는 형상만).
6. **AI.** 대화의 AI는(기본 대화의 모델링 턴도) 할 일을 읽고, 사용자의 말이 요청할 때('내일 3시 구조 회의 넣어줘', '회의록에서 할 일 뽑아서 넣어줘') 확인 없이 더하거나 고친다(T1, SPEC-02.19의 7). 종류·기간·위치·참석자도 말에서 정한다('금요일까지'는 마감, 회의·협의는 협의, 제출·접수는 접수, '2시~4시'는 시작~끝 시각, 참석자는 참석자 칸). 한 번의 쓰기는 대화 원장에 한 항목으로 남는다. 목록은 쓰기마다 바로 다시 그리고, 턴이 끝나면 화면은 그 턴에 바뀐 항목을 알리는 안내 하나와 [되돌리기] 하나를 보인다(한 턴에 여러 번 썼어도 하나). 안내는 사용자가 누르거나 닫을 때까지 남는다. AI의 답은 더하거나 고친 항목을 적는다. [되돌리기]는 그 턴의 쓰기로 더한 항목을 지우고 고친 항목을 이전 내용으로 돌린다. 그 뒤 사람이 다시 고쳤거나 지운 항목은 그대로 두고 그 수를 알린다. 한 쓰기는 한 번만 되돌린다. 회의록에서 뽑기는 자료 검색·파일 읽기(SPEC-08.7, SPEC-01.13) 뒤 같은 더하기로 한다. 대시보드에서 글·파일을 넣어 뽑는 길은 9다. 계획 모드 턴은 읽기만 한다. 사용자가 요청하지 않은 할 일을 AI가 먼저 넣지 않는다.
7. **삭제.** 프로젝트를 지우면 그 할 일과 하루 기록(10)도 지운다(SPEC-01.1).
8. **이번 범위 밖.** 반복 일정, 주 보기, 구글 캘린더 등 외부 캘린더 가져오기·연동, 여러 프로젝트를 합친 달력, 참석자를 프로젝트 구성원에서 고르기(참석자는 자유 글), 문장 읽기에서 날짜와 시각이 함께 붙은 여러 날 범위('10/7 2시~10/9 5시'; 폼으로 넣는다), 뽑은 항목을 넣기 전에 고르는 미리보기(ADR-031), 하루 기록을 보는 화면과 공유 메모·업무 일지(10의 기록을 읽을 다음 기능).
9. **글·파일에서 할 일 만들기.** 할 일 구역의 [글·파일에서 할 일 만들기]는 여러 줄 입력칸과 파일 놓기 자리를 연다. 협의 내용·회의록·이메일 같은 글을 적거나 붙여 넣고, 파일을 끌어 놓거나 붙여 넣거나 골라 한 번에 넣는다. 파일은 대화 입력의 첨부처럼 보관한다(SPEC-01.12). [할 일 만들기]를 누르면 이 프로젝트의 기본 대화에 호스트를 쓰지 않는 자동 모드 턴 하나를 보낸다(대화에는 그 요청과 AI의 답이 남는다. 기본 대화의 AI 고정은 SPEC-02.19 2를 따른다). 그 턴의 AI는 글과 첨부에서 할 일·협의·접수·마감을 뽑아 6의 더하기로 묻지 않고 바로 넣는다: 날짜는 오늘 기준으로 읽고('내일', '금요일까지'), 시각이 있으면 시각(범위면 끝 시각, 여러 날이면 끝 날짜까지)을, 장소가 적혀 있으면 위치를, 담당자·참석자가 적혀 있으면 참석자 칸을 채우며, 이미 목록에 있는 같은 항목은 다시 넣지 않는다. 넣기 전에 고르는 단계는 두지 않는다(ADR-031). 도는 동안 구역 안에 '할 일을 뽑는 중'과 지금까지 더한 수를 보이고, 더한 항목은 쓰기마다 목록에 바로 나온다. 끝나면 'n개를 더했습니다'와 그 턴의 모든 쓰기를 함께 되돌리는 [되돌리기] 하나(6과 같은 되돌리기)를 보인다. 하나도 넣지 않았으면 그렇다고 알리고, 턴이 실패하면 이유를 알린다. 이 턴의 결과는 화면 아래 안내(6)로 한 번 더 띄우지 않는다.
10. **퇴근하기.** 날짜가 오늘이거나 지났거나 기간에 오늘이 드는 미완료 체크 항목이 없고 오늘 완료한 항목이 하나 이상이면, 할 일 구역의 '오늘'은 '오늘 할 일을 다 했습니다'와 [퇴근하기]를 차분하게 보인다. 날짜 없는 미완료 항목과 '협의'는 남아 있어도 막지 않는다. [퇴근하기]는 오늘 완료한 항목을 목록에서 빼고(오늘 이전에 완료해 남은 항목은 '완료 n'에 그대로), 이 프로젝트의 하루 기록에 그날 한 줄(날짜, 완료 수, 완료한 내용들)을 남긴다. 같은 날 다시 퇴근하면 그날의 한 줄에 더한다. 뺀 항목은 하루 기록에 남는다. 그 뒤 '오늘'은 '퇴근했습니다 · 완료 n'과 내일 날짜의 미완료 항목을 시각 순으로 앞의 셋까지(없으면 '내일 정해진 일은 없습니다.') 보인다. 그날 다시 할 일을 더하거나 완료하면 1~3의 보기와 이 규칙으로 돌아간다. 퇴근하기는 되돌리지 않는다. 하루 기록은 이 PC의 프로젝트 자료에 날짜·종류·한 줄·항목으로 남고, 앞으로의 공유 메모·업무 일지가 읽을 수 있는 모양으로 둔다(정확한 모양은 ARCH-01 §3).
11. **자료에서 찾은 할 일·일정(2026-10-07 사용자 요청 "일정표나 회의록 같은 것들에서 할일이나 일정 추가할거 있으면 사용자 컨펌 받고 대시보드에 자동으로 추가", PLAN-42 T-196).** 자료 정리(SPEC-08.9)가 끝날 때마다 AI가 그 정리에서 새로 뽑은 진술 가운데 날짜가 있는 결정·요청·조건·일정(회의록·일정표·메일에서 특히)으로 할 일·일정 후보(내용·종류·날짜·시각·끝·위치·참석자·근거 진술)를 만든다. 오늘보다 앞선 날짜, 날짜를 알 수 없는 것, 근거 진술이 없는 것, 이미 목록에 있는 항목·이미 제안한 후보·버린 후보와 같은 것(같은 날짜에 한쪽 내용이 다른 쪽을 품음)은 후보가 되지 않는다. 후보는 목록에 넣지 않고 할 일 구역의 '자료에서 찾은 할 일·일정 n건'에 접혀 보인다. 펼치면 후보마다 고르기·[고치기](내용·종류·날짜·시각)·근거(진술 창, SPEC-08.4)가 있고, [고른 것 추가]는 고른 후보만 2의 더하기로 넣으며(더한 쪽은 AI), [버리기]는 고른 후보를 버린다. 버린 후보는 다시 제안하지 않는다. 사람이 고르기 전에는 아무것도 목록에 들어가지 않으므로 6의 "요청하지 않은 할 일을 AI가 먼저 넣지 않는다"를 지킨다. 9의 '넣기 전에 고르는 단계 없음'은 사람이 직접 보낸 글·파일의 경우이고, 이 경로는 사람이 요청하지 않은 제안이라 확인을 거친다. 후보가 없으면 카드를 보이지 않는다.

**수용 결과:** '내일 3시 구조 회의'를 Enter로 더하면 내일 15:00 '구조 회의'가 예정에 보인다. 완료·고치기·순서 바꾸기·빼기가 새로고침 뒤에도 남고, 완료는 '완료 n'에 접혔다가 비울 수 있다. 오래된 판으로 고치면 거절되고 최신 목록이 보인다. iPad 세션도 더하고 고친다. AI가 대화에서 더한 할 일은 [되돌리기]로 사라진다. 달력에서 날을 누르면 그 날짜의 일정 폼이 뜨고, '설비 협의'·종류 '협의'·10:00~11:00·위치 '현장 사무실'로 [추가]하면 그날에 '협의'로 보이며 확인란이 없다. '10/7~10/9 현장 점검'은 세 날을 잇는 막대로 보이고, 다른 날로 끌면 기간을 지켜 옮겨진다. '2시~4시 구조 협의'는 14:00~16:00 '협의'다. '금요일까지 보고서'는 금요일 '마감'이다. 할 일과 일정은 두 구역으로 함께 보이고, 할 일 행을 달력의 날로 끌면 날짜가 바뀐다. 회의록 글 파일을 놓고 [할 일 만들기]를 누르면 AI가 뽑은 항목이 목록에 바로 나오고 'n개를 더했습니다'의 [되돌리기] 하나로 모두 사라진다. 오늘 할 일을 다 완료하면 [퇴근하기]가 나오고, 누르면 완료한 항목이 빠지고 하루 기록에 그날 한 줄이 남으며 내일 할 일이 보인다.

## 단면 보기 — SPEC-01.15

근거: FR-01·FR-03(자체 뷰에서 대상 확인), SPEC-01.9의 4. 2026-10-07 사용자 요청("clipping plane 기능 추가되면 좋을 듯")과 같은 날 정한 기본값(PLAN-43 '같은 날 정한 기본값' 1, T-197)이다. **설계자는 모델 안쪽(실 내부, 층, 벽 속)을 보려고 VIDE 뷰포트의 표시를 평면이나 상자로 잘라 본다.**

1. **보기 전용.** 단면은 VIDE 뷰포트의 그리기만 자른다. 호스트 문서, Rhino 클리핑 평면 객체, 취득한 형상·속성, 객체 목록, 요청 대상은 바꾸지 않으며 호스트로 보내지 않는다. 다른 사용자·화면과 나누지 않고 저장하지 않는다(새로고침하면 꺼진다).
2. **평면 — 두 점(기본).** 2026-10-07 사용자 요청("rhino에서 clipping plane 만드는 것처럼, 두 점을 클릭해서")에 따라 평면은 뷰포트에서 두 점을 찍어 만든다. 평면을 켜면 바로 첫 점을 기다리고, [두 점으로 그리기]로 언제든 다시 그린다. 점은 커서 아래 보이는(잘리지 않은) 모델 표면에 붙고, 표면이 없으면 바닥(보이는 모델의 가장 낮은 높이, 모델이 없으면 0)에, 바닥과 나란히 보는 앞·옆 보기에서는 화면 중심을 지나는 보기 평면에 놓인다. 단면은 두 점을 지나는 **연직 평면**이다(평면도에 그은 단면선처럼, 3D·위·앞·옆 어느 보기에서나 같다). 첫 점을 찍으면 커서까지 고무줄 선과 남길 쪽 화살표를 보이며 둘째 점을 기다린다. 남는 쪽은 카메라에서 먼 쪽(단면을 들여다보는 방향)이고, 바로 위에서 내려다볼 때는 화면 위쪽이며, 선이 보는 방향과 나란하면 첫 점에서 둘째 점으로 그은 방향의 왼쪽이다. [반대쪽 남기기]로 뒤집는다. 그리는 동안 클릭은 객체를 고르지 않고 단면 창도 닫히지 않는다. 끌기(5px 넘게 움직인 누름)는 점을 찍지 않으며 오른쪽 끌기는 평소처럼 회전·이동한다. 다 그리면 창에 단면선(두 점의 X·Y와 길이)과 '위치' 슬라이더를 보인다. 위치는 평면을 법선 방향으로 옮긴 거리(그린 자리 0, 모델 범위 안)다.
3. **평면 — 축 기준.** [축 기준]은 축 X·Y·Z 가운데 하나에 수직인 평면 하나로 자른다. 축 기준을 고르거나 축을 바꾸면 위치는 보이는 모델 범위의 그 축 가운데다. 위치는 모델 범위(약간의 여유 포함) 안에서 끌어 옮긴다. 기본은 위치 이하 쪽을 남기고(Z면 아래쪽, 평면도처럼) [반대쪽 남기기]로 위쪽을 남긴다.
4. **상자.** 켤 때마다 보이는(숨기지 않은) 모델 범위에 약간의 여유를 둔 상자에서 시작하며, X·Y·Z 각 축의 최소·최대 면 여섯 개를 따로 옮긴다. 상자 안쪽만 남는다. 한 면을 반대 면 너머로 끌면 반대 면이 함께 밀린다(최소 ≤ 최대). [모델 범위로]는 상자를 지금 모델 범위로 되돌린다.
5. **자르는 것과 안 자르는 것.** 문서 객체(면·선·점·CAD 채움·문자, 블록, 플롯 미리보기)는 자른다. 사용자의 스케치와 그리는 중의 선, jig 오버레이, 바닥 격자는 자르지 않는다. 잘린 면의 단면 채움(cap)과 3D 조작 손잡이(기즈모)는 두지 않는다(PLAN-43 기본값 1).
6. **선택.** 잘려서 보이지 않는 부분은 클릭으로 고르지 않고 스케치가 붙을 표면도 되지 않는다. 클릭은 그 뒤에 보이는 객체를 고른다. 창 선택은 보이는 부분만으로 판단한다. 이미 고른 객체와 고정은 단면으로 바뀌지 않는다.
7. **걷기·보기·캡처.** 단면은 끌 때까지 남는다: 3D·위·앞·옆 보기, 투영 전환, 맞춤, 걷기(SPEC-01.9의 4)에도 같은 단면이 보인다. 걷기의 벽 충돌과 층 이동은 단면과 관계없이 모델 전체로 판단한다. 요청과 함께 보내는 뷰포트 캡처, 검토본·프로젝트 썸네일 같은 화면 캡처는 보이는 대로(단면 포함) 찍힌다. Sync로 모델이 바뀌어도 단면 위치는 그대로이며 켜져 있는 동안 도구 버튼이 눌림 상태로 보인다.
8. **끄기.** [끄기]를 누르면 모든 객체가 원래대로 그려지고 선택도 원래대로 된다.
9. **실패.** 보이는 모델이 없으면(연결·Sync 전, 모두 숨김) 단면을 켜지 않고 '단면을 만들 모델이 없습니다. 문서를 연결하고 Sync하세요.'를 알린다. 3D 뷰포트가 없는 화면(호스트 패널)에는 도구가 없다. 두 점을 그리는 중 Esc나 오른쪽 클릭(움직이지 않은 누름)은 그리기를 취소한다: 이미 그린 단면선이 있으면 그대로 두고, 없으면 평면을 끈다. 둘째 클릭이 첫 점과 화면에서 4px 안이거나 두 점의 평면 위치(X·Y)가 같으면(앞 보기에서 위아래로 찍은 경우 등) 그 클릭은 무시하고 둘째 점을 계속 기다린다. 그리는 중 [끄기]·[상자]·[축 기준]을 고르면 그리기를 멈춘다.
10. **이번 범위 밖.** 단면 채움·단면선 추출, 3D 기즈모, 기울어진 평면(두 점 평면은 늘 연직), 단면선을 뷰포트에 남겨 끄는 손잡이, 단면 저장·공유, 호스트 문서에 클리핑 평면 만들기.

**수용 결과:** 두 상자가 보일 때 위 보기에서 평면을 켜고 왼쪽 상자 위의 두 점을 위아래로 찍으면 그 선의 왼쪽만 남아 왼쪽 상자의 오른쪽 부분과 오른쪽 상자가 사라지고, 점을 찍은 클릭은 상자를 고르지 않는다. 같은 자리를 두 번 누르면 둘째 점을 계속 기다리고, Esc·오른쪽 클릭은 그리기를 취소한다. [반대쪽 남기기]는 남는 쪽을 뒤집고 '위치'는 평면을 법선 방향으로 옮긴다. 축 기준에서 평면 X를 켜고 위치를 두 상자 사이에 두면 +X 쪽 상자가 사라지고 그 자리를 클릭해도 고르지 않는다. [반대쪽 남기기]를 켜면 반대 상자가 사라진다. 상자를 켜면 전체가 보이고, X 최대를 두 상자 사이로 끌면 +X 쪽 상자가 사라진다. 걷기와 캡처에도 같은 단면이 보인다. [끄기]를 누르면 두 상자가 다시 보인다. 연결한 Rhino 문서는 바뀌지 않는다.

## 1. 프로젝트와 대상 고정 — SPEC-01.1

근거: FR-01·02·05. 프로젝트는 연결 문서, 입력, 작업, 결과의 소유 경계다. 연결은 호스트 종류·프로세스 인스턴스·열린 문서 인스턴스로 구분한다. 파일 경로나 현재 활성 화면으로 문서 동일성을 추정하지 않는다. 재열기·재연결 시 이전 문서의 쓰기 요청을 새 연결로 자동 전송하지 않는다.

핀은 작성 시 프로젝트·문서·객체·동기화 기준에 고정된다. 이후 B를 선택해도 A의 핀이 B로 이동하지 않는다. 삭제·분할·합침 후 동일성을 확인할 수 없으면 SPEC-00 §1에 따라 표시하며 임의 재연결하지 않는다. 대상·보존·참고 역할을 구분하고 역할 변경은 이후 실행 조건에 반영한다.

**프로젝트 목록(ADR-037 1):** 프로젝트 목록과 구성원의 원본은 계정 사이트다. 계정에 로그인한 PC에서 만들거나 이름을 바꾼 프로젝트는 같은 id로 사이트에 오른다. 프로젝트 고르기는 이 PC의 프로젝트와 공유받은 프로젝트를 함께 보이며, 공유받은 프로젝트를 여는 방식은 SPEC-04.11이 정한다.

**프로젝트 삭제(2026-10-01 사용자 결정):** VIDE 앱의 프로젝트 선택기에서 지우든 계정 웹의 프로젝트 목록에서 지우든 이 PC의 결과는 같다.

- 지우는 것: 그 프로젝트가 소유한 기록(작업·Sync·연결 파일·대화·jig·검토 등)과, VIDE가 데이터 폴더 안에 만든 그 프로젝트의 파일(작업 사본·가져오기 사본·구조·AI 지침·지식 DB)이다.
- 남기는 것: 사용자의 원본 파일, 그리고 다른 프로젝트가 아직 쓰는 파일이다.
- 진행 중인 작업이 있을 때: 앱에서 지우면 거절한다. 웹에서 지운 프로젝트는 목록에서 먼저 빼고, 작업이 끝난 뒤 지운다.
- 저장 공간: 지워서 생긴 빈 공간은 데이터 파일 크기에서도 돌려받는다.
- 다시 나타나지 않음: 지운 프로젝트는 계정 웹이 아직 갱신하지 않은 목록으로 되살아나지 않는다.
- 열려 있던 창: 다른 곳(계정 웹·사이트 정리·다른 창)에서 지워진 프로젝트를 연 창은, 그 프로젝트에 대한 첫 '찾을 수 없음' 답에서 프로젝트 목록을 다시 읽고 없으면 '프로젝트가 삭제되어 목록으로 돌아갑니다'를 알린 뒤 프로젝트 목록으로 돌아간다. 그 뒤로는 그 프로젝트를 다시 조회하지 않는다(T-191).

## 2. 수동 동기화 — SPEC-01.2

근거: FR-02·03·16. 사용자가 지정한 연결의 동기화를 요청하면 지원 객체·속성·단위와 취득 시각을 새 기준으로 저장한다. 부분 취득은 누락 유형·건수를 표시한다. 실패 시 마지막 성공 기준을 유지하고 실패 원인을 별도로 표시한다. 동기화 전 화면이 최신임을 보증하지 않는다. 호스트 변경을 관측했으면 오래됨, 관측할 수 없으면 최신 여부 미확인으로 표시한다.

수동 동기화는 원본 쓰기·저장·카메라 동기화·웹 게시를 수행하지 않는다. 호스트 선택이나 카메라 이동도 동기화를 대신하지 않는다. 여러 문서의 취득 시각은 독립적이며 하나의 원자적 스냅샷처럼 표시하지 않는다.

## 3. 입력과 저장 — SPEC-01.3

근거: FR-05·06·07·16. 코멘트 저장은 AI 실행을 발생시키지 않는다. 텍스트·핀·스케치를 먼저 로컬 기록으로 보존하고 실행은 별도 지시로 시작한다. 저장 실패를 성공으로 표시하지 않는다. 입력 수정은 기대 버전을 확인해 오래된 화면의 덮어쓰기를 거절한다.

기하 스케치는 작업 평면·단위·원래 점열을 보존한다. 화면 위 주석이나 좌표 정합이 없는 이미지에는 호스트 기하 좌표를 부여하지 않는다. 객체 핀과 화면 위치 핀을 구분한다. AI 연결이 없어도 입력 저장·열람·삭제가 가능하다.

## 4. 수용 예

A 핀 작성 → B 선택 → 다시 열기에서 A가 유지된다. 다른 프로젝트 객체를 포함한 입력은 거절된다. A 삭제 후에는 끊긴 참조가 남는다. 동기화 실패는 기존 표시 데이터를 지우지 않는다. 두 호스트의 동기화와 독립 작업이 서로의 대상을 바꾸지 않는다.

## 5. 공간 입력의 계약 — SPEC-01.5

근거: FR-05·06·07. 입력은 본문, 참조, 원본 스케치, 출처, 사용 역할을 함께 보존한다. 핀 삽입은 현재 선택의 복사이며 선택과의 실시간 연결이 아니다. 필수 대상의 참조가 끊겼으면 저장은 허용하되 그 대상을 쓰는 실행은 대상 재지정 전 보류한다. 참고 자료의 끊김은 제외 사실을 확인하고 진행할 수 있다.

| 입력 | 반드시 보존할 기준 | 수정·오류 행동 |
|---|---|---|
| 객체 핀 | 문서·객체·취득 기준; 선택한 부분이 있으면 부분 참조 | 동일성 확인 실패는 끊김. 사용자가 대체 대상을 지정하면 새 입력 버전 |
| 공간 위치 핀 | 문서 기준 좌표·단위·작성 기준 | 객체 핀으로 자동 승격하지 않음 |
| 스케치 | 모델 좌표 점열(m)·그린 위치(표면/시점 평면)·색·굵기. 이전 스케치는 평면·선 역할 포함 | 카메라 변경으로 점열 재투영/덮어쓰기 금지 |
| 화면 주석 | 작성 화면/게시 표현과 정규화한 2D 위치 | 원본 표현과 함께 재표시. 모델 깊이를 추정해 원본 쓰기에 사용하지 않음 |
| 미등록 이미지 | 원본 자료와 주석 | 단위·원점·평면 정합 전 공간 치수로 사용하지 않음 |

평면의 두 축은 직교·정규화되어야 하며 원점과 단위가 알려져야 한다. 다른 호스트로 전달할 때는 문서 간 변환을 별도로 확인한다. 등록 정보 수정은 새 버전을 만들고 종전 스케치와 이를 사용한 실행을 보존한다. AI 해석선은 원본 선과 별도 결과이며 채택 전 원본을 대신하지 않는다.

마우스·펜·터치로 자유곡선을 그리며 포인터 점열을 보존한다. 펜(Apple Pencil 등)을 쓰면 펜은 그리고 손가락은 화면 회전·이동·확대만 한다. 펜이 없는 기기에서는 한 손가락으로 그리고 두 손가락으로 화면을 조작한다. 좌표 입력은 제공하지 않는다(2026-09-29 사용자 결정). 정밀한 치수는 문장과 핀으로 전한다.

### 5.1 치수와 파라미터 입력

범용 대화 제출 자체에는 높이·객체 핀·스케치를 필수로 요구하지 않는다. 본문 또는 참조 첨부가 있으면 요청을 구성할 수 있다. 아래 수치 검증은 그 값이 필요한 기하 실행 직전에 적용한다. 필요한 정보가 부족하면 해당 작업을 질문/결정 필요로 두며 다른 종류의 요청까지 막지 않는다. 높이 변경 대표 과업은 입력 UI의 고정 스키마가 아니다.


근거: FR-05·06·07. 문장의 수치와 별도로 대상 핀에 연결한 파라미터를 편집할 수 있다. 각 값은 대상, 속성 이름(높이·폭·거리·각도 등), 입력 원문, 수치, 단위, 출처(사용자 입력/호스트 조회/AI 제안), 조건 버전을 보존한다. 호스트가 지원하는 속성만 실행에 연결한다. 기존 값은 조회 기준과 함께 읽기 전용으로 표시하고 모르면 ‘미확인’으로 둔다.

사용자는 속성과 새 값을 입력한다. 길이는 mm/cm/m, 각도는 deg로 명시하고 문서 단위와 다르면 변환값을 함께 표시한다. 빈 값·비유한 수치·속성에 맞지 않는 단위를 거절한다. 높이·폭은 양수, 이동 거리는 부호를 허용한다. 단위나 대상이 불명확한 자연어는 제안으로 분리하고 확인 전 실행하지 않는다. 문장과 구조화 값이 다르면 어느 값을 사용할지 선택하게 하며 마지막 입력으로 몰래 덮어쓰지 않는다. 편집은 새 조건 버전이며, 이미 실행한 결과는 문서에 그대로 두고 다음 턴이 새 값으로 이어 간다(SPEC-02.13의 2). 첫 검수는 조회 높이 6 m, 사용자 변경 4.5 m와 4500 mm가 같은 결과인지 확인한다.

### 5.2 그리기 위치 (Grease Pencil 방식)

2026-09-29 사용자 결정으로 그리기 위치 선택(표면·화면 평면·축 평면)과 평면·오프셋 입력을 없애고 자동으로 정한다(Blender Grease Pencil의 Surface 배치 + 시점 평면 방식).

- 획은 첫 점 아래의 모델 표면 점을 지나는 **시점 평면** 위에 놓인다. 첫 점 아래에 모델이 없으면 마지막으로 그린 표면 점(Blender의 3D 커서에 해당), 그것도 없으면 궤도 중심을 지난다.
- **표면에 붙이기**(기본 켜짐)는 펜 아래에 모델이 있는 동안 점을 표면 위에 둔다. 끄면 획 전체가 그 시점 평면에 놓인다.
- 위·앞·옆 보기에서는 시점 평면이 곧 XY·XZ·YZ 축 평면이다. 축 평면에 그리려면 그 보기로 바꿔 그린다.
- 기존 카메라 변경으로 이미 그린 점을 재투영하거나 덮어쓰지 않는다. 획은 모델 좌표 점열(m)로 보존한다.

### 5.3 스케치의 의미

선 역할(참고·경계·경로·방향) 선택은 없앴다(2026-09-29 사용자 결정). 스케치가 윤곽·경로·방향·영역 중 무엇인지는 함께 보낸 문장이 정한다. AI는 획을 대략적인 의도로 다루고 근처 형상에 맞춘다. 이전에 역할을 붙여 보낸 스케치는 그 역할을 그대로 보존·표시한다. 자동 닫기·점 보정은 제안과 사용자 채택을 구분한다.

### 5.4 도구 전환

스케치 중 선택 도구로 바꾸면 그린 획을 비우거나 취소하지 않아도 된다. 그린 획은 입력의 스케치 첨부로 옮겨지고 선택 도구가 켜진다. 비우기·취소는 그린 획을 버리는 명시적 행동으로만 남긴다.

## 6. 문서 기준과 동기화 경합 — SPEC-01.6

근거: FR-02·03·16. 연결, 마지막 성공 기준, 현재 취득 요청은 별개다. Sync는 시작할 때 대상을 고정하며 화면 전환으로 바뀌지 않는다. 같은 연결의 중복 Sync 요청은 진행 중 요청을 보여주고 새 취득을 겹쳐 시작하지 않는다.

취득 중 원본 변경을 감지하면 결과를 완전한 동일 시점 기준으로 확정하지 않는다. 다시 취득하거나 불일치 범위를 표시한다. 지원하지 않는 객체와 읽기 실패 객체의 수·이유를 구분한다. 완전 취득임이 확인되지 않은 목록에서 빠진 객체를 삭제 확정으로 판정하지 않는다. 기준 교체 후 참조·집계·jig 입력의 의존성을 확인한다. VIDE의 선택/카메라는 호스트로 자동 전송하지 않으며(Rhino 선택을 VIDE가 따라 보이는 것은 SPEC-01.11의 4), 실행 전후의 문서 확인·재조회가 화면 전체 Sync나 웹 게시를 발생시키지 않는다.

## 7. 편집 초안과 복구 — SPEC-01.7

근거: FR-01·07·16. 편집 중 초안과 저장된 입력 버전을 분리한다. 패널 접기·대상 선택·작업 범위 전환은 초안을 지우지 않는다. 프로젝트 전환 시 초안은 원래 프로젝트에 보관한다. 로컬 저장 실패 시 편집 내용을 유지하고 재저장을 제공한다. 앱 종료 전 저장되지 않은 내용을 알리고, 저장 확인 전 재시작 보존을 약속하지 않는다. 기존 구현의 메모리 초안은 이 제한을 표시해야 한다.

오래된 버전 수정은 충돌로 반환하고 최신 저장본과 내 편집본을 함께 남긴다. 무조건 덮어쓰는 재시도는 제공하지 않는다. 저장된 입력을 실행에 넣을 때는 실제 포함 버전을 보여 준다.

## 8. 수용 사례의 상세

| 기준 | 입력·조작 | 관찰 결과 |
|---|---|---|
| AC-01·31 | A 문서 핀 → B 선택 → 다른 프로젝트 → 복귀·재열기 | A 참조와 소속 유지; B 권한/문맥 혼입 없음 |
| AC-02·03 | 평면 선 작성 → 카메라 회전; 미등록 이미지 추가 | 원점·점열·단위 불변; 이미지는 공간 입력 미등록 |
| AC-04 | AI 미인증 상태에서 저장; 저장 오류 삽입 | 성공분 재열기 가능; 실패분은 미저장·편집 내용 유지 |
| AC-21·29·39 | 원본 삭제/직접 수정 → Sync 실패 → 성공 | 실패 때 이전 기준 유지; 완전 조회 뒤에만 삭제 판정·표시 갱신 |

### 입력 보호와 작업 공간 탐색
근거: FR-01·05·07·16, SPEC-01.7. 선택 대상 없는 객체 고정과 빈 문장의 요청 추가는 비활성화한다. 연계는 SDK 조회에 성공한 서로 다른 기준(Sync 결과) 두 개가 필요하며 부족하면 조건을 설명한다. 연계 문맥은 두 대상이 한 묶음임을 표시하고 묶음 단위로 제거한다. 참고 파일의 형식·상한·묶음 단위 거절은 SPEC-01.12를 따른다.
수동 저장본 불러오기는 현재 입력 또는 미첨부 스케치가 있으면 교체 확인을 거치고 취소 시 모두 유지한다. 문서·이력 탭 전환과 패널 폭 변경은 입력과 선택을 보존한다. 카메라 방향·투영 표시는 실제 카메라 상태를 따른다.

## 프로젝트 연결 파일(Link)과 여러 파일의 한 공간 — SPEC-01.11

근거: PRD §8.1·§8.6·§12.2, FR-01·02·03·05·16. 2026-09-29 사용자 결정: 연결은 호스트 플러그인에서 시작하고, VIDE는 프로젝트의 연결 파일을 보여 주고 보이기/숨기기와 강제 Sync만 맡는다.

1. **Link(플러그인):** 사용자가 Rhino·ZWCAD 플러그인에서 Link를 누르면 VIDE의 프로젝트 목록(최근 순, 새 프로젝트 포함)에서 연결할 프로젝트를 고른다. 문서가 그 프로젝트의 연결 파일로 등록되고 곧바로 첫 Sync가 이루어진다. VIDE가 실행 중이 아니면 연결하지 않고 그 사실을 알린다. 같은 창의 문서를 다시 Link하면 기존 연결을 갱신한다. 창이 닫힌 연결은 경로가 같은 파일을 다시 열면 그 연결로 이어지고, 그때부터 그 창의 연결이다(Link 없이 Sync·Live Sync만 한 ZWCAD 창도 같다).
   - **문서 안의 연결 ID(2026-10-02 사용자 결정, [ADR-030](../decisions/ADR-030-link-id-in-document.md)):** Link하면 플러그인이 그 연결의 ID를 문서 안에 적는다(프로젝트마다 하나). 열린 문서를 연결에 맞출 때는 같은 창의 연결 다음으로 이 ID를 경로·이름보다 먼저 쓴다. 그래서 다른 이름으로 저장, 파일 이동·이름 바꾸기, 재시작 뒤에도 같은 연결로 이어진다. 적으면 문서가 '수정됨'이 되므로 처음 적을 때 "연결 ID를 문서에 저장했습니다. 저장하면 다음에도 이어집니다"를 알린다(호스트 명령줄과 연결 파일 목록의 그 행, 한 번). 사용자가 저장하지 않은 문서는 다음에 예전처럼 창·경로로 잇는다. 연결을 빼거나 프로젝트를 지워도 문서의 ID는 지우지 않으며, 행이 없는 ID는 무시한다.
   - **모호한 Link는 묻는다(2026-10-02, T-107):** 문서가 가진 ID의 연결이 있으면 묻지 않고 그 연결로 잇는다. 그 연결이 지금 다른 창에 열려 있으면(파일 사본이 같은 ID를 가짐) 두 번째 창의 Link에서 "기존 'X' 대체(기록 이어짐) / 새 연결 파일로 추가"를 묻고 기본은 새 항목이다. ID가 없고 이 창의 연결도 없는데 같은 호스트의 닫힌 연결 가운데 이 문서일 수 있는 것(같은 경로, 같은 이름, 최근 12시간 안에 닫힘, 많아야 다섯)이 있으면 같은 질문을 하고, 기본은 자동 대조가 고를 연결(같은 경로의 연결, 없으면 새 항목)이다. 대체를 고르면 그 연결의 Sync 기록이 이어지고, 같은 창에 있던 다른 연결은 닫힘이 된다. 새 항목을 고르면 닫힌 연결과 기록은 그대로 남는다. 취소하면 연결하지 않는다. 모호하지 않은 Link는 지금과 같다. 이전 버전 플러그인의 Link는 묻지 않고 예전 규칙으로 잇는다.
   - **다른 이름으로 저장(2026-10-01 사용자 결정):** 연결된 창의 문서를 다른 이름으로 저장하거나 저장 안 된 문서를 처음 저장하면(Rhino·ZWCAD) 연결은 그 창을 따라간다. 같은 항목의 이름과 경로가 새 파일로 바뀌고 Sync 기록과 표시는 그대로다. 이전 파일도 같은 연결 ID를 지니므로, 새 파일이 열려 있지 않을 때 이전 파일만 열면 Link 없이 그 ID로 같은 연결에 다시 이어지고 따라감 알림과 [새 항목으로 분리]를 보인다. 두 파일이 함께 열려 있으면 연결은 그 항목의 경로에 있는 파일에 남는다.
   - **따라감 알림과 분리(2026-10-02, T-107):** 자동 따라가기가 연결의 경로를 다른 파일로 바꾸거나(다른 이름으로 저장, 저장한 파일의 이동) 닫힌 연결을 다시 연 창에 경로로 이으면 목록의 그 행에 "'A' → 'B'로 따라감"(다시 연 창이면 "'A'을(를) 다시 연 창으로 따라감")과 [새 항목으로 분리]·[확인]을 한 번 보인다. 여러 번 따라가면 처음 파일부터 지금 파일까지 하나로 보인다. 처음 저장(경로가 없던 문서)은 알리지 않고, 문서의 연결 ID로 이은 재연결은 경로가 바뀐 경우에만 알린다. [새 항목으로 분리]를 누르면 그 창은 새 연결 항목이 되고(첫 Sync부터), 이전 항목은 Sync 기록을 지닌 채 따라가기 전의 이름·경로로 돌아가 닫힘이 된다. 그 창의 문서에는 새 항목의 ID를 다시 적는다(적지 못하면 그 사실을 알리고, 다음 Link에서 묻는다). 알림은 VIDE를 다시 시작하면 사라진다.
   - **창 하나에 항목 하나:** 열린 창 하나에는 연결 항목 하나만 연결 상태가 된다. 예전에 같은 창을 다시 Link해 생긴 중복 항목은 닫힘으로 보인다. 다음에 다른 이름으로 저장하면 그 창에 연결 상태로 보이던 항목이 따라가며, 보이기/숨기기는 이를 바꾸지 않는다.
   - **합치기·빼기(2026-10-02, T-107):** 같은 창의 닫힌 중복 항목에는 '같은 창의 중복 항목 · [합치기]'를 보인다. 확인하면 그 항목의 Sync·불러오기 기록과 jig 읽기·만들기 기록이 그 창의 연결 항목으로 옮겨지고 중복 항목은 목록에서 빠진다. 파일과 객체는 그대로다. 그 항목의 Sync가 진행 중이면 합치지 않고 끝난 뒤 다시 하라고 알린다. 기록이 없는 닫힌 항목에는 '기록 없음 · [빼기]'를 보인다(빼기는 9와 같다).
2. **Live Sync(플러그인):** 켜 두면 편집이 멈춘 뒤 변경분만 갱신한다. 끄면 플러그인의 Sync나 VIDE의 ⟳로만 갱신한다. Live Sync는 표시 기준만 갱신하며 AI 호출·호스트 쓰기·파일 저장·공개를 하지 않는다. 실패하면 이전 성공 표시를 유지하고 알린다. 편집이 이어져 생긴 실패만 VIDE가 다시 시도한다(10). 해제(Unlink)는 이 창의 연결만 끊으며 프로젝트의 연결 기록과 마지막 Sync는 남는다.
3. **연결 파일 목록(VIDE):** 프로젝트마다 연결 파일을 저장해 파일이 닫혀도 보인다. 파일마다 호스트, 이름, 상태(Live·연결됨·닫힘), 마지막 Sync 시각, 객체 수를 표시하고 보이기/숨기기, ⟳ 강제 Sync와 전체 다시 읽기(연결 중일 때, 10), 목록에서 빼기(9)를 제공한다.
4. **한 공간:** 보이기로 둔 모든 연결 파일을 각 파일의 좌표(미터) 그대로 함께 그린다. 파일 사이에 주종은 없다. 객체는 자기 파일(기준 Sync)을 기억하며 선택·핀·검사·수량은 그 파일 기준으로 동작한다. 좌표가 다른 파일의 정렬은 Sync jig(SPEC-05.8)가 맡는다.
   - **Rhino 선택 따라 보기(2026-10-01):** VIDE는 연결된 Rhino 문서마다 그 문서의 현재 선택을 따로 기억해 뷰포트 선택에 비춘다(Rhino → VIDE 한 방향). 보고 있는 파일의 Rhino 선택이 바뀌면 VIDE 선택을 그 객체로 바꾸고, 다른 연결 Rhino 창에서 객체를 고르면 VIDE가 그 파일을 따라가 선택을 보인다. 따라가기 시작한 파일은 그때의 선택부터 보며 지난 선택을 다시 재생하지 않는다. 마지막 Sync에 없는 객체만 고른 경우 VIDE 선택을 그대로 둔다. VIDE에서 고른 객체는 Rhino 선택을 바꾸지 않는다. 호스트 패널 화면은 자기 문서의 선택만 본다.
   - **숨기기와 작업 결과(2026-10-01 사용자 결정):** 숨긴 파일은 그 파일의 Sync와 그 파일을 기준으로 한 후보·결과까지 공간에서 뺀다. 작업 이력에서 연 결과가 지금 어느 연결 파일에도 속하지 않으면(예전 불러오기, 연결 전 Sync, 뺀 파일의 AI 결과) 목록에 '작업 결과 · <이름>' 행으로 보이고 그 행의 닫기로 내린다. 모든 연결 파일을 숨기면 그 파일들에 속한 것은 모두 사라지고 남는 것은 이 행으로 보인다. VIDE를 다시 열 때 지난 화면의 결과를 되살려도 숨긴 파일을 다시 보이게 하지 않는다.
   - **고정 묶음(2026-10-01):** Rhino 문서가 연결되어 있는 동안 그 문서의 이름 없는 고정(작성기의 '📌 고정 객체' 칩)은 Rhino 쪽 고정 목록과 같은 묶음이다. 패널의 'Rhino 선택 N개 첨부'는 누를 때 Rhino 선택을 다시 읽어 고정 목록에 더하고, VIDE에서 고정 칩을 비우면 Rhino 목록도 비운다. Rhino 목록이 바뀌거나 그 문서의 새 Sync가 들어오면 Rhino 목록이 관리하던 고정만 바꾼다. 작성기의 `[고정N · k개]` 토큰처럼 VIDE에서 이름을 붙여 만든 고정은 사용자의 것이라 Rhino 목록의 변경으로 지우지 않는다. 마지막 Sync에 없는 고정 객체는 'Sync 대기'로 세고 그 파일을 Sync한 뒤 핀이 된다.
5. **요청이 다루는 파일(2026-10-02 사용자 결정, T-103):** 사용자는 요청의 대상 파일을 고르지 않으며 작성기에 대상 파일 표시도 없다(사용자 질문 "어떤 파일을 수정할지는 우리가 정하는게 아니라, AI가 판단해서 link된 연결 파일 중에 어떤거를 수정할지 결정하는거 아닌가?"). 2026-10-01 사용자 결정([ADR-027](../decisions/ADR-027-multi-file-coordination.md) "sync된 파일들은 다 하위에 있는 파일이니까, 동시에 조율할 수 있어야")에 따라 한 요청은 **그 프로젝트의 연결 파일 가운데 지금 열려 연결된 것**을 모두 실시간으로 읽고(계획·자동), 자동 모드에서는 고친다. 어느 파일을 읽고 고칠지는 요청 문장·핀·읽은 내용으로 AI가 정한다. 핀은 어느 파일에 있든 기본 역할이 변경이며, 사용자가 유지·참고로 표시할 때만 달라진다. 다른 연결 파일의 변경·유지 핀은 그 파일의 Sync를 기준으로 그대로 받으며, 시작 문서와 기준이 다르다는 이유로 오래된 참조로 거절하지 않는다. 시작 문서 자체의 이전 Sync에 고정된 변경·유지 핀만 오래된 참조다. 요청에는 화면에 보이지 않는 **시작 문서**가 하나 있다: 초안을 쓰기 시작할 때 보고 있던 연결 파일(핀이나 객체를 고르면 그 객체의 파일)이다. 시작 문서는 파일을 지정하지 않은 도구 호출의 기본 문서이자 문서별 쓰기 차례(SPEC-02.9)의 접수 기준일 뿐, 요청 범위의 한계가 아니다. 닫혔거나 연결되지 않은 파일은 마지막 Sync로만 읽고 고치지 않는다. AI가 어떤 파일을 고치면 실행 뒤 같은 문서를 다시 읽어 바뀐 결과를 그 파일 자리에 보인다(SPEC-02.16). 여러 파일을 고친 요청의 결과·되돌리기·실패 처리는 SPEC-02.13, 문서별 쓰기 차례는 SPEC-02.9가 정한다. 1차 범위는 Rhino 연결 문서에서 시작하는 요청이다(다른 Rhino 문서는 읽기·보기·측정·쓰기, ZWCAD 도면은 읽기·쓰기). ZWCAD 도면에서 시작하는 요청은 다른 파일을 마지막 Sync로만 읽는다(실행 경로가 달라 후속, PLAN-26 T-103).
6. **자동 Sync의 보류:** 초안·핀·스케치나 실행 중 작업이 어떤 파일을 기준으로 삼고 있으면 그 파일의 자동 갱신만 보류하고 ⟳를 제공한다. 보류 중에 누른 ⟳는 새 Sync로 남고, 초안·핀이 기준으로 삼은 Sync는 바뀐 객체만 묻는 경우에도 고치지 않는다(2026-10-06, PLAN-28 T-123). 보류가 이어지는 동안 다시 누른 ⟳는 그 새 Sync를 고치며 ⟳마다 Sync가 늘지 않는다. 다만 초안·핀·다른 기록이 그 새 Sync를 쓰기 시작했으면 그것도 고치지 않고 다시 새 Sync로 남긴다(PLAN-28 T-127). 첫 Sync는 보류하지 않는다. 다른 파일은 계속 갱신한다. 보류는 VIDE 엔진이 판단하며 모든 화면에 같게 보인다(10).
7. **실패:** 연결이 끊기면 목록에 닫힘으로 표시하고 마지막 Sync를 유지한다. Sync 실패는 그 파일 행과 오류 기록에 남기고 다른 파일에는 영향이 없다.
8. **파일에서 연 파일(2026-09-29 사용자 지적):** VIDE의 '파일에서 열기'로 연 3DM·DWG 작업 사본도 목록에 '파일' 항목으로 보인다. 같은 이름을 다시 열면 같은 항목이 새로 고쳐지고 보이게 된다. 이 기능 전에 열었던 파일은 한 번만, 숨김 상태로 목록에 들어온다. 빼기 버튼은 늘 보인다.
9. **빼기(2026-09-30 사용자 결정):** 목록에서 빼면 그 파일이 VIDE 안에 남긴 것을 지우고 연결을 끊는다. 사용자의 원본 파일과 호스트 창의 객체는 건드리지 않는다.
   - 그 파일의 Sync·불러오기 기록과 결과(형상 포함), VIDE가 만든 불러오기 사본·작업 폴더를 지운다. 다른 파일 항목이나 남은 기록이 쓰는 파일은 지우지 않는다. 웹 게시·공유 의견이 가리키는 기록은 지우지 않고 작업 이력에서만 내린다.
   - 그 파일의 Sync가 진행 중이면 빼지 않고 끝난 뒤 다시 하라고 알린다.
   - 플러그인 연결 파일이면 그 문서의 패널이 연결이 없어진 것을 보고 플러그인 연결을 끊어 연결 전 화면으로 돌아간다. 패널이 닫혀 있으면 다음에 패널이 보일 때 끊는다. 빠진 파일은 다시 Link하기 전까지 Sync되지 않는다.
   - 같은 파일을 다시 열거나 Link하면 새 항목으로 처음부터 Sync한다.
   - 확인 창은 지워지는 것과 그대로인 원본을 함께 알린다.
10. **Sync는 VIDE 엔진이 맡는다(2026-10-01 사용자 결정, 아래 세부는 2026-10-02 사용자 확인, T-084):** 연결 파일의 자동 Sync(첫 Sync, Live Sync, 다시 연 Live 파일의 따라잡기)는 화면이 아니라 VIDE 엔진이 문서마다 한 곳에서 한다.
   - 엔진이 연결된 문서의 변경 번호를 직접 보고, 바뀌었으면 그 문서에 Sync 하나를 한다. 마지막 Sync가 있으면 바뀐 객체만 반영하는 Live Sync, 없거나 이어 갈 수 없으면 전체 Sync다.
   - 데스크톱 창, Rhino 패널, ZWCAD 팔레트, 브라우저 탭, 원격 화면은 자동 Sync를 시작하지 않는다. 엔진이 만든 결과를 알림으로 받아 화면만 갱신한다. 그래서 화면을 몇 개 열어도 한 문서의 변경 한 번은 Sync 한 번이고, VIDE 화면이 하나도 열려 있지 않아도 엔진이 켜져 있으면 Live 파일은 갱신된다.
   - 같은 문서에 Sync가 겹치면 하나로 합친다. 자동 Sync는 진행 중인 Sync에 합류하고, 끝난 직후 문서가 그대로면 그 결과를 쓴다. 사용자가 누른 ⟳·지금 Sync·플러그인 Sync는 진행 중인 자동 Sync에 합류하지 않고 호스트에 직접 새로 묻는다. 그 파일의 표시 중인 Sync가 Live Sync로 이어질 수 있으면 그 Sync 뒤에 바뀐 객체만 묻고(Live Sync), 처음이거나 Live Sync를 할 수 없으면 문서 전체를 읽는다(2026-10-06, PLAN-28 T-123). 읽는 도중 문서가 바뀌었거나 호스트가 바빠 Live Sync가 안 되면 잠시 뒤 몇 번 다시 묻고, 그래도 안 될 때만 전체를 읽는다(T-127). 표시가 의심스러우면 사용자가 '전체 다시 읽기'(연결 파일 행 메뉴, Shift+⟳)로 바뀐 객체만 묻지 않고 문서 전체를 읽게 할 수 있다. 사용자 요청끼리 겹치면 진행 중인 것을 보인다(SPEC-01.6).
   - 보류(6)는 엔진이 판단한다. 초안·핀·스케치가 어떤 파일을 기준으로 하고 있으면 그 화면이 엔진에 알리고, 그 화면이 닫히거나 알림이 5초 동안 끊기면 보류가 풀린다. 실행 중 작업이 그 파일을 기준으로 하거나 AI·jig가 그 문서를 고치는 중이면 끝날 때까지 기다린다. 끝나면 쌓인 변경을 Sync 한 번으로 반영한다(AI 편집 뒤 다시 읽기, SPEC-02.16).
   - Sync 도중 문서가 바뀌어 한 시점의 결과로 확정할 수 없거나(SPEC-01.6) 호스트가 바쁘면 실패로 남기지 않는다. 그 파일 행에 '변경 중 · 곧 다시 Sync'를 보이고 잠시 뒤 다시 한다. 30초 동안 계속 안 되면 다음 변경이나 ⟳를 기다린다. 사용자의 Sync가 성공하면 그 파일의 '변경 중'·실패 표시와 재시도는 끝난다. 다른 실패는 2·7대로 이전 표시를 유지하고 알린다.
   - Sync 중·보류·변경 중·실패 표시와 마지막 Sync는 엔진의 상태이므로 모든 화면에 같게 보인다.
11. **도면 xref 관계(2026-10-07 사용자 요청, PLAN-43 T-200):** 사용자 요청 "도면-모델링 sync — 서버에 있는 것들에 대해서 다 링크를 거는 방식으로… 각 cad 파일의 xref 관계를 알아서 파악해서 모델링으로 반영". 읽기 전용이며, 모델에서 CAD로 되돌리는 반영은 C-08이다.
   - **읽기:** 대시보드 프로젝트 폴더 구역의 [다시 읽기]를 누를 때만 프로젝트 폴더(SPEC-01.13의 `project` 폴더, 서버 공유 경로 포함) 안의 DWG를 읽는다. 자동 갱신은 없다. 크기·수정 시각이 지난번과 같은 도면은 다시 읽지 않는다. 원본은 VIDE 데이터 폴더로 복사한 사본만 VIDE가 직접 띄운 숨은 ZWCAD가 읽고, 읽은 뒤 그 ZWCAD만 끈다. 사용자의 ZWCAD 창과 원본은 건드리지 않는다. ZWCAD 2023이 없으면 읽지 않고 그 이유를 보인다. 원격 세션은 결과만 본다.
   - **관계:** 도면마다 xref(외부 참조)의 이름, 저장된 경로, 부착/오버레이, 그 xref의 삽입(모형 공간·배치·블록 안, 위치·회전·축척)을 읽는다. 저장된 경로는 원본 도면의 폴더를 기준으로 ① 저장된 경로 그대로(절대 경로이고 파일이 있을 때) ② 상위 도면 폴더 기준 상대 경로 ③ 상위 도면 폴더의 같은 파일 이름 순으로 찾는다. 찾지 못하면 '누락', 따라가다 이미 지나온 도면으로 돌아오면 '순환', 한 도면이 같은 파일을 두 번 이상 참조하면 '중복'으로 표시한다. 프로젝트 폴더 밖에서 찾은 도면도 읽어 관계에 넣고 '폴더 밖'으로 표시한다. 단위가 없는 도면은 mm로 본다.
   - **트리:** 다른 도면이 참조하지 않으면서 xref가 있는 도면이 루트다(루트가 없는 순환은 그 첫 도면을 루트로 보인다). 루트 아래에 xref를 중첩해 보이고, 이름에 마우스를 올리면 저장된 경로와 찾은 파일·찾은 방법을 보인다. 관계가 없는 도면은 개수만 보인다.
   - **[모델에 반영](루트마다):** 루트 도면과 그 루트가 모형 공간에 보이는 도면들을 프로젝트 연결 파일(3)로 넣고 루트의 좌표에 함께 그린다. CAD처럼 오버레이는 루트가 직접 참조할 때만, 배치·블록 안의 삽입은 넣지 않고, 같은 도면은 한 번(첫 삽입)만 보인다. 각 도면은 그 삽입의 변환(상위 도면의 변환과 합성)대로 놓이며 이 배치는 표시에만 쓴다(4의 '각 파일의 좌표 그대로'의 예외). 연결 항목은 경로로 구분하는 파일 항목이며, 같은 경로의 플러그인 연결(Link)이 있으면 그 연결을 그대로 쓴다. 도면 내용은 숨은 ZWCAD가 사본의 모형 공간을 연결 Sync와 같은 방식으로 읽은 표시이며, 지난번과 파일이 같으면 다시 읽지 않는다. 읽지 못한 도면은 이름과 이유를 보인다. 다른 루트를 반영하면 그 루트의 배치로 바뀐다. 연결 파일의 빼기(9)는 다른 파일 항목과 같다.

플러그인의 패널(Rhino 패널, ZWCAD 팔레트)에는 연결한 프로젝트 이름, Link/연결 해제, Live Sync 켜기/끄기, Sync와 그 파일의 AI 작업·작성기를 둔다(2026-09-29 사용자 결정: CAD 패널도 같은 작업 화면). 연결 전에는 연결 안내와 Link만, VIDE가 꺼져 있으면 실행 안내만 둔다. Link는 프로젝트를 고르는 창을 열고, 모호하면(1) 이을 연결을 고르는 창을 연다. 패널과 플러그인은 모델·원본 파일을 임의 수정/저장하지 않는다. 예외는 문서 안의 연결 ID 한 값이다(1, ADR-030): 객체·레이어·다른 설정은 건드리지 않고 파일을 저장하지 않는다. AI 수정은 요청의 모드(계획·자동)에 따라 열린 문서를 바로 고치고 실행마다 되돌리기 기록을 남긴다(SPEC-02.11·02.20, [ADR-022](../decisions/ADR-022-direct-apply-plan-auto.md)). 닫힘/재연결은 이전 연결의 쓰기 대상을 승계하지 않고, 서버 종료는 사용자 호스트를 종료하지 않는다.

### 이전 연결 방식(2026-09-28)

문서별 Connect/Disconnect 패널과 '별도 후보에서 실행하고 확인한 변경만 적용'하던 방식은 위의 Link(2026-09-29)와 바로 적용(2026-09-30 ADR-022)으로 대체되었다. 이전 규칙은 Git 이력에 있다.

### 네이티브 블록이 있는 문서의 취득

블록 인스턴스와 그 정의에 속한 객체는 서로 다른 보존 대상이다. 화면 객체 수와 저장 파일 내부 객체 수가 다르다는 이유만으로 누락을 판정하지 않는다. 취득 기준은 블록 정의의 형상·속성과 정의/인스턴스 관계를 포함하고, 정의만 변경되어도 이전 기준을 재사용하지 않는다. 화면에서 아직 표현하지 못한 블록을 원본에서 없는 객체로 해석하지 않는다. 읽기 보존 지원은 블록 편집·적용 지원을 뜻하지 않는다.

### 큰 문서의 분할 취득

읽기 Sync는 연결된 Rhino에서 화면용 형상·객체 ID·속성을 직접 조회한다. 전체 네이티브 작업 사본의 저장·재열기 검증을 화면 표시의 선행 조건으로 요구하지 않는다. 숨긴 객체는 Rhino의 표시 상태를 따르고, 미지원 표시 유형은 명시한다. 조회만으로 원본 형상을 수리·삭제하거나 파일을 저장하지 않는다.

AI 편집은 열린 문서에서 바로 실행하므로(SPEC-02.11) Sync 표시 기준이나 작업 사본 검증을 편집의 선행 조건으로 두지 않는다. 실행 뒤 그 문서를 다시 읽어 표시를 갱신하며, 편집 성공과 후속 Sync 실패는 구분한다(SPEC-02.16). Sync에서 수량 계산을 수행하지 않은 값은 미계산으로 유지한다.

표시 데이터를 여러 번 나눠 읽더라도 동일 기준의 모든 페이지를 검증한 뒤에만 새 성공 모델로 확정한다. 페이지 중 실패·중복·기준 변경·크기 상한 초과는 기존 성공 모델을 유지하며 일부만 성공으로 저장하지 않는다. 표시 데이터를 다시 읽는 것은 네이티브 실행을 재실행하지 않는다. 블록 상세 표현과 큰 단일 형상의 표시 상한은 별도 지원 범위로 알린다.
