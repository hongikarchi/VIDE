# 법규 Q&A (cLAWde 연동)

이 명세는 VIDE 안에서 법규를 묻고 답을 보는 동작만 정한다. 법령 DB·온톨로지·수집·판정 규칙은 cLAWde 저장소가 소유한다([ADR-040](../decisions/ADR-040-domain-services.md)). 서비스와 주고받는 물리 계약(주소·인증·필드)은 [ARCH-01](../architecture/ARCH-01-system.md) §「외부 도메인 서비스」, jig 공통 동작은 [SPEC-07](SPEC-07-jig-platform.md), 대화·경로 판정·질문 카드는 [SPEC-02](SPEC-02-execution-candidates.md) SPEC-02.17·19, 프로젝트 자료와 인용 규칙은 [SPEC-08](SPEC-08-project-facts.md), 대지 형상과 가능 매스는 SPEC-12가 소유한다. 구현 순서와 시험은 [PLAN-46](../plans/PLAN-46-legal-qa.md)이다.

이 기능은 PRD C-06(법규 질의응답)과 C-04(외부 서비스 연동)를 구체화한다. 2026-10-07 사용자가 두 후보를 채택했고 제공 범위는 PRD §14.2의 '법규 Q&A' 행이다. cLAWde는 새 저장소로 시작하며 과거 법규 검토 자산 세 곳(RESEARCH-04 S-01·S-04·S-19)을 종합한다(PLAN-46 T-215).

## 대충 물어도 근거와 함께 적용 여부를 답한다 — SPEC-13.1

근거: [PRD](../PRD.md) §4.4 C-06·C-04, §6.3, FR-09·18·25, [RESEARCH-16](../research/RESEARCH-16-domain-services-roadmap.md) §3. **설계자는 "우리 건물은 일조 사선 봐야 해?"처럼 대충 묻는다. VIDE는 이 프로젝트의 대지·용도·규모·설계 단계와 모델 정보를 붙여 cLAWde에 묻고, 결론을 먼저 보인 뒤 근거 조항(원문 링크)·원문 발췌·해석·확인 필요 사항을 차례로 보인다. 모자란 정보는 되묻는다.**

1. **묻기:** 대화에서 묻거나, 법규 jig 패널의 질문 칸에 적는다(SPEC-13.2).
2. **보낼 정보 확인:** 처음 보낼 때와 보낼 정보가 바뀐 뒤에는 무엇이 나가는지 보이고 사용자가 확인한다(SPEC-13.3·13.4).
3. **답 보기:** 결론 → 근거 → 해석 → 확인 필요 사항 순서의 답 카드(SPEC-13.5).
4. **되묻기:** 용도처럼 답이 갈리는 정보가 없으면 질문 카드로 묻고, 답을 받아 다시 묻는다(SPEC-13.7).
5. **단계별 보기:** 지금 설계 단계에서 봐야 할 법령 목록과 이 프로젝트의 적용 여부를 본다(SPEC-13.6).
6. **문장의 품질:** 판정과 근거는 cLAWde가 규칙으로 정하고, 답 문장은 사용자의 CLI가 cLAWde가 준 방법(레시피)대로 쓴 뒤 VIDE와 cLAWde가 검증한다(SPEC-13.13).
7. **모델과 잇기:** 답이 가리키는 대지·인접 대지·방위를 뷰포트에서 보고, 수치 제한은 SPEC-12의 가능 매스 계산에 넘긴다(SPEC-13.8).
8. **되돌려 보내기:** VIDE에서 확인한 프로젝트 정보를 항목마다 골라 cLAWde로 보낸다(SPEC-13.10).

**완료 기준(1차):** 가짜 cLAWde 서버(PLAN-46 T-216)로 다음이 통과한다. 대화와 패널 두 길에서 같은 답 카드가 보이고, 보낼 정보 확인 전에는 아무것도 나가지 않으며, 근거 조항마다 원문 발췌와 링크가 있고, 근거 없는 결론은 '판단 불가'로 보이며, 되묻기 답이 법규 프로필에 남아 다시 묻지 않고, 서비스가 꺼지면 캐시한 답을 조회 시각과 함께 보이고 새 질문은 보내지 않으며, 역전송은 고른 항목만 나간다. 레시피로 쓴 문장 중 근거 팩 밖 조항·근거 없는 수치·판정 변경이 든 표본은 '문장 생성 검증 실패'로 보이고 판정·근거만 남는다. 실제 cLAWde로 한 검수는 VERIFY로 따로 남긴다.

## 1. 묻는 길 — SPEC-13.2

근거: FR-25·24, SPEC-02.17·19, SPEC-07.18.

| 길 | 동작 |
|---|---|
| 대화 | 어떤 대화든 AI가 법규 도구(SPEC-13.9)로 cLAWde를 부른다. Jev가 법규 질문으로 판정한 새 요청은 이 프로젝트의 법규 대화로 간다(SPEC-02.17의 경로 판정, 대화가 없으면 새로 연다). AI의 답에도 SPEC-13.5의 답 카드가 붙는다 |
| 법규 jig 패널 | 공식 내장 jig '법규 검토'(J-03, SPEC-07 §9의 내장 jig). 질문 칸, 답 카드 목록, 단계 체크리스트(SPEC-13.6), 법규 프로필(SPEC-13.4)을 한 화면에 둔다. 패널의 질문은 대화 AI를 거치지 않고 엔진이 바로 cLAWde에 묻는다. 답 문장은 SPEC-13.13의 방법으로 쓴다 |

- 두 길은 같은 법규 프로필·캐시·답 기록을 쓴다. 패널에서 받은 답은 대화에서 `[L<번호>]`로 가리킬 수 있고, 대화에서 받은 답 카드는 패널 목록에도 보인다.
- 서비스가 연결되지 않았거나(SPEC-13.11) 이 프로젝트에서 껐으면 패널은 연결 안내만 보이고, 대화의 AI에는 법규 도구를 주지 않는다. 이때 AI가 법규를 답하면 그 답 전체가 'AI 추정 · 서비스 근거 없음'으로 보인다(SPEC-13.5).

## 2. 보낼 정보와 확인 — SPEC-13.3

근거: FR-18, PRD §6.3, SPEC-01.13의 4. **VIDE는 사용자가 확인한 정보만 cLAWde에 보낸다.**

- **보내는 것:** 질문 글, 설계 단계, 법규 프로필의 값(SPEC-13.4)과 각 값의 출처 구분, 모델 요약(대지 경계의 면적·방위, 정북 방향, 접한 도로 폭, 주변 건물 높이 요약, SHP 속성에서 읽은 지목·용도지역 코드). 모델 요약은 수치와 코드이며 형상 전체가 아니다.
- **보내지 않는 것:** 호스트 문서와 원본 파일, 형상 데이터, 프로젝트 자료의 진술·원문 발췌·메일, 사람 이름, 대화 기록, VIDE 데이터 폴더의 파일, 토큰 이외의 인증 정보.
- **확인 시점:** 프로젝트에서 처음 보낼 때, 그리고 보낼 값이 지난 확인 뒤 바뀌었거나 새 항목이 생겼을 때 '보낼 정보' 카드가 뜬다. 설계 단계만 바뀐 것은 다시 묻지 않는다(단계는 질문마다 함께 보이는 선택이다). 같은 질문·단계·보낼 정보로 캐시한 답이 있으면 보내지 않으므로 카드도 뜨지 않는다. 카드는 항목·값·출처를 보이고 항목마다 뺄 수 있다. [보내기]를 누르기 전에는 아무것도 나가지 않는다. 바뀌지 않았으면 카드 없이 보내고, 질문 옆에 '보낸 정보' 칩을 남겨 누르면 실제로 보낸 내용을 본다.
- **뺀 항목**은 이 프로젝트에서 다시 넣을 때까지 보내지 않는다. 답이 그 항목 때문에 갈리면 cLAWde가 되묻기(SPEC-13.7)로 돌려준다.
- 대화의 AI가 법규 도구를 부를 때도 같은 규칙이다. 확인이 필요하면 도구는 카드를 띄우고 답을 기다린다(SPEC-02.19의 6과 같은 대기 규칙).

## 3. 법규 프로필 — SPEC-13.4

근거: PRD §6.3, SPEC-08.6, SPEC-12. 법규 프로필은 이 프로젝트에서 법규 판단에 쓰는 사실의 묶음이다. 프로젝트마다 하나이며 작업환경 DB에 둔다.

| 항목 | 예 | 들어오는 길 |
|---|---|---|
| 대지 | 주소·PNU, 대지면적, 지목, 용도지역·지구·구역, 지구단위계획 여부, 접도 | SPEC-12의 대지 결과, 사용자 입력, 되묻기 답 |
| 계획 | 주용도·부용도, 연면적, 층수(지상·지하), 높이, 세대·실 수 | 사용자 입력, 되묻기 답, 모델에서 읽은 값 |
| 모델 요약 | 정북 방향, 대지 경계 면적, 인접 대지 방위, 주변 건물 높이 | SPEC-12의 대지 모델(SPEC-13.8) |
| 단계 | 규모검토·계획설계·기본설계·실시설계(SPEC-13.6) | 사용자 선택. 기본은 규모검토 |

- **값마다 출처를 둔다:** 서비스에서 받음(Site Modeling·cLAWde) · 모델에서 읽음 · 사용자 확정 · AI 추정. 출처와 판은 함께 보인다. AI 추정 값은 사용자가 확정하기 전에는 보내지 않는다(SPEC-13.3 카드에서 흐리게 보이고 고를 수 없다).
- **바꾸기:** 패널의 프로필 칸에서 고친다. 사용자가 고친 값은 사용자 확정이며, 서비스·모델에서 다른 값이 오면 알림만 하고 바꾸지 않는다(SPEC-07.6의 근거 변화 규칙과 같다).
- **근거 진술:** 값의 근거로 프로젝트 자료 진술(SPEC-08.6)을 가리킬 수 있다. 진술 내용은 보내지 않는다.
- 프로필이 바뀌면 그 값을 쓴 답은 '다시 확인 필요'가 된다(SPEC-13.9).

## 4. 답의 형식 — SPEC-13.5

근거: RESEARCH-16 §3 Front, PRD §6.3, SPEC-08.7. 답 카드는 위에서 아래로 다음 순서다.

1. **결론:** 적용 · 적용 안 됨 · 조건부 · 판단 불가 중 하나와 한 문장("일조 사선 제한을 받지 않습니다"). 판정 값은 언제나 cLAWde의 것이다(SPEC-13.13).
2. **이유:** 결론에 이른 까닭을 짧은 문장 몇 개로. 문장마다 근거 조항을 가리킨다.
3. **근거 조항:** 조항마다 법령명·조·항·호, 시행일, 원문 링크, 원문 발췌. 발췌는 서비스가 준 원문 그대로이며 VIDE가 고치거나 요약하지 않는다.
4. **해석:** 조항을 이 프로젝트에 적용한 풀이. 출처 표시를 붙인다(아래).
5. **확인 필요 사항:** 계획에 달려 지금 결론 낼 수 없는 것, 사람이 도면·현장·고시로 확인할 것, 그 확인으로 결론이 어떻게 바뀌는지.
6. **쓴 정보:** 이 답에 쓰인 프로필 항목과 값, 단계, 서비스 법령 DB의 기준일, 조회 시각.

그림이 있으면(예: 사선 제한 단면도) 3과 4 사이에 보인다. 그림은 이미지로만 보이며 글이나 스크립트로 실행하지 않는다. 모델 위 표시는 SPEC-13.8이다.

**출처 표시**(PRD §6.3)는 답의 문장·값마다 붙는다.

| 표시 | 뜻 |
|---|---|
| 원문 | cLAWde 법령 DB의 원문. 근거 조항의 발췌 |
| 서비스 확정 | cLAWde에서 사람이 확인한 판정·해석 |
| 서비스 해석 | cLAWde 판정 레코드의 문구 중 사람이 확인하지 않은 것 |
| AI 문장(검증됨) | 사용자의 CLI가 cLAWde 레시피대로 쓰고 검증을 통과한 결론·이유·해석 문장(SPEC-13.13). 레시피 판과 작성 모델을 함께 보인다 |
| AI 해석 | VIDE 대화의 AI가 덧붙인 풀이(검증 대상 아님) |
| 프로젝트 정보 | 법규 프로필의 값(그 값의 출처 포함) |

- **근거 없는 결론은 내지 않는다.** 근거 조항이 하나도 없는 '적용'·'적용 안 됨'·'조건부'는 VIDE가 '판단 불가(근거 없음)'로 낮춰 보인다. 이유 문장이 가리킨 조항이 답의 근거 조항 목록에 없으면 그 문장에 '근거 미확인'을 붙인다.
- **대화의 인용 규칙:** AI는 이 턴에 법규 도구가 돌려준 조항·답만 `[L<번호>]`로 인용한다(SPEC-08.7의 인용 게이트와 같은 방식). 도구가 돌려주지 않은 조문 번호나 수치를 쓰면 그 부분을 '확인되지 않은 인용'으로 표시한다. AI가 서비스 결론과 다르게 말하면 서비스 결론을 위에 두고 AI 말은 'AI 해석'으로 보인다.
- **계획에 달린 항목은 결론으로 바꾸지 않는다.** 서비스가 '조건부'로 준 답을 VIDE·AI가 '적용'이나 '적용 안 됨'으로 바꾸지 않는다.

## 5. 단계별 법령 — SPEC-13.6

근거: RESEARCH-16 §3 Backend, 2026-10-07 사용자 결정("설계 단계 + 인허가 단계 (추천)"). **설계 단계(규모검토·계획설계·기본설계·실시설계)마다 봐야 할 법령을 나누어 보이고, 항목마다 걸리는 인허가 시점(심의·허가·착공·사용승인)을 함께 붙인다.**

- 설계 단계가 목록의 축이다. 인허가 시점은 축이 아니라 항목의 표시이며 한 항목에 여럿 붙을 수 있고 없을 수도 있다(예: 주차 대수는 기본설계 항목이며 '허가'에서 확인됨). 인허가 시점으로 목록을 거를 수 있다.

- 패널의 '단계별 법령' 칸은 지금 단계의 항목만 보인다. 항목은 주제(예: 일조 사선, 주차, BF 인증), 이 프로젝트의 적용 여부(적용·적용 안 됨·조건부·확인 필요), 이 단계에서 보는 까닭 한 줄, 근거 조항 수다.
- 다른 단계의 항목은 '다른 단계 n개'로 접어 둔다. 예: BF 인증은 면적에 걸리는 부분이 아니면 규모검토 단계 목록에 들지 않고 기본설계 단계에 든다. 단계별 배치는 cLAWde가 정하며 VIDE는 그대로 보인다.
- 항목을 누르면 그 주제의 답 카드(SPEC-13.5)를 연다. 캐시에 있으면 캐시를, 없으면 그때 묻는다.
- 단계를 바꾸면 목록을 다시 받는다. 단계는 프로필(SPEC-13.4)에 남는다. 인허가 시점 거르기는 화면 상태이며 서비스에 다시 묻지 않는다.
- 대화의 AI도 같은 목록을 도구로 읽는다(SPEC-13.9).

## 6. 되묻기 — SPEC-13.7

근거: SPEC-02.19의 6, ADR-026. cLAWde가 답에 '필요한 정보'를 돌려주면(예: 주용도가 업무시설인지 근린생활시설인지에 따라 결론이 갈림) VIDE는 질문 카드로 묻는다.

- 카드 규칙(한 턴 최대 3개, 권장값, 이미 정한 것은 다시 묻지 않음)은 SPEC-02.19의 6을 따른다. 대화에서는 그 대화의 질문 카드, 패널에서는 VIDE 질문 카드다.
- 답은 법규 프로필에 사용자 확정으로 남고, 같은 질문을 그 답과 함께 다시 보낸다. 새로 보내는 항목은 SPEC-13.3의 확인을 거친다(카드의 답이 곧 확인이다).
- [권장값으로 진행]을 고르면 그 값은 '가정'으로 표시되어 보내고, 답 카드의 '쓴 정보'에 가정임을 보인다. 가정은 사용자 확정이 아니므로 역전송(SPEC-13.10)에서 고를 수 없다.
- 사용자가 답하지 않고 닫으면 서비스가 준 결론(대개 '조건부'·'판단 불가')을 그대로 둔다.

## 7. 모델과 잇기 — SPEC-13.8

근거: RESEARCH-16 §3 「모델과 연결」, ADR-030, SPEC-12.

- **모델에서 읽기:** SPEC-12의 대지 모델(대지 경계, 인접 대지, 도로, 주변 건물, SHP 속성)이 있으면 그 결과에서 모델 요약(SPEC-13.4)을 채운다. 프로젝트에 대지 모델이 여럿이면 가장 최근에 계산된 것을 읽는다. 읽는 값은 대지 요약(SPEC-12.5)과 대지 정보 점의 메타데이터(SPEC-12.6)의 것이며 VIDE가 새로 계산하지 않는다: PNU, 대지 위치, 대지면적(공부)과 계산 면적(따로), 지목, 용도지역·지구·구역(고시 포함), 접한 도로와 그 가운데 가장 넓은 도로의 계산 폭, 정북 기준(진북·도북)과 그 차, 주변 건물 수와 최고 높이. 대지 모델이 모르는 값(공부 면적 없음, 용도지역 미확인)은 채우지 않는다. 읽은 값의 출처는 '모델에서 읽음'이며 그 대지 결과의 판을 함께 둔다. 사용자 확정 값은 바꾸지 않고 다른 값을 알림으로만 보인다(SPEC-13.4). 대지 모델이 다시 계산되어 값이 바뀌면 프로필 값이 바뀌고 이전 값을 '바뀐 값' 알림으로 보이며, 그 값을 쓴 답은 '다시 확인 필요'가 되고 다음 질문은 보낼 정보 카드를 다시 띄운다(SPEC-13.3). 읽는 때는 프로필을 볼 때, 묻기 전, 단계별 목록을 받기 전이다.
- **답에서 모델로:** 답이 대지·인접 대지·도로를 가리키면 답 카드 머리 줄에 대상 칩이 붙고, 누르면 뷰포트에서 그 객체(Link ID, ADR-030)를 선택해 강조하고 화면에 맞춘다. 대상은 대지 모델이 Rhino에 만든 객체다: 대지는 대지 경계와 대상 필지, 인접 대지는 주변 필지, 도로는 도로 곡선. 되돌린 만들기와 지워진 객체는 가리키지 않는다. 대상을 찾지 못하면 칩에 '모델에 없음'을 보이고 누를 수 없다. 그 파일이 화면에 없거나 그 객체가 화면의 Sync에 아직 없으면 그렇다고 알린다. 강조는 VIDE 뷰포트의 선택일 뿐 호스트로 보내지 않는다(SPEC-01.11의 4).
- **수치 제한 넘기기:** 서비스 답이 근거 조항이 붙은 수치 제한(예: 정북 일조 사선의 높이·거리, 건축선 후퇴 거리)을 주면, 법규 jig는 그것을 출력 `legal.constraints`로 낸다. SPEC-12의 가능 매스 jig가 이 출력을 입력(SPEC-07.2의 '다른 jig의 출력')으로 받는다. VIDE는 서비스가 주지 않은 산식을 만들지 않으며, 근거 조항이 없는 수치는 출력하지 않는다.
  - 출력에 드는 제한은 가리킨 조항이 모두 그 답의 근거 조항에 있고, 그 조항마다 원문 발췌와 링크가 있는 것뿐이다. 제한마다 근거 조항(법령명·조·항, 원문 링크), 출처 표시(서비스에서 사람이 확인한 값이면 '서비스 확정', 아니면 '서비스 해석'), 적용 여부(답의 결론이 적용이면 '적용', 적용 안 됨이면 '미적용', 조건부면 '판단 필요')와 어느 답(`L<번호>`)에서 왔는지를 함께 둔다.
  - 같은 항목을 여러 답이 주면 가장 새 답이 정한다. 그 답이 '다시 확인 필요'이거나, 판단 불가(근거 없음 포함)로 보이거나, 근거가 확인되지 않거나 원문이 없으면 그 항목은 출력에서 빠지고 빠진 까닭이 함께 남는다. 더 오래된 답의 값으로 대신 채우지 않는다.
  - 가능 매스 jig에서는 사람이 넣은 값이 언제나 이기고, 법규 값은 사람이 비워 둔 항목만 채우며 다른 값은 차이로 알린다(SPEC-12.7의 5). '판단 필요'는 '판단 필요' 그대로 간다.
- 법규 jig는 Rhino에 직접 만들지 않는다. 형상은 SPEC-12의 jig가 만든다.

## 8. 기록·캐시·오프라인 — SPEC-13.9

근거: FR-09, ADR-040 결과, OQ-16.

- **답 기록:** 받은 답·체크리스트·조항은 프로젝트마다 작업환경 DB에 남는다. 기록에는 질문, 보낸 정보, 단계, 서비스 DB 기준일, 조회 시각, 답 전체와, 문장을 썼다면 레시피 판·작성 모델·effort·검증 결과(실패한 문장 포함)가 있다. 답 번호 `L<번호>`는 프로젝트 안에서 바뀌지 않는다.
- **같은 질문:** 같은 질문·단계·보낸 정보면 캐시한 답을 바로 보이고 '조회 시각'을 함께 보인다. [다시 묻기]를 누르면 새로 묻고 새 답을 이전 답 위에 쌓는다(이전 답은 지우지 않는다).
- **오래된 답:** 그 답이 쓴 프로필 값이 바뀌었거나, 서비스가 알린 법령 DB 기준일이 답의 기준일보다 새로우면 '다시 확인 필요'로 표시한다. 자동으로 다시 묻지 않는다.
- **서비스에 닿지 않을 때:** 캐시한 답·체크리스트·조항은 '오프라인 · n일 전 조회'로 계속 보인다. 새 질문은 보내지 않고 '서비스에 닿지 않음'과 [다시 시도]를 보인다. 질문을 쌓아 두었다가 나중에 저절로 보내지 않는다.
- **대화 도구:** `legal_ask`(질문), `legal_checklist`(단계 목록), `legal_article`(조항 원문), `legal_answers`(이 프로젝트의 답 기록) 네 가지다. `legal_ask`는 판정·근거와 검증된 문장(SPEC-13.13)을 함께 준다. 대화의 AI는 답 카드의 문장을 새로 쓰지 않고, 덧붙인 풀이는 'AI 해석'이다. 도구는 이 프로젝트 범위만 읽고, 역전송·프로필 쓰기는 하지 않는다. 서비스가 닿지 않으면 도구는 캐시 결과에 '오프라인' 표시를 붙여 주거나 `SERVICE_UNAVAILABLE`을 돌려준다.
- 다른 프로젝트의 답 기록은 읽지 않는다. 서비스 DB를 VIDE에 통째로 복제하지 않는다(공유 방식은 OQ-16).

## 9. 되돌려 보내기 — SPEC-13.10

근거: ADR-040 결정 3, OQ-17, FR-18, SPEC-08.5. **VIDE에서 확인한 프로젝트 정보를 cLAWde로 보내 그쪽 DB에 쌓는다. 사용자가 항목마다 골라 보낸다.**

- **보낼 수 있는 항목:** 법규 프로필의 사용자 확정 값, 되묻기 답(가정 제외), 사용자가 답 카드에 남긴 판단(예: "이 항목은 해당 없음을 확인함", 이유 포함), 사용자가 원문을 붙이기로 고른 프로젝트 자료의 확정 진술.
- **보낼 수 없는 항목:** AI 추정·서비스 해석·가정 값, 미확정·기각·오염 진술, 원본 파일, 사람 이름. 목록에 흐리게 보이고 고를 수 없다.
- **흐름:** 패널의 [cLAWde로 보내기]를 누르면 보낼 수 있는 항목이 체크 목록으로 보인다. 기본은 모두 꺼짐이다. 사용자가 고르고 [보내기]를 누르면 고른 항목만 한 번에 보낸다. 대화의 AI는 보내기를 제안할 수만 있고 직접 보내지 못한다.
- **기록:** 보낸 항목·시각·서비스가 준 접수 번호를 작업 기록에 남긴다. 이미 보낸 같은 값은 '보냄'으로 표시하고, 값이 바뀌면 다시 고를 수 있다.
- **실패:** 서비스가 일부 항목을 거절하면 거절한 항목과 이유를 보이고, 받은 항목은 '보냄'이 된다. 닿지 않으면 아무것도 '보냄'이 되지 않으며 쌓아 두었다가 저절로 보내지 않는다.

## 10. 연결 설정 — SPEC-13.11

근거: ADR-040, ADR-037, ADR-039, FR-18.

- 설정 → '외부 서비스'에 cLAWde 칸이 있다. 서비스 주소, 연결 상태(연결됨·닿지 않음·로그인 필요·꺼짐), 법령 DB 기준일, [연결]·[끊기]를 보인다.
- [연결]은 VIDE 계정(ADR-039)으로 서비스 토큰을 받는다. 계정에 로그인하지 않은 PC는 [연결]을 쓸 수 없다. 개발·시험용으로 주소와 토큰을 직접 넣을 수 있다. 저장한 토큰은 다시 보이지 않는다.
- 프로젝트마다 '이 프로젝트는 법규 서비스에 보내지 않음'을 켤 수 있다. 켜면 그 프로젝트에서는 묻기·역전송이 막히고 캐시만 보인다.
- 원격 세션(SPEC-04)에서는 설정과 토큰을 바꿀 수 없고 묻기·답 보기만 할 수 있다. 법규 프로필 고치기와 역전송도 이 PC의 화면에서만 한다. 보낼 정보 카드의 확인은 묻기의 일부이므로 원격에서도 된다.

## 11. 실패와 복구 — SPEC-13.12

| 상황 | 동작 |
|---|---|
| 서비스 미연결·프로젝트에서 끔 | 패널은 연결 안내, AI에는 법규 도구 없음. 캐시는 보인다 |
| 닿지 않음·시간 초과 | 캐시에 '오프라인' 표시, 새 질문은 보내지 않음, [다시 시도] |
| 토큰 만료·거절 | '로그인 필요'로 바꾸고 다시 연결을 안내. 같은 요청을 저절로 다시 보내지 않음 |
| 응답 형식이 계약과 다름 | 그 답을 저장하지 않고 '서비스 응답 오류'와 서비스 이름·시각을 보인다 |
| 근거 조항 없는 결론 | '판단 불가(근거 없음)'로 낮춰 보인다(SPEC-13.5) |
| 발췌·링크가 빠진 조항 | 그 조항에 '원문 없음'을 붙이고 결론의 근거 수에서 뺀다 |
| 보낼 정보 확인을 닫음 | 보내지 않는다. 질문은 패널에 '보내지 않음'으로 남는다 |
| 되묻기에 답하지 않음 | 서비스 결론을 그대로 둔다 |
| 역전송 일부 거절 | 거절 항목과 이유를 보이고 받은 항목만 '보냄' |
| 대상 칩의 객체가 모델에 없음 | 칩에 '모델에 없음' |
| 레시피가 요구하는 모델이 이 PC에 없음·인증 실패 | 문장을 쓰지 않는다. 판정·근거·확인 필요 사항과 '문장 생성 안 함 · 자격 모델 없음'을 보인다 |
| 문장 검증 실패(로컬 또는 `/v1/verify`) | 그 문장을 보이지 않는다. 판정·근거와 '문장 생성 검증 실패'(이유 펼침)를 보인다. 자동으로 다시 쓰지 않고 [다시 쓰기]만 둔다 |
| 레시피 판이 낡음 | 새 판을 받아 다시 쓴 뒤 보인다. 받을 수 없으면 검증 실패와 같다 |

## 12. 답 문장과 품질 관리 — SPEC-13.13

근거: 2026-10-07 사용자 결정. 답 문장을 쓰는 LLM을 cLAWde에 두지 않고 VIDE에서 사용자의 CLI가 쓰는 안을 골랐고, "품질은 각자라는 말이 좀 걸리네. 분석하는 방법이나 모델을 계획해서 주면 퀄리티 컨트롤이 가능하지 않을까?"라고 했다. **판정과 근거는 cLAWde가 규칙으로 정하고, 문장은 cLAWde가 정한 방법·모델로 쓰며, 검증을 통과한 문장만 답으로 보인다.**

1. **cLAWde가 주는 것:** 판정(규칙 기반), 근거 팩(인용할 조항과 원문), 계산값, 필요한 정보·확인 필요 사항, 그리고 레시피. 레시피는 판이 붙은 문장 틀, 출력 구조, 인용할 수 있는 조항 목록, 문장에 나올 수 있는 수치 목록, 쓸 수 있는 최소 모델 등급과 effort(예: Claude Opus·Sonnet 5.x, Codex Sol급)다. cLAWde는 답 문장용 LLM 키를 갖지 않는다.
2. **쓰기:** 엔진이 사용자의 CLI를 레시피가 정한 모델·effort로 한 번 띄워 근거 팩만 주고 결론·이유·해석 문장을 받는다. 대화의 모델·도구·프로젝트 파일은 쓰지 않는다. 이 PC에 자격 모델이 없으면 쓰지 않고 판정·근거만 보인다(SPEC-13.12). 새로 받은 답마다 한 번 쓰고, 캐시에서 보인 답은 저장한 문장을 그대로 보인다. 근거가 없어 VIDE가 판정을 '판단 불가'로 낮춘 답과 레시피·근거 팩·계산값이 없는 답에는 문장을 쓰지 않는다. 레시피 판이 낡았다는 검증 결과는 현재 판을 받아 한 번 다시 쓰는 것으로 처리하며, 그 밖의 실패는 [다시 쓰기]를 누를 때만 다시 쓴다.
3. **검증:** 다음을 모두 지켜야 통과다. 출력 구조가 맞음 · 가리킨 조항이 모두 근거 팩 안 · 문장의 모든 수치가 인용 원문이나 계산값에 있음 · 판정을 바꾸거나 올리지 않음(조건부·판단 불가를 적용·적용 안 됨으로 바꾸지 못함). VIDE가 먼저 검사하고, 통과하면 cLAWde가 같은 검사와 레시피 판·모델 자격을 다시 본다. 서비스가 닿지 않아 두 번째 검사를 못 하면 '로컬 검증만'을 함께 보인다.
4. **보이기:** 통과한 문장은 'AI 문장(검증됨)'과 레시피 판·작성 모델을 붙여 결론·이유·해석 자리에 보인다. 통과하지 못한 문장은 답으로 보이지 않고, 판정·근거·확인 필요 사항과 '문장 생성 검증 실패'를 보인다. 이때 결론 자리에는 cLAWde의 결정적 문장을 보인다.
5. **기록:** 답마다 레시피 판, 작성 모델·effort, 검증 결과를 남긴다(SPEC-13.9). 실패한 문장도 감사용으로 남기며 답 카드에는 보이지 않는다.
6. **모델 인증:** cLAWde는 골든 질문 묶음(기대 판정과 반드시 인용할 조항)을 관리한다. 사용자가 설정의 cLAWde 칸에서 [모델 인증]을 누르면 VIDE가 그 묶음을 이 PC의 모델로 돌려 통과 수를 보인다. 마지막 인증이 실패한 모델은 다시 통과할 때까지 문장 쓰기에 쓰지 않는다. 인증은 누를 때만 돈다.

## 13. 이 명세 범위 밖

cLAWde의 법령 수집·정규화·온톨로지·판정 규칙·단계 배치 규칙(cLAWde 저장소), 대지 형상 수집과 가능 매스 계산(SPEC-12), 법규검토 보고서 문서(A/B/C 검토서, RESEARCH-04 J-03)의 VIDE 안 생성, 인허가 일정, 서비스 DB를 직접 읽거나 사본으로 동기화하는 방식(OQ-16), 다른 PC·다른 사용자의 답 기록 공유(계정 사이트 공유는 후속), 지자체 고시 PDF 판독, 자동·주기 재질의.
