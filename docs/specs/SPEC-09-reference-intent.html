참고 이미지로 의도 확인

근거: 2026-10-01 사용자 결정 — "레퍼런스 이미지를 보고 내가 원하는 부분을 명확히 파악(마스킹해서 딱 표시) → 제대로 파악했는지 말로 설명 + 이미지로 빠르게 생성 → 그거를 모델링으로 반영". FR-07(자료 참조), FR-08(AI 요청·문맥), FR-10(검토 가능한 과정), FR-12(바로 적용·되돌리기), FR-14(산출물), FR-18(전송 권한), FR-25(대화). PRD에는 이 기능의 약속 문장이 아직 없다. 범위 문장은 PRD §13·§14에서 사용자가 정하고, 그 전까지 이 명세는 draft다.

이 기능은 jig가 아니라 VIDE의 기본 기능이다. 같은 흐름을 반복하는 작업(예: 파사드 루버 배치)은 나중에 이 기능 위에 jig로 만들 수 있다(SPEC-07). 첨부 자체(경로 기반 첨부, 모든 형식, AI의 읽기 도구가 이미지를 모델에 돌려줌)는 SPEC-01 SPEC-01.12(PLAN-26 T-089)가 소유하고, 이 명세는 첨부된 이미지를 참고 이미지로 쓰는 동작만 정한다. 화면 표현은 Design(보완 예정), 도구 이름·저장 경로·이미지 작업의 실행 인자는 ARCH-01(보완 예정), 순서와 시험은 PLAN-26 T-090이 소유한다.

00 / 참고 이미지에서 원하는 부분을 짚고, 이해를 확인하고, 모델에 반영한다 — SPEC-09.1

사용자 입력 프로그램의 동작 사용자가 확인할 결과
이미지를 첨부하고 [영역 표시]를 누르거나 "이 루버 느낌으로" 같은 요청을 보냄 가운데 열 위쪽 줄에 '참고 이미지 · <파일 이름>' 탭을 열고 영역 표시 편집기를 보인다 원본 이미지와 표시 도구
붓·올가미·사각형으로 영역 A·B·C를 칠하고 영역마다 메모 영역을 원본과 따로 저장한다. 원본 이미지는 바꾸지 않는다 반투명 영역과 글자 표시, 영역 목록
[이해 확인] 지금 대화의 AI에 이미지·영역·메모를 보내 영역별 해석을 받는다(SPEC-09.4). 탭 이름이 '이해 확인 · <제목>'으로 바뀐다 오른쪽 AI 열의 말 답변, 가운데 보드 왼쪽의 영역별 말풍선
(기다림) 말풍선이 나온 뒤 이미지 작업이 3D 뷰 캡처·참고 이미지·해석으로 우리 건물에 입힌 이미지를 만든다(SPEC-09.7) 보드 오른쪽의 '생성 중' 자리 → 생성된 이미지
말풍선을 눌러 고침 그 영역만 다시 해석한다(SPEC-09.6) 그 말풍선만 바뀌고 오른쪽 이미지는 '이전 해석' 표시 뒤 다시 생성
[맞음 → 모델링 반영] 확정한 해석을 다음 턴의 입력으로 자동 모드에 보낸다(SPEC-09.8) 열린 문서의 실제 변경과 바뀐 객체 목록, [되돌리기]

대화의 공급자가 Claude든 Codex든 같은 흐름이다. 해석은 그 대화의 AI가 하고, 이미지는 이미지 작업이 따로 만든다.

01 / 참고 이미지 탭 — SPEC-09.2

  1. 이미지 첨부(SPEC-01.12가 이미지로 읽는 형식: PNG·JPEG·GIF·WebP)에는 [영역 표시]가 있다. 누르면 그 이미지의 참고 이미지 탭을 연다. 같은 첨부를 다시 누르면 기존 탭으로 간다. AI가 이미지 첨부를 받은 턴에서 영역이 필요하다고 판단하면 답변에 [영역 표시] 행동을 제안할 수 있다. 탭을 스스로 열지는 않는다.
  2. 탭은 위쪽 줄(열어 둔 것만 보이는 줄, Design §03)에 jig 문맥 탭과 함께 놓인다. 닫아도 보드와 영역·해석 기록은 남고, 대화의 해당 카드나 작업 이력에서 다시 연다.
  3. 보드 하나는 참고 이미지 하나와 대화 하나에 묶인다. 대화를 바꾸면 보드는 남고, 새 대화에서 [이해 확인]을 누르면 그 대화에 묶인 새 판(SPEC-09.6의 판)이 된다.
  4. 호스트 패널(SCR-12)에는 이 탭을 그리지 않는다. 호스트 패널에서 첨부한 이미지는 데스크톱에서 연다.

02 / 영역 표시 편집기 — SPEC-09.3

  1. 도구: 붓(굵기 조절), 올가미(손으로 닫는 다각형), 사각형, 지우개. 확대·이동은 휠·스페이스 끌기로 한다.
  2. 영역: 새 영역을 시작할 때마다 A, B, C… 글자가 붙는다(개수 제한 없음, 2026-10-01 사용자 결정. Z 다음은 AA). 지금 영역에 그리는 획은 그 영역에 더해지고, 지우개는 지금 영역에서만 지운다. 영역마다 메모 한 줄(선택, 예: "루버 간격과 깊이만")을 단다. 영역을 지우면 글자는 다시 쓰지 않는다(뒤 영역 글자가 당겨지지 않는다).
  3. 되돌리기: 획·영역 추가·삭제·메모 단위로 Ctrl+Z / Ctrl+Shift+Z. 편집기를 닫았다 열어도 영역은 남는다.
  4. 영역이 없으면 이미지 전체를 영역 A 하나로 본다.
  5. 영역 표시는 원본 위의 겹침이다. 원본 파일을 바꾸지 않고, 영역은 이미지 좌표(원본 픽셀 기준 비율)로 저장한다.
  6. [이해 확인]은 영역이 하나 이상(또는 전체)이고 지금 대화가 이미지를 받을 수 있는 공급자·모델일 때 켜진다. 받을 수 없으면 이유('이 모델은 이미지를 읽지 않습니다')를 보인다.

03 / 해석 결과의 의미 — SPEC-09.4

AI는 영역별 해석을 정해진 모양으로 돌려준다(필드 이름·전달 형식은 ARCH-01). 말 답변은 같은 해석을 사람이 읽는 문장으로 한 번 더 쓴 것이고, 보드는 정해진 모양에서 그린다.

항목 뜻
전체 요약 무엇을 어디에 적용하려는지 한 문장(예: "남측 파사드 전면에 수직 루버를 600 간격으로")
영역 id 사용자가 그린 영역 글자. AI가 영역을 새로 만들지 않는다
기준점 말풍선 꼬리가 가리킬 이미지 안의 점(비율 좌표). 없으면 영역의 중심
요소 그 영역이 무엇인지 짧은 이름(예: 수직 루버)
읽은 값 이름·값·단위와 출처: 사용자(메모에 적은 값), 추정(이미지에서 읽은 값, "약"·"느낌"으로 표시), 모름
한 줄 설명 말풍선 문장(예: "A: 수직 루버 · 간격 약 600 · 깊이 300 느낌")
확인할 것 이미지로 정할 수 없는 것(예: 재료, 끝 처리). 말풍선 아래 '?'로 보인다
적용 대상 우리 모델의 어디에(핀한 객체·레이어, 또는 '모름'). 모르면 [맞음] 전에 묻는다(SPEC-09.8)
이미지 지시문 이미지 작업에 줄 영어·한국어 지시문. 사용자에게는 [자세히]에서만 보인다
  • 말풍선의 글자는 VIDE가 겹침으로 그린다. 생성 이미지에 글자를 그려 넣지 않는다(이미지 모델은 한글을 망가뜨린다). 그래서 말풍선 하나를 눌러 그 영역만 고칠 수 있다.
  • 정해진 모양이 오지 않거나 영역 id가 맞지 않으면 말 답변만 보이고 보드에는 '말풍선을 만들지 못했습니다 · [다시 확인]'을 보인다. 추측으로 말풍선을 채우지 않는다.

04 / 확인 보드의 상태 — SPEC-09.5

보드는 두 이미지를 나란히 둔다: 왼쪽은 참고 이미지 + 사용자 영역 + 말풍선, 오른쪽은 우리 건물에 요소를 입혀 본 이미지.

상태 왼쪽 오른쪽 오른쪽 AI 열 할 수 있는 일
답하는 중 영역만, '읽는 중' 비어 있음 진행 중 턴 [중단]
말풍선 준비 영역 + 말풍선 '생성 대기' 또는 '생성 중' 말 답변 + 확인 카드 말풍선 고치기, [맞음], [다시]
이미지 생성 중 같음 '우리 건물에 입혀 본 이미지 · 생성 중'과 걸린 시간 같음 [생성 취소], 말풍선 고치기, [맞음]
이미지 실패 같음 실패 이유 + [다시 생성] 같음 [다시 생성], [맞음](이미지 없이)
이미지 준비 같음 생성 이미지(누르면 크게) 같음 말풍선 고치기, [맞음], [다시]
이전 해석 고친 말풍선 표시 지난 이미지에 '이전 해석' 띠 같음 자동 다시 생성(SPEC-09.6)
확정 말풍선 고정(고칠 수 없음) 마지막 이미지 모델링 턴 진행 [새 판으로 고치기]

[다시]는 영역 표시 편집기로 돌아가 영역·메모를 고친 뒤 전체를 다시 해석한다. [맞음]은 이미지를 기다리지 않는다. 확정 뒤에 고치려면 새 판을 만든다(이전 판은 기록에 남는다).

05 / 말풍선으로 고치기 — SPEC-09.6

  1. 말풍선을 누르면 그 자리에 메모 칸이 열린다("간격은 450, 깊이는 맞음"). [이 영역만 다시]를 누르면 같은 대화의 다음 턴으로 그 영역만 다시 해석하게 한다. 다른 영역의 해석은 그대로 고정해 함께 보내고, AI는 그 영역들을 바꾸지 않는다.
  2. 답이 오면 그 말풍선만 바뀌고 판 번호가 오른다(판 1, 판 2…). 사용자가 메모로 준 값은 출처가 사용자가 된다.
  3. 해석이 바뀌면 오른쪽 이미지는 '이전 해석' 띠를 달고 새 이미지 작업이 자동으로 시작된다. 진행 중이던 이미지 작업은 취소한다. 이전 이미지는 판 기록에 남는다.
  4. 말로 고쳐도 된다("B는 루버가 아니라 차양이야"). AI가 영역을 짚으면 같은 규칙으로 그 영역만 바뀐다. 짚지 못하면 어느 영역인지 묻는다.

06 / 이미지 작업 — SPEC-09.7

  1. 한 장에 한 번 실행. 이미지 작업은 대화 세션 없이 한 장마다 한 번 실행하는 Codex CLI 작업이다(ChatGPT 로그인의 기본 이미지 생성, API 키 없음). 대화의 공급자와 상관없이 같다. 실행 인자·격리는 ARCH-01이 정한다.
  2. 입력: 지금 모델 뷰의 캡처(대화 AI의 뷰 캡처와 같은 방법, 문서는 바꾸지 않음), 영역을 눈에 보이는 겹침으로 그린 참고 이미지, 해석의 이미지 지시문. 정확한 픽셀 마스크는 쓰지 않는다(이 경로에서 지원하지 않음). 연결된 모델이 없으면 이미지 작업을 하지 않고 오른쪽에 '연결된 모델이 없어 만들지 않음'을 보인다.
  3. 순서: 말풍선이 먼저 나오고, 이미지는 그 뒤에 채워진다. 보드 하나에 이미지 작업은 하나만 돈다. 다른 대화와 다른 문서의 작업을 막지 않는다.
  4. 시간 제한·취소: 시간 제한은 1분이다(2026-10-01 사용자 결정: 확인 이미지는 빠른 검토용이라 모델링보다 오래 걸리면 쓸모가 없다). 생성은 빠른 품질·작은 크기로 요청한다. [생성 취소]와 1분 초과는 프로세스를 끝내고 '취소됨'·'시간 초과 · 이미지 없이 확인'을 보인다. 이미지가 없어도 말풍선 판으로 [맞음]을 누를 수 있다. 부분 결과는 쓰지 않는다.
  5. 실패: Codex 없음, 로그인 안 됨, 사용 한도, 이미지 생성 거절, 결과 파일 없음을 구분해 이유와 [다시 생성]을 보인다. 실패는 해석과 [맞음]을 막지 않는다.
  6. 사용량: 처음 생성하기 전에 한 번 '이미지 생성은 ChatGPT 요금제 사용량을 씁니다'를 알린다. 생성 한 장의 걸린 시간을 보드에 남긴다. 프로젝트 설정에서 이미지 생성을 끌 수 있고, 끄면 오른쪽은 '이미지 생성 꺼짐'이다.
  7. 생성 이미지는 참고용 시각화이며 도면·렌더링 산출물로 약속하지 않는다. 모델링의 기준은 확정한 해석이다(SPEC-09.8).

07 / 확정 → 모델링 반영 — SPEC-09.8

  1. 오른쪽 AI 열의 확인 카드: 전체 요약, 영역별 한 줄, [맞음 → 모델링 반영] [다시].
  2. 적용 대상이 '모름'이면 [맞음]을 누를 때 질문 카드(SPEC-02.19의 6)로 대상을 묻는다. 위치를 추측하지 않는다.
  3. [맞음]은 확정한 해석(판 번호, 영역별 요소·값·출처·적용 대상), 참고 이미지와 영역, 마지막 생성 이미지(있으면)를 다음 턴의 입력으로 같은 대화에 자동 모드로 보낸다. 대화가 계획 모드여도 [맞음]이 사용자 확인이므로 이 턴은 자동 모드로 실행한다(2026-10-01 사용자 결정). 실행은 SPEC-02.11·13의 바로 적용 흐름이다: 실행마다 되돌리기 기록과 바뀐 객체 목록, 보호 확인.
  4. AI는 확정한 값을 그대로 쓴다. 추정 값은 그 값으로 만들고 결과에 '이미지에서 추정한 값'으로 적는다. 바꿔야 하면 바꾸기 전에 묻는다.
  5. 확정한 판은 고정되고 대화 원장에 남는다. 모델링 결과를 보고 다시 고치려면 [새 판으로 고치기]로 보드를 이어 간다.

08 / 저장 위치 — SPEC-09.9

  • 참고 이미지 원본: 첨부 그대로. 이 기능이 복사·수정하지 않는다.
  • 보드 기록(프로젝트에 저장): 영역(획·도형과 글자·메모), 판별 해석, 판과 대화·턴의 연결, 확정 표시. 대화를 닫아도 남는다.
  • 이미지 파일(이 프로젝트의 산출물): 뷰 캡처, 영역을 그린 입력 이미지, 생성 이미지. 산출물 탭의 렌더링 보기(SPEC 미작성, PLAN-26 T-081의 나중 항목)에 판별로 보인다. Codex가 자기 폴더에 만든 결과는 산출물로 복사하고 그 폴더의 것은 기준으로 쓰지 않는다. 물리 경로는 ARCH-01이 정한다.
  • 보드를 지우면 보드 기록과 그 산출물 이미지를 지운다(확인 카드). 첨부 원본은 지우지 않는다.

09 / 데이터 보호 — SPEC-09.10

  1. 이미지는 이 PC에 남는다. 밖으로 나가는 곳은 둘뿐이다: 해석을 맡은 그 대화의 공급자, 이미지 작업의 Codex(OpenAI). 대화가 Claude여도 이미지 작업은 항상 Codex로 가므로 이미지가 OpenAI로도 간다. 따로 묻지 않는다(2026-10-01 사용자 결정). 이 사실은 설정 화면의 AI 안내에 적는다.
  2. 경로 판정(Jev)에는 이미지와 영역을 보내지 않는다(SPEC-02.17의 4의 전송 항목 그대로).
  3. 웹 공유·검토본에는 사용자가 명시해 넣을 때만 들어간다(SPEC-04).
  4. 원격 세션에서는 ADR-010 §3의 제한을 그대로 받는다. 이미지 작업은 이 PC의 Codex 로그인을 쓰므로 원격 세션에서는 실행하지 않는다.

10 / 완료 기준

.vide/ 아래 합성 모델과 직접 그린 참고 이미지로: 영역 두 개 표시 → [이해 확인] → 말풍선 두 개가 이미지보다 먼저 나옴 → 말풍선 하나 고치기로 그 영역만 바뀜 → 이미지 생성(또는 실패 이유) → [맞음]이 자동 모드 턴을 보내 열린 문서가 바뀌고 [되돌리기] 한 번으로 돌아감. 이미지 파일이 산출물에, 보드 기록이 프로젝트에 남는다. 말 답변이나 그림만 나온 것으로 완료하지 않는다.
