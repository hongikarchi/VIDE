# AI 작업 환경 — 지침·문맥·도구·격리·진행 방식

근거: FR-08(AI 요청·세션·문맥)·FR-18(데이터 보호·실행 권한)·FR-25(대화 세션·말로 하는 경로 판정), FR-27(AI 작업 환경의 표시). 2026-10-19 사용자 결정 D1 ③·D2 ③·D3 ②·D4 ②·D5 ①([RESEARCH-18](../research/RESEARCH-18-environment-not-model.md) §8, [ADR-044](../decisions/ADR-044-cli-environment-isolation.md)·[ADR-045](../decisions/ADR-045-working-modes-and-project-start.md))과 같은 날 사용자 메모(7).

VIDE는 모델을 바꾸지 않고 **모델이 일하는 환경**을 만든다. 이 명세는 그 환경의 동작 의미 — 어떤 지침이 붙고, 한 턴에 무엇이 들어가고, 어떤 도구와 권한이 주어지고, 사용자 자신의 CLI 설정 중 무엇을 끄고 켜며, 요청이 어느 길로 가는지 — 를 한 곳에서 소유한다. CLI 인자·환경 변수·패킷 형식은 [ARCH-01](../architecture/ARCH-01-system.md) §2가, 구현 순서와 검증은 [PLAN-55](../plans/PLAN-55-ai-environment.md)가, 설정 화면의 표현은 Design.md(SCR-24)가 소유한다. 지금까지 이 의미를 나눠 가졌던 SPEC-02.6·.17·.19·.20, SPEC-05.2, SPEC-07.18의 해당 절은 그대로 유효하며, 이 문서와 어긋나는 곳은 '정렬 필요'로 표시하고 PLAN-55가 그 절을 이 문서에 맞춘다. 다른 SPEC의 문장은 이 문서에서 고치지 않는다.

## 1. 환경의 정의와 층 — SPEC-18.1

**VIDE = 순정 CLI + 건축 환경 + 호스트 다리.**

| 층 | 무엇인가 | 정본 |
|---|---|---|
| 순정 CLI | 사용자가 구독한 Claude Code·Codex CLI를 그대로 실행한다. 모델·추론·공급자 기본 도구·자체 질문 기능은 CLI의 것이다([ADR-031](../decisions/ADR-031-stock-first.md) 1) | SPEC-02.18·SPEC-05.2 |
| 건축 환경 | 지침(2) · 문맥(3) · 도구와 권한(4) · 격리(5) · 진행 방식(6) · 개입(SPEC-02.4·.8·.19 4) · 화면(Design) · 확장(SPEC-07) | 이 문서와 각 SPEC |
| 호스트 다리 | 연결·Sync·핀·스케치·`execute`·요청 단위 되돌리기·같은 문서 쓰기 직렬화. 모델이 직접 읽지 못하는 Rhino·CAD 문서를 잇는 VIDE 고유 층 | SPEC-01·SPEC-02.13·.9 |

- **환경이 바꾸지 않는 것.** 모델 자체, 공급자의 기본 시스템 프롬프트(VIDE는 덧붙이기만 한다), CLI 프로그램과 그 판, 공급자의 로그인과 한도. VIDE는 CLI를 고치거나 감싸서 다른 동작을 흉내 내지 않는다.
- **환경이 더하는 것의 기준.** 터미널에 없는 것만 더한다(ADR-031 2). 건축 지침·건축 문맥·호스트 도구·보호 동작 확인·화면이다. 순정 CLI가 이미 하는 일(파일 읽기, 셸, 요약)은 VIDE가 다시 만들지 않는다.
- **호스트 다리는 순정으로 대체하지 않는다.** 외부 도구(5의 외부 MCP)가 호스트 문서를 다뤄도 핀·Sync·되돌리기·직렬화는 VIDE 경로에만 있다.

**수용 결과:** 같은 요청을 같은 모델로 터미널과 VIDE에서 보냈을 때, 차이는 이 문서의 2~6에 적힌 것으로만 설명된다.

## 2. 지침 층 — SPEC-18.2

한 턴에 붙는 지침은 네 층이다. 위에서 아래로 우선한다.

| 층 | 무엇 | 누가 소유·고치나 | 언제 붙나 | 사용자가 보나 |
|---|---|---|---|---|
| 이번 실행의 규칙 | 그 턴의 대상·모드·허용 도구·보호 동작 | VIDE가 턴마다 발급(4) | 매 턴 | 활동 로그·카드 |
| 전역 묶음 | 모드별(모델링·데이터·만들기·검토) 건축 작업 규칙, 호스트별 조각 | VIDE 코드. 판과 함께 바뀐다 | 매 턴, 모드·호스트에 따라 | 설정 → AI에서 읽기 전용(아래 3) |
| 프로젝트 AI 지시 | 그 프로젝트의 표기·단위·관례 | 구성원. 원본은 사이트, PC는 사본(SPEC-04.11 4) | 그 프로젝트의 턴 | 설정 → AI에서 보고 고침 |
| 작업 폴더 `AGENTS.md` | 작업 폴더에 있는 사람용 진입문(SPEC-01.13 7·10) | 사용자(폴더의 파일) | 작업 폴더가 있는 턴(D1 ③, 5) | 작업 폴더에서 |

jig `skill.md`(jig의 이름·설명·부름말·제외 말, jig 작성자 소유 SPEC-07.18, 만들기 탭에서 읽기 전용)는 경로 판정·카탈로그에만 쓰이며 층 순위에 들지 않는다.

1. **우선순위.** 이번 실행의 규칙 > 전역 묶음 > 프로젝트 AI 지시 > `AGENTS.md`. 아래 층은 위 층을 보충만 한다.
2. **충돌 규칙.** 아래 층의 문장은 권한·대상·보호 동작·확인 등급(SPEC-02.19 7)을 넓히지 못한다. 프로젝트 AI 지시와 `AGENTS.md`는 '자료'로 넣으며, 그 안의 "확인 없이 저장해", "폴더 밖도 읽어" 같은 문장은 지시로 따르지 않는다(PRD §4.3). 같은 층 안에서 두 문장이 다르면 AI는 위 층을 따르고, 결과가 달라지는 경우만 질문 카드로 묻는다(SPEC-02.19 6).
3. **전역 묶음 보기(D3 ②, FR-27).** 설정 → AI에 '매 턴 붙는 지침' 칸을 두고 모드(모델링·데이터·만들기·검토)와 호스트(Rhino·CAD)를 고르면 그 조합에 실제로 붙는 묶음 본문을 읽기 전용으로 보인다. 칸에는 그 묶음의 VIDE 판과 갱신일, 묶음 길이를 함께 적는다. 프로젝트 AI 지시는 같은 화면의 아래 칸에 따로 보인다.
4. **덮어쓰기 없음.** 사용자는 전역 묶음을 고치거나 끄지 못한다. 고치고 싶은 내용은 프로젝트 AI 지시에 적는다. 전역 묶음의 PC·프로젝트 덮어쓰기는 적용 조건 선언(경로·호스트·jig) 설계 뒤 별도로 정한다(ADR-045).
5. **길이.** 지침 전체(전역 묶음·프로젝트 AI 지시·작업 폴더 `AGENTS.md`)를 합친 길이에는 실행 환경의 물리 한계가 있다. 그 값(글자 수)은 ARCH-01 §2가 소유한다. 넘으면 가장 아래 층인 작업 폴더 `AGENTS.md`부터 자르고, 다음으로 프로젝트 AI 지시를 뒤에서부터 자른다. 전역 묶음은 자르지 않는다. 잘린 층은 그 턴의 '이번 턴 문맥'(3의 2)에 '일부만 들어감'으로 표시하고, 설정 → AI의 지침 보기(3)에도 프로젝트 AI 지시와 `AGENTS.md`마다 '넣음 / 없음 / 일부만 들어감'을 보인다.

**수용 결과:** 설정 → AI에서 모델링·Rhino를 고르면 지금 Rhino 모델링 턴에 붙는 묶음과 같은 본문·판·갱신일이 보이고, 고칠 수 있는 칸은 프로젝트 AI 지시뿐이다. 작업 폴더 `AGENTS.md`에 "확인 없이 저장"을 적어도 저장은 확인 카드를 거친다.

## 3. 문맥 조립 — SPEC-18.3

한 턴에 들어가는 문맥은 아래 표가 전부다. **지금 동작을 그대로 적는다.** 이 표는 SPEC-02.6(문맥 우선순위)·SPEC-02.17 6(대화의 문맥)·SPEC-02.19 5(인계)의 크기 서술을 모은다. 그 절들은 이관 예정이며(PLAN-55) 그때까지 같은 뜻으로 읽는다.

숫자는 2026-10-19 기준 참고값이고 정본은 ARCH-01 §2다. 이 절이 정하는 것은 넘칠 때의 동작(잘라서 알림 / 실패)이다.

| 항목 | 들어가는 것 | 상한 | 넘칠 때 |
|---|---|---|---|
| 요청 본문(goal) | 대상·모드 규칙·보호 객체·연결 파일 목록과 요청 문장 | 20,000자 | **실패**(턴을 시작하지 않음) — 정렬 필요 |
| 문맥 묶음 전체 | 아래 항목을 합친 한 덩어리 | 256 KB | **실패** — 정렬 필요 |
| 핀 | 고정한 객체 각각의 참조 | 200개, 나머지는 요약 | 잘라서 요약과 개수를 알림 |
| 스케치 | 그린 선·영역과 좌표 | 개수 상한 없음 | — |
| 작업 모델 요약 | 열린 문서의 객체 요약 | 100개 | 잘라서 '나머지는 조회로'를 알림 |
| 연결 파일 | 같은 프로젝트의 연결 파일 이름·상태 | 30개 | 잘라서 알림. 내용은 도구로 읽음(SPEC-02.6) |
| 보호 객체 | 이번 턴에 바꾸면 안 되는 객체 | 100개 | 잘라서 알림 |
| 첨부 | 이름·형식·위치만, 내용은 AI가 기본 도구로 읽음(SPEC-01.12 3) | — | — |
| 이미지 | 참고 이미지 | 장당 크기·턴당 장수 한도 | 넘는 이미지는 '빠짐'으로 표시하고 알림 |
| 폴더 | 작업 폴더·허용 폴더·폴더 칩 | 폴더 칩 64개 | 잘라서 알림 |
| 프로젝트 DB·자료 | 위치만. 내용은 자료 도구로 읽음(SPEC-08) | 도구 결과 한 번에 정해진 크기 | 잘라서 이어 읽을 위치를 줌(SPEC-02.6) |
| 노트·구성원 이력 | PC 사본 위치(SPEC-10) | — | — |
| 대화 이력 | 세션이 있으면 세션이 이어 감. 없으면 최근 교환 몇 개 | 요청·답 각각 길이 한도 | 잘라서 넣음 |
| 원장 | 대화에서 정한 조건·질문 답 | 정해진 크기, 주기적으로 전체 | 잘라서 넣음 |
| 인계 | 새 세션·다른 AI로 이어 갈 때의 요약(SPEC-02.19 5) | — | — |
| 다른 곳의 변경 | 다른 대화·호스트에서 바뀐 것, 아직 안 본 결과 | 각각 정해진 개수 | 최근 것만 |
| 질문 결과 | 질문 카드의 답(SPEC-02.19 6) | 턴당 질문 3개 | — |

1. **정렬 필요.** ADR-031 7은 남기는 상한을 셋(호스트 통신 한 덩어리, 모델 문맥, 동시 턴 수)으로 정하고 "나머지는 없애거나 넘으면 잘라서 알린다"고 했다. 요청 본문 20,000자와 문맥 묶음 256 KB에서 턴을 실패시키는 지금 동작은 이와 어긋난다. PLAN-55가 둘 중 하나로 맞춘다: 물리 한계임을 확인하면 ARCH-01에 근거를 적고 실패 안내를 보이며, 아니면 잘라서 알리는 쪽으로 바꾼다. 결정 전까지 실패할 때는 무엇이 얼마나 넘었는지를 대화 카드에 보인다.
2. **이번 턴 문맥 보기(FR-27).** 사용자는 턴마다 '이번 턴 문맥'을 펼쳐 위 표의 항목별로 무엇이 들어갔는지(개수·잘림 여부·빠진 것)를 본다. 본문은 보이되 비밀값·로그인 정보는 넣지도 보이지도 않는다(SPEC-02.19 7).
3. **추정 금지.** 잘렸거나 요약된 항목 밖의 객체·파일을 AI가 추정하지 않고 도구로 읽는다(SPEC-02.6).

**수용 결과:** 핀 250개를 고정해 보낸 턴의 '이번 턴 문맥'에 '핀 200개 + 요약 50개'가 보이고, 요청 본문이 상한을 넘으면 턴이 조용히 사라지지 않고 넘은 항목과 크기가 카드에 남는다.

## 4. 도구와 권한 — SPEC-18.4

1. **VIDE 도구 묶음.** 목적별로 묶어 턴마다 발급한다: 호스트(조회·실행·측정·보기), Grasshopper(읽기·쓰기), jig(열기·설정값·계산), 화면 이동, 만들기(초안 파일·점검), 질문, 프로젝트 읽기(연결 파일·Sync 표본·자료), 할 일·기록, 폴더 역할, 법규. 도구 하나하나의 이름과 형식은 ARCH-01이 소유한다.
2. **공급자 기본 도구.** 파일 읽기·쓰기와 셸은 프로젝트 작업 폴더 범위로 켠다(ADR-031 8, SPEC-01.13 2). 하위 에이전트·할 일 목록은 대화 안의 모델링·데이터·만들기 턴에서만, 웹 검색은 설정 「AI 웹 검색」을 켰을 때만 준다(SPEC-02.19 3). 만들기 대화는 초안 폴더 안의 파일 도구만 준다(SPEC-07.16).
3. **모드별 차이.** 계획 모드는 읽기·질문·화면·법규 도구만 받고 쓰기 도구(`execute`, Grasshopper 쓰기, 파일 쓰기)를 받지 않는다(SPEC-02.20). 자동 모드에서만 쓴다.
4. **폴더 범위와 승인.** 작업 폴더·허용 폴더 밖은 그때마다 승인 카드로 묻고, 늘 거절하는 위치는 승인해도 닿지 않는다(SPEC-01.13 3·4).
5. **확인이 필요한 동작.** 대량 삭제·레이어 삭제·정리·저장·다른 이름 저장·내보내기·게시는 실행 전에 확인 카드를 거친다(SPEC-02.13 4). 아래 층의 지침(2의 2)은 이 확인을 없애지 못한다.
6. **허용 밖 호출.** 그 턴에 발급하지 않은 도구를 부르면 그 호출 하나만 거절하고 AI에 거절로 알리며 턴은 계속된다. 활동 로그에 남는다(ADR-031 8, 지금 동작). 턴 시작 때 공급자가 알린 도구 목록이 발급 범위와 다르면 경고를 남기고 실행은 계속한다. **정렬 필요:** SPEC-02.19 3의 "다르면 실행하지 않고 멈춘다"와 7 끝의 "파일 쓰기 도구는 주지 않는다"는 이 항·ADR-031 8과 어긋난다. PLAN-55가 SPEC-02.19를 이 항에 맞춘다.

**수용 결과:** 계획 모드 턴의 도구 목록에 쓰기 도구가 없고, 자동 모드에서 작업 폴더 밖에 쓰려 하면 승인 카드가 뜨며, 허용 밖 도구를 부른 턴이 끝까지 진행되고 활동 로그에 거절이 남는다.

## 5. 격리 — SPEC-18.5

근거: D1 ③(2026-10-19, ADR-044). VIDE 턴은 사용자 자신의 CLI 환경과 분리하되, 사용자가 고른 것만 들인다.

1. **늘 끄는 것.** 개인 `CLAUDE.md`(사용자 폴더·상위 폴더), 공급자 플러그인, 스킬, 전역 MCP 서버, 개인 설정 파일(사용자·프로젝트·로컬 설정), 훅, 사용자 메모리. 끄는 것은 매 턴 다시 적용한다(SPEC-02.19 3).
2. **켜는 것 ① — 고른 외부 MCP 서버.**
   - 사용자가 설정 → AI의 '외부 도구(MCP)'에서 서버를 **프로젝트마다** 고른다. 고르지 않은 서버는 연결하지 않는다.
   - 처음 켜는 턴에 승인 카드로 묻는다: 서버 이름·하는 일·접근 범위 — [이 프로젝트에서 허용] [이번만] [거절](권장).
   - **턴별 켬·끔의 기본값.** [이 프로젝트에서 허용]을 고르면 그 뒤 그 프로젝트의 턴에서 기본이 '켬'이고 사용자가 턴마다 끌 수 있다. [이번만]을 고르면 그 턴만 켜지고 다음 턴은 '끔'이며, 다시 켜려 하면 승인 카드를 다시 보인다. [거절]을 고르면 꺼진 채로 남아 그 턴은 서버 없이 진행되고, 설정 → AI의 '외부 도구'에서만 다시 허용한다.
   - 작성기에 이번 턴의 외부 도구 켬·끔이 보인다. 끈 턴에는 그 서버에 연결하지 않는다.
   - 외부 MCP의 도구도 4의 6(허용 밖 호출)과 계획 모드 제한을 따른다. 계획 모드에서는 외부 도구도 읽기로 표시된 것만 준다.
3. **켜는 것 ② — 작업 폴더 `AGENTS.md`.** 작업 폴더(SPEC-01.13 7)의 `AGENTS.md`를 그 프로젝트 턴의 '자료'로 넣는다(2의 1·2). 개인 `CLAUDE.md`는 들이지 않는다. 작업 폴더가 없으면 넣지 않는다.
4. **외부 MCP가 호스트 문서를 쓸 때.** VIDE의 되돌리기·쓰기 직렬화·확인 카드는 VIDE `execute` 경로에만 있다. 외부 MCP가 열린 Rhino·CAD 문서를 고칠 수 있는 서버이면:
   - 승인 카드와 켬·끔 칸에 '이 도구의 변경은 VIDE 되돌리기 밖입니다(호스트 실행 취소로만 되돌림)'를 적는다.
   - 그 변경은 같은 문서 쓰기 차례(SPEC-02.9) 밖이라 다른 대화의 쓰기와 겹칠 수 있음을 함께 적는다.
   - 결과 카드에 외부 도구로 바뀐 것은 '외부 도구 변경'으로 구분해 보이고, VIDE가 바꾼 객체 목록(SPEC-02.13)에 섞지 않는다.
5. **실패.** 외부 MCP 서버에 연결하지 못하면 그 턴에서 그 서버의 도구만 빠지고 턴은 계속된다. 작성기와 활동 로그에 '○○ 연결 안 됨'을 보인다. 자동으로 다시 붙지 않고 다음 턴에 다시 시도한다.

**수용 결과:** 사용자 폴더에 개인 `CLAUDE.md`와 전역 MCP를 둔 PC에서 VIDE 턴은 둘 다 쓰지 않는다. 설정에서 고른 MCP 서버 하나는 처음 켤 때 승인 카드가 뜬다. [이 프로젝트에서 허용] 뒤에는 다음 턴이 '켬'으로 시작하고 켬·끔 칸으로 턴마다 끌 수 있으며, [이번만] 뒤에는 다음 턴이 '끔'이고 다시 켜면 승인 카드가 다시 뜨고, [거절] 뒤에는 설정에서 다시 허용하기 전까지 켜지지 않는다. 서버를 꺼 둔 채 보내도 턴이 끝까지 진행된다.

## 6. 진행 방식 — SPEC-18.6

근거: D2 ③(2026-10-19, ADR-045). 진행 방식은 사람이 정하고, 판정기는 그 안에서만 움직인다.

1. **기본은 대화.** 말로 한 요청은 대화 AI가 처리한다. 판정기(규칙·Jev)가 jig가 맞다고 보아도 jig를 열지 않고, 대화에 **jig 제안 카드**를 붙인다. AI 턴은 카드와 상관없이 그대로 시작한다.
2. **제안 카드.** jig 이름 · 왜 제안했나 한 줄(예: "'구조 검토'라는 말이 구조 검토 jig의 부름말과 맞음") · [열기] · [AI로 계속]. [열기]를 누르면 SPEC-07.18대로 jig를 열고 대화를 묶는다. [AI로 계속]이나 무시하면 카드는 접히고 대화 AI가 그대로 진행한다. 한 턴에 카드는 하나다.
3. **예외 — 지금대로 바로 처리하는 것.**
   - 사용자가 jig 이름으로 부르거나(예: "구조 검토 jig 열어") [JIG] 버튼으로 열 때.
   - 프로젝트에 고정된 jig의 설정값을 바꾸는 말(D2가 명시한 예외).
   - 화면·설정값·앱 동작(SPEC-02.17의 `view`·`param`·`app`). AI를 부르지 않는다.
   - "jig 열지 말고"는 제안 카드도 붙이지 않는다.
4. **계획부터.** '계획부터' 토글(SPEC-02.20)은 그대로 둔다. 판정기가 복잡하다고 보면 계획 카드를 제안할 수 있으나 모드를 스스로 바꾸지 않는다.
5. **다른 절과의 관계.** 이 절이 우선한다. SPEC-02.17 1~2(jig 열기를 AI 없이 처리), SPEC-07.18의 자동 열기, ADR-026 4(요청으로 jig 자동 열기)는 PLAN-55에서 이 절에 맞춘다. 그때까지 코드가 jig를 자동으로 열면 결함으로 본다.

**수용 결과:** "구조 검토하고 싶어"를 보내면 대화 AI가 답을 시작하고 구조 jig 제안 카드가 붙는다. [열기]를 누를 때만 jig가 열린다. "구조 검토 jig 열어"는 바로 열린다. 열린 고정 jig에서 "경간 11 m로"는 AI 없이 다시 계산된다.

## 7. 프로젝트 시작 두 길 — SPEC-18.7

근거: 2026-10-19 사용자 메모(D2 보충, 2026-10-19 P1 ① 수락, ADR-045). 프로젝트를 만들 때 **차근차근(설정 안내)** 과 **바로 시작** 중 하나를 고른다. 두 길은 같은 설정 항목을 묻는 순서와 시점만 다르다.

1. **고르는 때.** 대시보드에서 새 프로젝트를 만들거나 폴더로 만들 때(SPEC-01.13 7) 한 번 묻는다. 기본 선택은 '바로 시작'이다. 이미 있는 폴더를 다시 열 때는 묻지 않는다.
2. **차근차근의 체크리스트.** 다음 여섯 항목을 순서대로 한 장씩 묻는다. 각 장에는 [건너뛰기]가 있다.

   | 순서 | 항목 | 정본 |
   |---|---|---|
   | 1 | 작업 폴더 트리 | SPEC-01.13 7 |
   | 2 | 서버 폴더 연결과 스키마 확정 | SPEC-01.13 8 |
   | 3 | 프로젝트 AI 지시 | SPEC-04.11 4, 이 문서 2 |
   | 4 | 역할 경로 | SPEC-01.13 7~8 |
   | 5 | 자료 정리 범위 | SPEC-08 |
   | 6 | 기본 대화 모델 | SPEC-02.19 2 |

3. **바로 시작의 지연 질문.** 같은 여섯 항목을 처음에 묻지 않는다. 그 항목이 처음 필요해지는 때(예: AI가 역할 경로를 찾을 때, 첫 대화의 모델을 정할 때) 질문 카드(SPEC-02.19 6)로 한 번 묻는다. 사용자가 [나중에]를 고르면 같은 항목을 그 대화에서 다시 묻지 않는다.
4. **'프로젝트 설정 n/m'.** 어느 길이든 대시보드에 '프로젝트 설정 n/m'(끝낸 항목 수/여섯)이 남고, 누르면 남은 항목부터 체크리스트를 이어 한다. 건너뛴 항목은 언제든 이어 할 수 있다.
5. **AI 동작을 가르지 않는다.** 시작 길은 기록되지만 요청 경로(6)·도구와 권한(4)·격리(5)를 바꾸지 않는다. 설정하지 않은 항목은 각 정본의 '없을 때' 동작을 따른다(예: 작업 폴더가 없으면 임시 폴더, SPEC-01.13).

**수용 결과:** 같은 요청을 차근차근으로 만든 프로젝트와 바로 시작으로 만든 프로젝트에 보내면, 설정을 마친 뒤 경로·도구·권한이 같다. 바로 시작 프로젝트는 처음 필요할 때만 질문 카드가 뜨고, 대시보드의 '프로젝트 설정 n/m'에서 남은 항목을 이어 할 수 있다.

## 8. 모델·판 변경 — SPEC-18.8

근거: D4 ②(2026-10-19).

1. **대화 고정.** 공급자·모델은 대화의 첫 턴에 정하고 그 대화 동안 바꾸지 않는다(SPEC-02.17 5, SPEC-02.19 2). 다른 모델은 새 대화와 인계로 이어 간다. 공급자 목록과 실행 설정은 SPEC-05.2가 소유한다.
2. **판 범위.** 설치된 CLI의 판이 VIDE가 확인한 범위 밖이면 그 공급자로 실행하지 않고, 카드에 공급자·설치된 판·허용 범위를 보인다(SPEC-02.18 6). 다른 공급자는 계속 쓸 수 있다.
3. **범위 넓히기.** 허용 범위는 '판 갱신 절차'를 통과한 뒤에만 넓힌다. 절차(격리·세션·질문 기능 확인과 경로 회귀 시험)는 PLAN-24 T-059가 소유한다. 통과하지 못한 판은 범위 밖으로 남고, 무엇이 떨어졌는지를 PLAN에 남긴다.
4. **사용자에게 보이는 것.** 설정 → AI 연결에 공급자마다 설치된 판·허용 범위·범위를 마지막으로 넓힌 날을 보인다. 판이 범위 밖으로 바뀌면 다음 요청 전에 이 칸과 작성기에 알린다. 전역 지침 묶음의 판·갱신일(2의 3)도 같은 화면에서 본다.

**수용 결과:** CLI가 범위 밖 판으로 자동 갱신된 PC에서 그 공급자 요청은 실행되지 않고 판·범위가 카드에 보이며, 다른 공급자 대화는 그대로 진행된다.
