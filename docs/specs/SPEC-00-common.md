# SPEC-00 · VIDE 사용자 여정과 공통 동작 규칙

PRD 0.7의 핵심 경험을 세 가지 완결 작업으로 연결한다. 먼저 사용자 여정을 읽고, 기능별 정상 흐름과 뒤의 공통 규칙을 함께 적용한다. 제품 범위 변경은 PRD, 물리 필드와 전송 형식은 PLAN이 소유한다.


## VIDE에서 완결할 세 가지 작업 — SPEC-00.11

근거: PRD §8·§16.4, FR-01~12·14·16·19·22. **VIDE는 설계자가 Rhino·ZWCAD의 모델과 도면을 보고, 문장·핀·스케치로 AI에 작업을 맡기고, 실제 변경 후보를 조정해 네이티브 결과로 반영하는 작업환경이다.** 이 절은 기능 묶음이 연결되는 사용자 여정을 정의한다. 세부 동작은 아래의 기능 정본에서 읽으며, 뒤의 §1~10은 이 경험을 지키는 공통 규칙이다.

### 작업 A. 가리키고 그려서 설계를 수정한다

설계자는 호스트에서 작업하던 문서를 VIDE 프로젝트에 연결한다. 수동 Sync 뒤 모델·도면을 탐색하며 바꿀 객체와 유지할 객체를 고른다. 문장에 핀을 넣고 작업평면에 변경 방향이나 경계를 그려 요청한다. 프로그램은 이 입력으로 작업 목적·변경 대상·보존 조건을 구성하고, 지원 능력 안에서 실제 후보를 만든다. 사용자는 설명뿐 아니라 후보의 형상과 변경 수치를 보고 추가 지시한다. 마음에 드는 후보를 적용하면 해당 호스트에서 기본 편집 도구로 이어서 작업하고 저장할 수 있다.

| 단계 | 사용자가 하는 일 | 프로그램에서 관찰할 결과 | 기능 정본 |
|---|---|---|---|
| 작업 준비 | 프로젝트에 문서 연결, 지정 문서 Sync | 같은 작업 공간에서 모델/도면·객체·속성을 탐색 | SPEC-01.9 |
| 의도 전달 | 변경 핀·유지 핀·스케치·치수를 문장에 포함 | 원본 입력과 해석한 대상/목표를 나란히 확인 | SPEC-01.10 |
| 작업 위임 | 목표를 맡기고 필요한 모호함에 답함 | 검토 가능한 작업 구성, 실제 네이티브 후보와 측정 결과 | SPEC-02.11·12 |
| 방향 조정 | 후보를 보고 선·수치·보존 조건 변경 | 달라진 후보와 유지된 부분을 이전 기준과 비교 | SPEC-02.13 |
| 반영·후속 편집 | 검토한 변경 적용, 호스트에서 재편집·저장 | 실제 객체 유형·값·저장 결과 확인 | SPEC-02.13 |

이 흐름은 Rhino와 ZWCAD 각각에서 완결한다. 작은 요청은 복잡한 양식이나 작업 트리 작성을 요구하지 않는다. 작업 단위와 실행 이력은 프로그램이 관리하며, 사용자는 설계 목적과 결과를 중심으로 조작한다.

### 작업 B. 도면과 모델에 같은 설계 의도를 연결한다

설계자는 CAD 도면의 경계를 Rhino 생성 입력으로 지정하고, 두 문서의 좌표·단위·대응을 확인한다. 프로그램은 CAD에서 읽은 실제 경계에 연결된 Rhino 후보를 만든다. 이후 같은 변경을 도면과 모델에 요청하면 각각의 후보와 적용 결과를 같은 작업에서 확인한다. 선행 결과가 필요한 작업은 순서대로, 무관한 다른 문서 작업은 독립적으로 진행한다. 구체적인 요청과 결과는 SPEC-02.14가 소유한다.

두 프로그램 이름이 연결 목록에 보이는 것만으로 이 경험이 완성되지 않는다. 한 요청의 데이터가 실제로 다른 호스트의 생성·수정에 사용되고, 사용자가 대응·결과·부분 실패를 설명할 수 있어야 한다.

### 작업 C. 외부 의견을 실제 설계 변경과 전달로 이어간다

설계자는 모델·도면·표와 검토본을 공개 범위 안에서 공유한다. 외부 검토자는 설치 없이 웹에서 탐색하며 특정 대상에 핀·문장·스케치를 남긴다. 설계자는 VIDE에서 그 의견과 작성 당시 대상을 함께 열고, 채택할 내용을 수정 요청으로 연결한다. 작업 A/B의 흐름으로 변경한 뒤 전후 검토본과 갱신된 표를 비교하고 웹 상태 및 표·요약 파일로 전달한다. 세부는 SPEC-04.7과 SPEC-03.8이다.

### 구현자가 지켜야 할 해석

이 세 작업은 특정 예제 형상 하나를 고정 생성하는 데모가 아니다. 다른 대상·좌표·치수·선으로 같은 흐름을 수행할 수 있어야 한다. 개발용 예제와 출시 전체 범위를 혼동하지 않는다. 전문 법규·구조·자동 평면 작성은 PRD §14의 후속 범위를 유지한다.

정상 작업의 입력→동작→결과를 먼저 구현하고, 이 문서 §1~10의 보호 규칙을 같은 흐름에 적용한다. 상태 배지·로그·저장소가 있어도 실제 설계 결과가 없으면 해당 기능은 완료가 아니다. 반대로 사용자 입력·원본을 보호하지 못하는 시연도 완료가 아니다.

## 1. 참조 규칙

객체의 분할·합침·삭제·재생성 뒤 동일성이나 부분 참조를 확인할 수 없다면, ‘연결 끊김’ 또는 ‘이전 버전 참조’로 표시한다.

근거: PRD §6.2, FR-05, AC-21
문서 재열기·연결 교체는 새 연결 인스턴스다. 경로가 같다는 이유로 이전 쓰기를 새 연결에 보내지 않는다.

## 2. 상태 축 정의

실행 상태, 지시 반영 상태, 후보 유효성, 원본 적용 결과, 파일 저장, 웹 공유 반영, 검증 증거는 서로 독립된 축이며 동시에 참일 수 있다(예: 지시 접수·원본 적용 확인·파일 미저장). 이 문서는 이 축들을 하나의 상태 열거형으로 합치지 않는다. 이 절은 축의 독립성만 정하며 일곱 개의 공개 enum이나 별도 카드·서비스 구현을 요구하지 않는다(필드·전송 형식은 PLAN).

근거: PRD §9.3·§1.3·§11.3, FR-11, FR-12, FR-19, AC-08, AC-18, AC-35
실행은 대기→진행→성공/실패/결과 불명확으로 전이한다. 중단 요청과 실제 중단 확인을 구분한다. 후보는 생성 중/검토 가능/재비교 필요/폐기로, 적용은 미요청/대기/진행/확인/실패/불명확으로 구분한다. 파일 저장과 공유는 각각 마지막 확인 기준 및 현재 변경 유무를 유지한다. 통과 증거가 없는 검증은 미시험이다.

## 3. 늦은 결과·직접 수정 처리

진행 중 연산을 안전하게 멈출 수 없는 경우 그 연산의 종료까지 기다려야 함을 표시하고, 종료 결과가 새 조건을 위반하면 활성 후보나 원본에 자동 채택하지 않는다.

무관한 변경은 영향 확인 후 유지하고, 관련 변경은 재비교한다. 안전하게 재사용할 수 없는 결과는 과거 결과로 남기되 현재 유효한 결과와 구분한다.

근거: PRD §4.3(늦은 결과 보호 정본)·§9.3·§9.4, FR-11, AC-09, AC-10, AC-11
조건 버전이 달라진 결과는 기록하되 관련성 검사를 거치기 전 활성 후보에 합치지 않는다. 입력·보존 대상과 무관함을 확인하면 유지하고, 관련성이 있으면 재비교한다. 확인 불가는 보류다. 세부 실행은 SPEC-02가 소유한다.

## 4. 불명확 적용 결과 처리

캡처나 보고서 생성 실패로 확인된 변경을 다시 실행하지 않는다. 적용 결과가 불명확하면 영향받는 대상의 후속 쓰기를 보류하고 상태를 확인하되 다른 비파괴 작업은 유지한다.

근거: PRD §11.3, FR-16, AC-17, AC-18
미결: 없음.

## 5. 확장 선언 항목

근거: FR-13·18. 확장 선언과 실행 계약은 [SPEC-05 §1](SPEC-05-extensions-install.md)로 옮겼다. 기존 절 번호는 유지한다.

## 6. 공통 실행 경계 — SPEC-00.6

근거: FR-01·02·11·16·18. 작업과 실행은 복수 문서를 포함할 수 있지만 개별 호스트 명령의 대상은 한 연결·문서로 고정한다. 같은 문서의 쓰기는 직렬화하고 다른 문서의 독립 작업은 병렬로 진행할 수 있다.

접수한 변경 요청과 확인된 결과를 재시작 뒤에도 식별할 수 있어야 한다. 결과를 확인할 수 없는 요청은 불명확으로 구분하고 자동으로 같은 변경을 반복하지 않는다. 같은 요청을 다시 제출해도 중복 변경을 만들지 않는다. 외부 의견·AI 출력·확장 입력은 권한을 부여하지 못한다. 명령 저장/전달 순서와 멱등 식별의 물리 계약은 PLAN §4.3이 소유한다.

## 7. 저장과 버전 — SPEC-00.7

근거: FR-01·07·16. 입력·조건은 AI와 독립된 로컬 저장 대상이다. 저장 완료 응답은 실제 저장 성공 뒤에 반환한다. 수정은 기대 버전을 확인하고 오래된 화면의 덮어쓰기를 거절한다. 호스트 파일 저장, 로컬 기록 저장, 웹 게시 확인은 서로 대신하지 않는다.

## 8. 소속과 생명주기 — SPEC-00.8

근거: FR-01·02·09·10·12·16. 아래는 논리 관계이며 DB 테이블 수를 강제하지 않는다.

| 개념 | 소속·관계 | 변경·종료 규칙 |
|---|---|---|
| 작업 범위(WorkScope) | 프로젝트 하나; 목표·필수조건·대상·참고 입력 | 조건 수정은 새 버전. 과거 실행의 기준은 유지 |
| 작업 단위(Task) | 작업 범위 하나; 검토할 목적과 기대 결과 | 선행 작업과 영향 문서를 명시. 호출마다 카드를 새로 만들지 않음 |
| 실행(Run) | 작업 단위 하나; 고정된 조건·자료·문서별 기준 | 재시도·재개는 이전 실행에 연결한 새 시도. 완료 기록을 덮어쓰지 않음 |
| 후보 | 실행과 생성 문서에 연결; 복수 객체 묶음 가능 | 버전별 생성·사람 수정·채택·폐기 이력 유지 |
| 입력 | 프로젝트 소유; 여러 작업이 특정 버전을 참조 가능 | 편집이 과거 요청을 소급 수정하지 않음. 삭제해도 이미 사용한 버전의 근거는 유지 |
| 검토본·게시본 | 선택한 입력·결과·문서별 기준 묶음 | 생성 이후 불변. 현재 자료와 별도로 보존·접근 범위 적용 |

프로젝트 전환은 실행 취소가 아니다. 다른 프로젝트의 실행은 소속 이름과 함께 확인할 수 있으나 현재 입력·권한에 합쳐지지 않는다. 다른 프로젝트 자료를 연결할 때는 원 출처와 선택한 버전·허용 범위를 유지하며 실행 권한은 가져오지 않는다.

## 9. 행동별 권한 — SPEC-00.9

근거: FR-07·08·12·18·19. 허용 여부는 요청마다 제어 경계에서 검사한다.

| 행동 | 로컬 작업자 | 웹 참여자 | AI·확장 |
|---|---|---|---|
| 입력 저장·의견 제출 | 자신의 프로젝트 입력 저장 | 허용 게시본에 의견 제출 | 실행 결과만 반환; 사용자 의견으로 위장하지 않음 |
| 호스트 수동 Sync | 연결·범위 확인 후 허용 | 불가 | 위임된 조회만; 웹 권한으로 요청 불가 |
| 후보 생성·조건 개입 | 위임 범위 내 실행·수정 | 불가 | 허용 명령 제안; 조건·권한 변경은 불가 |
| 원본 적용 | 특정 후보·영향 범위에 대한 지시 | 불가 | 사용자 지시를 새로 만들거나 확대 불가 |
| AI 전송·웹 게시·파일 내보내기 | 각 목적별 범위 선택 | 허용 게시 자료만 접근 | 허용된 자료만 결과에 사용 |

전송·게시·적용 권한은 서로 대체하지 않는다. UI에서 숨긴 행동을 직접 API로 요청해도 같은 거절을 받는다. 저장·열람 실패는 다른 대상의 허용 행동을 일괄 차단하지 않는다.

### 9.1 복합 상태에서 행동 허용 여부

아래 조건은 AND로 검사한다. 권한 거절 → 대상 동일성/쓰기 결과 불명확 → 입력·조건 유효성 → 행동별 진행 상태 순서로 제한 사유를 표시한다. 한 조건이라도 실패하면 해당 행동만 비활성화하고 이유를 제공한다. 버튼뿐 아니라 명령 경계에도 같은 규칙을 적용한다. 읽기·초안 편집은 쓰기 차단과 독립적이다.

| 행동 | 활성 조건 | 비활성 또는 후속 행동 |
|---|---|---|
| 입력 저장 | 로컬 작업자, 프로젝트 확인, 저장 요청 진행 중 아님 | AI 미연결·미완성 평면/역할도 초안 저장 가능; 충돌은 비교 후 새 저장 |
| Sync | 로컬 작업자, 해당 문서 연결, 같은 취득 진행 중 아님 | 연결 끊김/취득 중 표시; 마지막 성공 자료는 열람 가능 |
| 새 작업 요청 | 로컬 권한, 전송 범위 확정, 입력 버전 저장, 대상·단위·필수 값·선 역할 유효, 공급자 사용 가능 | 같은 요청 중복 제출 금지; 불명확 쓰기 대상은 읽기 요청만 가능 |
| 추가 지시 | 소유 작업 확인, 저장 가능, 비어 있지 않은 지시 | 진행/중단 대기에도 접수 가능; 접수와 실제 반영을 구분 |
| 중단 | 실행 대기/진행, 중단 요청 없음 | 요청 뒤 중복 비활성; 종료 대기 또는 정지 확인 표시 |
| 재개 | 정지/실패, 진행 명령 없음, 필수 입력·전송·공급자 유효 | 불명확 명령부터 조회; 확인 전 같은 쓰기 재전송 금지 |
| 후보 비교 | 조회 가능한 후보 또는 과거 결과 있음 | 이전 조건/재비교 필요도 열람 가능 |
| 이 변경 적용 | 로컬 권한, 특정 후보 버전 지시, 검토 가능, 최신 조건·대상·보존 지문 확인, 대상 쓰기 없음 | 조건 편집·참조 끊김·재비교·진행/불명확 적용은 차단; 적용 확인 후 같은 후보 재적용 차단 |
| 후보 폐기 | 소유권 확인, 대상 쓰기 없음, 적용 전 후보 | 직접 수정이면 변경 범위를 확인한 새 지시 필요; 소유권 불명/적용 결과 불명확이면 차단 |
| 결과 다시 확인 | 읽기 권한, 대상 연결, 조회 진행 중 아님 | 확인을 누르는 것만으로 성공 처리하지 않음 |
| 게시·내보내기 | 해당 권한, 선택 기준·공개/출력 범위 확정, 같은 처리 없음 | 이전 기준 자료는 시점을 표시; 미확인 최신 결과를 포함하지 않음 |
| 웹 의견 제출 | 게시본 의견 권한, 유효 입력, 제출 진행 중 아님 | 호스트 실행·적용·재개 권한 없음 |

예: 실행 성공이어도 후보가 재비교 필요이면 적용 불가다. 적용 확인·파일 미저장은 재적용 사유가 아니다. A 문서 적용 불명확이어도 B 문서의 독립 작업과 A의 입력 저장·열람은 유지한다. 검수 화면의 합성 상태는 실제 연결 권한을 만들지 않는다.

## 10. 공통 상태 전이와 관찰 근거 — SPEC-00.10

근거: FR-10·11·12·16. 아래 명칭은 논리 상태이며 물리 값은 PLAN §4에서 매핑한다.

| 축 | 허용 전이 | 전이 근거·제한 |
|---|---|---|
| 실행 | 대기 → 진행 → 성공/실패/불명확; 대기 → 취소 | 성공은 해당 실행 결과 확인. 원본 적용·파일 저장 성공을 뜻하지 않음 |
| 중단 | 미요청 → 요청됨 → 종료 대기 → 정지 확인/종료 미확인 | 이미 끝난 실행은 종료 상태 유지. 요청만으로 정지 확인 금지 |
| 지시 | 접수 → 정리 중 → 반영됨/일부 반영/결정 필요 | 접수는 영속 기록, 반영은 후속 실행 기준 채택. 범위별 결과를 기록 |
| 후보 | 생성 중 → 검토 가능 → 재비교 필요/폐기 | 검토 가능은 실제 결과 조회 확인. 재비교 통과 뒤 새 기준에 연결 가능 |
| 적용 | 미요청 → 대기 → 진행 → 확인/실패/불명확 | 실패는 미반영 증거가 있을 때. 불명확 해소는 SPEC-02.7 |
| 저장·게시 | 미확인/변경 있음 → 처리 중 → 확인/실패/불명확 | 확인에는 대상 버전·시각 필요. 후속 변경은 기존 확인 기록과 별도로 표시 |

상태 통지는 중복·역순 도착할 수 있다. 이미 확인된 최신 버전을 오래된 통지로 되돌리지 않는다. 통지 단절 후에는 저장된 기준을 다시 읽고, 연결이 돌아왔다는 이유로 이전 실행을 성공으로 바꾸지 않는다.
