# 실행·개입·실제 후보·원본 적용


## 설계 요청을 실제 작업으로 수행한다 — SPEC-02.11

근거: PRD §7·§8.3·§9.5, FR-04·08·10·15·18. **AI는 문장으로 조언만 하는 것이 아니라, 지정한 모델·도면을 읽고 사용자의 의도를 실제 네이티브 후보로 만든다.** 로컬 작업자가 SPEC-01의 입력으로 작업을 맡기며, 현재 지원 능력과 전송 범위 안에서 실행한다.

정상 흐름은 다음과 같다.

1. 요청의 목표, 실제 변경 대상, 유지 조건, 스케치·치수, 참고 자료를 읽는다. 입력과 기존 확정 조건으로 결정할 수 없는 중요한 내용만 질문한다. 대상이 명확한 작은 이동/수정에 불필요한 계획 승인 단계를 추가하지 않는다.
2. 작업을 사람이 검토할 결과 단위로 구성한다. 예를 들어 ‘경계 수정 후보’와 ‘변경 면적 확인’은 목적과 선후관계를 보여 주되, 점 하나를 바꾸는 내부 연산마다 별도 사용자 작업으로 나누지 않는다.
3. 필요한 객체·속성·좌표·관계를 조회하고 현재 지원되는 생성/수정 동작을 선택한다. 근거 없는 수치를 AI가 만들어 기하 입력으로 사용하지 않는다.
4. 호스트에서 실제 후보를 만들고 결과를 다시 읽어 유효성·치수·보존 조건을 검사한다. 허용 범위 안에서 후보를 보정하거나 필요한 자료를 추가 조회한다. 안전한 내부 단계마다 사용자 승인을 반복하지 않는다.
5. 일관된 결과가 준비되면 자체 뷰의 후보, 원본과의 차이, 관련 측정값, 사용한 가정과 미검토 범위를 함께 보여 준다. 작업 중에도 마지막 실제 결과를 탐색하고 추가 지시할 수 있다.
6. 사용자는 후보 조정·중단·적용으로 이어간다. 요청이 설명/조회라면 근거가 연결된 답변이나 표로 끝나고, 생성/수정 요청이라면 텍스트 답변만으로 완료하지 않는다.

**진행 단계의 표시(PRD §9.1·9.3, FR-10·11):** 호스트 작업은 ① 기준 준비(문서 취득·작업 사본) ② 요청 이해(AI에 전달) ③ 모델 조회 ④ 생성·수정 실행 ⑤ 저장·재열기 검증 ⑥ 결과로 나누어 보인다. 호스트 없는 질문·검토는 ② 요청 전달과 ⑥ 답변만, 확장은 실행과 결과만 갖는다. 단계 상태는 실제로 기록된 사건(취득, 조회, 코드 실행, 검증 성공·실패, 요청 종료)으로만 정한다. 사건이 없는 단계를 완료로 표시하지 않고, 끝난 작업에서 일어나지 않은 단계는 '생략'이다. 실행 실패는 AI의 수정 재시도로 이어질 수 있으므로 실패 사건만으로 작업 실패를 뜻하지 않는다. 진행 중에는 추가 지시(§8)와 중단(쓰기 검증 중에는 종료 확인 뒤)을, 끝난 뒤에는 후보 보기·이어가기·원본 적용·입력 복원을 해당 단계와 결과 가까이에서 제공한다. 작업 도중의 중간 결과는 검증된 변경 수로 보이고, 후보 형상은 일관된 결과가 준비된 뒤 보인다. 단계마다 걸린 시간을 보인다(예: 기준 준비 (5.2s)). 단계의 시작은 그 단계의 첫 기록(기준 준비는 요청 접수)이고 끝은 다음 단계의 시작이며, 진행 중인 단계는 지금까지의 시간이 계속 올라간다. 끝난 작업의 마지막 단계는 마지막 기록에서 끝난다.

계획, 실행 중인 동작, 실제로 준비된 결과를 구분한다. CLI가 문장을 반환하는 것은 연결 시험일 뿐 이 기능의 완료가 아니다. 기하 작업 없이 “수정했습니다”라고 말하거나 화면 전용 형상을 그리는 것으로 네이티브 후보를 대신하지 않는다. 예외·상한·재개 규칙은 §1·4·6, 직접 수정 보호는 §8을 따른다.

## 어떤 생성·수정을 요청할 수 있는가 — SPEC-02.12

근거: PRD §8.2~5·§12.1·§14.1, FR-04·05·06·08·10·12. 다음은 **첫 구현에 사용할 기능 지원 검토안**이다. OQ-03·10의 구체안으로 제시하며 최종 지원 확정이나 실증 완료를 뜻하지 않는다. 호스트별 유형·보존 속성·검수는 `hosts/rhino.md`와 `hosts/zwcad.md`가 소유한다. 이 예제를 제품 전체의 기능 상한으로 삼지 않는다.

| 요청 종류 | 입력 예 | 프로그램이 수행할 일 | 눈에 보이는 결과 |
|---|---|---|---|
| 새 경계 생성 | 평면의 닫힌 스케치와 치수로 경계를 만들어 줘 | 점열/치수에서 지원 네이티브 평면 폴리라인 후보 생성 | 원본 선·해석 경계·실제 후보와 길이/면적 |
| 기존 경계 수정 | 선택 경계의 지정 변을 선까지 늘리고 반대편은 유지 | 해당 정점/변을 수정한 복사 후보, 닫힘·보존 대상 검사 | 원본과 수정 경계, 변경 치수와 면적 차이 |
| 배치 조정 | 선택 객체를 이 방향으로 지정 거리만큼 옮겨 줘 | 지원 객체에 문서 좌표 기준 이동 적용 후보 생성 | 이동 전후 위치, 거리·방향, 유지 객체 |
| 반복 배치 | 이 경계를 지정 간격·개수로 복사해 줘 | 명시한 개수·간격의 복사 후보 묶음 생성 | 실제 개수와 배치·원본 구분 |
| 입체 후보 생성(Rhino 검토안) | 이 닫힌 경계를 높이 h의 매스로 만들어 줘 | 평면 경계로부터 지원되는 닫힌 돌출 형상 생성 | 호스트 네이티브 입체, 높이·입력 경계·검사 결과 |
| 입체 후보 수정(Rhino 검토안) | 이 후보의 높이만 바꾸고 바닥 경계는 유지 | 지원 생성 기준을 가진 후보의 높이를 수정/재생성 | 이전/새 후보의 높이와 유지된 경계 |

여기서 경계는 문/벽/실이라는 BIM 의미를 자동으로 갖지 않는다. 닫힌 선의 면적은 기하 면적이다. 임의 솔리드의 모든 편집 이력을 복원하거나 전문 평면을 자동 설계하는 약속으로 확대하지 않는다. 입체 후보는 현재 폴리라인 실험보다 추가 검증이 필요한 별도 지원안이다.

요청은 버튼별 고정 예제와 달리 다른 객체·치수·점열에도 적용되어야 한다. 동작을 조합하는 방법은 AI가 정하되, 허용 능력을 벗어나면 어떤 부분이 지원되지 않는지 설명하고 가능한 결과를 구분한다. 지원하는 요청인데도 상시 ‘결정 필요’로 멈추는 구현은 완료가 아니다.

**기능 판단 예:** 폭을 유지한 채 선택 경계 한쪽을 늘리면 길이·면적이 그 변경에 맞게 달라지고, 유지 대상으로 지정한 다른 경계는 그대로여야 한다. 수치 기준과 시험 좌표는 PLAN §7.2에서 정한다. 생성 유형을 이름만 바꾸거나 화면에서만 흉내 낸 결과는 불합격이다.

## 후보를 보며 고치고, 원본에 반영한다 — SPEC-02.13

근거: PRD §8.3~5·§9·§11.2, FR-04·10·11·12·16. **사용자는 긴 로그 대신 실제 후보를 보며 “이 부분은 그대로, 저 부분만 변경”하는 방식으로 작업을 이어간다.**

첫 후보가 나오면 원본/후보를 구분해 탐색하고 바뀐 객체·치수·관련 수치를 확인한다. 스케치 원본과 해석도 다시 열 수 있다. “너무 넓다, 이 선까지만 줄여 줘”처럼 새로운 선이나 수치를 주면 같은 목표의 후속 실행으로 연결한다. 이전 후보는 기준과 함께 남고, 새 지시가 적용된 후보가 준비됐을 때 그 차이를 확인한다. 여러 후보 전체를 자유 병합하는 기능은 추가하지 않는다.

유지 대상을 추가하거나 하위 작업을 제외하면 해당 부분의 후속 실행을 조정한다. 사용자가 호스트에서 직접 고친 결과는 관련 기준 재조회 뒤 새 작업의 입력으로 쓸 수 있다. 무관한 문서 작업은 계속된다. 중단해도 이미 만든 후보를 열어 보거나, 확인된 결과에서 나중에 이어갈 수 있다(§4·8).

사용자가 적용할 후보를 고르면 대상 문서·버전·변경 내용을 보여 준다. **적용은 검토한 후보의 변경을 실행하는 행동이며, AI에 새 설계안을 다시 생성시키는 행동이 아니다.** 새 객체 후보의 채택과 기존 객체에 대한 수정은 호스트 지원 계약에 맞게 수행한다. 현재 조건과 충돌하면 차이를 보여 주고 재검토한다(§3·7).

적용 뒤 해당 호스트에서 객체를 선택하고 기본 도구로 이동·정점/지원 형상 편집을 이어갈 수 있어야 한다. 파일 저장은 호스트에서 수행하고 VIDE는 확인한 저장 상태를 별도로 표시한다. 저장·재열기 뒤 유형·형상·선언 속성이 유지되는지 검수한다. 원본 적용 뒤 표·캡처 생성이 실패하면 그 산출물만 다시 만든다.

**완료 기준:** 요청 → 실제 후보 → 적어도 한 번의 수정 지시 → 달라진 후보 확인 → 적용 → 호스트 재편집·저장·재열기가 하나의 작업 기록으로 이어져야 한다. AI 답변 성공이나 후보 버튼 표시만으로 완료하지 않는다(AC-05~11·17·18·24·38).

## CAD 도면과 Rhino 모델을 한 요청으로 바꾼다 — SPEC-02.14

근거: PRD §8.6·§12.2, FR-02·03·04·09·10·11·12. 로컬 작업자는 연결된 CAD 도면과 Rhino 문서를 같은 작업의 대상으로 지정한다.

**CAD 자료로 Rhino 후보 만들기:** ZWCAD에서 지원되는 닫힌 경계를 선택해 참고 입력으로 넣고 Rhino를 결과 문서로 지정한다. 사용자는 두 문서의 단위와 배치 기준을 확인하고 “이 경계로 높이 h의 매스를 만들어 줘”라고 요청한다. 프로그램은 실제 CAD 경계를 읽고 확인된 변환으로 Rhino 후보를 만든다. 후보를 선택하면 원 CAD 경계와 취득 시점, 높이 조건으로 이동할 수 있다. 돌출 지원 검토안은 H-RHINO-05에 연결한다.

**같은 변경을 양쪽에 반영하기:** 설계자가 대응하는 CAD 경계와 Rhino 후보/결과를 지정한 뒤 “이쪽 경계를 그린 선까지 늘리고 모델에도 반영해 줘”라고 요청한다. 프로그램은 도면 수정 후보와 그 수정 경계를 사용하는 모델 후보를 구성한다. CAD 변경 전 원본을 먼저 덮어쓰는 대신 확인된 후보 기하를 후속 입력으로 사용할 수 있다. 두 후보의 관계·실제 변경·호스트별 적용 결과를 한 요청에서 확인한다.

이후 원본이 직접 편집되었다면 Sync와 관련성 확인을 거쳐 필요한 쪽만 재계산한다. 연결은 지속적인 양방향 자동 동기화가 아니며, 새 연계 실행에는 사용자의 요청이 필요하다. 임의의 두 객체를 이름이나 근접성으로 자동 대응시키지 않는다.

**완료 기준:** 지정 CAD 경계가 실제 Rhino 입력이 되고, 조건 변경으로 양쪽 결과가 일관되게 바뀌며, 한쪽 실패가 다른 쪽 성공으로 가려지지 않아야 한다. 별도 문서의 독립 작업도 함께 실행해 활성 화면 전환과 무관한 대상을 유지한다(AC-25·32·33). 정확한 관계/충돌/부분 실패 규칙은 §9를 따른다.

## 1. 실행 조건 — SPEC-02.1

근거: FR-08·15·18. 작업 범위는 목표, 복수 문서 대상, 보존 조건, 허용 도구, 전송 자료와 실행 상한을 포함한다. 실행 시작 시 그 버전을 고정한다. AI는 허용 자료와 호스트 API로 필요한 조회·실행 코드를 구성한다. VIDE는 대상·기준·권한·실행 결과를 관리한다. 특정 편집 명령 목록만을 제품 기능의 상한으로 삼지 않는다. AI 출력 자체는 권한 부여나 적용 성공의 증거가 아니다.

AI가 미설정·미인증·한도 초과이면 해당 원인을 표시하고 입력은 보존한다. 공급자 변경으로 전송 범위가 확대되면 그 범위를 먼저 결정한다. 공급자 실패를 모의 성공으로 대체하지 않는다. 재개는 저장된 작업과 확인된 결과에서 새 세션으로 이어갈 수 있으며 불명확한 쓰기를 반복하지 않는다.

## 2. 후보와 보호 — SPEC-02.2

근거: FR-04·10·12. 계획 설명과 실제 네이티브 객체 후보를 구분한다. 후보는 생성 결과의 문서·객체 식별자와 기준 버전에 연결된다. 같은 문서에 만드는 후보도 기존 객체의 속성·관계·사용자 변경을 보호한다. 후보 때문에 문서가 수정 상태가 되거나 저장에 포함될 수 있음을 표시한다.

후보를 버릴 때는 해당 후보로 확인된 객체만 제거한다. 전체 문서 Undo나 옛 파일 복원으로 사용자 편집을 되돌리지 않는다. 후보가 직접 수정됐거나 소유권을 확인할 수 없으면 자동 제거·교체를 보류한다. 지원 객체와 변환의 실제 한계는 호스트 지원표가 소유한다.

## 3. 적용과 실패 — SPEC-02.3

근거: FR-11·12·16·18. 적용은 특정 후보 버전과 원본 영향 범위에 대한 사용자 지시를 필요로 한다. 이미 명시한 적용 지시는 중복 승인창을 요구하지 않는다. 실행 직전 원본·후보·보존 대상의 관련 변경과 연결 동일성을 재검사한다. 충돌이면 재비교하고 새 조건에 어긋난 후보를 자동 적용하지 않는다.

복수 문서의 적용은 개별 결과를 남긴다. 한 문서의 실패가 다른 문서의 성공을 취소하거나 성공한 쓰기의 재실행으로 이어지지 않는다. 응답 유실은 실패로 단정하지 않고 불명확으로 남겨 해당 대상의 후속 쓰기를 보류한다. 원본 적용 확인과 파일 저장 확인은 별개다.

## 4. 개입 — SPEC-02.4

근거: FR-11·15. 조건 변경은 새 조건 버전을 만들고 미전송 명령을 무효화한다. 안전한 중단을 지원하지 않는 진행 중 호스트 연산은 종료 대기를 표시한다. 프로세스 종료 요청만으로 호스트 연산 중단을 선언하지 않는다. 늦은 결과는 이력에 남기고 관련성을 검사한 뒤 현재 후보로 사용할 수 있는지 결정한다. 검사 불가 결과는 보류한다.

## 5. 수용 예

같은 적용 요청의 재전송은 객체를 두 번 만들지 않는다. 적용 직후 응답 유실·프로그램 재시작은 자동 재시도를 발생시키지 않는다. A 실행 중 B 조건을 채택하면 A의 늦은 결과가 B를 덮지 않는다. Rhino 성공·ZWCAD 실패는 둘을 구분해 보여 준다.

SDK 객체 조회는 한 번에 제한된 목록을 반환하고 전체 수·다음 위치·기준 revision을 함께 제공한다. 다음 페이지는 같은 revision에서만 읽으며 편집으로 기준이 바뀌면 다시 조회한다. 명시한 객체 ID로 범위를 좁힐 수 있고 이 필터는 다른 문서 접근이나 쓰기 권한을 주지 않는다. 응답 한도를 넘는 객체는 누락 성공으로 처리하지 않고 크기 제한을 알린다.

SDK 실행 성공 응답의 객체/변경 목록도 요약일 수 있다. 전체 변경 건수와 생략 여부를 함께 알리며 저장 후보·영수증·원본 보호 비교는 전체 자료로 수행한다. 응답 요약이 크기 제한에 걸려도 이미 확인된 저장 성공을 실패로 바꾸지 않고 세부 조회가 필요함을 알린다.


## 6. 작업 구성·문맥·반복 상한 — SPEC-02.6

근거: FR-08·10·15·18. 시작 전 작업 목적, 변경/보존 대상, 예상 결과, 의존 작업, 전송 자료와 제한을 확인할 수 있다. 상위 필수조건은 하위 작업이 삭제하거나 참고로 낮출 수 없다. 큰 목표를 여러 작업으로 나눠도 같은 조건 버전을 사용한다.

AI 문맥은 확정 조건, 명시된 대상과 기준, 관련 입력 원본, 확인된 완료 결과, 미결/불명확 작업을 우선한다. 요약만으로 원본 근거를 지우지 않는다. 긴 문맥은 필요한 항목을 재조회하고 누락된 필수조건을 복구한 뒤 실행한다. SDK 실행의 초기 모델 문맥은 핀으로 지정한 객체를 우선한 한정 요약이며 전체 목록으로 간주하지 않는다. 전체·포함·생략 수를 명시하고 요약 밖 객체의 형상이나 수량을 추정하지 않는다. 필요한 최신 정보는 허용된 조회로 확인한다. 명시적 입력·핀의 역할·보호 범위는 요약 때문에 삭제하거나 축소하지 않는다. AI 추정은 출처를 유지하며 사용자의 확정 결정으로 저장하지 않는다.

실행 중 조회 완료 수, 호스트 실행 시도 수, 저장·재읽기 검증을 마친 단계 수를 구분해 보여 준다. 계획된 단계 수를 알 수 없으므로 이를 전체 완료율로 표시하지 않는다. 저장된 단계는 작업 사본의 결과이며 원본 적용 완료를 뜻하지 않는다.

실행에는 호출 횟수·경과 시간·호스트 명령 수의 유한 상한을 둔다. 시작할 때 적용 상한을 볼 수 있으며 사용자가 조정할 수 있다. 연속 실패나 같은 기준·같은 제안의 반복으로 진전이 없으면 자동 반복을 멈추고 마지막 실제 후보와 남은 문제를 제시한다. 상한 연장은 로컬 작업자의 새 지시로 기록한다. 사용량 미제공은 0으로 기록하지 않는다. 수치 기본값은 PLAN의 시험 설정이며 OQ-06의 제품 성능 보증이 아니다.

조건 충돌·검토 미완료 후보는 탐색 결과로 보존할 수 있다. 대상·권한·단위·보존 조건을 위반하는 원본 쓰기는 차단하고, 전문 적합성 미검토를 기술적 실행 실패와 혼동하지 않는다.

## 7. 적용과 불명확 결과의 해소 — SPEC-02.7

근거: FR-04·11·12·16·18. 적용 지시는 후보 버전·대상·변경 집합에 묶인다. 후보 또는 영향 범위가 바뀌면 기존 지시로 다른 변경을 수행하지 않는다. 원본 생성/수정의 결과를 객체별로 기록한다. 같은 문서의 생성 후보를 원본 결과로 채택할 때 새 복사본을 중복 생성하지 않는다. 기존 객체 수정 후보는 지원된 수정 방식과 보존 속성·관계를 명시하고, 관련성 확인 불가이면 보류한다(OQ-03·10).

| 상황 | 해소에 필요한 증거 | 허용되는 다음 행동 |
|---|---|---|
| 확인된 적용 뒤 캡처 실패 | 호스트 적용 결과와 변경 객체 | 캡처/요약만 재생성 |
| 전달 전 취소 확인 | 호스트 미전달 기록 | 새 조건으로 새 명령 생성 |
| 호스트가 미반영 확정 | 명령 식별과 트랜잭션/결과 조회의 미반영 증거 | 확인 기록 후 새 명령으로 재시도 가능 |
| 변경 성공 응답 유실 | 호스트 명령 기록과 대상·객체·변경 지문 일치 | 기존 명령을 확인으로 종결, 쓰기 재실행 없음 |
| 일부 변경 또는 확인 불가 | 객체별 확인/불명과 관측 증거 | 해당 문서 쓰기 보류; 읽기·수동 확인·다른 문서 작업 유지 |

사용자가 ‘확인’ 버튼을 눌렀다는 사실만으로 미반영 증거가 되지 않는다. 증거 없는 강제 성공/재시도 경로는 제공하지 않는다. 호스트 수동 복구가 필요하면 기존 기록을 유지한 채 복구 결과와 새 기준을 확인한다. 자동 전체 문서 Undo는 사용하지 않는다.

저장된 사본을 복구했다는 사실과 원 요청의 전체 목표 달성을 구분한다. AI 응답이 유실된 복구 후보는 목표 완료 미확인으로 표시한다. 단일 대상 요청은 사용자가 복구 후보를 새 기준으로 삼아 원 조건·첨부를 유지한 후속 초안을 만들 수 있다. 기존 대상 핀의 동일 객체 대응을 확인하지 못하면 자동 재연결하지 않는다. 후속 초안은 자동 전송하지 않고 성공분의 재실행 대신 현재 결과 확인과 남은 목표 수행을 요청한다. 복수 대상 부분 결과는 각 대상의 확인 결과를 유지하며 일괄 재실행하지 않는다.

## 8. 직접 수정과 개입의 처리 — SPEC-02.8

근거: FR-11·12. 관련 변경의 범위는 읽은 입력 객체·관계, 수정 대상, 보존 대상으로 판정한다. 후보 자체 생성으로 문서가 dirty가 된 것만으로 전체 후보를 무효화하지 않는다. 관련 지문이 같다고 확인되면 무관한 변경은 허용하고, 달라졌거나 확인 불가이면 관련 작업만 재비교한다.

새 지시는 먼저 저장하고 접수를 알린다. 연계 작업의 추가 지시 버튼은 그 상위 작업을 대상으로 한다. 입력창에 별도 대상이 없으면 해당 작업의 두 기준과 확인된 좌표계를 이어받으며, 명시적으로 다른 기준·호스트·권한을 선택한 입력을 조용히 바꾸지 않고 거절한다. 현재 실행에 대한 추가 지시는 대상 작업을 명시한다. 원 조건·핀·스케치·자료를 유지하고 새 조건을 뒤에 연결한 별도 요청으로 먼저 저장한다. 같은 대상·권한을 유지하며, 보존 역할의 암묵 변경이나 대상 교체는 접수하지 않는다. 이전 요청에 중단을 요청하고 실제 종료를 기다린 뒤 원 기준 사본에서 새 조건을 실행한다. 이전 요청이 만든 결과는 이력에 남으며 자동 원본 적용하지 않는다. 결과 불명확 또는 연계 작업의 부분 결과 때문에 안전한 재개를 판정할 수 없으면 새 조건을 보류하고 이유를 표시한다. 재시작은 접수된 새 조건을 보존하지만 자동 실행하지 않는다. 새 조건의 접수·중단 대기와 실행 시작을 분리해 표시한다. 조정 대상과 이미 완료된 범위를 나눠 후속 조건에 채택한 뒤 반영됨을 표시한다. 일부만 채택하면 문서/작업별 이유를 표시한다. 이전 조건의 미전송 명령은 취소하고, 이미 진행 중인 연산은 중단 가능 여부를 확인한다. 중단 불가 연산 뒤 결과는 과거 조건의 결과로 보존한다. 사람 수정 후보를 폐기하려면 달라진 내용과 삭제 대상을 다시 확인한 명시적 지시가 필요하다.

## 9. 연계·병렬·부분 결과 — SPEC-02.9

연계 후보 작업에서 한 대상은 유지하고 다른 대상만 바꿀 수 있다. 유지 대상은 그 요청에서 실제 조회했고 쓰기를 시도하지 않았으며 기존 저장 기준을 확인한 경우에만 변경 없는 후보로 연결한다. 조회하지 않은 대상을 확인한 것으로 표시하거나 불명확 쓰기를 변경 없음으로 바꾸지 않는다. 검토 전용 요청에는 후보 생성 의미를 추가하지 않는다.

복수 대상 요청은 종료 후 두 하위 결과가 모두 저장 검증된 후보이면 원 조건·권한·자료를 유지한 후속 초안을 만들 수 있다. 부모의 실패 표기보다 각 하위 결과의 현재 확인 상태를 사용한다. 불명확·실행 중·후보 없는 대상이 있으면 원 기준으로 대신하지 않고 먼저 결과 확인을 요구한다. 원 대상 핀은 같은 객체임이 확인될 때만 새 후보에 연결한다. 후속 초안은 자동 전송하지 않으며 기존 성공 작업의 반복 대신 현재 후보 확인과 남은 목표를 요청한다. 연계 실행 중 추가 지시가 부분 결과 때문에 보류됐으면, 이전 요청의 두 후보가 확인된 뒤 그 추가 지시까지 보존해 명시적으로 이어갈 수 있다. 대상·좌표·권한이 원 요청과 달라진 보류 입력은 자동 연결하지 않는다.

근거: FR-02·04·09·10·11·16. CAD 정보를 Rhino에 사용할 때 원 문서·객체·기준과 좌표 변환·단위를 결과에 연결한다. 문서 간 대응은 일대일로 가정하지 않으며 사용자가 지정하거나 확인한 대응과 추정을 구분한다. 좌표/단위를 확정하지 못한 입력은 참고로 보존하되 자동 기하 쓰기에 사용하지 않는다.

선행 결과를 읽는 후속 작업은 그 결과의 확인을 기다린다. 선행 실패/불명확이면 의존 작업은 보류하고 독립 작업은 계속한다. 여러 문서의 결과 요약은 모두 확인, 부분 확인, 불명확 포함을 구분하고 전체 원자적 적용·복구를 약속하지 않는다. 재개 시 성공분을 다시 적용하지 않는다.

**동시 접수.** 근거: FR-11·15·25, AC-46, 2026-09-29 사용자 결정(목적별 여러 대화의 동시 진행, [ADR-021](../decisions/ADR-021-conversation-sessions.md)). 여러 대화(SPEC-02.19)가 동시에 요청을 보내도 겹친다는 이유로 거절하지 않고, 겹치는 쓰기만 차례를 기다리게 한다. 경합은 프로젝트 전체가 아니라 요청이 실제로 쓰는 호스트 문서와 후보 계보로 판정한다.

1. **호스트를 쓰지 않는 요청:** 요청은 접수 때 호스트 사용을 '없음·읽기·쓰기' 중 하나로 정한다. 자료 질문, 앱 조작(Sync 받기 제외), 조회만 하는 jig 대화, jig 계산처럼 '없음'으로 접수한 요청은 호스트 작업과 경합하지 않으며, 그 요청의 AI 턴에는 호스트 도구를 주지 않는다.
2. **읽기:** Sync 받기와 jig 입력 읽기는 읽는 문서를 대상으로 삼고 같은 문서의 원본 반영하고만 겹친다(반영이 끝난 뒤 읽는다). 읽기는 자원 상한에 세지 않는다.
3. **같은 문서 쓰기:** AI 편집, jig의 Rhino에 만들기, 원본 반영이 같은 문서(그 문서의 작업 사본 포함)를 쓰면 접수 순서대로 문서별 대기열에 넣고 한 번에 하나만 실행한다. 대기 중인 요청에는 무엇을 기다리는지와 순서(예: 'CAD 편집 대화가 이 도면을 쓰는 중 · 대기 1')를 보이고, 사용자는 대기 중인 요청을 취소할 수 있다. 같은 원본을 다시 취득한 기준도 같은 문서로 본다. 대상 문서를 확인할 수 없는 호스트 요청은 같은 호스트의 모든 문서 쓰기와 겹치는 것으로 보고 그 뒤에 선다. 새 독립 후보임을 명시한 요청은 별도 작업으로 구분한다.
4. **자원 상한:** 한 문서의 쓰기는 한 번에 하나, 프로젝트 전체의 AI 턴은 동시에 N개(기본 3, 설정 2~4)까지 실행한다. 넘는 요청은 거절하지 않고 프로젝트 대기열에 넣어 'AI 작업 3개 진행 중 · 대기 1번째'처럼 이유와 순서를 보인다. AI를 부르지 않는 처리(화면·설정값·jig 계산)는 AI 턴 상한에 세지 않는다.
5. **불명확과 낡은 기준:** 결과가 불명확하면 해당 문서의 대기열을 멈추고 이유를 보이며(§7), 대상을 식별할 수 없으면 해당 호스트의 쓰기를 보수적으로 보류한다. 다른 대화의 원본 반영으로 기준이 낡은 후보는 적용하지 않고(§3), 그 대화에 새 기준으로 같은 의도를 다시 적용하는 후속 턴을 제안한다. 재시작하면 대기 중이던 요청은 보존하되 자동으로 실행하지 않는다(§8).

## 범용 실행과 복수 실행본의 대상 — SPEC-02.15

실행 방향의 결정 근거는 [ADR-014](../decisions/ADR-014-sdk-agent-execution.md), 구현·비교 시험은 [PLAN-02](../plans/PLAN-02-agent-host-versioning.md)를 따른다.

근거: FR-02·04·08·11·16·18. AI는 SDK 기반 코드와 재사용 함수를 조합하고 실제 오류·결과를 읽어 후속 동작을 정한다. 사용자에게 별도 MCP 설치·수동 설정을 요구하지 않는 제품 연결을 목표로 한다. AI는 조회에서 받은 대상 참조와 코드를 전달하고, 연결 식별·권한·기준·실제 변경 기록은 VIDE가 관리한다. 정밀한 변경 집합이나 권장 코드 스타일을 AI가 사전 선언해야만 실행되는 조건을 추가하지 않는다. SDK 설명은 필요한 부분만 조회하며 전체 문서 반복 전송이나 매 작업 웹 검색을 요구하지 않는다. 호스트/AI 설치·로그인은 별도로 필요하다. 코드 실행은 §1~9의 전송·후보·원본 적용·중단 계약을 우회하지 않는다. 조회 권한은 임의 코드 실행 권한이 아니며, 코드 본문으로 다른 문서 접근을 완전히 차단할 수 있다고 주장하지 않는다.

PRD §14.2의 임의 비신뢰 코드 실행 제외는 임의 업로드 코드/공개 플러그인을 실행하는 범용 서비스를 제공하지 않는다는 범위다. 로컬 작업자가 허용한 설계 과업을 수행하기 위한 AI 생성 SDK 코드는 이 절의 실행 경로이며, 생성 주체가 AI라는 이유로 신뢰된 코드나 OS 샌드박스 안의 코드가 되지는 않는다. 기존 대상·자료 전송·후보 보호·적용 권한을 그대로 적용한다.

동일 종류 호스트의 복수 실행본과 각 열린 문서를 구분한다. 파일명·활성 창이 같아도 대상을 대체하지 않는다. 문서 닫힘·재시작·Save As·복사로 동일성을 확인할 수 없으면 해당 쓰기를 보류하고 재연결한다. 읽기만으로 사용자 파일에 추적 속성을 기록하지 않는다.

Rhino A의 객체를 Rhino B로 복사하면 원본 버전을 읽어 확인한 단위·좌표로 새 객체를 생성하고 원본과 새 객체의 관계를 남긴다. 지원하지 않는 속성·참조 관계는 누락 범위를 표시하고 결과를 완전 복사로 선언하지 않는다. 재접속 때문에 같은 객체를 두 번 만들지 않으며 불명확 쓰기는 §7을 따른다. 다른 문서로 복사했다는 이유로 후속 자동 양방향 동기화가 시작되지는 않는다. 수용 사례는 동명/미저장 문서·창 전환·두 실행본·응답 유실을 포함한다.


## 요청의 경로와 대화의 문맥 — SPEC-02.17

근거: PRD §8.2·§9.5, FR-04·08·18·24·25, AC-48. 2026-09-29 사용자 지적("텍스트만 남기고 숨겨 같은 요청이 VIDE 화면에 먹히지 않는다, VIDE에 하는 명령인지 CAD에 하는 명령인지 애매하다")과 결정("어떤 최근 요청을 보낼건지는 맥락 상 비슷한거를 보내는거니까 jev가 처리", 모델 자동 선택은 "자동 (Jev)" 규칙 하나로 통일), 같은 날의 대화 세션 결정([ADR-021](../decisions/ADR-021-conversation-sessions.md)). Jev 판정으로 실행하는 범위와 Jev에 보내는 항목(아래 2·4)은 에이전트 권고를 사용자가 이의 없이 받은 기본값이다.

1. **경로:** 요청을 보낼 때 다음 일곱 경로 중 하나로 정한다.

   | 경로 | 뜻 | 예 | AI |
   |---|---|---|---|
   | 화면(`view`) | VIDE 화면만 바꾼다(숨기기·끄기·격리·다시 보이기·선택·확대) | "기둥만 남겨 줘" | 없음 |
   | 설정값(`param`) | 열린 jig의 설정값을 바꾸고 다시 계산한다 | "경간 상한 11 m로" | 없음 |
   | 앱(`app`) | 로그인·계정·Sync·연결 프로그램·내보내기 같은 VIDE 조작 한 가지 | "codex 로그인해줘" | 없음 |
   | jig 열기(`jig`) | 맞는 jig를 제안한다 | "구조 검토하고 싶어" | 없음 |
   | 자료 질문(`ask`) | 프로젝트 자료에 묻는다. 호스트를 쓰지 않는다 | "보 춤 900 회신 왔어?" | 있음 |
   | 파일 작업(`document`) | AI가 원본의 작업 사본을 고치거나 파일에 대한 질문·검토에 답한다 | "이 거더를 슬래브 끝선에서 1 m 안으로" | 있음 |
   | jig 만들기(`make`) | 새 jig를 만드는 대화를 연다 | "신설 E.J.마다 양쪽 기둥이 있는지 보는 도구 만들어 줘" | 있음 |

   Jev 키가 있으면 Jev가 경로·화면 동작·대상 묶음(화면에 있는 종류·레이어·현재 선택 중)·설정값·앱 동작·jig·지금 대화와 목적이 같은지를 한 번에 판정한다(2026-09-29 사용자 결정: 규칙은 칩을 너무 자주 누르게 한다). 다음 말은 판정 없이 규칙으로 정하고, 앞의 것부터 본다: 로그인·로그아웃과 공급자 이름(codex·chatgpt·gpt·claude·클로드) → 앱(로그인), Sync·싱크·동기화·다시 읽기와 파일·도면·모델 → 앱(Sync 받기), 등록된 jig의 부름말(구조 검토·구조 해석 등) → jig 열기, '도구로 만들'·'jig로 만들'·'자동화해' → jig 만들기, jig가 열려 있을 때 설정값 이름의 핵심어와 숫자 → 설정값, 파일이나 프로그램을 가리키는 말(원본·CAD에서·Rhino에서·도면에서·파일에) → 파일 작업. Jev 키가 없거나 응답이 실패·지연(3초)되거나 확신이 낮으면 나머지도 규칙으로 정한다: 화면 동작 말(숨겨·만 남기고·격리·다시 보여·선택·확대)이 있고 원본을 가리키거나 바꾸는 말(지워·삭제·색 바꿔·수정·이동·만들어·그려 등)이 없으면 화면이고, 그 밖에는 지금 대화의 AI에 보낸다(자료 질문 대화이면 자료 질문, 아니면 파일 작업). 대상은 종류 말(문자·치수·해치·블록·면·선·점), 레이어 이름, 객체 이름, "이것/선택한"이면 현재 선택이다. Jev가 대상을 짚지 못하면 규칙이 찾은 대상을 쓴다. 설정값 경로의 값·단위·방향은 Jev가 아니라 코드가 말에서 읽는다. 단위가 없으면 그 설정값의 표시 단위로 보고, 범위 밖이면 적용하지 않고 범위를 알린다. 설정값의 단위·범위·상대어('조금 더 촘촘히') 선언은 [SPEC-07.6](SPEC-07-jig-platform.md)이 소유한다. 열린 jig의 대화에서 AI에 가는 말이 할 수 있는 일은 SPEC-02.19의 3을 따른다.
2. **AI 없이 처리하는 경로:** 화면·설정값·앱·jig 열기는 AI와 모델 선택을 부르지 않는다. 화면 요청은 호스트·파일을 쓰지 않고 VIDE 뷰포트에서 바로 적용하며 작업 이력에 남기지 않는다. 결과와 "원본은 그대로"를 알리고 U로 되돌린다. 대상을 찾지 못하면 적용하지 않고 그 사실을 알린다. **화면을 빼면 Jev 판정만으로 사용자가 누르지 않고 실행하는 것은 되돌리기가 있는 설정값 변경뿐이다.** 설정값 변경은 바로 적용해 다시 계산하고, 지금 대화에 바뀐 값과 [되돌리기]를 카드로 남긴다. 앱 조작과 jig 열기는 제안 카드로 보이고 SPEC-02.19의 확인 등급대로 실행한다. 계정 전환은 확인 카드(T2)가 필요하다. 여러 조작이 섞였거나 모호한 말은 지금 대화의 AI에 보내며, AI도 앱 동작을 직접 실행하지 않고 카드로 제안한다.
3. **바꾸기:** 보내기 전 칩은 두지 않는다. AI 없이 처리한 알림과 카드에는 **'AI 작업으로 보내기'**를 두어, 누르면 그 처리(화면 변경·설정값 변경)를 되돌리고 같은 글을 지금 대화의 AI에 보낸다. 대상을 찾지 못한 알림에도 같은 버튼을 둔다.
4. **Jev에 보내는 것:** 경로 판정에는 정해진 항목만 보낸다: 요청 글(2,000자 이하), 열린 jig의 설정값 이름·설명, 등록된 jig의 부름 설명, 연결 파일의 역할 이름(구조 모델·CAD 1 등), 앱 동작 이름 목록. 파일 이름·경로·폴더 이름, 자료 진술 본문, 형상, 계정 주소, 로그인 코드는 보내지 않는다. 기록에는 판정 결과·판정 방법·시간·되돌림 여부만 남기고 글은 남기지 않는다. Jev 전송은 FR-18에 따라 알리고 사용자가 끌 수 있으며, 끄면 규칙만 쓴다.
5. **모델:** 모델은 대화를 열 때 정한다(SPEC-02.19). 작성기의 모델 선택이 "자동 (Jev)"이면 서버가 대화의 작업 종류와 대상 영역으로 서비스·모델·effort를 고르고(우선순위표는 [PLAN-05 §7.2a](../plans/PLAN-05-decision-layer-evaluation.md)), 사용자가 모델을 고르면 그 모델로 대화를 연다. 열린 대화의 공급자·모델은 바꾸지 않고 effort만 턴마다 바꿀 수 있다. 열린 대화에서 다른 공급자·모델을 고르면 인계로 처리한다(SPEC-02.19). 작성기는 요청 글로 모델을 따로 바꾸지 않는다.
6. **대화의 문맥:** 요청은 대화 하나에 속하고, 대화는 시작 때 정한 공급자 세션 하나를 이어 간다(SPEC-02.19). 공급자가 이전 턴의 요청·답·쓴 코드·오류를 기억하므로 VIDE는 이전 대화를 다시 골라 보내지 않고, 턴마다 이번 턴의 범위, 대화 원장에서 바뀐 항목, 그 사이 다른 대화에서 바뀐 것(반영된 문서 판, jig 설정값 변경)의 요약을 보낸다. 세션이 길어지면 공급자가 문맥을 압축(auto compact)할 수 있고 압축은 내용을 잃을 수 있으므로, 결정·가정·질문과 답·결과 참조는 VIDE의 대화 원장이 정본이다. 새 세션을 열 때와 정해진 턴마다 원장 전체를 보낸다. 세션을 이어 쓰지 않는 원장 방식(ADR-021)은 원장과 함께 이 대화의 이전 요청과 답(성공한 것, 사용자가 숨긴 것 제외)을 골라 보낸다: 6개 이하이면 모두, 더 많으면 Jev가 최근 20개 각각이 새 요청에 도움이 되는지 판단해 도움이 되는 것(최대 5개)과 바로 앞 하나를 원래 순서대로 보내고, Jev 키가 없거나 응답이 실패·지연(5초)되면 최근 6개를 보낸다. 판단에는 요청·답의 앞부분만 쓰고 기록에는 개수·방법·시간만 남긴다. 보내는 대화는 하나당 요청 2,000자·답 6,000자까지로 줄여 전체 자료 한도(256 KB)를 넘지 않게 한다.

## 목적별 대화와 세션 — SPEC-02.19

근거: FR-08·10·11·15·18·25, AC-46·47, [ADR-021](../decisions/ADR-021-conversation-sessions.md). 2026-09-29 사용자 결정: 모든 대화를 세션으로 잇고, 대화를 시작할 때 Jev가 공급자·모델을 정해 그 대화가 끝날 때까지 고정하며, 모델 편집·CAD 편집·법규 질문처럼 목적이 다른 대화를 동시에 진행한다. 동시 접수는 SPEC-02.9, 경로 판정은 SPEC-02.17이 소유한다. 대화 칩·카드의 화면 표현은 [Design](../../Design.md) SCR-15, 저장 구조는 [ARCH-03](../architecture/ARCH-03-jig-runtime.md) §10, CLI 인자와 공급자 기록 관리는 [ARCH-01](../architecture/ARCH-01-system.md) §2가 소유한다.

**1. 대화.** 대화는 목적 하나의 작업 흐름이다. 한 프로젝트에 여러 대화가 동시에 열리고 서로 독립으로 돈다. 작성기로 보낸 요청은 대화 하나에 속하며, 이 기능 이전의 요청과 호스트 패널에서 보낸 요청은 프로젝트 기본 대화에 속한다. Sync 받기·jig 입력 읽기·Rhino에 만들기 같은 작업은 대화에 속하지 않고, 대화에서 시작했으면 그 대화에 결과 카드를 남긴다.
- 사용자가 새 대화를 연다. jig를 열면 그 jig의 대화가 열려 작업본과 연결되고, jig를 닫아도 대화는 남는다. jig 만들기는 제작 대화를 연다.
- Jev가 새 요청의 목적이 지금 대화와 다르다고 보면 새 대화 제안 카드('이 요청은 법규 질문으로 보입니다 — [새 대화로 보내기] [지금 대화에서 계속]')를 보인다. 자동으로 나누지 않는다.
- 대화마다 공급자·모델·계정을 보인다. 다른 대화에 답이나 질문이 오면 그 대화에 표시한다.
- 화면을 뺀 AI 없는 처리(설정값·앱·jig 열기)의 결과도 지금 대화에 카드로 남고 원장에 기록된다.
- 호스트 패널은 대화가 아니라 대상 문서로 거른다. 그 호스트 문서를 대상으로 한 요청을 모든 대화에서 모아 보인다.
- 대화를 닫아도 VIDE의 요청·결과·원장은 남는다. 공급자 CLI가 이 PC에 남긴 대화 기록은 대화를 닫고 30일 뒤 VIDE가 지우고, 버린 jig 초안의 기록은 바로 지운다. 기록을 지운 뒤 다시 연 대화는 원장으로 새 세션을 시작한다.

**2. 공급자·모델·계정 고정.** 대화를 열 때 Jev가 대화의 종류·공급자·모델·effort를 한 번 정하고(SPEC-02.17의 5), 계정은 그때의 선택 계정으로 고정한다(SPEC-02.18의 접수 시 고정을 대화 단위로 적용). 대화가 끝날 때까지 같은 공급자·모델로 가고 effort만 턴마다 바꿀 수 있다. 선택 계정을 바꾸면 새 대화부터 적용하고, 열린 대화를 다른 계정·공급자로 옮기는 것은 인계(5)로 한다.

**3. 한 턴의 실행과 안전장치.** 대화가 세션으로 이어져도 권한은 턴마다 새로 준다.
- 턴마다 대상, 기준 판, 허용 도구, 권한, 호출·시간·호스트 명령 상한을 새로 발급하고 턴이 끝나면 회수한다. 이전 턴에서 받은 대상 참조나 권한으로는 다음 턴에서 조회·쓰기를 할 수 없다. 앞 턴에 도구가 있었다는 이유로 다음 턴에 도구를 주지 않는다.
- 공급자 CLI의 개인 설정·전역 MCP·플러그인 차단 같은 격리를 매 턴 다시 적용한다. 턴 시작 때 공급자가 알린 도구 목록이 그 턴의 허용 범위와 다르면 실행하지 않고 멈춘다.
- 턴의 조건 버전은 SPEC-02.1대로 시작 때 고정한다. 세션의 기억은 권한이나 확정 조건의 근거가 아니며, 후보·원본 보호·적용·불명확 규칙(§2~§9)을 그대로 적용한다.
- jig 대화의 AI는 그 jig 작업본을 읽고 수정 사항·입력 역할을 카드로 제안한다. 2026-09-30 결정: 대화 안에서 AI는 그 대화에 열린 jig에 한해 **설정값 변경(`jig_set`)과 계산 단계 실행(`jig_run`)을 확인 없이** 할 수 있다. 설정값 변경은 되돌릴 수 있는 T1 동작으로, 대화 원장에 기록하고 바뀐 값과 [되돌리기]를 카드로 보인다. `jig_run`은 계산 단계만 돌리며 만들기·반영 단계는 돌리지 않는다. 해석 확정(M), Rhino에 만들기·원본 반영·로그인·계정 동작(T2)은 계속 사람이 누르는 동작이며 AI는 카드로 제안만 한다. 턴마다 주는 도구 목록은 ARCH-01 §3이 소유한다.
- jig 단계 안의 AI 호출(입력 역할 제안 등)은 대화가 아니라 계산 단계다. 매번 같은 입력으로 새로 부르고 SPEC-07.7의 점검을 거친다.
- AI의 한 턴은 완료, 진행 중 보고, 질문 중 하나로 끝난다. 질문은 질문 카드(6)로 보인다.

**4. 한 대화 안의 순서.** 한 대화에는 진행 중인 턴이 하나다.
- 진행 중에 덧붙인 말은 그 대화의 대기열에 접수 순서대로 넣고('대기 1'), 앞 턴이 끝나면 그 결과를 이어받는 다음 턴으로 보낸다. 앞 턴은 끊지 않는다. 대기 중인 말은 보내기 전에 지울 수 있다.
- 앞 턴을 끊고 싶을 때만 **[멈추고 이걸로]**를 누른다. 이것은 §8의 개입이다. 새 말을 먼저 저장하고, 앞 턴에 중단을 요청하고, 실제 종료를 확인한 뒤 새 턴을 실행한다.
- 말로 한 '잠깐 멈춰'·'그거 말고'도 대기열에 넣는다. 개입으로 보이면 [멈추고 이걸로]를 눈에 띄게 보이지만 자동으로 끊지 않는다.
- 앞 턴이 불명확 결과로 끝나면 그 대화의 대기열을 멈추고 이유를 보인다(§7). 다른 대화와의 차례는 SPEC-02.9를 따른다.

**5. 인계와 복구.** 인계해도 사용자에게는 같은 대화로 이어 보인다. 인계는 대화에 카드로 남기고, 새 세션에는 인계 자료(대화 원장 전체, 최근 턴 요약, 작업 파일 목록, 마지막 시험 결과)를 준다. 이전 세션은 다시 쓰지 않는다.

| 상황 | 처리 |
|---|---|
| 계정 한도(`PROVIDER_LIMIT`) | 한도로 끝난 턴은 자동으로 다시 보내지 않는다(SPEC-02.18). 자동 전환을 켰으면 다음 턴부터 같은 공급자의 여유 있는 계정에서 새 세션으로 잇고, 켜지 않았으면 계정 전환 확인 카드(T2)를 보인다 |
| 공급자·모델 바꾸기 | 자동으로 하지 않는다. 사용자가 [다른 AI로 이어 가기]를 누르면 바뀌는 공급자와 전송 범위를 확인 카드(T2)로 보인 뒤 새 세션을 연다(SPEC-02.1) |
| 세션을 잃음(이어 쓰기 실패) | 인계 자료로 새 세션을 연다 |
| 종료를 확인하지 못한 중단, 재시작으로 끊긴 턴 | 그 세션은 다시 이어 쓰지 않는다. 이전 프로세스의 종료를 확인한 뒤에만 인계 자료로 새 세션을 연다. 한 세션을 두 실행이 함께 쓰지 않는다. 호스트 쓰기 보호는 §4·§7대로다 |
| 대화가 길어짐 | 정한 턴 수나 누적 입력량을 넘으면 원장과 최근 요약으로 새 세션을 연다. 기준은 설정값이며 기본값은 PLAN-24의 측정으로 정한다 |
| 세션을 이어 쓸 수 없는 공급자 | 원장 방식으로 턴마다 새로 실행하되 같은 대화로 보인다(ADR-021) |

**6. 질문 카드.** AI는 다음 셋 중 하나일 때만 묻는다: (a) 결과가 크게 갈리는 선택인데 근거가 없거나 서로 충돌한다, (b) 필수 입력이 비었다, (c) 대상이 둘 이상으로 읽힌다. 그 밖에는 권장값으로 진행하고 가정 목록에 적는다.
- 한 턴에 최대 3개다. 원장에 있는 질문은 되풀이하지 않고, 사용자가 이미 결정한 조건은 다시 묻지 않는다.
- 질문은 건축 실무 용어로 된 한 문장이다. 설명서 형식·단계 순서·노드 병합 허용 오차 같은 내부 값은 묻지 않고 '자세히'에만 둔다.
- 카드에는 질문, 왜 묻는지와 답에 따라 무엇이 달라지는지(근거 포함), 답의 형태(고르기·숫자·스케치·가리키기·글), 선택지와 권장 선택지, 답 전까지 막히는 단계를 보인다. 건너뛸 수 있는 질문에는 [권장값으로 진행]을 두고 그 선택을 가정으로 기록한다.
- 답이 곧 설정값·입력·구역이면 그 값에 바로 연결한다. 답은 원장에 남고 다음 턴으로 간다. 막히지 않은 단계와 다른 대화는 계속 진행한다.
- 예: "'동선' 레이어를 소방 동선으로 봤습니다. 맞나요?"(가리키기, 권장: 예, 막는 단계: 기둥 배치).

**7. 확인 등급.** Jev 판정·규칙·AI 턴이 낸 동작은 영향에 따라 네 등급으로 처리한다. 사람이 직접 누르는 기존 버튼의 동작은 바꾸지 않는다.

| 등급 | 뜻 | 처리 | 예 |
|---|---|---|---|
| R | 읽기 | 확인 없이 실행 | 자료 검색, jig 상태, 확정된 해석 결과 읽기 |
| T1 | VIDE 안의 상태만 바꾸고 이전 상태가 남는 동작 | 제안 카드의 버튼 한 번으로 실행하고 결과에 [되돌리기]를 붙인다(되돌릴 수 있는 것). 사용자의 말에서 바로 읽은 설정값 변경만은 누르지 않고 적용한다(SPEC-02.17의 2) | 설정값 변경, 다시 계산, Sync 받기, jig 열기 |
| T2 | [ADR-011](../decisions/ADR-011-delegation-working-mode.md) §3.1의 경계(원본 반영, 외부 공개, 유지 조건 변경, 범위 확대, 큰 비용)와 로그인·계정·공급자·연결 프로그램 같은 설정·권한 변경 | 무엇을·어디에·어떤 영향으로 하는지 적은 확인 카드 한 장과 실행 버튼 하나 | Rhino에 만든 후보의 원본 반영, 로그인 시작, 계정 전환, 다른 AI로 이어 가기, 연결 프로그램 설치 |
| M | 사람만 할 수 있는 일 | 실행하지 않고 이유와 누를 곳(해당 화면)만 안내 | 로그인 코드 입력, 원격 비밀번호, 원본 파일 열기, 구조 해석 확정 |

- Jev와 AI는 동작을 제안만 하고(예외: 3의 대화 안 `jig_set`·`jig_run`), 실행은 VIDE가 사람이 누를 때와 같은 경로·검사로 한다. 제안 카드로 실행하는 동작도 원격 세션 제한([ADR-010](../decisions/ADR-010-first-release-local-only.md) §3)을 그대로 받으며, 등급은 원격에서 허용하는 범위를 넓히지 않는다.
- 로그인 주소·일회용 코드·비밀값은 AI 대화와 도구 결과에 넣지 않는다.

## 구독 계정 프로필 — SPEC-02.18

관리 계정의 로그인은 기본 브라우저를 자동으로 열지 않는다(2026-09-29 사용자 결정). VIDE가 공식 CLI의 로그인 주소를 보여 주고 사용자가 원하는 브라우저·계정에 복사해 연다. Claude는 승인 뒤 브라우저에 표시된 코드를 VIDE에 붙여 넣어 끝내고, ChatGPT는 기기 코드 방식으로 주소와 일회용 코드를 보여 주며 코드 입력 뒤 자동으로 끝난다. 기기 코드가 막힌 계정과 원하는 사용자에게는 기본 브라우저 로그인(이전 방식)을 제공한다. 로그인은 10분 안에 마쳐야 하고 남은 시간을 보인다. 주소·코드는 로그인하는 동안 이 PC 화면에만 보이며 파일·로그에 남기지 않고 원격 기기에는 보내지 않는다. 취소한 로그인은 표시를 남기지 않고, 실패는 사용자가 닫거나 다시 시도할 때까지 보인다.

계정 이름은 기존 CLI 로그인과 추가 계정 모두 바꿀 수 있다. 이름 변경은 표시 이름만 바꾸며 로그인·선택·진행 중 작업에 영향이 없고, 기존 CLI 로그인의 이름을 비우면 기본 이름으로 돌아간다. 사용자가 붙인 이름은 상태 표시줄에서 이메일보다 먼저 보인다.

관리 프로필 제거는 로그아웃 확인 뒤 사용자가 로컬 CLI 설정·이력 삭제를 확인한 경우에만 수행한다. 기본 CLI 로그인은 제거하지 않는다. 실행/불명확 작업·인증 작업 중에는 거절하고, 선택된 프로필을 제거하면 기본 프로필로 돌아가되 요청을 자동 전송하지 않는다. 프로젝트 작업 이력은 유지한다.

관리 계정의 로그아웃은 해당 프로필의 공식 CLI에 맡긴다. 기존 CLI 기본 로그인은 이 동작의 대상이 아니다. 진행/종료 대기 동안 해당 공급자의 새 요청과 전환을 막고, 프로세스 성공 종료와 공식 상태의 인증 해제를 확인한 뒤 완료한다. 실패/취소를 로그아웃 완료로 표시하거나 다른 계정으로 자동 전환하지 않는다.

근거: FR-08·FR-18. 공급자별 활성 계정을 선택하고 요청 접수 시 고정한다. 목적별 대화(SPEC-02.19)의 요청은 대화를 열 때 고정한 계정을 쓰고, 열린 대화의 계정 변경은 인계(SPEC-02.19의 5)로 한다. 동일 계정의 독립 작업 병렬 실행은 기존 규칙을 유지한다. 계정 변경은 기존 계정의 큐·실행·불명확 작업이 해소된 후 다음 요청부터 적용한다. 전환 대기 중 신규 요청 접수는 보류하고 기존 작업 개입은 원 계정을 유지한다. 계정 제거·재로그인은 사용 중 거절한다. 재시작 후 불명확 쓰기 보호를 우회하지 않는다.

인증은 공식 CLI가 소유한다. 기본 로그인은 호환 경로로 유지하며 새 프로필은 독립 로그인한다. VIDE에서 시작한 로그인은 실제 프로세스 종료와 공식 인증 상태 확인까지 진행 중으로 표시하고 같은 공급자의 새 요청·전환·추가 로그인을 보류한다. 로그인 취소/실패는 계정 선택을 바꾸지 않으며 중단 요청과 종료 확인을 구분한다. 확인되지 않은 격리는 지원으로 표시하지 않는다. 사용량 미확인은 0%나 무제한이 아니며 자동 전환·유료 API 우회 근거가 되지 않는다. 사용자가 지정한 모델/effort를 판정 실험이 변경하지 않는다.

**사용량 조회와 자동 전환(2026-09-29 사용자 결정).** 계정 목록은 각 계정의 공식 CLI 로그인 파일에서 로그인 여부·이메일·요금제를 보여 준다. 사용자가 켠 경우에만(기본 꺼짐) 그 계정의 로그인 정보로 서비스의 비공개 사용량 주소를 조회해 5시간·7일 사용률과 초기화 시각을 보여 준다. 서비스 약관상 위험을 알리고 사용자가 감수하는 선택 기능이다. VIDE는 토큰을 갱신·복사·표시하지 않고, 계정당 조회는 3분(직접 새로고침 1분)에 한 번이다. 자동 전환을 켜면 새 요청 접수 때 선택 계정이 기준(기본 90%) 이상이거나 한도로 실패한 계정이면 같은 서비스에서 로그인돼 있고 여유가 가장 많은 계정으로 바꾸고 그 계정을 선택 계정으로 둔다. 진행 중인 요청은 옮기지 않는다. 사용량을 모르는 계정은 기준 초과로 보지 않는다. 요청이 구독 한도로 끝나면 `PROVIDER_LIMIT`로 구분하고 그 계정을 초기화 시각(모르면 1시간)까지 건너뛴다. 자동 재전송은 하지 않는다.


## 연결 Rhino 수정 위임 — SPEC-02.16

근거: FR-04·08·11·16, PRD §9.5 및 2026-09-28 사용자 연결 흐름 지시. 사용자가 요청 전 `연결 Rhino 수정`을 선택하면, 명시된 기준 캡처의 연결 문서 하나에 해당 요청의 검증된 후보를 반영하는 권한이다. 검토/후보 만들기는 원본 쓰기를 허용하지 않는다. 클라우드 공개·파일 저장·다른 문서 수정 권한은 포함하지 않는다.

접수 시 연결 문서와 기준 캡처를 고정한다. 생성 코드는 격리된 작업 사본에서 실행하고, 실제 대상 반영은 기존 차이 검증·Undo·적용 영수증 경로를 사용한다. 사람이 기준 문서를 변경했거나 연결이 끊겼으면 원본을 덮어쓰지 않고 후보와 실패 이유를 남긴다. 추가 지시로 권한이나 대상을 넓히지 않는다. 중단이 접수되면 새 원본 적용을 시작하지 않는다.

적용 성공 후 같은 문서를 다시 읽어 VIDE와 다음 요청의 기준을 갱신한다. 반영 성공과 후속 Sync 실패는 구분하고 Sync만 다시 시도한다. 원본 반영 응답이 불명확하면 재실행하지 않고 적용 영수증 조회로 해결한다. 자동 복구·재연결·재시작이 새 원본 쓰기 동의가 되지 않는다. 복수 문서 연계 위임은 이 모드에서 제외한다.
