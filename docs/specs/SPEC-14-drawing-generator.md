# 도면 생성기와 모델 → CAD 역반영

근거: 2026-10-07 사용자 메모 "도면 생성기(export to cad. sheet. annotation. dimension. xref 등의 설정이 그대로 잘 넘어가는지)", "모델링 수정하면 그거를 역으로 cad에 반영(수정하는 방식으로. 형식 잘 지켜서)"와 같은 날의 상세 계획 지시. 실험 근거는 [SPIKE-2026-10-07-drawing-export](../tdd/SPIKE-2026-10-07-drawing-export.md)(PLAN-43 T-199), xref 관계 읽기는 [SPEC-01.11](SPEC-01-project-input-sync.md)의 11(T-200)이다. 구현 계획은 [PLAN-47](../plans/PLAN-47-drawing-generator.md)이다.

연결되는 제품 약속은 FR-04(네이티브 생성·수정), FR-12(바로 적용·되돌리기·확인), FR-14(파일 내보내기), FR-03(Sync 기준), FR-02(여러 문서 연계), FR-16(불명확 쓰기 재실행 금지), FR-18(권한)이다. 이 기능은 PRD [C-08](../PRD.md) 후보이며 아직 채택 전이다. 아래 R-01이 채택 제안이다. 채택 전에는 이 명세를 근거로 구현하지 않는다(PLAN-47의 SPIKE 티켓은 예외).

<!-- claude-review:start -->
> **[검토 · claude · R-01 · 높음]** C-08은 PRD §4.4 후보이고, §14.2 제외에는 '전문 스킬 완성(FR-21, 도면 포함)'과 '요청 없는 호스트 간 원본 자동 동기화'가 있다. 이 명세의 범위(사용자가 누르는 도면 생성과 사용자가 고른 변경만 반영하는 역반영)는 후자에 걸리지 않지만, 전자의 '도면' 전문 스킬과 겹쳐 PRD 결정이 필요하다. 제안: PRD §4.4 C-08에 "2026-10-07 채택, 동작은 SPEC-14"를 적고, §14.2 포함 표에 `도면 생성·역반영 | 템플릿 기반 새 DWG 생성과 정리 패스, 연결 도면의 고른 변경 반영과 실행별 되돌리기 (C-08, FR-04·12·14)` 행을 더하며, 제외의 FR-21 문구를 "구조 분석(FR-23)과 도면 생성·역반영(C-08)을 뺀 전문 스킬 완성"으로 좁힌다. 사용자가 수락 범위를 정한다.
<!-- claude-review:end -->

## 사용자가 하는 일 — SPEC-14.1

**도면 생성**

1. 설계자는 연결된 Rhino 문서(SPEC-01.11)에서 **도면 생성기**를 연다. 원천은 그 문서의 레이아웃(페이지 뷰)과 모델 공간의 2D 도면 요소다(지원 범위는 SPEC-14.4).
2. 출력할 시트(레이아웃)를 고르고, 등록된 **템플릿**(SPEC-14.3) 하나를 고르거나 '템플릿 없음'을 고른다.
3. [미리보기]를 누르면 VIDE가 원본을 건드리지 않고 출력 사본을 만든다. 시트마다 그림과 **보존 보고**(보존·고침·못 고침, SPEC-14.6)를 보인다.
4. [저장]을 누르면 확인 카드에 쓸 파일 경로·덮어쓰지 않음·템플릿·시트 수를 보이고, 사용자가 확인하면 새 DWG 파일을 쓴다(SPEC-14.7).
5. 결과 파일은 프로젝트 폴더 목록에 나타나고, 사용자가 ZWCAD에서 열어 이어서 편집한다. 열어서 Link하면 그 도면은 원천 모델과 짝을 이룬 **생성 도면**으로 인식된다(SPEC-14.8).

**역반영**

1. 모델을 고친 뒤, 짝이 있는 CAD 도면(생성 도면 또는 Sync jig로 대응을 맞춘 기존 도면)에서 **[모델 변경 반영]**을 연다.
2. VIDE가 마지막 반영 기준 이후 모델 변경을 도면 단위의 **변경 행**(추가·수정·삭제·충돌·끊김)으로 보이고, 행마다 도면의 어느 파일(루트 또는 xref 도면)에 쓸지 보인다(SPEC-14.9·10).
3. 사용자가 행을 고르고 [반영]하면 열린 연결 도면은 바로 고치고(되돌리기 기록 하나), 닫힌 도면은 새 사본 파일로 쓴다(SPEC-14.11).
4. 반영 뒤 같은 도면을 다시 읽어 바뀐 개체를 보인다. 사용자는 [되돌리기] 또는 ZWCAD의 Ctrl+Z로 되돌린다. 파일 저장은 사용자가 한다.

AI는 이 흐름의 계산·쓰기를 대신하지 않는다. 대화 요청이 도면 생성·역반영을 원하면 생성기 또는 반영 화면을 열어 같은 확인 단계로 보낸다(SPEC-14.14).

## 1. 용어 — SPEC-14.2

- **원천 문서:** 도면의 근거가 되는 Rhino 연결 문서. 생성 시점의 문서 상태(저장 안 된 변경 포함)를 스냅숏으로 쓴다.
- **템플릿:** 레이어·선종류·문자/치수 스타일·도곽 블록·레이아웃(용지·뷰포트 축척)·xref 구조를 가진 DWG. 사용자의 회사 템플릿이나 기존 프로젝트 도면이다. VIDE는 템플릿의 사본만 쓴다.
- **출력 도면:** 생성기가 쓴 새 DWG. 원천 문서·템플릿·생성 시각·생성기 판을 도면 안에 출처 표시로 지닌다([ADR-030](../decisions/ADR-030-link-id-in-document.md)의 연결 ID와 같은 방식).
- **모델 기하:** 원천 문서에서 나온 2D 기하 묶음. 출력 도면 안에서 VIDE 소유의 한 단위(블록 또는 xref 도면, PLAN-47 결정 질문 6)로 들어가며, 템플릿의 다른 내용과 구분된다.
- **대응:** 원천 객체와 도면 개체의 짝. 생성 도면은 개체마다 출처 표시(원천 객체 ID)를, 기존 도면은 Sync jig가 만든 일치 행을 쓴다.
- **반영 기준:** 마지막 생성·반영 때 대응마다 기록한 원천 객체 상태와 도면 개체 상태. 변경과 손 수정 판별의 기준이다.

## 2. 템플릿 — SPEC-14.3

1. 프로젝트마다 템플릿을 등록한다. 등록은 사용자가 프로젝트 폴더 안 DWG를 고르는 것이며, VIDE는 숨은 ZWCAD로 그 사본을 읽어 레이어·스타일·도곽 블록·레이아웃·xref 목록을 보인다. 원본은 읽기만 한다.
2. 템플릿에서 **유지하는 것:** 레이어(이름·색·선종류·선가중치), 문자·치수 스타일, 블록 정의와 도곽 삽입·속성, 레이아웃(용지·뷰포트 축척·잠금), 기존 xref 부착(경로 그대로, T-200 해석 규칙으로 존재 확인).
3. **레이어 대응:** 원천 레이어 → 템플릿 레이어 표를 템플릿마다 둔다. 같은 이름은 자동 대응, 나머지는 사용자가 고르며, 고르지 않은 원천 레이어는 원래 이름으로 새로 만든다(보존 보고에 '템플릿에 없는 레이어'로 표시).
4. 템플릿을 읽을 수 없거나 단위가 mm가 아니면 등록하지 않고 이유를 보인다.

## 3. 도면 생성 — SPEC-14.4

1. **원천 범위(1차):** Rhino 레이아웃과 그 디테일, 모델 공간의 2D 도면 요소(선·폴리선·원·호·곡선, 문자, 치수, 해치, 블록 삽입). 3D 객체를 2D로 투영하는 평·입·단면 생성(Make2D)은 PLAN-47 T-231 실험과 결정 질문 1 뒤에 정한다.
2. **방식:**
   - **템플릿 없음(방식 A):** 원천 레이아웃을 DWG 2018 형식의 출력 도면으로 쓰고 정리 패스(SPEC-14.5)를 적용한다.
   - **템플릿 병합(방식 C, 기본):** 템플릿 사본에 모델 기하를 넣고, 템플릿의 레이아웃·뷰포트가 모델 기하를 보이게 한다. 원천 레이아웃의 시트 이름·디테일 축척은 템플릿 레이아웃의 대응 시트(이름이 같거나 사용자가 고른 것)에 옮긴다. 템플릿 도곽의 속성(도면명·축척)은 시트 정보로 채운다.
3. 형식은 DWG 2018로 고정하고, 곡선은 원래 유형(호·원·폴리선)으로 쓴다. 선분화(Lines 체계)와 2007 형식(Default 체계)은 쓰지 않는다.
4. 생성은 원천 문서와 템플릿 원본을 바꾸지 않는다. 사용자의 Rhino·ZWCAD 창을 쓰지 않고 VIDE가 띄운 숨은 호스트만 쓴다.

## 4. 정리 패스 — SPEC-14.5

실험에서 확인된 손실을 출력 사본에서 고친다. 고친 것과 못 고친 것은 보존 보고에 남긴다.

| 손실(실험) | 규칙 |
|---|---|
| 치수 문자가 고정 문자로 바뀜 | 문자가 측정값의 표시와 같으면 측정값 연동(`<>`)으로 되돌린다. 접두·접미가 붙은 경우 그 부분만 남기고 값은 연동한다. 측정값과 다른 문자(사용자 의도)는 그대로 두고 '고정 문자 유지'로 보고한다. |
| 반지름·지름 치수 화살표 개체 재정의(1.0) | 개체 재정의를 지워 스타일 값을 따르게 한다. |
| 정렬 치수가 회전 치수로 바뀜 | 값·위치가 같으면 정렬 치수로 바꾼다. 못 바꾸면 회전 치수로 두고 보고한다. |
| 한글 글꼴 이름 깨짐 | 원천 문자 스타일의 글꼴 이름으로 고친다. 템플릿에 같은 이름의 문자 스타일이 있으면 템플릿 정의를 따른다. 그 글꼴이 PC에 없으면 보고한다. |
| 빈 레이아웃(`배치1`·`배치2`) 추가 | 개체가 없는 추가 레이아웃을 지운다. 원천·템플릿에 있던 레이아웃은 지우지 않는다. |
| 축척 뷰포트 꺼짐 | 원천 디테일에 대응하는 뷰포트를 켠다. |
| 링크 블록이 일반 블록이 됨 | 원천의 링크 블록이 가리키던 파일의 DWG(같은 이름, 같은 폴더 또는 생성기가 함께 내보낸 DWG)가 있으면 그 블록 삽입을 xref 부착으로 바꾼다(삽입 변환 유지). 없으면 일반 블록으로 두고 'xref 미복원'으로 보고한다. |
| 사용하지 않은 스타일·레이어 추가(`STANDARD_ACAD`, `Defpoints` 등) | 지우지 않는다(호스트 기본 항목). |

정리 패스 자체가 실패하면 출력은 '정리 안 됨'으로 보이고 저장할 수 없다(SPEC-14.13).

## 5. 보존 보고 — SPEC-14.6

미리보기와 저장 결과는 시트마다 다음을 보인다.

- 레이아웃·뷰포트 축척·잠금, 레이어 수(템플릿 대응/새 레이어), 치수(연동 복원/고정 유지), 문자 스타일·글꼴, 블록·xref(복원/미복원), 해치, 개체 수.
- 원천에 있었지만 출력에 없는 개체 수와 종류(지원 밖 객체, SPEC-14.4의 1).
- 보고의 수치는 출력 사본을 다시 읽은 실제 값이다. 예상값으로 채우지 않는다.

## 6. 출력 위치와 확인 — SPEC-14.7

1. **새 파일만:** 생성기는 언제나 새 파일을 쓴다. 원천 3DM, 템플릿 원본, 기존 도면, 같은 이름의 파일을 덮어쓰지 않는다. 이름이 겹치면 번호를 붙인다.
2. **위치:** 기본은 프로젝트 폴더 아래 생성기 출력 폴더다(이름 규칙은 PLAN-47 결정 질문 3). 프로젝트 폴더가 없으면 VIDE 데이터 폴더의 프로젝트 출력 폴더다. 사용자는 확인 카드에서 다른 폴더를 고를 수 있다.
3. **확인:** 파일 쓰기는 PRD §11.2의 '경로 지정 저장·내보내기'다. 확인 카드는 쓸 파일 경로 전부, 템플릿, 시트 수, 보존 보고의 못 고친 항목 수를 보이고 [저장]·[취소]를 둔다. 확인 전에는 어떤 파일도 출력 위치에 남지 않는다(미리보기 사본은 VIDE 작업 폴더에만 있다). 원격 화면에서는 확인을 받지 않고 작업 PC 화면으로 안내한다.
4. 쓴 뒤 파일을 다시 읽어 보존 보고와 대조한다. 쓰기 결과가 불명확하면 다시 쓰지 않고 그 경로의 파일 상태를 확인하라고 알린다(FR-16).

## 7. 역반영의 대상과 대응 — SPEC-14.8

1. **대상 도면:** (a) 생성 도면 — 출처 표시가 원천 문서의 연결을 가리키는 DWG, (b) 기존 도면 — 같은 프로젝트의 ZWCAD 연결 파일이며 사용자가 Sync jig(SPEC-05.8)로 원천 문서와 위치 관계를 확정한 것. 짝이 없는 도면에는 [모델 변경 반영]을 보이지 않는다.
2. **변경 단위는 대응 하나다.** 생성 도면은 개체의 출처 표시(원천 객체 ID)로, 기존 도면은 Sync jig의 일치 행으로 짝을 찾는다. 가까운 위치라는 이유만으로 새 짝을 만들지 않는다. 원천 객체가 분할·결합·재생성되어 ID가 바뀌면 그 짝은 '끊김'이다(AC-21).
3. **형식 보존:** 반영은 기존 개체를 고치며 다시 그리지 않는다. 개체의 레이어·색·선종류·선가중치·블록 소속·치수 스타일·Handle은 유지한다. 블록 삽입은 펼치지 않고 삽입 위치·회전만 고친다. 새로 추가하는 개체는 템플릿 레이어 대응(SPEC-14.3의 3)으로 레이어를 정하고, 대응이 없으면 그 도면에 같은 이름의 레이어가 있을 때만 쓰며 아니면 행을 '레이어 지정 필요'로 둔다.
4. **치수:** 고친 기하에 연동된 치수는 호스트가 갱신한다. 생성기가 만든 치수(출처 표시 있음)는 정의점을 고치고 측정값 연동을 유지한다. 연동되지 않은 손 치수가 고친 개체에 닿아 있으면 고치지 않고 '치수 확인 필요' 목록에 넣는다.
5. **좌표:** 생성 도면은 생성 때의 변환을, 기존 도면은 Sync jig의 확정 관계를 써서 모델 변경을 도면 단위·좌표로 환산한다.

## 8. xref가 있는 도면 — SPEC-14.9

1. 대응 개체가 xref 도면 안에 있으면 **그 개체를 소유한 xref 도면**에 쓴다. 루트 도면을 통해 xref 내용을 고치지 않는다. 좌표는 T-200의 삽입 변환 사슬을 거꾸로 적용해 그 도면 좌표로 바꾼다.
2. xref 도면 전체의 위치가 바뀌는 변경(삽입 이동)은 하지 않는다. 모델 변경이 그런 이동으로만 설명되면 행을 '지원 안 함 · xref 삽입 이동'으로 보인다.
3. 같은 xref 도면을 다른 루트도 참조하면 행에 영향받는 루트 도면 목록을 보인다.
4. 관계가 '누락'·'순환'·'폴더 밖'인 도면에는 쓰지 않는다(SPEC-01.11의 11).

## 9. 미리보기·차이 — SPEC-14.10

1. 행은 대응마다 하나다: **추가**(원천에 새 객체), **수정**(원천만 바뀜), **삭제**(원천에서 지워짐), **충돌**(원천과 도면이 둘 다 반영 기준에서 바뀜), **끊김**(도면 개체가 지워졌거나 원천 ID가 바뀜), **지원 안 함**(SPEC-14.13).
2. 행마다 쓸 파일, 레이어, 바뀌는 값(정점·중심·반지름·삽입 위치 등, 도면 단위)과 뷰포트 표시(전·후 겹쳐 보기)를 보인다.
3. 기본 선택은 추가·수정이다. 삭제는 선택하지 않은 채로 보이며, SPEC-02.13의 기준 개수를 넘는 삭제는 확인을 한 번 더 받는다. 충돌·끊김·지원 안 함은 선택할 수 없고, 충돌은 행에서 [모델로 덮기]를 고르면 수정 행이 된다.
4. 차이 계산은 도면을 바꾸지 않는다. 계산 도중 도면이 바뀌면 결과를 확정하지 않고 다시 계산한다(SPEC-01.6).

## 10. 적용·되돌리기·저장 — SPEC-14.11

1. **열린 연결 도면:** 고른 행을 그 도면의 바로 실행 하나로 적용한다. 실행 하나가 되돌리기 기록 하나이며, 적용 뒤 다시 읽어 바뀐 개체를 보인다(SPEC-02.13, [ADR-022](../decisions/ADR-022-direct-apply-plan-auto.md)). 쓸 파일이 여러 개(루트와 xref 도면)면 파일마다 기록 하나이고 결과·실패는 SPEC-02.13의 6([ADR-027](../decisions/ADR-027-multi-file-coordination.md))을 따른다. 한 파일이라도 실패하면 이미 적용한 파일을 되돌린다.
2. **닫힌 도면:** 원본을 덮어쓰지 않고 그 도면의 사본에 적용한 새 파일을 쓴다(SPEC-14.7의 확인을 거침). xref 도면이면 그 xref 도면의 사본만 새로 쓰며, 루트가 그 사본을 가리키게 바꾸지 않는다. 원본 교체는 사용자가 한다.
3. **반영 기준 갱신:** 적용이 확인된 대응만 반영 기준을 새로 기록한다. 되돌리면 그 실행의 대응은 이전 기준으로 돌아간다.
4. 반영은 파일을 저장하지 않는다(열린 도면). 원천 Rhino 문서는 바꾸지 않는다.

## 11. 손 수정과 충돌 — SPEC-14.12

- 반영 기준 이후 도면에서 사람이 고친 개체는 '충돌'(원천도 바뀐 경우) 또는 '변경 없음'(원천은 그대로)이다. 사람이 고친 값을 원천으로 조용히 덮지 않는다.
- 사람이 지운 개체는 '끊김'이며 다시 만들지 않는다.
- 사람이 도면에 더한 개체(치수·문자·해치 등)는 대응이 없으므로 반영 대상이 아니며 그대로 남는다.

## 12. 지원하지 않는 것과 실패 — SPEC-14.13

**지원하지 않는 것**(행·보고에 이유를 보이고 성공으로 세지 않는다, AC-27):

- 3D 객체의 투영 갱신(평·입·단면의 숨은선·단면 채움). 1차에는 생성도 하지 않는다(SPEC-14.4의 1).
- 해치 경계의 재연동, 문자 내용의 변경, 주석 축척, 레이아웃·뷰포트·용지의 변경, 도곽 속성의 역반영.
- 동적 블록 매개변수, 블록 정의 내부 개체의 개별 수정, 프록시·OLE·래스터 개체.
- mm가 아닌 도면, ZWCAD 외의 CAD(AutoCAD·Revit), DWG 2018보다 새 형식의 출력.
- xref 삽입 이동(SPEC-14.9의 2), 다른 프로젝트 도면.

**실패 규칙:**

1. 숨은 호스트가 없거나(ZWCAD 2023·Rhino 8) 시작·응답에 실패하면 그 단계만 실패로 보이고 원천·템플릿·기존 도면은 그대로다. 숨은 호스트는 그 실행에서 끈다.
2. 내보내기·정리·병합 가운데 한 단계라도 실패하면 출력 사본을 저장할 수 없고, 실패한 단계와 이유를 보인다. 부분 출력을 완성본처럼 저장하지 않는다.
3. 열린 도면 적용 결과가 불명확하면 다시 적용하지 않고 도면을 다시 읽어 어느 행이 적용됐는지 보인다(AC-17·33).
4. 차이 계산 뒤 원천 문서가 바뀌었으면 [반영]을 막고 다시 계산하게 한다.
5. 실패와 못 고친 항목은 오류 기록과 보존 보고에 남는다.

## 13. 권한과 AI 경계 — SPEC-14.14

1. 파일 저장·내보내기·xref 부착은 **엔진의 생성기·반영 경로만** 하며 그 경로는 엔진이 정한 출력 위치(작업 폴더, 사용자가 확인한 출력 경로)에만 쓴다. AI가 작성한 코드의 저장·다른 이름 저장·내보내기·xref 부착 금지는 그대로다(H-RHINO-08, H-ZWCAD 정책).
2. 대화 요청이 도면 생성·역반영을 원하면 AI는 생성기·반영 화면을 열고 설정값(시트·템플릿)을 제안할 수 있다. 미리보기·저장·반영은 사용자가 누른다.
3. 템플릿·출력 도면은 프로젝트 자료이며, AI 전송과 웹 공개는 기존 권한(FR-18, AC-30)을 따른다. 생성기가 템플릿·도면 내용을 외부로 보내지 않는다.
4. 사용자의 Rhino·ZWCAD 창으로 원본을 열지 않는다. 숨은 호스트는 사본만 연다.
