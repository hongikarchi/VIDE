# 확장·AI 설정·설치·복구


## 설치한 IDE에서 AI와 확장을 작업에 사용한다 — SPEC-05.7

근거: PRD §8.1·§12.3·§14.4, FR-08·13·15·16·17·18. **사용자는 개발 도구를 조작하지 않고 VIDE를 시작해 자신의 호스트·AI를 연결하고, 추가 기능도 같은 프로젝트 안에서 사용한다.**

설치 후 IDE를 열면 VIDE 계정에 로그인한 뒤 프로젝트를 고르거나 만들고(§6 「첫 실행」), 설치된 지원 호스트의 연결 상태를 확인한다. AI 설정에서는 Claude Code 또는 Codex CLI 경로와 공식 로그인 상태를 확인하고 공급자를 선택한다. 정상 설정 뒤 같은 공간 입력으로 설계 요청을 실행한다. 공급자를 바꿔도 작업 목표·핀·스케치·이전 결과를 다시 만들 필요가 없다. 새 실행에 적용되는 공급자를 알 수 있고, 실패하면 입력을 유지한 채 설정을 교정한다(§2·5).

신뢰된 확장은 이름·목적·필요 입력과 권한을 확인한 뒤 등록한다. 첫 검토안인 ‘지원 객체 속성 요약’을 선택 객체에 실행하면 같은 작업 기록에 실제 표와 근거가 생기고 대상을 찾아갈 수 있다. 실패는 해당 작업 결과로 남으며 비활성화 뒤 새 실행 목록에서 사용할 수 없다(§1·4). 이 샘플은 확장이 공통 문맥·진행·결과를 재사용함을 검증하는 것이며, 플랫폼 전체 기능을 속성 요약으로 축소하지 않는다.

앱을 종료하고 다시 열면 프로젝트와 저장된 작업을 이어서 확인한다. AI 미연결 상태에서도 저장된 모델 표현·입력·의견·결과 열람과 가능한 로컬 입력은 유지한다. 제거는 앱과 사용자 기록을 구분한다(§3·6).

**완료 기준:** 별도 사용자 환경에서 설치→프로젝트/호스트 연결→AI 작업→종료/재개가 가능하고, 실제 확장 등록→실행→실패 확인→비활성화가 공통 화면과 데이터로 이어져야 한다(AC-23·26·27). 설정 화면이나 manifest만으로 완료하지 않는다.

## 1. 신뢰된 확장 — SPEC-05.1

근거: FR-13·18. 확장은 목적, 입력, 결과 유형, 필요한 호스트·도구·권한, 진행·개입 지원 범위를 선언한다. 허용 목록의 작은 확장을 실제 등록·실행·실패·비활성화한다. 비활성화 후 새 실행을 막고 이미 시작한 실행은 개입 계약에 따라 처리한다. 선언 범위를 벗어난 입력·도구 사용을 거절한다. 실패해도 입력·이전 결과는 보존한다. 임의 업로드 코드 실행은 지원 선언에 포함하지 않는다. 구체적인 첫 확장은 OQ-07에 연결해 검증한다.

## 1.1 JIG 탭과 Sync jig — SPEC-05.8

근거: FR-13·18·24. jig의 정의·수명 단계·작업본·입력 조립·실행 위치·점검·Rhino에 만들기·가져오기·채팅 제작은 [SPEC-07](SPEC-07-jig-platform.md)이 정한다. JIG 탭은 공식 jig 목록(사용 가능/준비 중, 필요한 입력, 과거 작업 출처)과 이 프로젝트의 jig·제작 중인 초안(SPEC-07.3)을 보여 주고 사용 가능한 jig를 연다. 연 jig는 3D를 보면서 쓰고, 다른 화면으로 옮겨도 작업본 상태를 잃지 않는다(배치는 Design). 개발용 확장의 화면 입구는 두지 않는다(2026-09-29 사용자 결정: JIG가 그 역할을 이어받아 지금 쓸 일이 없다). 확장 등록·실행의 서버 계약과 이미 실행된 확장 결과의 표시는 유지한다. jig 가져오기는 SPEC-07.15를 따른다.

**Sync jig(도면↔모델):** 같은 프로젝트의 Rhino Sync 하나와 ZWCAD Sync 하나를 입력으로 받는다.

1. **계산(항상 같은 결과):** 두 문서의 위치 관계(XY 이동·회전·높이 차)를 직선 요소의 대응으로 구하고 잔차(최대·RMS)와 대응 수를 보인다. 같은 간격이 반복돼 관계가 하나로 정해지지 않으면 그 사실과 후보를 보이고 사용자가 후보·기준 레이어·기준 쌍으로 정한다. 관계를 적용한 뒤 객체마다 일치/오차/Rhino에만/CAD에만으로 나눈 행(R1…)과 레이어 대응을 만든다. 일치 허용·탐색 반경·대상 레이어는 사용자가 정한다.
2. **AI 검토(의미 판정):** 계산 표만 첨부해 호스트·문서 문맥 없이 보낸다. AI는 오차·한쪽에만 있는 행이 실제 불일치인지 의도된 표현인지와 고칠 쪽을 행 번호와 표의 수치로만 답한다. 표에 없는 행 번호를 인용하면 답 끝에 경고를 붙여 근거 없는 내용임을 알린다(ref-whitelist). [AI 검토]는 작성기의 요청과 같다(2026-10-15, T-299): 지금 고른 대화로 보내고 그 대화에 진행 행을 보이며, 결과도 그 대화에 남는다(모델이 달라 새 대화로 이어지면 그 대화를 고른다, SPEC-02.19의 5). 대화로 보내도 보내는 내용은 계산 표뿐이며, 그 대화의 원장·세션·이전 교환은 붙이지 않는다(2026-10-15 검토). 요청이 대기·진행 중인 동안 버튼은 '검토 중…'으로 바뀌어 누를 수 없는 모양이 되고, 그래도 누르거나 jig를 다시 열어 누르면 새 요청을 만들지 않고 진행 중인 요청을 대화에서 보여 준다. 요청이 끝나면 버튼이 돌아온다.
3. **반영(사용자가 고른 행만):** "CAD를 Rhino에 맞춤"은 도면 역반영의 적용 경로(SPEC-14.11의 1)로 열린 도면을 바로 고친다: 오차·일치 행의 도면 개체는 그 자리에서 Rhino 객체의 모양(선·호가 있는 폴리선·호·원, 블록은 위치·회전)을 따르고 종류·레이어·Handle은 유지되며, Rhino에만 있는 객체는 대응한 도면 레이어(도면에 있는 것만)에 추가하고, CAD에만 있는 개체는 지운다. 실행 하나가 되돌리기 기록 하나이고, 종류가 다르거나 자유 곡선이거나 레이어가 없는 행은 이유와 함께 반영하지 않으며, 짝은 반영 기준으로 남는다(SPEC-14.10). "Rhino를 CAD에 맞춤"은 모델 좌표로 역변환한 목록을 열린 Rhino 문서 수정 요청으로 보낸다. 목록에 없는 객체는 바꾸지 않는다.

행을 누르면 해당 Sync의 객체를 뷰포트에서 선택해 보여 준다. 두 Sync 중 하나가 없거나 성공 결과가 아니면 실행하지 않는다.

**입력 Sync 고르기(2026-10-15, T-302):** Rhino Sync·ZWCAD Sync 칸도 열린 연결 기준(SPEC-07.5의 7)을 따른다. 기본값은 그 호스트의 열린 연결의 최신 Sync이고, 닫힌 연결의 Sync는 구분선 뒤에 '(닫힘)'을 붙여 나열하며 사람이 고를 때만 쓴다. 그 호스트에 열린 연결이 있는데 아직 Sync가 없으면 아무것도 고르지 않고 '이 CAD 연결에는 아직 Sync가 없습니다 — 동기화를 기다리거나 닫힌 Sync를 고르세요'(Rhino 칸은 'Rhino 연결')를 보이며, 그 연결에 Sync가 생기면 사람이 고르지 않은 칸은 그 Sync를 고른다. 열린 연결이 하나도 없으면 닫힌 연결의 최신 Sync를 기본으로 고르고, 닫힌 Sync가 골라진 칸에는 '닫힌 연결 기준'을 보인다.

입력은 각 Sync에 저장된 최신 객체(Live Sync가 고친 내용 포함)다. 비교하는 직선 요소는 Rhino의 선·폴리선 곡선과 CAD의 선분으로 된 개체, 그리고 Rhino 솔리드의 평면 단면 외곽선이다(2026-10-14 사용자 결정, T-283). Rhino의 면·블록 참조·점·문자는 비교하지 않는다.

- **솔리드 단면(평면 단면 비교):** Rhino 솔리드(Brep·Extrusion·메시)는 기준 높이의 수평면으로 자른 단면 외곽선의 곧은 변 하나하나가 비교 요소다. 곡면 외곽은 곧은 조각으로 나뉘어 비교된다. 기준 높이는 층 레벨이 있으면 층마다 '층 바닥 레벨 + 1.2 m'이고, 없으면 솔리드들의 높이 범위 가운데다. 층 레벨은 레이어 경로나 이름에 'LEVEL' 또는 '레벨'이 들어간 Rhino 점의 높이다. 사람이 jig에서 높이를 정하면 그 높이 하나로 자른다. 기준 높이에 걸치지 않는 솔리드(예: 1.2 m 위의 보)는 그 높이에서 비교 요소가 없다.
- **규칙 표시:** jig는 쪽마다 비교 요소가 어떤 규칙에서 나왔는지(Rhino: 선·폴리선 수와 솔리드 단면 수·쓴 높이와 그 출처 — 층 레벨/높이 범위 가운데/사람이 정함; CAD: 선분 개체 수)를 보이고, 표의 행마다 단면에서 나온 Rhino 요소에 그 높이를 붙인다.
- **단면 행의 반영:** 단면 요소는 솔리드의 일부라 행을 골라도 "CAD를 Rhino에 맞춤"·"Rhino를 CAD에 맞춤" 목록에 넣지 않고, 뺀 행 수를 알린다. 단면 행은 비교·AI 검토에만 쓴다.

한쪽의 비교 요소가 0개이면 0만 보이지 않고 이유를 보인다(2026-10-14, T-283): 저장된 객체가 없으면 그 Sync를 읽지 못했다는 것과 다시 Sync할 것을, 객체는 있지만 비교 요소가 없으면 그 사실(선·폴리선이 없고 기준 높이에 걸친 솔리드도 없음)과 읽은 객체 수·종류별 개수를, 고른 레이어에만 없으면 그 사실을 보인다.

## 1.2 갱신 제안 카드(C-12) — SPEC-05.12

근거: PRD §4.4 [C-12](../PRD.md)와 같은 절의 비목표(요청 없는 호스트 간 원본 자동 동기화), FR-03·12·18, [PLAN-54](../plans/PLAN-54-outputs-accounts-proposals.md) 3부(2026-10-15 사용자 결정). 사람이 지정한 파일 쌍의 한쪽이 바뀌면 VIDE가 "맞출까요?" 카드를 띄우고, 사람이 누를 때만 맞춘다. 이 항에서 'Sync jig의 n'은 SPEC-05.8의 Sync jig 목록 n을 가리킨다. 호스트 안 표시와 그 지움은 [SPEC-14.16](SPEC-14-drawing-generator.md), 카드가 뜨는 자리·여러 카드를 묶는 표현·안내 문구는 Design §07, 쌍과 카드 상태의 저장 형식은 ARCH-01이 소유한다.

1. **대상:** 사람이 지정한 **동기화 쌍**(SPEC-01.13의 11)만. 지정한 쌍이 없으면 어떤 카드도 뜨지 않는다. 쌍에는 Sync jig로 확정한 위치 관계(Sync jig의 1)가 있어야 한다. 쌍을 지정할 때 두 최신 Sync로 계산한 위치 관계가 하나로 정해지면 그것을 확정 관계로 두고, 정해지지 않으면 '위치 관계 없음'으로 둔다. 확정 관계가 없으면 감지하지 않고 쌍에 '위치 관계 없음'을 보이며 Sync jig로 안내한다.
2. **감지 조건:** 쌍의 한쪽이 Live Sync 변경(SPEC-01.11의 2) 또는 Sync로 바뀐 뒤(저장 감지는 호스트 지원표가 저장 알림을 확인한 뒤) 다른 쪽이 그대로일 때, 그 쌍의 두 최신 Sync로 Sync jig의 1(계산)을 다시 돌린다. 오차·한쪽에만 행이 하나 이상이면 카드를 띄우고, 없으면 띄우지 않는다. 바뀐 쪽이 기준, 그대로인 쪽이 맞출 쪽이다. 두 쪽이 모두 바뀌었으면 고칠 쪽을 정할 수 없으므로 카드를 띄우지 않고 쌍에 '양쪽 변경'을 보이며 Sync jig로 안내한다. 감지는 호스트·문서를 바꾸지 않으며 AI를 부르지 않는다.
3. **카드 내용:** 쌍의 두 파일, 바뀐 쪽과 시각, **어긋남 목록**(Sync jig의 1의 행 형식을 그대로 쓴다: 행 번호·분류·바뀌는 값), 맞출 수 없는 행과 이유(SPEC-14.10의 1 '지원 안 함'·'충돌'·'끊김', SPEC-14.13)(이유 일부는 [적용] 뒤에 보일 수 있다), 그리고 **[적용]·[무시]·[나중에]**. 행을 누르면 Sync jig의 행 누르기와 같이 객체를 보인다. 카드가 떠 있는 동안 호스트 안과 VIDE 뷰포트에 같은 어긋남을 그린다(SPEC-14.16).
4. **카드 수명과 중복 억제:** 한 쌍의 카드는 하나다. 같은 쌍에 새 변경이 오면 새 카드를 만들지 않고 그 카드의 목록을 다시 계산해 갱신하며, 어긋남 집합이 같으면 시각만 바꾼다. 여러 쌍의 카드가 쌓이면 하나로 묶어 보이고 펼치면 쌍별로 보인다. **[나중에]**는 카드를 접고 표시를 지우며 그 쌍의 다음 변경까지 다시 띄우지 않는다. **[무시]**는 그때의 어긋남 집합을 무시로 기억해 같은 집합이면 다시 띄우지 않고, 새 어긋남이 더해지면 다시 띄운다. 사람이 호스트에서 직접 맞춰 어긋남이 0이 되면 카드는 스스로 닫힌다.
5. **닫힌 연결:** 쌍의 한쪽이라도 연결이 닫혀 있으면(SPEC-01.11의 7) 카드를 띄우지 않는다. 그 연결이 다시 열릴 때 한 번 2를 확인해 어긋남이 있으면 띄운다. 닫힌 동안의 변경을 하나씩 쫓아 여러 카드를 만들지 않는다.
6. **적용(사람이 누를 때만):** [적용]은 카드에서 고른 행(기본 선택은 SPEC-14.10의 3)을 맞춘다. 모델이 바뀐 쌍은 도면 역반영 경로(SPEC-14.8의 대응, SPEC-14.10의 행, SPEC-14.11의 1 열린 연결 도면의 바로 실행)로 맞춘다. 도면이 바뀐 쌍은 Sync jig의 3 "Rhino를 CAD에 맞춤"과 같이 열린 Rhino 문서 수정 요청 하나로 보내며, 그 요청은 요청 실행(SPEC-02.13)의 바로 실행·되돌리기를 따른다(이 방향을 둘지는 PLAN-54 「결정이 필요한 질문」). 실행 하나가 되돌리기 기록 하나이며 되돌리기는 PRD §11.2를 따른다. 적용 직전에 다시 계산해 카드의 목록과 다르면 적용하지 않고 갱신한 목록을 보인다(SPEC-14.13 실패 4와 같음). 감지·카드·표시는 적용을 하지 않으며, 대화의 AI는 [적용]을 대신 누르지 못하고 카드를 가리키는 안내만 한다(FR-18, SPEC-14.14의 2).
7. **기록:** [적용]·[무시]가 기록 후보가 되는지와 그 유형·본문은 SPEC-17.3의 1의 표가 정한다. [나중에]는 후보 대상이 아니다.
8. **실패:** 카드에 이유를 보이고 카드는 남긴다. ① 한쪽 연결 없음 — 5와 같이 띄우지 않거나, 카드가 떠 있던 중이면 [적용]을 끄고 '연결이 닫혔습니다'(이유 일부는 [적용] 뒤에 보일 수 있다). ② 역반영 불가 — 그 행은 이유와 함께 적용 대상에서 빼며, 모든 행이 불가면 [적용]을 끈다(이유 일부는 [적용] 뒤에 보일 수 있다). ③ 호스트 바쁨(그 문서에 실행 중인 요청이 있거나 호스트가 명령 중) — 적용을 대기열에 넣지 않고 '프로그램이 바쁩니다 — 끝나면 다시 누르세요'. ④ 계산 실패 — 카드를 띄우지 않고 쌍에 오류를 보인다. ⑤ 호스트 표시 실패 — 카드는 VIDE 화면에만 보이고 SPEC-14.16의 8을 따른다. 적용 결과가 불명확하면 다시 적용하지 않는다(SPEC-14.13 실패 3).
9. **원격 세션:** 원격 화면(SPEC-04)은 카드·목록·VIDE 뷰포트 표시를 보기만 한다. [적용]·[무시]·[나중에]는 없고 작업 PC 화면으로 안내한다.

**수용 결과:** 파일 지도에서 `A.3dm` ↔ `A-평면.dwg`를 동기화 쌍으로 지정하고 Rhino에서 기둥 하나를 500 mm 옮기면, 편집이 멈춘 뒤 '모델이 바뀌었어요. 도면도 맞출까요?' 카드 하나에 그 기둥의 오차 행이 보이고 ZWCAD 도면에는 `VIDE_제안` 레이어의 rev cloud와 "+500"이 보인다. 더 옮기면 같은 카드가 갱신되고, [무시]하면 표시가 지워지며 같은 어긋남으로는 다시 뜨지 않고, [적용]하면 도면 개체가 그 자리에서 고쳐지고 Ctrl+Z 한 번에 돌아가며 기록 후보에 D 한 건이 생긴다. 쌍으로 지정하지 않은 파일이나 연결이 닫힌 쌍에는 카드가 없다.

## 2. 공급자와 실행 설정 — SPEC-05.2

근거: FR-15·18. 공급자 어댑터는 인증 상태, 지원 기능, 요청, 진행, 종료와 오류를 공통 의미로 반환한다. Claude 구독의 Claude Code와 ChatGPT 구독의 Codex CLI를 명시적으로 선택할 수 있는 경로로 구현한다. 실행마다 선택 공급자를 고정하고 한도·인증·연결 실패 시 다른 공급자나 API 과금 경로로 자동 전환하지 않는다. 인증은 사용자가 설치한 공식 도구의 로그인 절차에 맡기며 VIDE가 구독 토큰을 추출하지 않는다. 공급자 교체가 호스트 쓰기 권한을 바꾸지 않는다. 구독 포함 사용량의 잔여치를 알 수 없으면 미확인으로 표시하고 API 가격 추정치를 구독 잔량으로 환산하지 않는다.

### 2.1 입력 시 모델·effort·모드

각 제출은 공급자·모델·effort·모드(계획·자동)와 입력 버전을 함께 고정한다. 모델 목록과 effort는 실제 공급자의 확인된 능력을 사용하고, 미연결 예시 목록을 계정에서 사용 가능한 모델로 표시하지 않는다. 모델 변경은 입력·핀·스케치를 지우지 않으며 지원하지 않는 effort는 표시된 기본값으로 변경한다. 변경된 설정은 다음 요청에 적용하고 이전 요청의 기록을 바꾸지 않는다.

모드는 VIDE의 위임 범위다(SPEC-02.20, [ADR-022](../decisions/ADR-022-direct-apply-plan-auto.md)). ‘계획’은 조회·분석·설명과 계획 카드까지이며 호스트 문서를 쓰지 않는다. ‘자동’은 지정 대상/조건 안에서 열린 문서를 바로 고치고 실행마다 되돌리기 기록을 남기며, 되돌리기로 쉽게 고칠 수 없는 동작은 확인 카드를 거친다(SPEC-02.13). 이전 권한 값(검토·후보·적용)으로 저장된 요청은 검토 → 계획, 후보·적용 → 자동으로 읽는다. CLI의 도구 권한이나 OS 권한을 직접 확장하는 설정으로 연결하지 않는다. 모델/effort 변경도 전송·쓰기 범위를 확대하지 않는다.

## 3. 설치와 복구 — SPEC-05.3

근거: FR-16·17. 실행 파일과 사용자 데이터 위치를 구분한다. 설치·업데이트·제거 과정에서 사용자 데이터를 자동 삭제하지 않는다. 동일 프로젝트의 제어 주체는 하나이며 두 번째 로컬 프로세스가 동시에 제어권을 획득하지 못한다. 재시작 시 저장된 입력과 결과를 복원하되 진행 중이던 쓰기는 결과 확인 전 재전송하지 않는다. 개발 도구가 없는 별도 Windows 환경에서 설치·실행·재시작·제거를 확인해야 배포 검수를 통과한다.

## 4. 확장 실행 계약 상세 — SPEC-05.4

근거: FR-13·18. 검토안은 개발자 제공 ‘지원 객체 속성 요약’ 확장 하나다(OQ-07). 선택된 취득 기준과 객체 참조를 읽어 유형·레이어별 개수와 근거를 반환한다. 전문 일람표 자동화나 원본 쓰기를 이 확장의 기본 권한으로 포함하지 않는다.

선언은 고유 이름·버전·지원 계약 버전·필요 읽기/쓰기 능력·입력/결과 형식·진행/중단 지원을 포함한다. 등록 시 형식과 허용 목록을 검사한다. 실행 시 현재 활성 여부·프로젝트·입력 버전·요청 능력을 다시 검사한다. 결과는 공통 출처·상태 계약으로 검증하고 알 수 없는 출력은 실패로 격리한다. 비활성화는 새 호출을 막고 진행 중 실행에는 중단 요청과 실제 종료 결과를 구분한다.

신뢰된 개발자 코드를 등록한다는 선택은 임의 코드의 보안 격리 보증이 아니다. 실행 모듈은 공통 서비스로 데이터를 받고 공통 권한 검사를 우회하는 접점을 제공하지 않는다. 신뢰하지 않는 사용자 업로드 코드는 등록 대상이 아니다.

## 5. AI 연결과 실행 복구 상세 — SPEC-05.5

근거: FR-08·15·16·18. 설정은 공급자·설치 경로·공식 로그인 확인·선택 모델·기능 확인 결과를 구분한다. 설치되지 않음, 로그인 필요, 계정 방식 불일치, 제한된 실행 기능, 정상 응답 가능을 구분하며 실행 오류에서 계정 정보를 노출하지 않는다.

프로젝트별 기본 공급자를 지정할 수 있고 실행 시작 때 실제 선택을 보여 준다. 진행 중 설정을 바꿔도 기존 실행의 공급자는 바뀌지 않는다. 한도 초과·네트워크 오류는 해당 실행의 중지 사유로 남기고 저장된 입력과 실행 결과를 유지한다. 재개는 조건·실제 결과·미결 명령을 확인한 새 실행이며 공급자 대화 이력을 유일한 복구 근거로 삼지 않는다.

## 6. 설치·마이그레이션의 관찰 결과 — SPEC-05.6

근거: FR-16·17. 최초 실행은 데이터 위치, 연결 가능한 설치 호스트, AI 설치/인증 상태를 표시한다. AI 미설정은 로컬 기록 사용을 막지 않는다. 호스트 미지원은 지원되는 기록/다른 연결의 사용을 막지 않는다.

### 첫 실행 — 로그인과 프로젝트 고르기

근거: PRD §8.1, [ADR-039](../decisions/ADR-039-sign-in-first-run.md). 2026-10-06 사용자 결정: "처음에 딱 깔면, 로그인 화면이 나와야 하는거 아닌가? 왜 바로 새 프로젝트가 만들어지고 시작하는거지?" → 로그인 필수.

1. **로그인 화면:** 설치한 VIDE가 VIDE 계정(사이트 아이디)에 연결되지 않은 PC에서 열리면 작업 화면 대신 로그인 화면을 보인다. 아이디·비밀번호·PC 이름, 가입 안내(사이트에서 가입 코드로 만들기)와 사이트 링크를 둔다. 로그인 전에는 작업 화면·프로젝트를 열지 않는다. 비밀번호는 로그인 한 번에만 쓰고 저장하지 않는다(SPEC-04.8).
2. **AI 연결 상태 한 줄:** 같은 화면에 Claude Code·Codex CLI마다 '설치 안 됨' / '로그인 필요' / 로그인된 계정을 한 줄로 보인다. AccountSwitch가 설치돼 있으면 [AccountSwitch 열기], 없으면 설치 링크를 둔다. AI 미연결은 로그인·프로젝트 고르기를 막지 않는다.
3. **실패:** 아이디·비밀번호가 틀리면 그 사실을, 사이트에 닿지 않으면 '웹사이트에 연결하지 못했습니다. 인터넷 연결을 확인하고 다시 시도하세요.'를 보이고 입력을 지우지 않는다(비밀번호 제외). 다시 [로그인]을 누르면 다시 시도한다.
4. **프로젝트 고르기·만들기:** 로그인 뒤 이 PC의 프로젝트와 공유받은 프로젝트(SPEC-04.11 1)를 보이고, 고르면 그 프로젝트로 연다(공유받은 프로젝트는 원격 프로젝트, SPEC-04.11 3). 이름을 넣어 [만들기]를 누를 때만 새 프로젝트를 만든다. 프로젝트가 없다고 묻지 않고 만들지 않는다.
5. **이미 로그인한 PC:** 로그인 정보가 남아 있는 PC는 사이트에 닿지 않아도 기존처럼 바로 작업 화면을 연다. 프로젝트가 하나도 없으면 4의 고르기·만들기를 보인다.
6. **로그인과 원격 접속:** 로그인은 원격 접속(다른 기기에서 열기)을 켜지 않는다. 원격 접속은 계정 창(SPEC-05.10)에서 사용자가 켤 때만 켜지며, 꺼져 있는 동안 원격 접속 도구의 오류를 보이지 않는다.
7. **원격 접속 도구 준비:** 원격 접속에 필요한 공식 도구(cloudflared)는 설치본에 넣지 않는다. 설치 뒤 첫 실행 때 엔진이 배경에서 받아 확인값을 검사해 두고, 이미 있으면 건너뛴다. 받지 못해도 알리지 않으며, 원격 접속을 켤 때 없으면 그때 받는다(받는 동안 '켜는 중'). 받기·확인에 실패하면 이유와 해결 방법(인터넷 확인 뒤 다시 켜기)을 보인다.
8. 개발 서버와 자동 시험의 엔진은 1~5의 확인과 7의 미리 받기를 끄고 연다. 이때 프로젝트가 없으면 이전처럼 '새 프로젝트'를 만들어 연다.

데이터 버전 변경 전 백업과 무결성을 확인하고 실패하면 기존 데이터를 열어 덮어쓰지 않는다. 앱 버전 되돌리기가 최신 DB의 역호환을 보증하지 않으므로 호환 가능한 백업 복구 경로를 안내한다. 두 번째 제어 프로세스는 쓰기 권한을 얻지 못하고 기존 실행 안내를 제공한다. 단일 PC 제어 잠금은 공유 폴더의 여러 PC 동시 제어 지원을 뜻하지 않는다.

AC-23·27: 개발 도구 없는 PC에서 설치→미지원/미설정 확인→지원 호스트 연결→입력 보존→재시작→제거 후 자료 보존을 검수한다. AC-26: 확장 등록→정상 실행→잘못된 입력/권한 거절→실행 실패→비활성화 후 새 실행 거절을 각각 확인한다. AC-30·37: 다른 공급자 자동 전송·웹 실행·두 제어자의 동시 쓰기를 거절한다.

### 연결 표시와 모델 능력 확인
근거: FR-08·15·16, SPEC-05.2. 로컬 인증 만료/연결 실패는 공급자 로그인 및 호스트 실행 준비와 구별한다. 인증 실패 시 입력을 보존하고 실행 링크를 통한 재연결을 안내하며 쓰기를 자동 재전송하지 않는다. 호스트 실행 준비는 열린 문서에 연결됐다는 뜻이 아니다.
모델별 effort는 설치 CLI의 능력 자료와 공식 모델 지원표로 확인된 값만 노출한다. 알 수 없는 조합은 공급자 기본값만 제공한다. 캐시 목록에 있다는 사실을 현재 계정의 실제 실행 성공으로 표시하지 않는다. 슬라이더는 지원 단계만 이동하며 기본값과 현재 단계를 이름으로 표시한다.

### 작업 공간 상태와 설정 진입

근거: FR-08·15·16. 공급자 로그인 확인, 호스트 실행 준비, 로컬 서버 인증·연결, 작업 실패는 서로 다른 상태로 제공한다. 상태 상세에서 해당 설정과 최근 실패 원인을 확인할 수 있다. 실패 기록을 확인했다고 실제 실패가 해결된 것으로 바꾸지 않는다. 설정을 열고 닫아도 입력·첨부·현재 선택을 유지한다. 계정 잔여량이나 호스트 문서 연결을 설치 여부만으로 추정하지 않는다.

## 7. 오류·성능 정보 보내기(동의한 설치만) — SPEC-05.9

근거: FR-16·18, [ADR-036](../decisions/ADR-036-opt-in-telemetry.md)(2026-10-06 사용자 결정 "설치할 때 동의하면 가능하도록"). 화면 표현은 Design SCR-22, 물리 계약은 ARCH-01 §6 「오류·성능 보고」.

1. **동의 전·거부 뒤에는 보내지 않는다.** PC 프로그램의 첫 실행(기존 설치는 이 기능이 들어간 갱신 뒤 첫 실행)에 한 번 묻는다. 답은 [동의]·[보내지 않음] 둘뿐이며, 창을 닫아 답하지 않으면 다음 실행에 다시 묻고 그동안 보내지 않는다. 설정 › 상태 · 오류의 스위치로 언제든 바꾼다. 원격 접속·호스트 패널 화면은 묻지 않고 선택을 바꾸지 못한다.
2. **보내는 것은 이름 없는 요약이다.** 동의한 시각 이후의 진단 기록(T-126)에서 버전·시스템 크기·무작위 설치 번호·이벤트 수·실패(코드·경로 패턴·정리한 문장·VIDE 소스 위치만 남긴 스택)·비정상 엔진 종료·시간·메모리 수치만 담는다. 이벤트별 허용 필드 밖의 값, 요청·프로젝트·연결·대화 ID, 요청 글·AI 답·파일/프로젝트/레이어/객체 이름·내용·경로·사용자 이름·PC 이름·계정·키·DB·첨부·덤프는 담지 않는다. 사용자는 [보낼 내용 보기]로 다음 요약을 그대로 볼 수 있다.
3. **언제·얼마나.** 시작할 때(지난 요약 뒤 1시간 이상)와 하루 한 번 하나를 만들고, 32 KB를 넘으면 자세한 항목부터 줄여 줄였다는 표시를 붙인다. 보내지 못한 요약은 PC에 최근 14개까지 두고 다음 기회에 오래된 것부터 보낸다. 거부로 바꾸면 남은 요약을 지운다. 보내기 실패는 작업을 막지 않으며 설정에 마지막 전송 시각과 실패를 보인다.
4. **큰 자료는 물어본 뒤에만.** VIDE가 요청하지 않은 작업 엔진 종료가 기록되면, 동의 질문에 답한 뒤의 화면에서 그 종료마다 한 번 "진단 묶음을 보낼까요?"를 묻고 묶음에 들어가는 것을 보인다. [보내지 않음]이면 아무것도 보내지 않고 다시 묻지 않는다. [보내기]이면 최근 3일 진단 묶음을 만들어 보내며, 크래시 덤프는 사용자가 따로 고를 때만 최신 하나를 넣는다. 사이트의 묶음 한도를 넘는 덤프는 고를 수 없고 보내지 않으며, 이 PC에서 만드는 [진단 묶음 내보내기]에는 최신 덤프 하나를 크기와 함께 묻고 기본으로 넣는다(T-191). 사이트가 묶음을 받지 않는 동안(R2 정리 전 기본값)은 보내지 않았다고 알리고 이 PC에 만든 묶음 파일의 경로를 보인다.
5. **사이트.** 사이트는 형식·크기·한도(설치당·주소당 하루 건수)를 지키지 않거나 경로·사용자 폴더·이메일이 남은 요약을 저장하지 않는다. 받은 요약은 사이트 관리자만 날짜·버전·종류로 보고 CSV로 내려받으며 180일 뒤 지운다.

수용 확인: 동의 전·거부 뒤 전송 0건, 동의 뒤 요약에 동의 이전 줄 없음, 한글 이름·UNC 경로·사용자 폴더·따옴표 안 글자가 요약에 남지 않음, 연결 실패 뒤 다음 기회에 전송, 충돌 질문 한 번·[보내기]일 때만 묶음 전송, 관리자 외 보고 API 거절(시험 목록은 PLAN-34).

## 8. 계정 단추와 계정 창 — SPEC-05.10

근거: FR-16·18·19, [ADR-039](../decisions/ADR-039-sign-in-first-run.md), [ADR-025](../decisions/ADR-025-accounts-in-accountswitch.md), SPEC-04.8·04.11. 2026-10-08 사용자 요청: "왼쪽 아래에 계정(동그라미 안에 알파벳 있는 식으로)이 떠있고, 그거 누르면 vide 계정 관련 설정 할 수 있도록. 기존에 있는 설정에서 계정.원격 접속을 분리하는거지." **사용자는 지금 어느 VIDE 계정으로 일하는지 늘 보고, 계정과 원격 접속을 설정과 따로 한 곳에서 다룬다.**

1. **계정 단추.** 작업 화면 왼쪽 아래(레일 맨 아래)에 VIDE 계정 동그라미 하나를 둔다. 로그인한 PC는 계정 아이디의 첫 글자(대문자)를 계정마다 늘 같은 색의 동그라미에 보인다. 같은 계정은 어느 PC·사이트에서도 같은 글자·색이다. 로그인하지 않은 엔진(개발 서버)은 글자 없는 중립 사람 표식이다. 가리키면 '아이디 · PC 이름'(로그인 안 됨이면 '로그인 안 됨')을 보인다. 원격 접속이 켜져 있으면 동그라미 귀퉁이에 작은 점(켜짐 · 켜는 중 · 실패)을 둔다. 할 일의 작성자(SPEC-01.14의 12)도 같은 동그라미를 쓴다.
2. **계정 창.** 계정 단추를 누르면 그 옆에 계정 창이 뜬다(Esc·바깥 누르기로 닫힘). 내용은 지금 설정의 '계정 · 원격 접속'에 있던 것 그대로이며 동작 규칙도 같다(SPEC-04.8, §6 「첫 실행」, ADR-039).
   - **VIDE 계정:** 큰 동그라미, 아이디, PC 이름, 사이트 연결 상태(연결됨 / '웹사이트에 연결하지 못했습니다' 와 마지막으로 닿은 시각 / '웹사이트에서 이 PC가 로그아웃됐습니다. 다시 로그인하세요.'), [웹사이트에서 모든 프로젝트 보기](새 창).
   - **원격 접속:** '다른 기기에서 열기 (원격 접속)' 스위치와 상태 한 줄(꺼짐 · 켜는 중 · 처음 받는 중 · 켜짐 · 켜기 실패와 이유). 로그인해도 기본 꺼짐이고 꺼져 있으면 도구 오류를 보이지 않는다(§6 「첫 실행」 6·7).
   - **AI 계정(보기만):** Claude Code·Codex CLI마다 '설치 안 됨' / '로그인 필요' / 로그인된 계정을 한 줄로 보이고, AccountSwitch가 있으면 [AccountSwitch 열기], 없으면 설치 링크. 계정 바꾸기는 AccountSwitch에서만 한다(ADR-025). VIDE 계정과 AI 계정이 다르다는 것을 소제목으로 나눠 보인다.
   - **[이 PC 로그아웃]:** 한 번 더 눌러 확인한다. 로그아웃하면 설치한 VIDE는 작업 화면을 닫고 첫 실행 로그인 화면(SCR-26)으로 돌아간다(로그인 필수, ADR-039 1). 이 PC의 프로젝트 자료는 지우지 않는다. 로그인 검사를 끈 엔진(개발 서버)은 작업 화면에 남고 계정 단추가 중립 표식이 된다. 다른 계정으로 바꾸려면 로그아웃 뒤 로그인한다(VIDE 계정 바꾸기 단추는 따로 두지 않는다).
   - 로그인하지 않은 엔진(개발 서버)의 계정 창은 지금 설정처럼 로그인 양식(아이디·비밀번호·PC 이름·가입 안내)을 보인다.
3. **원격 세션.** iPad 등 원격 접속으로 연 화면에도 계정 단추가 PC의 계정으로 보인다. 계정 창은 계정·사이트 링크만 보이고 원격 접속 스위치·로그아웃·로그인 양식은 감춘다('원격 접속과 로그아웃은 PC에서 합니다.'). 지금의 원격 세션 제한과 같다.
4. **설정과의 분리.** 설정 창에서 '계정 · 원격 접속' 탭을 뺀다. 설정은 AI·외부 서비스·연결 프로그램·PC 프로그램·상태 · 오류 탭으로 열리고(처음 여는 탭은 AI), 탭 목록 아래에 'VIDE 계정과 원격 접속은 왼쪽 아래 계정 단추에서 합니다.'와 [계정 열기]를 둔다(누르면 설정을 닫고 계정 창을 연다). 전에 설정의 계정 탭을 열던 안내·오류(원격 접속 실패, 이 PC 로그아웃됨 등)는 계정 창을 연다.
5. **좁은 화면·호스트 패널.** 레일이 사라지는 폭에서는 위 탭 줄의 끝에 같은 계정 줄(동그라미·아이디)을 두고 누르면 계정 창을 연다(고정 화면 메뉴는 기본 선택 목록이라 줄을 담지 못한다). 호스트 패널(SCR-12)에는 계정 단추를 두지 않는다.

**수용 결과:** 계정 kim으로 로그인한 PC의 왼쪽 아래에 'K' 동그라미가 있고, 누르면 아이디·PC 이름·사이트 연결과 원격 접속 스위치가 있는 계정 창이 뜬다. 설정 창에는 계정 탭이 없고 [계정 열기]가 계정 창을 연다. 원격 접속을 켜면 동그라미에 켜짐 점이 붙는다. [이 PC 로그아웃]을 두 번 누르면 로그인 화면이 나온다. iPad 화면의 계정 창에는 스위치와 로그아웃이 없다. 할 일 행의 작성자 동그라미가 같은 계정이면 같은 글자·색이다.

## 9. 외부 서비스 계정 — SPEC-05.11

근거: FR-18, [ADR-043](../decisions/ADR-043-user-accounts-deploy.md), [ADR-042](../decisions/ADR-042-workspace-folders.md), SPEC-13.11(cLAWde 칸의 틀), 2026-10-15 사용자 결정(GitHub·Cloudflare 둘 다 1차).

사용자가 **자기 계정**으로 쓰는 외부 서비스를 설정 → '외부 서비스'에 등록한다. VIDE 계정(ADR-039)과 별개이며, VIDE는 이 계정을 대신 소유하거나 다른 PC와 공유하지 않는다.

| 서비스 | 넣는 것(1차) | 쓰는 곳 | 하지 않는 것 |
|---|---|---|---|
| GitHub | 개인 접근 토큰(PAT) | 작업 폴더(SPEC-01.13 7)의 이력: 원격 저장소 만들기, [저장점 만들기] 뒤 푸시, 다른 PC에서 [가져오기], 상태(앞섬·뒤처짐) 보기 | 회사 서버 연결 폴더에 git 만들기(ADR-042), 충돌 풀기(멈추고 안내), 사람이 누르지 않은 푸시 |
| Cloudflare | API 토큰 + 계정 ID | 보고용 산출물(SPEC-07.11 두 등급)을 본인 계정에 비밀번호와 함께 게시, 다시 게시하면 덮음, [내리기] | 검토용 올리기, 사람이 누르지 않은 배포 |

- **저장:** 토큰은 이 PC의 비밀 저장소에 봉인하고(물리 형식은 ARCH-01 「외부 도메인 서비스」의 설정·비밀 항) 화면에는 '연결됨·안 됨·확인 실패'와 마지막 확인 시각만 보인다. 저장한 값은 다시 보이지 않는다. 진단 묶음·로그·작업 기록·공유 사이트 업로드·검수 증거에 넣지 않는다.
- **연결 확인:** [연결]은 토큰으로 서비스의 '나' 조회를 한 번 해 권한 범위를 확인하고 결과를 보인다. 범위가 모자라면 무엇이 모자란지(예: 저장소 만들기 권한 없음) 적고 저장은 한다.
- **권한 경계(FR-18):** 푸시·게시·내리기는 사람이 단추를 누를 때만 한다. 대화의 AI는 이 동작을 대신 부르지 못하고 "설정에서 [푸시]를 누르세요"로 안내만 한다. 원격 세션(SPEC-04)에서는 설정·토큰을 바꿀 수 없고 상태만 본다.
- **끊기:** [끊기]는 토큰을 지우고 그 서비스를 쓰는 단추를 끈다. 이미 올린 게시물과 원격 저장소는 그대로 두며 VIDE가 지우지 않는다. 다시 연결하면 같은 원격·같은 게시 이름을 다시 쓴다.
- **실패:** 토큰 없음(`ACCOUNT_NOT_CONNECTED`) · 권한 부족(`ACCOUNT_SCOPE`) · 원격이 이미 있음(`REMOTE_EXISTS`, 이어 쓸지 묻기) · 로컬과 원격이 다름(`REMOTE_DIVERGED`, 멈추고 git 도구 안내) · 배포 실패(`PUBLISH_FAILED`, 서비스 응답 요약) · 서비스 닿지 않음(`SERVICE_UNREACHABLE`). 실패해도 로컬 폴더·산출물은 그대로다.
- **비목표:** VIDE가 사용자 계정으로 임의로 푸시·배포하지 않는다. 조직 계정·팀 공유 토큰·OAuth device flow는 1차가 아니다(ADR-043 대안).

**수용 결과:** 설정의 '외부 서비스'에서 GitHub 토큰을 넣고 [연결]을 누르면 '연결됨 · 저장소 만들기 가능 · 방금 확인'이 보이고, 작업 폴더의 [저장점 만들기] 뒤 [푸시]를 누르면 원격이 생기며 토큰은 화면·로그·진단 묶음 어디에도 없다. Cloudflare를 연결하고 보고용 산출물에서 [게시]를 누르면 비밀번호 뒤에서 열리는 주소가 생기고 검토용은 올라가지 않는다.
