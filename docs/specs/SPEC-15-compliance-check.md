# 법규 체크

근거: 2026-10-08 사용자 요청 "지금 우리 건물 설계에서 법규 위반 사항이 없는지 체크하는 기능도 구현해줘. 이거는 cLAWde쪽에서 구축하는게 아니라, VIDE쪽에서 구현해야하는 것 같은데. geometry와 data를 비교하는 작업이라." 같은 날 사용자가 고른 것: 모델은 **레이어 규칙 + AI 분류**로 읽고(규칙에 맞지 않는 객체는 AI가 분류를 제안하고 사람이 확인), 첫 판의 검사는 **규모 항목**(건폐율·용적률·높이·층수), **형상 제한**(일조 사선·건축선 후퇴·인접 대지 이격 등 법정 외피 밖으로 나간 부분을 3D로), **주차·조경·공개공지**(법정 대비 계획), 실행은 **[법규 체크]를 누를 때만**(Sync 때 저절로 돌지 않음)이다.

이 명세는 VIDE가 **사람이 Rhino에서 모델링한 건물**(또는 손본 규모검토 매스)을 읽어 이미 정해진 규제 조건과 숫자·형상으로 비교하는 동작만 정한다. 규제 조건 항목과 그 값·근거·확정 상태는 [SPEC-12](SPEC-12-site-and-massing.md).7이, 법규 판단(적용 여부·값·완화)은 [SPEC-13](SPEC-13-legal-qa.md)과 사람이 소유하고, 가능 외피·제한선·주차 산정 규칙은 SPEC-12.8~12.12의 규칙을 그대로 쓴다. jig 공통 동작(작업본·입력 조립·설정값·단계·보고서)은 [SPEC-07](SPEC-07-jig-platform.md), 물리 계약(파일·스키마·저장)은 [ARCH-03](../architecture/ARCH-03-jig-runtime.md) §8.6, 화면은 [Design](../../Design.md) SCR-32, 구현 순서와 시험은 [PLAN-48](../plans/PLAN-48-compliance-check.md)이 소유한다.

제품 범위: 2026-10-08 사용자 결정으로 PRD §14.2의 '법규 체크' 행이다(C-05·C-06). 판단 근거는 cLAWde가 아니라 VIDE 안의 형상·자료 비교이며, cLAWde 답은 규제 조건을 거쳐서만 들어온다.

## 누르면 모델을 읽고 항목마다 근거와 함께 판정한다 — SPEC-15.1

근거: FR-24·22·10·09, C-05·C-06. **설계자는 [법규 체크]를 눌러, 지금 Rhino 모델이 규제 조건을 넘는 곳이 있는지 항목별로 본다. 숫자와 형상은 코드가 계산하고, 한계 값은 규제 조건(사람 입력 또는 법규 Q&A 결과)에서만 오며, 정할 수 없는 것은 '판단 필요'나 '사람 입력 필요'로 남긴다. AI는 모델 객체의 역할을 제안할 뿐 판정하지 않는다.**

1. **열기:** JIG 목록의 '법규 체크'를 열거나 대화에서 "법규 위반 있는지 봐 줘"라고 말한다(SPEC-07.18). 작업본은 이 프로젝트의 '건축 가능 영역·매스' 작업본(규제 조건과 외피)과 '사이트 모델링' 작업본(대지)을 앞 결과로 받는다(SPEC-12.2). 대화로 열어도 같은 화면이며, 화면 맨 위(상태 칸 위)에 이름이 붙은 [법규 체크] 버튼이 늘 보인다. 아직 체크하지 않은 빈 결과에도 같은 버튼을 둔다. 앞 매스 작업본이 없으면 체크 전에도 '규제 조건 없음 — 사람 입력 또는 건축 가능 영역·매스 계산 필요'를 보인다(2026-10-08 T-271).
2. **역할 확인:** 처음 열 때와 [법규 체크] 때 연결 Rhino 문서를 읽어, 객체마다 검사 역할(건물 매스·층 윤곽·주차 구획 등)을 속성과 레이어 규칙으로 정한다(SPEC-15.3). 규칙으로 정하지 못한 객체는 AI가 역할을 제안하고 사람이 받거나 고친다(SPEC-15.4). 확인한 분류는 프로젝트에 남아 다음 체크에 그대로 쓰인다. 문서를 아직 읽지 않아 문서 키가 없으면 분류 기록을 묻지 않고 읽기를 기다린다(대화로 열 때도 같음, 2026-10-08 T-271).
3. **체크:** [법규 체크]를 누르면 모델을 다시 읽고 SPEC-15.2의 모든 항목을 계산한다. 설정·분류·모델·규제 조건이 바뀌어도 저절로 다시 돌지 않고 '다시 체크 필요'만 보인다(SPEC-15.13).
4. **결과:** 항목마다 상태(적합 · 위반 · 판단 필요 · 사람 입력 필요 · 검사 불가), 계획 값과 한계 값, 여유, 근거 조항, 숫자마다 출처를 표로 본다. 행을 누르면 VIDE 뷰포트에서 걸린 객체를 고르고 외피 밖 부분을 색 덩어리로 겹쳐 보인다(SPEC-15.11). Rhino에는 아무것도 쓰지 않는다.
5. **내보내기:** 보고서(HTML)와 결과 표(CSV)를 낸다(SPEC-15.12).

**완료 기준(1차):** 합성 사슬(합성 대지 → 사이트 모델링 → 규제 조건 입력 → 가능 외피 → 고른 대안을 Rhino에 만들고 사람이 손으로 고친 모델)에서 [법규 체크] 한 번으로 SPEC-15.2의 모든 항목이 다섯 상태 가운데 하나와 이유·근거·숫자 출처를 갖고 나오며, 일부러 외피 밖으로 늘린 층이 '위반'과 초과 부피·위치로, 값이 비어 있는 규제 조건은 '사람 입력 필요'로, '판단 필요' 항목에 걸리는 비교는 '판단 필요'로 나와야 한다. 숨은 Rhino 8의 합성 문서에서 같은 결과를 확인한다. 화면만 있거나, 고정 예제에서만 되거나, 근거 없이 '적합'이 나오는 상태는 완료가 아니다. 결과 화면과 보고서에는 늘 "탐색용 법규 체크 — 인허가 검토·법규 검토를 대체하지 않음"을 보인다.

## 1. 검사 항목 — SPEC-15.2

근거: 2026-10-08 사용자 결정(첫 판의 세 묶음), SPEC-12.7 2의 규제 조건 항목.

검사 항목은 아래 닫힌 목록이다. 한계 값은 모두 오른쪽 열의 규제 조건 항목에서 오고, 그 항목이 비어 있으면 그 행은 '사람 입력 필요'다. 코드에는 법정 값이 없다.

| 묶음 | 검사 | 계획 값(모델) | 한계 값(규제 조건 항목) |
|---|---|---|---|
| 규모 | 건폐율 | 건축면적 ÷ 대지면적 (SPEC-15.6 2) | 건폐율 상한 `coverage` |
| 규모 | 용적률 | 용적률 산정 연면적 ÷ 대지면적 (SPEC-15.6 5) | 기준·허용·상한 용적률 `farBase`·`farAllowed`·`farMax`, 인센티브 `incentiveFar`·`openSpaceIncentiveFar` |
| 규모 | 높이(항목마다 한 행) | 기준 지반에서 건물 최고점까지 (SPEC-15.6 3) | 최고 높이 `heightMax`, 가로구역 최고 높이 `streetHeight`, 고도지구 높이 `altitudeHeight`, 높이 완화 `incentiveHeight`(적합 근거로는 쓰지 않음, SPEC-15.6 3) |
| 규모 | 층수 | 지상 층수 (SPEC-15.6 4) | 지상 층수 상한 `floorsMax` |
| 형상 제한 | 건축선 후퇴 · 가각 · 건축한계선 · 대지 안의 공지(건축선에서·인접 대지 경계선에서) · 민법상 이격 · 기타 이격 (규칙마다 한 행) | 그 규칙의 금지 띠 안에 든 건물 부분 (SPEC-15.7 2) | `roadSetback`·`chamferLength`·`limitLine`·`openSpaceRoad`·`openSpaceAdjacent`·`civilSetback`·`otherSetback` |
| 형상 제한 | 정북 일조 | 일조 사선 금지 부피 안의 건물 부분 (SPEC-15.7 3) | `sun`·`sunBaseHeight`·`sunNearDistance`·`sunRatio`·`sunDistance`·`sunDatumRoad` |
| 형상 제한 | 최대 외피 | 최대 외피 밖의 건물 부분 전체 (SPEC-15.7 4) | 위 규칙과 높이 항목 모두(SPEC-12.9의 최대 외피) |
| 형상 제한 | 대지 밖 | 대지 경계 밖의 건물 부분 (SPEC-15.7 5) | 없음(대지 경계) |
| 주차·조경·공개공지 | 주차 대수 | 모델의 주차 구획 수 (SPEC-15.8 1) | `parkingRule`·`parkingRounding`·`parkingRoundScope`·`parkingAreaBasis` |
| 주차·조경·공개공지 | 조경 면적 | 모델의 조경 영역 면적 (SPEC-15.8 2) | `landscapeRatio` |
| 주차·조경·공개공지 | 공개공지 면적 | 모델의 공개공지 영역 면적 (SPEC-15.8 3) | `publicOpenSpace`(대상 여부와 면적 비율) |

- 적용 여부가 '미적용'(확정)인 항목은 검사하지 않고 결과 아래 '미적용 항목' 목록에 근거와 함께 보인다. 적합으로 세지 않는다. 위 목록의 검사는 결과마다 **행 하나 또는 미적용 항목 하나로 꼭 한 번** 나온다. 계산하지 못한 검사를 빼서 목록을 줄이지 않는다.
- 같은 항목이 경계 구간·용도마다 다른 값을 가지면(`target`, SPEC-12.7) 구간마다 계산하고, 행의 상태는 SPEC-15.9 2의 '구간' 규칙으로 정하며, 구간별 값은 행 안에 펼친다.
- 규제 조건 항목 가운데 위 표에 없는 것(용도지역, 허용 용도·층별 용도 제한, 주차 출입 제외 거리 `parkingEntryCornerDistance` 등)은 검사하지 않는다(「이 명세 범위 밖」). 법규 Q&A 결과의 '연결 안 된 제한'(SPEC-12.14)도 규제 조건 항목이 아니므로 검사에 들어오지 않는다. 결과와 보고서에는 "검사 목록 밖의 법규는 보지 않음"을 고지와 함께 둔다.

## 2. 모델 읽기와 역할 규칙 — SPEC-15.3

근거: FR-24·03, SPEC-07.5, SPEC-01.11, ADR-030, 2026-10-08 사용자 결정 '레이어 규칙 + AI 분류'.

1. **읽는 문서:** 작업본에 고정한 연결 Rhino 문서 하나(Link ID, ADR-030)다. 기본은 규모검토 매스 작업본이 대지를 읽은 문서이고, 사람이 바꿀 수 있다. 읽기는 jig 입력 읽기(표시용 Sync와 같은 형식, SPEC-07.5의 5)이며 뷰포트·Live Sync 기준·작업 이력을 바꾸지 않는다. 읽는 때는 처음 열 때(역할 확인용)와 [법규 체크]를 누를 때뿐이다. 문서 단위는 m로 바꿔 쓴다. 단위를 알 수 없으면 읽기는 실패하지 않고 환산 비율을 '모름'으로 넘기며, 길이·면적·부피를 쓰는 모든 행(건폐율·용적률·높이·형상 제한·조경·공개공지)이 '검사 불가 · 문서 단위 모름'이다. 층수(층 이름이 있을 때)와 주차 대수의 계획 값은 계산한다.
2. **역할은 객체마다 하나다.** 검사 역할은 아래 닫힌 목록이다.

   | 역할 | 이름(화면) | 받는 모양 | 쓰는 곳 |
   |---|---|---|---|
   | `mass` | 건물 매스 | 닫힌 솔리드(폴리서피스·돌출·메쉬; 중정·관통부가 있거나 껍질이 여럿이어도 닫혀 있으면 됨) | 건축면적·높이·형상 제한 |
   | `floor` | 층 윤곽 | 수평인 닫힌 평면 곡선, 또는 한 층 높이의 닫힌 솔리드 | 연면적·층수, 매스가 없을 때 형상 제한 |
   | `building-area` | 건축면적 윤곽 | 수평인 닫힌 평면 곡선 | 건축면적(그리면 이것이 앞섬) |
   | `rooftop` | 옥탑 등 | 닫힌 솔리드 | 높이·층수 산입 여부가 법규 판단인 부분 |
   | `parking` | 주차 구획 | 닫힌 평면 곡선 또는 블록 삽입(구획 하나 = 1대, `vide-count`가 있으면 그 수) | 주차 대수 |
   | `landscape` | 조경(지상) | 수평인 닫힌 평면 곡선 | 조경 면적 |
   | `landscape-roof` | 조경(옥상 등 지상 아님) | 수평인 닫힌 평면 곡선 | 조경 면적의 산입 판단 |
   | `open-space` | 공개공지 | 수평인 닫힌 평면 곡선 | 공개공지 면적 |
   | `ignore` | 검사에서 뺌 | 무엇이든 | 아무 데도 쓰지 않음 |

3. **역할을 정하는 순서**(앞의 것이 이김):
   1. **객체 속성** `vide-check-role`(값은 위 역할 키). 같은 객체의 `vide-floor`(`1F`·`2F`…, 지하 `B1`·`B2`…), `vide-use`(용도 이름), `vide-count`(주차 대수, 1 이상 정수)도 읽는다. 이름·값 규칙은 jig 만들기 속성과 같다(ARCH-03 §9.1).
   2. **사람이 확인한 분류**(객체 단위, 다음 사람이 정한 레이어 단위) — 프로젝트에 남은 기록(SPEC-15.4 4). AI 제안을 받으면 그 제안이 가리킨 객체마다 객체 기록이 된다(SPEC-15.4 3). 예전에 AI 제안으로 받은 레이어 기록은 jig 태그(3)와 그 레이어보다 깊은 레이어 이름 규칙(4) 뒤에서만 쓴다.
   3. **jig 태그:** '건축 가능 영역·매스'는 모든 대안의 층 매스를 '대안 매스' 레이어에 겹쳐 만들고 지하 주차 추정 매스도 만든다(SPEC-12.9~12.12). 그래서 그 jig가 만든 층 매스(`vide-key`가 `alt:`로 시작하고 `vide-option`·`vide-floor`가 있는 것) 가운데 **매스 작업본에서 고른 대안의 것만** `floor`로 읽는다. 고른 대안이 없고 모델에 그런 대안이 하나뿐이면 그 대안을 읽고 '고른 대안 없음 · 모델의 대안 하나로 읽음'을 적는다. 고른 대안이 없는데 둘 이상이면 모두 '고르지 않은 대안'으로 빼고, 다른 대안의 매스도 '고르지 않은 대안'으로 뺀다(겹친 대안이 연면적에 두 번 들어가지 않게). 주차 추정 매스(`vide-key`가 `park:`로 시작)와 사이트 모델링·외피·제한선·주차·공지 곡선 등 다른 jig가 만든 객체(`vide-jig` 태그)는 주변 맥락이나 추정이므로 읽지 않는다(주변 건물이 건물 매스로 잡히지 않게). 이 규칙은 속성과 사람 기록보다 약하므로, 사람이 그 객체에 역할을 정했으면 그것을 따른다.
   4. **레이어 이름 규칙:** 레이어 경로(`::`로 나눈 단계) 가운데 한 단계가 아래 이름이면(대소문자·앞뒤 빈칸 무시) 그 역할이다. 여러 규칙에 맞으면 더 깊은 단계가 이기고, 같은 단계면 역할을 정하지 않고 AI 제안으로 넘긴다.

      | 역할 | 레이어 단계 이름 |
      |---|---|
      | `mass` | `건물` · `매스` · `건물매스` · `MASS` · `BUILDING` |
      | `floor` | `층윤곽` · `층` · `바닥` · `FLOOR` · `SLAB` |
      | `building-area` | `건축면적` · `BUILDING-AREA` |
      | `rooftop` | `옥탑` · `ROOFTOP` |
      | `parking` | `주차` · `주차구획` · `PARKING` |
      | `landscape` | `조경` · `LANDSCAPE` |
      | `landscape-roof` | `옥상조경` · `ROOF-LANDSCAPE` |
      | `open-space` | `공개공지` · `OPEN-SPACE` |
      | `ignore` | `검사제외` · `참고` · `REF` |

   위 어느 것으로도 정하지 못한 객체는 '역할 없음'이다. 꺼진 레이어·숨긴 객체는 설정 '숨긴 객체 포함'(기본 끔)이 켜졌을 때만 계산에 넣는다. 꺼져 있어도 역할이 정해지는 숨긴 객체는 '숨김' 표시와 함께 읽어 두고(계산에는 넣지 않음), 그 역할을 쓰는 행은 적합이 되지 못한다(SPEC-15.9 7). 숨겨서 검사를 피하는 일이 조용히 통과하지 않게 한다.
4. **층과 용도:** `floor` 객체의 층은 `vide-floor` → 사람이 확인한 분류의 층 → 높이 순서로 정한다. 높이 순서는 기준 지반 경우마다(SPEC-15.6 3) 이름 없는 윤곽을 이름 있는 층(그 층의 가장 낮은 바닥 높이)과 함께 높이로 늘어놓아 정한다: 이름 있는 층과 같은 높이(1 cm 안)의 윤곽은 그 층 이름을 받고, 나머지는 그 지반 위에 있으면 낮은 것부터의 순서로 1F, 2F…, 아래에 있으면 위에서부터의 순서로 B1, B2…를 받으며 '도구로 계산함'으로 적는다(읽은 모델에는 층 이름이 비어 있고, 지반 경우를 아는 계산 쪽이 붙인다). 순서로 받을 이름을 이미 다른 높이의 이름 있는 층이 쓰고 있으면(예: 두 이름 있는 층 사이의 중층) 그 윤곽은 어느 층에도 넣지 않고, 그 윤곽을 읽는 행(층수·용적률·주차)은 적합이 되지 못한다('판단 필요', 이유: '층 이름 없는 윤곽 n개 — 층 이름을 정하세요'). 다른 높이의 이름 있는 층에 합치지 않는다. 지상·지하는 층 이름이 정한다(`B…`는 지하, `…F`는 지상). 층 이름 없이 높이로 정한 윤곽의 바닥이 지반 경우에 따라 위·아래로 갈리면 그 층의 지상 여부는 경우로 나눈다(SPEC-15.9 2). 지하층의 법적 정의는 법규 판단이므로 VIDE가 높이로 바꾸어 정하지 않는다. 같은 층 이름 안에 바닥 높이가 1 cm보다 다른 윤곽이 있으면(중층·복층 등) 높이마다 따로 면적을 내어 그 층 바닥면적에 더하고, 층은 하나로 세며 '한 층에 높이가 다른 바닥 n개'를 미확정 사항으로 적는다. 이 경우 층수 행은 적합이 되지 못하고 '판단 필요'다(층 이름째 복사한 맨 위층이 한 층으로 세어질 수 있음); 높이 차가 층고(1층·기준층 가운데 작은 것) 이상이면 이유는 '같은 층 이름의 바닥이 다른 층 높이에 있음'이다. 용도는 `vide-use` → 사람이 확인한 분류의 용도 → 수정 사항 '층 용도'(SPEC-12.11과 같은 꼴, 사람이 넣은 것만) → 매스 작업본의 주용도 순이다.
5. **모양이 맞지 않으면** 그 객체는 쓰지 않고 '역할과 모양이 맞지 않음'·'닫히지 않음'·'평면이 아님'으로, 시도한 역할과 함께 목록에 남긴다. 고치지 않는다. 역할이 있는데 쓰지 못한 객체는 SPEC-15.9 7대로 그 역할을 쓰는 행을 막는다.

## 3. AI 분류 제안과 사람 확인 — SPEC-15.4

근거: SPEC-07.5의 1·3, AC-14, ADR-026, 2026-10-08 사용자 결정.

1. **제안 대상:** 역할 없음 객체(고르지 않은 대안·다른 jig의 결과는 제외)가 있으면 [역할 제안 받기]로 단발 AI 단계를 한 번 돌린다(SPEC-07.5의 1과 같은 경로, 꺼진 상태로 시작하지 않고 사람이 누를 때만). AI에게는 역할 없는 묶음이 있는 레이어의 표와 객체 묶음 요약(레이어 · 객체 종류 · 닫힘 · 수평 여부 · 크기 구간 · 높이 구간 · 개수 · 기존 속성 이름)만 보내고 좌표는 보내지 않는다. 보내는 항목은 대화의 전송 고지 규칙(FR-18, SPEC-02.17)을 따른다: [역할 제안 받기]를 누르면 먼저 보낼 레이어 이름 목록과 묶음 요약의 꼴을 보이고, 사람이 [보내고 제안 받기]를 눌러야 보낸다. 모델을 아직 읽지 않았으면(열 때의 읽기가 실패·진행 중) 버튼은 꺼지고 이유를 보인다.
2. **제안의 꼴:** 레이어 하나 또는 객체 묶음(같은 레이어 · 같은 모양 종류 · 비슷한 크기, 예: 'Default 레이어의 2.5 × 5.0 m 닫힌 사각형 48개') 마다 역할 하나, 층·용도(있으면), 이유 한 줄이다. 목록 밖 역할·없는 레이어·없는 객체를 가리킨 제안은 버리고 그 사실을 보인다.
3. **사람이 받기 전에는 쓰지 않는다.** 제안은 '제안'으로만 보이고 계산에 들어가지 않는다. 사람은 묶음마다 [받기]·[역할 바꾸기]·[버리기]를 하고, 묶음 안 객체를 하나씩 뺄 수 있다. 여러 묶음을 한 번에 받는 버튼은 두지 않는다. [받기]는 레이어 전체 제안이어도 그 제안이 가리킨(그리고 화면에 센) 객체마다 객체 기록을 쓴다 — AI가 보지 않은 객체(그 레이어의 하위 레이어, 같은 레이어의 다른 jig 결과, 나중에 그린 객체)에는 역할이 붙지 않는다. 받은 분류의 출처는 'AI 제안을 사람이 받음'이다(SPEC-12.14의 AI 추정 규칙). AI가 `ignore`(검사에서 뺌)를 제안한 묶음은 [받기] 옆에 '이 객체들은 어떤 검사에도 들어가지 않음'을 보이고, 뺀 객체 수는 결과의 분류 요약('검사에서 뺌' 수)에 보인다.
4. **프로젝트에 남는다.** 사람은 분류 카드에서 역할 없는·쓰지 못한 객체의 레이어나 객체에 역할을 직접 정할 수 있다(레이어에 정하면 그 레이어와 하위 레이어의 모든 객체, 나중 객체 포함 — 화면이 그렇게 알린다). 사람이 정하거나 받은 분류(레이어 단위·객체 단위)는 프로젝트의 분류 기록에 문서(Link)·레이어 경로 또는 객체 ID·역할·층·용도·누가·언제와 함께 남는다. 같은 프로젝트의 다른 법규 체크 작업본도 이 기록을 쓴다. 객체 단위 기록은 그때의 형상 지문을 함께 두고, 그 객체의 형상이 바뀌면 기록은 유지하되 '형상이 바뀐 객체 n'으로 다시 확인을 안내한다(역할은 그대로 쓴다). 지운 객체의 기록은 다음 읽기에서 '모델에 없음'으로 보이고 사람이 지울 수 있다.
5. 분류는 객체 속성에 쓰지 않는다(Rhino 문서를 바꾸지 않음). 속성으로 남기고 싶은 사람은 Rhino에서 `vide-check-role`을 직접 단다.

## 4. 규제 조건·대지 입력 — SPEC-15.5

근거: SPEC-12.2·12.7·12.14, SPEC-13.8, SPEC-07.2.

1. **규제 조건과 외피:** '건축 가능 영역·매스' 작업본의 넘겨줄 결과 '한계'(SPEC-12.2의 출력, ARCH-03 §8.6)를 앞 결과로 받는다. 들어 있는 것: 규제 조건 항목 전부(값 · 단위 · 적용 여부 · 확정 상태 · 출처 구분 · 근거 조항 · 출처, SPEC-12.7 2 — 법규 Q&A의 `legal.constraints`가 채운 값과 사람이 넣은 값이 이미 합쳐진 것), 미반영 조건, 대지 경계와 대지면적·정북, 규칙별 금지 띠(평면), 변형(기준·'판단 필요' 미적용)마다의 높이 상한·일조 금지 부피·최대 외피와 미확정 조건, 주용도·층고. 법규 Q&A 결과는 이 경로로만 들어오고, 법규 체크가 법규 서비스를 직접 부르지 않는다.
2. **고른 대안은 필요 없다.** 법규 체크는 사람이 모델링한 건물을 본다. 매스 작업본에 고른 대안이 없어도, 외피 단계까지 계산되어 있으면 된다.
3. **앞 작업본:** 이 프로젝트에서 가장 최근에 계산된 매스 작업본을 기본으로 읽고 사람이 고를 수 있다(SPEC-12.13 1과 같은 규칙). 앞 작업본이 없거나 '다시 계산 필요'이면 규제 조건을 쓰는 모든 행이 '사람 입력 필요'(이유: '규제 조건 없음 — 건축 가능 영역·매스에서 규제 조건을 넣고 계산하세요' 또는 '앞 작업본이 다시 계산 필요')이고, 형상 제한 행은 '검사 불가'다. 앞 결과를 대신 계산하지 않는다.
4. **대지:** 대지면적·대지 경계·정북은 매스 작업본이 쓴 값 그대로다. 사이트 모델링 작업본(있으면)에서는 기준 지반 후보(SPEC-15.6 3)만 더 읽는다.
5. **좌표:** 매스 작업본의 대지와 체크하는 모델은 같은 연결 문서여야 한다. 다른 문서면 형상 제한 행은 '검사 불가 · 대지와 모델이 다른 문서'이고 규모 행은 계산한다(대지면적은 숫자이므로). 매스 작업본의 대지가 연결 문서에서 오지 않았으면(문서를 알 수 없음) 형상 제한 행은 '검사 불가 · 대지가 어느 문서에서 왔는지 모름'이다. 모든 좌표는 매스 작업본의 로컬 m(문서 좌표 × m 환산 − 프레임 원점)로 맞춘다. 매스 작업본의 금지 부피(일조 사선·높이 상한·최대 외피)는 그 작업본이 쓴 지반 높이(프레임의 `groundZ`, 지금은 로컬 0) 위에 세워져 있으므로, 법규 체크는 기준 지반 경우마다(SPEC-15.6 3) 그 차이만큼 금지 부피를 위아래로 옮긴 뒤 겹침을 계산한다. 평면 금지 띠는 높이와 무관하다. 기준 지반 값(설정값·사이트 모델링 후보)은 문서 z(m)로 받는다.
6. **한계 항목 읽는 법:** 규제 조건 항목 하나가 행에 주는 것은 적용 여부·확정 상태·출처 구분으로 정하며, 모든 행이 같은 규칙을 쓴다.

   | 항목 | 행에 주는 것 |
   |---|---|
   | 값 없음, 적용 여부 없음, 확정 상태 '사람 입력 필요', 선택 항목이 '사람 입력 필요'(`ask`) | 그 한계 없음 → '사람 입력 필요'. 단 같은 행의 다른 확정 한계로 이미 위반이면 위반(그 항목은 미확정 사항) |
   | 적용 여부 '미적용'(확정) | 그 한계는 검사하지 않음. 행의 모든 한계가 미적용이면 '미적용 항목' |
   | 적용 여부 '판단 필요' | 그 항목을 넣은 경우와 뺀 경우로 나눈다(SPEC-15.9 2) |
   | 적용 '적용', 확정 상태 '판단 필요'(값 자체가 미확정) | 그 한계로는 적합·위반을 내지 않음 → '판단 필요' |
   | 적용 '적용', 확정 상태 '가정'(예: 서비스 해석) | 계산대로 두고 '가정 값 기준' 표지, 미확정 수에 셈(SPEC-15.9 5) |
   | 적용 '적용', 확정 상태 '확정' | 그대로 한계 |
   | 출처 구분 'AI가 추정함' | 한계로 쓰지 않음 → '사람 입력 필요'(이유: 'AI 추정 값은 사람이 확정해야 함', AC-14) |

   VIDE는 항목의 값·단위를 바꾸거나 빈 항목을 다른 항목으로 채우지 않는다. 단위가 그 항목 정의(SPEC-12.7 2, massing-kit `REGULATION_ITEMS`)의 단위와 다른 항목은 '사람 입력 필요'(이유: '단위가 다름')다.

## 5. 규모 계산 — SPEC-15.6

근거: SPEC-12.10 3·4, SPEC-12.13, FR-22.

1. **대지면적:** 매스 작업본의 대지면적과 그 출처를 쓴다. 공부 면적과 계산 면적이 둘 다 있고 다르면 두 값 모두로 계산하고 결과가 다르면 '판단 필요'다(SPEC-15.9 2). 하나로 합치지 않는다.
2. **건축면적:** `building-area` 윤곽이 있으면 그 합집합의 면적(출처: 모델 · 사람이 그린 윤곽)이다. 이때 지상 매스의 수평투영이 윤곽 밖으로 더 나간 면적도 숫자 출처에 함께 보인다(판정에는 윤곽을 씀). 윤곽이 없으면 지상 부분의 수평투영 면적이다: `mass`·`rooftop` 솔리드를 기준 지반에서 잘라 그 위 부분만, 지상 `floor` 윤곽(지하 층 이름은 뺌)과 합쳐 위에서 본 합집합이며 '수평투영 · 산정 예외 미반영'을 적는다. 지반 경우마다 따로 잰다. 수평투영은 산정 예외(처마·차양 등)를 빼지 않은 큰 쪽 값이므로, 이것으로 적합이면 적합이고 넘으면 '판단 필요'(이유: '건축면적 윤곽을 그리면 다시 체크')다.
3. **기준 지반과 높이:** 기준 지반은 설정값 '기준 지반 높이'(문서 z, m, 근거 함께)를 사람이 넣었으면 그 값 하나다. 없으면 사이트 모델링 결과의 대지 경계 위 지형 높이(최저·최고·평균, 도구로 계산함)를 후보로 보이고 최저·최고 두 경우로 계산한다(평균은 보이기만 한다). 후보도 없으면 기준 지반을 쓰는 행(건축면적이 수평투영일 때의 건폐율, 높이, 층 이름 없는 층수·연면적, 형상 제한)은 '사람 입력 필요'(이유: '기준 지반 높이')다. 지표면 산정 방법(가중 평균 등)은 법규 판단이라 VIDE가 하나를 고르지 않는다. 높이 = 지반 위 건물 형상(`mass`·`floor` 솔리드와, 그 솔리드가 덮지 않는 지상 층 윤곽의 프리즘 — SPEC-15.7 1)의 최고점 − 기준 지반이다. 매스가 지하나 저층부만 덮고 그 위층을 윤곽으로만 그렸어도 그 층들이 높이에 들어간다. 프리즘이 높이를 정하면 '가정 층고로 만든 높이'를 미확정 사항으로 적는다. `rooftop`은 빼고 잰 값과 넣고 잰 값의 두 경우로 계산한다(넣을 때만 넘으면 '판단 필요', 이유: '옥탑 등의 높이 산입 여부'). 한계는 그 행의 높이 항목 값이다. `incentiveHeight`(높이 완화)는 어느 높이 제한을 얼마나 푸는지가 법규 판단이고 매스 외피에도 들어가지 않으므로(SPEC-12.10) 적합 근거로 쓰지 않는다: 계획 높이가 항목 값을 넘지만 항목 값 + 완화량 합 이하이면 '판단 필요'(이유: '높이 완화 적용 미확정'), 그보다 크면 위반이다. `incentiveHeight` 항목이 있으나 한계로 쓸 수 없으면(AI 추정·사람 입력 필요 등, SPEC-15.5 6) 항목 값을 넘는 높이가 그 항목의 값(없으면 끝없이) 안에 있는 동안 위반이 아니라 '사람 입력 필요'(이유: 그 항목의 이유)다.
4. **층수:** 지상 층 이름(SPEC-15.3 4)의 가장 큰 번호다. 지상 층 이름의 수가 가장 큰 번호와 다르면(빈 번호가 있음) 두 값을 경우로 나누고 '층 번호가 이어지지 않음'을 적는다. `rooftop`은 세지 않고, 넣으면 상한을 넘는 경우 '판단 필요'다(옥탑 하나 = 한 층으로 셈). 층 윤곽이 없으면 '검사 불가 · 층 윤곽 없음'이다(매스 높이를 층고로 나누어 만들지 않는다).
5. **연면적·용적률:** 층마다 그 층 `floor` 윤곽의 합집합 면적(솔리드면 그 높이 가운데의 수평 단면 면적, 같은 층 안 높이가 다른 바닥은 SPEC-15.3 4대로 더함)이 바닥면적이고, 지상 층 합이 지상 연면적, 지하 층 합이 지하 연면적이다. 층 윤곽이 없으면 연면적과 용적률 행은 '검사 불가 · 층 윤곽 없음'이다(매스를 층고로 썰어 만들지 않는다). 용적률 산정 연면적 = 지상 연면적 − 층별 산정 제외 면적이다. 제외 면적은 사람이 층마다 넣는 수정 사항(값과 근거, SPEC-12.10 4와 같은 꼴)이며 AI가 낸 값은 받지 않는다(계약에서 거절). 모델에 없는 층의 제외 면적은 쓰지 않고 '모델에 없는 층의 제외 면적'을 미확정 사항으로 적으며, 그 층 바닥면적보다 큰 제외 면적이 있으면 용적률 행은 '사람 입력 필요'(이유: '제외 면적이 바닥면적보다 큼')다. 설정 '산정 제외 입력 끝남'이 꺼져 있으면 제외 면적이 더 있을 수 있으므로, 넘는 결과는 '판단 필요'(이유: '산정 제외 면적 입력 전')이고 적합은 그대로 적합이다. 한계는 매스 작업본(massing-kit `farTargets`)과 같은 사다리다.
   - **기준:** `farBase`. 계획 ≤ 기준이면 적합.
   - **완화 한도:** 기준 + 적용 여부가 '적용'·'판단 필요'이고 값이 있는 `incentiveFar`(구간마다)와 `openSpaceIncentiveFar`의 합, `farMax`가 있으면 그것을 넘지 않게 자른 값. 기준 < 계획 ≤ 완화 한도이면, 더한 완화 항목이 모두 '적용'·확정이고 `farMax`(있으면)가 확정일 때만 적합이고, 아니면 '판단 필요'(이유: '완화 조건 미확정').
   - **가장 느슨한 상한:** 값이 있는 `farMax` → `farAllowed` → `farBase` 가운데 앞의 것. 완화 한도 < 계획 ≤ 가장 느슨한 상한이면 '판단 필요'(이유: '기준을 넘지만 넘는 근거가 되는 완화 항목 없음'). 계획 > 가장 느슨한 상한이면 위반이다.
   - `farBase`가 없으면 적합을 내지 않는다: 계획이 가장 느슨한 상한을 넘으면 위반, 아니면 '사람 입력 필요'(이유: '기준 용적률'). `farBase`가 '미적용'(확정)이면 다시 묻지 않고, 가장 느슨한 상한 안이면 '판단 필요'(이유: '기준 용적률 미적용 — 허용·상한 용적률 안이지만 기준 없이 적합으로 정하지 않음'), 넘으면 위반이다. 한계 값이 하나도 없으면 '사람 입력 필요'다. 사다리의 모든 값은 숫자 출처에 항목별로 둔다.
   - **아직 쓸 수 없는 완화·상한 항목:** `incentiveFar`·`openSpaceIncentiveFar`·(확정 값이 없을 때) `farMax`·`farAllowed` 항목이 있으나 한계로 쓸 수 없으면(AI 추정·사람 입력 필요 등), 기준을 넘는 계획이 그 항목이 열 수 있는 범위(그 값을 더한 한도, 값이 없으면 끝없이; 확정 `farMax`를 넘지는 않음) 안에 있는 동안 위반이나 '판단 필요'가 아니라 '사람 입력 필요'(이유: 그 항목의 이유)다. 항목이 아예 없으면 이 규칙은 걸리지 않는다.

## 6. 형상 제한 — SPEC-15.7

근거: SPEC-12.8·12.9, 2026-10-08 사용자 결정 '법정 외피 밖으로 나간 부분을 3D로'.

1. **검사하는 형상:** 기준 지반 위의 `mass`(닫힌 솔리드)와 `rooftop`, 그리고 매스가 덮지 않는 지상 층 윤곽이며, 지반 경우마다 그 지반에서 잘라 위 부분만 쓴다(지하층의 이격은 범위 밖). 층 윤곽은 그 층 바닥에서 다음 층 바닥까지(맨 위층은 매스 작업본의 기준층 층고, '가정'으로 적음 — 다만 그 윤곽 위에 선 매스가 있으면 그 매스 꼭대기까지) 세운 프리즘에서 매스를 뺀 나머지가 1 mm·0.001 ㎥를 넘을 때만 더하고 '매스가 덮지 않은 지상 층 윤곽 n개를 층 윤곽 프리즘으로 더함'과 '층 윤곽으로 만든 형상'을 적는다(매스가 지하·저층부만 덮어도 위층 윤곽이 빠지지 않음). 지하 층 이름(`B…`)과 모든 지반 경우보다 낮은 이름 없는 윤곽은 넣지 않는다. 초과 부분이 `rooftop`에서만 나오면 그 초과로 정해지는 결과는 '판단 필요'(이유: '옥탑 등의 산입')다. 매스 역할 객체(쓰지 못한 것 포함)가 있으나 쓸 수 있는 매스가 하나도 없으면 프리즘으로 대신하지 않고 '검사 불가'다. 닫히지 않는 매스는 쓰지 않고 '검사 불가' 이유로 센다.
2. **평면 규칙(건축선·가각·건축한계선·대지 안의 공지·민법 이격·기타 이격):** 규칙마다 매스 작업본이 낸 금지 띠(대지 경계 구간에서 그 거리 안쪽, 가각 삼각형, 건축한계선 바깥)를 기준 지반에서 건물 최고점까지 세운 기둥과 건물 형상의 겹침이 초과 부분이다. 제한선 계산은 SPEC-12.8의 규칙 그대로이며 같은 코드를 쓴다.
3. **정북 일조:** 변형마다 일조 금지 부피(SPEC-12.9 2의 사선 외피 바깥)를 지반 경우의 높이로 옮긴 것(SPEC-15.5 5)과 건물 형상의 겹침이다.
4. **높이와 최대 외피:** 높이 상한 위(기준 지반 + 상한)의 건물 부분은 높이 행(SPEC-15.6 3)에서 이미 판정하고, '최대 외피' 행은 건물 형상 − 지반 경우의 높이로 옮긴 최대 외피(SPEC-12.9 3) 전체를 보인다. 최대 외피에는 높이 완화가 들어 있지 않으므로, 초과 부분이 모두 외피 높이 상한과 상한 + 높이 완화량 합 사이에만 있으면 '판단 필요'(이유: '높이 완화 적용 미확정')다. 초과 부분마다 번호(결과 전체에서 1부터, 뷰포트 표식과 같음), 규칙 이름, 변형, 지반 경우, 부피(㎥), 범위(최저·최고 높이와 평면 범위), 가까운 대지 경계 구간(예: '도로 2', '인접 3'), 겹친 객체 ID, 옥탑만인지를 둔다. 형상 행의 계획 값은 초과 부피 합(㎥)이고 한계 값은 두지 않으며(규칙 항목은 숫자 출처와 근거에 둠), 여유는 비운다. 부피 0.001 ㎥ 이하이거나 두께 1 mm 이하인 조각은 계산 오차로 보고 버린다(규제 값이 아니라 기하 허용 오차이며 SPEC-12.8 3의 1 mm와 같다).
5. **대지 밖:** 대지 경계 밖으로 나간 건물 부분이 있으면 '판단 필요'(이유: '대지 경계 밖 부분 — 대지 경계와 모델 위치 확인')이고 위치를 보인다. 없으면 적합이다.
6. **상태:** 그 규칙의 항목이 비었으면 '사람 입력 필요', '미적용'이면 미적용 목록, 금지 띠나 금지 부피를 매스 작업본이 만들지 못했으면 '검사 불가'다. 초과가 없으면 적합, 있으면 위반이다. 단 그 규칙이 '판단 필요'(적용 여부·거리의 정의·기준선 위치 등 미확정 조건이 걸림)이면 변형 두 개(기준·미적용)의 결과가 같을 때만 그 결과이고 다르면 '판단 필요'다(SPEC-15.9 2). 구간(`target`)이 여럿인 규칙은 한계가 띠의 각 영역이 어느 구간에서 잰 것인지 줄 때 구간마다 자기 띠만 겹쳐 구간별 상태·초과 부피·구간 이름을 낸다. 그 연결이 없으면 구간을 나눌 수 없으므로 구간별로는 위반을 내지 않고('판단 필요', 이유: '구간별 금지 띠를 나눌 수 없음'), 모든 항목이 확정 값이고 합친 띠에 든 부분이 있을 때만 행을 위반으로 둔다. 매스 작업본의 미반영 조건(그 제한 없이 계산한 항목)은 만들어진 띠·부피로 먼저 계산한다: 미반영 구간은 그 구간이 '사람 입력 필요', 구간이 없는 미반영 조건은 행이 적합이 되지 못하고 '사람 입력 필요'이며, 다른 구간에서 위반이 나오면 행은 위반이고 미반영 조건은 미확정 사항으로 남는다(SPEC-15.9 2). 정북 일조의 미반영 조건(일부 기준선 구간·값)도 같다. 그 제한 없이 만든 최대 외피로 '최대 외피' 행이 적합이면 그 행에 '미반영 조건 n개'를 붙인다. 높이 항목이 하나도 없어 매스 작업본이 검토 높이로 외피를 자른 경우, 그 높이 위의 초과는 위반이 아니라 '사람 입력 필요'(이유: '높이 상한 사람 입력 필요')다.

## 7. 주차·조경·공개공지 — SPEC-15.8

근거: SPEC-12.12, SPEC-12.10 5.

1. **주차:** 계획 대수 = `parking` 객체 수(객체마다 `vide-count`, 없으면 1). 법정 대수 = SPEC-12.12 1의 규칙 그대로(같은 코드)에 이 모델의 용도별 면적을 넣은 값이다. 용도별 면적은 SPEC-15.6 5의 층별 바닥면적을 SPEC-15.3 4의 용도로 묶은 것이며, 산정 면적 기준이 `gross`면 지상·지하 모든 층, `far`면 지상 층에서 제외 면적을 뺀 값이다(SPEC-12.12와 같은 뜻). 모델의 용도 이름과 산정 기준 항목의 용도(`target`)는 앞뒤 빈칸만 지우고 글자가 같을 때만 짝짓는다. 비슷한 이름을 코드나 AI가 맞추지 않으며, 짝이 없는 용도는 '사람 입력 필요'(이유: '용도 n의 주차 산정 기준')다. 산정 기준·끝수 처리·산정 면적 가운데 하나라도 비거나 '사람 입력 필요'(`ask`)이면 '사람 입력 필요', 용도가 정해지지 않은 층이 있으면 '사람 입력 필요'(이유: '층 용도'), 기준이 '판단 필요'인 용도가 있으면 '판단 필요'다(다른 용도의 기준이 '사람 입력 필요'이면 '사람 입력 필요'가 앞섬). 끝수 처리·산정 범위·산정 면적의 적용 여부나 값이 '판단 필요'이면 계산한 대수로 적합·위반을 내지 않고 '판단 필요'(이유: 그 항목)다. '면적 n ㎡당 1대' 꼴이 아닌 기준(세대당 등)은 SPEC-12.12처럼 받지 않으므로 '사람 입력 필요'다. 계획 ≥ 법정이면 적합, 아니면 위반이다. 구획 치수·차로·장애인 주차는 검사하지 않는다.
2. **조경:** 계획 면적 = `landscape` 영역의 대지 안 합집합 면적(겹친 부분은 한 번). 법정 면적은 SPEC-12.12의 조경 규칙 그대로(massing-kit `landscape.ts`, 같은 코드)이며 그 함수가 값을 내지 못하면 '사람 입력 필요'다. `landscape-roof`는 산입 비율이 법규 판단이므로 넣지 않은 경우와 면적 그대로 넣은 경우로 나누고(넣은 경우는 '판단 필요'만 낼 수 있음), 넣지 않아 모자라고 넣으면 채워지는 경우만 '판단 필요'(이유: '옥상 등 조경의 산입')다. 조경 영역과 공개공지 영역이 겹친 부분은 조경에 넣는 경우와 빼는 경우로 나눈다(이유: '공개공지와 겹친 조경의 산입').
3. **공개공지:** 대상 여부가 '적용'이면 계획 면적 = `open-space` 영역의 대지 안 합집합 면적, 필요 면적은 SPEC-12.12의 공개공지 규칙 그대로(massing-kit `open-space.ts`)다. 위치 요건(도로 접면·개방 등)은 판단하지 않으며 행 제목이 '공개공지 면적'이고 '위치 요건은 검사하지 않음'을 적는다. 대상 여부가 '판단 필요'면 '판단 필요'다.
4. **모델에 그 역할이 하나도 없으면** 그 행은 '검사 불가 · 모델에 주차 구획 없음' 등이다. 계획이 정말 0이면 사람이 설정 '없음 확정'(주차·조경·공개공지 각각)을 켜고, 그때 계획 값은 0이다.

## 8. 결과 상태와 근거 — SPEC-15.9

근거: SPEC-12.7 5, SPEC-13.5, AC-14, FR-09.

1. **상태:** 행마다 하나다.

   | 상태 | 뜻 |
   |---|---|
   | 적합 | 한계 값이 있고, 아래 2의 모든 경우에서 계획 값이 한계 안이다 |
   | 위반 | 한계 값이 있고, 모든 경우에서 계획 값이 한계를 넘는다 |
   | 판단 필요 | 경우에 따라 결과가 갈리거나, 법규 판단이 걸린 산입·완화·적용 여부가 미확정이다 |
   | 사람 입력 필요 | 한계 값이 비었거나(규제 조건 '사람 입력 필요'), 계산에 필요한 사람 값(기준 지반·층 용도 등)이 없다 |
   | 검사 불가 | 모델이나 앞 결과로 계산할 수 없다(역할 객체 없음, 닫히지 않음, 단위 모름, 다른 문서, 외피 점검 실패 등) |

   모든 행은 '적합'이 아니면 이유를 가진다. 판정을 돌리지 못한 행을 적합으로 두지 않는다.
2. **경우와 구간:** 두 가지를 섞지 않는다.
   - **경우(어느 하나가 맞음):** 확정되지 않은 입력이 둘 이상의 값을 가질 수 있으면 그 값마다 계산한다 — 외피 변형(기준·'판단 필요' 미적용), 기준 지반 후보(최저·최고), 대지면적(공부·계산), 옥탑·옥상 조경·겹친 조경 산입(넣음·뺌), 완화·적용 여부 '판단 필요' 항목(넣음·뺌), 층 번호(SPEC-15.6 4). 행의 계산에 실제로 쓰이는 입력만 나누며, 한쪽으로 커지기만 하는 입력(기준 지반은 낮을수록 높이가 큼 등)은 양 끝 두 값만 쓴다. 한 행의 경우는 32개를 넘지 않게 묶고, 넘으면 '판단 필요'(이유: '미확정 입력이 너무 많음')다. 모든 경우가 적합이면 적합, 모두 위반이면 위반, 갈리면 '판단 필요'이고 경우별 결과를 행 안에 펼친다. 큰 쪽 값(수평투영, 제외 전 연면적)은 적합 쪽으로만 결론을 낸다(SPEC-15.6 2·5).
   - **구간(모두 지켜야 함):** 규제 조건 `target`이 구간·용도마다 다른 값이면 구간마다 상태를 낸다. 행의 상태는 구간 가운데 하나라도 위반이면 위반(나머지 구간의 미확정은 이유에 함께 적음), 위반이 없고 '사람 입력 필요'가 있으면 '사람 입력 필요', 그다음 '검사 불가', 그다음 '판단 필요' 순이며, 모든 구간이 적합일 때만 적합이다.
3. **숫자의 출처:** 행의 모든 숫자(계획 값, 한계 값, 그 계산에 쓴 대지면적·면적·높이·대수·제외 면적)는 출처를 가진다: 모델(역할·객체 수·읽은 문서 판), 규제 조건(항목 ID·확정 상태·출처 구분), 대지(매스 작업본), 사람 입력(설정값·수정 사항과 근거), 계산(규칙 이름).
4. **근거 조항:** 한계 값 행은 그 규제 조건 항목의 근거 조항·원문 링크·법규 답 번호(`L<번호>`)를 그대로 보인다(SPEC-12.14). 근거가 없는 사람 입력 값은 '근거 없음'을 붙인다. VIDE가 조항을 새로 붙이지 않는다.
5. **'가정' 값:** 한계 값의 확정 상태가 '가정'(예: 서비스 해석)이면 상태는 계산대로 두고 '가정 값 기준' 표지를 붙여 미확정 수에 센다.
6. **머리 요약:** 상태별 수, 미확정 수(미확정 사항이 하나라도 있는 행의 수), 마지막 체크 시각과 읽은 문서 판, 앞 결과(매스 작업본·대지 작업본)의 이름과 계산 시각. 위반이 없어도 적합이 아닌 행이 있거나 미확정 수가 0이 아니면 "위반 없음"이라고 쓰지 않고 상태별 수만 보인다.
7. **쓰지 못한 객체는 적합을 막는다:** 다음 객체가 있으면 그 행은 계산 결과가 적합이어도 적합이 되지 못하고, 위반은 그대로 위반이다.
   - 역할이 있는데 쓰지 못한 객체(닫히지 않음·평면이 아님·역할과 모양이 맞지 않음), 그리고 '숨긴 객체 포함'이 꺼진 채 역할이 정해진 숨긴 객체 → 그 역할을 쓰는 행 가운데 적합이었을 행이 '검사 불가'(이유: '쓰지 못한 〈역할〉 객체 n개' 또는 '숨긴 〈역할〉 객체 n개 — 포함해서 다시 체크하거나 검사에서 빼세요').
   - '역할 없음' 객체 가운데 닫힌 솔리드·닫힌 평면 영역·블록(건물 부분일 수 있는 것) → 적합이었을 모든 행이 '판단 필요'(이유: '역할 없는 객체 n개 — 역할을 정하거나 검사에서 빼세요'). 열린 곡선·글자·치수 등은 막지 않는다. '고르지 않은 대안'·'다른 jig의 결과'는 막지 않는다.
   - 최소 기준 행(주차·조경·공개공지)은 계획 값을 이루는 역할(주차 구획, 조경, 공개공지)의 쓰지 못한·숨긴 객체가 계획 값을 줄이므로, 계산이 위반이어도 위반이 되지 못하고 '검사 불가'(이유: '숨긴 〈역할〉 객체 n개 — 계획 값에 넣지 않음…' 등)다. 법정 값을 키우는 역할(층 윤곽)은 적합만 막는다.
   - 사람이 레이어나 객체를 `ignore`로 정하면 막지 않는다. 막힌 행은 이유와 함께 [역할 제안 받기]·분류 탭으로 가는 길을 보인다.
8. **비교의 정밀도:** 적합·위반은 반올림하지 않은 값으로 비교하고 계획 = 한계는 적합이다. 계산의 부동소수점 잡음(mm→m 환산, 원점 빼기)은 수치 허용 오차로 본다: 계획과 한계의 차가 한계의 1e-9배(최소 1) 안이면 같은 값이며(법정 값이 아니라 계산 오차의 기준), 이때 여유는 0이다. 화면 글자는 반올림이 결과를 뒤집어 보이지 않게(위반인데 계획과 한계가 같은 글자로 보이지 않게) 필요한 만큼 자릿수를 늘리고, 그래도 같은 글자이면 계획 값에 '(한계 초과)'·'(한계 미만)'을 붙인다. 비율 항목은 0.6 = 60%처럼 비율로 계산하고 글자로만 %를 쓴다.

## 11. 보고서와 표 내보내기 — SPEC-15.12

근거: FR-14·22, AC-20, SPEC-07.11, SPEC-12.13 6.

- **보고서(HTML, 자체 포함):** 머리의 탐색용 고지, 상태별 수와 미확정 수, 행 표(상태·계획·한계·여유·근거), 행마다 숫자 출처와 경우별 결과, 초과 부분 목록(규칙·부피·높이 범위·구간·객체), 미적용 항목, 분류 요약(역할별 객체 수·쓰지 못한 객체 수·AI 제안을 받은 수), 입력(읽은 문서와 시각, 매스·대지 작업본과 계산 시각, 법규 답 번호).
- **표(CSV):** 행마다 검사 · 묶음 · 상태 · 계획 값 · 한계 값 · 단위 · 여유 · 한계 값 확정 상태 · 출처 구분 · 근거 조항 · 이유 · 미확정 사항.
- '다시 체크 필요' 상태(SPEC-15.13)이거나 아직 체크하지 않았으면 내보내지 않는다(보고서 저장·인쇄와 CSV가 꺼지고 이유를 보임). XLSX·HWPX는 OQ-08을 따르며 만들지 않는다.

## 12. 다시 체크 필요 — SPEC-15.13

근거: SPEC-07.5의 6, SPEC-12.1 6, 2026-10-08 사용자 결정 '[법규 체크] 누를 때만'.

- 결과는 읽은 것의 지문을 가진다: 모델 문서와 그 판, 분류 기록의 판, 매스 작업본의 넘겨줄 결과 지문, 대지 작업본의 지문, 설정값 지문, 수정 사항(제외 면적·층 용도) 지문.
- 하나라도 바뀌면 결과 머리에 '다시 체크 필요'와 바뀐 것(예: 'Rhino 모델이 바뀜 · 규제 조건이 바뀜')을 보인다. 매스 작업본은 법규 결과·규제 조건이 바뀌어도 다시 계산하기 전까지 넘겨줄 결과가 그대로이므로(SPEC-12.2), 매스 작업본이 '다시 계산 필요'가 되는 것만으로도 '다시 체크 필요 · 규제 조건이 바뀜(건축 가능 영역·매스를 다시 계산)'이다. 이때 [법규 체크]를 눌러도 SPEC-15.5 3대로 규제 조건 행이 '사람 입력 필요'가 되므로, 먼저 매스 작업본을 다시 계산하라고 안내한다. 연결 문서가 바뀌거나(다른 Link) 모델 문서가 닫혔다 다시 열려 판을 비교할 수 없으면 '모델 판 확인 불가'와 같이 다룬다. 이전 결과는 지우지 않고 흐리게 보인다. 저절로 다시 계산하거나 읽지 않는다. Sync는 법규 체크를 돌리지 않는다.
- 모델 문서 판은 연결의 현재 판과 비교하며(문서를 읽지 않는 판 확인 — 패널을 열 때, 체크 뒤, VIDE 창이 Rhino에서 돌아와 초점을 받을 때), 연결이 끊겼거나 문서가 닫혔으면 '모델 판 확인 불가'로 보이고 결과는 그대로 둔다. 어느 쪽이든 내보내기는 꺼진다(SPEC-15.12).
- [법규 체크]가 끝나지 못하면(읽기 실패, 계산 실패) 이전 결과는 '마지막 체크 실패 · 이전 결과'로 흐리게 남고 내보내기가 꺼진다(SPEC-15.14).

## 13. 실패와 사람 투입 — SPEC-15.14

근거: SPEC-07.17, SPEC-12.16.

| 상황 | 동작 |
|---|---|
| 연결 Rhino 없음·문서가 닫힘 | 체크하지 않고 이유와 마지막 결과를 보인다 |
| 읽기 실패·중간에 끊김·계산 실패 | 결과를 바꾸지 않는다. 이유(한국어)와 [법규 체크 다시 누르기]; 이전 결과는 '마지막 체크 실패 · 이전 결과'로 흐리게 두고 내보내지 않는다 |
| 문서 단위를 알 수 없음 | SPEC-15.3 1: 길이·면적·부피를 쓰는 행 '검사 불가 · 문서 단위 모름', 층수·주차 대수는 계산 |
| 매스 작업본 없음·다시 계산 필요 | SPEC-15.5 3 |
| 매스 작업본의 외피가 점검 실패 | 형상 제한 행 '검사 불가 · 외피 점검 실패'. 규모 행은 계산 |
| 닫히지 않은 매스 | 그 객체는 쓰지 않고 목록. 매스를 쓰는 행은 적합이 되지 못한다(SPEC-15.9 7). 층 윤곽 프리즘(SPEC-15.7 1)은 매스 역할 객체가 하나도 없을 때만 쓴다 |
| 불리언 실패(기하 연산이 닫힌 결과를 못 냄) | 그 규칙 행만 '검사 불가 · 형상 연산 실패'와 객체 ID. 다른 행은 계속 |
| 역할 없음 객체 | 계산에서 빼고 수를 보인다. 계산은 막지 않지만 건물 부분일 수 있는 것은 적합을 막는다(SPEC-15.9 7) |
| AI 제안 실패·없음 | 제안 없이 진행하고 'AI 제안을 받지 못했습니다. 역할은 직접 정할 수 있습니다'를 알린다(버린 제안으로 세지 않음). 사람이 분류 카드에서 직접 역할을 정할 수 있다 |
| 원격 화면 | SPEC-15.16 |

## 14. AI가 하는 일 — SPEC-15.15

근거: FR-25, ADR-026, AC-14.

- **한다:** 말로 법규 체크 열기(SPEC-07.18), 역할 없음 객체의 역할 제안(SPEC-15.4), 대화에서 결과 표를 읽고 설명하기(행의 상태·숫자·근거를 그대로 인용).
- **하지 않는다:** 적합·위반 판정, 한계 값·적용 여부 정하기, 산입·제외 판단, 숫자 만들기·고치기(제외 면적·층 용도·기준 지반을 수정 사항이나 설정값으로 넣는 것 포함), 분류를 사람 대신 확정하기, [법규 체크] 누르기, Rhino 문서 고치기. 대화 AI의 설명은 'AI 해석'이며 결과 행을 바꾸지 않는다.
- 결과가 없거나 '다시 체크 필요'이면, 대화 AI는 "위반 있나?" 같은 질문에 모델을 보고 스스로 판정하지 않고 그 사실(체크 안 함 · 다시 체크 필요와 바뀐 것)과 [법규 체크]를 안내한다. 이전 결과를 인용할 때는 '이전 결과(다시 체크 필요)'라고 함께 말한다.

## 15. 권한과 원격 — SPEC-15.16

근거: FR-18, SPEC-04, SPEC-13.11.

- 법규 체크는 연결 Rhino 문서를 읽기만 한다. 쓰기·만들기·호스트 선택 바꾸기는 없다.
- 원격 화면(SPEC-04)은 결과 보기와 3D 보기, 보고서 보기만 한다. [법규 체크], 분류 받기·바꾸기, 설정값·제외 면적 고치기는 작업 PC 화면에서 한다.
- AI 분류 제안에 보내는 내용은 SPEC-15.4 1의 요약뿐이며 프로젝트에서 대화 AI 전송을 껐으면 [역할 제안 받기]가 꺼진다.
