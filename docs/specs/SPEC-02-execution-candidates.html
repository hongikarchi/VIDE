00 / 설계 요청을 실제 작업으로 수행한다 — SPEC-02.11

근거: PRD §7·§8.3·§9.5, FR-04·08·10·15·18. AI는 문장으로 조언만 하는 것이 아니라, 지정한 모델·도면을 읽고 사용자의 의도를 실제 네이티브 후보로 만든다. 로컬 작업자가 SPEC-01의 입력으로 작업을 맡기며, 현재 지원 능력과 전송 범위 안에서 실행한다.

정상 흐름은 다음과 같다.

  1. 요청의 목표, 실제 변경 대상, 유지 조건, 스케치·치수, 참고 자료를 읽는다. 입력과 기존 확정 조건으로 결정할 수 없는 중요한 내용만 질문한다. 대상이 명확한 작은 이동/수정에 불필요한 계획 승인 단계를 추가하지 않는다.
  2. 작업을 사람이 검토할 결과 단위로 구성한다. 예를 들어 ‘경계 수정 후보’와 ‘변경 면적 확인’은 목적과 선후관계를 보여 주되, 점 하나를 바꾸는 내부 연산마다 별도 사용자 작업으로 나누지 않는다.
  3. 필요한 객체·속성·좌표·관계를 조회하고 현재 지원되는 생성/수정 동작을 선택한다. 근거 없는 수치를 AI가 만들어 기하 입력으로 사용하지 않는다.
  4. 호스트에서 실제 후보를 만들고 결과를 다시 읽어 유효성·치수·보존 조건을 검사한다. 허용 범위 안에서 후보를 보정하거나 필요한 자료를 추가 조회한다. 안전한 내부 단계마다 사용자 승인을 반복하지 않는다.
  5. 일관된 결과가 준비되면 자체 뷰의 후보, 원본과의 차이, 관련 측정값, 사용한 가정과 미검토 범위를 함께 보여 준다. 작업 중에도 마지막 실제 결과를 탐색하고 추가 지시할 수 있다.
  6. 사용자는 후보 조정·중단·적용으로 이어간다. 요청이 설명/조회라면 근거가 연결된 답변이나 표로 끝나고, 생성/수정 요청이라면 텍스트 답변만으로 완료하지 않는다.

계획, 실행 중인 동작, 실제로 준비된 결과를 구분한다. CLI가 문장을 반환하는 것은 연결 시험일 뿐 이 기능의 완료가 아니다. 기하 작업 없이 “수정했습니다”라고 말하거나 화면 전용 형상을 그리는 것으로 네이티브 후보를 대신하지 않는다. 예외·상한·재개 규칙은 §1·4·6, 직접 수정 보호는 §8을 따른다.

01 / 어떤 생성·수정을 요청할 수 있는가 — SPEC-02.12

근거: PRD §8.2~5·§12.1·§14.1, FR-04·05·06·08·10·12. 다음은 첫 구현에 사용할 기능 지원 검토안이다. OQ-03·10의 구체안으로 제시하며 최종 지원 확정이나 실증 완료를 뜻하지 않는다. 호스트별 유형·보존 속성·검수는 hosts/rhino.md와 hosts/zwcad.md가 소유한다. 이 예제를 제품 전체의 기능 상한으로 삼지 않는다.

요청 종류 입력 예 프로그램이 수행할 일 눈에 보이는 결과
새 경계 생성 평면의 닫힌 스케치와 치수로 경계를 만들어 줘 점열/치수에서 지원 네이티브 평면 폴리라인 후보 생성 원본 선·해석 경계·실제 후보와 길이/면적

입체 후보 수정(Rhino 검토안) 이 후보의 높이만 바꾸고 바닥 경계는 유지 지원 생성 기준을 가진 후보의 높이를 수정/재생성 이전/새 후보의 높이와 유지된 경계

여기서 경계는 문/벽/실이라는 BIM 의미를 자동으로 갖지 않는다. 닫힌 선의 면적은 기하 면적이다. 임의 솔리드의 모든 편집 이력을 복원하거나 전문 평면을 자동 설계하는 약속으로 확대하지 않는다. 입체 후보는 현재 폴리라인 실험보다 추가 검증이 필요한 별도 지원안이다.

요청은 버튼별 고정 예제와 달리 다른 객체·치수·점열에도 적용되어야 한다. 동작을 조합하는 방법은 AI가 정하되, 허용 능력을 벗어나면 어떤 부분이 지원되지 않는지 설명하고 가능한 결과를 구분한다. 지원하는 요청인데도 상시 ‘결정 필요’로 멈추는 구현은 완료가 아니다.

기능 판단 예: 폭을 유지한 채 선택 경계 한쪽을 늘리면 길이·면적이 그 변경에 맞게 달라지고, 유지 대상으로 지정한 다른 경계는 그대로여야 한다. 수치 기준과 시험 좌표는 PLAN §7.2에서 정한다. 생성 유형을 이름만 바꾸거나 화면에서만 흉내 낸 결과는 불합격이다.

02 / 후보를 보며 고치고, 원본에 반영한다 — SPEC-02.13

근거: PRD §8.3~5·§9·§11.2, FR-04·10·11·12·16. 사용자는 긴 로그 대신 실제 후보를 보며 “이 부분은 그대로, 저 부분만 변경”하는 방식으로 작업을 이어간다.

첫 후보가 나오면 원본/후보를 구분해 탐색하고 바뀐 객체·치수·관련 수치를 확인한다. 스케치 원본과 해석도 다시 열 수 있다. “너무 넓다, 이 선까지만 줄여 줘”처럼 새로운 선이나 수치를 주면 같은 목표의 후속 실행으로 연결한다. 이전 후보는 기준과 함께 남고, 새 지시가 적용된 후보가 준비됐을 때 그 차이를 확인한다. 여러 후보 전체를 자유 병합하는 기능은 추가하지 않는다.

유지 대상을 추가하거나 하위 작업을 제외하면 해당 부분의 후속 실행을 조정한다. 사용자가 호스트에서 직접 고친 결과는 관련 기준 재조회 뒤 새 작업의 입력으로 쓸 수 있다. 무관한 문서 작업은 계속된다. 중단해도 이미 만든 후보를 열어 보거나, 확인된 결과에서 나중에 이어갈 수 있다(§4·8).

사용자가 적용할 후보를 고르면 대상 문서·버전·변경 내용을 보여 준다. 적용은 검토한 후보의 변경을 실행하는 행동이며, AI에 새 설계안을 다시 생성시키는 행동이 아니다. 새 객체 후보의 채택과 기존 객체에 대한 수정은 호스트 지원 계약에 맞게 수행한다. 현재 조건과 충돌하면 차이를 보여 주고 재검토한다(§3·7).

적용 뒤 해당 호스트에서 객체를 선택하고 기본 도구로 이동·정점/지원 형상 편집을 이어갈 수 있어야 한다. 파일 저장은 호스트에서 수행하고 VIDE는 확인한 저장 상태를 별도로 표시한다. 저장·재열기 뒤 유형·형상·선언 속성이 유지되는지 검수한다. 원본 적용 뒤 표·캡처 생성이 실패하면 그 산출물만 다시 만든다.

완료 기준: 요청 → 실제 후보 → 적어도 한 번의 수정 지시 → 달라진 후보 확인 → 적용 → 호스트 재편집·저장·재열기가 하나의 작업 기록으로 이어져야 한다. AI 답변 성공이나 후보 버튼 표시만으로 완료하지 않는다(AC-05~11·17·18·24·38).

03 / CAD 도면과 Rhino 모델을 한 요청으로 바꾼다 — SPEC-02.14

근거: PRD §8.6·§12.2, FR-02·03·04·09·10·11·12. 로컬 작업자는 연결된 CAD 도면과 Rhino 문서를 같은 작업의 대상으로 지정한다.

CAD 자료로 Rhino 후보 만들기: ZWCAD에서 지원되는 닫힌 경계를 선택해 참고 입력으로 넣고 Rhino를 결과 문서로 지정한다. 사용자는 두 문서의 단위와 배치 기준을 확인하고 “이 경계로 높이 h의 매스를 만들어 줘”라고 요청한다. 프로그램은 실제 CAD 경계를 읽고 확인된 변환으로 Rhino 후보를 만든다. 후보를 선택하면 원 CAD 경계와 취득 시점, 높이 조건으로 이동할 수 있다. 돌출 지원 검토안은 H-RHINO-05에 연결한다.

같은 변경을 양쪽에 반영하기: 설계자가 대응하는 CAD 경계와 Rhino 후보/결과를 지정한 뒤 “이쪽 경계를 그린 선까지 늘리고 모델에도 반영해 줘”라고 요청한다. 프로그램은 도면 수정 후보와 그 수정 경계를 사용하는 모델 후보를 구성한다. CAD 변경 전 원본을 먼저 덮어쓰는 대신 확인된 후보 기하를 후속 입력으로 사용할 수 있다. 두 후보의 관계·실제 변경·호스트별 적용 결과를 한 요청에서 확인한다.

이후 원본이 직접 편집되었다면 Sync와 관련성 확인을 거쳐 필요한 쪽만 재계산한다. 연결은 지속적인 양방향 자동 동기화가 아니며, 새 연계 실행에는 사용자의 요청이 필요하다. 임의의 두 객체를 이름이나 근접성으로 자동 대응시키지 않는다.

완료 기준: 지정 CAD 경계가 실제 Rhino 입력이 되고, 조건 변경으로 양쪽 결과가 일관되게 바뀌며, 한쪽 실패가 다른 쪽 성공으로 가려지지 않아야 한다. 별도 문서의 독립 작업도 함께 실행해 활성 화면 전환과 무관한 대상을 유지한다(AC-25·32·33). 정확한 관계/충돌/부분 실패 규칙은 §9를 따른다.

01 / 실행 조건 — SPEC-02.1

근거: FR-08·15·18. 작업 범위는 목표, 복수 문서 대상, 보존 조건, 허용 도구, 전송 자료와 실행 상한을 포함한다. 실행 시작 시 그 버전을 고정한다. AI는 허용 자료와 호스트 API로 필요한 조회·실행 코드를 구성한다. VIDE는 대상·기준·권한·실행 결과를 관리한다. 특정 편집 명령 목록만을 제품 기능의 상한으로 삼지 않는다. AI 출력 자체는 권한 부여나 적용 성공의 증거가 아니다.

AI가 미설정·미인증·한도 초과이면 해당 원인을 표시하고 입력은 보존한다. 공급자 변경으로 전송 범위가 확대되면 그 범위를 먼저 결정한다. 공급자 실패를 모의 성공으로 대체하지 않는다. 재개는 저장된 작업과 확인된 결과에서 새 세션으로 이어갈 수 있으며 불명확한 쓰기를 반복하지 않는다.

02 / 후보와 보호 — SPEC-02.2

근거: FR-04·10·12. 계획 설명과 실제 네이티브 객체 후보를 구분한다. 후보는 생성 결과의 문서·객체 식별자와 기준 버전에 연결된다. 같은 문서에 만드는 후보도 기존 객체의 속성·관계·사용자 변경을 보호한다. 후보 때문에 문서가 수정 상태가 되거나 저장에 포함될 수 있음을 표시한다.

후보를 버릴 때는 해당 후보로 확인된 객체만 제거한다. 전체 문서 Undo나 옛 파일 복원으로 사용자 편집을 되돌리지 않는다. 후보가 직접 수정됐거나 소유권을 확인할 수 없으면 자동 제거·교체를 보류한다. 지원 객체와 변환의 실제 한계는 호스트 지원표가 소유한다.

03 / 적용과 실패 — SPEC-02.3

근거: FR-11·12·16·18. 적용은 특정 후보 버전과 원본 영향 범위에 대한 사용자 지시를 필요로 한다. 이미 명시한 적용 지시는 중복 승인창을 요구하지 않는다. 실행 직전 원본·후보·보존 대상의 관련 변경과 연결 동일성을 재검사한다. 충돌이면 재비교하고 새 조건에 어긋난 후보를 자동 적용하지 않는다.

복수 문서의 적용은 개별 결과를 남긴다. 한 문서의 실패가 다른 문서의 성공을 취소하거나 성공한 쓰기의 재실행으로 이어지지 않는다. 응답 유실은 실패로 단정하지 않고 불명확으로 남겨 해당 대상의 후속 쓰기를 보류한다. 원본 적용 확인과 파일 저장 확인은 별개다.

04 / 개입 — SPEC-02.4

근거: FR-11·15. 조건 변경은 새 조건 버전을 만들고 미전송 명령을 무효화한다. 안전한 중단을 지원하지 않는 진행 중 호스트 연산은 종료 대기를 표시한다. 프로세스 종료 요청만으로 호스트 연산 중단을 선언하지 않는다. 늦은 결과는 이력에 남기고 관련성을 검사한 뒤 현재 후보로 사용할 수 있는지 결정한다. 검사 불가 결과는 보류한다.

05 / 수용 예

같은 적용 요청의 재전송은 객체를 두 번 만들지 않는다. 적용 직후 응답 유실·프로그램 재시작은 자동 재시도를 발생시키지 않는다. A 실행 중 B 조건을 채택하면 A의 늦은 결과가 B를 덮지 않는다. Rhino 성공·ZWCAD 실패는 둘을 구분해 보여 준다.

SDK 객체 조회는 한 번에 제한된 목록을 반환하고 전체 수·다음 위치·기준 revision을 함께 제공한다. 다음 페이지는 같은 revision에서만 읽으며 편집으로 기준이 바뀌면 다시 조회한다. 명시한 객체 ID로 범위를 좁힐 수 있고 이 필터는 다른 문서 접근이나 쓰기 권한을 주지 않는다. 응답 한도를 넘는 객체는 누락 성공으로 처리하지 않고 크기 제한을 알린다.

SDK 실행 성공 응답의 객체/변경 목록도 요약일 수 있다. 전체 변경 건수와 생략 여부를 함께 알리며 저장 후보·영수증·원본 보호 비교는 전체 자료로 수행한다. 응답 요약이 크기 제한에 걸려도 이미 확인된 저장 성공을 실패로 바꾸지 않고 세부 조회가 필요함을 알린다.

06 / 작업 구성·문맥·반복 상한 — SPEC-02.6

근거: FR-08·10·15·18. 시작 전 작업 목적, 변경/보존 대상, 예상 결과, 의존 작업, 전송 자료와 제한을 확인할 수 있다. 상위 필수조건은 하위 작업이 삭제하거나 참고로 낮출 수 없다. 큰 목표를 여러 작업으로 나눠도 같은 조건 버전을 사용한다.

AI 문맥은 확정 조건, 명시된 대상과 기준, 관련 입력 원본, 확인된 완료 결과, 미결/불명확 작업을 우선한다. 요약만으로 원본 근거를 지우지 않는다. 긴 문맥은 필요한 항목을 재조회하고 누락된 필수조건을 복구한 뒤 실행한다. SDK 실행의 초기 모델 문맥은 핀으로 지정한 객체를 우선한 한정 요약이며 전체 목록으로 간주하지 않는다. 전체·포함·생략 수를 명시하고 요약 밖 객체의 형상이나 수량을 추정하지 않는다. 필요한 최신 정보는 허용된 조회로 확인한다. 명시적 입력·핀의 역할·보호 범위는 요약 때문에 삭제하거나 축소하지 않는다. AI 추정은 출처를 유지하며 사용자의 확정 결정으로 저장하지 않는다.

실행 중 조회 완료 수, 호스트 실행 시도 수, 저장·재읽기 검증을 마친 단계 수를 구분해 보여 준다. 계획된 단계 수를 알 수 없으므로 이를 전체 완료율로 표시하지 않는다. 저장된 단계는 작업 사본의 결과이며 원본 적용 완료를 뜻하지 않는다.

실행에는 호출 횟수·경과 시간·호스트 명령 수의 유한 상한을 둔다. 시작할 때 적용 상한을 볼 수 있으며 사용자가 조정할 수 있다. 연속 실패나 같은 기준·같은 제안의 반복으로 진전이 없으면 자동 반복을 멈추고 마지막 실제 후보와 남은 문제를 제시한다. 상한 연장은 로컬 작업자의 새 지시로 기록한다. 사용량 미제공은 0으로 기록하지 않는다. 수치 기본값은 PLAN의 시험 설정이며 OQ-06의 제품 성능 보증이 아니다.

조건 충돌·검토 미완료 후보는 탐색 결과로 보존할 수 있다. 대상·권한·단위·보존 조건을 위반하는 원본 쓰기는 차단하고, 전문 적합성 미검토를 기술적 실행 실패와 혼동하지 않는다.

07 / 적용과 불명확 결과의 해소 — SPEC-02.7

근거: FR-04·11·12·16·18. 적용 지시는 후보 버전·대상·변경 집합에 묶인다. 후보 또는 영향 범위가 바뀌면 기존 지시로 다른 변경을 수행하지 않는다. 원본 생성/수정의 결과를 객체별로 기록한다. 같은 문서의 생성 후보를 원본 결과로 채택할 때 새 복사본을 중복 생성하지 않는다. 기존 객체 수정 후보는 지원된 수정 방식과 보존 속성·관계를 명시하고, 관련성 확인 불가이면 보류한다(OQ-03·10).

상황 해소에 필요한 증거 허용되는 다음 행동
확인된 적용 뒤 캡처 실패 호스트 적용 결과와 변경 객체 캡처/요약만 재생성
전달 전 취소 확인 호스트 미전달 기록 새 조건으로 새 명령 생성

변경 성공 응답 유실 호스트 명령 기록과 대상·객체·변경 지문 일치 기존 명령을 확인으로 종결, 쓰기 재실행 없음

사용자가 ‘확인’ 버튼을 눌렀다는 사실만으로 미반영 증거가 되지 않는다. 증거 없는 강제 성공/재시도 경로는 제공하지 않는다. 호스트 수동 복구가 필요하면 기존 기록을 유지한 채 복구 결과와 새 기준을 확인한다. 자동 전체 문서 Undo는 사용하지 않는다.

저장된 사본을 복구했다는 사실과 원 요청의 전체 목표 달성을 구분한다. AI 응답이 유실된 복구 후보는 목표 완료 미확인으로 표시한다. 단일 대상 요청은 사용자가 복구 후보를 새 기준으로 삼아 원 조건·첨부를 유지한 후속 초안을 만들 수 있다. 기존 대상 핀의 동일 객체 대응을 확인하지 못하면 자동 재연결하지 않는다. 후속 초안은 자동 전송하지 않고 성공분의 재실행 대신 현재 결과 확인과 남은 목표 수행을 요청한다. 복수 대상 부분 결과는 각 대상의 확인 결과를 유지하며 일괄 재실행하지 않는다.

08 / 직접 수정과 개입의 처리 — SPEC-02.8

근거: FR-11·12. 관련 변경의 범위는 읽은 입력 객체·관계, 수정 대상, 보존 대상으로 판정한다. 후보 자체 생성으로 문서가 dirty가 된 것만으로 전체 후보를 무효화하지 않는다. 관련 지문이 같다고 확인되면 무관한 변경은 허용하고, 달라졌거나 확인 불가이면 관련 작업만 재비교한다.

새 지시는 먼저 저장하고 접수를 알린다. 현재 실행에 대한 추가 지시는 대상 작업을 명시한다. 원 조건·핀·스케치·자료를 유지하고 새 조건을 뒤에 연결한 별도 요청으로 먼저 저장한다. 같은 대상·권한을 유지하며, 보존 역할의 암묵 변경이나 대상 교체는 접수하지 않는다. 이전 요청에 중단을 요청하고 실제 종료를 기다린 뒤 원 기준 사본에서 새 조건을 실행한다. 이전 요청이 만든 결과는 이력에 남으며 자동 원본 적용하지 않는다. 결과 불명확 또는 연계 작업의 부분 결과 때문에 안전한 재개를 판정할 수 없으면 새 조건을 보류하고 이유를 표시한다. 재시작은 접수된 새 조건을 보존하지만 자동 실행하지 않는다. 새 조건의 접수·중단 대기와 실행 시작을 분리해 표시한다. 조정 대상과 이미 완료된 범위를 나눠 후속 조건에 채택한 뒤 반영됨을 표시한다. 일부만 채택하면 문서/작업별 이유를 표시한다. 이전 조건의 미전송 명령은 취소하고, 이미 진행 중인 연산은 중단 가능 여부를 확인한다. 중단 불가 연산 뒤 결과는 과거 조건의 결과로 보존한다. 사람 수정 후보를 폐기하려면 달라진 내용과 삭제 대상을 다시 확인한 명시적 지시가 필요하다.

09 / 연계·병렬·부분 결과 — SPEC-02.9

근거: FR-02·04·09·10·11·16. CAD 정보를 Rhino에 사용할 때 원 문서·객체·기준과 좌표 변환·단위를 결과에 연결한다. 문서 간 대응은 일대일로 가정하지 않으며 사용자가 지정하거나 확인한 대응과 추정을 구분한다. 좌표/단위를 확정하지 못한 입력은 참고로 보존하되 자동 기하 쓰기에 사용하지 않는다.

선행 결과를 읽는 후속 작업은 그 결과의 확인을 기다린다. 선행 실패/불명확이면 의존 작업은 보류하고 독립 작업은 계속한다. 같은 문서 쓰기는 직렬화한다. 실행 접수는 프로젝트 전체가 아니라 명시된 문서와 후보 계보의 경합을 검사한다. 같은 원본을 다시 취득한 기준도 같은 대상으로 본다. 대상이 생략돼 독립성을 확인할 수 없는 요청은 같은 호스트 작업과 경합한다. 새 독립 후보임을 명시한 요청은 별도 작업으로 구분한다. 결과 불명확 시 해당 대상의 쓰기만 보류하며, 식별 불가이면 해당 호스트를 보수적으로 보류한다. 독립 요청에도 자원 상한을 적용하고 초과 접수 이유를 표시한다. 여러 문서의 결과 요약은 모두 확인, 부분 확인, 불명확 포함을 구분하고 전체 원자적 적용·복구를 약속하지 않는다. 재개 시 성공분을 다시 적용하지 않는다.

14 / 범용 실행과 복수 실행본의 대상 — SPEC-02.15

실행 방향의 결정 근거는 ADR-014, 구현·비교 시험은 PLAN-02를 따른다.

근거: FR-02·04·08·11·16·18. AI는 SDK 기반 코드와 재사용 함수를 조합하고 실제 오류·결과를 읽어 후속 동작을 정한다. 사용자에게 별도 MCP 설치·수동 설정을 요구하지 않는 제품 연결을 목표로 한다. AI는 조회에서 받은 대상 참조와 코드를 전달하고, 연결 식별·권한·기준·실제 변경 기록은 VIDE가 관리한다. 정밀한 변경 집합이나 권장 코드 스타일을 AI가 사전 선언해야만 실행되는 조건을 추가하지 않는다. SDK 설명은 필요한 부분만 조회하며 전체 문서 반복 전송이나 매 작업 웹 검색을 요구하지 않는다. 호스트/AI 설치·로그인은 별도로 필요하다. 코드 실행은 §1~9의 전송·후보·원본 적용·중단 계약을 우회하지 않는다. 조회 권한은 임의 코드 실행 권한이 아니며, 코드 본문으로 다른 문서 접근을 완전히 차단할 수 있다고 주장하지 않는다.

PRD §14.2의 임의 비신뢰 코드 실행 제외는 임의 업로드 코드/공개 플러그인을 실행하는 범용 서비스를 제공하지 않는다는 범위다. 로컬 작업자가 허용한 설계 과업을 수행하기 위한 AI 생성 SDK 코드는 이 절의 실행 경로이며, 생성 주체가 AI라는 이유로 신뢰된 코드나 OS 샌드박스 안의 코드가 되지는 않는다. 기존 대상·자료 전송·후보 보호·적용 권한을 그대로 적용한다.

동일 종류 호스트의 복수 실행본과 각 열린 문서를 구분한다. 파일명·활성 창이 같아도 대상을 대체하지 않는다. 문서 닫힘·재시작·Save As·복사로 동일성을 확인할 수 없으면 해당 쓰기를 보류하고 재연결한다. 읽기만으로 사용자 파일에 추적 속성을 기록하지 않는다.

Rhino A의 객체를 Rhino B로 복사하면 원본 버전을 읽어 확인한 단위·좌표로 새 객체를 생성하고 원본과 새 객체의 관계를 남긴다. 지원하지 않는 속성·참조 관계는 누락 범위를 표시하고 결과를 완전 복사로 선언하지 않는다. 재접속 때문에 같은 객체를 두 번 만들지 않으며 불명확 쓰기는 §7을 따른다. 다른 문서로 복사했다는 이유로 후속 자동 양방향 동기화가 시작되지는 않는다. 수용 사례는 동명/미저장 문서·창 전환·두 실행본·응답 유실을 포함한다.

15 / 구독 계정 프로필 — SPEC-02.14

근거: FR-08·FR-18. 공급자별 활성 계정을 선택하고 요청 접수 시 고정한다. 동일 계정의 독립 작업 병렬 실행은 기존 규칙을 유지한다. 계정 변경은 기존 계정의 큐·실행·불명확 작업이 해소된 후 다음 요청부터 적용한다. 전환 대기 중 신규 요청 접수는 보류하고 기존 작업 개입은 원 계정을 유지한다. 계정 제거·재로그인은 사용 중 거절한다. 재시작 후 불명확 쓰기 보호를 우회하지 않는다.

인증은 공식 CLI가 소유한다. 기본 로그인은 호환 경로로 유지하며 새 프로필은 독립 로그인한다. VIDE에서 시작한 로그인은 실제 프로세스 종료와 공식 인증 상태 확인까지 진행 중으로 표시하고 같은 공급자의 새 요청·전환·추가 로그인을 보류한다. 로그인 취소/실패는 계정 선택을 바꾸지 않으며 중단 요청과 종료 확인을 구분한다. 확인되지 않은 격리는 지원으로 표시하지 않는다. 사용량 미확인은 0%나 무제한이 아니며 자동 전환·유료 API 우회 근거가 되지 않는다. 사용자가 지정한 모델/effort를 판정 실험이 변경하지 않는다.
