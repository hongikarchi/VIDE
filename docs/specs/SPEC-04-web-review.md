# 외부 웹 공유·의견·검토본


## 웹 의견을 실제 설계 수정으로 이어간다 — SPEC-04.7

근거: PRD §8.7·§12.5·§16.4 과업 ③, FR-06·07·16·18·19. **외부 검토자는 공유된 설계를 보고 공간에 의견을 남기고, 설계자는 그 의견을 실제 수정 작업에 연결한다.** 로컬 IDE의 편집 화면을 원격 제어하는 기능은 아니다.

1. 설계자는 로컬 프로젝트에서 공개할 모델/도면 표현, 표, 후보·작업 상태와 허용 검토본을 선택한다. 공개 범위를 미리 본 뒤 게시하고 프로젝트 검토 링크를 전달한다.
2. 검토자는 링크에서 마지막 게시 상태를 연다. 모델/도면을 탐색하고 객체·표·공개된 후보를 확인한다. 설계자의 현재 카메라나 선택과 같을 필요는 없다. PC가 꺼져 있어도 마지막 게시본을 열 수 있다.
3. 검토자는 객체 또는 위치에 핀을 붙이고 “이쪽을 더 줄여 주세요”라는 문장과 선을 남긴다. 공간 평면에 등록된 선과 화면 주석은 구분한다. 제출하면 서버가 실제 접수한 시각과 기준을 확인한다.
4. 설계자는 IDE의 새 의견 목록에서 그 의견을 연다. 작성 당시 게시본과 대상·원본 선을 보고 현재 상태와 비교한다. 이미 바뀐 대상에 대한 의견이면 그 차이를 확인한다.
5. 설계자는 의견 전체나 필요한 내용을 기존 작업 또는 새 작업의 입력으로 연결한다. 원 의견은 보존하고, 채택한 목표·대상·보존 조건으로 실행 요청을 구성한다. 이때부터 SPEC-02의 후보 생성·조정·적용 흐름이 이어진다.
6. 수정 후 표를 갱신하고 전후 검토본을 남긴다. 허용 범위의 새 상태를 게시하면 같은 프로젝트 링크에서 새 게시본을 확인한다. 이전 기준의 의견은 새 객체로 조용히 이동하지 않는다. 파일 전달은 SPEC-03.8로 이어진다.

첫 동작 검토안은 로컬 작업자가 ‘공유 갱신’을 명시적으로 요청하는 방식이다. 공개 범위 확대와 이미 허용된 범위의 갱신을 구분한다. 이 방식은 수동 Sync와 별개이며, 향후 허용 범위 내 갱신 자동화 여부는 OQ-04에서 판단한다. 게시본/의견의 접수·권한·보존 계약은 §1·2·4·5를 따른다.

**완료 기준:** 모델·표를 보는 데서 끝나지 않고, 실제 제출된 의견을 로컬 설계자가 찾아 같은 대상을 수정하고, 수정 결과·검토본·전달 자료까지 연결할 수 있어야 한다. 검토자가 IDE 미설치 상태에서 이 과정을 이해하는지 확인한다(AC-19·22·28·30·35~37). 합성 의견 카드와 로컬 임시 웹 화면은 실제 접수·PC 종료 후 지속성 검수의 대체물이 아니다.

## 1. 게시 경계 — SPEC-04.1

근거: FR-18·19. 선택한 공개 자료를 별도 게시본으로 만들어 외부 서비스에 보관한다. 마지막 서버 확인 게시본은 로컬 PC가 꺼져도 열람 가능해야 한다. 업로드 실패는 이전 성공 게시본을 유지하고 로컬 최신 상태와 구분한다. 게시본의 범위를 늘리는 일은 자동 동기화의 부수 효과로 수행하지 않는다. 보존·만료·인증 범위는 OQ-04를 따른다.

## 2. 의견과 권한 — SPEC-04.2

근거: FR-06·07·16·18·19. 외부 의견은 게시본 버전과 핀·스케치 기준에 연결한다. 로컬 초안, 서버 접수, IDE 수신, 작업 조건으로 채택, 원본 적용은 서로 다르다. 재전송은 동일 의견을 중복 생성하지 않는다. 원본이 바뀌어도 의견의 대상 버전을 바꾸지 않는다.

외부 열람·의견 권한으로 AI 실행, 호스트 명령, 원본 적용, 로컬 설정 변경을 요청하면 서버에서 거절한다. 같은 사용자의 다른 기기라도 이 권한 경계는 유지한다. 검토 링크 폐기 후 새 접근을 차단하고 이미 내려받은 복사본을 원격 삭제했다고 주장하지 않는다.

## 3. 검수 경계

외부 서비스에서 마지막 게시본 읽기와 의견 저장을 검증한 뒤 로컬 제어 프로세스를 종료해 다시 확인한다. 같은 PC의 임시 서버나 정적 화면 시연은 PC 종료 후 지속성 검수의 대체물이 아니다. 지원 브라우저·iPad 입력 검수는 PLAN §7과 OQ-04에 연결한다.

## 4. 게시 버전과 접근 — SPEC-04.4

근거: FR-16·18·19. 게시 요청은 공개 목록과 선택 기준을 고정한다. 업로드 도중 로컬 결과가 바뀌면 현재 요청에 몰래 포함하지 않는다. 자산·메타데이터 전체를 서버에서 확인한 뒤 해당 게시본을 열람 대상으로 전환한다. 일부 업로드만으로 이전 게시본을 대체하지 않는다. 재접속 시 요청 ID로 서버 결과를 확인하고 이미 성공한 게시를 중복 생성하지 않는다.

공개 범위에서 제외한 입력·숨긴 속성·로컬 경로는 서버 응답/자산에도 포함하지 않는다. 현재 게시본과 과거 검토본마다 접근 범위를 확인하며 현재 링크가 과거 전체 이력 접근권을 자동으로 부여하지 않는다. 권한 만료/폐기 때 새 자료 조회와 의견 제출을 차단한다. 인증 방식·보존 기간·삭제 정책의 구체 값은 OQ-04 결정 전까지 설정 미완료로 취급한다.

## 5. 의견 제출과 로컬 채택 — SPEC-04.5

근거: FR-06·07·16·18·19. 의견에는 작성한 게시본·문서/객체 또는 표현 기준, 본문, 원본 선, 작성자 표시와 제출 식별자를 둔다. 서버 접수 후에는 작성 당시 원본을 보존한다. 새 게시본이 나와도 작성 중 의견의 대상을 옮기지 않는다. 제출 전에 이전 기준에 대한 의견임을 알린다.

| 상태 | 가능한 행동 | 금지할 오해 |
|---|---|---|
| 작성 중·미전송 | 편집·로컬 초안 보관 | 다른 기기나 IDE에 접수되었다고 표시 |
| 전송 중·접수 불명 | 동일 제출 ID로 확인/재전송 | 실패 확정·다른 ID의 자동 중복 제출 |
| 서버 접수 | 접수 시각·기준 확인 | 로컬 실행 조건으로 자동 채택 |
| IDE 수신 | 로컬 작업자가 검토·작업에 연결 | 원본 적용 완료 |
| 작업 조건에 채택 | 원 의견 버전을 참조한 새 조건 생성 | 원 의견/작성자의 문구를 수정 |

웹 초안 저장이 불가하면 화면에 남은 입력과 저장 불가를 알린다. 재접속 시 동일 게시본·초안·제출 상태를 복구하며 서버가 없을 때 접수 성공을 만들지 않는다. 취소와 화면 이동은 실제 접수된 의견의 원격 삭제를 뜻하지 않는다.

## 6. 기기별 입력과 수용 사례

근거: FR-06·19. 모델 선택·회전/이동/확대와 스케치 모드를 분리한다. 스케치 중 탐색 제스처가 원본 점열을 바꾸지 않는다. 포인터 취소 때 미완성 선을 확정하지 않고 유지/취소를 선택할 수 있게 한다. 기기별 제스처 표현은 Design §12 상세를 따른다. 지원 iPad·펜·브라우저 조합과 실제 동작의 확정은 OQ-04와 실기기 검수에 남긴다.

AC-19·28: 전송 직후 응답 유실·재접속에서 의견 하나만 접수되고 원 게시 기준이 유지된다. AC-35·36: 게시 중 실패는 이전본을 유지하고 PC 종료 후 외부 서버에서 마지막 게시본·허용 검토본을 열람한다. AC-30·37: 권한 밖 자산 조회·로컬 실행 요청을 서버에서 거절한다. 표시용 시나리오만으로 이 AC들을 통과 처리하지 않는다.

## 사용자 로그인·프로젝트 초대와 공유 — SPEC-04.8

근거: FR-18·19, PRD §12.5. 사용자는 계정으로 로그인하고 권한 있는 프로젝트를 열며 다른 사용자를 프로젝트에 초대한다. 첫 역할은 소유자·열람자·의견 작성자다. 소유자는 공유 대상과 초대·권한을 관리하고, 참여자는 부여된 역할과 게시 범위 안에서 자료 열람/의견 작성을 수행한다. 로컬 작업의 AI 구독 로그인과 웹 공유 계정은 별개다.

초대는 지정한 수신 계정으로 수락하고 만료·취소·이미 수락한 상태를 구분한다. 탈퇴·권한 회수 뒤 새 조회/의견/파일 접근을 차단한다. 화면에서 링크를 숨기는 것만으로 권한을 집행하지 않는다. 현재 프로젝트 멤버십을 서버에서 확인하며 공개하지 않은 로컬 자료와 과거 이력을 자동 노출하지 않는다. 다운로드 완료 파일과 이미 발급된 임시 링크의 유효기간 한계는 §2·4와 함께 표시한다.

로그인·프로젝트 공유는 동시 네이티브 편집, 원격 호스트 실행, 오프라인 자동 병합을 포함하지 않는다. 두 사용자·두 프로젝트의 교차 접근, 초대 취소/만료, 권한 변경, 직접 파일 접근과 과거 게시본을 검수한다. 구체적인 보존 기간·배포 정책은 OQ-04를 따른다.


### 메일 없는 시험 계정과 참여 승인

2026-09-22 사용자 결정: 무료 시험 환경은 이메일 인증 없이 가입·로그인·본인 프로젝트 생성을 허용한다. 이메일 인증 상태는 미확인으로 보존하며 이메일 주소나 표시 이름만으로 타인의 프로젝트 접근권을 부여하지 않는다. 초대 링크를 받은 계정은 참여 신청을 하고, 소유자가 신청자의 계정 ID·미확인 이메일·이름·역할을 확인해 승인하거나 거절한다. 소유자는 별도 연락으로 의도한 사람인지 확인한다. 이 환경에서 이메일 주소는 신원 증명이 아니다.

승인 전에는 프로젝트·게시본·파일·의견에 접근할 수 없다. 승인 시 현재 소유권·초대 취소/만료·처리 여부를 다시 검사하고 멤버 생성과 처리 기록을 함께 저장한다. 거절·권한 회수 후 같은 신청/링크 재시도로 멤버십을 복원하지 않는다. 새로운 참여에는 새 초대와 승인이 필요하다.

메일 연결 전에는 비밀번호 재설정·이메일 변경·인증 메일 발송을 제공하지 않으며 가입 화면에 복구 불가를 알린다. 비밀번호 분실 시 운영자가 이메일 주장만 믿고 계정을 복구하지 않는다. 후속 메일 인증 전환은 기존 계정의 인증 상태를 보존하고, 기존 미인증 계정의 접근·재인증 절차를 정한 뒤 수행한다. 인증 플래그를 일괄 변경해 전환하지 않는다.

## 작업 PC가 꺼져 있을 때 — 저장된 모델 보기와 요청 남기기 — SPEC-04.9

근거: FR-18·19, [PLAN-20](../plans/PLAN-20-offline-view.md). 2026-09-29 사용자 지시: 링크된 CAD·Rhino 파일은 PC가 꺼져 있어도 계정 사이트에서 볼 수 있고, 작업 요청을 대기열에 걸어둘 수 있다(Cloudflare 무료 용량 안에서).

- **저장 동의:** 저장은 소유자가 작업 PC의 VIDE에서 프로젝트별로 켤 때만 한다(기본 꺼짐). 켜면 그 프로젝트의 보이는 연결 파일마다 마지막 Sync를 보기 전용 모델로 사이트에 둔다. 형상·레이어·화면 색·문자만 담고 원본 파일·객체 속성·<del>대화·작업 이력은</del><ins>대화는</ins> 올리지 않는다<ins>(작업 이력은 §10의 요약만, [ADR-035](../decisions/ADR-035-offline-project-summary.md))</ins>. 끄면 사이트의 저장본을 지운다.

- **최신 하나:** 파일마다 가장 최근에 올린 하나만 두고 교체한다. 계정·사이트 용량 한도를 넘거나 파일이 너무 크면 새 저장은 실패로 PC에 표시하고, 이전 저장본은 그대로 둔다.
- **보는 사람:** 저장본과 요청은 프로젝트 구성원(소유자와 초대된 참여자) 모두가 본다(2026-10-06 사용자 결정 "PC없이 보기는 모든 사용자가 볼 수 있도록", §10의 6).
- **여는 흐름:** PC가 꺼진 프로젝트를 사이트에서 열면 오류 대신 <del>저장된 모델과 요청 화면을</del><ins>§10의 PC 없이 보는 화면(할 일·작업 이력 요약·노트·저장된 모델·요청)을</ins> 연다. PC가 켜져 있으면 기존처럼 PC 작업 화면을 연다(메뉴에서 저장된 모델도 볼 수 있다). 사이트 화면은 보기 전용이다(평면·3D, 레이어 끄기, 문자).
- **요청 남기기:** 구성원은 요청 글과 선택적 대상 파일을 남긴다. PC가 켜지면 VIDE의 연결 파일 목록 위에 "사이트에서 남긴 요청"으로 나타난다. 자동으로 실행하지 않는다. 사용자가 작성기로 가져와 확인한 뒤 보낸다. PC가 가져가기 전에는 사이트에서 취소할 수 있고, 가져간 뒤에는 PC에서 지운다. 같은 요청은 PC에 한 번만 전달된다.
- 이 절은 원격 호스트 실행을 더하지 않는다. AI 실행과 파일 변경은 여전히 작업 PC에서 사용자가 보낸 요청으로만 일어난다.

## PC가 꺼져 있어도 프로젝트 열기 — 할 일·노트·작업 이력 요약 — SPEC-04.10

근거: FR-16·18·19, [ADR-035](../decisions/ADR-035-offline-project-summary.md), [PLAN-33](../plans/PLAN-33-offline-project.md). 2026-10-06 사용자 결정: PC가 꺼져 있어도 프로젝트는 사이트에서 늘 열린다. 모델은 보이지 않아도 된다.

1. **여는 흐름:** 소유자가 사이트에서 프로젝트를 열 때 작업 PC가 꺼져 있거나, 계정에서 로그아웃됐거나, 고를 PC가 없거나, 업데이트가 필요하면 오류에서 멈추지 않고 **PC 없이 보는 화면**을 연다. 화면 위에는 "PC가 꺼져 있어 모델은 보이지 않습니다"를 두고(저장된 모델이 있으면 "아래는 마지막으로 저장된 모델입니다"), 업데이트가 필요하면 그 안내를 함께 둔다. PC가 켜져 있으면 기존처럼 PC 작업 화면을 열고, 카드 메뉴의 "PC 없이 열기"로 이 화면을 볼 수도 있다. 다른 기기(iPad)에서 사이트 중계 주소로 연 작업 화면이 PC가 꺼져 열리지 않으면 그 안내 화면에 이 프로젝트의 "PC 없이 열기" 링크를 둔다.
2. **할 일(읽기·쓰기):** PC가 마지막으로 올린 프로젝트의 할 일(SPEC-01.14)을 보인다. 소유자는 여기서 추가(글·날짜), 완료 표시, 글 고치기, 날짜 바꾸기, 삭제를 한다. 바꾼 항목에는 "PC 반영 대기"를 붙이고, PC가 켜지면 PC가 적용한다. 같은 항목을 PC에서도 그 사이 고쳤으면 더 나중에 고친 쪽이 남고, 항목 글 끝에 충돌 내용(시각, 반영하지 않은 쪽의 변경)을 적는다. PC에서 이미 지운 항목에 대한 변경은 버린다. 아직 PC가 할 일을 올린 적이 없으면 쓰기를 받지 않고 그 이유를 보인다.
3. **작업 이력(요약, 읽기 전용):** 요청마다 요청 글, 답의 처음 몇 줄, 상태(완료·실패·취소·중단·진행 중·대기), 시각, 연결 파일 이름을 최근 것부터 보인다. 모델·첨부·핀·스케치·AI 모델 이름은 없다(ADR-035 1). 사이트에서 이력을 고치거나 다시 실행하지 않는다.
4. **노트:** 공유 노트(SPEC-10)의 최근 노트 목록과 [노트·일지 열기]가 이 화면의 노트 자리에 있다. 노트는 사이트의 것이라 PC가 꺼져도 열리고 고칠 수 있다.
5. **모델:** 저장된 모델(§9)은 사이트의 저장본 스위치가 켜져 있고 소유자가 PC에서 켠 프로젝트에만 있다. 이 절은 그 조건을 바꾸지 않는다.
6. **보는 사람:** 이 화면의 할 일(읽기·쓰기)·작업 이력 요약·노트·저장된 모델·요청은 프로젝트 구성원(소유자와 초대된 참여자) 모두가 소유자와 같이 쓴다(2026-10-06 사용자 결정 "PC없이 보기는 모든 사용자가 볼 수 있도록"). 참여자는 소유자의 PC를 열 수 없으므로 사이트의 프로젝트를 누르면 이 화면이 열린다. 구성원이 아닌 계정은 프로젝트가 없는 것처럼 거절한다(404).
7. **올리기와 끄기:** 계정에 로그인한 PC는 프로젝트마다 할 일과 작업 이력 요약이 바뀌면 사이트에 올린다(기본 켜짐). VIDE의 "할 일·대화 기록을 사이트에 올리기"(ADR-037 4로 대화 기록까지 넓힌 같은 스위치, SPEC-04.12)를 끄면 그 프로젝트의 사본과 요약, 대화 기록을 사이트에서 지우고 더 올리지 않는다. 이 스위치는 저장된 모델 스위치(§9)와 따로 동작한다.
8. 이 절은 원격 호스트 실행을 더하지 않는다. 사이트의 할 일 변경은 PC의 할 일만 바꾸고, AI 실행과 파일 변경은 여전히 작업 PC에서 사용자가 보낸 요청으로만 일어난다.

## 팀이 함께 쓰는 프로젝트 — 목록·AI 지시·정리된 자료 — SPEC-04.11

근거: FR-09·18·19, [ADR-037](../decisions/ADR-037-team-shared-project-layer.md) 1~3, [PLAN-35](../plans/PLAN-35-shared-project-layer.md). 2026-10-06 사용자 결정: 가벼운 것(글·목록·설정)은 서버에서 공유하고 무거운 것(모델 형상·첨부·원본 파일)은 PC에 둔다. 요청·답·대화 전문(ADR-037 4)은 이 절이 아니라 PLAN-36의 범위다.

1. **프로젝트 목록:** 계정 사이트의 프로젝트와 구성원이 원본이다. 계정에 로그인한 PC의 VIDE 프로젝트 고르기는 이 PC의 프로젝트와 **공유받은 프로젝트**(이 계정이 소유자나 참여자인데 이 PC에 없는 프로젝트)를 묶음으로 나눠 보인다. 공유받은 프로젝트에는 소유자와 돌리는 PC 이름·켜짐 여부를 붙인다. 사이트에 닿지 않으면 마지막으로 받은 목록을 보이고 그 사실을 알린다. 로그인하지 않은 PC는 이 PC의 프로젝트만 보인다.
2. **만들기·이름 바꾸기:** 계정에 로그인한 PC에서 만든 프로젝트는 같은 id로 사이트 목록에 오르고, 이름을 바꾸면 사이트에도 바뀐다(SPEC-01.1). 다른 사람의 프로젝트 이름은 소유자만 바꾼다.
3. **원격 프로젝트로 열기:** 공유받은 프로젝트를 고르면 VIDE는 그 프로젝트를 **원격 프로젝트**로 연다. 화면 위에 "이 프로젝트는 ○○의 PC(△△)에서 돌아갑니다. 모델·Sync·AI 작업은 그 PC에서만 할 수 있고, 여기서는 사이트에 올라간 자료를 봅니다."를 둔다. 보이는 것은 §10의 PC 없이 보는 자료(할 일, 작업 이력 요약, 노트 목록, 저장된 모델 목록)와 정리된 자료의 수, AI 지시다. 연결 파일·Sync·작성기·jig·호스트 동작은 없다. 할 일 고치기와 노트 편집은 사이트(§10)와 노트 화면(SPEC-10)에서 한다. 사이트 화면으로 가는 링크를 둔다.
4. **AI 지시(프로젝트 지침):** 프로젝트 AI 지시의 원본은 사이트다. 구성원 누구나(역할 무관) VIDE 설정의 프로젝트 AI 지침, 원격 프로젝트 화면, 사이트의 PC 없이 보기 화면에서 고친다. 각 PC는 사본을 두고 AI 요청마다 지금처럼 넣는다(사이트에 닿지 않아도 사본으로 턴이 돈다). 기본 모델·노력 수준·웹 검색·응답 대기 시간 같은 PC별 선호는 PC에 둔다.
   - **첫 연결:** 이 PC에만 있던 지시는 사이트에 지시가 없으면 그대로 올린다. 사이트에 이미 있으면 아래의 나중 쓰기를 따른다(더 나중에 고친 쪽이 남고 다른 쪽은 충돌 안내로 남는다).
   - **닿지 않을 때:** 고친 지시는 PC 사본에 바로 적용되고 '사이트 반영 대기'로 남았다가 다음 연결 때 보낸다.
   - **나중 쓰기와 충돌:** 판 번호로 비교한다. 내가 본 판 뒤에 다른 사람이 고쳤으면 더 나중에 고친 쪽이 남는다. 남지 못한 글은 고친 사람·시각과 함께 '다른 구성원의 수정과 겹쳤습니다' 안내에 보이고, 사람이 [확인]을 누를 때까지 남는다. 자동으로 합치지 않는다.
5. **정리된 자료:** 진술·이슈·현황 요약과 사람의 검토·출처 제외 규칙(SPEC-08)의 원본은 사이트다. 원본 문서·파일과 자료 수집(크롤러)은 수집한 PC에 있고, 그 PC가 수집 결과가 바뀔 때 사이트에 올린다. 다른 구성원의 PC는 사이트의 결과를 받아 사본으로 두고 자료 화면과 AI 자료 도구는 그 사본을 읽는다(사이트에 닿지 않아도 된다). 원본 열기는 원본 경로가 그 PC에서 열릴 때만 된다(SPEC-08.4).
6. **보는 사람:** 1~5의 자료는 프로젝트 구성원 모두가 같다. 구성원이 아닌 계정은 프로젝트가 없는 것처럼 거절한다(404). 구성원에서 빠지면 다음 목록 갱신 때 VIDE의 공유받은 프로젝트에서도 빠진다.
7. 이 절은 원격 호스트 실행을 더하지 않는다. AI 실행과 파일 변경은 프로젝트를 돌리는 PC에서 사용자가 보낸 요청으로만 일어난다.

## 대화 기록 공유 — 요청·답 전문 — SPEC-04.12

근거: FR-16·19, [ADR-037](../decisions/ADR-037-team-shared-project-layer.md) 4와 2026-10-06 사용자 조정("모델링 대화는 서버에 안 올림"), [PLAN-36](../plans/PLAN-36-conversation-mirror.md). 표 구조는 ARCH-01 「데이터 위치」가 소유한다.

1. **무엇을 올리나:** 그 작업을 돌린 PC가 원본이고 사이트에는 글 사본만 둔다. 요청 하나의 사본은 요청 글 전문, AI 답 전문, 활동 줄(시각·종류·글; 세부 내용은 AI의 생각·메시지·실행 코드 줄만), 실행 코드, 파일 이름(연결 파일·첨부의 이름)이다. 대화에는 제목, 종류, AI 제공자·모델 이름, 시각을 둔다. 모델 형상, 첨부 내용, 핀·스케치 좌표, 조회 결과의 세부(모델 자료가 들어갈 수 있다)는 올리지 않는다.
2. **호스트 문서 없는 대화만:** 요청이 호스트 문서를 쓰지 않을 때만(`hostUse: 'none'`) 올린다. 연결 파일·Sync 기준·원본 문서·대상 파일을 가리키거나, jig·확장을 실행하거나, 결과에 문서 실행 기록이 있는 요청은 모델링 요청이라 그 PC에만 남는다. 섞인 대화는 호스트 문서 없는 요청만 올리고 대화 행에는 제목·종류만 있다. 모델링 요청은 §10 3의 작업 이력 요약(최근 50개, 요청 글·답의 첫 줄·상태·시각·파일 이름)으로만 사이트에 보인다. 판정 규칙은 `shareableRequest`(src/contracts/conversation-mirror.ts)가 정본이다.
3. **올리는 방식:** §10 7의 스위치가 켜진 프로젝트에서 PC는 지난번 올린 뒤 바뀐 요청(상태나 저장 크기가 달라진 것)만 묶어 올린다. 사이트에 닿지 않으면 PC에 남겨 두었다가 다시 올리고, 다시 시작해도 마지막으로 올린 묶음 다음부터 이어 간다. 작업 이력에서 지운(숨긴) 요청은 다음 올리기 때 사이트에서도 지운다. 긴 글은 자르지 않고 여러 행으로 나눠 둔다(ADR-031).
4. **읽는 사람:** 프로젝트 구성원 모두가 사이트의 [대화 기록]에서 대화 목록, 대화 전문(요청·답·활동·코드·파일 이름), 글 검색을 본다. 각 대화에는 누가 어느 PC에서 했는지를 붙인다. 보기 전용이며 사이트에서 고치거나 다시 실행하지 않는다. PC 없이 보기 화면의 작업 이력 요약에서도 [대화 기록 전문]으로 연다. 구성원이 아닌 계정은 404다.
5. **자기 VIDE에서:** 구성원의 VIDE는 작업 이력 아래 '다른 구성원의 대화'에 다른 PC의 대화를 보기 전용으로 보이고(누가·어느 PC), 누르면 대화 전문을 연다. 사이트에 닿지 않으면 마지막 사본을 '사이트 연결 안 됨'과 함께 보인다. AI가 다른 VIDE 작업의 실행 기록을 읽도록 사본을 그 프로젝트의 기록 폴더 `projects/<id>/history/`에 대화마다 Markdown 한 파일과 README로 둔다(노트 사본과 같은 방식, AI는 읽기만).
6. **원본과 끄기:** 한 PC는 자기 행만 바꾸거나 지운다. 다른 PC의 요청 ID와 겹치면 거절한다. 스위치를 끄면 그 PC가 올린 그 프로젝트의 대화 기록을 사이트에서 지우고(사이트에 닿지 않으면 닿을 때까지 다시 시도), 다른 구성원 VIDE의 사본도 다음 읽기에서 사라진다. 개인정보 안내(사이트 `/privacy`)에 이 내용을 적는다.
