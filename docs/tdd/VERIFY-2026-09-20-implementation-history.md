# 초기 구현 이력과 이행 기록

2026-09-24 문서 재배치로 마스터 PLAN의 과거 기록을 옮겼다. 아래는 2026-09-20~21 당시 기록이며 새로운 시험 결과나 현재 지원 선언이 아니다. 실제 증거 파일과 현재 지원은 [PLAN §6.5](../plans/PLAN.md)를 따른다. 과거의 승인 대기·ESM·MCP 경로를 현재 개발 지시로 사용하지 않는다. 문서 이동에는 새 제품 AC 판정을 부여하지 않는다.

## 부록 · 구현 이력 (2026-09-20~21)

아래는 당시 개발 세션이 남긴 작업 기록이며 현재 상태의 정본이 아니다. 현재 티켓·다음 행동은 §6.5, 폴더 책임은 §2.1을 따른다. 이 절의 파일 경로는 TypeScript 전환 이전 이름(`*.mjs`)이며 지금은 같은 위치의 `.ts`/`.tsx`다. 상세 증거는 각 VERIFY와 Git 이력에 있다.

### 입력·뷰포트 보정 — 사용자 피드백 적용

높이 전용 합성 후보 흐름을 범용 대화 제출로 교체했다. 현재 검수는 문장·고정 핀·평면 스케치·모델/effort/permission을 불변 요청 카드로 만드는 흐름이다. AI의 작업 해석을 흉내 내어 임의 후보를 만들지 않는다. 현재 제품에서는 실제 CLI 해석·Rhino 후보 생성·저장/재열기·메시/선 재조회가 연결됐다. TXT·MD·CSV·JSON 참고 자료는 파일당 50KB까지 내용을 전달한다. 기존 사용자 원본에 대한 적용은 미완료다.

뷰포트는 `viewport.mjs`, 문맥/제출은 `model.mjs`, 화면 연결은 `app.mjs`로 분리한다. 목업 전용 package.json/lock에 Three.js 0.186.0을 고정하고 `npm.cmd ci --prefix tools/mockups/workspace --ignore-scripts`로 재현한다. 런타임 CDN/inline script를 쓰지 않으며 정적 서버가 지정한 모듈 경로만 제공한다. OrbitControls의 bare import는 제공 시 로컬 Three 모듈 경로로 매핑하고 원 패키지는 변경하지 않는다.


뷰포트 카메라는 원근/정투영 인스턴스를 분리한다. 앞/위/옆·스케치에서 정투영, 3D에서 원근을 사용하며 resize는 각 투영 행렬을 갱신한다. 전체 보기는 합성 객체 경계 상자의 카메라 방향별 범위와 뷰포트 종횡비로 계산한다. 근거와 검사 결과는 VERIFY-2026-09-20-workspace-review §7에 있다.


### 개발 위임 참조

현재 개발 위임과 자율 진행 기준은 [개발 가이드 §12](../../DEVELOPMENT_GUIDE.md#development-delegation), 실행 제약과 다음 행동은 이 문서 §6.5를 따른다.

### 실제 작업 공간 구현 경로

- `src/ui`: 제품 화면·3D 표시·작성기·API 연결. `tools/mockups/workspace`는 과거 합성 검수본이다.
- `src/core/workspace.mjs`: 기존 SQLite에 별도 요청 테이블을 추가한다. 프로젝트별 동시 쓰기 거절, 요청 ID 멱등, 이전 후보 기준 선택, 핀 기준 버전, 재시작 상태를 보존한다.
- `src/core/geometry.mjs`: AI의 유한 JSON 명령을 검증한다. 일반 코드 실행과 임의 파일 경로를 입력 계약으로 받지 않는다.
- `src/server/execution.mjs`: 공식 구독 CLI에 선택 입력·최근 대화·기준 객체·측정값을 전달한다. 공급자 자동 교체는 없다.
- `hosts/rhino`: 설치된 로컬 MCP의 길이 접두 JSON 전송과 고정 RhinoCommon 프로그램. headless 작업 사본에서 생성·검증·새 파일 저장 후 다시 읽는다. 쓰기 응답 유실은 자동 재시도하지 않는다.
- 3dm 가져오기는 64MB/500개 객체까지이며, 원본을 수정하지 않고 m 단위의 사본을 만든다. 새 후보는 별도 파일로 남고 SHA-256 기준 변경을 검사한다. 현재 지원되지 않는 임의 형상 편집을 박스로 대체하지 않는다.
- 측정값은 기하 면적/체적이다. 건축면적·연면적 산출로 표시하지 않는다. 검토본은 뷰포트 PNG와 기록/측정값을 포함한 단독 HTML이며 외부 게시 기능과 구분한다.

이 단계의 실제 검증은 VERIFY-2026-09-20-native-workspace가 소유한다. 실제 화면은 `npm.cmd start`의 개인 실행 링크에서 제공한다. 현재 작업 환경에서는 기존 검수 포트 4317을 실제 서버로 전환했다.

ZWCAD 경로는 `hosts/zwcad`의 COM 작업자로 제공한다. 새로 만든 문서에 고정된 참조를 사용하며 전역 ActiveDocument나 앱 종료를 사용하지 않는다. 입력은 검증한 XY 폴리라인, 결과는 네이티브 DWG·재열기 점열/면적이다. 기존 DWG 가져오기·원본 적용·다중 문서 동시 실행은 별도 남은 작업이다. 작업별 `host`를 고정하고 다른 호스트 핀은 참조 기하만 전달한다. 결과 기준 파일과 핀의 프로젝트/호스트 혼동을 거절한다.

사용자 실행은 `npm.cmd run workspace`이며 개인 실행 링크를 기본 브라우저로 연다. 현재 설치본/로그인을 사용하는 경로이고 별도 PC 설치 검증을 대신하지 않는다.


### 구현 보강 — 입력 보호와 수량표

스케치 좌표 입력/수정/삭제는 `src/ui/sketch.mjs`, 요청 항목 편집은 `requests.mjs`가 맡는다. 요청 묶음은 순서가 보존된 본문과 공통 핀·스케치·자료로 제출하며 서버가 수락하기 전에는 초안을 지우지 않는다. 핀의 변경/유지/참고 역할을 표시하고, 유지·현재 기준 참고 객체를 바꾸는 제안은 `protectGeometry`에서 호스트 호출 전에 거절한다.

`src/core/quantities.mjs`는 저장된 네이티브 결과 기준으로 개별 수량과 알려진 값 합계/미상 개수를 산출한다. API는 프로젝트·후보 ID로 격리한다. CSV에 기준·단위·출처를 포함하고 수식 시작 문자를 무해화한다. 현재 유형·객체별 조회와 결과별 CSV이며 필터/그룹 정의 영속화와 법정 면적은 지원 완료가 아니다.


### 후보 비교 구현

`src/core/comparison.mjs`와 프로젝트별 비교 API는 후보의 명시적 기준 체인을 확인한다. 같은 호스트의 연결된 후보에서 객체 추가/삭제/변경/동일과 알려진 수량 차이를 표시한다. 다른 호스트·기준 관계가 없는 과거 기록은 비교 불가이며 이름 일치로 동일성을 만들지 않는다. 실행 결과에 실제 사용한 기준 후보 ID를 보존한다. 수량표에서 비교할 이전 후보를 선택한다. 전체 검토본/웹 비교 완료는 아니다.


실제 후속 검수에서 8×6×6 m → 8×6×4.5 m의 클릭/핀 수정과 체적 −72 m³ 비교가 구독 CLI·Rhino·API·브라우저 전 구간을 통과했다. `VERIFY-2026-09-20-native-workspace`의 실제 재검증 절을 따른다. 다음 미완료 범위는 원본 적용·복구, 기존 도면 입력과 필터/검토본·웹·확장·설치다.


### 호스트 응답 유실·재시작 보호

호스트 호출 직전에 의도한 객체 집합·기준 후보를 저장한다. 이 단계에서 프로세스가 종료되면 재시작 시 `unknown`으로 복구하며 일반 AI 응답 중단과 구분한다. 같은 프로젝트/호스트의 새 후보 쓰기는 보류하고 읽기 검토는 허용한다. 응답 유실 오류에도 의도 기록을 보존한다. 아직 호스트 증거를 읽어 불명확 결과를 해소하는 UI/어댑터는 남아 있으며 확인 버튼만으로 해제하지 않는다.


### 경계 정점 수정·이동 복사

유한 기하 계약에 `vertices`(생성된 폴리라인/돌출의 정점 대체)와 `copy`(생성된 박스/폴리라인/돌출의 명시적 이동 복사)를 추가했다. 돌출 경계의 닫힘·XY 평면·기존 높이를 검증하며 좌표/명령 상한을 유지한다. 가져온 임의 네이티브 객체의 복사는 지원한다고 표시하지 않는다. 실제 Rhino 시험에서 경계 폭 변경 후 두 Extrusion의 체적 각 45 m³, 높이 6 m, 복사 위치 +10 m 및 저장/재열기를 확인했다.


### 열린 Rhino 문서의 식별 조회

`hosts/rhino/documents.mjs`는 Rhino 프로세스 ID·시작 시각과 문서 RuntimeSerialNumber를 함께 확인한다. 열린 문서의 이름·단위·객체 수·modified 상태와 지정 문서의 현재 선택 ID를 읽는다. 활성 문서에 기대지 않으며 프로세스/문서 불일치는 거절한다. 왼쪽 ‘열린 Rhino 문서’는 조회 전용이고 작업 기준으로 취득/원본 적용을 완료했다고 표시하지 않는다. [OpenDocuments](https://developer.rhino3d.com/api/RhinoCommon/html/M_Rhino_RhinoDoc_OpenDocuments.htm), [RuntimeSerialNumber](https://developer.rhino3d.com/api/rhinocommon/rhino.rhinodoc/runtimeserialnumber)를 기준으로 구현했다.


### 열린 Rhino 문서에 생성 후보 적용

`src/server/application.mjs`는 영향 검토와 적용을 분리한다. 검토한 문서 인스턴스·전체 객체 형상/속성 지문·후보 파일 지문을 10분짜리 서버 검토 항목에 묶고 기존 Store의 승인 해시·명령 큐·결과 기록을 사용한다. 명시적 적용 버튼이 확인한 명령만 실행하며 중복 요청은 같은 결과를 반환한다. 서버 재시작 후 검토 항목은 다시 만들고 진행 중 쓰기는 기존 큐의 unknown 보호를 따른다.

`hosts/rhino/application.mjs`는 실제 호출 안에서 프로세스/문서와 양쪽 지문을 다시 확인한다. generated box/polyline/extrude만 허용하며 단위를 변환한다. 프로젝트 소유 객체를 GUID 유지 Replace로 수정하고 새 객체에는 소유 표식을 붙인다. 미포함 소유 객체만 삭제하며 무관한 객체는 건드리지 않는다. 잠김/참조 객체는 보류한다. 변경 후 객체 수·유효성·경계를 재조회한다. 일부 쓰기 또는 응답 유실은 unknown으로 남긴다. 파일 저장은 수행하지 않으며 원본 적용과 저장 상태를 분리한다.

현재 생성 후보의 소유 객체 적용을 실증했다. 가져온 임의 네이티브 원본 편집·ZWCAD 원본 적용·관련 변경만 구분하는 정밀 충돌·호스트 증거 기반 unknown 해소는 남아 있다. 전체 문서 지문 검사는 무관한 편집도 보수적으로 재검토시킬 수 있다. [ObjectTable.Replace](https://developer.rhino3d.com/api/RhinoCommon/html/M_Rhino_DocObjects_Tables_ObjectTable_Replace.htm)와 [CommonObject.ToJSON](https://developer.rhino3d.com/api/rhinocommon/rhino.runtime.commonobject/tojson)을 참고했다.


결과 카드의 표시·후보 행동은 `src/ui/history.mjs`로 분리했다. 앱 제어기는 현재 상태와 화면 간 선택만 연결한다. 작업 갱신 때 사용자가 과거 이력을 읽고 있으면 강제로 맨 아래로 이동하지 않는다. 기존 후보·수량표·다운로드·초안·좁은 화면 회귀를 다시 통과했다.


로컬 API 오류는 작업을 자동 재전송하지 않고 한국어 원인·다음 행동으로 표시한다. 원본 적용의 영향 검토 중에는 닫기·대상 변경·중복 검토를 막아 늦게 도착한 응답이 다른 적용 창에 섞이지 않게 했다. 기능 검증 후 개별 커밋을 남긴다는 사용자 후속 지시를 따른다.


### 열린 문서의 수동 작업 사본 취득

SPEC-01.2·9의 시작 경로를 `hosts/rhino/capture.mjs`와 프로젝트 capture API에 연결했다. 문서 인스턴스와 객체 지문을 확인하고 `UpdateDocumentPath=false`로 새 사본을 기록한 뒤 기존 3dm 취득 경로에서 m 단위 변환·재열기·객체 재조회를 수행한다. 원본 경로·이름·modified 상태가 변하지 않았는지도 호스트 안에서 확인한다. 성공 시 취득 시각·원본 단위·선택 ID·문서 인스턴스를 저장하고, 현재 호스트의 최신 상태라고 표시하지 않는다. 렌더링하지 못한 유형과 개수를 표시하며 원본 파일에는 보존한다.

같은 요청 ID의 재전송은 재취득하지 않고 기존 기록을 반환한다. 실패한 취득은 이전 성공 사본을 유지한다. 이 경로는 원본 쓰기가 없으므로 실패를 원본 적용 unknown으로 분류하지 않는다. 응답 유실 시 임시 사본은 늦은 호스트 작업과 충돌하지 않도록 남긴다. 실시간 동기화·정밀 변경 비교·네이티브 원본 적용 완료를 뜻하지 않는다. 파일 복사 옵션 근거는 [FileWriteOptions](https://developer.rhino3d.com/api/RhinoCommon/html/T_Rhino_FileIO_FileWriteOptions.htm)다.


### 호스트 선택에서 실제 후보 편집까지

열린 문서의 선택을 읽을 때 문서 지문을 함께 확인한다. 취득한 문서 인스턴스/지문과 현재 사본의 객체 ID가 일치할 때만 선택 전체를 요청의 변경 대상으로 첨부한다. 기존 핀의 보존 역할과 본문을 유지하며 중복 첨부·100개 초과·일부 미대응 선택은 안전하게 거절한다. 소스 문서 대응은 후속 후보에도 보존한다. 현재 후보에서 삭제된 원본 선택은 임의로 새 객체에 붙이지 않는다.

실제 합성 문서 취득 → Rhino에서 선택 → 요청에 첨부 → ChatGPT 구독 CLI → X 방향 2 m 이동 후보 → 3DM 저장/재열기까지 연결했다. 대상 체적과 무관한 객체·원본 문서는 유지됐다. 원본 적용은 여전히 생성 후보 범위이며, 이 취득 원본 후보의 적용은 다음 구현 대상이다.


### 취득한 원본의 이동 후보 적용

SPEC-02.13의 원본 이동 경로를 `native-application.mjs`에 분리했다. 최초 문서 취득까지 기준 체인을 따라가 이동량을 산출하고, 같은 객체 집합의 이동만 허용한다. 생성·삭제·혼합 후보를 이동으로 포장하지 않는다. 적용 대상은 취득한 프로세스/문서로 고정하며 취득 시점과 영향 검토/적용 시점의 원본 지문을 비교한다. 후보 파일도 검토 지문과 일치해야 한다.

잠김·참조·그룹·이력 부모/자식·블록 정의·미지원 형상의 이동은 거절한다. 실제 Replace 전 형상을 준비하고 native GUID를 유지한다. 검증은 GeometryEquals, 객체 수, 무관한 형상, 공개 스칼라 속성·그룹 목록·사용자 문자열을 비교한다. Rhino의 Replace 이후 속성 아카이브 내부 표현이 변하는 현상이 있어 속성 ToJSON 원문 일치만을 성공 조건으로 사용하지 않는다. 일반 플러그인 사용자 데이터·데칼·공유 렌더 관계의 보존 검증으로 확대하지 않는다.

실제 합성 원본의 이동 적용과 중복 적용 거절까지 통과했다. 최초 시험에서 속성 바이너리 비교가 실패해 unknown이 남았고 이를 완료로 바꾸거나 재실행하지 않았다. 해당 합성 문서는 `.vide/integration/source-apply-unknown.3dm`으로 보존했으며 새 문서 인스턴스에서 수정 코드를 검수했다. 사용자 원본 Rhino/ZWCAD 문서는 변경하지 않았다. 기존 unknown의 증거 기반 해소는 별도 남은 작업이다.


### 원본 이동 적용의 증거 기반 복구

원본 이동 직전에 GUID별 선언 속성 스냅샷·변경 전/후 형상·단위를 `.vide`의 해당 후보 옆 증거 파일로 기록한다. 원본 문서에도 명령별 증거 SHA-256을 남겨 파일의 손상/변경을 확인한다. 증거 파일은 운영 데이터이며 Git에 넣거나 자동 삭제하지 않는다. `hosts/rhino/reconciliation.mjs`는 원래 프로세스/문서를 다시 읽어 전체 객체 수·ID·단위·선언 속성·GeometryEquals를 검사한다. 기대한 변경 후와 일치하면 성공, 변경 전과 일치하면 원상태 확인, 어느 쪽도 아니거나 증거가 없으면 unknown을 유지한다.

원본 이동 명령의 ‘결과 다시 확인’은 실제 쓰기를 재전송하지 않는다. API는 서버의 저장된 명령만 대상으로 삼고 이전 오류 기록·확인 시각을 보존한다. 기존 생성 후보와 증거가 없는 과거 원본 이동 unknown은 자동 해소하지 않는다. 해당 문서에 대한 추가 쓰기 보류는 실제 증거로 해소된 뒤에만 풀린다. 일반 임의 플러그인/공유 관계의 복구 검증은 지원 완료가 아니다.


### 재사용 가능한 수량표 구성

SPEC-03.1·5·8을 따라 검색·유형·레이어 필터와 유형/레이어 그룹 합계를 연결했다. `table_views`는 프로젝트별 이름·질의 정의·revision·갱신 시각을 저장한다. 저장은 객체 목록을 고정하지 않으며 다른 후보에서 조건을 다시 계산한다. 갱신·삭제는 기대 revision을 요구하고 다른 프로젝트의 구성을 수정하지 못한다. 프로젝트당 200개 구성, 이름 80자, 필터 200자 상한을 둔다.

표는 선택한 저장 기준만 집계하며 원본 최신 여부와 구분한다. 실패 시 마지막 성공 표/CSV 기준을 유지한다. CSV는 필터된 객체 행과 그룹 합계를 행 구분·단위·출처·미상 제외 건수와 함께 내보낸다. 객체 행과 그룹 합계를 합산해 이중 집계하지 않도록 행 구분 열을 제공한다. 저장 UI는 `quantity-view.mjs`, 후보 비교는 기존 모듈에 남긴다.

Rhino 재조회에 실제 레이어와 Curve.GetLength 측정값을 추가했다. 길이 측정이 없는 과거 native 곡선의 화면용 표본 선을 실제 길이로 주장하지 않고 미상으로 둔다. 폴리라인 생성 계약의 선분 길이는 계산할 수 있다. API 근거는 [Curve.GetLength](https://developer.rhino3d.com/api/rhinocommon/rhino.geometry.curve/getlength?overload=1)이며 기본 상대 정밀도 1e-8의 측정이다.


### 이름 있는 고정 검토본

SPEC-03.2·6·8에 따라 프로젝트별 검토본 목록·저장·열람·HTML 다운로드를 연결했다. 저장 시 프로젝트 이름, 입력/핀/스케치/첨부 이름, 후보 측정값과 표 정의, 공개할 표시 이미지, 당시 적용 상태를 복사한다. 이후 입력·수량·적용 상태가 바뀌어도 기존 검토본은 갱신하지 않는다. 원본 파일 경로·첨부 전문·구독 인증정보를 검토본 데이터에 복제하지 않는다. 표시 PNG와 측정값 중심이며 전체 네이티브 파일 복원 기능은 아니다.

`review_snapshots`는 제목·기준 요청·시각·고정 payload를 저장한다. 이름 100자, PNG 문자열 1MB, 검토본 payload 2MB, 프로젝트당 200개 한도다. 로컬 열람은 스크립트/외부 연결을 허용하지 않는 sandbox iframe과 전용 CSP를 사용한다. HTML 다운로드는 자체 포함 이미지·표·상태를 내보낸다. 기존 즉시 내보내기도 실제 원본 반영/미확인 기록을 표시하도록 보완했다. 전체 A/B 검토본 비교·웹 게시·의견 연결은 다음 작업이다.

### 고정 검토본 A/B 비교
SPEC-03.6·8의 검토본 선택을 프로젝트 목록에서 연결했다. A/B 두 검토본의 고정 HTML을 나란히 열고 저장된 표시 형상·속성 차이와 수량 증감을 확인한다. 후보 계보 또는 같은 Rhino 원본 문서/GUID 관계가 확인돼야 객체를 대응한다. 표 정의·단위가 다르면 수량 증감을 계산하지 않으며 미측정 값을 0으로 보정하지 않는다. 표시용 형상 해시는 네이티브 전체 기하의 완전 동일성 보증이 아니다. 표시 데이터가 부족한 예전 검토본은 비교 불가로 표시한다.
구현은 core/review-comparison과 UI 동명 모듈, 프로젝트별 GET review-comparison에 분리했다. 실제 구독 AI·Rhino가 만든 두 후보를 새 검토본으로 저장해 브라우저에서 −72 m³와 −42 m²를 확인했다. 단위·계보·불완전 표시 계약 시험과 390px 화면 폭을 검증했다. 다음 작업은 검토 의견의 원 기준 보존과 수정 요청 연결이며 외부 게시 완료를 뜻하지 않는다.

### 검토 의견의 로컬 보존과 요청 초안 연결
SPEC-04.5의 원 의견·작성 기준 보존 중 로컬 부분을 구현했다. 검토본 열람창에서 전체 또는 객체를 지정해 의견을 별도 review_notes에 저장한다. 본문/원 검토본/요청/대상/접수 시각은 고정되며 동일 제출 ID 재전송은 중복을 만들지 않는다. 결과 유실 시 같은 ID·내용으로 확인하며 재전송 전에 내용을 바꾸지 않는다.
‘기준 후보 열기’와 ‘요청 초안에 첨부’를 분리했다. 현재 후보가 원 기준과 다르면 첨부를 거절하고, 맞으면 원 의견 참조 자료와 대상 핀·요청 조건을 기존 초안에 추가한다. 기존 본문과 보존 역할을 덮어쓰지 않는다. 초안의 기준 후보도 저장/재접속 때 유지한다. 초안 첨부는 AI 실행/채택 완료/원본 적용과 구분한다.
프로젝트별 검토본 notes GET/POST는 기존 로컬 인증 경계 안에 있다. 외부 게시·작성자 인증·서버 간 수신·스케치 의견은 이 구현에 포함하지 않는다. 다음은 실제 설계 과업의 지오메트리 편집 범위를 넓히고 외부 공유의 미결 배포 조건과 독립된 부분을 진행한다.

### 네이티브 작업 사본의 복사 후보
독립된 Brep·Extrusion·Curve·Mesh·Point의 copy 명령을 작업 사본 경로에 추가했다. 원본 네이티브 형상을 박스/메시로 재구성하지 않고 RhinoCommon [GeometryBase.Duplicate](https://developer.rhino3d.com/api/rhinocommon/rhino.geometry.geometrybase/duplicate?version=8.x)와 [ObjectAttributes.Duplicate](https://developer.rhino3d.com/api/rhinocommon/rhino.docobjects.objectattributes/duplicate)를 사용한다. 내부 ID·새 이름만 명시적으로 바꾸며 레이어와 사용자 속성을 복제한다.
같은 요청에서 원 객체 이동·복사·재복사·삭제를 조합해도 명령 순서가 형상을 이중 이동시키지 않도록 원본 기하/속성을 먼저 복제한다. nativeSourceId는 작업 사본의 원 기준을 가리키고 후속 후보에서는 실제 새 GUID를 사용한다. 그룹·잠김·참조·이력·공유 정의 관계는 복사 전에 거절한다. 생성 기준 없는 임의 솔리드의 높이 편집은 여전히 지원하지 않는다. 이 복사 후보의 열린 원본 문서 적용은 미구현이며 기존 native-move 적용 검증에서 거절한다.
실제 브라우저 3DM 입력→객체 핀→ChatGPT 구독 Sol low 1회→Rhino Extrusion 복사→저장/재열기에서 원형 체적 72 m³ 유지, 복사 위치 X+10 m를 확인했다. 사용자의 열린 문서·파일은 변경하지 않았다.

### 점 객체 표시와 선택
nativeType=Point의 실제 원점 좌표를 3D 점으로 표시하고 객체 선택·핀·전체 보기·표준 정투영/원근 전환에 포함했다. 화면 픽셀 기준으로 점/선 히트 영역을 계산하고 점 하나의 전체 보기에서도 카메라가 점 좌표와 겹치지 않도록 최소 반경을 사용한다. 표시 가능 여부는 scene-representation 모듈을 UI·검토본·보고서에서 공유한다. 이전 검토본은 저장 당시 미지원 기록을 그대로 보존한다.

### 실제 치수·길이·레이어 전달
Rhino 재열기 검증의 GetBoundingBox(true) 축별 범위를 boundsSize(m)로 저장한다. Inspector는 이 값을 폭/깊이/높이로 표시하고, 과거 후보의 표시 메시에서만 얻은 범위는 ‘표시 폭’ 등으로 구분한다. 실제 Curve.GetLength와 레이어 이름도 표시한다. AI 문맥의 측정값에는 길이·실제 범위·디코딩된 레이어를 포함하며 표시용 점열을 실측값으로 전달하지 않는다.

### DWG 참고 입력 — 실환경 재검증 대기
T-006의 DWG 업로드를 ZWCAD 전용 읽기 경로에 연결했다. 고유 작업 사본을 읽기 전용으로 열고 모델 공간의 직선 XY LWPolyline만 정점·닫힘·Elevation·단위·Handle·레이어·색·길이·면적으로 읽는다. 지원 밖 모델 공간 객체나 bulge/Normal 조건이면 일부만 성공으로 반환하지 않는다. 작업 사본 바이트 해시가 유지돼야 읽기 성공이다.
참고 입력은 원 도면 편집을 지원한다고 표시하지 않는다. 같은 DWG 기준의 후보 쓰기는 AI 호출 전에 거절하며 경계를 핀으로 첨부해 Rhino로 넘기는 경로가 대상이다. 구체 읽기 의미는 ZWSOFT COM 지원 문서와 호환 ActiveX의 GetBulge 계약을 조사했으나 설치본 실증으로 별도 확인해야 한다.

### AI 실행 경로 설정
SPEC-05.2·5의 로컬 AI 설정을 보조 화면으로 연결했다. Claude Code와 Codex의 실행 파일 경로는 ai_settings에 버전과 함께 저장하며 비우면 환경/기본 경로를 사용한다. 인증 토큰·API 키·임의 셸 명령은 설정 계약에 포함하지 않는다. 로컬 절대 경로의 claude.exe/codex.exe와 파일 존재를 검사하고 오래된 수정은 거절한다.

### 신뢰 확장의 등록·실행·비활성화
SPEC-05.4·7의 개발자 제공 object-summary 확장을 허용 목록에 추가했다. manifest는 이름/버전/계약 1/저장된 선택 입력/요약 출력/model.read/중단 미지원 선언을 가진다. 등록은 버전 충돌을 검사하고 비활성화는 새 호출을 차단한다. 임의 파일 업로드나 경로를 실행 모듈로 읽는 등록은 없다.
Extensions는 확장에 저장된 객체 ID·유형·레이어 사본만 전달한다. 저장소·파일 경로·호스트 명령 핸들은 넘기지 않으며 신뢰된 정적 모듈을 같은 프로세스에서 실행한다(임의 코드 격리 보증 아님). 결과의 유형·객체 집합·중복·개수를 검증하고 실패를 작업 기록으로 남긴다. extension provider는 전용 실행 API에서만 생성되며 일반 AI 요청 API에서는 거절한다.
실행은 한 번에 100개 이하 저장된 선택에 대해 동기적인 요약 계산으로 끝나며 실행 도중 중단 기능을 주장하지 않는다. 같은 제출 ID는 비활성화 이후에도 기존 결과를 조회한다. 결과 카드에서 원 기준의 객체를 찾아갈 수 있고 이전 후보·입력은 바뀌지 않는다.

### 로컬 실행 재사용과 종료
SPEC-05.3·6의 재개 경로에서 --open으로 다시 실행하면 동일 데이터 디렉터리의 제어 잠금을 새로 얻지 않고, 기존 launch.json의 loopback 주소/토큰으로 실제 VIDE 인증이 되는지 확인한 뒤 기존 창을 연다. 인증되지 않는 오래된 주소·외부 URL로 연결하지 않는다.

### Windows 실행 패키지
SPEC-05.3·6에 따라 src/desktop의 C# 실행기와 빌더를 추가했다. npm run package:windows -- <버전>으로 .vide/releases에 기존 산출물을 덮어쓰지 않는 ZIP을 만든다. Node 24.15.0 x64와 필요한 Three 파일·라이선스·SHA-256 목록만 포함한다. 사용자 데이터·인증·호스트/CLI 설치본은 포함하지 않는다. 공식 Node 고지는 https://raw.githubusercontent.com/nodejs/node/v24.15.0/LICENSE 에서 고정 버전으로 취득했다.
압축 해제 후 VIDE.exe를 실행하며 기본 데이터는 %LOCALAPPDATA%/VIDE에 둔다. 앱 종료 후 새 버전 폴더에서 실행할 수 있으나 DB 버전 변경의 백업/복구는 후속 작업이다. Codex는 명시 경로 다음으로 알려진 npm/데스크톱 설치 위치를 제한적으로 확인한다.
0.1.0-dev.20260920.1 패키지의 생성·해시·공백 경로·개발 Node 없는 PATH·브라우저·공식 Codex 구독 연결·중복 실행·재시작·실행 폴더 제거 후 자료 보존을 현재 PC에서 검증했다. 별도 PC 설치, 서명, 외부 배포, ZWCAD 미응답 문제 해결은 완료로 세지 않는다.

### 기존 데이터의 쓰기 전 호환성 검사
SPEC-05.6에 따라 단일 제어 잠금을 얻은 뒤 기존 DB를 읽기 전용으로 열어 quick_check와 단일 schema_version=1을 확인한다. 다른 버전·여러 버전 행·다른 앱 DB·읽기 실패는 WAL 설정/테이블 생성 전에 거절한다. 실패하면 제어 잠금을 해제하며 기존 DB를 초기화하지 않는다. 새/빈 DB는 기존 초기화 경로를 따른다. 자동 백업·마이그레이션·사용자 복구 UI는 별도 남은 작업이다.

### 종료된 작업 공간 백업
SPEC-05.3·6의 보존 경로로 src/core/backup.mjs와 src/desktop/backup.mjs를 추가했다. 앱과 같은 제어 잠금을 얻어야 하며 실행 중인 앱을 자동 종료하지 않는다. Node의 [SQLite backup API](https://nodejs.org/download/release/latest-v24.x/docs/api/sqlite.html)를 사용해 DB를 복사하고 models/cad-models의 파일 해시를 대조한다. 기존 백업 폴더·데이터 폴더 내부 목적지·심볼릭 링크는 거절한다. 실패한 부분 폴더를 유효한 백업으로 표시하지 않으며 완료 manifest는 마지막에 기록한다.
개발 실행은 `npm run backup -- create "<데이터 폴더>" "<새 백업 폴더>"`, 확인은 `npm run backup -- verify "<백업 폴더>"`다. 패키지에는 동봉 Node로 같은 명령을 실행하는 START-HERE 안내가 있다. 백업에는 로그인 파일이나 launch 토큰을 포함하지 않는다. 앱 DB의 경로 설정과 프로젝트 자료는 포함되므로 로컬 사용자 자료로 취급한다.
복구 시에는 앱을 종료하고 백업 검증 후 기존 데이터 폴더를 별도로 보존해야 한다. 모델 파일 참조가 절대 경로이므로 manifest.source와 동일한 데이터 경로에 DB·models·cad-models를 함께 복원한다. 현재 도구는 기존 데이터를 덮어쓰는 복원·경로 이관·마이그레이션을 자동 수행하지 않는다. 백업은 로컬 기록/후보를 보존하며 외부 호스트 원본이나 브라우저의 미제출 초안까지 포함하지 않는다.

### 프로젝트별 수동 초안 복원
SPEC-01의 프로젝트/입력 기준 보호를 수동 저장본에도 적용했다. 브라우저 저장 키와 envelope에 projectId를 넣고 다른 프로젝트나 알 수 없는 기준 후보는 현재 초안을 유지한 채 거절한다. 저장 당시 후보를 선택해 화면과 입력 기준을 함께 복원한다. 명시적으로 기준이 없는 초안은 최신 후보에 자동 연결하지 않으며 재열기에도 유지한다. 과거 공용 v3 저장본은 삭제하지 않지만 프로젝트 소속을 추정해 불러오지 않는다.
초안 메뉴 항목 증가로 summary가 헤더 위로 밀리던 배치도 수정했다. 버튼은 헤더 아래 드롭다운 안에서 표시되며 390px 화면에서도 화면 안에 남는다.

### DWG 가져오기 응답 유실 복구 — 2026-09-21
SPEC-00·05.5의 결과 확인 원칙을 읽기 전용 DWG 가져오기에 적용했다. 업로드 당시 SHA-256과 import 단계를 실행 전에 저장한다. unknown 카드의 결과 확인은 같은 요청 경로의 DWG 복사본을 저장 해시와 대조한 뒤 읽기 전용으로 검사한다. 최초 import/copy를 반복하지 않는다. 동시 확인은 하나의 진행 Promise를 공유하고 완료된 확인은 기존 결과를 반환한다.

### 3.3 단계별 전환 계획

관련 티켓은 기존 T-013(계약), T-014·016(화면), T-015(뷰포트), T-004·018(실행), T-011(패키징)을 사용한다. 전환 자체를 새 제품 기능이나 범위 축소로 취급하지 않는다.

| 1. 기준선·공통 계약 | 기존 자동/브라우저 시험과 데이터 예제를 고정. src/contracts에 요청·후보·객체 참조·이벤트 타입과 런타임 스키마를 필요한 범위부터 정리 | 타입은 스키마에서 유도하거나 동일 원본을 사용. 외부 데이터 오류·다른 프로젝트/낡은 기준 거절이 유지됨 |

3D 선정은 Speckle·xeokit 추가 분석까지 반영하여 ADR-017로 확정했다. 5단계는 엔진 교체 없이 TypeScript 어댑터와 React 수명 통합으로 수행하며 스냅·단면·대형 모델 등 개별 기능 검증은 생략하지 않는다.

**전환 상태 (2026-09-23):** 1~5단계는 완료다. 제품 런타임(`src/ui`·`ai`·`core`·`server`·`contracts`, `hosts/*` Node 어댑터)은 전부 TS/TSX이고 strict 검사와 웹/서버 빌드가 통과한다. 남은 `.mjs`는 `src/desktop/build.mjs`·`backup.mjs`(패키징 스크립트), `tests/`, `tools/`이며 이들은 전환 대상이 아니다. 6단계 중 패키징은 검증했고(§6.5 T-011), PLAN-02 실행·호스트·공유 기능은 진행 중이다. 실제 진행은 1~4단계와 SDK 실행기·공유 구현이 같은 날 병행됐으며 "다음 대규모 전환을 겹치지 않는다"는 원칙은 이후 작업에 적용한다. 증거는 [TS 전환 VERIFY](../tdd/VERIFY-2026-09-22-typescript-foundation.md)다.

현재 HTTP의 Host/Origin·세션·CSP·작업별 MCP 토큰 검사를 보존한다. Vite 개발 연결은 개발 전용 경로로 구성하고 운영의 CORS/CSP 완화로 해결하지 않는다. Vite의 변환 성공은 TypeScript 타입 검사 성공이 아니다. 서버는 빌드된 ESM JavaScript를 Node로 실행하며 사용자가 TypeScript/Vite를 별도 설치하지 않게 패키징한다. 문서 HTML 렌더러 tools/docs는 제품 React 전환 대상이 아니다.

각 묶음은 기존 동작과 새 구현을 대조하고 통과 후 커밋한다. 실패하면 해당 묶음을 고치며 다음 대규모 전환을 겹치지 않는다. SQLite·모델 원본을 되돌려 언어 전환 실패를 해결하지 않는다. 신규 파일은 기존 폴더 책임에 넣고 장기적으로 JS/TS 이중 구현을 유지하지 않는다.

#### 공통 설계 3.1 · 첫 구현의 선택과 기술 실험 경계

기존 ESM JavaScript/CSS 구현과 검증은 이행 기준선으로 보존한다. 이후 구현 기준은 §3의 확정 스택과 §3.3의 전환 순서다. 전환을 위해 프로젝트를 재초기화하거나 UI·API·저장 계약을 동시에 교체하지 않는다.

클라우드 저장/인증 공급자와 설치 패키저는 외부 공개·배포 단계에서 결정한다. 첫 프런트에 클라우드 접근을 필수 의존성으로 넣지 않는다. 계정·정책 미정은 PLAN §9.2의 해당 작업만 제한한다. 설치형 래퍼가 추가되더라도 입력·작업·후보의 계약은 유지한다.

### 공통 설계 5 · 실제 연결

**레거시 구현·이행 기록:** 아래 빈 tools/MCP·구조화 제안 변환은 현재 코드의 동작이며 새 설계의 요구가 아니다. 새 기준은 PLAN-02 §1~3, 시험/교체 순서는 §6이다. 기존 지원 경로의 검증 근거를 보존하기 위해 남긴다.

호스트 어댑터는 연결 등록 후 인증된 로컬 명령을 가져와 문서 동일성을 확인한다. 명령 가져오기와 UI 문맥 실행은 분리한다. 최초 후보는 폴리라인 생성·기존 대상의 변환 복사이며 SDK 실험에서 실제 가능 범위를 선언한다. 원본과 후보의 관련 형상·속성 지문을 비교한 뒤 적용한다. 저장·재열기까지 확인하기 전 네이티브 지원 완료로 표시하지 않는다. 기존 사용자 문서 대신 새 합성 시험 문서를 사용한다.

Claude Code는 설치 경로와 로그인 상태를 확인하고 독립 작업 폴더에서 safe mode·빈 tools·빈 strict MCP로 시작한다. 기본 모델은 사용자가 설정한 CLI 선택을 따르고 무단 모델 전환이나 API 과금 fallback을 하지 않는다. 사용자 승인 자료를 표준 입력으로 보내고 진행·최종 결과를 읽는다. 구조화 결과는 허용 작업 종류·대상·유한 수치·좌표 단위·보존 조건을 검증한 뒤 다음 명령으로 변환한다. 강제 종료는 생성한 프로세스 ID에만 적용하고 종료 확인 전에는 stopping을 유지한다. Windows 자식 프로세스 종료 실패도 결과에 남긴다.

첫 확장 후보는 지원 객체 속성 요약이다. 등록·실행·실패·비활성화를 동일 프로젝트/입력 계약으로 시험한다(OQ-07). 웹 서비스는 PC 밖에서 게시본을 지속 보관해야 한다. 배포 위치·인증·보존 결정(OQ-04) 전에는 계약과 로컬 통합 시험을 구현하고 실제 외부 서비스 통과로 집계하지 않는다.

Codex 경로도 T-004에 포함한다. `src/ai/providers.ts`의 `claude-cli`·`codex-cli` 선택으로 같은 입력·결과 계약을 사용한다. `src/ai/codex-cli.ts`는 공식 CLI의 ChatGPT 로그인 여부를 검사하고, API 인증·API 자격 증명 환경 변수는 사용하지 않는다. `codex exec --json --ephemeral --ignore-user-config --ignore-rules --sandbox read-only`를 빈 임시 폴더에서 실행한다. 셸·앱·플러그인·브라우저·이미지·멀티에이전트 기능을 끄고 웹 검색·MCP·개인 문서 자동 주입을 제한한다. 예상하지 않은 도구 이벤트는 실행 실패로 처리한다. 모델은 옵션으로 명시하거나 CLI 기본값을 사용하며 자동 대체하지 않는다.

공통 프로세스 수명·입력 선택 로직은 두 경로에서 재사용한다. 현재 공급자 선택은 어댑터 생성 계층까지 구현됐고, 로컬 화면의 AI 선택·대화·호스트 실행 연결은 후속 T-004·005 작업이다. Codex의 비치명적 오류 항목은 원문 없는 경고로 구분하며 최종 성공 이벤트와 종료 코드를 모두 확인한다. CLI가 사전에 모든 도구를 제거했는지의 일반 보증과 관리자 설정 조합 검증은 합성 응답 시험으로 대체하지 않는다.

공식 구독 연결 조건과 Codex app-server 대안은 PLAN-01 §3을 따른다. 위 exec 경로는 현재 기반 구현 설명이며 최종 UI 연동 방식을 고정하지 않는다. 공급자 간 인계는 제품 기록으로 구성하고 실제 전환·취소·중복 쓰기 검증 후 연결한다.

#### 공통 설계 5.1 · 어댑터 handshake와 실행 제한

호스트 handshake는 adapterProtocolVersion, hostVersion, hostInstanceId, documentSessionId, supportedCapabilities, unit 정보를 전달한다. 인증은 UI 세션과 별도 로컬 pairing 자격을 사용하고 설치 시 전달한다. 자격은 로그·게시·내보내기에 포함하지 않는다. 버전/능력 불일치 때 기능별 미지원으로 응답하며 다른 활성 문서로 대체하지 않는다.

읽기/변경/저장 확인은 별도 능력이다. 명령 결과는 nativeRefs, before/after 지문, operation outcome, fileSaveObservation을 분리한다. 후보 tag는 소유권 단서이며 복제·사람 수정 가능성이 있으므로 tag 하나만으로 삭제를 승인하지 않는다. 이 계약의 두 SDK 실행 문맥과 영속 receipt 가능 범위는 T-003·005·006에서 실험 후 지원표에 기록한다.

첫 개발 시험의 AI 상한 제안은 실행당 8회 모델 호출, 120초 모델 호출 시간, 20개 호스트 명령, 같은 제안/기준의 연속 무진전 2회다. 이는 조정 가능한 합성 시험 설정이며 제품 성능 목표가 아니다. 호스트 연산의 시간 초과는 강제 롤백이 아니라 종료 미확인으로 처리한다. 호출·명령·취소·재개 검증 후 실제 과업 자료로 기본값을 조정한다.

#### 공통 설계 5.2 · 설계 요청을 수행하는 AI 실행 루프

**레거시 실행 계획:** 제한된 구조화 제안 방식은 이행 중에만 유지한다. 범용 코드 실행·개입·상한은 PLAN-02 §2, 단계별 전환은 §6이 소유한다.

SPEC-02.11의 구현 책임은 application의 작업 조정기와 `src/ai/`의 공급자 어댑터에 나눈다. CLI는 추론과 다음 동작 제안을 제공하며 실제 호스트/계산 도구는 VIDE가 실행한다. 이는 현재 ‘도구 없는 응답’ 어댑터만으로 구현된 상태가 아니다. T-018에서 공통 실행 루프를 추가한다.

1. 저장된 문장·핀·원본 선·치수·확정 조건으로 request context를 구성한다. 공급자에는 허용 자료와 현재 capability 목록을 전달한다. 전체 모델/대화의 무조건 전송은 하지 않는다.
2. AI 응답을 `clarification`, `proposeTasks`, `requestRead`, `proposeCandidateOps`, `explainResult`의 구조화 결과로 검증한다. 사용자에게 보이는 문장과 실행 인자를 분리한다. 해석 불가는 실제 쓰기 전에 교정하거나 이유를 제시한다.
3. `requestRead`는 허용된 객체/속성/계산을 조회하여 실제 도구 결과를 돌려준다. `proposeCandidateOps`는 타입·대상·좌표·단위·보존 조건·능력을 검사한 후 후보 명령으로 변환한다. 원본 적용 권한을 이 제안으로 만들 수 없다.
4. 실제 호스트 결과와 수량을 읽고 기록한다. AI에 필요한 요약/참조를 보내 다음 보정 또는 종료를 판단하게 한다. 검사 가능한 수치는 도구 결과를 사용하고 불필요한 모델 재검증 호출을 추가하지 않는다.
5. 후보 DTO에는 실제 객체 참조·표시 자산·변경 요약·측정값·입력 기준을 연결한다. 이벤트는 그 확인된 결과를 UI에 전달한다. 사용자는 작업 진행 중 후보를 탐색하고 지시할 수 있다.
6. 추가 지시를 받으면 관련 작업의 조건/미전송 명령을 조정하고 마지막 유효 결과에서 이어간다. 호출별 모델 세션과 사용자가 보는 작업을 동일시하지 않는다. 종료·상한·불명확 처리에는 기존 SPEC/큐 계약을 사용한다.

네이티브 도구의 첫 목록은 선택 읽기, 객체/속성 조회, 지원 경계 생성/정점 수정/이동/복사, Rhino 돌출 후보, 후보 조회/폐기, 기본 측정이다. 정확한 유형과 인자는 호스트 지원안 검증 뒤 계약으로 고정한다. 생성 코드 열람이 필요하면 실제 실행한 명령/생성 코드를 작업 진단에 연결하며 존재하지 않는 코드를 만들어 보여주지 않는다. 임의 셸 명령 실행을 이 경로에 추가하지 않는다.

**적용 경로는 추론 루프와 분리한다.** UI의 특정 후보 적용 지시는 저장된 변경 집합으로 명령을 만든다. 적용 버튼 처리 중 새 AI 설계 결과로 후보를 교체하지 않는다. AI 제안·호스트 receipt·화면 표시의 run/condition/candidate 버전이 맞는지 검증한다.
