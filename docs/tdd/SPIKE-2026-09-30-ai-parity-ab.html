VIDE 안 AI와 터미널 Claude Code의 모델링 동등성 A/B

상태: 아직 실행하지 않음. 도구와 판정 기준만 준비했다. Rhino가 비어 있을 때 사람이 tools/ab/README.md 절차로 실행하고 아래 표를 채운다.

00 / 질문

사용자 관찰(2026-09-30): VIDE 안 AI가 터미널 Claude Code보다 모델링을 못 한다. 원인 후보는 기본 시스템 프롬프트 대체, 결과를 볼 수 없음(화면·측정 없음), 좁은 도구 예산·읽기 범위, 이전 교환 전달 방식, 질문 불가였다(RESEARCH-10 §1·§8). 이번 물결은 기본 프롬프트 유지 + VIDE 지시 묶음 추가, 화면·측정 도구, 넓힌 읽기와 대화 턴 예산을 넣는다. 이 기록은 그 전후로 같은 요청 5개에서 VIDE(A)가 터미널(B)과 얼마나 가까운지 잰다.

01 / 합격 기준 (실행 전)

  • A의 성공 수가 B 이상, 또는 B보다 1개 적고 실패 원인이 기록돼 있음.
  • 성공한 요청에서 A의 시간·토큰이 B의 2배를 넘지 않음(넘으면 원인 기록).
  • 원본 문서 무변경: A는 후보만 만들고 반영하지 않는다. B는 시험 모델 사본에서만 한다.

02 / 방법·환경

  • 시험 모델: tools/ab/fixture.py가 만드는 합성 mm 문서(축선 7, 보 3, 2층 슬래브 1, 층 표시점 3, 난간 기준 곡선 1). 실제 프로젝트 자료 없음.
  • 요청과 판정: tools/ab/requests.json(R1 기둥 격자, R2 보 춤 600, R3 슬래브 3층 복사, R4 곡선 따라 난간, R5 축선 이름 X·Y). 판정 코드는 tools/ab/checks.mjs이며 A·B가 같은 코드를 쓴다.
  • A: 개발 엔진(47831)의 대화 API, 요청마다 새 대화, permission: candidate, tools/ab/run.mjs.
  • B: 터미널 Claude Code + rhino MCP, 요청마다 시험 모델을 다시 열고 실행, dump_scene.py → tools/ab/terminal.mjs.
  • 수치 정의는 README의 「수치 정의」를 따른다. 두 쪽 모두 같은 모델·effort로 한다.

03 / 결과

시간은 초, 토큰은 입력+출력+캐시 읽기+캐시 쓰기 합, 도구는 A = 호스트 조회+실행, B = 도구 호출(rhino). run.mjs의 rows.md와 terminal.mjs 출력 줄을 그대로 붙인다.

04 / 결론과 한계

(실행 뒤 작성) 차이가 난 요청별 원인(지시·도구·예산·화면 유무), 다음 조치.

알려진 한계: A의 화면은 후보 모델에서 그린 SVG이며 호스트 화면 캡처가 아니다. B의 판정은 Rhino 객체 id로 변경을 구하므로 객체를 지우고 새로 만든 수정은 추가+삭제로 보인다. 판정은 경계 상자 기반이라 형태의 세부(난간 모양 등)는 비고에 사람이 적는다.
