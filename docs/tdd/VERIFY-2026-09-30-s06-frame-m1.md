# S-06 골조 jig 0.1 합성 자료 검증 (M1)

## 범위

[PLAN-23](../plans/PLAN-23-s06-frame-jig.md) T-051의 검증 항목 가운데 **합성 자료·점검·실패 시험**만 다룬다. 대상은 형식 v3 jig `project/s06-frame@0.1.0`(`extensions/jigs/s06-frame/`)의 단계 ⓪ 입력 조립 → ① 진단 → ② 축선·배치 → ③ 기둥 → 기초 발자국 → ④ 기초 간섭이다. **실데이터(`.vide/` 사본) 검수는 이 기록에 없다**(아래 '다음 단계'). 구조 결과는 탐색용 예비값이다.

### grid-4m-bay

- ① 진단(그려 둔 기둥 3개): 파일캡 0 · 오픈컷 3 · 유수지 보 0 — 한 방향 분리(0.15 m)로 통과.

### priority-conflict

- ② 배치: 직교 격자 기둥 8, 최대 경간 11.72 m, **경간 초과 0**, 파일캡 간섭 10(기둥당 겹친 기존 기초 수의 합), 오픈컷 14. `relaxed = [openCut, cap]`, 위반 목록에 파일캡 행, 메모에 완화 순서. 엇갈림 격자는 슬래브 끝을 3.5 m 안에 받치지 못해 대안에서 뺐다(메모).
- ④ 간섭: 파일캡 불가 8(기둥마다), 비켜 두기 후보 8건 모두 '없음'(±0.6 m 안에 빈 자리 없음), 확인 목록에 파일캡 행.

### 실패·보호

- `spanMax −1` 등 잘못된 설정값 → `RangeError`, 축선 결과 없이 단계 실패. `gridAngle NaN` → 거절.
- 기존 기초 하나의 변환에 NaN → 그 기초만 '좌표에 숫자가 아닌 값이 있음'으로 빼고(6개 중 5개 읽음) 나머지는 계산. 회전 없는 경계 상자로 대신하지 않는다.
- 나비넥타이(자기교차) 슬래브 곡선 → 슬래브 없음 + 메모, ②는 `SLAB_MISSING`으로 멈춤.
- 엔진 실행기 통과: 사람 단계 '확정 전'은 계산을 막지 않고(`blocks: []`), 확인하지 않은 역할은 `inputs-confirmed`(warn)에 이름이 오른다(`site.existingFootings`). `span-max` 점검 통과.

## 가정

- 파일캡 정사각 `capSize`(기본 2.0 m), 오픈컷 = 파일캡 + 2 × 0.8 m, 캡 깊이 1.0 m(블록 솔리드용), 쌍기둥 공통 캡 = capSize × (capSize + 기둥 + E.J. 폭).
- ② 후보 위치는 (u, v) 프레임의 0.25 m 격자. 축선 간격 하한 = max(capSize + 1, 3) m. 첫·끝 축선에서 슬래브 끝까지 ≤ `cantileverMax`(엇갈림은 행마다 양 끝).
- ② 목적: 경간(초과 수·초과량) > 슬래브 끝 미지지 > 파일캡↔기존 기초 > 파일캡↔유수지 보 > 오픈컷↔기존 기초 > 기둥 수. ④는 SPEC-06.11 표대로 **기둥 단면**↔유수지 보를 판정하므로 ②의 유수지 보 수와 다를 수 있다.
- 거더망은 ②의 이웃 축선과 칸의 짧은 대각선(동률 u+v)만이다. 삼각망·테두리보·작은보는 M2.
- 기둥 하단 = 기존 기초 블록 상단 z(`baseSource: footings`), 거더 상단 = 슬래브 하면(메시 아랫면, 곡선이면 곡선 z).

## 한계

- **실데이터 미실행.** `.vide/` 사본의 S-06 모델로 ⓪~④를 돌리지 않았다(이 작업 흐름의 규칙: 호스트 실행 없음). PLAN-23 T-051의 실데이터 항목(파일캡 불가 0 또는 완화 목록, 유수지 보 목록, 경간 초과, 요청 영역)은 남았다.
- **AI 역할 제안 미연결.** 규칙 후보(`assembly/propose`)와 역할 카드 확인만 이어졌다. T-049의 단발 AI 제안(`input-roles`)을 `assembly/propose`에 붙이는 일은 `src/jigs/runtime/runtime.ts`·`src/server/jig-routes.ts`(이 작업의 소유 밖)에서 해야 한다.
- CAD 정렬 변환·잔차는 작업본 `assembly[].transform`에 저장되나 단계는 아직 읽지 않는다(스냅샷은 이미 변환된 좌표라는 전제).
- 유수지 보 띠는 볼록 껍질(`bandFromMesh`)이다. 곡선 보의 오목 외곽(`outlineFromMesh`)은 간섭 함수가 볼록만 받아 아직 쓰지 않는다.
- 엇갈림 격자는 끝 기둥을 더하지 않아 좁은 띠에서는 슬래브 끝을 받치지 못하고 대안에서 빠진다.
- 임시 진단 경로(`POST …/jigs/structure/diagnose`)와 `sync-input.ts`는 서버 파일이 소유 밖이라 지우지 않았다. M0 화면은 그대로 동작한다.
- `heightStep`의 '결정' 고정, 설정값 근거 진술은 작업본에서 넣는다(저장소는 일반 기본값).
