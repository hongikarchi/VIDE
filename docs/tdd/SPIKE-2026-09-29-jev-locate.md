# SPIKE — Jev 기반 수정 위치 찾기

## 질문

개발 요청 문장(영어·한국어)으로 이 저장소에서 고쳐야 할 파일과 줄 범위를 Jev가 빠르고 쓸 만하게 제안하는가. 단순한 단어 일치보다 나은가. 한국어는 공식 문서상 신뢰도가 낮다고 하는데 실제로 어떤가.

## 방법

- **도구:** `tools/locate/`(T-032). 색인은 추적 파일 502개(코드·문서·제품 HTML)이고, 요약은 각 파일이 스스로 선언한 내용이다(앞부분 설명 주석, 문서 제목·목차, export·클래스·함수·메서드 이름, 명령, API 경로).
- **단계:** 공식 skill suggestion·line-by-line search 레시피를 따른다.
  1. 255개 이하 묶음별 Choice 순위(병렬)
  2. 상위 16개 후보의 Choice + 후보별 Noul
  3. 상위 파일의 줄 블록 Choice + “수정 위치가 있는가” Noul
- **모델:** `jev-1.13.0`
- **평가:** `tools/locate/eval.mjs`
  - **영어 20건:** 최근 커밋 제목이 요청, 변경된 코드 파일이 정답. 병합·포맷·12개 초과 변경·문서만 바뀐 커밋은 제외.
  - **한국어 14건:** `tools/locate/cases-ko.jsonl`. 최근 커밋 12개의 실제 변경 파일을 정답으로 삼고, 사용자가 실제로 했던 말투로 요청을 작성.
  - **지표:** 정답 파일 중 가장 높은 순위가 1위·3위 안·5위 안인 비율. 기준선은 요청과 경로·요약의 단어 일치 수.
- **환경:** Windows, Node 24.15, 2026-09-29. 키는 Git 무시 `.env`의 `TYPESAFE_API_KEY`.

## 결과

요약을 보강한 뒤의 결과다(1위 / 3위 안 / 5위 안, %). 첫 측정에서는 C# 파일 앞의 `using` 줄 때문에 설명 주석을 못 읽고 함수 이름도 없어, 한국어 1건(CAD 문자·해치·xref)이 후보에서 빠졌다. 보강 뒤 이 건은 정답 파일 1위가 되고, 제시한 줄 범위가 실제 해치 수집(`CollectHatch`)과 클립 경계(`ClipPolygon`) 함수였다.

| 정렬 방식 | 영어 20건 | 한국어 14건 |
|---|---|---|
| 2단계 Noul(파일별 “수정 필요” 판정) | 50 / 65 / 90 | 79 / 93 / 93 |
| 2단계 Choice 확률 | 55 / 90 / 90 | 100 / 100 / 100 |
| 1단계 Choice 확률 | 65 / 90 / 100 | 64 / 93 / 100 |
| **2단계 확률 + 1단계 확률(채택)** | **65 / 95 / 100** | **93 / 100 / 100** |
| 단어 일치 기준선(Jev 없음) | 55 / 70 / 70 | 0 / 7 / 14 |

- **정답 파일:** 34건 모두 채택한 정렬의 5위 안에 들었다.
- **비용·시간:** 요청당 1·2단계 입력 약 3.5만 토큰, 판정 한 단계 중앙값 약 0.28초. 줄 위치까지 포함한 전체 실행은 Jev 7회, 입력 4~5.3만 토큰, 0.8초 안팎이다. 요금은 입력 100만 토큰당 $0.042라 실행당 약 $0.002다.
- **Noul 판정:** 파일별 “수정이 필요한가”는 정렬 기준으로 쓰면 오히려 성능이 떨어졌다. 결과에는 참고 값으로만 표시한다.
- **단어 일치 기준선:** 한국어 요청은 영어 코드와 단어가 거의 겹치지 않아 기준선이 사실상 실패했다. 의미 매칭에서 Jev의 이득이 가장 크다.

## 한계

- **요약 시점:** 평가는 현재 파일 내용으로 만든 요약을 쓴다. 과거 커밋 시점에는 없던 이름이 요약에 들어 있어 절대 수치는 낙관적일 수 있다(기준선도 같은 조건).
- **한국어 사례 작성:** 정답 파일을 알고 있는 에이전트가 작성했다. 표현이 정답 쪽으로 기울었을 수 있다. 앞으로 실제 개발 요청을 그대로 모아 다시 측정해야 한다.
- **표본 크기:** 영어 20건, 한국어 14건으로 작다. 차이 몇 %p는 우연 범위다.
- **여러 파일 변경:** “정답 중 하나라도 상위”로 셌다. 함께 고쳐야 하는 파일을 모두 찾는지(recall)는 더 낮다.
- **미측정:** 코딩 에이전트가 스스로 찾는 것과의 비교(착수 시간·토큰)는 재지 않았다.
- **외부 전송:** 요청 문장과 파일 요약·파일 본문(줄 위치 단계)이 TypeSafe로 전송된다.
