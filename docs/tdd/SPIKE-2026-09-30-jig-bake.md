# jig 만들기 바로 적용 — 실제 Rhino 확인

## 질문

1. 고정 만들기 틀 네 개(`vide.bake.curves@1`·`sweep-h@1`·`extrude-column@1`·`textdot@1`)의 본문이 연결된 Rhino 8에서 코드 규칙(CodePolicy)을 통과하고, 바로 적용(본문 하나당 되돌리기 기록 하나)으로 실제 객체를 만드는가.
2. 두 번째 만들기는 기록된 객체만 바꾸고, 사람이 고친 객체를 남기는가. 출력 레이어가 꺼지면 막히는가. [되돌리기]는 한 실행의 기록을 모두 되돌리는가.
3. 실데이터 크기(S-06 상단선 161개)에서 본문 크기와 시간은 얼마인가.

## 방법과 환경

- 사용자 Rhino·CAD가 모두 닫힌 확인 구간에, 에이전트가 숨김 Rhino 8을 띄웠다. 연결 플러그인은 이번에 고친 워커를 레인 전용 폴더(`.vide/h2-build/bin/`)에 빌드해 `LoadPlugIn`으로 올렸다. 공용 빌드 폴더는 다른 레인이 쓰고 있어 건드리지 않았다.
- **합성 문서:** `node tests/integration/rhino-bake.mjs`(`VIDE_TEST_RHINO_PLUGIN`에 레인 빌드, `VIDE_TEST_KEEP_REGISTRATION=1`). 엔진은 시험 프로세스 안에서 만든다.
- **S-06 사본:** `.vide/s06/`의 구조·유수지 모델 사본을 다시 복사해 두 숨김 Rhino에 하나씩 열었다. 개발 엔진(`node src/server/main.ts --dev`, 데이터 `.vide/h2-data`, 포트 47842)에 제품 경로(`/links` → `/capture` → `/jig-instances` → `/reads` → `/assembly` → `/run` → `/steps/:id/confirm` → `/bake` → `/bakes/:id/undo`)로 연결했다. 사본은 저장하지 않았다. 사람 수정 흉내는 작은 C# 이동 본문을 연결의 `direct-execute`로 보냈다.
- 스크립트는 `.vide/h2-s06/`(저장소 밖)에 두었다.

## 찾은 결함과 고친 것

**`direct-undo`가 한 실행의 두 번째 기록부터 실패했다(`hosts/rhino/worker/DirectExecution.cs`).** 원인은 둘이다.

1. '최신' 판정이 `NextUndoRecordSerialNumber == serial + 1`이었다. 한 실행의 본문이 여럿이면 최신 기록을 되돌린 뒤 그 앞 기록은 영영 최신이 아니다(`BAKE_UNDO_NOT_LATEST`, `partial`). 또 Rhino는 되돌리기 동작에도 번호를 준다.
2. 명령 밖(Idle)에서 부른 `RhinoDoc.Undo()`/`Redo()`가 자기 되돌리기 기록을 열어 둔 채 끝난다. 그 뒤의 `Undo`·`Redo`·`BeginUndoRecord`가 모두 실패한다. 숨김 Rhino 실험에서 기록 8개를 만들고 `Undo`를 부르면 첫 번째만 성공하고, `UndoRecordingIsActive`가 참으로 남았다. 열린 기록을 `EndUndoRecord`로 닫으면 다음 `Undo`가 된다.

**고친 것:**

- 문서의 되돌린 기록(`UndoRedo` 이벤트)과 이 연결의 빈 기록·되돌리기 동작 번호를 추적한다. 뒤의 기록이 모두 되돌려졌거나 빈 기록일 때 그 기록을 최신으로 본다.
- `Undo`/`Redo` 뒤에 Rhino가 열어 둔 기록을 닫는다(`CloseOwnRecord`).
- 결과는 다음과 같다.
  - `rhino-bake.mjs`의 [되돌리기]가 통과한다.
  - `tests/integration/rhino-direct-apply.mjs`(다른 레인)는 고치기 전 빌드로는 되돌리기 뒤 실행이 `HOST_RESULT_UNKNOWN`으로 멈췄다. 고친 빌드로는 최신만 되돌리기·최신 아님·실패 본문 단계를 지나고, 그 뒤의 화면 캡처 단계에서 멈춘다(숨김 창의 흰 캡처, 되돌리기와 무관).

**시험 코드 고친 것(`tests/integration/rhino-bake.mjs`):**

- 표시 읽기는 부피를 싣지 않는다(`DisplayScene`이 `volume: null`). 그래서 솔리드·부피는 연결 Rhino에서 직접 잰다.
- 웨브 수직 확인을 더했다.
- 불러온 플러그인 경로를 결과에 남긴다.
- `VIDE_TEST_KEEP_REGISTRATION=1`이면 설치본 플러그인 등록을 되돌리지 않는다.

## 한계

1. **엔진의 S-06 해석은 돌지 않는다.** 저장소 jig(`dev-source`)의 단계는 권한 모델 아래 자식 프로세스에서 돈다. 해석은 작업 스레드가 필요한데 자식에게는 작업 스레드 권한이 없다. 그래서 `analysis`는 `unavailable`(`ERR_ACCESS_DENIED`)이다.
   - [해석 확정] 사람 단계는 확정으로 표시된다. 하지만 `bakeMembers`는 `previewOnly: true`로 남고, 부재 만들기는 문제 목록으로 막힌다.
   - 실데이터 부재 만들기와 부재 방향은 이번에 보지 못했다. 합성 문서로만 확인했다.
   - 자식 실행기에 작업 스레드 권한을 여는 시험용 우회는 보안 약화라 쓰지 않았다.
   - 해석을 엔진 쪽에서 돌리는 경로는 ARCH-03 §6.4와 PLAN-23에서 정해야 한다.
2. `/bake`는 인스턴스의 조립이 여러 연결을 읽으면 `linkId`를 요구한다(없으면 400 `INVALID_INPUT`). 만들기 카드가 이 값을 보내는지는 화면 시험에서 봐야 한다.
3. 되돌리기 추적은 연결 프로세스 메모리에 있다. Rhino를 다시 연 뒤에는 이전 기록을 되돌릴 수 없다(기존과 같음).
4. 설치본(0.2.11) 플러그인으로의 재등록과 설치본에서의 재확인은 메인 세션이 한다.
