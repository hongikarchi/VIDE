# 검증 범위

PLAN-02 §5의 단계 1·2a, SPEC-04.8에 따른 공유 계정·권한·게시 검증이다. 아래 절은 시간 순서이며 현재 상태는 이 요약으로 읽는다(2026-09-23 기준).

| 범위 | 원격 staging에서 확인 | 로컬 런타임에서만 확인 | 미시험 |
|---|---|---|---|
| 계정·참여 | 메일 없는 가입/로그인, 프로젝트 생성, 참여 신청→소유자 승인→접근→회수→거절, 로그아웃 (마지막 절) | 메일 인증 모드의 초대 수락·만료·취소·역할 변경 (첫 절) | 실제 메일 수신·비밀번호 복구 |
| 모델 게시·의견 | — (`UPLOADS_ENABLED=false`로 차단) | R2 게시·과거본·핀/스케치 의견·응답 유실 재확인·파일 왕복 채택·10~500 MiB 전송·재시작/복원 | 원격 업로드, PC 종료 후 모델 열람 |
| 운영 | D1 4개 마이그레이션 적용, 비밀 바인딩 | 로컬 D1/R2 사본 복원 | 원격 백업/복구, 부하·비용 계측 |

인증 자체의 확인/복구/세션 회수는 [인증 실험](SPIKE-2026-09-22-cloudflare-auth.md)을 따른다.

## 구현과 실행

제품 코드는 `src/sharing/`에 두며 Better Auth 1.7.5와 D1 마이그레이션을 고정했다. `npm --prefix src/sharing ci` 후 `run typecheck`, `test`로 재현한다. 별도 Worker이며 데스크톱 제어 서버의 AI 계정·호스트 실행 권한과 분리한다. 프로젝트 API는 매번 로그인/현재 멤버십을 확인하며 실험용 메일 조회나 마이그레이션 HTTP 경로를 제공하지 않는다.

합성 세 계정·두 프로젝트의 시험 `tests/sharing/membership.mjs`가 실제 로컬 workerd/D1에서 통과했다. 증거는 `.vide/sharing-membership/445e721c-e764-441b-9896-31706bdc3c20/result.json`이다. 시험에서는 계정 확인 상태만 D1에 직접 설정하고 실제 라이브러리 로그인·서명 세션을 사용한다. 메일은 로컬 모의 바인딩이며 외부 발송하지 않는다.

| 확인 | 결과 |
|---|---|
| 미로그인·교차 프로젝트·잘못된 Origin 접근 | 거절 |
| 지정 수신자 이외의 초대 수락 | 거절 |
| 동시 수락 두 번 | 멤버 한 명, 같은 결과 |
| 역할 변경 뒤 기존 세션 조회 | 현재 역할 반영 |
| 권한 회수 뒤 조회·옛 초대 재수락 | 거절, 멤버십 복원 없음 |
| 초대 취소·만료, owner 역할 초대 | 거절 |
| 소유자 제거 | 거절 |
| 원격 호스트 실행·실험 관리 경로 | 없음/거절 |
| 초대 토큰 저장 | 해시만 저장, 원문 링크는 소유자 응답과 발송 요청에만 사용 |

초대 수락·멤버 생성은 D1 batch로 원자 처리한다. 기존 멤버 역할을 옛 초대로 덮어쓰지 않는다. 초대 링크는 fragment에 토큰을 두고 API 본문으로 수락해 URL 요청 로그에 토큰이 남지 않게 한다. 초기 로컬 시험의 초대 만료는 7일이며 운영 보존/만료 정책 확정을 대체하지 않는다.

## 로컬 공개 자료 추출

`src/core/publication.ts`의 명시적 allowlist로 성공/검증된 결과에서 선택 객체의 표시 형상만 추출한다. 이름과 캐시된 측정값은 각각 명시 선택해야 포함한다. 로컬 경로·native ID·입력 문장·첨부·임의 속성·선택하지 않은 객체는 내보내지 않는다. 중복 ID·없는 객체·잘못된 mesh index·미검증 결과는 거절하며 다른 형상으로 조용히 대체하지 않는다.

`tests/core/publication.test.mjs` 세 사례와 서버 strict 타입 검사가 통과했다. 실제 추출 번들을 로컬 R2 업로드/다운로드까지 연결한 공유 시험도 `.vide/sharing-membership/ebc4a049-b4be-4d4a-8e09-8f7ed8ca6c58`에서 통과했다. 아직 내보내기 UI나 사용자 자료 업로드를 수행한 결과는 아니다.

## 공유 웹 화면 — SCR-06

`src/sharing/web/`에 TypeScript·React·Vite·CSS·Three.js 화면을 추가했다. 로그인/가입/복구, 프로젝트/초대 진입, 소유자 공유 관리, 게시 모델·과거본 선택, 객체 선택/첨부와 문장 의견을 연결했다. 이름/측정값이 공개된 객체만 해당 정보를 보여 준다. 3D 코드는 모델을 열 때 지연 로드한다.

`npm run build:sharing` 후 `node tests/sharing/membership.mjs --browser`로 실행한다. 실제 로컬 workerd/D1/R2 API에 테스트 HTTP 정적 파일 브리지를 연결하며 설치 Chrome을 headless로 사용한다. 사용자 마우스/키보드와 기존 브라우저 세션은 사용하지 않았다. Cloudflare Static Assets의 원격 전달 검수는 아니다.

`.vide/sharing-membership/accfd9ba-9768-43df-b6c2-fd043988cafa`에서 로그인→프로젝트→3D→객체 첨부→의견 접수, 위 보기의 orthographic 전환, 접수 성공 직후 응답 유실→새로고침→동일 제출 ID 재확인을 통과했다. 응답 불명확 상태와 원문을 로컬 초안에 보존하며 재확인 동안 입력을 고정한다. 서버 의견은 하나였다. 1440×900/390×844 캡처를 직접 확인했고 모바일 프로젝트 버튼의 높이 문제를 수정했다. 모바일 가로 넘침과 pageerror는 없었다.

화면 증거는 같은 폴더의 sharing-desktop.png·sharing-mobile.png다. 실제 iPad/펜 사용성 검수는 아니다. 현재 웹 표시 파서는 64 MiB 이하 JSON 모델로 제한하고 더 큰 모델은 명시적으로 거절한다. 게시 전송 한도와 웹 렌더 지원 크기는 별개다. 큰 모델/부분 로드 최적화는 미시험이다. 바이너리 전송의 로컬 실측은 아래 전송 시험 절을 따른다. 3D 지연 청크 약 559 kB의 빌드 경고를 유지하며 초기 화면 번들과 분리했다.

## 로컬 선택에서 웹 게시까지

로컬 후보의 ‘공유 자료’에서 객체를 직접 선택하고 이름/측정값의 포함 여부를 지정한다. `publication-export`는 현재 로컬 인증/Origin·프로젝트 검사를 거친 읽기 전용 추출이다. 선택 자료를 VIDE-publication.json으로 내려받아 웹 프로젝트의 ‘모델 게시’에서 고른다. 이 단계는 파일 경유 전달이며 자동 연결이나 원격 배포로 표현하지 않는다.

웹은 형식·대상·청크 해시를 확인하고 공개할 목록을 보여 준 뒤 사용자의 게시 행동으로 업로드한다. 공개 파일은 사용자/프로젝트로 구분한 IndexedDB에 보관해 재접속 후 같은 requestId/manifest로 결과 확인·남은 업로드를 진행한다. 게시 확인 후 재시도 파일을 지운다. ‘이 파일 닫기’는 브라우저 자료만 지우며 이미 접수된 서버 게시본은 삭제하지 않는다고 알린다.

`tests/sharing/desktop-publish.mjs`를 포함한 전체 공유 브라우저 시험이 `.vide/sharing-membership/3b37411f-63ea-4baa-b59d-a98207659472`에서 통과했다. 합성 로컬 프로젝트에서 선택 객체 하나만 내려받아 실제 로컬 R2 게시→3D 표시를 확인했다. 다른 로컬 프로젝트의 같은 요청 ID를 통한 내보내기는 404였다. 게시 확정 뒤 응답을 끊고 새로고침·재확인해도 게시본 하나였다. 이전 검토자 화면의 의견은 새 게시 후 제출 전에 이전 기준임을 알렸고 원문/대상을 옮기지 않았다. UI/서버/Worker strict 검사 및 관련 코어/HTTP 9개 회귀도 통과했다. 이전 전체 회귀는 128개 통과다.

UI 증거 desktop-export.png·published-from-desktop.png를 직접 확인했다. 기본 필드 제외로 PRIVATE 합성 입력/이름·숨긴 객체가 공유 파일에 없었다. 실제 사용자 자료·이메일·외부 계정으로 수행한 검수는 아니다.

## 월드 핀·스케치 의견

공유 화면에 탐색/핀/스케치 도구를 추가했다. 핀은 실제 형상 교차점(빈 곳은 XY 기준면), 선은 사용자가 고른 원점 기준 XY/XZ/YZ 평면의 m 좌표와 역할을 보존한다. 스케치는 해당 평면의 정투영 화면에서 입력하며 참고/경계/경로/방향을 고를 수 있다. 문장이 없어도 공간 입력을 제출할 수 있고 게시본·객체 기준과 원시 점열을 서버에 보존한다. 저장된 공간 의견은 다시 3D에 표시한다. 임의 작업 평면이나 화면 위 자유 주석은 이 구현에 포함하지 않았다.

pointercancel/창 포커스 유실의 선은 완성된 것으로 처리하지 않는다. 로컬 초안의 중단 입력으로 남겨 새로고침 후 선 보관·한 점의 핀 전환·제외를 선택하게 한다. 응답 불명확 초안과 동일 제출 ID 재확인을 유지하며 권한·공간 좌표는 서버에서도 검사한다.

`tests/sharing/membership.mjs --browser`가 `.vide/sharing-membership/2d6735ad-d87a-443b-a642-7cd99152305d`에서 통과했다. 실제 로컬 D1/R2의 핀/두 선 원문 보존, XZ 평면·방향 역할, 중단/새로고침 복구, 기존 게시/의견 응답 유실 회귀를 포함한다. sharing-spatial.png에서 모델·핀·두 선 표시를 직접 확인했다. 캡처는 레이아웃 변경 후 두 렌더 프레임을 기다린다. headless Chrome의 가상 포인터를 사용했으며 시스템 마우스는 조작하지 않았다. Worker strict 검사도 통과했다.

## 외부 의견의 로컬 초안 채택

공유 소유자가 의견 하나를 VIDE-feedback.json으로 내려받고, IDE 검토본의 ‘외부 의견’에서 가져와 원 기준 후보를 열고 초안에 첨부할 수 있다. 로컬 공유 내보내기 때 기록한 export ID·공개 manifest 해시·원 후보 결과 해시를 대조한다. 프로젝트/기준이 없거나 달라지면 거절하며 의견을 현재 후보로 조용히 옮기지 않는다. 외부 의견의 원문·작성 당시 게시본·작성자 ID·서버 시각·핀·선 점열은 수신 기록과 초안 첨부에 남긴다. 선은 편집 입력으로도 복사하고 대상 객체는 원 후보 기준으로 첨부한다. 가져오기/첨부는 새 실행 요청을 만들지 않는다.

파일 전달은 출처의 온라인 인증을 대신하지 않는다. 로컬 화면은 파일 수신임을 표시하고 작성자·접수 정보가 서버에 재인증된 정보가 아님을 알린다. 자동 동기화·IDE 신규 의견 알림·현재 후보와 공간 차이 비교는 후속이다. 이전 구현에서 만든 export 파일은 로컬 대응 기록이 없으므로 새 내보내기가 필요하다.

증거 `.vide/sharing-membership/2c16b17c-d548-4bd6-9ad3-72744a3adae6`: 소유자 의견 다운로드→IDE 수신→중복 수입→초안 첨부→새로고침 보존이 통과했다. 게시본 ID·핀 좌표·스케치 점열을 검사했고 수신 기록은 1개, 기존 작업 요청은 1개 그대로였다. 의견 작성자는 소유자 전용 내보내기에 403을 받았다. 별도 코어 시험은 다른 프로젝트·변형 manifest·변경된 원문·미공개 객체·변경된 원 후보를 거절했다. 전체 자동 시험 129개, UI/서버/Worker strict 및 빌드 통과. feedback-adopted.png를 직접 확인했다.

## 로컬 전송·재시작·복원 시험

`node tests/sharing/membership.mjs --recovery --large`가 `.vide/sharing-membership/c75bc825-4363-4509-a769-4e588210c3ee`에서 통과했다. 10 MiB 자산의 첫 8 MiB 청크 뒤 런타임을 정상 종료/재시작하고 동일 게시 요청·청크 재전송을 확인했다. 미완료 확정은 이전 게시본을 유지했고 나머지 업로드 후 게시·다시 재시작·전체 해시 대조가 통과했다. 강제 전원 차단 시험은 아니다.

| 합성 자산 | 청크 | 업로드 | 확정 | 전체 읽기·해시 |
|---|---|---|---|---|
| 100 MiB | 13 | 1,542 ms | 16 ms | 415 ms |
| 500 MiB | 63 | 8,085 ms | 32 ms | 1,986 ms |

2 MiB 청크의 동시 읽기 1/10/50건은 각각 p50 14/93/457 ms, p95 14/111/558 ms였다. 모든 읽기의 크기·SHA-256을 대조했고 오류는 0건이었다. 단일 로컬 실행의 합성 바이너리 전송값이며 한국 원격 접속·Cloudflare 운영 제한·대형 3D 모델 렌더링 성능으로 일반화하지 않는다. 64 MiB 웹 표시 한도는 유지한다. 성공한 대용량 실행의 런타임 상태는 경로·심볼릭 링크 확인 후 정리했고 result.json과 worker.log만 보존했다.

`node tests/sharing/membership.mjs --backup`은 `.vide/sharing-membership/1031adda-3075-4511-8da1-8bbe82ee743c`에서 통과했다. 정지한 로컬 에뮬레이터 D1/R2 상태를 복사한 뒤 합성 의견과 자산 청크를 직접 삭제해 손실을 확인했다. 별도 새 경로로 복원하여 같은 세션의 접근·게시 포인터·의견 ID·자산 해시가 돌아옴을 확인했다(손실 주입부터 복원 검증까지 939 ms). 이 방식은 로컬 런타임 사본 검증이며 원격 D1 SQL 반출/R2 백업이나 운영 재해 복구 절차의 대체물이 아니다.

## 공유 화면의 큰 좌표 정밀도

데스크톱에서 사용하던 상대 GPU 정점 계산을 `src/core/display-coordinates.ts`로 공통화해 공유 모델과 의견 선에도 적용했다. 월드 원점은 객체 변환에 유지하고 작은 차이만 Float32 정점에 저장한다. 작은 모델의 전체 보기에서 최소 1 m 범위를 강제하던 부분도 조정했다. 원 공개 자료와 핀/선 좌표는 변경하지 않는다.

`tests/sharing/precision.mjs`가 `.vide/sharing-precision/89c12475-4ffe-4220-82a6-e28bcf67f48f`에서 실제 공유 Model 컴포넌트로 90,000 m 부근의 2 mm 형상을 정투영/원근에서 선택하고 월드 핀 위치를 0.1 µm 이내로 대조했다. 이는 합성 입력·수치 판정 허용오차이며 실제 설계/측량 정확도 보증은 아니다. precision.png에서 형상과 핀 표시를 확인했다. 코어 상대 좌표 시험·UI/서버 strict가 통과했고, `.vide/sharing-membership/819c4483-9dc5-4de1-8b9c-549934702b0a`에서 공유 브라우저 전체 왕복도 재검증했다. 설치 ZIP .5는 이 후속 표시 보완 이전 코드다.

## Cloudflare 계정 연결과 원격 자원 준비

2026-09-22 사용자가 Aside의 로그인 계정으로 CLI 연결과 VIDE 시험 배포를 승인했다. 첫 OAuth 재인증은 자동 승인 검토에서 권한 범위의 명시적 승인 부족으로 거절되었고, 사용자가 범위를 승인한 뒤 동일 범위로 재시도해 연결했다. `wrangler whoami`로 브라우저와 CLI가 같은 계정임을 확인했다. 인증정보는 Wrangler의 사용자 설정에만 저장하고 저장소/검증 증거에는 복사하지 않았다. 기본 전체 OAuth 권한 대신 account/user read, workers/scripts write, tail read, D1 write, zone read, email_sending write, offline access를 사용한다. `whoami`의 나머지 기본 scope 누락 경고는 권한을 제한한 결과이며 필요한 작업이 실패하지 않는 한 확장하지 않는다.

| 확인 | 실제 결과 |
|---|---|
| 계정 요금제 / 도메인 | Workers Free / Domains 목록에 등록 도메인 없음 |
| D1 | `vide-sharing-staging`, APAC 생성. 0001-auth·0002-projects·0003-publications 적용 후 원격 재조회 일치 |
| 원격 사용자 자료 | user 0행, projects 0행. 사용자 원본과 합성 모델도 아직 업로드하지 않음 |
| R2 | `vide-sharing-staging` 생성, `r2 bucket dev-url get`에서 공개 접근 disabled 확인 |
| 로컬 설정 보존 | 기존 `wrangler.jsonc` 유지, 별도 `wrangler.staging.jsonc` 추가 |
| 웹 빌드 / Worker dry-run | 통과. Worker 2652.03 KiB, gzip 456.64 KiB. 공유 3D 청크의 기존 500 kB 경고는 유지 |
| 미완료 | Worker 실제 배포·공개 URL·AUTH_SECRET·발신 도메인·메일·원격 가입/공유·청구량/복구 시험 |

원격 설정의 `workers_dev:false`, `preview_urls:false`, 빈 origin/발신자는 아직 서비스를 열지 않았음을 나타낸다. 비밀키도 미주입이므로 현재 앱의 설정 검사가 요청을 거절한다. 이 구성은 완성된 서비스가 아니다. `remote:false`는 로컬 개발의 원격 데이터 접근 방지 설정이며 실제 원격 마이그레이션은 명시적 `--remote`로 실행했다. D1/R2 식별자는 비밀이 아니며 설정에 기록한다.

공식 [Email Service 가격](https://developers.cloudflare.com/email-service/platform/pricing/)에 따르면 일반 수신자 발송은 Workers Paid가 필요하고 사전 인증한 destination에 대한 발송은 무료 예외다. [발신 설정](https://developers.cloudflare.com/email-service/get-started/send-emails/)에는 Cloudflare DNS의 발신 도메인이 필요하다. 계정 대시보드의 Paid 표시는 월 $5 + 사용량이며 유료 전환은 하지 않았다. 발신 도메인·시험 비용 범위와 실제 메일 시험 수신자를 확인한 뒤 설정한다. 이 확인은 메일 API 형식이 틀렸다는 의미가 아니며 현재 `EMAIL.send({from,to,subject,text})`는 공식 Workers binding 형식과 일치한다.

재개 순서:

1. 발신 도메인/DNS·발송 자격과 비용 승인을 확인한다. 기존 서비스 DNS나 요금제를 임의 변경하지 않는다.
2. 준비된 전용 자원으로 정확한 origin/발신자를 설정하고 AUTH_SECRET을 비밀 바인딩으로 주입한다. 메일 발송과 공개 접근을 실제 설정 전에는 완료로 올리지 않는다.
3. `npm run build:sharing` 후 `node src/sharing/node_modules/wrangler/bin/wrangler.js deploy --dry-run --config src/sharing/wrangler.staging.jsonc`를 확인하고, 준비된 설정만 실제 배포한다.
4. 허용된 시험 계정의 실제 인증 메일·로그인/로그아웃·복구·공유 권한/파일을 검증한다. D1의 emailVerified 값을 강제로 바꿔 실제 메일 검증을 통과 처리하지 않는다.
5. PC 종료 지속성·사용량·백업/복구 시험을 수행한다. 로컬 대용량 시험을 원격 부하 시험으로 재사용해 주장하지 않는다.

사용자 후속 결정: 무료 범위의 서버 준비까지만 진행한다. 현재 전용 D1/R2 및 설정·스키마·dry-run 준비를 완료했으며 도메인 구매/요금제 전환은 하지 않는다. R2 무료 제공량은 계정 내 기존 서비스와 공유되므로 무료 상한 보장을 주장하지 않고, 이번 단계에서는 빈 버킷과 작은 빈 DB만 생성했다. 원격 부하 시험과 외부 가입 공개는 수행하지 않는다.
