# 한 요청의 복수 문서 SDK 후보 검증

기준은 SPEC-02.9·13·14, ARCH-01의 복수 대상 계약, PLAN-02 §6.1의 3b, Design의 요청 입력이다. 두 후보를 명시 선택하고 m 환산 후 공통 원점/축을 확인한 한 요청을 시험했다. 두 호스트 원본을 자동 적용하는 기능은 아니다.

## 실제 호스트·브라우저 결과

`tests/integration/browser-linked-hosts.mjs`는 실제 Chrome·제품 UI·MCP·설치 Rhino 8.34/ZWCAD 2023을 사용한다. 에이전트만 결정적 대역이므로 새 구독 모델의 추론 정확도·비용 검수는 아니다.

| 시험 | 확인 결과 | 로컬 증거 |
|---|---|---|
| CAD→Rhino | CAD 24×10 m 경계를 26×10 m로 수정하고 **수정 후 조회한 정점**으로 Rhino 높이 6 m 후보 구성. 면적 260 m²·체적 1,560 m³, 기존 Handle/GUID·두 원본 파일 해시 보존 | `.vide/browser-linked-hosts/33946428-26cb-4dfb-a429-3bf8bc75d2d1` |
| 두 번째 쓰기 불명확 | CAD 성공 뒤 Rhino 쓰기 중 예외. 전체 요청 실패, CAD 후보 보존, Rhino unknown·진단/영수증 경로 유지. 성공한 CAD를 다시 쓰지 않음 | `.vide/browser-linked-hosts/ccae8bcc-0169-41db-a5cb-4c8fcecb9017` |
| ZWCAD 두 문서 | 별도 DWG 두 개에서 첫 경계 수정→실제 조회 정점을 두 번째 후보의 새 폴리라인으로 생성. 두 번째 기존 240 m² 객체 유지·260 m² 객체 추가, 서로 다른 Handle, 원본 파일 불변. 범위 밖 대상 조회 거절 | `.vide/browser-linked-hosts/e181094a-3b0b-4541-a091-91e5a1b5b91e` |

각 시험의 provider 호출은 1회다. 입력 UI의 좌표 확인 전 제출 금지·두 대상 첨부·재접속 복원·결과별 후보 보기를 확인했다. 새로고침 초기 복원이 완료되기 전에 문장을 쓰면 덮일 수 있던 문제를 수정해 복원 완료 후 입력을 받는다. Inspector 관계에는 같은 요청의 다른 후보를 연결하며 기하학적 동일 객체나 자동 동기화 관계로 표시하지 않는다.

## 자동 계약·회귀

`tests/server/linked-execution.test.mjs`는 한 호스트 시작 실패 때 다른 대상 대기 해제·에이전트 호출 0회, 두 대상 범위, 다른 프로젝트/중복/좌표 미확인/부모 ID 위조 거절, 호출 상한·만료, 한 공급자와 대상별 결과, unknown의 저장 후 재조회·중복 쓰기 부재, 복구 후 부모의 대상 행 갱신을 검증한다. 복구로 대상 상태가 바뀌어도 실패했던 전체 요청을 임의 성공으로 바꾸지 않는다.

전체 자동 회귀 145개, 타입 검사와 기존 React 브라우저 회귀(프로젝트 격리·문서 경합·Inspector·스케치·복원·원본 적용·불명확 쓰기 보호·모바일 초안)를 통과했다.

## 판정과 남은 범위

AC-25·32·33의 위 합성 시나리오는 통과했다. 전체 AC와 MVP를 완료로 판정하지 않는다. 원점/축이 다른 문서의 임의 변환, 일반 곡선/블록/재질/관계의 정확 복사, 대용량 네이티브 자산 전달, 문서 간 지속 자동 동기화는 이 검증 밖이다. 원본 적용은 각 후보의 기존 명시 적용 절차로 수행한다. 두 문서 전체의 원자적 적용/롤백을 제공하지 않는다. 논현동 수준 실무 수용 과업은 사용자 지시에 따라 현재 묶음 이후 결정한다.

최종 공유 통합 회귀도 `.vide/sharing-membership/0a067ed2-c453-4ff2-b134-8cedecfdc043`에서 통과했다. 전체 verify 중 esbuild가 Windows 샌드박스 상위 디렉터리 권한으로 실패해 공유 시험만 권한 있는 환경에서 재실행했다. 포맷·배포 설정·UI/서버/공유 타입·빌드·145개 자동 시험·공유 통합·문서 최신성 검사를 각각 통과했고 Git 이력 160개 커밋의 비밀정보 검사에서도 발견 0건이었다.
