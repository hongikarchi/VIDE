S-06 골조 jig 0.2 그려진 배치 검증 (M2)

00 / 범위

PLAN-23 T-053 가운데 M2 머리말(2026-09-30)이 먼저 하라고 한 그려진 배치를 다룬다. 지금 그려진 기둥·거더에서 시작해 ⑤ 거더 보정 → 칸 → ⑦ 작은보 → 해석 모델 → ⑧ 해석 미리보기와 [해석 확정]까지 이어지는지 본다. 대상은 project/s06-frame@0.2.0(extensions/jigs/s06-frame/)이다. 새 축선·기둥 후보(②~④)는 설정값 layoutSource가 '새 배치 제안'일 때만 돌고, 그 결과는 M1 기록과 같다. 삼각망·테두리보·줄돔 곡선 생성은 이 기록의 범위가 아니다. 구조 결과는 모두 탐색용 예비값이다.

01 / 자료

  • 합성: fixtures/cases.ts의 drawn-two-bay. 15° 돌린 8 m × 7 m 두 칸, 기둥 6개, 거더는 사람이 그린 그대로 두었다(기둥에서 0.2 m 모자란 끝, 0.15 m 벗어난 끝, 중복 조각 하나, 마지막 기둥을 2.5 m 지나는 거더, 가운데 기둥 위를 지나는 16 m 거더). 식재 구역은 왼쪽 칸이고, 구속 레벨은 EL 3이다. 각 단계 fixture(girders-*, beams-*, analysis-two-bay)는 레인별 시험이 쓴다.
  • 실데이터: 설치본 DB(%LOCALAPPDATA%/VIDE/vide.sqlite)를 읽기 전용으로 열어, 문서 이름에 '구조'가 들어간 연결 문서의 가장 최근 Sync(2026-09-29)를 scratch 폴더로 꺼냈다. 역할은 레이어 이름으로 골랐다. 입력 기둥 레이어의 곡선 34개, 입력 거더 레이어의 곡선 62개, 입력 슬래브 레이어의 메시 7개를 썼고 보이드 역할은 비워 두었다. 저장소에는 아무것도 넣지 않았다. 이름·좌표·레이어 이름은 이 기록에 적지 않는다.

02 / 방법

  • npm run jig:validate -- extensions/jigs/s06-frame
  • npm run jig:test -- extensions/jigs/s06-frame(자식 프로세스 실행기), -- --runner engine(엔진 실행기)
  • node --test tests/core/s06-m2.test.mjs: drawn-two-bay를 엔진 실행기로 끝까지 돌리고, 확정 대기·설정값 전달·배치 기준 전환을 확인한다.
  • 레인별 시험 tests/core/s06-girders.test.mjs·s06-beams.test.mjs·s06-analysis.test.mjs·geometry-kit-faces.test.mjs
  • 실데이터: 순수 함수 girders → cells → beams → model → analysis → confirmAnalysis를 Node에서 차례로 불렀다(Node 24, 이 PC).
  • 화면 시험 tests/integration/browser-s06-jig.mjs는 고쳐 두기만 했고 돌리지 않았다.

05 / 발견하고 고친 레인 사이 계약 불일치

  • 작은보 끝이 슬래브 끝·개구에 닿으면 beams는 girderId: null로 내는데, model은 그 끝을 가장 가까운 거더로 끌어당겼다. 그래서 거더와 겹친 조각이 생겼고 실데이터 모델이 invalid였다. 이제 그 작은보는 거더 쪽 끝에서 내민 보로 싣고, 양 끝이 다 안 닿으면 경고와 함께 뺀다(steps/model.ts).
  • 내민 보의 자유단을 핀으로 풀어서 끝 절점이 기구가 됐다. 이제 자유단은 풀지 않는다(steps/model.ts).
  • 해석 요약의 maxRatio가 세장비 한도 밖에서 가장 큰 수(1.8e308)로 나와 화면 값으로 쓸 수 없었다. 표와 KPI에서는 999로 자른다(steps/analysis.ts).
  • 패널용 필드를 더했다. girders: note(보정 한 줄)와 danglingAt(기둥 없는 끝의 점), analysis: rows·deflections와 summary.steel_t. beams는 jig 설정값 cantileverMax를 받는다. model은 하중·구속 설정값을 평평한 이름(deckD… planterL, restraintOn)으로 받는다.

06 / 남은 문제

  1. 내민 보가 있는 실데이터 모델이 불안정하다. 기둥 절점에 뿌리를 둔 가장자리 내민 보는 공식 라이브러리 규칙(기둥 약축의 강접을 핀으로 바꿈)에 따라 뿌리가 핀이 되어 기구가 된다. 한 거더(내민 보 둘이 붙은 것)의 중간 절점도 기구에 남는다. vide/structure-analysis frame-model.ts의 내민 보 뿌리 규칙과 비틀림 구속을 확인해야 한다(담당 밖이라 고치지 않음).
  2. 앱의 자식 프로세스 실행기에서는 model·analysis가 돌지 않는다. 저장소 jig(dev-source)의 자식 프로세스는 src/jigs/official과 node_modules만 읽을 수 있다. 그런데 해석 모델은 src/jigs/structure/sections.ts를 읽고, 해석은 작업 스레드와 네이티브 코어가 필요하다. jig:test(자식)에서는 model이 실패하고 그 뒤 단계는 막힌다. 합성 사례의 기대값이 거더·칸·작은보까지만인 이유다. 엔진 실행기에서는 끝까지 돈다. 플랫폼 쪽에서 해석 단계를 엔진에서 돌리는 경로(vide/structure-analysis의 단계형 함수 또는 실행기 선택)를 만들어야 한다.
  3. 보이드 역할이 비어 있으면 개구가 슬래브 조각으로만 나타난다. 실데이터에서 보이드 레이어를 확정한 뒤 다시 봐야 한다.
  4. 구속 레벨·단면·하중은 가정값이다. 구속 레벨은 유수지 상판 레벨을 토목사무소에 확인해야 한다.
  5. 화면 시험은 돌리지 않았다.

07 / 추가 · 내민 보 뿌리 규칙과 기구 사전 점검 (2026-09-30)

'남은 문제' 1을 공식 라이브러리 vide/structure-analysis에서 고쳤다.

  • 내민 부재 뿌리: freeEnd가 있는 부재는 계획이나 기둥 약축 규칙과 상관없이 양 끝을 강접으로 둔다(뿌리가 핀이거나 자유단이 풀리면 기구). 바꾼 수는 가정 목록에 '내민 부재 n개는 핀으로 준 단부를 강접으로 둠'으로 남긴다(frame-model.ts).
  • 핀만 모인 절점: 닿는 단부가 모두 핀인 절점은 거더(없으면 가장 긴 부재)와 그 부재에 가장 곧게 이어지는 부재 하나를 연속으로 둔다. 핀 두 개만 만나는 이음도 이렇게 연속 이음이 된다. 거더 중간에 핀으로 붙는 작은보는 그대로 둔다.
  • 기구 사전 점검: runAnalysis가 코어를 부르기 전에 mechanismIssues를 돌린다(mechanism.ts). 뿌리가 핀인 내민 끝과 트러스 부재 하나만 닿은 자유 절점은 MECHANISM 오류로 멈추고 끝·뿌리 절점과 부재를 적는다. 풀린 자유단(RELEASED_TIP)은 경고다. 좌표축과 나란한 부재면 코어가 끝 회전을 잡아 해석이 되고, 비스듬하면 코어가 그 절점을 기구로 알린다. 모든 단부가 핀인 절점(ALL_PINNED)과, 뿌리를 거더 비틀림만 잡는 내민 보(TORSION_ROOT: 기둥·교차 부재·같은 줄의 뒤쪽 보가 없음)는 경고로 알린다.
  • 시험: node --test tests/structure/mechanism.test.mjs(4건), tests/structure/*.test.mjs·tests/core/s06-{analysis,m2,m3-steps}.test.mjs·compute-box.test.mjs 95건 통과. npm run typecheck 통과.
