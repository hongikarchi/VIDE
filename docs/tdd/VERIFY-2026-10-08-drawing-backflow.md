# 도면 반영 jig — 실호스트 검수

## 범위와 기준

- **대상:** [PLAN-47 T-234](../plans/PLAN-47-drawing-generator.md)의 화면(Design SCR-31 도면 반영 jig: [모델 변경 반영] 탭과 SCR-30을 그대로 쓴 [도곽 미리보기] 탭)과 PLAN-47 「검수 계획」 1~7.
- **기준:** SPEC-14.1·14.6·14.7·14.8·14.9·14.10·14.11·14.12·14.15. 관련 AC-24·30·33·38은 이 기능이 그 시나리오의 도면 반영 부분을 맡는 범위에서만 본다(AC 전체 통과로 세지 않는다).
- **환경:** 작업 PC, ZWCAD 2023(이 검수가 띄운 숨은 프로세스만), worker는 이 작업 트리에서 빌드, 화면은 `npm run build:web` 결과를 머리 없는 Chrome으로. 사용자의 ZWCAD·Rhino 창은 열려 있지 않았고 붙거나 끄지 않았다(검수 뒤 남은 ZWCAD 프로세스 0).
- **Rhino 쪽:** Rhino를 띄우지 않았다. 원천 스냅숏(엔진 reader의 `source`)과 화면이 그 연결을 위해 부르는 두 호출(`…/links`, `…/jigs/sync`의 위치 관계·일치 행)만 시험이 정한 값이다. 도면 읽기·레이어 대응·짝 기록·차이 계산·저장 확인·[저장]·xref 읽기·도곽 찾기는 엔진 경로와 숨은 ZWCAD의 실제 결과다.
- **하지 않은 것:** 사용자의 ZWCAD로 연 도면에 반영(열린 도면 경로), 새 도면 시작(T-230 미구현), AutoCAD로 열기.

## 시나리오와 결과

1. **합성 기존 도면에 모델 변경 반영(검수 계획 1·3).** 화면에서 [도면 읽기](숨은 ZWCAD, 약 7.6초) → 'DWG 2018 · mm' → [짝 기록](Sync 일치 5행이 반영 기준, xref 자식의 짝 1은 경로로) → 모델에서 선 늘이기·호 반지름 키우기·원 지우기·짝 있는 레이어에 호 추가·도면에 없는 레이어(`Rhino::가구장`)에 원 추가·xref 자식의 호 반지름 바꾸기 → [차이 계산](약 7~24초): 수정 3·추가 2·삭제 1, 자식 행에 'xref' 표지, 추가 하나는 '레이어 지정 필요'. 레이어 대응 표에서 그 원천 레이어를 도면 레이어로 고르고 [표 저장] → 다시 계산되어 선택 가능. 삭제는 기본 미선택이라 손으로 고름 → '선택 6행 · 파일 2개' → [반영] → 저장 확인 카드(DWG 2018·DWG 2013, 이 시점 폴더에 새 파일 없음, 계산 약 13.7초) → [저장](약 0.06초) → 원본과 같은 폴더에 루트·자식 새 파일 2개, 버전 각각 AC1032·AC1027 유지, 두 파일 모두 '형식 보존 확인 — 차이 없음', 연동 안 된 손 치수 1개가 '치수 확인 필요'. 새 파일을 다시 읽으니 고친 개체의 Handle·레이어·색·선종류·선가중치가 그대로이고 기하만 바뀜, 추가 개체는 대응 표의 레이어와 출처 표시를 지님, 지운 개체는 없음. 원본 두 파일 해시 불변. 자식은 자식 파일에만 쓰였고 루트가 새 자식을 가리키게 바꾸지 않았다(SPEC-14.11 2).
2. **손 수정 → 충돌·끊김(검수 계획 2).** 합성 루트를 사람처럼 고친 판(호 반지름 변경, 짝 있는 폴리선 삭제)으로 바꾼 뒤 [도면 읽기]·[차이 계산] → 호는 '충돌 · 모델과 도면이 둘 다 바뀜'(체크 상자 막힘), 폴리선은 '끊김 · 도면에서 지워짐'. [모델로 덮기] → '충돌 → 모델로 덮음' → [반영] → 카드 → [취소] → '저장하지 않았습니다. 쓴 파일이 없습니다.', 폴더 목록 그대로.
3. **도곽 미리보기(검수 계획 4).** 합성 도면(T-235 시험): 창·배치 시트 2 → 목록 등록 5 → xref 후보 고르기 6, CTB 펜 표시. 화면에서는 [도곽 미리보기] 탭이 SCR-30 묶음을 그대로 띄움(브라우저 시험; 도면 관계가 없을 때 안내). 실도면의 도곽 결과는 T-235 기록(PLAN-47 「현재 상태」)을 따르고 이번에 다시 재지 않았다.
4. **새 도면 시작(검수 계획 5):** T-230이 없어 하지 않았다.
5. **실패 주입(검수 계획 6).**
   - 단위 불일치·읽기 실패·파일 없음: 엔진 시험(`tests/server/drawing-layers.test.mjs`·`drawing-backflow*.test.mjs`)이 거절을 확인하고, 화면은 경고색 이유와 [도면 읽기]를 보인다(브라우저 시험은 정상 경로만).
   - 출력 경로의 같은 이름 파일: 이름에 `-2`…를 붙여 덮어쓰지 않음(T-233 엔진 시험). 이번 실호스트에서는 겹치지 않았다.
   - 도면이 행을 거절(잠긴 레이어): 실도면 사본에서 3행 `LAYER_LOCKED` → 전체 취소, 화면은 행 번호와 '잠긴 레이어'를 보이고 사용자가 빼고 다시 반영(브라우저 시험은 같은 응답으로 표시 확인).
   - 숨은 ZWCAD 종료·무진행: `runHiddenZwcad`의 시간 상한·정체 감시(T-226·T-227 시험). 이번에 반영 중 강제 종료는 주입하지 않았다.
   - 손상된 CTB: T-235 엔진·브라우저 시험(내장 흑백 표와 이유).
   - 이전 연결 플러그인: 화면은 `ZWCAD_PLUGIN_UPDATE_REQUIRED`를 '연결 플러그인을 새 판으로 바꾼 뒤…'로 보인다(브라우저 시험).
6. **실도면 사본(검수 계획 1의 형식 유지·7의 시간).** 사용자 제공 도면 세트를 `.vide/` 아래로 `XREF\` 구조째 사본으로 만들어(DWG 24·CTB 1) 엔진 경로로: 도면 관계 읽기 약 38초, 루트 11장 T-227 읽기 약 16초(모두 대상). 루트마다 모형 공간의 지원 개체를 최대 100개 짝 기록 → 모델에서 10 mm 이동 → 차이 계산 → 반영 → 카드 → [저장]: 수정 행 1,010개 계산, 잠긴 레이어 거절 3행을 빼고 1,007행 반영, 11장 모두 새 파일, 11장 모두 형식 보존 차이 0·DWG 버전 유지, 치수 확인 필요 43개, 실패 0, 새 ZWCAD 충돌 보고 0. 사본은 쓰지 않았고(해시 비교) 사용자 원본 폴더의 25개 파일 해시 불변, 원본 폴더에 새 파일 0. 사본과 결과는 검수 뒤 지웠다. 이름·내용은 기록하지 않는다.

## 한계

- **열린 도면 경로:** 사용자의 ZWCAD에 연 도면에 반영하려면 새 연결 플러그인 배포가 필요하다. 설치된 이전 플러그인은 `ZWCAD_PLUGIN_UPDATE_REQUIRED`로 답하고 화면은 그 안내를 보인다. 이번 검수는 사용자 ZWCAD를 쓰지 않았으므로 열린 도면 반영은 `zwcad-backflow-attached.mjs`(같은 `BackflowOps.cs`를 시험 하네스로 불러 숨은 ZWCAD에서 적용·U 한 번 원상)로만 확인했다.
- **xref 자식의 되돌리기:** 열린 xref 자식이 따로 열린 문서일 때 파일마다 되돌리기 기록 하나(ADR-027)이지만, 여러 문서를 함께 연 실호스트 확인은 하지 않았다. 닫힌 도면의 새 파일은 [되돌리기] 대상이 아니다(새 파일이 남는다). 화면의 [되돌리기]는 브라우저 시험(모의 응답)으로만 확인했다.
- **Rhino 원천:** 원천 스냅숏과 Sync jig 위치 관계는 시험이 넣은 값이다. Rhino Sync에서 되찾은 곡선의 정밀도(float32, 0.01 mm 허용)는 T-232·T-233 시험이 본다.
- **결과 사본을 ZWCAD로 열어 보통 도면인지:** 새 파일을 숨은 ZWCAD가 다시 읽어 개체·기호표·레이아웃·xref·버전이 같음을 확인했다. 창을 띄워 사람이 열어 보는 확인과 AutoCAD 확인은 하지 않았다.
- **치수:** '치수 확인 필요'는 목록만 보이며 치수를 고치지 않는다(SPEC-14.8 4).
