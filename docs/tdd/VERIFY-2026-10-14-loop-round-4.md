# 검증–수정 루프 라운드 4

[PLAN-51](../plans/PLAN-51-verify-loop.md) §5 수정 웨이브 3(T-270·T-280·T-283·T-287·T-288·T-289)을 담은 설치본 0.2.34에서 다시 잰 기록이다. 라운드 3 기록은 [VERIFY 라운드 3](VERIFY-2026-10-14-loop-round-3.md)이다. 판정 등급은 PLAN-51 §1·§2를 따른다. 페르소나의 직관·쉬움 판정과 `goalReached`는 모두 **대행 판정**이다. `goalReached`는 검수자가 스크린샷을 읽고 손으로 적었고, 근거는 각 `run.json`의 `goalReachedNote`에 있다. 스코어카드 판정(`tools/ab/scorecard.mjs`)과 검토 판정이 다르면 둘 다 적는다.

**요약:**
- 스코어카드는 P0 4 · P2 1 · PASS 1로 통과율 1/6이다(`.vide/ab/r4-scorecard-installed/`). R1-HIDE가 P0에서 P2로 올라왔다. route-only는 7/7 PASS다.
- 다섯 페르소나 런은 모두 `completed`였다. 오보 M1·엔진 종료·요청 failed/unknown/interrupted·`server-error`는 0건이고, 다른 프로젝트의 Link 변경도 0건이다.
- 웨이브 3의 핵심은 설치본에서 확인됐다.
  - **T-287:** 죽은 행이 열린 연결로 잡히지 않았다. 법규 체크가 이번 Link를 읽어 결과 표까지 갔다.
  - **T-270:** "보만 남기고 다 숨겨줘"가 AI 요청 없이 보 레이어 22개를 모두 남겼다.
  - **T-288:** 사이트 모델링이 1~8단계를 계산하고 '9. Rhino에 만들기' 앞에서 멈췄다.
  - **T-283:** Sync jig가 솔리드 단면 변 2,044개를 비교해 대응 1쌍을 냈다.
  - **T-280:** jig 요청 3건이 모두 새 CLI 세션(`resume` 없음)으로 시작했다.
- 그래도 R1-D·A·C·B는 페르소나 막힘이 있어 §1 기준 P0다.
  - **R1-D:** 레이어 선택칸이 네이티브 `<select>`라 드라이버가 고르지 못했다(도구 한계). AI는 질문 카드로 레이어를 물은 뒤 "역할을 정하는 일은 제가 할 수 없습니다"라고 답했다.
  - **R1-A:** 같은 문장 재전송 무반응(T-291)으로 막힘을 선언했다.
  - **R1-C:** 결과 행이 모두 '규제 조건 없음'이었고 결과 직후 '다시 체크 필요' 띠가 떴다.
  - **R1-B:** 확정 뒤 [가져오기]와 [만들기] 출력 레이어 안내에서 무진전이 났다.
- **T-274:** 처음으로 실제 읽기를 쟀다. 분류 단계(`classifyMs` 5.25–5.39 s)가 읽기 시간의 대부분이고, 같은 시간대 `health` loopMax는 5.66–5.83 s였다.
- **T-285:** ZWCAD 단독 Sync는 100,318 ms로 라운드 3과 같다(경보선 5.0배).
- 새 티켓은 도구 1(T-292), P0 후보 1(T-293), P2 3(T-294~T-296)이다.
- **졸업:** 0/10이다. R1-NOTE는 route-only PASS 3라운드 연속이지만 사용자 동승 0회·답 내용 미시험이라 졸업이 아니다.
