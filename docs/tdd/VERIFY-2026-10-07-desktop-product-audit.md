- 설치 VIDE: 0.2.26.0, 제품 버전 `0.2.26+846b8239993c646a02bb748f405964ae43329939`.
- Computer Use: 26.930.41038. 실제 창 목록·스크린샷·키보드·마우스로 조작한다. 테스트 도구의 좌표/포커스 오류는 제품 오류로 집계하지 않는다.

## CAD 재연결 실패의 진단 근거

실제 UI 재현 뒤 로컬 DB와 연결 메타데이터를 읽기 전용으로 대조했다. 연결 token은 열람/기록하지 않았다. 현재 document_links와 실행 중 CAD 연결의 세션은 `848479fa-…`로 일치했지만, 기존 대화 요청 `6f5ae6c7-…`와 독립 대화 요청 `fd71b2c9-…`의 sourceDocument.instance는 재열기 전 `5bbcbe0e-…`였다. 두 요청은 이전 캡처 시각 `2026-10-06T16:32:02.715Z`를 계속 사용했다. 엔진 로그의 query는 1~2ms 안에 DOCUMENT_MISMATCH로 실패했다. 새 대화만으로 해결되지 않았다.

이는 ‘경로를 코드로 열어서 실패했다’는 설명으로는 맞지 않는다. 파일 열기와 연결은 실제 호스트 화면에서 성공했으며, 현재 연결과 요청 기준의 세션 불일치가 확인됐다. 오래된 기준을 선택하는 정확한 코드 경로는 추가 분석 대상이다. 전체 Sync 후 F5로 화면 기준을 갱신하면 새 원이 나타났고, 이후 핀 조회와 색상 편집도 성공했다. CAD AI 기능 전체가 불가능한 것이 아니라 재연결 후 기준 갱신 경로에 문제가 있다.

복구 뒤 핀 요청 `42b97658-ac93-4e2d-a7b7-5a5f4d5282bd`는 실제 열린 도면의 Circle handle 489638, 중심 (2259628.8249, 619503.0843, 0)mm, 반지름 32733.2854mm를 반환했다. 색상 편집 `6feeb15c-ee58-4b9f-b610-93ebd30c27c5`는 첫 실행 코드 정책 거절 뒤 두 번째 실행으로 ACI 5를 적용했다. 실제 실행 1,489ms, 재조회 697ms에 비해 요청 전체는 117,153ms였다. 답변 단계로 집계된 103,530ms의 세부 원인은 추가 분석 대상이다. 되돌리기 경로는 2026-10-06T16:51:12.290Z에 180,909,730 bytes 응답 전송을 기록했지만 원의 색상 복구는 관찰되지 않았다.

되돌리기 후 읽기 전용 DB 확인에서도 execution `58f92745-60cd-4c54-9c5b-35899468612f`는 state=applied, undoneAt 없음이었다. 호스트 구현은 `_.U _VIDEAIUNDONE`을 순서대로 실행하고 revision 변화로 취소를 판정한다. 화면의 ManagedDocLock과 이 구현을 근거로 취소 스택을 후속 조사 대상으로 삼되, 정확한 원인을 확정하지 않는다.

재현 요청 식별자: 독립 Claude `fd71b2c9-e5bc-44c4-b3e5-fd0ea3f9ea6e`(조회 실패 후 18,857ms에 응답 완료), 자동 선택 `81990705-9d4b-44d2-8374-cccb6050809d`(34ms에 CLI_VERSION_UNSUPPORTED), 전체 Sync `b353608f-b15b-4359-acf9-4afe74a40f37`(93,191ms 성공). 로그는 로컬 VIDE/logs의 engine-2026-10-06.jsonl에 있다. 이 실행 중 새 엔진 종료는 현재까지 확인하지 못했다.

## 우선 확인할 제품 문제와 개선안

- 실시간 CAD 조회 실패의 실제 오류·실행 기록을 확인해야 한다. 저장 Sync로 답하는 복구는 가능하지만 열린 도면을 직접 읽는 기능 통과와 구분한다.
- 노트 화면의 CAD 요청이 Rhino 대상으로 시작하고 모델 화면에서는 ZWCAD 대상으로 바뀌었다. 전송 전에 대상 파일이 명확히 보여야 한다.
- ‘Link와 Sync가 완료된 상태’라는 설명을 포함한 조회 요청에 다시 Sync할지 묻는 카드가 끼어들었다. ‘AI 작업으로 보내기’를 눌러 진행했다. 완료 상태 설명과 동기화 명령을 구별할 필요가 있다.
- ‘Sync 완료 3,841개’와 ‘표시 3,717개·미지원124’를 같은 위치에서 설명해야 한다. 현재는 누락 여부를 사용자가 수치 비교로 추론해야 한다.
- 2D CAD 도면이 처음에는 비스듬한 3D 시점으로 표시돼 위 보기를 눌러야 읽기 쉬워진다. CAD에는 평면 보기를 기본으로 제안한다.
- 연결 파일은 대시보드의 큰 월간 달력 아래 접힌 영역에 있다. 연결 검증이라는 주요 동작의 발견성이 낮다.
- AI 응답 Markdown 렌더링, 짧은 결과 우선 표시, 노트 작업에 맞는 진행 단계가 필요하다.

## Rhino 복구·사본 실측과 적용 범위

H-RHINO 지원 범위와 AC-39의 실제 열린 문서 편집을 small.3dm에서 시험했다. Rhino의 연결 프로젝트 및 연결 선택 대화상자가 부모 없이 열리던 경로에 `RhinoEtoApp.MainWindowForDocument(doc)`를 지정했다. 오류 알림도 UI 스레드에서 같은 부모를 사용한다. 로컬 빌드한 플러그인으로 새 Rhino를 실행한 뒤 작은 파일과 큰 파일 모두 화면에서 Link를 마쳤다. 최초 막힘을 파일 경로 오류나 사본 부재로 설명할 근거는 없다. 수정 전 자동 조작의 창 복원 현상과 모달 소유 문제는 구분해야 하며, 수정 후 정상 동작을 확인했다.

## 도구와 환경의 관찰

Rhino 연결 대화상자 선택 과정에서 호스트 창이 작아지고 모달이 캡처에 나타나지 않았다. 부모 창은 disabled로 조회됐다. 사용자는 다른 에이전트나 직접 조작 없이 기다리는 중이라고 두 차례 확인했다. 동시 조작으로 설명하지 않는다. 당시의 자체 실행 Rhino를 종료하고 부모 창을 명시한 플러그인으로 다시 실행한 뒤 Link를 완료했다. 창 활성화 시 작게 복원되는 자동 조작 현상은 별도로 남아 있어, 최신 캡처에서 최대화하고 진행했다.

CAD 명령줄에 type_text로 _CIRCLE을 입력한 한 차례에 무관한 이전 클립보드 문자열이 들어갔다. 즉시 Esc로 취소했으며, 단일 키 C와 Enter·마우스 클릭 경로로 원 생성에 성공했다. 이후 VIDE 한국어 입력은 정상 동작했다. 이 현상은 CAD 제품 오류와 구분한다.

CAD에서도 부모 창이 복원 크기로 바뀌어 모달 하단이 가려졌지만, list_windows에 반환된 연결 모달을 직접 대상으로 선택해 클릭하니 진행됐다. 내장 CAD 웹 패널 클릭은 Computer Use가 msedgewebview2.exe를 다른 대상이라고 거절했다. 네이티브 VIDECADLink 명령은 정상 동작했다. 에이전트가 처음 입력한 VIDELINK는 Rhino 명령이어서 CAD가 알 수 없는 명령으로 응답한 것이며 제품 오류가 아니다. 접근성 트리가 오래된 AI 진행 상태를 반복하는 동안 실제 화면은 완료 응답을 표시하기도 했다. 판정은 최신 화면과 실제 동작을 우선했다.

## 증거 보존과 종료

시험 프로젝트에는 대화·노트·완료된 할 일·JIG 작업본·검토본·시험 폴더 연결을 남겼다. DWG의 파란 원은 앞선 시험 사본에 저장했으며 후속 초록색 변경은 Undo했다. Rhino의 small-verified.3dm은 다른 이름으로 저장했다. 사용자 지정 원본 사본 폴더의 파일은 수정하지 않았다. 다운로드한 HTML 두 개는 사용자 Downloads에 있다. 실제 화면 조작·반복 재연결·저장/재열기·Sync 동시 변경과 563MB Rhino의 열기·Link·Sync를 실행했으며 장시간 반복 부하는 미시험이다.

앞선 비활성 모달에 막힌 자체 실행 Rhino들은 프로세스 식별 후 종료했다. 수정 플러그인 시험에 쓴 Rhino PID 23344와 ZWCAD PID 35496은 실제 창에서 Alt+F4와 저장 확인 대화상자로 종료했으며 프로세스가 사라진 것을 확인했다. 큰 Rhino 사본의 Link 메타데이터와 CAD 후속 시험 변경은 추가 저장하지 않았다. 시험 플러그인 등록은 유지돼 다음 호스트 실행에 적용된다. ## 미완료

이 문서는 전체 기능 통과 보고가 아니다. Rhino Link/Sync/핀/단일 색상 편집/되돌리기와 큰 파일 열기·Sync, CAD 속성 변경 집계·Undo는 수정 후 실제 시험을 통과했다. 재연결·화면 갱신·편집 후 capture·Undo 전송·CLI 호환·진행 상태는 위 후속 수정과 회귀 시험에 반영했다. 최초 대형 도면 전체 Sync 지연과 Rhino 기존 이름 저장 오류의 환경 원인은 남아 있다. 새 세션으로 재연결한 후의 모든 AI 대상 선택 조합은 아직 실제 재시험하지 않았다. Rhino↔CAD 동시 조율, 큰 파일 반복 편집, 입력이 갖춰진 JIG 계산·베이크, 완성 보고서 인쇄, 두 사람 동시 협업·권한 충돌은 미검증이다. 이번 테스트에서 새 엔진 종료는 관찰하지 못했으나 5.7초 이벤트 루프 정지가 있었으므로 엔진 안정성 전체를 통과 처리하지 않는다.
