디자인 DNA · 배치 · 컴포넌트 · 화면 표현

초록 추가·교체 제안빨강 삭제·교체 대상CLAUDE: 파란 상자 · CODEX: 보라 상자

검토자 필터는 코멘트·부록만 바꿉니다. ‘인라인 제안 미리보기’는 코멘트의 대안까지 합친 최종본이 아닙니다. 보기 전환은 MD 수정·수락·승인을 하지 않습니다.

요청별 실행 상한(SPEC-02.6)은 오른쪽 초안 메뉴의 작업 상한에서 작은 모달로 조절한다. 도구 호출 수·대상별 호스트 실행 수·AI 응답 시간(초)을 표시하고 적용/취소를 제공한다. 실행 중인 작업의 값은 변경하지 않는다. ACTIVE WORK의 실행 횟수 분모는 해당 요청에 고정된 상한을 사용한다. 기본 화면에 상시 설명 문단을 추가하지 않는다.

이 문서는 화면의 시각 언어·배치·컴포넌트·조작 표현을 소유한다. 기능 입력/결과·상태 전이·권한은 SPEC, 기술 구조·저장/API는 ARCH, 구현 순서·시험 방법은 PLAN을 따른다. 기능을 설명하는 문장을 여기서 다시 확정하지 않는다. 문서별 판단 방법과 개발 진행은 개발 가이드 §01·§12에 있다.

기능 의미가 바뀌면 SPEC을 고치고, 같은 의미를 더 잘 보여 주는 변경이면 이 문서를 고친다. 아래 상태 라벨은 SPEC 상태의 표현이며 서버 동작을 정의하지 않는다. 현재 개발 지시·착수 기준은 가이드 §12를 읽는다.

01 / 디자인 DNA

도면을 보는 듯 정돈된 작업 공간. 모델과 의도가 주인공이고, AI 대화는 그 둘을 연결한다.

  • 무채 웜 그레이 바탕, 0.5px 경계, 정렬된 정보와 고정 코랄 포인트 하나를 사용한다(§02).
  • 중앙 형상을 충분히 크게 두고 필요한 설명은 대상·후보 가까이에 둔다.
  • 중요한 치수·대상·현재 기준은 읽기 쉬운 글자로 표시한다. 작은 배지를 빽빽하게 나열하지 않는다.
  • 한 화면에서 현재 판단에 필요한 정보부터 보여 주고, 근거·실행 이력·진단은 펼쳐 읽는다.
  • 강조는 현재 선택과 주요 행동에 사용한다. 과장된 그림자·장식적 그라디언트·반복 로딩 애니메이션은 피한다.
  • 목록 행·카드의 현재 선택은 옅은 배경으로 표시한다. 둥근 행이나 상자의 왼쪽에 색 막대를 붙이는 표시(괄호처럼 휘어 보이는 강조선)는 쓰지 않는다(2026-09-30 사용자 지적).

별도 전체 폭 상단 바는 두지 않고 프로젝트는 좌측 탐색에, 패널 토글은 뷰포트 양쪽 경계에 둔다. 단계 안내·영문 소제목·설명용 큰 제목을 반복하지 않는다. 모델과 입력을 먼저 보여 주며, 작업이 없을 때 결과 영역을 숨긴다. 보조 설명은 상세 펼침/도움말로 옮기고 오류와 필요한 다음 행동은 해당 위치에 표시한다. 검수 화면 여부는 짧은 표시로 유지하고 제한 설명은 그 상세에서 제공한다.

화면은 ‘무엇을 보고 있는가’, ‘어디를 바꾸려는가’, ‘어떤 결과를 검토하는가’, ‘지금 누를 행동은 무엇인가’에 답해야 한다.

02 / 시각 토큰과 타이포그래피

위 두 블록과 어두운 값이 시각 토큰의 정본이다. 글꼴은 Inter·Noto Sans KR·JetBrains Mono 가변 글꼴을 앱에 동봉하고(@fontsource-variable), 없으면 설치된 글꼴로 대체한다. 본문 13px, 보조 12px, 작은 표지 11px, 작업 제목 20px이며 10px 이하는 쓰지 않는다. 숫자·KPI는 --font-mono로 자릿수를 정렬한다. 일반 설명은 자연스럽게 줄바꿈하고 이름·단위·수치는 함께 읽히게 한다.

간격은 4/8/12/16/24px 단위(보고서의 큰 여백은 32/48px), 모서리는 세 값(6/10/14px)만, 그림자는 겹쳐 뜬 것에만 한 종을 쓴다. 기본 주요 버튼은 --cta-bg 바탕과 --cta-text 글자다. 코랄은 작은 글자의 유일한 강조색으로 쓰지 않는다. 실제 색 조합의 읽기 가능성은 PLAN의 화면 검수에서 확인한다.

03 / 작업 공간의 배치

바뀌는 방식: 2026-10-01 사용자 결정(ADR-026 결정 5와 그 조정)으로 이 배치(레일·좌측 탐색·작업공간 탭·우측 AI 열)는 유지하고, 사용자가 명시한 변경만 하나씩 반영한다: 레일의 대시보드·프로젝트 자료·피드백·다크/라이트, 작업공간 탭의 대시보드·산출물(도면·보고서·렌더링, 보고서 탭을 흡수), 연결 파일 행 정리, lucide 아이콘과 Inter·Noto Sans KR·JetBrains Mono 글꼴(PLAN-26 T-079·T-081). 레일 = 고정 화면(대시보드·모델·작업 이력·자료·JIG·만들기·산출물), 위쪽 줄 = 열어 둔 작업본·표만, 열린 것이 없으면 숨김(2026-10-01 사용자 결정). 화면 검토는 실제 빌드를 찍은 미리보기(tools/mockups/ui-preview/)로 한다. 아래 배치가 유효하다.

위 그림은 기본인 모델 탭이다. 프로젝트와 작업 문맥·요청 목록(작업 이력)은 좌측 탐색에, 형상/표/비교는 중앙에, 선택 상세는 중앙 하단 검사기에, 선택한 작업 하나의 진행·결과·개입은 우측에 배치한다. 우측 보기를 바꾸어도 작성 위치를 쉽게 다시 찾을 수 있게 입력 복귀 행동을 둔다. 배치 전환은 아래의 고정 배치 작업공간 탭으로만 하며, 재귀적 화면 분할·자유 도킹·노드 배선 편집기는 추가하지 않는다.

‘보고 있는 문서’는 중앙의 간결한 문맥 표시, ‘요청 대상’은 입력기의 핀에 표시한다. 두 의미의 동작은 SPEC-01.9·10을 따르고, 화면에서는 같은 라벨로 합치지 않는다. 중앙 ‘도면’ 표시는 지원 도면 표현을 뜻하며 별도 CAD 편집 기능의 정의가 아니다.

좌우 패널의 접기와 복귀

사용자가 선호한 Aside의 작업 공간 경험을 참고해 좌측 탐색과 우측 작업 패널에 독립적인 접기/펼치기 버튼과 단축키 진입점을 둔다. 접힌 상태에서도 복귀 버튼은 남기고 버튼의 도움말에 실제 단축키를 표시한다. 중앙 모델을 넓게 보다가 동일한 작업 문맥으로 돌아오는 표현을 우선한다. 현재 DNA의 색·글꼴은 유지한다.

접기/펼치기에서 초안·선택·스크롤과 키보드 포커스를 잃지 않게 하고, 숨겨진 패널 내부에 포커스를 남기지 않는다. 저장·실행·취소 행동과 패널 토글을 혼동시키지 않는다. 구체 키 조합은 Windows/브라우저/호스트 충돌 검사 후 정하며 Aside의 Ctrl+S를 그대로 사용하지 않는다. 조사 근거와 구현 비교는 PLAN-01 §2.1·5를 따른다.

도구와 작업 영역

사용자 UI 스터디에서 합의한 배치를 다음 기준으로 유지한다. 뷰포트 왼쪽의 세로 도구는 선택·스케치, 오른쪽은 3D·위·앞·옆·전체 보기를 맡는다. 기본 클릭은 객체 선택이다. 객체를 고르면 뷰포트 위 선택 막대에 선택 수와 [요청에 고정]을 둔다(고정은 연결된 Rhino에도 표시된다). 스케치 작성 중에만 스케치 도구 막대(§04)를 표시한다. 좌우 패널 접기는 각 경계의 상단에 작게 배치한다.

왼쪽은 프로젝트·작업 문서·작업 이력·참고 자료를 담는다. 요청 목록은 작업 이력 하나에만 두고 행마다 상태를 표시한다. 작업 문서의 맨 위는 연결 파일 목록(SPEC-01.11)이다: 행마다 보이기 토글(눈), 호스트 표식, 파일 이름, 상태 점(Live·연결됨·닫힘), 마지막 Sync 시각·객체 수, ⟳ 강제 Sync, 빼기(더보기)를 둔다. 행을 누르면 그 파일이 작성기의 대상이 되고 그 파일을 화면에 맞춘다. 연결 파일이 없으면 점선 상자에 '아직 연결된 파일이 없습니다'와 번호 붙은 세 단계(파일 열기 → VIDE 패널의 Link에서 현재 프로젝트 이름(파란 표식) 고르기 → 첫 Sync 뒤 표시), 명령 이름과 '파일에서 열기' 안내를 둔다. '파일에서 열기'로 연 파일은 회색 네모 표식과 '파일에서 연 사본'으로 구분하고 Sync 버튼 자리를 비운다. 목록 빼기(연결 해제)와 작업 이력 지우기 버튼은 늘 흐리게 보이고 가리키면 진해진다. 계정에 로그인한 PC면 목록 아래에 'PC가 꺼져도 사이트에서 보기' 체크와 저장 상태(저장 개수·크기, 저장 대기, 저장 실패 이유)를 한 줄로 두고, 사이트에서 남긴 요청이 있으면 목록 위에 산호색 테두리 상자로 요청 글·시각·대상 파일과 '작성기로'·'지우기'를 둔다(SPEC-04.9). 계정 사이트는 PC가 꺼진 프로젝트를 누르면 왼쪽에 저장된 모델(평면·3D 전환, 오른쪽 위 레이어 목록, 흰색 CAD 색은 어둡게), 오른쪽에 요청 남기기(대상 파일, 요청 글)와 요청 목록(PC 대기 중·PC에 전달됨·취소됨)을 둔다. 좁은 화면에서는 위아래로 쌓는다. 객체 목록은 그 아래에서 파일별로 묶어 펼친다. 파일 가져오기는 작업 문서 영역에 배치한다.

뷰포트는 보이기로 둔 모든 파일을 함께 그린다. 주 파일은 없다. 작성기 첨부 영역에 '대상 파일' 칩을 두어 지금 요청이 어느 파일을 고치는지 보여 준다. 경로는 보낼 때 Jev가 정하므로 보내기 전 칩은 없다. 판정하는 짧은 동안 보내기 버튼을 흐리게 하고, 화면만으로 처리한 알림(하단 어두운 상자)에 'AI 작업으로 보내기' 버튼을 둔다(SPEC-02.17). 모델 자동 선택은 모델 메뉴의 '자동 (Jev)' 항목 하나로 한다. 오른쪽은 대화 칩(SCR-15)으로 고른 대화 안에서 선택한 작업의 작업 보기(§06 SCR-03)와 하단 작성기이며 작성기에서 작업 모드(계획/자동)·공급자/모델·effort를 함께 선택한다. 공급자·모델은 대화를 시작할 때 정해지고, 그 대화 동안에는 읽기 표시로 두며 effort만 턴마다 고른다(SCR-15). 실행별 바뀐 객체와 [되돌리기], 내려받기·검토본 출력은 작업 보기의 결과 영역에 붙이고 측정값은 펼쳐 확인한다.

실제 기능·지원 범위는 SPEC, 구현/진행 상태는 PLAN과 VERIFY에 따른다. 이 기준은 화면의 최종 사용자 검수 완료를 뜻하지 않는다.

객체 검사기와 시스템 상태

화면은 어두운 탐색 레일, 프로젝트 문서 패널, 3D 뷰포트와 하단 객체 검사기, 오른쪽 AI 작업 패널로 구성한다. 색은 §02 토큰을 따른다. 아이콘은 같은 선 두께의 SVG로 통일하고 접근 가능한 이름과 툴팁을 붙인다. 레일은 실제 작업 문서·이력·자료로 이동한다.

하단 검사기는 선택 객체의 속성·형상·이력을 제공하고 접을 수 있다. 호스트의 실제 네이티브 ID와 측정값을 표시하며 기하 면적을 연면적으로 이름 붙이지 않는다. 없는 레이어·층·관계·BIM 속성을 예시 값으로 채우지 않는다. 오른쪽은 실제 요청과 상태, 결과 행동, 하단 문맥·메시지 작성기와 모드·모델·effort를 유지한다. 스터디의 가짜 타이머 실행·예시 관계·샘플 상태는 제품 동작으로 옮기지 않는다.

각 영역의 역할은 왼쪽 프로젝트 구조, 중앙 왼쪽 공간 입력/편집, 중앙 오른쪽 카메라/보기, 중앙 하단 선택 객체 정보, 오른쪽 요청·실행·결과, 최하단 시스템 상태의 역할 분리다. 별도 전체 폭 프로젝트 바는 두지 않고 프로젝트 이름은 왼쪽 패널 상단에 둔다. 치수는 §12.9를 따르고 중앙이 남은 폭을 차지한다.

검사기는 미선택 시 38px 요약 바만 남기고 선택 후 사용자가 펼쳐 상세 정보를 확인한다. 선택 정보와 시스템 상태를 섞지 않는다. 관계·근거 탭은 실제 데이터 연결과 함께 추가한다. AI 요청은 AI 작업 영역에, 선택 객체 첨부는 검사기 헤더에 둔다. 오른쪽은 요청 묶음(REQUESTS), 실제 실행 상태(ACTIVE WORK), 이전 결과(RECENT)의 구분을 목표로 하며, 요청 목록은 제출 전 개별 문장을 편집·삭제할 수 있고 공통 참조와 실행 설정을 사용한다. 실제 실행 상태는 별도 영역, 결과 행동은 이력 카드에서 확인한다. 연계 유지 대상은 “변경 없음 · 기존 후보 확인”으로 표시한다. 복구 후보는 “사본 복구됨 · 목표 완료 미확인”으로 표시하고 “복구 후보에서 이어가기”로 조건이 보존된 후속 초안을 연다. 자동 전송하지 않는다. 실제 조회·실행 시도가 관측되면 진행 상태 아래 한 줄에 조회 완료 수·실행 시도/상한을 표시한다. 전체 완료율로 표현하지 않으며 작업 사본(검토·jig 내부 사본)의 검증과 열린 문서에 바로 적용한 실행을 구분한다. 진행 중인 상위 작업에는 현재 입력을 그 작업에 연결하는 “추가 지시” 행동을 둔다. 연계 하위 작업에는 중복 버튼을 두지 않는다. 연계 상위 버튼의 도움말은 기존 두 대상에 추가한다는 것을 알린다. 대상·모드가 맞지 않거나 입력이 비어 있으면 비활성 이유를 표시한다. 후속은 “추가 지시 접수 · 이전 작업 종료 대기”로 표시하고, 보류된 후속은 이유와 기존 초안 복원 행동으로 연결한다. 자유 3D의 Ortho/Perspective 전환과 선택 프레이밍을 카메라 도구에 두고 검사기 경계는 드래그와 방향키로 높이를 바꾼다.

핀 칩에는 변경·유지·참고 역할 선택을 둔다. 후보 결과의 ‘수량표’는 해당 기준의 객체·유형·길이·기하 면적·체적과 미상 제외 건수를 보여 주며, 행에서 객체 선택과 CSV 출력으로 연결한다.

객체 사용자 속성 표시

SCR-01 하단 Inspector의 Properties에 이 객체 수량표 행동을 둔다. 선택한 객체로 좁혀진 표를 열고 표 안에서 전체 범위로 돌아갈 수 있다. Properties에서 Rhino 사용자 속성은 기존 속성 그리드 아래에 표시한다. 일부만 읽혔으면 누락 안내를 표시하며, 표시 속성을 요청에 첨부 행동을 둔다. 값은 일반 텍스트로 표시한다.

04 / 입력기와 대상 토큰

입력의 기본은 우측 하단에 고정한 범용 대화 작성기다. 위쪽은 대화/작업 결과, 입력 상자는 첨부 칩·자유 문장·첨부(클립) 버튼·전송, 바로 아래는 작업 모드(계획/자동, Shift+Tab으로 전환)·모델·effort 선택이다. 계획은 '문서를 바꾸지 않음', 자동은 '열린 문서에 바로 적용'으로 읽히게 하고 하단 상태줄에도 같은 문구를 둔다. 높이·폭 등 특정 과업의 필드를 기본 폼으로 고정하지 않는다. 필요한 치수는 사용자 문장 또는 해당 대상의 상세 편집에서 다루고 미확정 값은 관련 실행 단계에서 질문한다. 모델별 가능한 설정의 의미는 SPEC-05.2를 따른다.

고정(핀)은 뷰포트 선택 막대의 [요청에 고정] 또는 문장 커서 위의 흐린 칩(현재 선택 넣기)으로 넣으며, 문장 안에 [고정N · k개] 토큰으로 보인다. 이 토큰은 사용자가 직접 고정한 집합이다. 스케치는 중앙 뷰포트 도구로 그린 뒤 입력의 첨부 칩으로 연결한다. 스케치 도구 막대는 색상 견본·굵기·지우개·표면에 붙이기·되돌리기·비우기·첨부·취소만 둔다(그리기 위치는 SPEC-01.5.2가 자동으로 정한다). 첨부한 뒤 선택을 바꿔도 기존 핀은 바뀌지 않는다. 첨부(클립) 버튼은 메뉴 없이 파일 선택 창을 바로 열고, 이미지·파일은 입력 상자에 붙여넣거나 끌어 놓아도 첨부된다. 첨부한 파일은 문맥 줄의 칩(이미지는 칩 높이에 맞춘 작은 미리보기)으로 보이고 ×로 뺀다(SPEC-01.12).

연계 대상 선택은 여러 파일이 보일 때 입력기의 대상 파일 칩을 눌러 연다(첨부 버튼에는 두지 않는다, SPEC-01.12의 5). 두 기준 후보의 호스트·이름을 고르고 공통 좌표 기준을 확인한 뒤, 입력기에는 대상 두 개의 간결한 칩만 표시한다. 결과는 호스트별 후보 보기와 상태로 구분하며 부분 실패를 전체 완료 배지로 덮지 않는다. 동작은 SPEC-02.14·15, 물리 계약은 ARCH-01을 따른다.

입력기는 문장, 객체 핀, 원본 선, 자료 참조를 같은 문맥에서 읽히게 구성한다. 대상 토큰은 이름과 ‘변경/유지/참고’ 역할을 함께 표시한다. 누르면 문서·기준·참조 상태를 팝오버에서 확인하고, 제거 아이콘에는 ‘요청에서 제외’라는 라벨을 사용한다. 끊긴 참조는 아이콘과 문구를 함께 사용한다.

객체 선택 뒤 [요청에 고정] 또는 문장 커서의 현재 선택 넣기로 입력기에 넣는다. 드래그만으로 조작하게 하지 않는다. 모델 위 의견 진입점은 작은 입력기를 열며 전체 입력기와 동일한 토큰/선 표현을 사용한다. 입력의 저장·실행 의미는 SPEC-01.10을 따른다.

의견에는 ‘의견 저장’, 새 작업에는 ‘작업 요청’, 현재 작업에는 ‘이 작업에 지시’를 명시한다. 문장 입력의 Enter는 줄바꿈이며 실행 버튼을 대신하지 않는다. 전송 범위는 ‘이번 요청의 문맥’ 상세에서 확인하고 기본 입력 공간을 거대한 설정 양식으로 채우지 않는다.

입력 상세는 SPEC-01.5.1~3에 맞춰 대상별 치수·단위·출처를 보인다. 스케치의 그리기 위치는 표면에 붙이기 켜기·끄기와 보기 방향으로 정하며 평면·선 역할을 따로 고르게 하지 않는다. 미확정은 빈 값/선택 필요로 표시한다. 검수 화면의 합성 표시는 PLAN §6.1을, 개발 진행은 가이드 §12를 따른다.

초안 메뉴의 펼침

AI WORK 헤더의 더보기 메뉴는 헤더 높이를 바꾸지 않고 버튼 아래에서 펼친다. 항목은 오른쪽 정렬 드롭다운에 모으고 모바일에서도 화면 안에 둔다. 메뉴가 열린 상태에도 같은 버튼으로 닫을 수 있어야 한다.

05 / 뷰어·선택·스케치 표현

중앙의 기본 표현은 실제 3D 뷰포트다. 원근 카메라의 회전·확대·이동, 객체 선택과 강조, 3D/위/앞/옆 전환을 제공한다. 정적 투영 그림으로 3D 탐색을 대신하지 않는다. 스케치 도구에서는 표면에 붙이기 상태와 그리기·카메라 조작 방법을 도구 막대와 안내 줄에 보인다. 카메라 조작(손가락·우클릭)과 획 입력(펜·드래그)을 분리하며 취소된 제스처로 점이나 선을 확정하지 않는다.

최초 모델이 없을 때 뷰포트에 연결 대기·연결됨/Sync 대기·가져오는 중·Sync 실패를 짧게 표시한다. 실패 상세는 하단 오류 기록에서 확인하며, 안내가 포인터 입력을 가로채거나 기존 모델·스케치를 덮지 않는다.

직접 읽기 Sync의 결과는 Rhino 화면 동기화 · 원본 변경 없음으로 표시한다. 생성하지 않은 네이티브 파일의 다운로드/열기나 저장·재열기 검증 완료 표시를 제공하지 않는다. 검증된 작업 사본·후보와 구분한다.

Rhino의 VIDE 도킹 패널과 ZWCAD 팔레트의 구성은 SCR-12(§09)가 정한다. 마지막 조회를 브라우저 렌더링 완료나 파일 저장 완료로 표시하지 않는다.

선택은 외곽선과 이름으로, 원본/후보는 선 패턴과 라벨로 구분한다. 색만으로 선택·오류·후보를 구별하지 않는다. 원래 객체 색과 겹치는 경우에도 외곽선/패턴이 읽혀야 한다.

현재 도구(선택·스케치)와 그 조작을 뷰포트 아래 안내 줄에 텍스트로 표시한다. 스케치 도구 막대는 색 견본·굵기([ ])·지우개(E)·표면에 붙이기(S)·마지막 획 지우기(Ctrl+Z)·비우기·입력에 첨부·취소를 둔다. 취소는 그리는 중인 획을 버리는 행동이며 이미 첨부한 스케치를 입력에서 빼는 행동과 다르게 안내한다. 공간 기준과 보존 동작은 SPEC-01.5를 따른다.

미등록 이미지는 ‘공간 기준 미등록’, 이전 자료는 취득 시각/기준으로 표시한다. 스케치와 탐색 모드는 펜/터치에서도 구분한다. 실제 기기별 제스처 선택과 검증 범위는 PLAN의 기기 검수에서 확인한다.

탐색과 카메라 조작

좌측은 연결 문서·작업·참고 자료의 탐색을 맡는다. 전체 객체 목록을 최상위에 상시 노출하지 않고 문서 안에서 필요할 때 펼친다. 선택의 기본 진입은 3D 뷰포트이며 현재 선택과 속성은 중앙 하단 검사기에 표시한다. 작업 목록은 실제 제출한 요청, 자료 목록은 실제 첨부한 파일을 표시하며 가상의 항목을 채우지 않는다.

패널 접기/복귀는 뷰포트 양쪽 경계의 작은 버튼으로 제공한다. 패널을 접어도 같은 위치의 복귀 버튼과 단축키가 유지된다. 별도 전체 폭 상단 바를 없애고 뷰포트와 대화가 창 위부터 사용한다. 앞·위·옆은 OrthographicCamera와 평행 이동/확대로 고정하며 드래그 회전으로 방향을 잃지 않게 한다. 3D는 PerspectiveCamera로 전환한다. 전체 보기는 모델 범위를 기준으로 프레이밍하며 패널 폭 변경은 비율을 갱신하고 사용자의 줌·대상을 임의 초기화하지 않는다.

06 / 작업 카드와 정보 밀도

카드는 작업 목적·대상·최근 실제 결과·현재 행동을 우선 표시한다. SPEC-00.8의 Task/Run 관계는 작업 제목 아래 실행 이력으로 표현한다. 내부 실행 식별자를 기본 제목으로 쓰지 않는다. 접수된 지시와 결과는 시간순으로 연결하되 긴 로그처럼 기본 화면 전체를 차지하지 않게 한다.

우측 작업 보기 — SCR-03

우측은 대화 목록이 아니라 작업 하나를 보여 준다. 작업 이력에서 고른 작업, 고르지 않았으면 진행 중인 최신 작업(없으면 최신 작업)이다. 새 요청을 보내면 그 작업으로 바뀐다. 대화 칩(SCR-15)이 있으면 고른 대화 안에서 같은 규칙으로 작업을 고른다. 위에서 아래로 다음 순서다.

  1. 머리: 목적(요청 문장)·상태·호스트·모델·모드(‘계획 · 읽고 계획만’ / ‘자동 · 열린 문서에 바로 적용’). 다른 작업이 진행 중이면 그 수와 전환 행동을 한 줄로 둔다.
  2. 조건: 대상 문서(연계면 두 문서), 고정 대상과 역할(변경/유지/참고), 스케치·첨부, 입력 기준(있으면 보기 행동). 펼치지 않아도 한눈에 읽히는 요약이다.
  3. 단계: SPEC-02.11의 진행 단계를 세로 목록으로 둔다. 단계마다 상태 표식(대기·진행·완료·생략·실패)과 실제 횟수(조회 n회, 실행 n/상한, 검증 n회)를 쓰고, 진행 중인 단계 옆에 그 시점에 가능한 개입을 둔다.
  4. 결과: 자동 모드는 실행마다 한 행(추가 n · 변경 n · 삭제 n, 펼치면 바뀐 객체 목록)과 [되돌리기]를 두고, 보호 동작에 걸려 되돌려 둔 실행은 무엇을·몇 개를 보이는 확인 카드와 [진행]을 둔다. 계획 모드는 계획 카드(단계·질문)와 [진행]을 둔다. 작업 사본에서 만든 결과(검토·jig 내부 사본·파일에서 연 사본)는 보기·내려받기를 둔다. 그 아래에 AI 답변. 진행 중이고 아직 결과가 없으면 그 사실을 보여 준다.
  5. 확인할 것: 결과 미확인 실행, 표시 제외, 근거 없는 인용 경고 등 사용자가 판단할 항목.
  6. 작업 과정(펼침): 활동 로그 전체와 생성 코드.

개입 행동은 상태에 따라 바뀐다: 진행 중에는 추가 지시·중단(쓰기 검증 중에는 중단 대신 이유 표시), 끝난 뒤에는 [되돌리기](마지막 기록일 때만)·입력 복원·이어서 지시. 좁은 화면에서는 작업 이력의 행을 누르면 이 보기로 이동한다.

실행 이력·사용량·생성 코드·진단은 펼침 영역에 둔다. 형상 작업의 결과는 열린 호스트 문서와 Sync된 뷰포트에서 확인하고(작업 사본 결과는 ‘후보 보기’), 표 작업은 ‘표 보기’로 이동시킨다. 도구 결과가 없는 동안에는 단계 문구를 표시하고 임의의 퍼센트나 가상의 사고 과정을 장식으로 만들지 않는다. 상태의 의미는 SPEC-00.10과 SPEC-02를 참조한다. 표시 책임은 §12.1을 따른다.

07 / 상태 문구와 피드백

상태 전이는 SPEC-00.10, 개입은 SPEC-02.8, 바로 적용·되돌리기·보호는 SPEC-02.13, 작업 사본 결과의 적용/복구는 SPEC-02.7이 소유한다. 아래는 대응 상태가 제공되었을 때의 화면 표현이다.

중단된 요청의 복원 표시

실패·중단된 AI 요청 카드에 ‘입력을 초안으로 복원’을 둔다. 현재 초안 교체는 취소할 수 있고 복원 뒤에는 입력란에서 조건을 확인한다. 사라진 모델은 이름과 사용 확인 필요를 표시하며 유효한 선택 전에는 보내기를 비활성화한다. 호스트 결과 미확인 카드는 이 복원 행동을 표시하지 않는다.

입력 기준과 표시 후보가 다를 때는 입력 첨부 영역에 ‘입력 기준 보기’를 표시한다. 기존 후보를 기준으로 삼지 않은 입력은 같은 위치에 ‘새 작업 기준’을 표시한다. 기준이 같을 때는 이 표시를 생략한다.

08 / 작업 사본 결과의 비교와 적용 화면

자동 모드의 AI 편집은 열린 문서에 바로 적용되고 결과는 작업 보기의 실행 행과 [되돌리기]로 보인다(§06, ADR-022). 이 절의 비교·적용 화면은 작업 사본에서 만든 결과(검토, jig 내부 사본, 파일에서 연 사본, 바로 적용 이전의 요청)에만 쓴다.

중앙에는 원본/후보/겹쳐 보기, 우측에는 변경 요약·측정값·입력 기준·검토 범위를 둔다. 현재 보고 있는 후보 제목과 버전을 항상 찾을 수 있어야 한다. 이전 후보는 ‘이전 조건’ 등 기준 차이를 표시한다.

‘문서에 적용’ 행동은 대상 문서·변경 요약 근처에 배치한다. 적용 중·결과 확인·파일 저장 표시는 문서별 결과 행으로 분리한다. 예: ‘적용 확인 · 파일 저장 미확인’. 실제 활성 조건은 SPEC-00.9.1, 처리 규칙은 SPEC-02.7·13을 참조하며 여기서 재정의하지 않는다.

호스트가 여러 개면 문서별 행을 같은 작업 아래에 두고 하나의 거대한 성공 배지로 합치지 않는다. 원본/후보를 나란히 자유 배치하기보다 먼저 보기 전환과 겹쳐 보기를 제공한다.

Inspector 관계 표시

하단 Inspector의 관계 탭에는 이전 후보와 작업 입력의 참조 대상을 버튼으로 표시한다. 변경/유지/참고 역할과 호스트 이름을 함께 보여 주고 확인할 수 없는 기준은 비활성화한다. ‘이 객체가 포함된 작업의 기준과 입력’이라는 짧은 설명으로 작업 수준의 관계임을 구분한다.

DWG 가져오기 결과가 불명확하고 확인 근거가 있는 카드에는 ‘불러오기 결과 확인’을 표시한다. 확인 중에는 버튼을 비활성화하고 결과를 같은 카드에 표시한다. 원본 적용의 결과 확인 버튼과는 각각의 작업 카드로 구분한다.

09 / 표·검토본·공유·설정의 시각적 일관성

표는 단위·출처·기준을 제목/열 상세에 두고 숫자를 정렬한다. 행의 ‘대상 보기’로 형상 위치를 찾고 돌아오는 길을 제공한다. 긴 표는 자체 스크롤을 사용한다. 계산과 갱신 의미는 SPEC-03.5·8을 따른다.

검토본은 제목·기준 시각과 보존된 표현의 목록으로 보여 준다. 비교는 A/B 보기와 변경 목록을 사용하고 과거본에는 ‘과거 검토본’을 고정 표시한다. 공유는 게시 기준·미전송 변경·의견 접수 상태를 가까이 배치한다. 동작은 SPEC-03.6·8과 SPEC-04.7을 참조한다.

AI 설정과 확장은 작업 공간 위의 보조 화면으로 열고 닫으면 원 작업으로 돌아간다. 확장 결과도 같은 카드·표·대상 표현을 재사용한다. 제품 능력/등록 계약은 SPEC-05의 소유다.

고정 검토본의 진입과 열람 — SCR-08·09

후보 카드의 ‘검토본 저장’에서 제목과 저장한 표 구성을 고른다. 저장한 결과는 왼쪽 프로젝트 구조의 ‘검토본’ 목록에 둔다. 목록 선택은 현재 모델을 바꾸지 않고 넓은 읽기 창을 열며, 제목·HTML 내려받기·닫기는 상단에 둔다. 검토 화면·요청/참조·표·당시 적용 상태를 순서대로 보여 준다. 3D 이미지는 전체가 보이도록 높이를 제한하고 상세 표는 아래로 이어진다. 구현 계약과 보존 범위는 SPEC-03이 소유한다.

AI 연결 설정의 진입

왼쪽 rail 최하단 설정 또는 하단 공급자 상태에서 ‘AI 연결 설정’을 연다. 공급자별 실행 경로와 로그인 확인 결과를 나란한 폼 구역으로 보여 주고, 저장/연결 확인을 구분한다. 닫으면 원래 입력과 선택으로 돌아간다. 모드·모델·effort는 기존 입력기 하단에 유지한다. 경로 저장 오류는 폼 안에 표시한다. 계정 영역은 아래 「AI 설정의 계정 표시」를 따른다.

확장 진입과 결과 — SCR-05

확장의 화면 입구는 두지 않는다(2026-09-29, SPEC-05.7). 이미 실행된 확장 결과는 작업 이력에 '확장 완료'로 남고 작업 보기에서 표·근거를 볼 수 있다.

외부 검토 화면 — SCR-06

공유 화면은 왼쪽 프로젝트 탐색, 중앙 게시 모델, 오른쪽 의견으로 배치한다. 게시 제목/시각과 허용된 과거본 선택은 모델 가까이에 두며, 호스트 실행/후보 적용 버튼은 놓지 않는다. 모델 오른쪽에는 카메라 보기, 아래에는 선택 객체의 이름과 공개 측정값을 둔다. 객체 선택과 의견 대상 첨부는 별도 행동으로 표현해 탐색 중 작성 대상이 바뀌지 않게 한다.

좁은 화면에서는 프로젝트 탐색을 위쪽 가로 목록으로, 의견을 모델 아래로 옮긴다. 소유자의 초대·역할 관리만 의견 패널 아래 펼침에 둔다. 접수 확인 전에는 초안, 서버 응답 뒤에는 접수 문구를 표시한다. 응답 불명확 시 원문을 고정하고 같은 의견의 접수 확인 행동을 제공한다. 기능 계약은 SPEC-04.4·5·8, 현재 구현과 실기기 미시험은 공유 VERIFY를 따른다.

로컬 후보의 ‘공유 자료’는 객체 선택·게시 제목·이름/측정값 포함 여부를 보조 창에서 정한다. 기본 선택은 비워 두며 전체 내부 검토본을 자동 공개하지 않는다. 웹 소유자의 ‘모델 게시’ 펼침은 선택 파일의 제목·객체/필드 범위를 먼저 보여 주고 게시/재확인 행동을 둔다. 전송 확인 전후 문구를 구분하며 재시도 자료 닫기가 서버 게시 삭제를 뜻하지 않도록 안내한다.

공유 모델 왼쪽에는 탐색·핀·스케치를, 오른쪽에는 카메라 도구를 둔다. 스케치 모드의 평면·선 역할·단위는 모델 왼쪽 아래에 표시한다. 초안의 핀/선 제외와 중단 선의 보관/제외는 의견 입력기 가까이에 둔다. 저장 의견의 공간 표시는 별도로 열고 닫으며 새 초안을 덮어쓰지 않는다.

IDE 검토본 목록의 ‘외부 의견’은 파일 가져오기·수신 목록·기준 후보 열기·초안 첨부를 제공한다. 원문과 게시 기준, 공간 입력 건수를 먼저 보여 주며 파일 수신과 온라인 인증을 구분한다. 공유 웹에서 의견 내려받기는 소유자에게만 표시한다.

호스트 패널(Rhino·ZWCAD) — SCR-12

2026-09-29 사용자 결정: Rhino 패널과 ZWCAD 팔레트는 같은 웹 화면(VIDE 작업 열, ?panel=rhino|zwcad) 하나로 그린다. 호스트 기본 버튼 줄은 두지 않고, 연결·Sync·Live 같은 조작도 웹 화면 안에 둔다. 폭은 약 300–420px을 기준으로 한다.

  • 머리(3줄): ① 호스트 표식(R / CAD)·파일 이름(한 줄, 넘치면 말줄임)·⋯ 메뉴 ② 상태 점과 한 줄 상태(Live · Sync 3:19 · 531개 / 연결됨 · Sync 필요 / 연결 끊김) ③ 연결된 프로젝트 이름, 주 버튼 Sync, Live 스위치. ⋯ 메뉴에는 VIDE에서 크게 열기, 다른 프로젝트에 연결, 연결 해제, 다시 불러오기를 둔다. 같은 정보·버튼을 두 번 두지 않는다.
  • 연결 전: 머리에는 파일 이름과 '아직 VIDE 프로젝트에 연결되지 않음'만 두고, 본문에 한 장의 안내 카드(무엇이 되는지 한 문장, 주 버튼 이 파일 연결하기)를 둔다. 버튼은 호스트의 프로젝트 선택 창을 연다(사용자 결정: 뜨는 창이 직관적이다). 작성기는 숨긴다.
  • VIDE가 꺼져 있을 때: 같은 카드 모양으로 'VIDE가 실행되고 있지 않습니다'와 VIDE 실행을 두고, 켜지면 스스로 이어진다.
  • 본문: 지금 작업의 작업 보기(SCR-03)와 접힌 최근 작업.
  • 작성기: 호스트에서 고른 객체가 있으면 '선택 N개 첨부' 칩을 둔다(누르면 요청 대상으로 첨부, Rhino는 고정 핀과 같다). 모드·모델은 한 줄로 줄인다.
  • 바닥: 계정 사용량 막대 — 서비스마다 지금 CLI 기본 로그인 계정의 5시간(ChatGPT는 짧은 창)·7일 사용률을 얇은 막대와 %로 보이는 읽기 표시다. 90% 이상은 경고색, 한도 도달은 '한도'. 사용량 조회가 꺼져 있으면 '사용량 조회 꺼짐'만 흐리게 둔다. 막대에서 계정을 바꾸는 행동은 두지 않는다(계정 전환은 AccountSwitch, ADR-025). 같은 막대를 VIDE 앱 하단 상태줄에도 둔다.
  • CAD의 차이: 호스트 표식 CAD, 도면 단위 표기. 선택 칩은 CAD에서 고른 객체를 가져와 첨부한다.
  • 색·글꼴·간격은 VIDE 작업 화면의 토큰을 따르고, 호스트의 밝음/어두움 설정을 따른다.

10 / 진단·전문가 상세

진단에는 실행 시간·공급자·확인된 사용량·실제 명령/생성 코드·오류 상세를 읽기 좋게 구분한다. 기본 화면에 코드 덤프를 노출하지 않는다. 값이 없을 때는 ‘미확인’을 사용한다. 긴 텍스트는 줄바꿈/복사/접기 행동을 제공한다. 실행 권한이나 셸 기능을 진단 화면에서 새로 정의하지 않는다(SPEC-00.9, ARCH-01 §1.4).

11 / 반응형·접근성

큰 화면은 세 영역, 중간 폭은 중앙과 한 보조 패널, 좁은 화면은 모델/입력/작업 탭을 사용한다. 정확한 초기 치수는 §12.9에 있다. 패널·탭 전환 시 복귀 위치가 분명해야 하며 입력 보존은 SPEC-01.7을 따른다.

모든 행동에 읽을 수 있는 라벨·키보드 포커스를 제공한다. 닫힌 팝오버의 포커스는 열었던 행동으로 돌아간다. 중요한 치수·단위·상태를 색이나 작은 아이콘에만 맡기지 않는다. 뷰어 조작에 객체 목록 대안을 제공한다. 확대 시 내용이나 주요 행동이 가려지면 안 된다. 대비·터치 목표·실기기 시험 기준은 PLAN §7.5에서 검증한다.

12.6 공간 작업의 화면 배치

12.7 두 호스트 작업의 화면 배치

SPEC-02.14의 연계 작업은 우측 작업 영역에 공통 작업 제목, 입력기에는 참고/결과 문서 토큰, 결과 영역에는 문서별 행을 둔다. ‘CAD 후보 보기’와 ‘Rhino 후보 보기’로 중앙 표현을 전환한다. 문서 간 배치 기준은 상세 패널에서 표시한다. 의존 순서는 작업 카드 사이의 짧은 설명으로 표현하며 자유 노드 편집기를 추가하지 않는다.

12.8 웹 검토와 전달 화면의 배치

SPEC-03.8·04.7의 경험은 중앙 모델/표/비교와 보조 의견 영역으로 표현한다. 웹 상단은 프로젝트·게시 시각·검토본, 로컬 의견 상세는 작성 기준과 현재 기준을 구분해 보여 준다. ‘작업에 연결’은 의견 가까이에, 이후 작업 행동은 로컬 입력기에 배치한다. 서버 동작·권한·접수 의미는 SPEC의 해당 절을 따른다.

13 / 디자인 변경의 판단 기준

화면 변경은 대상·의도·실제 결과를 더 잘 읽고 조작하게 해야 한다. 배치·토큰·문구 개선은 이 문서에 반영한다. 새로운 기능·상태·권한이 필요하면 SPEC의 변경으로, 서비스/저장/기술 선택이 필요하면 PLAN의 변경으로 돌린다. 시각 검수 방법과 결과 기록은 PLAN §7과 VERIFY를 따른다.

자동 UI 검사는 배치·상태 표시의 구현 증거이며 사용자 이해도 검수를 대신하지 않는다. 후보/원본·접수/반영·적용/저장 오해는 실제 작업 문맥으로 확인한다. 검수자·환경·판정과 미시험 기록은 PRD AC-22·OQ-14 및 PLAN §7을 따른다. 호스트 옆 반폭 창도 §11·§12.9의 좁은 화면 기준으로 검수하며 별도 기능 범위를 만들지 않는다.

UI 점검 반영 — 작업 공간 조작

문서·이력·참고 자료 레일은 왼쪽 패널의 탭을 전환한다. 검토본은 이력 탭에 둔다. 프로젝트는 왼쪽 공통 영역, 연결 상태는 하단 상태줄에 남긴다. 좌우 경계는 드래그/방향키로 폭을 조절하며 중앙 최소 폭과 모바일 탭을 보존한다. 카메라는 방향(3D·위·앞·옆), 투영 전환 한 개(직교/원근), 맞춤(선택/전체)을 구분한다. 선택 강조는 실제 카메라에서 갱신한다. 요청 문맥은 대상·첨부·조건 요약을 먼저 보여 주고 원문 JSON은 진단용 펼침 안에 둔다. effort는 모델별 지원 단계의 이산 슬라이더로 표시하고 현재 단계 이름을 함께 둔다. 비활성 입력 행동에는 조건을 툴팁과 문맥 설명으로 알린다.

연계 결과의 후속 입력

종료된 연계 요청 카드에 확인된 후보에서 이어가기를 둔다. 대상별 상태와 후보 보기 동작은 유지한다. 두 후보의 확인 상태가 부족하면 이유를 표시하고 입력기를 바꾸지 않는다. 성공하면 원 조건과 새 기준을 입력기에 채우고 사용자가 수정·전송하게 한다.

AI 설정의 계정 표시

VIDE는 각 CLI의 기본 로그인만 쓰고 계정을 관리하지 않는다(ADR-025, PLAN-25). AI 연결 설정의 계정 영역은 공급자마다 읽기 전용 카드 하나다: 현재 계정(이메일·요금제), 사용량 막대(SCR-12와 같은 막대, 확인할 수 없으면 ‘사용량 미확인’), 그리고 ‘계정 관리·전환은 AccountSwitch에서’ 한 줄. 로그인되어 있지 않으면 ‘터미널이나 AccountSwitch에서 로그인하세요’를 보인다. 계정 추가·로그인·로그아웃·제거·이름 변경·선택·자동 전환 행동과 로그인 명령·인증 URL은 두지 않는다. 대화 머리 줄의 계정 표시는 그 턴에 쓴 기본 로그인 계정이다. 기존 입력창과 모델/effort 조작은 유지한다. 동작 기준은 SPEC-02.18이다.

현재 Rhino 문서 연결 표시

호스트 패널의 구성은 SCR-12를 따른다. 문서 선택을 조회 때마다 첫 문서로 되돌리지 않는다. 자동 갱신은 초안 보호/오류 시 보류 이유를 표시하며 기존 모델을 지우지 않는다.

연결 문서를 고치는지는 작성기의 작업 모드(계획/자동, §04)로만 보인다. 자동이면 연결한 열린 문서를 바로 고치고 결과는 실행 행·[되돌리기]·Sync 상태를 구분해 표시한다. 다시 연결하거나 기준을 바꿨다는 이유로 모드를 자동으로 바꾸지 않는다(모드는 프로젝트마다 기억한다).

작성기·카메라·상태 조작 보완

Effort는 현재 단계가 보이는 작은 캡슐을 눌러 이산 슬라이더를 펼친다. 얇은 채움 트랙과 단계 눈금을 사용하고 모델이 지원하는 단계만 제공한다. 작성기 상단 경계를 드래그하거나 방향키로 높이를 조절한다. 텍스트 영역 모서리의 별도 resize 손잡이는 없앤다.

뷰포트 왼쪽 클릭은 선택과 스케치 획에 사용한다. 원근/자유 뷰에서 우클릭 드래그는 회전, Shift+우클릭은 평행 이동이다. 위/앞/옆 보기에서는 우클릭으로 평행 이동하며 휠은 확대다.

검정 하단 상태줄에 공급자 연결, 호스트 준비, 작업·오류 요약을 배치한다. 상태를 클릭하면 상세 팝업을 열고 관련 설정으로 이동한다. 호스트 설치/실행 준비와 열린 문서 연결을 구분한다. 설정은 rail 하단에서 항상 찾을 수 있는 보조 화면이며 AI 경로·계정 표시와 작업 상한의 기존 설정으로 연결한다. 모달을 닫으면 원래 초안과 선택을 유지한다.

화면 기하가 없는 네이티브 객체는 결과 카드에서 표시 제외 수와 목록·파일 보존을 구분한다. 선택 객체 속성에는 “화면 표현 미지원”을 표시하고, 하단 표시 상태의 상세에서 현재 모델의 전체·표시·미지원 개수와 유형을 확인한다. 가져오기 성공을 전체 화면 표현 성공으로 부르지 않는다.

  • 다시 계산: 계산하는 동안 이전 결과를 지우지 않고, 영향받는 단계와 칸에 ‘다시 계산 필요’(속 빈 점)를 둔다.
  • 호스트 패널: SCR-12에는 탭·슬라이더 판·대화 칩을 그리지 않는다. 질문·확인·설정값 바뀜·jig 카드는 패널의 작업 보기에도 같은 모양으로 나오며, 300px 폭에서는 선택지를 세로로 쌓는다.

jig 실행 화면 — SCR-13

jig 문맥 탭의 화면이다(목업 s06-dashboard.html).

  • 왼쪽 머리: JIG › 이 프로젝트의 jig 경로, jig 이름(20px), 버전·마지막 계산 시각 한 줄.
  • 단계 레일: 단계마다 번호·이름·상태 기호(✓ 계산됨, ○ 계산 전, 속 빈 점 다시 계산 필요, ✕ 막힘, 계산 중)·한 줄 요약·맡는 쪽(계산·라이브러리·AI·사람·호스트)·걸린 시간·문제 수 배지를 둔다. 사람이 맡는 단계는 확정 전 · 확정됨 · 다시 확인 필요(!)로 표시한다. 현재 단계는 이름 앞의 포인트 점(--accent, 멈춘 점)과 옅은 바탕(--bg-selected)이며 왼쪽 경계선은 쓰지 않는다(§01·§02). 누를 때 계산하는 단계는 행 안에 행동 버튼(예: 단면 선정)을 둔다. 점검에 막힌 단계는 이유를 건축 문장 한 줄로 쓴다(예: 거더 3개가 슬래브 경계 밖으로 나갑니다). SCR-03 단계 목록과 같은 표현이다.
  • 입력 조립·대안: 단계 레일 아래에 입력 역할별 한 줄(기호·역할·원천·확인한 쪽)과 ‘n/m 확인’을 둔다. 확인 필요 행의 ‘확인’은 SCR-14를 연다. 같은 jig의 다른 작업본(대안)이 있으면 대안 목록(선택 단추·이름·핵심 수 세 개, AI가 권한 대안은 ‘제안’ 표지)으로 전환한다.
  • 가운데 머리: 보기 층 메뉴(‘보기 6/7 켜짐’, 층마다 켜기·끄기·투명도), jig가 선언한 예비값 표지(예: 탐색용 예비값 · 공식 구조 검토 아님), 확인하지 않은 입력이 있으면 ‘입력 미확인’ 표지, 3D·평면·보고서 전환.
  • KPI 띠: 가운데 위, 위 2px ink 선, 5~6칸. 칸마다 작은 제목 → 큰 숫자(--fs-kpi)와 작은 단위 → 두 줄 해설(기준·위치). 기준을 넘은 칸은 제목 옆에 기호와 문구 배지(✕ 초과 1)를 둔다. 값이 없으면 비우지 않고 이유(— 단면 선정 전)를 쓴다.
  • 3D·평면 겹침: jig 결과는 문서 객체 위의 겹침 층으로 그린다(축선 점선, 새 부재, 기존 기초 같은 참고 형상, 간섭은 §02의 겹침 토큰). 문제 위치에는 문제 표와 같은 번호 표식을 둔다. 평면은 기존 축을 기준으로 돌려 보인다. 평면에서 옮긴 점은 가까운 축선 교점에 붙고 ‘수정 사항’ 표지가 붙으며, 같은 일을 표·말로도 할 수 있게 한다(§12.3). 위치가 바뀌거나 대상을 잃은 수정 사항은 결과 서랍 위에 건수로 알린다.
  • 설정값 슬라이더 판: 뷰포트 왼쪽 위에 뜨는 접을 수 있는 판(최대 6행). 머리에 ‘끌면 기하만 · 놓으면 다시 계산’ 한 줄. 행마다 이름, 근거 칩, 구간 바탕(--zone-*)의 슬라이더, −/+ 버튼, 숫자 칩과 단위를 둔다. 사용자 결정으로 정한 값은 채운 점의 ‘결정’ 칩으로 구분하고 판 대신 ‘자세히’에 둔다. 작업본을 만들 때 고정한 값(출력 레이어 등)은 잠금 표시와 함께 읽기로만 보인다. 나머지 설정값은 왼쪽 단계별 설정값 묶음(펼침)과 ‘자세히’ 목록에 둔다.
  • 판정 범례: 뷰포트 오른쪽 아래. 제목(판정 · 하중 조합)과 부재 수, 구간마다 색 견본·기호·범위·건수(누르면 그 판정만 보기), 기하 판정 선(내민 길이 초과·경간 초과), [판정색 끄기]를 둔다. 확정 전 미리보기 판정이면 범례 머리·KPI 칸·보고서 전환에 ‘미확정 미리보기’ 표지를 붙이고 해석 확정 뒤 거둔다(SPEC-06.3). 해석 확정은 사람이 누르는 단계 행동으로 둔다.
  • 결과 서랍: 검사기 자리에 탭(문제 n·간섭·경간·검정·높이·일람표·조건 원장)과 오른쪽 행동(CSV, 보고서, 남은 확인 수, 주 버튼 Rhino에 만들기)을 둔다. 막힌 행동은 흐리게 두고 이유를 옆에 쓴다(예: 입력 확인 2건 먼저, Rhino에서 레이어를 켠 뒤 다시 누르세요). 문제 표는 번호·판정(기호+문구)·항목·위치·값·기준·원인 태그(입력 의심, 부재 부족 등 테두리 태그) 순이며, 행을 펼치면 한 줄 설명과 [평면에서 보기]가 나온다. 표 행과 3D·평면 선택은 서로 따라간다. 표 옆에는 고른 문제 주변의 부분 평면을, 표 바닥에는 통과한 점검 수를 한 줄로 둔다.
  • Rhino에 만들기 결과: 연결된 열린 Rhino 문서에 바로 만들고, 결과 카드에 추가·교체·사람이 고친 것 보존·복사본 그대로·사람이 지운 것(되살리기)의 수와 출력 레이어를 한 줄씩 둔다. 마지막 만들기면 [되돌리기](호스트의 되돌리기 기록)를 둔다. 연결 Rhino가 없어 사본에서만 만들었으면 그 사실을 카드에 쓴다. 결과가 바뀐 뒤에는 ‘만든 결과가 오래됨’ 표지를 둔다.
  • Rhino에서 바뀐 것: 가운데 위에 한 줄 띠로 모아 보인다(예: Rhino에서 5건이 바뀌었습니다: 기둥 높이 3 · 거더 모양 2 · 꺼진 레이어 1(비교 안 함) [보기]). [보기]는 항목별로 받기·유지·덮기 중 SPEC-07.13이 허용한 선택만 보인다.
  • 오른쪽·상태줄: 오른쪽은 이 jig의 대화(SCR-15)다. 상태줄에는 연결 상태, 마지막 계산 시간, 이 프로젝트의 jig 이름·수정 사항 수, 사용량 막대(SCR-12와 같은 막대)를 둔다.

입력 조립 확인 — SCR-14

jig 문맥 탭에서 입력 조립 단계를 열었을 때의 배치다. 연결 파일에서 제안된 입력을 역할별로 확인한다(SPEC-07.5).

  • 왼쪽: 제목 ‘입력 조립 n/m 확인’과 역할 카드 목록. 카드에는 역할 이름, 상태(✓ 확인 · ? 확인 필요 · 자료에 없음), 원천(파일·레이어·블록 이름·개수), 크기·각도 같은 요약값과 그 기준, 제안 이유 한 줄, 고정 / 따라가기 전환, 행동 [확인] [바꾸기] [직접 그리기]를 둔다. 확인 필요 카드를 위로 올린다. 자료에 없는 역할은 점선 카드와 [그리기]만 둔다. 읽은 문서 판이 지금 판과 다르면 카드에 ‘다시 읽기 필요’를 둔다.
  • 가운데: 평면이 기본이고 3D로 전환한다. 역할별로 겹쳐 그리되 굵기·빗금·점선·라벨로 구분하고 색에만 맡기지 않는다. 머리에 좌표 기준과 CAD 정렬 결과 한 줄(‘기준: 구조 모델 좌표 · CAD 3개 정렬됨 · 대응 24 · 잔차 0.02 m’)과 정렬 [확인]을 둔다. 확인하지 않은 정렬을 거친 역할은 ‘참고’ 표지로 구분한다.
  • 연결: 카드를 누르면 그 역할만 강조하고 화면을 맞춘다. 가운데에서 누른 객체는 해당 카드를 연다. [바꾸기]는 연결 파일 → 레이어 → 객체 순의 작은 선택 창, [직접 그리기]·[그리기]는 스케치 도구(§05)를 그 역할로 열거나 Rhino에서 그린 곡선을 고르게 한다.
  • 오른쪽: 확인을 청하는 질문 카드(예: [맞음] [다른 레이어])가 대화에 온다.

목적별 대화 칩·질문 카드 — SCR-15

오른쪽 AI 열의 표현이다(목업 workspace-model.html, s06-dashboard.html 오른쪽). 대화·질문·확인 등급의 동작은 SPEC-02.19를 따른다.

  • 대화 칩: 오른쪽 열 맨 위 한 줄의 탭. 탭 하나가 대화 하나이며 이름(목적 · 대상, 예: 구조 · S-06, CAD 편집, 법규 질문)과 상태(● 진행 중, ◌ 읽지 않은 답·질문, ‘대기 n’)를 둔다. 고른 탭은 옅은 배경과 굵은 글자이며 색 막대를 두지 않는다. 끝에 [+] 새 대화, 넘치면 더보기 목록으로 모은다. jig를 열면 그 jig의 칩이, jig 만들기는 제작 대화 칩이 생기고 탭을 닫아도 칩은 남는다.
  • 머리 줄: 칩 아래 한 줄에 대화 이름·연결 대상(예: 이 jig의 대화)과 공급자·모델·계정을 둔다. 첫 턴 전에는 ‘첫 요청 때 AI를 정합니다’를 둔다. 정해진 공급자·모델은 읽기 표시이고, 계정은 그 턴에 쓴 CLI 기본 로그인을 읽기로만 보인다(전환은 AccountSwitch). 탭을 고르면 작성기의 모델 선택이 그 대화의 모델로 맞춰지며 effort는 턴마다 바꾼다. 작성기에서 다른 모델을 골라 보내거나 머리 줄 메뉴의 [다른 AI로 이어 가기](확인 카드)를 고르면 새 탭이 열리고 그 탭이 골라진다(SPEC-02.19의 2·5). 인계가 일어나면 대화에 인계 카드(바뀐 세션과 이유 한 줄, 모델 바꾸기는 두 대화 모두 ‘모델이 달라 새 대화로 이어서 보냈습니다 · 모델’)를 남긴다. 계정 한도에 걸린 턴은 다시 보내지 않고 한도 알림(초기화 시각, AccountSwitch에서 바꾸면 이어 보낼 수 있음)을 남긴다.
  • 작성기: 범위 칩(예: 구조 · S-06 ×)과 대상 파일 칩을 둔다. 범위 칩을 지우면 기본 대화로 간다는 것을 도움말로 알린다. 지금 대화와 목적이 다르다고 판정되면 새 대화 제안 카드(‘이 요청은 법규 질문으로 보입니다’ [새 대화로 보내기] [지금 대화에서 계속])를 두고 스스로 옮기지 않는다. 단, 요청이 jig로 판정되면 SPEC-02.19의 1의 묶기 규칙대로 jig 대화로 옮기고 두 대화에 서로 가리키는 줄을 둔다(ADR-026). 셸 교체 뒤의 무대 이동 표현은 §03을 다시 쓸 때 정한다.
  • 대기: 진행 중에 보낸 말은 작업 보기에 대기 행(‘대기 1’, 지우기)으로 보이고, 지금 턴을 끊는 행동은 그 카드의 [멈추고 이걸로] 하나다. 말이 개입으로 보이면 이 버튼을 강조하되 누르기 전에는 끊지 않는다. 다른 대화가 같은 문서에 쓰는 중이면 작성기 위에 ‘CAD 편집 대화가 이 도면을 쓰는 중 · 대기 1’을 보이고 보내기 버튼은 끄지 않는다(SPEC-02.9).
  • 질문 카드: 머리에 ‘질문 i/n · 단계 이름’과 오른쪽에 막는 것(‘답 전까지 진단 대기’ 또는 ‘답 전까지 12 m 가정으로 계산’). 질문 한 문장(굵게), 이유와 답에 따라 달라지는 것 한 줄(회색), 선택지 행(선택 단추·이름·[권장] 테두리 태그·오른쪽에 그 선택의 결과 수치, 아래에 한 줄 설명과 근거 칩)을 둔다. 숫자 답은 단위·범위가 보이는 입력칸, 스케치 답은 [평면에 그리기], 가리키기 답은 [모델에서 고르기]다. 바닥에는 주 버튼(예: 12 m로 정하기)과, 건너뛸 수 있는 질문이면 보조 [권장값으로 진행 · 가정으로 기록]을 둔다. 한 번에 여러 장이면 i/n으로 번호를 붙인다.
  • 설정값 바뀜 카드: ‘설정값 바뀜 · 다시 계산됨’과 시각, 이전 값 취소선 → 새 값, 영향 수치 한 줄, [되돌리기] [AI에게 묻기].
  • 제안 카드와 확인 카드: 제안 카드는 머리에 ‘제안 · 무엇’, 본문에 무엇·영향(이전 값 취소선 → 새 값), 주 버튼 하나(예: 열기, Sync 받기)와 보조 [평면에서 보기]를 둔다. 누른 결과에는 되돌릴 수 있으면 [되돌리기]를 붙인다. 확인 카드는 보호 동작의 진행·다른 AI로 이어 가기·가져오기·고정처럼 확인이 필요한 일에만 쓰고 무엇을·어디에·어떤 영향으로를 세 줄로 둔 뒤 실행 버튼 하나를 둔다. 사람만 할 수 있는 일은 이유와 해당 화면으로 가는 링크만 있는 안내 카드다. 화면에 내부 등급 이름을 쓰지 않는다.
  • jig 카드: jig를 권할 때 eyebrow(JIG / 영문 이름)·출처·버전·예비값 표지, 이름과 한 줄 목적, 단계 칩 줄(번호·이름·상태), [열기] 또는 [탭에서 보기]를 둔다. JIG 목록(SCR-18) 카드의 축약형이다.
  • 판정 전송 고지: 말로 하는 경로 판정에 보내는 항목의 고지와 끄기는 AI 연결 설정(§09)의 Jev 항목에 둔다.

JIG 만들기 — SCR-16

만들기 탭의 제작 화면이다(목업 jig-studio.html). jig 실행(SCR-13)이 결과를 내는 화면이면 이 화면은 jig 자체(단계·설정값·화면·시험)를 만든다. 점검 이름·파일 이름은 이 탭에서만 오른쪽 작은 글자로 보인다.

  • 왼쪽 도구 설명 개요: 표지(새 도구 · 초안 v0.2 · 내 것), 이름·두 줄 설명·입력 요약, 그리고 묶음별 목록 — 단계(번호·이름·맡는 쪽·상태: 통과·고치는 중·가정), 설정값(값·단위·근거 상태), 화면(부품 칩과 ‘부품 n · 목록 밖 0’), 시험(시험 자료별 ✓/✕·시간·시도 n/3). 바닥에 초안 폴더의 파일 이름 목록(바뀐 파일 점)과 저장 시각을 둔다. 파일 내용을 여는 화면은 두지 않는다.
  • 가운데: 화면 미리보기. 오른쪽 위에 시험 자료 선택과 다시 실행을 둔다. 미리보기는 SCR-13과 같은 부품을 시험 자료나 최신 입력 사본으로 그린 것이며 머리에 ‘미리보기 선만 · Rhino에 쓰지 않음’ 표지와 [작업 화면] [보고서] 전환을 둔다. 사람이 설정값을 만져 볼 수 있다.
  • 아래 서랍: 탭(모두·점검 n/m·시험 n/m·작성 기록 n), 실행 시각·시간·[다시 시험]. 점검 행은 기호·문장·오른쪽 작은 점검 이름이다. 실패한 시험 행은 펼쳐 기대/실제 차이(− / +), 고치는 내용, 시도 횟수를 보인다.
  • 오른쪽 제작 대화: 칩(이름 · 만들기), 머리(제작 대화 · 공급자 · 계정 · 턴 n/20), 진행 표지 한 줄(계획 · 질문 · 작성 · 시험 · 미리보기 · 고정), 계획 카드(입력·설정값·단계·화면·결과 한 장, n/m 완료, 현재 항목 강조)와 그 아래 [만들기 시작], 질문 카드(SCR-15). 바닥 줄에 작성 중인 파일·남은 질문·남은 시험과 [버리기] 버튼(확인 창), 주 버튼 이 프로젝트의 jig로 고정을 둔다. 점검·시험이 남으면 주 버튼을 흐리게 두고 이유를 쓴다. 같은 시험이 세 번 실패하거나 턴 상한에 닿으면 멈춘 이유와 선택지를 질문 카드로 보인다.
  • 상태줄: 초안 저장 시각, 계산 시간, ‘호스트 쓰기 없음’.

보고서·원장 틀 — SCR-17

보고서 탭, jig의 보고서 전환, 내보낸 보고서가 같은 틀을 쓴다. 참고 형식은 S-04 분석 자료다(목업 s06-report.html). 문장·점검의 동작은 SPEC-07.11이 소유한다.

  • 머리: 맨 위 한 줄에 왼쪽 굵은 프로젝트 코드와 문서 이름·버전, 가운데 절 번호 내비(01 배치·기초 02 경간 …), 오른쪽 테두리 상자 버튼을 둔다. 버튼은 [조건 조정 ↗] [인쇄 ↗]이다. [조건 조정]은 앱 안에서만 보이며 그 jig의 문맥 탭과 설정값 묶음으로 돌아간다. 내보낸 보고서에서는 그 자리에 ‘VIDE에서 열기: 프로젝트 · 이 프로젝트의 jig · 버전’ 한 줄을 둔다.
  • 첫 화면: eyebrow(--fs-eyebrow, 대문자 영문, 자간 --track-eyebrow, 예: S-06 / STEEL LAYOUT REVIEW) → 문장형 헤드라인(--fs-headline, 두 줄, 마침표로 끝나는 결론) → 해설 2~3줄(회색, 핵심 구절만 굵게) → 출처 점 한 줄(입력을 읽은 시각·자료 진술 수(확정 수)·설정값 근거 현황) → 오른쪽 아래 절 요약(01 — 05, 영문 절 이름, 날짜). 그 아래에 예비값 안내 상자(테두리 태그 ‘예비 검토’와 한두 문장)와 가정·검토하지 않은 항목(구조 jig는 하중 조합 포함) 목록을 둔다. 주장 문장이 틀 문장으로 되돌아갔으면 그 문장 옆에 ‘확인 필요’ 태그를 둔다.
  • KPI 띠: SCR-13과 같은 부품이다. 기준을 넘은 숫자는 --bar-actual로 쓴다.
  • 번호 절: eyebrow(01 / LAYOUT & FOUNDATION) → 주장형 제목(--fs-claim, 두 줄) → 짧은 해설 → 그림·표. 그림은 평면 지도, 절제된 막대(§02의 세 색과 상한 점선), 분포 막대, 비교 카드(제목·오른쪽 메타·테두리 태그·막대)다. 표는 숫자 자리를 맞추고 판정은 기호와 문구 태그로 둔다. 미리보기 판정은 확정 결과처럼 쓰지 않고 ‘미확정 미리보기’ 표지를 유지한다.
  • 원장: 왼쪽 260px에 검색(/), 제목·부제, 필터 칩 두 줄(출처 / 근거 상태, 항목은 SPEC-07.6), 목차와 절별 건수(필터 반영). 오른쪽에 작은 경로, 제목, 한 줄 해설, 3열 표(항목명 회색 | 값 | 오른쪽 작은 근거 칩). 보고서의 남은 조건 절도 같은 표 모양(질문 | 근거 | 누가 답하나 | 막는 단계)을 쓴다.
  • 인쇄·좁은 폭: A3 가로와 A4 판형으로 절마다 쪽을 나누고 내비·버튼을 숨기며 3D는 캡처 그림으로 넣는다. 1024·390px 폭에서도 가로 넘침 없이 KPI 띠를 2열·1열로 접고 원장 왼쪽 목록을 위로 올린다. 내보내기 형식은 SPEC-07.11을 따른다.

claudeR-72중간 SCR-17의 영문 eyebrow·문장형 헤드라인·보고서 맨 위 줄은 §01의 “단계 안내·영문 소제목·설명용 큰 제목을 반복하지 않는다”, “별도 전체 폭 상단 바는 두지 않고”와 문자 그대로 부딪힌다. 이 예외(RESEARCH-10 §16 B15)는 사용자가 뒤로 미룬 결정이라 §01은 고치지 않았고, 이 요소들(SCR-15·17·18·19의 영문 eyebrow 포함)은 §12.2와 §14에 <ins> 제안으로만 표시했다. 결정 전 구현은 §01 현행 문장을 따른다(PLAN-22의 보고서 틀 작업). jig 단계 레일은 SCR-03 단계 목록과 같은 표현으로 보아 이 충돌에서 뺐다. 제안: 읽고 인쇄하는 보고서·원장 틀(SCR-17·19)에 한해 §01의 예외로 둘지 사용자가 정한다.

JIG 목록 — SCR-18

JIG 탭의 화면이다. 목록의 내용은 SPEC-05.8, 출처·수명의 의미는 SPEC-07.3을 따른다.

  • 왼쪽: 출처 필터(전체·공식·이 프로젝트의 jig·내 초안)와 건수, 아래에 [가져오기].
  • 가운데 맨 위: ‘말로 만들기’ 카드 한 장(한 줄 입력과 [만들기 탭에서 시작]).
  • jig 카드: eyebrow(JIG / 영문 이름), 이름, 한 줄 목적, 필요한 입력 칩, 할 수 있는 일(건축 문장 두세 줄), 출처·버전·예비값 표지, 상태(사용 가능 / 준비 중과 이유 한 줄)를 둔다. 이 프로젝트의 jig가 있으면 카드 아래에 목록(이름·마지막 계산 시각·수정 사항 수·새 버전이 있으면 [올리기])과 [열기]를 두고, 카드 행동으로 [새로 열기] [복제]를 둔다. 준비 중 카드는 흐리게 둔다. 공식 일반 예제 카드는 ‘본보기’ 표지를 달고, 프로젝트 jig는 그 프로젝트의 목록에만 보인다.
  • 행동: [열기]는 문맥 탭을, [복제]는 만들기 탭의 새 초안을 연다. [새로 열기]는 이름과 출력 레이어(연결 모델의 기존 레이어에서 고름)를 정하는 작은 창을 거쳐 문맥 탭을 연다. [가져오기]와 고정은 무엇을·어느 프로젝트에·할 수 있는 일을 보이는 확인 카드를 거친다.

자료 작업공간 — SCR-19

자료 탭의 화면이다. 프로젝트 자료 jig의 현황 보고서·이슈 노트·원장을 가운데에 둔다(SPEC-07.10).

  • 왼쪽: 검색(/), 보기(정해진 것·막힌 것·바뀐 것), 분야 목록과 건수, 상태 필터(확정·미확정·오염).
  • 가운데: 현황 보고서는 SCR-17 틀(eyebrow S-06 / PROJECT STATUS, 문장형 요약, KPI 띠: 진술·확정·이슈·오염 표시 수)을 쓴다. 이슈를 누르면 이슈 노트(결론 → 미결 → 조건 → 경과, 문장마다 근거 칩)를 연다. 원장 보기는 SCR-17 원장과 같다.
  • 아래 서랍: 고른 근거의 원문 발췌(해당 구절 강조), 보낸 역할·날짜, [원본 열기] 버튼(사람이 누르는 행동).
  • 오른쪽: 자료 범위의 대화 칩(예: 자료 질문).
  • 미확정 진술은 회색 글자, 오염 의심은 경고 기호·문구와 제외 이유로 표시한다. 확정·오염 표시 행동은 진술 창에 둔다. 의미는 PRD §4.4 C-02와 ADR-018을 따른다.
